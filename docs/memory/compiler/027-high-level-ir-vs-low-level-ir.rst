第027章：High-Level IR vs Low-Level IR
=======================================

核心知识点
----------

* IR 层级决定编译器当前能直接看见哪些事实，也决定哪些转换最容易证明正确。
* High-Level IR 保留语言或领域意图，例如结构化循环、对象、异常、张量、索引访问和高级类型关系，适合依赖这些抽象的分析与优化。
* Mid-Level IR 通常显式化 CFG、SSA、调用、类型和机器无关内存语义，是常量传播、死代码删除、内联后清理、循环优化等通用优化的主要工作层。
* Low-Level IR 暴露 basic block、branch、address calculation、load/store、calling convention 等执行约束，为指令选择、寄存器分配和目标 lowering 做准备。
* 一个事实若在高层是显式语义，降低后可能只能通过模式识别重新恢复；因此 pass 应尽量放在最直接提供所需证据的 IR 层。
* 大型编译器通常使用多层 IR，使高层语义优化、机器无关优化和目标相关优化分别在合适层级完成。

关键路径
--------

``Source/AST -> High-Level IR -> Mid-Level SSA/CFG IR -> Low-Level IR -> Machine IR``。

以数组循环为例，高层可直接保存“循环范围 + 元素访问”；进入中层后变成显式控制流与 SSA 值；进入低层后进一步变成 ``getelementptr/load/branch`` 一类地址和执行操作。

选择 pass 层级时先问它需要什么证据：需要循环边界、张量形状或异常区域，就应在高层处理；需要 use-def、CFG、常量和副作用关系，可在中层处理；需要寄存器、ABI、指令成本和调度，则进入低层。

概念辨析
--------

* **高层 vs 低层**：区别在抽象保留程度和执行约束显式程度，不等同于“好”与“差”。
* **Mid-Level IR**：不是固定格式，而是抽象程度适合机器无关分析和优化的一类工作层。
* **结构化控制流 vs CFG**：前者直接表达循环和条件区域；后者用 block 与 edge 表达同一执行关系。
* **降低后恢复高层事实**：可以通过 loop analysis、pattern matching 等重新推断，但成本更高且可能不完整。

本章结论
--------

IR 层级本质上是证据管理。高层保留意图，低层暴露执行约束，中层提供统一优化工作面。设计或阅读 pass 时，应让转换发生在所需事实仍然直接、可靠、廉价可用的层级。
