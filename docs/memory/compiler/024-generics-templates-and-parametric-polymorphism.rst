第024章：Generics, Templates, and Parametric Polymorphism
=========================================================

核心知识点
----------

* 泛型把代码复用提升到类型关系层：一份源码可以在多种具体类型上保持同一组输入、输出和约束关系。
* 类型参数是类型层面的占位符，泛型签名通过同一个类型变量在多个位置重复出现来表达关系，例如 ``T[] -> T``。
* 参数化多态要求泛型体只能依赖类型参数已经承诺的能力；若函数体需要 ``length``、比较或成员访问，就必须由约束显式提供这些事实。
* 类型参数和普通值参数处在不同阶段：值参数进入运行时调用，类型参数先参与类型检查、约束求解、重载解析或实例化。
* 泛型调用点会提供显式类型实参或由编译器推导类型实参，并把得到的具体关系传播到返回值和内部节点。
* 单态化为实际使用到的具体类型生成专门实例，后端因此能看到精确布局和操作，代价是编译时间和代码体积可能增加。
* 类型擦除在类型检查后把多个泛型实例降低为共享运行时表示，必要时插入转换或桥接逻辑，运行时保留的泛型信息较少。
* C++ template 不只表达泛型关系，还承担实例化、特化和编译期代码生成；依赖于模板参数的错误可能推迟到具体实例化点才出现。
* 显式特化和偏特化允许为特定类型组合提供专门实现，但会扩大候选规则和源码阅读复杂度。

关键路径
--------

``泛型声明 → 建立类型参数与约束 → 检查泛型体只能使用已承诺能力 → 调用点收集/推导类型实参 → 验证约束 → 实例化泛型关系 → 单态化或类型擦除 → IR/字节码/机器码``。

阅读 C++ template 时，还要追加 ``模板定义 → 识别依赖名称与依赖表达式 → 具体模板实参出现 → 实例化 → 重新检查依赖操作 → 选择普通模板/特化 → 生成实体或诊断``。

概念辨析
--------

* **泛型 vs 普通函数复用**：普通复用让多个值调用同一函数；泛型复用让同一类型关系适用于多个类型。
* **参数化多态 vs 动态多态**：前者在类型层抽象并通常于编译期解析；后者通过运行时对象、虚函数表或协议派发选择行为。
* **约束 vs 具体类型**：约束声明类型参数必须具备哪些能力，并不要求它提前等于某个唯一具体类型。
* **单态化 vs 类型擦除**：二者都可实现源语言泛型语义，差异在于具体类型信息是否继续进入后端和运行时表示。
* **C++ template vs 一般 generics**：template 的能力更宽，可接收类型、常量值和模板参数，并参与特化与编译期实体生成。

本章结论
--------

读泛型代码时应依次定位类型参数、约束来源、输入输出关系、泛型体实际使用的操作和最终实现策略。类型参数只允许代码使用签名已证明的能力；具体类型如何落到运行时，则由单态化、擦除或语言特有实例化机制决定。
