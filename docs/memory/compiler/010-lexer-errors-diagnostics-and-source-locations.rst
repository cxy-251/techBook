第010章：Lexer Errors, Diagnostics, and Source Locations
========================================================

核心知识点
----------

* 词法错误发生在字符无法形成合法 token，或 lexer 已进入某种字面量扫描状态但内部格式失效时。
* 常见错误包括未知字符、未知符号序列、未结束字符串、非法 escape、非法数字格式和错误源码位置映射。
* 诊断至少需要错误类别、message、source location/range 和原始 lexeme；源码范围越稳定，IDE、增量编译和错误去重越可靠。
* lexer 出错后不应默认终止；合理恢复可以继续产生后续 token，减少一次编译只暴露一个问题的低效反馈。
* 恢复策略必须保证前进性和位置单调性：每次错误后扫描 offset 必须向前，否则会重复诊断甚至无限循环。
* 是否输出 ERROR token，还是输出“正常 token + 附带诊断”，取决于该 token 是否仍具有可信结构和值。

关键路径
--------

* 普通状态：读取当前位置 → 匹配合法 token 起点 → 无匹配则形成最短稳定错误范围 → 报告诊断 → 移到恢复点。
* 字符串状态：遇到起始引号 → 扫描内容与 escape → 正常闭合则输出 String；遇到非法 escape 可局部诊断；换行/EOF 前未闭合则输出错误并恢复。
* 数字状态：扫描数字主体与合法后缀 → 遇到不允许的连续字符时确定整个错误 lexeme → 报告 invalid numeric literal → 跳到该序列结束。
* 诊断渲染：``FileID + offset/range`` → line/column → 取源码行 → 高亮具体范围 → 输出可行动 message/note/fix-it。
* 恢复后继续 token 化，让 parser 能看到错误之后仍然可靠的结构。

概念辨析
--------

* **invalid character 与 syntax error**：前者 lexer 无法分类当前字符；后者 token 都合法，但排列不符合 grammar。
* **局部字面量错误与不可恢复字面量**：未知 escape 可能仍能找到终止引号；未闭合字符串通常无法得到可信完整 value。
* **错误 token 与诊断列表**：错误可以进入 token stream，也可以独立存储；核心要求是 parser 能前进且 source range 不丢失。
* **恢复点与同步点**：lexer 的恢复点通常是字符级边界；parser 的同步点通常是分号、右括号、语句开头等语法级边界，二者层级不同。

本章结论
--------

词法错误处理的目标是“精确定位、最小吞噬、稳定前进”。实现时应先按当前扫描状态确定错误类型，再生成准确 source range，选择最近可靠恢复点并继续扫描；高质量 lexer 同时为 parser 和用户保留尽可能多的有效证据。
