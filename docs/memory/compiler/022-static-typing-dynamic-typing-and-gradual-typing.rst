第022章：Static Typing, Dynamic Typing, and Gradual Typing
===========================================================

核心知识点
----------

* 静态类型与动态类型的核心差异是类型约束在什么阶段获得足够证据并被检查，而不是语言有没有“类型”。
* 静态类型系统在运行前为变量、表达式、参数、返回值和成员访问建立类型事实，并把部分运行时失败提前为编译期诊断。
* 动态类型系统把对象的实际类型保留到运行时，成员访问、调用和运算在执行点根据真实对象检查是否合法。
* 静态系统面对外部 JSON、反射、动态加载和跨语言边界时，必须通过声明、守卫、schema、断言或较宽类型补充证据。
* 渐进类型允许静态区域和动态区域共存，并规定二者如何互操作；``any``、``dynamic`` 一类逃生口会削弱静态保证。
* 类型标注是否显式、语言是否允许隐式转换、类型兼容采用名义还是结构规则，都是独立于静态/动态检查时机的维度。
* 类型推导仍然可以产生完全静态的类型事实；“没有手写类型标注”不等于“动态类型”。
* 静态与动态边界是排查类型问题的高风险位置，错误常在宽类型穿透后延迟到更远的操作点才暴露。

关键路径
--------

静态路径：``源码/声明 → 类型事实 → 编译期检查 → 诊断或带类型表示 → 运行时执行``。

动态路径：``源码 → AST/字节码 → 运行时对象 → 成员/调用/运算时读取对象类型 → 成功执行或运行时类型错误``。

渐进路径：``静态区域 → 宽类型/动态边界 → 动态值流动 → 再进入静态区域或运行时操作点``。排查时要沿值流找到静态证据何时建立、在哪里被 ``any``、``dynamic``、断言、反射或外部输入削弱，以及最终在哪个操作点失败。

概念辨析
--------

* **静态类型 vs 动态类型**：描述检查时机和证据来源。
* **强类型 vs 弱类型**：更适合具体描述不匹配值是被拒绝还是发生隐式转换，不能与静态/动态画等号。
* **显式类型 vs 类型推导**：描述类型信息由程序员写出还是由编译器推出；二者都可以属于静态类型系统。
* **渐进类型 vs 完全动态**：渐进类型保留静态检查区域，只在特定边界允许动态行为进入。
* **``unknown`` vs ``any``**：前者通常要求先证明后使用，后者往往允许跳过检查并把风险传到后续位置。

本章结论
--------

分析类型策略时不要只给语言贴“静态”或“动态”标签。应追踪一条具体值流，确认类型事实何时建立、在哪一层被验证、哪些边界削弱证据，以及错误最终在编译期、静态/动态边界还是运行时操作点暴露。
