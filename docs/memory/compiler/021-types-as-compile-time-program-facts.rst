第021章：Types as Compile-Time Program Facts
=============================================

核心知识点
----------

* 类型是编译器在运行前建立的程序事实，用来约束值的解释方式、允许的操作、可传递的位置与合法转换。
* 类型检查的基本对象是“表达式实际类型”和“上下文期待类型”；赋值、参数传递、返回、字段访问和运算都依赖二者关系。
* 类型事实可来自显式声明、名字绑定后的声明信息、字面量规则、表达式推导和语言内建规则。
* 类型信息通常附着在 AST、符号表或独立类型上下文中，后续阶段直接复用，不再从源码文本重新推断。
* 源语言类型会在 lowering 中变成更低层约束，例如整数位宽、字段布局、调用签名、IR 操作数类型和返回类型。
* 类型安全的目标是让一部分“语法合法但没有合法语义”的程序在运行前被拒绝。
* 类型事实还能成为优化证据，但只有与语言语义、运行时模型和目标平台约束共同成立时，才足以证明优化合法。

关键路径
--------

``源码表达式 → 名字绑定 → 建立类型事实 → 检查操作规则 → 检查上下文兼容性 → 生成诊断或带类型 AST → lowering 为 typed IR → 后端与优化复用类型事实``。

对函数调用，应依次确定 callee 的函数类型、各实参的实际类型、形参期待类型、兼容性规则和调用结果类型。对字段访问，应先确定接收者类型，再查询成员集合并得到字段类型。对二元运算，应根据操作符与两侧操作数类型选择合法规则并产生结果类型。

概念辨析
--------

* **类型事实 vs 源码标注**：标注只是事实来源之一；推导得到的类型同样是编译器可依赖的事实。
* **类型错误 vs 语法错误**：语法错误无法形成合法结构；类型错误已有合法 AST，只是某个操作、位置或转换不满足类型规则。
* **源语言类型 vs IR 类型**：前者表达语言级值和操作约束，后者表达 lowering 后的位宽、指令、内存和调用约束。
* **类型安全 vs 运行时正确性**：类型系统只能排除其规则覆盖的非法状态，无法证明所有业务逻辑、输入数据和运行时行为都正确。
* **类型事实 vs 优化结论**：类型可以提供证明材料，但优化还必须满足副作用、别名、溢出、可观察行为等其它前提。

本章结论
--------

类型是贯穿前端到后端的编译期知识。稳定的分析顺序是：先找类型事实来源，再看事实存放在哪里，再检查哪些规则消费它，最后确认 lowering 和优化是否仍保持这些事实代表的语言语义。
