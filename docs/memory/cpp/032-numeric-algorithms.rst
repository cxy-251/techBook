第032章：Numeric Algorithms
===========================

核心知识点
----------

* 数值 algorithm 可按输出形态分三类：把区间归约成单值、把每个前缀生成阶段序列、把相邻元素转换成变化量。
* ``accumulate`` 是按迭代器顺序执行的左折叠，适合顺序有意义的归约；初始值 ``init`` 的类型直接决定累加器类型。
* ``reduce`` 允许实现重新分组，带 execution policy 时还可能并行；二元操作必须适合重排，浮点加法等分组敏感操作可能产生结果差异。
* ``inner_product`` 对两个同步区间逐对变换再顺序归约，第二个区间必须至少覆盖第一个区间的长度。
* ``partial_sum`` 生成顺序前缀累计结果；``inclusive_scan`` 包含当前位置，``exclusive_scan`` 输出当前位置之前的累计值并使用显式初值。
* ``adjacent_difference`` 第一项原样输出，后续项默认计算 ``current - previous``；它与加法前缀和在合适数值模型下形成互补变换。
* ``transform_reduce`` 把逐元素/逐对变换和可重排归约组合起来，适合点积、平方和、距离等可并行模型。
* 初始值和中间表达式的类型必须主动检查。``0`` 与 ``0LL`` 可能让同一输入走入不同宽度的累加器和溢出边界。
* 浮点运算不满足数学实数加法的严格结合律；``reduce`` 和并行 scan 允许不同分组，因此最低位差异属于语义边界。
* execution policy 改变执行顺序、并行性和可调用对象要求；有隐藏副作用或顺序依赖的操作不适合直接并行归约。

关键路径
--------

1. 先确定输出需要单值、前缀序列还是相邻变化序列。
2. 单值归约中，操作依赖严格左到右顺序时使用 ``accumulate``；允许重排且希望利用归约优化时考虑 ``reduce``。
3. 两个区间成对计算时，顺序归约用 ``inner_product``；允许重排/并行时考虑 ``transform_reduce``。
4. 生成累计序列时，根据“是否包含当前元素”选择 inclusive/exclusive；业务具有严格时间顺序时优先确认顺序语义。
5. 处理相邻变化时用 ``adjacent_difference``，确认自定义 operation 的参数方向是当前值与前一输入值。
6. 在调用前明确 ``init``、输入 value type、operation 返回类型和输出 value type，检查窄化与整数溢出。
7. 使用 execution policy 或浮点数据时，单独评估重排、并行和可复现性要求。

概念辨析
--------

* **accumulate 与 reduce**：前者固定顺序折叠；后者允许重新分组，适合满足结合/交换需求的归约。
* **inner_product 与 transform_reduce**：二者都是“变换后归约”；前者保持顺序语义，后者为可重排归约族。
* **partial_sum 与 inclusive_scan**：默认加法的可见结果可相同；scan 系列面向 C++17 前缀计算和执行策略模型。
* **inclusive_scan 与 exclusive_scan**：前者输出包含当前输入的前缀，后者输出当前输入之前的前缀并需要初始基准。
* **prefix sum 与 adjacent_difference**：一个从增量构造累计序列，一个从累计序列恢复相邻变化。
* **输入类型与累加器类型**：累加器通常由 ``init`` 决定，输入是宽类型也不能自动保证累加器足够宽。
* **数学结合律与浮点实现**：实数加法的结合性不能直接套到有限精度浮点；分组改变舍入路径。

本章结论
--------

数值算法应按“输出形态 → 顺序语义 → 类型来源 → 区间关系 → execution policy”分析。尤其要把 ``init`` 类型和允许重排的语义当作一级设计条件；否则同一个看似简单的求和或前缀计算会在溢出、浮点重现性和并行执行上产生隐藏差异。
