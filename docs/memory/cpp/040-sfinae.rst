第040章：SFINAE
===============

核心知识点
----------

* SFINAE 的核心语义是 substitution failure is not an error：模板参数替换使某个候选声明失效时，该候选被移出匹配集合，只要还有其他可行候选，整个调用仍可继续完成重载决议。
* SFINAE 发生在模板参数替换阶段，关注函数类型、模板参数声明或偏特化参数表等 immediate context；函数体内部的普通实例化错误通常是硬错误。
* SFINAE 只负责“过滤候选”，不会替代普通重载决议。替换成功后的候选仍要按转换等级、模板偏序等常规规则选择最佳匹配。
* ``decltype(expr)`` 可在未求值语境中检查表达式是否合法，是表达式 SFINAE 的常见基础。
* ``std::enable_if`` 把布尔条件转成类型是否存在的问题；条件为假时没有 ``type``，放在 SFINAE 位置即可过滤候选。
* ``enable_if`` 常放在返回类型、额外模板参数或额外函数参数中；构造函数没有返回类型，因此约束常放到模板参数位置。
* ``std::void_t`` 把合法类型映射成 ``void``，适合用偏特化构建成员/表达式检测。
* Detection idiom 把 ``void_t + decltype + declval`` 的检测过程封装成可复用 traits，用来判断某个操作是否能形成。
* Priority tag 可以结合 SFINAE 构建“先尝试专用接口、失败后回退通用接口”的分层重载路径。
* C++20 concepts 将很多传统 SFINAE 条件提升为声明式约束，但理解 SFINAE 仍是阅读旧 STL、兼容库和底层 traits 的基础。

关键路径
--------

1. 编译器从调用表达式收集同名候选，并对函数模板执行模板参数推导。
2. 把推导结果替换到候选声明的 SFINAE 位置中。
3. immediate context 中的类型或表达式若失效，则删除该候选；合法候选继续保留。
4. 过滤结束后，对剩余候选执行普通重载决议并选择唯一最佳匹配。
5. 只有被选中的模板才继续实例化函数体；函数体中的失败不再由 SFINAE 自动吞掉。
6. 阅读源码时先定位约束写在返回类型、模板参数、形参还是偏特化上，再判断它控制的是候选存在性还是实现内部路径。

概念辨析
--------

* **substitution failure 与编译错误**：声明表面 immediate context 的替换失效可过滤候选；更深层实例化错误通常直接形成诊断。
* **SFINAE 与重载决议**：SFINAE 先删候选，重载决议再从剩余候选中选最佳者。
* **enable_if 与 void_t**：``enable_if`` 常基于已有布尔条件过滤候选；``void_t`` 更适合把“某个类型/表达式是否存在”转成检测结果。
* **decltype 检测与执行**：``decltype`` 中表达式通常不被实际执行，只用于检查其类型合法性。
* **SFINAE 与 concepts**：前者依赖替换失败间接表达约束；后者把约束直接写入接口并参与约束偏序。

本章结论
--------

SFINAE 应按“候选生成 → 模板替换 → 候选过滤 → 普通重载决议”理解。排查模板代码时先确认失败是否位于 immediate context，再看候选是否被删除以及剩余重载为何胜出；不要把函数体硬错误误认为 SFINAE 机制的一部分。
