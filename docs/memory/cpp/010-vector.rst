第010章：Vector
================

核心知识点
----------

``std::vector<T>`` 是动态大小的连续序列容器。普通元素版本满足连续存储要求，核心状态可以抽象为 ``begin``、``end``、``cap`` 三个边界：``[begin,end)`` 是已经构造的元素，``[end,cap)`` 是已分配但尚未构造对象的原始存储。

``size()`` 表示活元素数量，``capacity()`` 表示当前存储最多能容纳多少元素。``data()`` 暴露当前连续元素区起点；只要发生重新分配，所有指向旧存储的 iterator、pointer 和 reference 都失效。

``reserve(n)`` 只保证容量至少达到 ``n``，不会创建元素；``resize(n)`` 改变元素数量，扩大时构造新元素，缩小时销毁尾部元素；``shrink_to_fit()`` 只是收缩请求，是否真的降低 capacity 由实现决定。

``push_back`` 从已有对象拷贝或移动构造尾部元素；``emplace_back`` 把构造参数直接传到目标位置。二者的主要成本边界不是临时对象数量，而是当前容量是否足够；容量不足时要迁移整段旧元素。

中间 ``insert`` 必须打开连续空位，容量足够时也要移动后缀元素；``erase`` 销毁目标元素并前移后缀。连续存储带来高局部性和 O(1) 随机访问，也把中间修改成本变成 O(n)。

扩容时容器需要先建立新状态，再提交新三指针。元素迁移通常依据移动构造是否 ``noexcept``、拷贝构造是否可用，在 move/copy 之间选择，以维持异常安全。

``vector<bool>`` 是特殊化边界，常用 bit-level 存储并返回代理引用，不能把它完全按普通 ``vector<T>`` 的元素地址模型理解。

关键路径
--------

无重分配的尾部追加路径：

``end < cap → 在 end 构造新元素 → end++``。

需要扩容时：

``容量不足 → allocate 更大连续存储 → 在新存储逐个 move/copy construct 旧元素 → 构造新元素 → 全部成功后销毁旧元素 → deallocate 旧存储 → 提交 begin/end/cap``。

``reserve`` 的判断路径是：

``n <= capacity → 不换存储；n > capacity → 分配新块并迁移全部活元素 → 所有旧位置对象失效``。

中间插入：

``确定 pos → 若容量不足先重分配 → 后缀从尾向后移动/构造 → 在 pos 写入新元素 → 更新 end``。

中间擦除：

``销毁/覆盖目标位置 → 后缀向前移动 → 销毁旧尾部重复元素 → end 前移``。

因此判断 iterator 失效时，先看是否发生重分配；若没有，再看操作位置是否导致该位置及其后方元素发生移动。

概念辨析
--------

``reserve`` 不等于 ``resize``。reserve 管容量，resize 管元素数量。

``capacity`` 不等于已有对象数量。``size`` 到 ``capacity`` 之间没有可通过普通元素接口访问的活对象。

``emplace_back`` 不等于“永远零拷贝”。它只省去显式临时对象的某些构造步骤；若触发扩容，旧元素仍然需要迁移。

``尾部摊还 O(1)`` 不等于每次都是 O(1)。发生 reallocation 的那一次追加是 O(n)，长期平均后才得到摊还常数复杂度。

``连续存储`` 不等于地址永久稳定。只要 capacity 改变，旧地址整体失效。

``erase`` 不会自动缩小 capacity。它主要缩短活元素区，底层存储通常继续保留。

本章结论
--------

读 vector 源码或分析性能时，固定按“size/capacity → 是否换存储 → 元素构造/迁移/销毁 → 提交点 → iterator 失效”判断。vector 的优势来自连续内存、随机访问和摊还尾部增长；它的主要代价来自重分配和中间元素搬移。
