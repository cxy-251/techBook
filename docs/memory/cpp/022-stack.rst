第022章：Stack
==============

核心知识点
----------

* ``std::stack<T, Container>`` 是容器适配器：它不定义新的元素存储结构，只把底层容器接口收窄成 LIFO（Last-In First-Out）。
* 标准语义只允许访问最近压入且尚未弹出的元素；核心接口是 ``push`` / ``emplace``、``top``、``pop``、``empty``、``size``。
* 适配器通常持有底层容器 ``c``；``top()`` 对应 ``c.back()``，``push()`` 对应 ``c.push_back()``，``pop()`` 对应 ``c.pop_back()``。
* 底层容器的 ``value_type`` 必须与 ``T`` 一致，并提供 ``back``、``push_back``、``pop_back``。默认底层容器是 ``std::deque<T>``。
* ``std::vector`` 也可作为底层容器，连续存储和局部性更好，但扩容可能迁移全部元素；``std::list`` 可用，但节点分配与指针追踪成本更高。
* ``top()`` 返回引用，不复制元素；``pop()`` 返回 ``void``。需要取出栈顶值时，应先读取或移动 ``top()``，再 ``pop()``。
* 对空栈调用 ``top()`` 或 ``pop()`` 不满足接口前提；调用前必须先建立 ``!empty()`` 条件。
* ``std::stack`` 不暴露 iterator；需要遍历、中间访问或任意删除时，需求本身已超出 stack 抽象。

关键路径
--------

LIFO 主路径：

``push(value)`` → 底层 ``push_back`` 构造新元素 → 新元素成为 ``back`` → ``top()`` 返回该元素引用 → ``pop()`` 调用 ``pop_back`` → 栈顶元素析构 → 前一个元素重新成为栈顶。

取出栈顶对象时应按以下顺序：

::

   if (!s.empty()) {
       T value = std::move(s.top());
       s.pop();
       use(std::move(value));
   }

底层为 ``vector`` 时，``push`` 可能触发扩容：申请新存储 → 移动/拷贝已有元素 → 提交新存储 → 旧地址失效。因此跨 ``push`` 长期保存 ``top()`` 返回的引用需要重新判断。

概念辨析
--------

* **stack 与底层容器**：stack 决定 LIFO 接口语义；deque/vector/list 决定具体存储、分配、引用稳定性与缓存行为。
* **push 与 emplace**：``push`` 从已有值拷贝/移动构造栈顶对象；``emplace`` 把构造参数直接转发到底层 ``emplace_back``。
* **top 与 pop**：``top`` 只访问当前栈顶；``pop`` 只删除当前栈顶。标准接口故意把“读取”和“删除”拆开。
* **LIFO 与普通序列**：需要查看最近状态、回溯、撤销、显式 DFS 时适合 stack；需要遍历历史或访问任意位置时直接使用底层序列更合适。
* **默认 deque 与 vector**：deque 避免整段连续存储扩容迁移；vector 在规模可预估、强调局部性时可能更合适。

本章结论
--------

``std::stack`` 的核心不是一种新的数据结构实现，而是把普通序列容器收窄成严格 LIFO 接口。读源码时只需抓住 ``top → back``、``push → push_back``、``pop → pop_back`` 三条转发关系，再把性能、引用失效和分配成本交给底层容器分析。工程上先确认业务是否只依赖“最近状态”，再选择底层容器；一旦需要遍历或非栈顶访问，就应退出 stack 抽象。
