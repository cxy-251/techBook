第028章：Sorting Algorithms
===========================

核心知识点
----------

* 排序需求应先按结果强度分类：完整排序、稳定完整排序、前 K 有序、只定位第 N 个分界点。
* ``std::sort`` 交付完整有序区间，不保证比较器等价元素保持原相对顺序；``std::stable_sort`` 额外保证稳定性。
* ``std::partial_sort(first, middle, last)`` 只保证前缀 ``[first, middle)`` 包含最靠前的 K 个元素且该前缀有序，尾部顺序未指定。
* ``std::nth_element`` 只建立 ``nth`` 位置及两侧分区关系，两侧内部不排序，适合中位数、百分位、Top-K 阈值。
* ``sort``、``stable_sort``、``partial_sort``、``nth_element`` 都依赖 random access iterator；节点链表应使用自己的排序成员或适合其结构的算法。
* comparator 必须形成严格弱序；比较器同时定义排序方向和“等价元素”的边界。
* ``is_sorted`` 只返回整体有序性，``is_sorted_until`` 返回第一处破坏有序前缀的位置；检测时必须使用与排序/查询阶段一致的 comparator。
* 常见 ``sort`` 实现采用 introsort 一类混合策略以控制最坏复杂度；具体内部策略属于实现细节，工程依赖应落在标准结果和复杂度承诺上。
* 元素移动成本可能比比较成本更重要；大对象场景可考虑排序索引、指针或轻量句柄。

关键路径
--------

1. 先确定后续代码真正消费的结果：全区间、稳定分组、前 K、还是单个分位位置。
2. 需要全排序时在 ``sort`` 与 ``stable_sort`` 之间按稳定性选择；只需要前 K 有序用 ``partial_sort``；只要阈值/第 N 个元素用 ``nth_element``。
3. 检查 iterator 是否满足 random access，元素是否可被算法移动/交换。
4. 验证 comparator：自比较为 false，方向不矛盾，传递关系稳定；同一次数据管线中的排序和二分必须保持同一关系。
5. 根据 N、K、稳定性、比较器成本、元素移动成本与额外内存决定最终实现。
6. 调试前置条件时用 ``is_sorted``；需要定位首个断点时用 ``is_sorted_until``。

概念辨析
--------

* **sort 与 stable_sort**：二者都完整排序；稳定排序额外保留等价元素原相对顺序。
* **partial_sort 与 nth_element**：前者保证前 K 元素本身有序；后者只保证分区与 nth 位置。
* **有序与稳定**：有序描述 comparator 关系，稳定描述等价元素的原先相对顺序。
* **比较相等与 operator==**：排序算法中的等价是 ``!comp(a,b) && !comp(b,a)``，不要求 ``a == b``。
* **算法复杂度与真实成本**：比较次数只是一个维度，元素移动、缓存局部性和临时内存也会影响实际性能。
* **排序算法与链表成员 sort**：通用排序依赖随机访问；节点容器可以通过重连节点提供更匹配的数据结构路径。

本章结论
--------

排序算法的核心不是“全部调用 sort”，而是只购买后续真正需要的结果强度。先确定全排序、稳定性、Top K 或分位点，再检查 iterator、比较器、元素移动和内存成本，才能选出正确算法。
