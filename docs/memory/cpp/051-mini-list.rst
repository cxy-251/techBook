第051章：Mini List
==================

核心知识点
----------

* 双向链表的最稳定实现模型是“哨兵节点 + 普通节点”。空表时哨兵的 ``prev`` 和 ``next`` 都指向自身。
* 普通节点保存 ``prev``、``next`` 和元素；哨兵只承担端点关系，因此 ``begin`` 可指向 ``sentinel.next``，``end`` 直接指向哨兵。
* list iterator 只需保存当前节点地址；``++`` 沿 ``next``，``--`` 沿 ``prev``，能力属于 bidirectional iterator。
* 插入已有位置不会搬移其他节点，因此已有元素地址和对应 iterator 通常保持稳定。
* ``insert/emplace`` 的安全顺序是：分配节点、构造元素、局部链接提交、更新 size。
* ``erase`` 的顺序是：保存后继、断链、销毁节点对象、释放节点存储、更新 size。
* ``splice`` 的本质是区间节点重连；只要 allocator 与接口前提允许，就无需逐元素复制或移动。
* node allocator 通常由元素 allocator 通过 ``allocator_traits::rebind_alloc`` 获得。

关键路径
--------

1. 创建空表时初始化哨兵自环，形成统一的空/非空端点模型。
2. ``emplace(pos, ...)`` 先分配并构造 fresh node；构造失败时只释放该独立节点。
3. 构造成功后执行 ``before <-> fresh <-> pos`` 的四个局部指针更新，再增加 ``size``。
4. ``erase(pos)`` 先保存 ``pos->next``，再让前驱和后继直接相连；随后销毁释放 victim，并返回保存的后继位置。
5. ``clear`` 从哨兵之后依次断链并销毁全部节点，最后恢复哨兵自环。
6. ``splice`` 先截断源区间两端，再把整段区间接入目标位置，两边 size 按转移数量更新。

概念辨析
--------

* **哨兵 vs 空指针端点**：哨兵让 ``begin/end``、``--end`` 和边界插入统一为普通链接操作，减少特殊分支。
* **节点地址稳定 vs iterator 永久有效**：插入通常不使旧 iterator 失效；被 erase 的节点及其 iterator 立即失效。
* **list iterator vs random access iterator**：双向链表只能按链接逐步移动，无法用常数时间 ``it+n``。
* **断链 vs 销毁**：断链只修改拓扑；节点对象仍然存在，随后才执行析构与释放。
* **splice vs copy/move**：splice 转移节点所有权和链接关系，不重新构造元素。

本章结论
--------

list 的正确性主要来自链表拓扑不变量：相邻节点的 ``next/prev`` 必须双向一致，哨兵必须始终正确表示首尾。实现修改操作时，应先在独立节点上完成可能失败的构造，再用不抛异常的局部指针重连完成提交。
