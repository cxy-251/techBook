第033章：Function Objects
=========================

核心知识点
----------

* 函数对象是提供 ``operator()`` 的对象类型；调用语法像函数，语义仍是对象上的成员函数调用。
* STL 把比较、筛选、变换和策略行为作为 callable 传入，使算法负责遍历，函数对象负责单次决策。
* 具体函数对象类型在模板实例化时可见，因此编译器拥有内联、常量传播和空对象优化的机会。
* 算法通常按值接收谓词或比较器；函数对象的复制、移动和内部状态生命周期必须满足调用路径要求。
* ``std::less``、``std::greater``、``std::equal_to`` 等标准函数对象把常见运算包装成统一 callable。
* 排序算法与有序容器的比较器必须形成严格弱序；比较器同时定义排序方向和“等价键”边界。
* ``std::less<>`` 等透明比较器通过 ``is_transparent`` 支持异构查找，减少不必要的临时 key 构造。
* 自定义透明比较器的所有异构重载必须表达同一排序关系，否则建树和查询会沿不同方向运行。
* stateful functor 适合保存阈值、排序方向、投影字段等只读策略状态；值状态复制后通常最稳定。
* 引用状态把 callable 的正确性绑定到外部对象生命周期；跨线程或长期保存时需要明确所有权和同步。
* 谓词和比较器的业务结果不应依赖“被调用了几次”或隐藏副作用，因为算法可能复制 callable 并以实现决定的方式调用。
* 模板报错应沿“算法需要的调用表达式 → 实参类型 → 返回值/写入位置”回到用户提供的函数对象。

关键路径
--------

1. 先确定算法需要的是一元谓词、二元比较器、变换函数、哈希函数还是其他策略 callable。
2. 检查 ``operator()`` 的参数能否绑定算法传入的元素类型，返回值是否满足算法契约。
3. 比较器进入排序或有序容器前，验证 irreflexive、非对称、传递性和诱导等价关系。
4. 需要异构查找时，再检查透明比较器是否提供一致的跨类型比较方向。
5. callable 带状态时，确认状态是值、引用、指针还是共享对象，并验证算法复制后的语义是否仍成立。
6. callable 可能长期保存、跨线程或延迟调用时，重新检查状态生命周期和同步边界。
7. 性能分析时再比较具体函数对象、lambda 和 type-erased wrapper 的调用路径，不先假设虚拟化或分配成本。

概念辨析
--------

* **函数对象与普通函数**：函数对象拥有对象类型和可保存状态；普通函数本身没有实例状态。
* **函数对象与 lambda**：lambda 生成匿名闭包类型，本质仍是函数对象；显式函数对象更适合具名、复用和复杂不变量。
* **比较器与相等谓词**：排序比较器定义“谁在前”，相等谓词定义“是否相等”；``equal_to`` 不能替代严格弱序比较器。
* **排序等价与 ``operator==``**：有序容器中的等价由 ``!comp(a,b) && !comp(b,a)`` 定义，不要求对象完全相等。
* **透明比较器与普通比较器**：透明比较器允许另一种查询类型直接参与同一排序关系，普通比较器通常只接受 key 类型。
* **状态仿函数与隐藏副作用**：保存只读配置属于稳定状态；依赖调用次数累积业务结果会受到 callable 副本和执行策略影响。
* **编译期多态与运行时类型擦除**：具体函数对象保留类型信息；需要把不同 callable 放入同一种运行时槽位时才进入 ``std::function`` 等 wrapper。

本章结论
--------

函数对象应按“调用签名 → 状态生命周期 → 语义前提 → 复制移动 → 标准版本”分析。局部一次性规则通常用 lambda，具名可复用策略适合显式函数对象；只有需要运行时隐藏具体 callable 类型时，才需要进一步引入类型擦除包装器。
