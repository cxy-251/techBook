第024章：Priority Queue
=======================

核心知识点
----------

* ``std::priority_queue<T, Container, Compare>`` 是基于二叉堆的容器适配器：调用方持续插入元素，每次只能快速访问当前最高优先级元素。
* 适配器通常持有底层容器 ``c`` 和比较器 ``comp``；``top()`` 对应 ``c.front()``，``push`` / ``emplace`` 在末尾加入元素后执行堆上浮，``pop`` 先调整堆再删除末尾元素。
* 默认底层容器是 ``std::vector<T>``。底层容器必须支持随机访问 iterator，以及 ``front``、``push_back``、``pop_back``；``std::deque`` 可用，``std::list`` 不满足随机访问要求。
* 二叉堆用数组下标表达树：父节点 ``(i-1)/2``，左孩子 ``2*i+1``，右孩子 ``2*i+2``。它只保证父子优先级关系，不保证整个数组完全有序。
* 默认 ``Compare = std::less<T>`` 时形成最大堆，``top()`` 返回最大元素；使用 ``std::greater<T>`` 时形成最小堆。
* ``Compare(a, b) == true`` 表示 ``a`` 在弱序中排在 ``b`` 前面，而 ``top`` 返回该关系中排在最后的元素。自定义比较器必须满足严格弱序。
* ``top()`` 返回 ``const_reference``，调用者不能直接修改堆顶关键字段；否则会破坏堆不变量。
* ``priority_queue`` 不提供 iterator、任意查找、任意删除或 decrease-key / increase-key。优先级改变通常通过重新插入、过期标记或换用支持定位更新的数据结构处理。

关键路径
--------

插入路径：

``push(x)`` → ``c.push_back(x)`` → 新元素位于数组末尾 → 与父节点比较 → 持续上浮 → 堆不变量恢复 → ``c.front()`` 成为当前最高优先级元素。

删除路径：

``pop()`` → 将堆顶与末尾区域调整 → 对剩余区间执行下沉修复 → 原堆顶移动到末尾 → ``c.pop_back()`` 销毁原堆顶。

批量构造路径通常是：初始化底层随机访问区间 → ``make_heap`` → 线性时间建立堆。逐个 ``push`` 构建则每次可能执行对数级上浮。

概念辨析
--------

* **priority_queue 与有序容器**：priority_queue 只保证 ``top`` 最优，内部不是全排序；``set`` / ``multiset`` 维持完整有序关系并支持迭代和查找。
* **heap 与 sorted array**：堆只维护局部父子不变量，因此插入/删除顶部为 ``O(log N)``；完全排序要求更强的全局顺序。
* **Compare 与“优先级更高”**：比较器描述弱序，不直接回答“谁先出队”。``top`` 返回比较关系下的最后元素，比较方向必须按这个规则推导。
* **vector 与 deque**：二者都提供随机访问，可作为底层容器；vector 连续存储和局部性更好，扩容会搬移元素；deque 使用分段存储。
* **top 与 pop**：``top`` 只读当前堆顶，``pop`` 删除它且不返回值；需要保留元素时必须先复制/移动到局部对象。
* **priority_queue 与可更新优先级结构**：标准适配器不支持按句柄修改内部节点优先级；调度器需要频繁更新已有任务时，应考虑额外索引、重新插入或其他 heap/tree 结构。

本章结论
--------

``std::priority_queue`` 的稳定模型是“随机访问容器上的二叉堆 + 比较器 + 受限接口”。源码阅读时抓住 ``push_back + push_heap``、``front``、``pop_heap + pop_back`` 三条主线即可。它适合任务调度、Top-K、延迟队列等只关心当前最优元素的场景；一旦需要遍历、任意查找、删除或原地更新优先级，就应重新评估数据结构。
