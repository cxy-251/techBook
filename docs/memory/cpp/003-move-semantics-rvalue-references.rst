第003章：Move Semantics and Rvalue References
==============================================

核心知识点
----------

移动语义的目标是转移资源责任，避免对堆内存、句柄或其它昂贵状态做不必要深拷贝。移动是否发生，首先取决于表达式的 value category，再由重载决议选择移动构造、移动赋值或其它右值入口。

现代 C++ 需要区分 ``lvalue``、``xvalue``、``prvalue``。lvalue 表示具有可重复定位身份的表达式；prvalue 提供值；xvalue 既有对象身份，又表示其资源可以被复用。rvalue 是 xvalue 与 prvalue 的合称。

``T&`` 通常绑定可修改 lvalue；``const T&`` 可绑定 lvalue 与 rvalue，常用于只读借用；``T&&`` 通常绑定 rvalue，作为可消耗入口。变量名表达式本身通常是 lvalue，即使变量的声明类型是 ``T&&``。

``std::move(x)`` 只把表达式转换成 xvalue。它不搬内存、不调用移动构造，也不修改 ``x``；真正的资源转移发生在后续接收这个 xvalue 的构造、赋值或函数调用中。

移动后的源对象仍处于生命周期内。标准库类型通常要求 moved-from 对象保持 valid but unspecified state：可以析构、重新赋值，并可调用满足前置条件的操作，但其业务值通常没有稳定保证。

移动构造用于创建新对象并接管资源；移动赋值还需要先处理目标对象已有资源。资源拥有型类型的移动操作通常把源对象资源句柄置为安全空状态，确保双方都能独立析构。

关键路径
--------

一次典型资源移动路径是：

``已有对象 src → std::move(src) 产生 xvalue → 选择 T(T&&) → dst 接管资源 → src 进入 moved-from 状态 → 两个对象分别继续生命周期``。

vector 扩容中的元素迁移路径通常是：

``申请新存储 → 对旧元素逐个选择 move/copy 构造 → 新元素全部成功 → 销毁旧元素 → 释放旧存储 → 提交新状态``。

若元素移动构造可能抛异常，而拷贝构造可用，容器为了维持更强异常安全可能选择拷贝。``std::move_if_noexcept`` 正是把“移动成本”和“失败后能否回滚”连接起来的选择入口。

完美转发路径是：

``模板参数推导 T → 形参 T&& 形成 forwarding reference → 函数体内形参名是 lvalue → std::forward<T>(arg) 恢复调用点原始 value category → 下游选择正确重载``。

因此 ``std::move`` 表达“把这里当作可移动对象”，``std::forward`` 表达“保持调用方原来的值类别”。

概念辨析
--------

``右值引用类型`` 不等于 ``右值表达式``。命名为 ``arg`` 的 ``T&& arg`` 在函数体中，表达式 ``arg`` 是 lvalue；要再次进入右值路径需显式 move 或 forward。

``std::move`` 不等于 ``移动操作``。它只是 cast；真正改变对象状态的是后续移动构造、移动赋值或其它消费右值的逻辑。

``moved-from`` 不等于 ``已析构``。源对象仍然存在，析构函数最终仍会执行；移动实现必须保证源对象后续析构安全。

``move`` 不保证地址稳定。vector 发生 reallocation 时，即使元素使用移动构造迁移，旧元素地址、引用、指针和 iterator 仍会失效。

``noexcept`` 不只是文档说明。对资源类型的移动构造而言，是否 ``noexcept`` 会直接影响标准容器在扩容时是否愿意走移动路径。

本章结论
--------

读移动语义代码时固定按“表达式 value category → 引用绑定 → 重载选择 → 真正资源转移动作 → moved-from 状态 → noexcept/异常安全后果”判断。对 STL 来说，移动语义的价值不在语法，而在让容器能低成本迁移元素，同时仍然保持资源唯一性、对象可析构性和异常安全。
