第011章：Array
===============

核心知识点
----------

``std::array<T, N>`` 是固定大小、连续存储的标准容器。``N`` 是模板参数并参与类型身份，因此 ``array<int,4>`` 与 ``array<int,8>`` 是不同类型；对象创建后元素数量始终为 ``N``。

array 直接把元素作为自身状态保存，不需要额外动态分配。它放在哪里，元素就跟着放在哪里：局部 array 通常位于局部对象存储中，作为成员时元素内嵌在外层对象布局里。

array 同时具备原生数组的固定连续布局和标准容器接口：``begin/end``、``data``、``size``、随机访问 iterator、算法集成、tuple interface。它适合“长度在编译期已知，同时希望保留 STL 接口”的场景。

``std::array`` 是 aggregate，花括号初始化按元素顺序进行；少于 ``N`` 个显式初始化器时，剩余元素按规则补初始化。``std::array<int,3>{}`` 会把三个元素值初始化为 0，而无初始化器的默认初始化对标量元素可能留下不确定值。

大量成员函数支持 ``constexpr``，固定查表、协议字段、编译期权重等可以直接放入 ``constexpr std::array``。C++20 的 ``std::to_array`` 可把内建数组转换为保留大小信息的 array。

array 的 iterator 在容器生命周期内通常具有稳定地址，因为容器没有容量扩张；赋值会修改对应元素值，``swap`` 按元素交换，不会重新分配存储。

``array<T,0>`` 是合法类型，但 ``front``、``back`` 和任何解引用都没有元素前提；``begin()==end()`` 是零长度范围的稳定判断。

关键路径
--------

对象建立路径：

``形成 array<T,N> 类型 → 外层对象取得存储 → N 个元素按 aggregate initialization 构造 → 整个 array 生命周期开始``。

算法使用路径：

``array 对象 → begin/end 形成连续随机访问范围 → STL 算法只依赖 iterator 能力 → 元素原地读写``。

接口借用路径常写成：

``array<T,N> 拥有元素 → data()/begin() 暴露位置 → span<T> 借用连续范围 → 调用结束后所有权仍属于 array``。

复制与赋值按元素进行：

``读取源 array 对应位置 → 对目标每个元素执行 copy/move assignment 或构造 → 目标仍保持固定 N 个元素``。

``swap`` 也是按元素交换，因此复杂度为 O(N)，不像某些动态容器只交换少量内部指针。

概念辨析
--------

``std::array`` 不等于动态数组。大小属于类型，运行时不能改变元素数量。

``std::array`` 不等于 C 数组。两者都可连续内嵌，但 array 提供值语义、标准容器接口、算法集成和类型化长度。

``array`` 不等于 ``vector``。vector 的容量和元素存储通常动态分配；array 的元素直接嵌入对象，生命周期与外层对象一致。

``固定大小`` 不等于“只能运行时使用”。因为 ``N`` 是编译期信息，array 特别适合 constexpr 数据与模板接口。

``iterator 稳定`` 不等于元素值不变。赋值和 swap 会改变对应位置里的值，但通常不会让位置对象指向另一块存储。

``array<T,0>`` 有容器对象，不代表有可访问元素。空范围接口可以使用，首尾元素访问需要非空前提。

本章结论
--------

当长度天然属于协议、算法或类型定义，并且需要连续存储与 STL 接口时，优先考虑 ``std::array``。判断时依次看“长度是否编译期固定 → 是否需要对象拥有元素 → 是否需要连续地址 → 是否需要标准 range/algorithm 接口 → 是否接受按元素复制和 swap 成本”。
