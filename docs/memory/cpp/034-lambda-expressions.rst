第034章：Lambda Expressions
===========================

核心知识点
----------

* Lambda 表达式求值会产生 closure object；其 closure type 是编译器生成的唯一、未命名类类型。
* STL 不识别“lambda 语法”，算法只看到一个拥有 ``operator()`` 的 callable 对象。
* 空捕获 lambda 通常是无状态闭包，并在满足规则时可转换为普通函数指针；带捕获 lambda 需要对象状态，不能按普通函数指针保存。
* 值捕获把创建 lambda 时的状态保存为闭包成员，适合快照语义；闭包被复制时，值捕获成员也随之复制。
* 引用捕获让闭包访问外部对象当前状态，不延长被引用对象生命周期；长期保存、异步执行或返回闭包时最容易产生悬垂引用。
* 初始化捕获从 C++14 起允许直接构造闭包成员，可用于移动 ``unique_ptr``、大对象或自定义所有权状态。
* ``[this]`` 保存当前对象指针并依赖原对象生命周期；C++17 的 ``[*this]`` 保存对象副本，表达快照语义。
* 默认非静态 lambda 的 ``operator()`` 为 ``const``；``mutable`` 让调用运算符可修改值捕获成员，但不会把值捕获变成引用捕获。
* ``mutable`` 状态属于具体闭包对象；算法复制 lambda 后，不应把某个外部闭包实例的内部计数当成算法结果来源。
* generic lambda 使用 ``auto`` 形参，本质上生成模板化调用运算符；具体参数类型在调用或算法实例化时推导。
* Lambda 进入 STL 算法后仍必须满足算法的谓词、比较器、变换函数等语义契约。
* 排序比较器必须保持严格弱序，结果不应依赖调用次数、随机状态或排序过程中正在变化的比较字段。

关键路径
--------

1. 先确认算法要求的 callable 角色和调用签名。
2. 把 lambda 还原成“闭包类型 + 捕获成员 + ``operator()``”，明确闭包真正保存了什么。
3. 对每个捕获判断是快照、外部引用、指针还是拥有型状态，并核对其生命周期。
4. 闭包会离开当前函数、进入回调系统、异步任务或线程时，优先重新审查引用捕获和 ``this`` 捕获。
5. 使用 ``mutable`` 时，确认修改的是闭包副本还是外部共享状态，避免依赖算法内部 callable 副本的调用次数。
6. generic lambda 进入模板算法时，沿实际推导出的参数类型检查约束和返回值。
7. 比较器或谓词参与排序、二分和移除等算法时，确认捕获状态在整个调用期间保持语义稳定。

概念辨析
--------

* **lambda 与函数对象**：lambda 是生成匿名函数对象的语言语法；显式函数对象拥有可命名类型和更适合复用的结构。
* **值捕获与引用捕获**：值捕获拥有快照，引用捕获观察外部当前状态并依赖外部生命周期。
* **``[this]`` 与 ``[*this]``**：前者保存指针，后者保存当前对象副本；两者的生命周期和状态可见性完全不同。
* **``mutable`` 与引用捕获**：``mutable`` 只改变闭包自身 ``operator()`` 的 const 性；引用捕获即使没有 ``mutable`` 也可修改外部非 const 对象。
* **闭包对象与函数指针**：函数指针只保存代码入口；捕获闭包还需要保存环境状态。
* **generic lambda 与普通 lambda**：generic lambda 的调用运算符是模板化入口，同一闭包类型可为多组实参类型实例化调用路径。
* **算法副作用与 lambda 状态**：算法可能复制 callable；依赖某一个闭包副本内部状态的副作用通常不构成稳定算法契约。

本章结论
--------

Lambda 应按“算法契约 → 闭包类型 → 捕获对象 → 生命周期 → 复制边界 → 副作用范围”分析。局部、一次性、捕获少的规则适合 lambda；需要长期保存时优先把所有权写清楚，需要复用、复杂状态或独立测试时则应考虑显式函数对象。
