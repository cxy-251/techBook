第002章：Object Lifetime
========================

核心知识点
----------

对象生命周期从“目标对象初始化完成”开始，到析构开始、存储被复用或其它标准规定的终止点结束。存储存在只是前提，真正决定能否按类型访问的是对象生命周期。

构造与赋值必须严格区分。构造处理尚未存在的目标对象，建立新生命周期；赋值处理已经活着的对象，先维护或替换旧状态，再建立新的值状态。判断 ``T x(y)`` 与 ``x = y`` 时，先看目标对象在操作前是否已经存在。

拷贝构造为新对象建立与源对象对应的独立状态；移动构造把可转移资源交给新对象，同时保持源对象仍然有效、可析构。拷贝赋值和移动赋值还需要先处理目标对象原有资源。

临时对象通常在完整表达式结束时销毁；某些引用绑定会延长临时对象生命周期。生命周期延长只解决对象“还能活多久”，不自动改变所有权，也不意味着引用拥有对象。

RAII 把资源责任绑定到对象生命周期：构造成功后资源责任成立，析构关闭责任。容器管理元素生命周期，元素类型通过自己的 RAII 继续管理堆内存、文件句柄等内部资源。

关键路径
--------

原始存储中的对象创建路径是：

``取得满足 sizeof/alignof 的存储 → construct_at / placement construction → 初始化完成 → 活对象 → destroy_at / 析构 → 原始存储``。

vector 扩容时的生命周期主线是：

``取得新存储 → 在新存储逐个构造元素 → 若失败则销毁已构造新元素并释放新存储 → 全部成功后销毁旧元素 → 释放旧存储 → 提交新 begin/end/capacity``。

构造失败时，尚未完成初始化的对象不会进入完整生命周期；已经完成构造的对象必须正常析构。多元素构造过程因此需要记录“已经成功构造到哪里”。

赋值路径则是：

``目标对象已存在 → 准备新状态 → 处理异常边界 → 释放或替换旧资源 → 提交新状态 → 保持目标对象继续处于同一生命周期``。

判断容器操作时，先确认当前位置是未构造槽位还是活元素。``emplace_back`` 在新槽位创建对象；``operator[] = value`` 给已有元素赋值；``erase`` 结束对象生命周期并可能移动后续元素；``clear`` 销毁元素但通常不释放容量。

概念辨析
--------

``构造`` 不等于 ``赋值``。构造建立对象，赋值修改已有对象；两者调用不同的特殊成员函数，也承担不同的旧资源处理责任。

``移动`` 不等于 ``销毁源对象``。移动后的源对象生命周期继续存在，必须保持可析构，并满足其类型规定的 moved-from 状态约束。

``clear`` 不等于 ``释放容器存储``。对 vector 而言，clear 主要结束元素生命周期并把 size 变为零，capacity 通常保留。

``reserve`` 不等于 ``创建元素``。reserve 调整可用存储容量，新增槽位仍是未构造存储；元素数量由实际构造成功的对象决定。

``引用延长临时生命周期`` 不等于 ``引用拥有对象``。引用没有独立资源释放责任，生命周期规则只保证特定绑定场景中的临时对象不会过早销毁。

本章结论
--------

读 STL 生命周期源码时，固定按“存储 → 构造 → 活对象 → 赋值/迁移 → 析构 → 存储释放 → 状态提交”检查。扩容、插入、擦除和异常回滚的正确性，本质上取决于容器始终准确知道哪些位置只是存储、哪些位置已经存在活对象。
