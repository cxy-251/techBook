第016章：Red-Black Tree Foundations
===================================

核心知识点
----------

* 有序关联容器需要同时维持按 key 查找、更新和有序遍历；底层结构必须同时满足二叉搜索树顺序与受控高度。
* BST 不变量是：任一节点左子树 key 按比较器排在当前 key 之前，右子树排在当前 key 之后；中序遍历因此得到有序序列。
* 普通 BST 的复杂度取决于树高。顺序输入可退化成链，查找、插入和删除由 ``O(log N)`` 退化到 ``O(N)``。
* 红黑树在 BST 节点上增加颜色状态，通过根黑、红节点不连续、各路径黑高一致等规则限制树高。
* 红黑树的稳定模型是：BST 顺序保证查找正确性，颜色不变量保证高度上界。
* 左旋和右旋只重排局部父子关系，不改变中序顺序；旋转负责调整形状，重新染色负责恢复颜色规则。
* 新节点通常先按 BST 规则插入并标红。红色插入不会直接改变黑高，主要修复目标是红父红子的连续冲突。
* 删除黑节点可能破坏 black height，因此删除修复通常比插入修复复杂，需要围绕兄弟节点、兄弟子节点颜色和旋转组合恢复平衡。
* 节点式平衡树的旋转只改链接关系，已有元素对象通常不搬移，这为 ``map`` / ``set`` 的位置稳定性提供基础。

关键路径
--------

**查找 / lower_bound**

``root -> comparator 判断 -> 左/右子树 -> 持续记录候选 -> 空节点结束 -> 返回匹配或边界节点``。

``lower_bound(k)`` 的关键规则是：当前节点不小于 ``k`` 时记录为候选并继续向左；当前节点小于 ``k`` 时向右。最终候选就是第一个不小于 ``k`` 的节点。

**插入**

``按 BST 定位叶子位置 -> 分配并构造节点 -> 标红 -> 链接节点 -> 检查父节点颜色 -> 重新染色或旋转 -> 根节点染黑``。

父节点为黑时直接结束；父和叔都为红时通常把父、叔染黑并把祖父染红，问题向上移动；叔为黑时根据内侧 / 外侧关系先旋父或直接旋祖父，再配合重新染色完成局部修复。

**左旋**

``x.right = y -> y.left 转移到 x.right -> 修正转移子树 parent -> y 接到 x 原父节点 -> x 成为 y.left``。

判断旋转是否正确只看两件事：局部所有 parent/child 边是否闭合，以及旋转前后的中序 key 顺序是否一致。

**删除**

``BST 定位目标 -> 若有两个孩子则定位中序后继 -> 摘除实际删除节点 -> 若删除红节点直接结束 -> 若删除黑节点进入 fixup -> 依据兄弟与侄子颜色执行染色 / 旋转 -> 恢复 black height``。

概念辨析
--------

* **BST 顺序 vs 红黑规则**：BST 负责 key 的逻辑顺序；红黑规则只负责限制树高，两者职责不同。
* **平衡 vs 完全平衡**：红黑树不要求左右子树高度完全相等，只要求高度保持对数级上界。
* **旋转 vs 排序**：旋转不会重新排序 key，它只改变树的局部拓扑。
* **颜色 vs 业务数据**：颜色是实现状态，不参与 ``map`` / ``set`` 的业务语义。
* **树高 vs 节点数**：有序容器的对数复杂度来自高度约束，不来自“节点式结构”本身。
* **节点移动 vs 链接变化**：旋转通常只修改指针，元素对象仍停留在原节点存储中。

本章结论
--------

红黑树可以压缩成一条稳定模型：``comparator 定义顺序 -> BST 路径完成定位 -> 节点插入或删除 -> 颜色和旋转恢复高度约束 -> 中序遍历继续保持有序``。阅读有序关联容器源码时，优先定位 comparator、节点字段、旋转、插入修复、删除修复和后继 / 前驱逻辑，不需要先陷入实现命名。
