第031章：Heap Algorithms
========================

核心知识点
----------

* Heap algorithm 把随机访问区间解释为完全二叉树，父子位置由数组下标关系计算，不需要节点指针。
* 对索引 ``i``，父节点为 ``(i-1)/2``，孩子为 ``2*i+1`` 与 ``2*i+2``；因此算法要求 random access iterator。
* 默认 ``std::less`` 下形成最大堆：根节点是最高优先级元素；换成 ``std::greater`` 后形成最小堆。
* 堆只保证父子局部优先级，不保证整个数组全局有序。
* ``make_heap`` 把已有区间原地建堆，常见自底向上下沉路径具有线性级建堆复杂度。
* ``push_heap`` 的前提是 ``[first,last-1)`` 已经为堆，最后一个元素刚由容器加入；算法只负责把最后一个元素上浮纳入堆。
* ``pop_heap`` 把原堆顶移动到区间尾部，并把前缀重新修复为堆；它不会缩短容器，真正删除需要继续 ``pop_back``。
* ``sort_heap`` 反复提取堆顶，把整个堆区间转换成有序区间；完成后原堆状态不再存在。
* ``is_heap`` 判断整体堆不变量，``is_heap_until`` 返回第一个破坏堆前缀的位置，适合定位父子关系断点。
* ``priority_queue`` 是对底层随机访问容器和 heap algorithms 的接口封装；裸 heap range 适合调用者需要直接控制底层区间的场景。

关键路径
--------

1. 先确认底层 range 支持 random access，并统一整个生命周期使用同一个 comparator。
2. 已有批量元素时调用 ``make_heap`` 建立堆；增量加入元素时先由容器 ``push_back`` 创建元素，再调用 ``push_heap``。
3. 提取堆顶时调用 ``pop_heap``，此时最高优先级元素位于 ``last-1``；读取后再由容器 ``pop_back`` 结束其生命周期。
4. 若要把剩余堆完整排序，调用 ``sort_heap``；之后按有序区间处理，继续调用 ``push_heap`` 前需要重新建立正确堆前提。
5. 来源不可信或调试状态时用 ``is_heap`` / ``is_heap_until`` 验证不变量。
6. 对容器层的扩容、引用失效、元素构造和销毁单独按 vector/deque 等底层容器规则判断。

概念辨析
--------

* **heap 与 sorted range**：堆只保证父子局部关系和根节点最优先；排序区间建立完整全局顺序。
* **push_back 与 push_heap**：前者增加真实元素并可能扩容；后者只重排已有最后元素以恢复堆。
* **pop_heap 与 pop_back**：前者重排并把堆顶移到尾部；后者才真正删除尾部对象。
* **make_heap 与逐个 push_heap**：批量已有元素时 ``make_heap`` 能利用自底向上建堆路径；逐个插入支付每次上浮成本。
* **heap algorithms 与 priority_queue**：前者直接操作 range，后者封装底层容器和比较器，只暴露优先队列接口。
* **比较器方向**：默认 less 产生最大堆，top 是“按 comparator 排在最后”的元素，不应凭“less”字面理解成最小堆。

本章结论
--------

堆算法应按状态机理解：普通区间 ``make_heap`` → 合法堆；``push_back + push_heap`` 增量加入；``pop_heap + pop_back`` 提取；``sort_heap`` 消耗成排序结果。每一步都要区分算法层重排和容器层生命周期变化。
