第001章：C++ Object Model
==========================

核心知识点
----------

C++ 对象需要同时满足四个条件：有一段可承载它的存储、满足 ``alignof(T)`` 的对齐、生命周期已经开始、当前访问方式与对象真实类型一致。地址只解决“在哪里”，生命周期解决“这里现在是不是一个活着的 T”。

``sizeof(T)`` 给出完整对象占用的步长，包含必要 padding；``alignof(T)`` 给出对象起始地址约束。连续容器按 ``sizeof(T)`` 安排相邻元素，并要求分配器提供满足 ``alignof(T)`` 的存储。

存储期与生命周期是不同概念。自动、静态、线程、动态存储期描述存储存在多久；对象生命周期描述何时可以按某个类型访问这段存储。STL 常先取得原始存储，再只在其中一部分位置构造对象。

容器拥有元素对象的生命周期；元素类型负责自己的内部资源。``vector<unique_ptr<T>>`` 中 vector 销毁 ``unique_ptr`` 元素，``unique_ptr`` 再释放 ``T``，形成两层所有权链。

多态对象的动态类型影响虚函数和析构路径。通过基类指针管理派生对象时，若需要经基类接口销毁，基类析构函数必须满足多态销毁要求，典型做法是虚析构。

关键路径
--------

对象从存储到销毁的最小路径是：

``取得存储 → 检查大小/对齐 → 构造对象 → 类型化访问 → 析构对象 → 复用或释放存储``。

对类似 vector 的连续容器，可进一步写成：

``allocate(capacity) → [begin,end) 构造元素 → [end,cap) 保持原始存储 → 修改元素 → destroy 已构造元素 → deallocate``。

因此 ``size`` 表示活对象数量，``capacity`` 表示已取得的元素槽位数量。``size`` 到 ``capacity`` 之间只是容器控制的原始存储，不等价于已经存在的元素对象。

判断指针或 iterator 是否仍有效时依次检查：地址是否仍属于当前存储、目标对象生命周期是否仍存在、地址上是否还是同一个对象、访问类型是否仍合法。vector 扩容会换存储，erase 会结束元素生命周期，placement construction 可以在同一地址建立新对象身份。

概念辨析
--------

``存储`` 不等于 ``对象``。一段字节足够大且地址正确，只说明可以承载对象；构造完成后才进入目标对象生命周期。

``地址相同`` 不等于 ``对象身份相同``。同一地址可以先后承载不同对象，旧对象生命周期结束后，新对象是新的身份。

``sizeof`` 不等于成员大小之和。padding 和尾部对齐会参与完整对象大小，并决定数组与连续容器的元素步长。

“栈对象/堆对象”是工程简称，更准确的边界是存储期。局部对象通常具有自动存储期，动态对象通常具有动态存储期；对象语义本身仍由类型、生命周期和所有权决定。

容器拥有指针元素，不代表拥有指针所指对象。``vector<int*>`` 只管理指针对象；``vector<unique_ptr<int>>`` 才通过元素类型继续表达所指对象的独占所有权。

本章结论
--------

读 C++ 与 STL 底层代码时，先判断存储，再判断生命周期，再判断布局与对齐，随后判断所有权，最后判断 iterator 或指针指向的对象身份。STL 的容量管理、扩容、擦除、allocator 和异常回滚都建立在这套对象模型上。
