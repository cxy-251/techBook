第050章：Mini Vector
====================

核心知识点
----------

* mini vector 的核心状态可由三指针表示：``first_`` 为存储起点，``last_`` 为已构造元素尾后，``cap_`` 为容量尾后。
* ``[first_, last_)`` 是有效对象区间，``[last_, cap_)`` 只是已分配但未构造的原始存储。
* ``size`` 来自 ``last_-first_``，``capacity`` 来自 ``cap_-first_``；空容器可以无存储，也可以 ``size==0`` 但仍保留 capacity。
* ``reserve`` 的强异常安全依赖“先准备新缓冲区，成功后再提交”：申请新存储、迁移元素、成功后销毁旧元素并释放旧存储，最后切换三指针。
* ``std::move_if_noexcept`` 用于在移动性能和强异常保证之间选择迁移策略。
* ``emplace_back`` 必须先保证容量，在 ``last_`` 位置构造成功后再推进 ``last_``。
* 扩容改变所有元素地址，因此旧 pointer/reference/iterator 全部失效；未扩容的尾插通常不会使已有元素位置失效。
* ``erase`` 需要把后续元素向前移动，再销毁尾部多余对象并收缩 ``last_``；``clear`` 销毁元素但通常保留 capacity。

关键路径
--------

1. ``emplace_back`` 检查 ``last_ == cap_``；空间不足时进入 ``reserve(next_capacity)``。
2. ``reserve`` 申请新 raw storage，并用新尾指针逐个构造旧元素的迁移结果。
3. 迁移失败时销毁新缓冲中已构造前缀并释放新存储，旧三指针保持不变。
4. 迁移全部成功后，销毁旧 ``[first_,last_)``，释放旧容量，提交 ``first_/last_/cap_``。
5. 尾插在 ``last_`` 构造新对象，成功后 ``++last_``；删除则先移动覆盖，再销毁多余尾元素。
6. 析构执行 ``clear`` 后释放容量存储，并恢复空状态。

概念辨析
--------

* **size vs capacity**：size 是有效对象数量，capacity 是原始槽位数量。
* **reserve vs resize**：reserve 只改变可用存储规模；resize 改变有效元素数量并涉及构造或析构。
* **移动元素 vs 移动存储**：扩容不能把旧内存块本身“搬过去”，而是在新存储中重新构造元素后释放旧存储。
* **iterator 失效 vs 对象失效**：旧元素可能已成功迁移到新地址，但指向旧地址的 iterator 仍然全部失效。
* **clear vs 释放内存**：clear 结束元素生命周期，通常保留已分配 capacity。

本章结论
--------

实现 vector 的关键不是下标访问，而是维护“原始存储范围”和“有效对象范围”的严格边界。所有修改操作都应围绕明确提交点组织：成功前不破坏旧状态，构造成功后才推进 size 边界，扩容成功后才切换底层存储。
