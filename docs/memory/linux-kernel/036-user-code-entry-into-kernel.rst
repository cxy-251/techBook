第036章：用户代码怎样进入内核
=============================

核心知识点
----------

系统调用是受控的权限转换
   用户程序不能直接调用内核函数或访问内核对象。系统调用通过架构规定的入口指令，把 CPU 从用户权限级切换到内核权限级，并进入内核预先配置的入口地址。

用户 API 与系统调用 ABI 是两层接口
   ``read()``、``write()`` 等是用户可见的库接口；系统调用号、参数寄存器、返回寄存器和错误表示属于二进制 ABI。libc 包装函数负责把前者转换为后者。

系统调用 ABI 由架构决定
   x86-64 通常使用 ``syscall`` 指令，arm64 通常使用 ``svc #0``。调用号和参数寄存器也随架构变化，不能把普通 C 函数调用规则或另一架构的规则直接套用。

架构入口先保存 CPU 现场
   入口汇编代码负责切换栈、保存用户寄存器、建立内核执行状态，并形成 ``struct pt_regs`` 一类现场表示。``pt_regs`` 是内核内部结构，其布局随架构变化。

当前任务仍是发起调用的进程
   系统调用进入内核后，代码通常仍运行在当前进程的进程上下文中。它可以访问 ``current``，也可能因锁、缺页或 I/O 睡眠并被调度出去。

通用入口处理边界策略
   在具体系统调用执行前后，通用 entry 逻辑可能处理 seccomp、audit、ptrace、tracing、信号和调度请求。这些机制可以观察、过滤或改变边界行为。

调用号连接到具体实现
   当前 ABI 的系统调用表把调用号映射到 wrapper，wrapper 再进入 ``SYSCALL_DEFINE*`` 生成的入口或共同内部实现，最终进入 VFS、网络、内存等子系统。

进入内核不代表参数可信
   系统调用入口只完成控制权和参数形式的交接。用户指针、文件描述符、长度、flag、权限和对象状态仍必须由后续路径逐层检查。

退出内核不是普通函数返回
   返回用户态前，内核需要处理返回值、待处理信号、调度、审计、追踪和用户寄存器恢复，并选择符合当前状态的安全返回路径。

阅读系统调用要分层
   稳定的阅读顺序是：用户 API、架构 syscall ABI、架构入口、通用 entry、系统调用实现、具体子系统。跳过其中任一层都容易把接口语义和内部实现混在一起。

关键路径
--------

一次系统调用的主干：

::

   用户代码调用 libc 接口
   → libc 准备调用号和参数寄存器
   → CPU 执行 syscall 或 svc
   → 架构入口切换权限级和栈
   → 保存用户现场并建立 pt_regs
   → 通用入口执行过滤、审计和追踪
   → 系统调用表按调用号分发
   → 具体实现进入内核子系统
   → 退出路径处理信号和调度
   → 恢复用户寄存器与权限级
   → 返回用户代码

``read`` 的对象路径：

::

   read(fd, buf, count)
   → syscall ABI 提交三个参数
   → 系统调用入口验证调用号
   → fd 查找得到 struct file
   → file_operations 分发读取实现
   → 数据经 uaccess 写入用户缓冲区
   → 返回字节数或错误

定位某架构的入口：

::

   确认用户程序 ABI
   → 查入口指令和寄存器约定
   → 找架构汇编入口
   → 找 pt_regs 保存方式
   → 找通用 syscall entry/exit
   → 找系统调用表和 wrapper
   → 进入具体实现

概念辨析
--------

用户 API 与系统调用 ABI
   用户 API 是源代码接口；系统调用 ABI 是用户二进制与内核之间的调用号、寄存器和返回协议。

普通 C ABI 与 syscall ABI
   普通函数调用遵守语言平台 ABI；系统调用使用专门的架构入口规则，两者的参数寄存器可能不同。

架构入口与系统调用实现
   架构入口保存和恢复 CPU 现场；系统调用实现处理文件、网络、内存等业务语义。

进入内核与获得权限
   进入内核只把请求交给内核执行；权限、安全策略和对象状态仍会决定请求是否允许。

``pt_regs`` 与用户 ABI
   用户 ABI 规定寄存器如何提交；``pt_regs`` 是内核保存并解释这些寄存器的内部表示。

系统调用退出与普通 ``return``
   普通返回只恢复调用者控制流；系统调用退出还要恢复权限级、用户现场并处理信号和调度状态。

本章结论
--------

系统调用是一条分层边界路径：用户态按架构 ABI 提交请求，入口代码保存 CPU 现场，通用逻辑完成策略处理与分发，退出路径再安全恢复用户态。
