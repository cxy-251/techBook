第030章：失败路径是内核设计的真实检验
=====================================

本章必须记住
------------

#. 成功路径把对象推到稳定可用状态，失败路径负责把半初始化或部分发布的对象恢复到安全状态。
#. 失败路径最重要的问题是：对象当前已经完成了哪些构造阶段。
#. 每次资源申请、状态设置、索引插入、sysfs 创建、回调注册和上层发布都会增加一项回滚责任。
#. 成功路径常隐藏对象生命周期假设，失败路径会迫使代码明确资源、可见性、引用和并发边界。
#. 资源账本应记录每一步改变的对象状态，而不是只记录调用了哪些函数。
#. 失败点发生时，应列出已经取得的资源、已经发布的入口、已经增加的引用和已经启动的异步执行。
#. ``goto err_*`` 标签通常代表对象构造过程中的明确恢复状态。
#. 越晚建立的外部可见状态，回滚时越应先撤销；越基础的对象内存和字段，越应晚释放。
#. 错误标签向下贯穿可以把多个恢复阶段集中在函数尾部，并共享反向清理逻辑。
#. 每个失败点必须跳到与当前半初始化状态匹配的标签，不能释放尚未取得的资源，也不能遗漏已经取得的资源。
#. 对象已经进入列表、IDR、XArray、sysfs、VFS 或 driver core 后，失败回滚必须先关闭这些发现入口。
#. 回调、workqueue、timer、IRQ、RCU 读侧和异步 I/O 仍可能运行时，不能直接释放对象。
#. 驱动 ``probe`` 返回错误不表示驱动核心会自动撤销驱动私有的全部副作用；回滚责任取决于 API 和 devres 契约。
#. devres 可以自动释放托管资源，但全局注册、外部通知、异步任务和非托管状态仍需显式撤回。
#. 下层错误码应尽量保存在 ``ret`` 中原样传播，清理代码不能意外覆盖真实失败原因。
#. 失败回滚结束后，核心对象应恢复到调用者能够理解的稳定状态，例如未注册、未绑定或已停止。
#. 错误路径必须通过测试主动执行，不能因为正常启动成功就假定回滚正确。
#. Fault injection 可以主动制造 slab 分配、页分配、块 I/O、函数调用、probe 或超时失败。
#. 失败注入测试应预先写明注入点、预期错误码、预期清理动作和可观察证据。
#. 测试结果不仅要看函数是否返回失败，还要检查资源是否泄漏、入口是否残留、引用是否归还和对象是否还能被查到。
#. KASAN 主要发现越界和 use-after-free，refcount warning 主要发现引用计数错误，lockdep 主要发现锁依赖和上下文问题。
#. Oops 和调用栈给出故障附近的动态路径，但必须结合对象状态、释放时间和错误回滚还原根因。
#. 释放后访问通常说明入口关闭、异步同步、引用或 RCU 等待中的某一环缺失。
#. 资源泄漏通常说明某个失败分支少执行了一次释放、put、注销或取消动作。
#. 重复释放通常说明不同错误标签清理了同一资源，或所有权转移后双方都执行了释放。
#. 失败路径的质量决定内核在内存压力、硬件异常、热拔插、并发退出和恶意输入下能否保持状态一致。

必背路径
--------

失败路径审查：

::

   找到成功路径的构造阶段
   → 为每一步写出新增状态和资源
   → 找到所有可能失败点
   → 标记失败时已经完成的阶段
   → 检查目标 err 标签是否匹配
   → 按可见性和依赖逆序回滚
   → 检查异步路径是否已经同步退出
   → 检查引用和所有权是否归还
   → 确认原始错误码仍然返回
   → 确认对象回到稳定状态

对外发布后失败：

::

   标记对象停止服务
   → 从索引和用户入口撤下
   → 阻止新的回调和查找
   → 等待已经进入的调用链退出
   → 取消并同步异步工作
   → 归还引用和资源
   → 最终释放对象

Fault injection 测试：

::

   选择一个可控失败点
   → 记录注入前对象状态
   → 注入分配、I/O、函数或 probe 失败
   → 检查返回错误码
   → 检查错误标签执行顺序
   → 检查索引、sysfs 和设备入口是否残留
   → 检查 work、timer、IRQ 和引用是否归零
   → 使用 KASAN、lockdep、refcount 和日志复查
   → 重复执行确认结果稳定

生命周期故障诊断：

::

   从 Oops、KASAN 或 warning 找最近调用点
   → 确认访问的对象和字段
   → 找对象的分配和发布位置
   → 找注销、put 和释放位置
   → 判断哪个执行者在释放后继续访问
   → 检查缺失的引用、同步或 RCU 等待
   → 用失败注入或压力测试复现

必须区分
--------

业务失败与回滚失败
   业务调用返回错误是原始故障；清理遗漏、重复释放或退出后访问是失败路径自身的缺陷。

错误标签与普通跳转
   ``err_*`` 标签表达构造阶段和恢复边界，不只是为了减少代码缩进。

返回失败与状态恢复
   函数返回负错误码只说明失败被报告；还必须证明对象状态和资源已经恢复安全。

正常测试与失败注入
   正常测试覆盖成功路径；失败注入主动覆盖低概率错误和半初始化路径。

KASAN 报告与根因
   KASAN 证明发生了非法内存访问；根因仍可能是引用、入口、异步同步或错误回滚缺失。

泄漏与延迟释放
   泄漏表示资源永远失去释放路径；延迟释放可能是仍有合法引用或等待 grace period，需要结合生命周期判断。

一句话结论
----------

真正可靠的内核设计不仅能成功建立对象，还能在任意中间阶段失败时关闭入口、归还所有权、逆序回滚并恢复稳定状态。
