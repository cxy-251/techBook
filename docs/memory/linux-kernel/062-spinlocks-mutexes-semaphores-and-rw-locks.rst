第062章：Spinlock、Mutex、Semaphore 与读写锁
==========================================

核心知识点
----------

锁的选择从执行上下文开始
   先判断所有访问路径是否允许睡眠，再判断临界区长度、资源语义、读写比例和实时要求。锁名不是选择依据，上下文约束才是第一条件。

Spinlock 适合短小原子临界区
   等待者持续忙等，不会主动让出 CPU，因此临界区必须短、固定且不能调用睡眠 API。典型用途是队列节点、状态位、索引和少量共享字段更新。

Spinlock 后缀表达本 CPU 的插入约束
   ``spin_lock_irqsave()`` 同时处理跨 CPU 互斥和本 CPU hardirq 重入；``spin_lock_bh()`` 同时禁止本 CPU bottom half。所有访问同一把锁的路径必须使用一致且足够强的上下文协议。

Raw spinlock 保留底层硬原子语义
   ``raw_spinlock_t`` 用于调度器、低层 IRQ 和必须保持不可睡眠的临界区。PREEMPT_RT 会改变普通 ``spinlock_t`` 的部分实现语义，但不会把 raw spinlock 转成可调度锁。

Mutex 是可睡眠的所有者互斥锁
   竞争失败时 task 可以睡眠，适合进程上下文中的配置、注册、打开关闭和较长状态转换。它不能用于 hardirq、softirq 或其它原子上下文。

Mutex 变体可能在未加锁时返回
   ``mutex_lock_interruptible()`` 和 ``mutex_lock_killable()`` 可能因信号失败。调用者必须区分“已经持锁”和“尚未持锁”，错误路径不能无条件执行 unlock。

Semaphore 表达可用额度
   计数 semaphore 允许有限数量的并发占用者，``down`` 消耗额度，``up`` 归还额度。普通所有者互斥优先使用 mutex，semaphore 更适合资源槽位、并发额度和历史协议。

读写锁允许共享读、独占写
   ``rwlock_t`` 是不可睡眠的读写自旋锁，``rw_semaphore`` 是可睡眠读写锁。只有读路径明显占优、临界区足够大且共享读确有收益时，复杂度才可能值得。

读写锁不会自动避免饥饿
   读者与写者的偏向、升级困难和锁顺序会增加设计复杂度。读锁通常不能原地升级为写锁，应释放读锁、取得写锁并重新验证状态。

锁保护的是不变量，不是对象生命期
   锁内取得的指针在解锁后可能被释放。需要跨越临界区继续使用时，必须在锁内取得引用或使用其它正式生命周期保证。

锁顺序必须全局一致
   两把锁在一条路径按 A→B 获取，在另一条路径按 B→A 获取，就具备死锁条件。未知回调、下层驱动和文件操作也必须纳入锁依赖图。

关键路径
--------

选择同步原语：

::

   列出所有访问者和执行上下文
   → 任一路径不可睡眠时排除 mutex、rwsem 和普通等待
   → 极短原子临界区选择 spinlock 或 raw spinlock
   → 可睡眠所有者互斥选择 mutex
   → 有限资源额度选择 semaphore
   → 读多写少且共享读有收益时评估 rwlock 或 rwsem
   → 检查 PREEMPT_RT、锁顺序和对象生命周期

进程路径与 hardirq 共享队列：

::

   保存本地 IRQ 状态
   → spin_lock_irqsave
   → 更新队列、索引和短状态
   → 取得需要继续处理的对象引用
   → spin_unlock_irqrestore
   → 在锁外执行复杂工作

可睡眠配置路径：

::

   复制并验证用户输入
   → 获取 mutex
   → 重新检查对象状态
   → 执行配置与可睡眠操作
   → 提交稳定状态
   → 释放 mutex
   → 单独处理未取得锁的失败路径

检查死锁：

::

   列出全部锁类
   → 记录每条路径的获取顺序
   → 标记 hardirq、softirq 和进程上下文
   → 检查同一锁的 irq/bh 后缀是否一致
   → 检查回调和下层调用是否反向取锁
   → 使用 lockdep 验证依赖图
   → 统一顺序或拆分临界区

概念辨析
--------

Spinlock 与 mutex
   Spinlock 忙等且不能睡眠；mutex 让等待者睡眠，只能用于可睡眠上下文。

``spinlock_t`` 与 ``raw_spinlock_t``
   普通 spinlock 可能受 PREEMPT_RT 转换影响；raw spinlock 始终保留底层硬原子语义。

Mutex 与 semaphore
   Mutex 表达所有者互斥；semaphore 表达可并发占用的资源额度。

``rwlock_t`` 与 ``rw_semaphore``
   前者是不可睡眠的读写自旋锁；后者是可睡眠的读写锁。

互斥与对象存活
   持锁保证当前临界区安全；解锁后继续使用对象仍需要引用或其它生命周期协议。

本章结论
--------

正确的锁来自执行上下文、睡眠能力、临界区长度、资源语义和全局锁顺序的共同约束；锁只能保护遵守同一协议的访问。
