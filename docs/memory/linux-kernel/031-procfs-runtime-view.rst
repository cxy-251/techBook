第031章：procfs 是进程与内核状态的运行时视图
==============================================

核心知识点
----------

procfs 是动态生成的伪文件系统
   ``procfs`` 通常挂载在 ``/proc``，其中大多数文件没有磁盘数据。用户读取文件时，内核根据当前进程对象、内存状态或系统计数器即时生成内容。

``/proc/<pid>`` 是进程对象的观察入口
   每个 PID 目录表示当前 PID namespace 中可见的一个任务。目录是否可见还受权限、ptrace 检查、``hidepid``、capability 和 LSM 策略影响。

不同文件回答不同进程问题
   ``status`` 提供适合人工阅读的身份、线程、信号和内存摘要；``stat`` 提供紧凑的程序化字段；``fd`` 展示文件描述符表；``maps`` 展示 VMA 布局；``smaps`` 进一步给出各映射的 RSS、PSS 和脏页等统计。

虚拟地址布局不等于物理内存占用
   ``maps`` 说明进程拥有哪些虚拟区域及其权限和来源。实际驻留页、共享贡献和私有占用需要结合 RSS、PSS、``smaps`` 或其它页级统计判断。

系统级条目投影全局内核状态
   ``/proc/meminfo`` 描述内存分布，``/proc/interrupts`` 和 ``/proc/softirqs`` 描述硬中断与延后执行负载，``/proc/slabinfo`` 描述内核对象缓存。每项统计都必须结合其更新来源和单位解释。

``/proc/sys`` 是 sysctl 控制面
   ``/proc/sys`` 把部分内核运行参数映射为文件。读取用于观察当前值，写入会改变运行状态；它属于运行期配置，不等同于编译期 Kconfig。

procfs 输出多为快照或累计计数
   对象和计数器在读取期间仍可能被其它 CPU 修改，因此单次读取只代表附近时刻的状态。增长、泄漏和负载偏移需要使用相同口径连续采样。

procfs 提供证据，不负责解释根因
   一个条目说明某个内核对象或计数器当前呈现什么状态。要解释为什么形成该状态，还需回到字段更新位置、生命周期、调用路径和时间线。

关键路径
--------

读取 procfs 条目：

::

   用户打开 /proc 路径
   → VFS 定位 procfs inode
   → proc_ops 或 seq_file 回调执行
   → 读取 task、mm、files 或系统计数器
   → 格式化当前状态
   → 返回用户空间

观察单个进程：

::

   status 查看任务摘要
   → fd 查看打开对象
   → maps 查看虚拟地址布局
   → smaps 查看页级内存贡献
   → 连续采样确认变化趋势
   → 回到对应内核对象解释原因

使用系统级证据：

::

   meminfo 判断内存分布
   → interrupts 与 softirqs 判断 CPU 负载来源
   → slabinfo 判断对象缓存变化
   → 结合日志与 tracing 定位具体路径

概念辨析
--------

伪文件与磁盘文件
   procfs 文件是内核对象的动态视图；普通文件的数据由文件系统和存储介质持久保存。

``maps`` 与 RSS、PSS
   ``maps`` 描述虚拟区域；RSS 表示驻留页规模，PSS 按共享比例分摊物理页贡献。

状态与累计计数
   状态描述对象当前处境；累计计数描述某类事件从统计起点以来发生的次数。

快照与趋势
   一次读取只能提供局部证据；趋势必须依靠固定时间间隔和相同口径的多次采样。

读取与控制
   大多数 ``/proc`` 条目用于观察；``/proc/sys`` 和少数控制文件的写入会改变内核运行状态。

条目不可见与对象不存在
   Namespace、权限、挂载选项和内核配置都可能隐藏条目，不能仅凭路径缺失断定对象不存在。

本章结论
--------

``procfs`` 把进程对象和系统计数器转换成可查询的运行时视图；正确使用它的关键是先明确每个文件回答什么问题，再用连续采样和源码路径解释状态变化。
