第068章：用户地址空间与内核地址空间
=====================================

本章必须记住
------------

#. 虚拟地址数值必须结合所属地址空间、页表、CPU 权限级和映射类型才能解释。
#. 用户地址空间属于具体进程的 ``mm_struct``，保存程序文本、数据、堆、栈、共享库和 ``mmap`` 区域。
#. 同一个用户虚拟地址在不同进程中可以表示不同内容，因为它们使用不同页表和 VMA 集合。
#. 用户地址空间不是一整块已分配内存，而是多个属性不同的 VMA 区间。
#. 程序文本通常可读可执行，数据与堆通常可读写，线程栈通常可读写并带有增长与 guard 规则。
#. 共享库、动态链接器和文件映射通常位于 ``mmap`` 区域，实际位置受架构和 ASLR 影响。
#. Guard page 是故意保留的不可访问区域，用于尽早发现栈或映射越界。
#. ``/proc/<pid>/maps`` 展示当前进程的用户 VMA 范围、权限、文件偏移和后端来源。
#. 用户 VMA 存在不代表所有页面已经驻留；物理页仍可能在首次访问时通过缺页建立。
#. 内核地址空间保存内核文本、核心数据、直接映射、``vmalloc``、模块、fixmap 和设备映射等区域。
#. 内核地址布局和具体地址范围依赖架构、页表级数、配置和随机化，不能跨机器套用固定数值。
#. Direct mapping（线性映射）把普通 RAM 按架构定义的偏移映射进内核虚拟空间，便于快速访问物理页。
#. 直接映射要求底层物理范围连续，但调用者看到的是对应的内核虚拟地址。
#. ``vmalloc`` 提供连续的内核虚拟地址范围，底层物理页可以不连续。
#. ``vmalloc`` 内存通常用 ``vfree()`` 释放，不能和普通 slab、page allocator 或直接映射释放接口随意混用。
#. ``ioremap`` 把设备 MMIO 物理资源映射成内核虚拟地址，并使用特定缓存和访问属性。
#. ``__iomem`` 指针表示设备 I/O 内存语义，应通过 ``readl()``、``writel()`` 等访问器操作。
#. MMIO 地址不是普通 RAM 指针，不能用普通 ``memcpy``、解引用和页分配规则随意处理。
#. 用户态和内核态的访问隔离由 CPU 特权级与页表权限共同执行。
#. 页表项的 user/supervisor、read/write、execute 等权限位决定当前执行级别能否访问页面。
#. 即使进程页表中存在内核映射，用户态指令也会因 supervisor-only 权限而无法直接访问。
#. 系统调用、异常和中断切换到内核执行路径后，内核代码才按内核权限访问内核映射。
#. KPTI/PTI 可以在用户态运行期间减少可见的内核映射，降低部分侧信道攻击面。
#. KPTI 会增加用户态与内核态切换中的页表和 TLB 管理成本，具体行为依赖架构和配置。
#. SMAP、PAN 等机制限制内核无意访问用户地址；访问用户内存必须走 uaccess 协议。
#. 用户指针使用 ``__user`` 标注，并通过 ``copy_from_user()``、``copy_to_user()`` 等接口访问。
#. 内核不能因为自己处于高权限就直接解引用任意用户指针；用户映射可能缺页、变化、无权限或由攻击者控制。
#. ASLR 随机化程序、库、堆、栈和 mmap 区域位置，降低地址可预测性。
#. KASLR 随机化内核映像或相关内核区域位置，降低内核地址布局可预测性。
#. PIE 可执行文件允许主程序文本位置参与用户态地址随机化；非 PIE 程序的部分区域可能更固定。
#. 地址随机化改变位置，不改变 VMA 权限、对象生命周期和页表正确性要求。
#. 日志中的十六进制地址只有和内核版本、架构、进程映射、符号文件和随机化偏移结合才能还原。
#. ``virt_to_phys()`` 只适用于其 API 明确支持的直接映射地址，不能用于任意 ``vmalloc``、用户或 ``ioremap`` 地址。
#. ``phys_to_virt()`` 同样只适用于架构直接映射范围，不能把任意物理资源转换成普通内核指针。
#. 判断一个地址时，应先分类为用户地址、直接映射、``vmalloc``、模块、设备映射或其它架构区域。
#. 地址属于内核高地址范围不代表对象仍然有效；还必须检查分配来源、生命周期和映射是否已经撤销。

必背路径
--------

解释一个用户地址：

::

   地址值
   → 确认进程 PID 和 mm_struct
   → 在 /proc/<pid>/maps 查找所属 VMA
   → 检查权限、文件和匿名属性
   → 检查页表 present / swapped 状态
   → 判断正常访问、缺页、权限错误或映射缺失

解释一个内核地址：

::

   地址值
   → 确认架构和内核版本
   → 判断属于 kernel text、direct map、vmalloc、module 或 ioremap
   → 找到创建该映射的分配接口
   → 检查页表属性和符号
   → 检查对象生命周期与释放路径

用户缓冲区进入内核：

::

   用户传入 __user 指针
   → 系统调用进入内核
   → access_ok / uaccess 检查
   → copy_from_user 建立内核快照
   → 内核验证并处理数据
   → copy_to_user 返回结果
   → 用户地址始终按不可信边界处理

设备寄存器映射：

::

   驱动取得设备物理资源
   → ioremap 建立 MMIO 虚拟映射
   → 保存 __iomem 指针
   → 使用 readl / writel 等访问器
   → remove 时停止设备和并发访问
   → iounmap 撤销映射

必须区分
--------

* 用户地址与内核地址：用户地址由具体进程的 mm 解释；内核地址由架构内核虚拟布局解释。
* 直接映射与 ``vmalloc``：直接映射按物理内存关系建立；``vmalloc`` 只保证虚拟连续，物理页可以分散。
* 普通 RAM 与 MMIO：RAM 使用普通内存和缓存一致性规则；MMIO 代表设备寄存器，需要 I/O 访问器和设备顺序规则。
* 用户权限与映射存在：页面存在不表示用户态可访问，CPU 还会检查 user、write 和 execute 权限。
* ASLR 与对象生命周期：随机化只改变地址位置，不保证对象有效，也不替代边界检查。
* 地址范围判断与精确对象判断：地址前缀只能给出候选区域；精确结论还要结合映射、符号、页表和分配来源。

一句话结论
----------

地址值没有脱离上下文的固定含义：用户地址由进程 ``mm_struct`` 解释，内核地址由架构虚拟布局解释，而权限、映射类型和生命周期共同决定它能否被安全访问。
