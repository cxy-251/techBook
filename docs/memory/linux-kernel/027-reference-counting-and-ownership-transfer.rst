第027章：引用计数与所有权转移
=============================

核心知识点
----------

引用计数记录对象所有权
   对象被多个路径共享后，释放时机由最后一个有效持有者决定。引用计数不是普通使用次数，而是一份“谁仍有权让对象继续存活”的所有权账本。

初始引用属于创建路径
   对象创建时通常建立一份初始引用。创建者可以保留、释放或把这份引用转交给注册表、队列或其它对象，但责任必须明确。

每个 get 都必须有对应的 put
   新增长期持有者或让对象跨越当前保护范围时，需要增加引用。正常、失败、取消和退出路径最终都必须归还这份引用，或者明确把归还责任转移给接收方。

``kref`` 和 ``refcount_t`` 服务对象生命周期
   ``kref`` 封装初始化、获取、归还和归零 release；``refcount_t`` 提供更底层的引用计数语义与错误使用保护。最后一次 put 触发最终释放，而不是任意路径直接 ``kfree()``。

安全查找必须在保护窗口内提升引用
   从链表、XArray 或其它索引查到指针，只得到候选地址。必须在锁、RCU 或子系统规定的保护范围内检查状态并增加引用，避免查找与引用递增之间发生并发释放。

异步边界需要独立引用
   把指针交给 workqueue、timer、异步 I/O、回调或另一个线程前，通常需要为接收方取得一份引用。任务完成或被同步取消后，由异步路径归还引用。

借用、复制与转移具有不同责任
   借用指针只能在原有保护范围内使用；复制所有权需要新增引用；转移所有权把现有引用及其 put 责任交给接收方。接口必须让调用者能够判断属于哪一种。

引用不等于状态与同步
   引用只保证对象内存仍然存在，不保证对象仍处于 active 状态，也不保证字段并发访问一致。状态检查、锁、RCU 和原子操作仍然需要单独建立。

关键路径
--------

标准引用生命周期：

::

   分配对象
   → 建立初始引用
   → 注册并允许查找
   → 查找者在保护窗口内增加引用
   → 使用对象
   → 使用结束执行 put
   → 注销关闭新查找
   → 旧持有者依次 put
   → 最后一次 put 触发 release

指针跨越异步边界：

::

   当前路径持有对象
   → 为异步执行者增加引用
   → 把指针交给 work、timer 或 I/O
   → 异步路径访问对象
   → 完成或同步取消
   → 异步路径执行 put

概念辨析
--------

指针与引用
   指针只是地址值；引用表示当前路径拥有保证对象存活的生命周期权利。

借用与拥有
   借用只在原保护范围内有效；拥有引用允许对象跨越该范围继续存活。

复制所有权与转移所有权
   复制所有权会增加一份引用；转移所有权不新增引用，只改变谁负责最终 put。

对象存活与对象可操作
   引用保证内存存在；dying、offline 等状态决定是否还能接受新操作。

引用计数与字段同步
   引用计数保护对象生命期；锁、RCU 和原子操作保护字段与集合关系的一致性。

本章结论
--------

引用计数的核心不是数字增减，而是明确每份对象所有权从哪里取得、跨越什么范围，并由哪条路径最终归还。
