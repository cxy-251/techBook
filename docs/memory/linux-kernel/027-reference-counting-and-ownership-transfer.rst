第027章：引用计数与所有权转移
=============================

本章必须记住
------------

#. 对象被多个执行路径共享后，释放时机由最后一个有效持有者决定，而不再由创建者单独决定。
#. 引用计数表达对象内存是否仍然有效，不表达对象是否仍处于 active 状态，也不表达字段访问是否已经同步。
#. 对象创建时通常建立一份初始引用，表示创建路径当前拥有对象。
#. 每增加一个可以长期保存或异步使用对象指针的持有者，就必须增加一份引用。
#. 每个成功的 ``get`` 都必须对应一个 ``put``，或者明确把这份引用的释放责任转交给另一条路径。
#. 最后一次 ``put`` 使引用计数归零，并调用对象的 release 回调完成最终清理。
#. ``struct kref`` 是面向对象生命周期的引用计数封装，通常嵌入具体对象中。
#. ``kref_init()`` 建立初始引用，``kref_get()`` 增加持有者，``kref_put()`` 归还引用并在归零时调用 release。
#. ``refcount_t`` 是更底层的对象引用计数类型，语义比裸 ``atomic_t`` 更明确，并包含溢出和错误使用保护。
#. release 回调取得的常是嵌入字段指针，需要用 ``container_of()`` 返回宿主对象，再释放私有资源和对象内存。
#. release 回调是生命周期终点，不能在回调中把已经归零的对象重新发布。
#. 查找结构返回一个指针，不等于调用者已经安全拥有对象；必须在受保护窗口内取得临时引用。
#. 安全查找通常采用锁内查找并加引用、RCU 读侧查找后提升引用，或使用子系统已经持有引用的句柄。
#. 查找、状态检查和引用递增之间不能留下并发释放窗口。
#. ``refcount_inc_not_zero()``、``kref_get_unless_zero()`` 一类操作只能在对象仍受锁、RCU 或其它规则保护时使用。
#. 引用保证对象内存存在；``dying``、``offline``、``removed`` 等状态位决定对象是否还接受新操作。
#. 把对象指针放入 workqueue、timer、异步 I/O、回调参数或另一个线程之前，通常需要先取得引用。
#. 异步路径完成或被取消后，必须归还它持有的引用。
#. 所有权转移必须明确：发送方是保留引用、复制引用，还是把唯一引用移交给接收方。
#. 借用指针只在约定保护范围内有效，借用者不能把它保存到保护范围之外。
#. 引用泄漏来自取得引用后没有归还；use-after-free 常来自没有取得引用或过早归还引用。
#. double put 会让引用过早归零，可能导致重复释放、refcount warning 或释放后访问。
#. 引用计数不能自动保护对象字段的一致性；字段并发访问仍需要锁、RCU、原子操作或其它同步机制。
#. 生命周期问题表面上是崩溃或泄漏，根因通常是某条路径没有明确说明谁拥有对象以及谁负责 ``put``。

必背路径
--------

标准引用生命周期：

::

   分配对象
   → kref_init 建立初始引用
   → 注册对象并允许查找
   → 查找路径在保护窗口内增加引用
   → 调用者使用对象
   → 使用结束执行 put
   → 注销路径关闭新查找入口
   → 旧持有者陆续 put
   → 最后一次 put 触发 release
   → 释放私有资源和对象内存

指针跨异步边界：

::

   当前路径持有对象引用
   → 为 work、timer 或回调增加一份引用
   → 把指针交给异步执行者
   → 异步路径访问对象
   → 异步完成或取消
   → 异步路径执行 put

安全查找：

::

   进入锁或 RCU 保护区
   → 从索引取得候选指针
   → 检查对象未进入禁止获取引用的状态
   → 在对象仍受保护时增加引用
   → 离开查找保护区
   → 使用对象
   → 执行 put

引用账本：

::

   每次 get
   → 记录新所有者
   → 记录这份引用跨越的范围
   → 记录正常路径的 put
   → 记录每条失败路径的 put
   → 记录取消和退出路径的 put

必须区分
--------

* 引用与指针：指针只是地址值；引用表示当前路径拥有保证对象存活的生命周期权利。
* 对象存活与对象可操作：引用保证内存仍存在；状态位和子系统规则决定新操作是否允许。
* 引用计数与字段同步：引用计数保护对象生命期；锁、RCU 或原子操作保护字段并发一致性。
* 借用与拥有：借用指针只能在原保护范围内使用；拥有引用允许对象跨越该范围继续存活。
* 复制所有权与转移所有权：复制所有权需要新增引用；转移所有权把现有引用及其 ``put`` 责任交给接收方。
* 注销与最后一次 put：注销阻止新持有者；最后一次 put 才触发对象最终释放。

一句话结论
----------

引用计数是一份所有权账本：谁让对象跨越并发或异步边界，谁就必须取得引用，并确保最终有人归还它。
