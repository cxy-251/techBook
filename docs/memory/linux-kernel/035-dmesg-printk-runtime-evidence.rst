第035章：dmesg、printk 与运行时证据收集
======================================

核心知识点
----------

printk 建立内核日志通道
   内核代码通过 ``printk``、``pr_*`` 和 ``dev_*`` 记录对象、动作、结果和错误。消息先进入 kernel ring buffer，再由 console、``/dev/kmsg`` 和用户态日志服务消费。

Ring buffer 与 console 是不同层次
   Ring buffer 保存日志记录；console 只实时显示满足当前日志级别和设备条件的消息。因此屏幕没有输出，不代表内核没有生成日志。

``dmesg`` 与持久日志来源不同
   ``dmesg`` 主要读取当前内核 ring buffer；``journalctl -k`` 读取日志服务已经收集并保存的内核消息。Buffer 容量有限，旧记录可能被覆盖。

日志级别表达报告意图
   ``pr_err()`` 表示当前操作失败，``pr_warn()`` 表示异常条件，``pr_info()`` 表示普通状态，``pr_debug()`` 表示调试信息。``console_loglevel`` 影响实时显示，不决定消息是否进入 buffer。

日志抑制会改变可见证据
   Ratelimit 限制重复消息频率，``*_once()`` 只报告首次命中，dynamic debug 决定部分调试调用点是否输出。缺少日志可能来自抑制、覆盖或开关，而不是事件未发生。

WARN、Oops 与 panic 表示不同故障层级
   WARN 报告违反预期且通常允许继续；Oops 表示当前执行路径出现严重异常；panic 表示内核判断系统不能安全继续。运行策略可能把 WARN 或 Oops 升级为 panic。

调用栈提供第一处动态路径
   ``function+offset/size [module]`` 能定位故障附近函数和模块。精确还原源码位置必须使用与运行内核完全匹配的 ``vmlinux``、模块、配置和符号文件。

报告点不一定是根因发生点
   日志说明代码在哪里发现异常。真正的错误可能发生在更早的资源申请、状态修改、并发窗口或对象释放路径中。

原始证据必须优先保存
   清空 buffer、重启、修改日志级别或打开调试前，应先保存完整日志、内核 release、命令行、模块列表、硬件身份和时间基准。

关键路径
--------

日志从源码到用户态：

::

   内核代码调用 pr_* 或 dev_*
   → printk 写入 kernel ring buffer
   → console 策略决定是否实时显示
   → /dev/kmsg 暴露记录
   → dmesg、journald 或 syslog 收集
   → 排查者按对象、时间和级别分析

读取一条错误日志：

::

   保存完整原文和前后上下文
   → 确认时间基准与日志级别
   → 提取设备、模块、动作和错误码
   → 在源码中定位格式字符串
   → 检查调用点的返回值与对象状态
   → 向前寻找最早异常
   → 用 procfs、sysfs 和 tracing 补齐证据

分析 WARN、Oops 或 panic：

::

   保存完整故障块
   → 判断故障类别和升级策略
   → 找最近相关函数和模块
   → 沿调用栈识别进入路径
   → 核对 CPU、PID、taint 和模块列表
   → 使用匹配符号解析位置
   → 检查对象分配、引用、注销与释放

概念辨析
--------

Ring buffer 与 console
   Ring buffer 保存日志；console 只实时输出符合当前策略的部分消息。

``dmesg`` 与 ``journalctl -k``
   ``dmesg`` 读取当前内核缓冲区；``journalctl -k`` 读取日志服务已收集的记录，并可能保留跨时间段证据。

日志级别与系统结果
   级别表达调用点对事件严重性的分类；系统是否继续运行还取决于错误处理和 panic 策略。

WARN、Oops 与 panic
   WARN 报告异常状态；Oops 表示严重执行错误；panic 进入系统级停机、重启或转储流程。

日志缺失与事件未发生
   限速、once、dynamic debug、覆盖和权限都可能使消息不可见。

报告点与根因
   报告点是发现异常的位置；根因可能位于更早的状态变化或生命周期错误。

本章结论
--------

``printk`` 和 ``dmesg`` 提供有限容量的故障时间线；可靠诊断必须先保存完整原始证据，再把日志报告点与对象状态、调用链和 tracing 结果结合起来。
