第017章：使用 Kbuild 构建 Linux 内核
===================================

核心知识点
----------

Kbuild 把配置转换成构建图
   Kbuild 根据 ``.config``、目标架构和各目录规则，决定哪些源码被编译、怎样组合成内建对象或模块，以及最终生成哪些产物。

构建规则具有层级关系
   顶层 ``Makefile`` 组织全局阶段，``arch/$(SRCARCH)/Makefile`` 提供架构规则，``scripts/Makefile.*`` 提供通用构建逻辑，各目录的 ``Makefile`` 或 ``Kbuild`` 决定本目录对象。

源码存在不等于进入构建
   一个 ``.c`` 文件只有被父目录和当前目录的 Kbuild 规则选中，才会参与目标构建。分析时必须从目标文件沿目录规则向上确认完整进入路径。

``obj-y`` 与 ``obj-m`` 决定对象形态
   ``obj-y`` 把对象加入当前内建链，``obj-m`` 把对象加入模块链。``obj-$(CONFIG_FOO)`` 会随配置值变成 ``obj-y``、``obj-m`` 或空规则。

父目录决定子目录能否进入
   子目录中的 ``obj-y`` 只说明对象在该目录被视为内建；若父目录没有把该子目录加入目标构建，它仍不会进入 ``vmlinux``。

复合对象组织一个逻辑目标
   ``foo-y``、``foo-objs`` 和 ``foo-$(CONFIG_BAR)`` 可以把多个 ``.o`` 组合成一个 ``foo.o``，并按更细配置选择组成部分。对象列表顺序还可能影响链接顺序和 initcall 排列。

内建链与模块链最终分离
   内建对象先进入各目录的 ``built-in.a``，再参与 ``vmlinux`` 链接。模块对象经过模块后处理和链接，最终生成独立 ``.ko``，不会直接进入 ``vmlinux``。

导出符号定义模块边界
   普通全局符号不自动对模块可见。``EXPORT_SYMBOL()`` 和 ``EXPORT_SYMBOL_GPL()`` 明确导出符号，后者只允许符合 GPL 许可要求的模块使用。

MODPOST 检查模块一致性
   MODPOST 检查未解析符号、模块元数据和部分 section mismatch。``Module.symvers`` 记录导出符号及相关版本信息，启用 ``CONFIG_MODVERSIONS`` 时还包含符号 CRC。

外部模块依赖目标内核构建环境
   外部模块通常使用 ``make -C <kernel-build> M=<module-source> modules`` 构建。它必须匹配目标内核版本、配置、生成头文件和符号信息；``modules_prepare`` 不能在所有场景替代完整构建。

关键路径
--------

从配置到构建产物：

::

   .config 中的 CONFIG_FOO=y/m/n
   → 父目录 obj-$(CONFIG_FOO)
   → 子目录 obj-y、obj-m 或复合对象规则
   → 编译源文件为 .o
   → 内建链进入 built-in.a 与 vmlinux
   → 模块链经过 MODPOST 生成 .ko

内建对象链：

::

   source.c
   → source.o
   → 复合对象或目录对象列表
   → built-in.a
   → 最终链接
   → vmlinux

模块链：

::

   source.c
   → 模块对象
   → 符号与元数据检查
   → MODPOST
   → module.ko
   → 安装后由 depmod 建立依赖索引

概念辨析
--------

运行调用链与构建依赖链
   调用链说明运行时谁调用谁；构建链说明哪些文件被选择、编译、组合和链接。

目录中的 ``obj-y`` 与最终内建
   当前目录的 ``obj-y`` 仍受父目录进入方式控制；必须沿父目录规则确认对象最终是否进入内建链。

``built-in.a`` 与 ``vmlinux``
   ``built-in.a`` 是目录级内建对象集合；``vmlinux`` 是所有内建对象最终链接后的内核 ELF。

编译成功与模块可加载
   编译成功只说明对象生成；模块还必须通过符号解析、版本匹配、签名策略和初始化检查。

普通全局符号与导出符号
   普通全局符号只在内核链接范围内存在；模块只能依赖明确导出的符号接口。

本章结论
--------

Kbuild 是从配置到产物的层级依赖图：父目录决定是否进入，子目录决定编译什么，内建对象形成 ``vmlinux``，模块对象形成 ``.ko``。
