第013章：Linux 内核错误处理与返回约定
===================================

核心知识点
----------

错误通过返回值显式传播
   内核函数通常把成功状态、完成数量或失败原因编码在返回值中。阅读错误路径前，必须先确认函数返回类型、成功值以及调用者如何检查结果。

负 ``errno`` 表示失败
   返回状态的接口常用 ``0`` 表示成功、负 ``errno`` 表示失败；返回长度的接口常用非负值表示已完成数量、负数表示失败。内核内部不依赖用户态全局 ``errno``。

错误可以产生、传播或转换
   当前函数可以直接返回 ``-EINVAL`` 等错误，也可以原样传播下层错误，或根据本层接口语义转换为另一种错误。分析时应区分原始失败原因和最终对外结果。

错误指针复用指针返回通道
   返回对象指针的接口可以用 ``ERR_PTR(error)`` 编码负错误码，用 ``IS_ERR()`` 检查，用 ``PTR_ERR()`` 还原。错误指针不是可解引用对象。

``NULL`` 与错误指针语义不同
   ``NULL`` 常表示没有对象或可选结果，错误指针表示操作失败并携带原因。具体接口是否允许两种状态，必须根据函数合同和调用点判断。

取得资源就增加清理责任
   内存、引用、锁、IRQ、DMA 映射、时钟和已注册对象等资源一旦取得，当前路径就必须保证成功或失败退出时完成对应释放或所有权移交。

错误回滚处理部分初始化状态
   失败路径只能释放已经成功取得的资源。存在依赖关系时，通常按照申请顺序的反方向清理，以免先释放仍被后续资源依赖的对象。

``goto`` 用于集中表达清理阶段
   多阶段初始化常让不同失败点跳到对应清理标签。标签应表达需要撤销的资源或阶段，使申请顺序、释放顺序和当前责任一目了然。

错误路径与成功路径同等重要
   成功路径定义对象怎样进入可用状态；错误路径定义部分初始化怎样撤销。遗漏清理、重复释放或错误保留注册状态，都会破坏对象生命周期。

关键路径
--------

检查一个函数的错误合同：

::

   确认返回类型与成功值
   → 找直接产生的错误码
   → 找下层错误传播与转换
   → 标出每个资源取得点
   → 写出各失败点已经取得的资源
   → 检查 goto 目标和释放顺序
   → 确认最终返回值未被清理代码覆盖

错误指针：

::

   调用返回对象指针的函数
   → 使用 IS_ERR(ptr) 检查
   → 使用 PTR_ERR(ptr) 取回负错误码
   → 传播错误或进入清理路径
   → 检查通过后才允许解引用对象

资源回滚：

::

   取得资源 A
   → 取得资源 B
   → 取得资源 C 失败
   → 释放 B
   → 释放 A
   → 返回 C 的原始错误码

概念辨析
--------

负错误码与用户态 ``errno``
   内核调用链直接传播负错误码；用户态 C 库通常把系统调用失败转换为 ``-1`` 并设置正值 ``errno``。

``NULL`` 与错误指针
   ``NULL`` 表示空状态；错误指针表示失败并保留具体原因，二者是否都可能出现由接口决定。

错误原因与清理阶段
   错误码说明为什么失败；清理标签说明失败时已经取得哪些资源、必须撤销哪些状态。

资源取得与所有权移交
   接口成功不一定表示调用者长期拥有资源；必须确认所有权是否已转交给其它对象或子系统。

Slow path 与错误路径
   Slow path 可以经过昂贵处理后成功；错误路径以失败、部分完成或状态回滚结束。

本章结论
--------

内核错误处理必须同时保持两条链完整：失败原因沿调用链向上传播，已经取得的资源和可见状态按正确阶段向后回滚。
