第026章：内核对象是具有生命周期的 C 结构体
=========================================

本章必须记住
------------

#. 内核结构体不仅是字段布局，还是运行时对象的内存载体。
#. 一个完整内核对象由内存、状态、对象关系、注册位置、操作回调、所有权和生命周期共同定义。
#. ``task_struct``、``struct file``、``struct inode``、``struct device`` 和 ``sk_buff`` 都应按运行时对象阅读，不能只按字段表阅读。
#. 分配只表示内存已经存在；初始化表示字段达到内部一致；注册表示其它路径开始能够发现对象。
#. 分配、初始化和注册是三个不同阶段，不能把“已经分配”误认为“已经可用”。
#. 注册是并发可见性的边界。对象一旦进入链表、树、IDR、XArray、文件描述符表、driver core 或 sysfs，其它 CPU 和回调就可能访问它。
#. 对象发布前应准备好名称、父子关系、操作表、释放回调、基本状态和外部可见属性。
#. 发布后修改共享字段必须遵守锁、RCU、引用计数、状态位或子系统专用同步规则。
#. 内核经常把通用对象嵌入具体对象，例如 ``struct pci_dev`` 嵌入 ``struct device``，具体对象再嵌入 ``struct kobject``。
#. 通用子系统只操作嵌入的公共对象，具体子系统通过 ``container_of()`` 从成员地址返回宿主对象。
#. ``container_of()`` 只证明内存布局关系，不证明宿主对象仍然存活。
#. 公共字段表达跨子系统接口，私有字段表达具体实现状态；调用者不能越过所有权边界随意修改私有状态。
#. 对象通常经历 allocated、initialized、registered、active、dying、unregistered、released 等状态。
#. 状态迁移必须有明确方向；已经进入 dying 或 removed 状态的对象通常应拒绝新操作。
#. 对象是否可发现、是否可继续服务、内存是否仍有效，是三个独立问题。
#. 注销关闭新的发现入口，但旧调用链可能仍持有对象指针，因此注销通常不等于立即释放。
#. 最终释放必须等到索引入口、异步回调、定时器、IRQ、工作队列和旧引用都已经退出。
#. 引用计数对象通常由最后一次 ``put`` 触发 release 回调，而不是由任意路径直接 ``kfree()``。
#. release 回调负责释放对象拥有的私有资源和对象本体；执行后所有旧指针都失效。
#. 状态机错误常表现为未初始化对象被发布、dying 对象接受新请求、注销后仍可查找或释放后仍有回调访问。

必背路径
--------

对象的完整生命线：

::

   分配对象内存
   → 初始化锁、引用、状态和操作表
   → 建立父子关系与私有资源
   → 注册到子系统容器
   → 对象对其它路径可见
   → 查找、回调和异步路径使用对象
   → 标记 dying 并拒绝新操作
   → 从索引和外部入口注销
   → 等待旧引用和异步执行退出
   → 执行 release 回调
   → 释放对象内存

阅读一个结构体时采用以下顺序：

::

   它代表什么运行时对象
   → 谁分配它
   → 谁完成初始化
   → 哪个动作发布它
   → 外部路径通过什么入口找到它
   → 谁取得和归还引用
   → 它有哪些合法状态迁移
   → 哪个动作关闭新入口
   → 谁执行最终释放

注册前后的边界：

::

   注册前
   → 构造路径通常独占对象
   → 可以继续补齐字段和依赖

   注册后
   → 对象进入共享并发世界
   → 字段修改必须遵守同步和生命周期规则

必须区分
--------

* 结构体定义与运行时对象：结构体定义描述内存布局；运行时对象还包含当前状态、注册关系、引用和释放规则。
* 分配与初始化：分配取得内存；初始化使字段和内部关系达到可用状态。
* 初始化与注册：初始化建立内部一致性；注册把对象发布给其它执行路径。
* 注销与释放：注销关闭新的发现入口；释放要等待所有旧持有者和异步执行者退出。
* 对象存活与对象可用：引用可保证内存存在；状态机决定当前操作是否仍然合法。
* 嵌入关系与生命周期保护：嵌入和 ``container_of()`` 解决对象转换；引用、锁或 RCU 才解决对象是否仍然有效。

一句话结论
----------

内核对象不是一块带字段的内存，而是一个从分配、发布、使用、注销到最终释放的状态机。
