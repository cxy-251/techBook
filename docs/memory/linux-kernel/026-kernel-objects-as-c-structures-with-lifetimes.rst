第026章：内核对象是具有生命周期的 C 结构体
=========================================

核心知识点
----------

内核对象不只是结构体实例
   结构体只规定内存布局。一个完整内核对象还包含当前状态、关联对象、操作回调、注册位置、所有权和释放规则。``task_struct``、``struct file``、``struct device`` 等都应按运行时对象理解。

对象构造分为不同阶段
   分配只取得内存，初始化使内部字段达到一致，注册才把对象发布给其它路径。三个阶段不能互相替代；尚未初始化完成的对象不应进入共享世界。

注册是并发可见性的边界
   对象进入链表、XArray、driver core、VFS、sysfs 或其它索引后，其它 CPU、用户入口和回调可能立即访问它。名称、锁、状态、操作表和释放回调应在发布前准备完成。

对象由状态机约束
   常见生命阶段包括 allocated、initialized、registered、active、dying、unregistered 和 released。进入 dying 后通常应拒绝新操作，状态迁移必须有明确方向和同步规则。

可发现、可操作和仍存活是三件事
   注册关系决定对象能否被找到，状态决定当前操作是否合法，引用和 RCU 等机制决定内存是否仍然有效。只满足其中一个条件不足以安全使用对象。

嵌入建立公共对象边界
   内核常把 ``kobject``、``device`` 或集合节点嵌入具体对象中，通用子系统操作公共成员，具体子系统通过 ``container_of()`` 返回宿主对象。内存布局转换不等于生命周期保护。

所有权决定字段与资源责任
   公共字段表达跨子系统合同，私有字段由对象所属子系统维护。调用者需要遵守操作表、锁和生命周期接口，不能绕过所有权边界直接修改内部状态。

注销先于最终释放
   注销关闭新的发现入口，旧调用链和异步任务仍可能持有对象。只有索引入口撤销、回调停止、引用归零并完成必要等待后，release 回调才能释放对象本体。

关键路径
--------

对象的完整生命线：

::

   分配内存
   → 初始化锁、引用、状态和操作表
   → 建立父子关系与私有资源
   → 注册并发布对象
   → active 状态处理请求
   → 标记 dying 并拒绝新操作
   → 注销所有发现入口
   → 等待旧引用和异步执行退出
   → release 回调
   → 释放对象内存

阅读一个内核对象：

::

   确认对象代表什么
   → 找分配与初始化位置
   → 找发布动作和外部入口
   → 找状态迁移与同步规则
   → 找 get、put 和异步持有者
   → 找注销动作
   → 找最终 release

概念辨析
--------

结构体定义与运行时对象
   结构体定义描述字段布局；运行时对象还包含状态、关系、可见性、引用和释放规则。

分配、初始化与注册
   分配取得内存；初始化建立内部一致性；注册把对象暴露给并发执行路径。

对象存活与对象可操作
   引用保证对象内存仍存在；状态机决定当前请求是否仍被允许。

注销与释放
   注销阻止新的发现和进入；释放必须等旧持有者和异步执行者全部离开。

嵌入关系与生命周期保护
   嵌入和 ``container_of()`` 解决对象转换；引用、锁或 RCU 才保证对象在转换后仍然有效。

本章结论
--------

内核对象是一台由内存承载的状态机：构造完成后才能发布，停止服务后先关闭入口，最后等待所有使用者离开再释放。
