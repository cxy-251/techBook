第103章：异步 I/O 与完成模型
============================

核心知识点
----------

异步 I/O 分离提交与完成
   提交调用返回通常只说明请求是否被接受。真实结果要在后续 completion 中取得，请求生命周期不会随提交调用栈结束。

请求具有多个时间点
   接受请求、进入文件系统、提交设备、设备完成、完成入队和用户消费是不同阶段。性能分析必须分别计时。

Outstanding work 必须有界
   已提交但尚未完成回收的请求会占用请求对象、文件引用、buffer、页面、队列槽位和业务状态。异步系统不能允许在途数无限增长。

背压约束提交速率
   长期提交速率高于完成消费速率时，队列必然膨胀。背压可通过深度上限、credit、部分提交、``EAGAIN`` 或主动暂停实现。

完成顺序不能作为身份
   缓存状态、设备并行和 worker 调度会导致乱序完成。每个请求都需要 token、索引、generation 或 ``user_data`` 关联原始业务对象。

完成结果不只是成功或失败
   短读、短写、EOF、部分提交和负 errno 都是合法结果。状态机必须按实际字节数和错误阶段推进。

提交错误与请求错误不同
   提交入口失败通常表示请求没有进入异步实例；完成队列中的错误表示某个已接受请求最终失败。

Readiness 与 Completion 不同
   ``epoll`` 等 readiness 模型表示 fd 当前可能可以推进 I/O，之后仍要执行非阻塞操作；AIO 与 ``io_uring`` completion 表示指定请求已产生结果。

通知与结果载体不同
   ``eventfd``、信号或唤醒只提示可能存在完成。请求身份、字节数和错误通常仍保存在完成队列中。

线程池也能提供异步接口
   提交线程不阻塞，worker 执行普通阻塞 syscall。它适合包装没有原生异步能力的操作，代价是线程栈、调度、队列锁和上下文切换。

内核异步不保证提交点零阻塞
   Buffered I/O、空间分配、文件系统锁、Page Cache miss 和元数据路径仍可能执行同步准备，或被转交到内核 worker。

Legacy Linux AIO 是完成队列模型
   ``io_setup``、``io_submit``、``io_getevents`` 和 ``io_destroy`` 通过 AIO context 管理请求与 ``io_event``。其稳定适用范围长期偏向受支持的 Direct I/O。

异步提高重叠而非单次设备速度
   主要收益来自让多个等待阶段并行和批量处理固定开销。设备饱和后继续增加深度通常只会增加排队与尾延迟。

取消不等于事务回滚
   请求可能已完成、正在完成或已经产生部分副作用。Cancel 与 timeout 必须处理目标不存在、不可取消和迟到 completion 的竞态。

Close 不等于取消
   在途请求可以持有独立 ``struct file`` 引用。关闭用户 fd 后，请求仍可能继续执行并产生完成事件。

资源只能在终结完成后释放
   Buffer、token、文件上下文和页引用必须活到请求最终 completion 被消费。Multishot 或重复通知还要等待明确终结状态。

Teardown 是反向生命周期协议
   先停止新提交，再取消或等待在途请求，持续消费 completion，确认计数归零，最后销毁队列、worker 和资源池。

关键路径
--------

异步请求生命周期：

::

   创建请求身份和 buffer
   → 尝试提交
   → 记录实际接受数量
   → 请求进入用户队列、内核或 worker
   → 文件系统 / 网络 / 设备执行
   → 生成 completion
   → 通知用户
   → 用户按 token 消费结果
   → 释放请求资源

Readiness 事件循环：

::

   epoll 监控 fd
   → 收到 ready 事件
   → 执行 nonblocking read/write
   → 得到完成、短 I/O 或 EAGAIN
   → 更新连接状态
   → 再次等待 readiness

线程池异步：

::

   提交线程写入有界任务队列
   → worker 取得任务
   → worker 执行阻塞 I/O
   → 返回值写入完成队列
   → 消费者处理结果
   → 归还任务、buffer 和 worker credit

安全关闭：

::

   标记 stopping
   → 拒绝新提交
   → 枚举 outstanding requests
   → 发起取消或等待自然完成
   → 持续消费终结 completion
   → 确认在途数为零
   → 释放 file / buffer / page 引用
   → 销毁 context、ring 或 worker

概念辨析
--------

* **提交成功与请求完成**：提交成功只说明请求已被接受；结果必须从 completion 获得。
* **Readiness 与 Completion**：Readiness 提示当前可尝试操作；completion 报告先前特定请求的结果。
* **异步 API 与异步执行**：接口分离提交和完成，底层可以原生异步、同步准备或转交线程。
* **完成通知与完成内容**：唤醒只说明有事件，完整请求结果仍需读取队列。
* **超时与请求终止**：调用者不再等待不代表底层工作已停止，迟到 completion 仍需处理。
* **Close fd 与 I/O 收束**：Close 移除句柄；异步请求自己的 file 引用和生命周期可能继续存在。

本章结论
--------

异步 I/O 的核心是管理有界的未完成工作。请求身份、背压、部分完成、取消竞态、完成消费和 teardown 必须组成闭合的生命周期协议。
