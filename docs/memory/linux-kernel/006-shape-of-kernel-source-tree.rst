第006章：Linux 内核源码树的结构
===============================

核心知识点
----------

源码目录表示工程归属
   Linux 内核顶层目录首先说明代码由哪个子系统维护，不表示一次请求的完整调用顺序。真实运行路径通常会跨越多个目录。

核心子系统目录
   ``kernel/`` 保存调度、进程、时间和核心基础设施；``mm/`` 保存内存管理；``fs/`` 保存 VFS 与文件系统；``net/`` 保存网络协议栈；``drivers/`` 保存总线、设备模型和具体驱动。

``arch/`` 承担架构差异
   ``arch/`` 处理启动、系统调用入口、异常、中断、页表、上下文切换和指令相关实现。通用代码表达 Linux 统一机制，架构代码提供 CPU 相关支撑。

头文件表达接口边界
   ``include/linux/`` 主要面向内核内部代码；``include/uapi/`` 保存用户态可见 ABI；``arch/*/include/asm/`` 和 ``arch/*/include/uapi/`` 保存架构相关接口。

生成头文件属于构建结果
   ``include/generated/`` 及架构生成目录由 Kconfig、架构和构建规则产生。它们说明目标构建最终得到什么定义，手写来源需要回到配置或生成规则定位。

文档、脚本与工具各有职责
   ``Documentation/`` 解释对象模型、接口和开发规则；``scripts/`` 保存构建、检查与生成逻辑；``tools/`` 保存 ``perf``、测试和其他用户态工具。它们辅助理解源码，但不代替运行路径证据。

先找通用对象，再进入架构细节
   阅读代码时应先确定子系统和核心对象。只有路径涉及寄存器、异常、页表、原子操作、内存屏障或用户访问约定时，再进入目标架构目录。

关键路径
--------

定位一个源码主题：

::

   判断问题所属资源或子系统
   → 找到对应顶层目录
   → 在头文件中确认核心对象和接口
   → 判断是否属于用户态 ABI
   → 判断是否依赖具体架构或生成配置
   → 沿对象和回调追踪跨目录运行路径

``read()`` 的目录级路径：

::

   arch/ 中的系统调用入口
   → fs/ 中的通用读取逻辑
   → include/linux/ 中的 struct file 与操作表
   → mm/ 与架构代码提供用户内存访问支撑
   → 文件系统、网络或 drivers/ 中的具体实现

概念辨析
--------

目录归属与调用顺序
   目录归属说明代码由哪个工程边界负责；调用顺序由函数、对象、状态和回调决定。

通用代码与架构代码
   通用代码定义跨架构共享的对象和机制；架构代码实现寄存器、异常、页表和指令等平台细节。

内核内部接口与用户态 ABI
   内核内部接口可以随源码演进；用户态 ABI 需要保持长期兼容。

手写头文件与生成头文件
   手写头文件是源码中的接口定义；生成头文件是特定配置和构建过程的产物。

本章结论
--------

源码树是一张工程地图：先用目录和头文件确定代码归属，再沿对象、状态和回调还原真正的跨目录执行路径。
