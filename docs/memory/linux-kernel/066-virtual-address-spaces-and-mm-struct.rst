第066章：虚拟地址空间与 mm_struct
=================================

核心知识点
----------

虚拟地址必须依附地址空间解释
   用户程序操作的是虚拟地址。同一个地址数值放在不同进程中，可以映射到不同物理页、文件内容或根本没有映射，因此地址值本身不能标识对象。

``mm_struct`` 是用户地址空间对象
   普通用户 task 通过 ``task_struct->mm`` 连接到 ``mm_struct``。该对象统一保存页表根、VMA 集合、地址布局、同步状态、统计信息和生命周期引用。

VMA 与页表承担不同职责
   VMA 描述一段地址范围允许怎样访问、内容来自哪里以及缺页时采用什么策略；页表记录具体虚拟页当前是否已建立映射，以及硬件应执行的页级权限。

映射存在不等于页面已经存在
   ``mmap``、堆和文件映射可以先建立 VMA，再在首次访问时通过缺页分配匿名页、装入文件页或建立写时复制页面。地址空间因此是策略与实际页面的组合，而不是一次性分配的连续内存。

地址空间修改需要分层同步
   ``mmap_lock`` 保护 VMA 集合和整体布局的结构性变化；具体页表更新还需要页表锁、TLB 失效和页面引用等更细粒度协议。一把地址空间锁不能覆盖所有页面生命周期。

线程、fork 与 exec 使用不同共享语义
   同一线程组通常共享一个 ``mm_struct``，任一线程修改映射都会影响其它线程。``fork`` 通常创建新的 mm 和页表结构，并通过 COW 共享物理页；``exec`` 则在当前 task 中替换原有用户程序映像。

``mm`` 与 ``active_mm`` 不是同一概念
   ``mm`` 表示 task 拥有的用户地址空间。内核线程通常没有用户 mm，但 CPU 仍需要合法页表上下文，因此通过 ``active_mm`` 暂时借用已有地址空间；这种借用不赋予用户内存访问语义。

地址空间采用分阶段释放
   ``mm_users`` 表示仍在使用用户地址空间的 task 或长期使用者；最后一个用户离开后可以拆除 VMA 和页表。``mm_count`` 管理描述符对象自身，只有该引用也归零后才能释放 ``mm_struct`` 内存。

关键路径
--------

解释一个用户虚拟地址：

::

   确认目标 task 与 PID namespace
   → 取得 task->mm
   → 在 mm 的 VMA 集合中查找地址
   → 检查范围、访问类型与 VMA 权限
   → 从 mm->pgd 检查页表项
   → 判断已映射、可修复缺页、权限错误或地址无效

地址空间的创建与共享：

::

   clone/fork 创建新 task
   → 根据 CLONE_VM 决定共享或复制 mm
   → 共享时多个 task->mm 指向同一对象
   → fork 时建立新 mm 与页表结构
   → 物理页通过 COW 暂时共享
   → exec 时提交并替换用户程序映像

地址空间释放：

::

   task 退出或归还地址空间使用权
   → mmput 递减 mm_users
   → 最后一个用户进入 __mmput
   → exit_mmap 删除 VMA 与页表映射
   → 归还描述符引用
   → mmdrop 递减 mm_count
   → 最后一个引用释放 mm_struct

内核线程的地址翻译上下文：

::

   用户 task 运行并拥有 mm
   → 切换到 mm 为 NULL 的内核线程
   → 内核线程借用 prev 的 active_mm
   → CPU 保留合法页表上下文
   → 切换到下一个用户 task 时执行真正的 mm 切换
   → 更新 ASID/PCID 与相关 TLB 状态

概念辨析
--------

虚拟地址与物理地址
   虚拟地址属于某个 mm 和页表；物理地址描述真实页框或设备资源位置。

VMA 与页表
   VMA 保存范围级策略；页表保存当前页级映射与硬件权限。

地址空间存在与页面驻留
   mm 和 VMA 可以长期存在，其中许多页面仍未分配、已换出或等待文件装入。

线程共享与进程独立
   共享同一 mm 的 task 观察同一套映射；不同 mm 即使包含相同地址数值，也属于不同地址空间。

``mm`` 与 ``active_mm``
   ``mm`` 表示 task 拥有用户地址空间；``active_mm`` 表示 CPU 当前使用或内核线程借用的翻译上下文。

``mm_users`` 与 ``mm_count``
   前者决定何时拆除用户映射，后者决定何时释放地址空间描述符本身。

本章结论
--------

``mm_struct`` 把虚拟范围、页表、线程共享、调度切换和分阶段释放组织成一个完整地址空间对象。分析任意用户地址时，必须先确定所属 mm，再逐层检查 VMA、页表和页面状态。
