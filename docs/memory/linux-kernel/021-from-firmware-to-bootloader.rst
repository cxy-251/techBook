第021章：从固件到 Bootloader
============================

核心知识点
----------

启动是分阶段的状态交接
   Linux 内核执行之前，固件和 bootloader 已经准备了 CPU 状态、可用内存、启动设备和启动材料。每一阶段都必须按架构协议把状态交给下一阶段。

固件建立最小平台环境
   BIOS、UEFI、Open Firmware、U-Boot 或虚拟机固件从 CPU 复位状态开始，完成最低限度的处理器、内存控制器和启动设备初始化，并选择下一段启动程序。

Bootloader 负责装载与交权
   Bootloader 选择目标内核，把内核镜像、initramfs、命令行和硬件描述放到合适的物理内存区域，再跳转到内核规定的入口。各区域必须满足对齐要求并避免相互覆盖。

启动材料构成入口状态包
   内核接收的不只是镜像，还包括命令行、内存映射、ACPI 表、设备树、initramfs 范围和寄存器状态。这些材料共同决定早期入口能够解释什么机器状态。

启动协议由架构定义
   x86 常通过 setup header 与 ``struct boot_params`` 传递信息；arm64 通常通过寄存器和 FDT 传递信息。镜像格式、入口地址、MMU、cache 和中断状态都必须符合目标架构协议。

EFI stub 可以承担 loader 角色
   启用 EFI stub 的 Linux 镜像可以作为 EFI 程序直接启动。Stub 在 UEFI 环境中收集命令行、initramfs 和内存映射，并在退出 Boot Services 后把控制权交给内核早期入口。

固件状态只是输入，不是最终内核状态
   固件可能已经发现设备和初始化部分硬件，Linux 仍会重新建立自己的页表、中断、调度、内存和驱动模型。内核必须验证并保存需要长期使用的固件数据。

安全验证与启动正确性是不同问题
   Secure Boot 验证启动组件是否来自受信任签名链；它不保证内核配置正确、代码没有缺陷或后续初始化一定成功。

关键路径
--------

通用启动交接：

::

   CPU 复位
   → 固件建立最小平台环境
   → 选择 bootloader 或 EFI stub
   → 加载内核镜像与 initramfs
   → 准备命令行和硬件描述
   → 按架构协议设置入口状态
   → 跳转到内核早期入口

x86 UEFI 常见路径：

::

   UEFI firmware
   → EFI 启动项
   → GRUB、systemd-boot 或 EFI stub
   → 加载 bzImage 和 initramfs
   → 填充 boot_params
   → 取得最终 UEFI memory map
   → 退出 Boot Services
   → 跳转到 x86 早期入口

概念辨析
--------

固件与 Bootloader
   固件首先建立平台最低运行条件并选择下一段程序；Bootloader 负责选择、放置内核启动材料并完成入口交接。

镜像已加载与内核已启动
   镜像已加载只说明文件进入内存；内核还必须完成入口执行、解压、地址映射和早期初始化。

启动协议与运行时 ABI
   启动协议约束 Bootloader 到内核入口的短暂交接；运行时 ABI 约束内核启动后对用户态提供的接口。

固件硬件状态与内核设备状态
   固件状态为内核接管提供起点；内核设备模型、驱动绑定和运行状态仍需重新建立。

Secure Boot 与系统正确性
   Secure Boot 证明签名链符合策略；系统正确性还取决于源码、配置、硬件描述和运行路径。

本章结论
--------

Linux 启动首先是一份架构相关的交接合同：固件和 Bootloader 必须把镜像、参数、硬件描述与 CPU 状态可靠地交给内核早期入口。
