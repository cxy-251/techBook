第076章：内核分配器家族与分配上下文
====================================

核心知识点
----------

分配器选择首先取决于资源形态
   内核申请的可能是物理页、普通字节对象、固定类型对象、连续虚拟区域或每 CPU 副本。资源粒度不同，对应的分配、访问和释放协议也不同。

Page allocator 管理物理页块
   ``alloc_pages()`` 一类接口以页和 ``order`` 为单位工作，直接受 node、zone、watermark、migratetype、物理连续性和回收能力约束。

Slab/SLUB 管理可复用对象槽位
   对象分配器从 page allocator 取得 backing pages，再把页面切分成固定大小槽位。它把高频小对象请求从页级慢路径中分离出来。

``kmalloc`` 提供通用大小等级
   普通小对象和字节缓冲区通常映射到通用 ``kmalloc-*`` cache。调用者只声明大小和 GFP，不携带独立对象类型语义。

专用 ``kmem_cache`` 表达对象类型
   高频同型对象可使用专用 cache 固化大小、对齐、构造、统计、回收和调试属性，使分配器围绕对象复用进行优化。

``vmalloc`` 只保证虚拟连续
   它把分散物理页映射成连续内核虚拟地址，适合 CPU 访问的大块区域，不提供物理连续或 DMA 可达保证。

Per-CPU allocator 用复制减少共享
   每个 possible CPU 获得独立副本，适合高频本地更新、低频聚合读取的状态。它用更多内存换取更少跨 CPU 竞争。

GFP 是执行上下文契约
   GFP 描述分配器能否睡眠、直接回收、进入 I/O 或文件系统路径以及使用哪些 zone。它不是单纯的成功概率或优先级提示。

分配成功只建立存储所有权
   对象初始化、发布、引用、异步回调、注销和最终释放仍需独立的生命周期协议。内存来源不会自动保护对象身份。

释放接口必须与来源匹配
   ``kmalloc`` family 对应 ``kfree()``，专用 cache 对应 ``kmem_cache_free()``，``vmalloc`` 对应 ``vfree()``，页分配对应匹配 order 的页释放接口，动态 per-CPU 内存对应 ``free_percpu()``。

设备内存需求必须使用 DMA API
   CPU 能访问、物理连续或来自低地址 zone，都不能替代 DMA mask、IOMMU、缓存一致性和总线映射协议。

关键路径
--------

选择分配器：

::

   确认申请单位与对象类型
   → 确认大小、对齐和连续性要求
   → 区分 CPU 访问与设备访问
   → 判断当前上下文能否睡眠和回收
   → 评估频率、NUMA 与缓存局部性
   → 选择 page、kmalloc、kmem_cache、vmalloc 或 per-CPU
   → 定义失败处理和匹配释放路径

小对象分配：

::

   子系统提出对象请求
   → 通用对象进入 kmalloc 大小等级
   或高频同型对象进入专用 kmem_cache
   → SLUB 优先使用本 CPU 可用槽位
   → 缺少槽位时取得 partial slab
   → 必要时向 page allocator 申请 backing pages
   → 调用者完成本次对象初始化并发布

分配失败回滚：

::

   分配返回 NULL
   → 不发布半初始化对象
   → 保留原始错误语义
   → 阻止已启动的异步入口
   → 按依赖逆序撤销引用和注册
   → 使用匹配接口释放已取得资源
   → 返回错误或执行预先设计的降级路径

对象最终释放：

::

   从查找结构摘除对象
   → 阻止新引用
   → 同步 RCU、timer、work、IRQ 与 DMA
   → 等待普通引用归零
   → 确认内存分配来源
   → 调用对应释放接口
   → 原对象地址和身份全部失效

概念辨析
--------

页分配与对象分配
   Page allocator 管理物理页块；slab/SLUB 把页切成适合高频复用的小对象槽位。

通用 cache 与专用 cache
   ``kmalloc`` 只按大小等级分类；``kmem_cache`` 还表达对象类型、对齐、构造和调试属性。

虚拟连续与物理连续
   CPU 线性访问通常只要求虚拟连续；硬件和 DMA 需求必须单独证明物理或总线布局。

GFP 与对象用途
   GFP 描述分配过程中允许执行的动作；对象用途描述返回内存之后怎样访问和管理。

释放存储与结束生命周期
   释放接口归还内存；调用前必须先结束所有查找、引用和异步访问。

快速尝试与前进保证
   ``GFP_ATOMIC`` 仍然可以失败；关键路径需要通过预分配、对象池或 mempool 建立前进保证。

本章结论
--------

内核分配器按页、对象、虚拟区域和每 CPU 副本分工。正确选择必须同时闭合资源形态、连续性、执行上下文、访问者能力和对象生命周期。
