第051章：上下文切换保存状态与恢复路径
=====================================

核心知识点
----------

上下文切换是真正的执行权转移
   调度器先选择 ``next`` task，``context_switch()`` 再把 CPU 从 ``prev`` 的执行环境交给 ``next``。选择任务与完成切换是两个连续但不同的阶段。

切换同时跨越三个状态层次
   调度器层处理运行队列和 task 状态，内存管理层处理地址空间，架构层保存并恢复栈、寄存器以及 CPU 私有状态。只读其中一层无法解释完整切换。

栈指针是控制流翻转的核心
   ``switch_to()`` 保存 ``prev`` 的内核栈位置并装入 ``next`` 的内核栈。栈切换后，返回地址和后续执行现场都来自 ``next``，因此函数表面上的“返回”实际发生在另一个 task 的历史执行流中。

内核执行现场与用户现场分开保存
   ``switch_to()`` 主要维护恢复内核执行所需的机器状态；用户态寄存器通常已由系统调用、异常或中断入口保存在 ``pt_regs`` 中。两套状态服务不同恢复边界。

地址空间切换取决于 mm 关系
   不同用户进程之间切换通常需要更换页表上下文，并处理 ASID、PCID 或 TLB 状态；共享同一 ``mm_struct`` 的线程仍要切换 task、内核栈和寄存器，但可减少地址空间成本。

内核线程通过 active_mm 维持地址翻译
   内核线程通常没有自己的用户 ``mm``，会借用当前 CPU 上的 ``active_mm``。这种借用只满足内核执行所需的地址转换，不赋予用户内存访问语义。

扩展 CPU 状态由架构规则管理
   FPU、SIMD、TLS、调试寄存器和安全相关状态的保存方式依赖架构与内核版本。阅读时应从目标架构的 ``switch_to`` 和线程状态结构出发，而不是套用固定寄存器清单。

切换前后存在严格交接协议
   ``prepare_task_switch()``、``switch_to()`` 和 ``finish_task_switch()`` 分别承担切换准备、机器状态转换和延后收尾。运行队列锁、前一 task 状态以及延迟的 mm 释放都可能跨越这条边界。

切换成本不只来自保存寄存器
   总成本包括调度决策、页表与 TLB 处理、架构状态保存恢复，以及切换后的缓存、分支预测和数据局部性损失。高切换次数必须结合运行区间和吞吐判断。

关键路径
--------

一次普通上下文切换：

::

   当前 task 进入 schedule
   → __schedule 更新 prev 状态并选择 next
   → context_switch(prev, next)
   → prepare_task_switch 完成交接准备
   → 切换 mm 或处理 active_mm
   → switch_to 保存 prev 栈与寄存器
   → 装入 next 栈与寄存器
   → finish_task_switch 在 next 的执行流中收尾
   → next 从上次暂停位置继续

地址空间处理：

::

   比较 prev 与 next 的 mm / active_mm
   → 共享同一 mm 时复用地址空间上下文
   → 不同用户 mm 时切换页表上下文
   → 更新架构地址空间标签
   → 按需要处理 TLB 状态
   → 内核线程进入 active_mm 借用路径

阅读架构切换实现：

::

   从 context_switch 找到 switch_to
   → 找保存 prev 栈指针的位置
   → 找装入 next 栈指针的位置
   → 确认返回地址与 current 如何切换
   → 检查 thread_struct 与扩展 CPU 状态
   → 回到 finish_task_switch 核对收尾责任

概念辨析
--------

调度决策与上下文切换
   调度决策确定谁应运行；上下文切换才真正改变 CPU 当前执行者。

内核切换现场与 pt_regs
   前者保证 task 的内核执行可以续接；后者主要保存用户态进入内核时的边界现场。

线程切换与地址空间切换
   共享地址空间的线程仍需切换栈、寄存器和调度状态；不同进程通常还要切换页表上下文。

mm 与 active_mm
   ``mm`` 表示 task 拥有的用户地址空间；``active_mm`` 可以只是内核线程临时借用的地址翻译上下文。

直接切换成本与局部性成本
   直接成本来自保存恢复和页表操作；局部性成本来自缓存、TLB 与预测状态变冷。

本章结论
--------

上下文切换的控制流转折点是架构代码装入 ``next`` 的内核栈；完整切换还必须同步交接调度状态、地址空间和扩展 CPU 状态。
