第130章：选择正确的驱动抽象
============================

核心知识点
----------

抽象选择从业务对象开始
   驱动设计首先要回答用户态和内核其它模块处理的最小对象是什么，再决定字符、块、网络、专业子系统或控制接口。

底层传输方式不能决定上层类型
   设备通过 USB、PCI、MMIO 或共享内存连接，只说明发现和传输路径；它最终可以注册为 netdev、block、DRM、IIO 或字符接口。

字符设备适合私有文件语义
   字节流、消息、事件和少量私有命令可用字符设备或 misc，但驱动要独自承担 UAPI、权限、阻塞、并发、工具和兼容责任。

块设备要求存储合同
   只有设备真正提供稳定 sector 地址、容量、随机访问、请求完成与持久化语义时，块设备抽象才成立。

网络设备要求 packet 合同
   只有数据应进入 socket、协议栈、routing、qdisc 和 NAPI 时才应注册 ``net_device``；底层使用 packet 传输并不自动等于网络接口。

已有专业子系统应优先复用
   Sample、input event、video frame、audio stream、terminal、display、sensor channel 等已有标准模型时，应优先选择 IIO、input、V4L2、ALSA、tty、DRM、hwmon 等子系统。

总线模型与功能模型正交
   Bus 负责设备发现、资源、匹配、probe/remove；功能子系统负责数据对象、用户接口、队列、命名空间和工具。两者必须分别设计。

控制面与数据面应分离
   数据面关注 buffer、队列、吞吐和所有权；控制面关注配置、状态、权限和管理。一个设备可以有多个接口，但必须共享单一硬件状态机。

控制接口各有边界
   Sysfs 适合单值对象属性，ioctl 适合文件实例上的私有命令，netlink 适合可扩展多对象消息与事件，configfs 适合用户创建配置对象，debugfs 只用于调试。

Mmap 和零拷贝不是设备分类
   Mmap、DMA-BUF、共享 ring 和 io_uring 是传输优化。它们必须建立在清晰的数据对象、buffer ownership、通知和 teardown 协议之上。

UAPI 是长期维护合同
   节点名、读写单位、阻塞、poll、ioctl、结构布局、mmap offset 和错误码都会成为兼容负担。内核内部结构和地址不能直接泄漏为 UAPI。

性能优化必须由证据驱动
   应先测量 syscall、复制、锁、queue、DMA、IRQ 和设备服务时间，再决定 batch、共享内存或零拷贝。实现方便或理论少一次复制不能证明抽象正确。

安全与可观测性属于抽象的一部分
   专业子系统通常已有权限、命名空间、统计、tracepoint 和工具；私有接口必须自行提供同等的隔离、审计和故障证据。

生命周期由所选对象决定
   字符设备要收束 fd/VMA，块设备要收束 open/request，网络设备要收束 skb/NAPI。抽象选择同时决定 remove 的并发边界。

关键路径
--------

选择功能抽象：

::

   写出最小业务对象
   → 判断是否已有内核专业子系统
   → 若是稳定 sector 地址空间，选择 block
   → 若是网络 packet，选择 net_device
   → 若是私有字节、消息或命令，评估 char/misc
   → 明确数据面、控制面和对象所有者
   → 再设计总线 probe、资源与 teardown

设计控制接口：

::

   单值、对象相关属性
   → sysfs
   → 文件实例私有控制
   → ioctl
   → 多对象结构化消息与事件
   → netlink
   → 用户创建和销毁配置对象
   → configfs
   → 仅开发诊断
   → debugfs

设计私有 UAPI：

::

   定义对象和操作语义
   → 使用固定宽度字段、size/version 和保留空间
   → 定义阻塞、超时、取消、poll 和错误码
   → 定义权限、namespace 和并发
   → 定义 reset、remove 和旧句柄行为
   → 编写 ABI 文档与兼容测试
   → 建立故障注入和模糊测试

概念辨析
--------

Bus 抽象与功能抽象
   Bus 决定设备怎样出现并取得资源；功能抽象决定系统怎样使用该设备。

字符设备与 Misc
   两者都提供文件操作；misc 只简化注册和 minor 管理，不改变 UAPI 与生命周期责任。

块设备与内存映射设备
   块设备承诺 sector、容量和存储语义；存在可映射内存并不足以满足该合同。

网络接口与私有 packet 通道
   Netdev 进入完整网络栈；私有 packet 字符通道不自动获得 routing、qdisc、NAPI 和 namespace 能力。

正式 ABI 与 Debug 接口
   Sysfs、ioctl、netlink 等正式接口需要长期兼容；debugfs 不承诺稳定，不能成为生产依赖。

正确基线与性能优化
   先选择能准确表达数据模型的接口，再针对已测得瓶颈优化传输方式；优化手段不能补救错误抽象。

本章结论
--------

正确驱动抽象由业务数据模型决定：优先复用能够准确表达该对象的内核子系统，再补充最小控制面，并把 ABI、安全、性能、可观测性和 teardown 作为同一项长期设计。
