第061章：内核并发中的上下文、生命周期与顺序
==========================================

核心知识点
----------

并发正确性由三条证明链组成
   任何共享对象都必须同时说明：访问发生在哪种执行上下文、对象在访问期间为何仍然存活、其它 CPU 按什么顺序观察状态变化。缺少任意一条，代码都可能在罕见交错中失败。

并发来源不限于多个线程
   多 CPU、内核抢占、hardirq、softirq、timer、workqueue、IRQ thread 和 RCU callback 都能形成并发访问。阅读代码时必须列出所有访问入口，而不是只看当前函数的调用者。

局部执行控制不能替代跨 CPU 同步
   关闭本 CPU 的抢占、IRQ 或 bottom half，只能阻止本 CPU 上某类执行流插入。其它 CPU 仍可同时访问共享对象，因此全局数据通常还需要锁、原子操作、per-CPU 设计或 RCU 协议。

上下文决定同步原语
   Hardirq 和普通 softirq 不能睡眠，通常使用 spinlock、原子操作、per-CPU 数据或 RCU。进程、workqueue 和 IRQ thread 通常可以睡眠，可以使用 mutex、rwsem 和等待机制，但持有 spinlock 或关闭 IRQ 后仍进入原子区。

锁、引用和屏障解决不同问题
   锁保护临界区和复合不变量；引用计数保证对象内存继续存在；RCU 保护短期查找和延迟回收；内存屏障约束跨 CPU 可见顺序。它们不能互相替代。

发布对象必须先初始化再公开
   生产者应完成所有读者可见字段，再通过锁、RCU、release store 或其它发布操作公开指针或 ready 状态。消费者只有通过匹配的锁、RCU 或 acquire 操作观察发布信号后，才能可靠读取对象内容。

删除对象不等于立即释放
   从链表、XArray 或全局指针中摘除对象，只能阻止新查找者获得它。旧引用、RCU 读者、timer、work、IRQ、DMA 和已有回调仍可能继续访问，最终释放必须等待这些路径全部结束。

一把锁只保护遵守该协议的访问
   锁内写入与绕开锁的无锁读取之间不存在自动同步关系。每个共享字段都必须明确由哪种协议保护，不能因为某条路径“曾经持锁”就认为其它路径也安全。

原子变量只保护指定内存位置
   原子读改写可以防止单个计数或状态丢失更新，但多个字段之间的一致性仍需锁、seqcount、RCU 替换或明确的内存顺序协议。

工具验证的是某类违规现象
   Lockdep 发现锁依赖和上下文问题，KCSAN 发现部分数据竞争，KASAN 发现越界与 use-after-free，refcount 和 RCU 调试检查生命周期协议。报警必须回到上下文、生命周期或顺序规则解释根因。

关键路径
--------

分析一个共享对象：

::

   找到对象定义、创建点和发布点
   → 列出进程、IRQ、softirq、timer、work 和 RCU 访问者
   → 标记每条路径是否可睡眠、是否跨 CPU、是否允许抢占
   → 为每个共享字段标注锁、原子、RCU 或 per-CPU 协议
   → 为每个指针标注引用与释放责任
   → 写出发布侧与观察侧的内存顺序
   → 检查停止入口、同步回调和最终释放

安全发布对象：

::

   分配对象
   → 初始化字段、锁、引用和状态
   → 建立宿主关系与释放回调
   → 使用锁、RCU 或 release 操作发布
   → 读者通过匹配协议取得指针
   → 成功取得生命周期保证后使用对象

安全删除对象：

::

   标记对象 dying
   → 从所有查找入口摘除
   → 阻止新请求、IRQ 和异步工作
   → 同步 timer、work、IRQ、DMA 与回调
   → 等待 RCU 旧读者
   → 等待长期引用归还
   → 释放底层资源
   → 最后释放对象内存

验证罕见交错：

::

   写出两个或多个执行流
   → 在锁、引用、发布和删除点插入切换
   → 加入另一 CPU、IRQ、抢占和失败返回
   → 检查未初始化读取、丢失更新、重复释放和悬空指针
   → 使用 lockdep、KCSAN、KASAN 和 fault injection 验证

概念辨析
--------

局部执行控制与跨 CPU 同步
   关抢占、关 IRQ 和关 bottom half 只约束本 CPU；跨 CPU 数据仍需要正式同步协议。

互斥与生命周期
   锁保证临界区内没有冲突访问；引用、RCU 和同步取消保证对象在访问期间仍然存在。

原子性与内存顺序
   原子性保证单个位置的操作不可分割；内存顺序约束多个位置被其它 CPU 观察的先后关系。

删除与释放
   删除关闭新发现入口；释放必须等待全部旧使用者和异步路径退出。

可抢占与可睡眠
   可抢占表示调度器可以切换 task；可睡眠表示当前路径可以主动阻塞等待，二者不是同一属性。

本章结论
--------

内核并发不能简化为“加一把锁”：共享对象只有同时闭合执行上下文、对象生命周期和跨 CPU 顺序三条证明链，才具备完整正确性。
