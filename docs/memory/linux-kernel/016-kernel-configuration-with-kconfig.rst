第016章：使用 Kconfig 配置 Linux 内核
=====================================

核心知识点
----------

Kconfig 定义功能选择空间
   Kconfig 描述内核功能有哪些配置符号、符号取值范围以及它们之间的依赖关系。源码存在只说明功能具备实现来源；目标内核是否包含该功能，由最终配置和构建结果决定。

配置符号进入不同表示层
   Kconfig 文件中的符号通常写作 ``FOO``，写入 ``.config``、Makefile 和 C 代码后表现为 ``CONFIG_FOO``。``.config`` 是当前目标构建经过 Kconfig 求值后的最终配置输入。

布尔值与三态值决定构建形态
   ``bool`` 只有 ``y`` 和 ``n``；``tristate`` 具有 ``y``、``m``、``n``。``y`` 表示内建，``m`` 表示构建成模块，``n`` 表示不进入本次构建。

依赖关系限制可选状态
   ``depends on`` 规定当前符号成立所需的前提；依赖不满足时，符号可能不可见或无法启用。菜单中看不到配置项，不代表符号不存在。

默认值不是强制值
   ``default`` 只在依赖成立且没有更高优先级选择时提供初始值。它不能绕过依赖，也不等于最终 ``.config`` 中一定采用该值。

``select`` 与 ``imply`` 是反向关系
   ``select`` 由当前符号强制提高目标符号的值，可能绕过目标自身依赖，适合依赖简单的底层辅助能力。``imply`` 只是较弱建议，仍允许依赖和用户选择影响最终结果。

配置工具服务不同场景
   ``menuconfig`` 适合交互搜索和调整；``defconfig`` 提供架构基线；``oldconfig`` 或 ``olddefconfig`` 用于迁移旧配置；``localmodconfig`` 根据当前已加载模块裁剪，可能误删未来需要的能力。

配置结果同时供 Make 和 C 使用
   构建过程会生成 ``include/config/auto.conf`` 供 Kbuild 读取，并生成 ``include/generated/autoconf.h`` 供 C 预处理使用。生成文件是当前配置的构建产物，不应手工维护。

配置状态与代码可达性不同
   ``IS_BUILTIN()`` 判断功能是否内建，``IS_MODULE()`` 判断是否为模块，``IS_ENABLED()`` 判断是否为 ``y`` 或 ``m``。``IS_REACHABLE()`` 还考虑当前编译单元是否能实际调用模块化实现。

关键路径
--------

从配置符号到内核能力：

::

   Kconfig 定义符号
   → 计算类型、依赖、默认值和反向关系
   → 生成最终 .config
   → 生成 auto.conf 与 autoconf.h
   → Kbuild 根据 CONFIG_* 选择对象
   → 代码进入 vmlinux、生成 .ko 或被排除
   → 运行时再确认模块加载和实际路径

三态配置：

::

   CONFIG_FOO=y
   → 内建对象
   → 链接进入内核镜像

   CONFIG_FOO=m
   → 生成模块文件
   → 运行时按依赖和策略加载

   CONFIG_FOO=n
   → 不进入本次构建

配置迁移：

::

   保存旧 .config
   → 固定新源码版本
   → 执行 olddefconfig 或 oldconfig
   → 审查新增、改名和默认值变化
   → 保存新的最终 .config

概念辨析
--------

源码存在与功能可用
   源码存在只说明功能可以被构建；配置、构建产物和运行状态共同决定功能是否可用。

``y`` 与 ``m``
   ``y`` 随内核镜像进入系统；``m`` 还依赖匹配的模块文件、符号、签名、依赖数据库和加载时机。

``depends on`` 与 ``select``
   ``depends on`` 限制当前符号；``select`` 从当前符号反向提高另一个符号，不能用来掩盖复杂依赖。

配置起点与最终配置
   defconfig、旧配置和人工选择只是生成过程；Kconfig 求值后的最终 ``.config`` 才是实际构建输入。

``IS_ENABLED()`` 与 ``IS_REACHABLE()``
   ``IS_ENABLED()`` 只判断功能是否被构建；``IS_REACHABLE()`` 还判断当前代码能否链接或调用该实现。

本章结论
--------

Kconfig 先定义功能能否被选择以及以何种形态进入系统，最终 ``.config`` 才把这种选择固定为目标内核的构建能力。
