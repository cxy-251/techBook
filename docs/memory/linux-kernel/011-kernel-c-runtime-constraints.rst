第011章：Linux 内核 C 的运行时约束
==================================

核心知识点
----------

内核 C 运行在受约束环境中
   Linux 内核使用 C，但代码运行在特权级、共享内核地址空间、并发执行和硬件中断环境中。判断一段代码是否合法，必须同时考虑执行上下文、锁状态、地址空间和硬件访问规则。

内核不依赖用户态运行时
   内核不能使用用户态 ``libc`` 作为基础。内存分配、日志、字符串处理、用户访问和错误传播都由内核 API 提供，并带有额外的上下文与生命周期语义。

GNU C 扩展表达编译期语义
   内核通常使用 GNU C 方言，并借助 ``typeof``、statement expression、属性和宏构造通用机制。``__init``、``__noreturn``、``__must_check`` 等标记会影响代码段、控制流判断或编译器检查。

执行上下文决定可调用能力
   进程上下文在未持有原子锁等限制时可以睡眠；硬中断、软中断、持有 spinlock 或关闭中断的路径不能调用可能睡眠的接口。同一个 helper 在不同调用点可能具有不同合法性。

分配标志属于接口合同
   ``GFP_KERNEL`` 表示分配过程可以睡眠、回收或等待，适合允许睡眠的上下文；原子路径需要使用相应的原子分配策略或把工作延后到可睡眠上下文。分配标志不是性能提示，而是调用点约束。

指针携带地址空间语义
   普通内核指针、``__user``、``__iomem``、``__percpu`` 和 ``__rcu`` 指针代表不同访问规则。类型标记帮助编译器、Sparse 和维护者识别错误混用，但真正访问仍需使用对应 helper。

用户地址必须受控访问
   ``__user`` 指针属于用户地址空间，不能直接解引用。``copy_from_user()``、``copy_to_user()``、``get_user()`` 和 ``put_user()`` 负责跨边界访问，并可能因缺页而睡眠。

I/O 地址和物理地址不是普通指针
   ``__iomem`` 地址通常通过 ``readl()``、``writel()`` 等访问器读写，以保留访问宽度和顺序语义。物理地址必须先按架构和映射规则转换为可访问的虚拟地址，不能直接作为 C 指针使用。

关键路径
--------

判断一个内核调用点是否合法：

::

   确定入口类型
   → 判断进程上下文或原子上下文
   → 检查锁、抢占和中断状态
   → 识别指针所属地址空间
   → 检查 API 是否可能睡眠
   → 检查分配标志和访问 helper
   → 确认错误与清理路径

用户数据复制：

::

   char __user *ubuf
   → 在允许睡眠的进程上下文中进入
   → 分配内核缓冲区
   → copy_from_user() 执行受控复制
   → 失败时释放已取得资源
   → 返回 -EFAULT 或其它负错误码

概念辨析
--------

普通 C 语法与内核 C 语义
   语法仍是 C；代码是否合法却取决于上下文、地址空间、并发和硬件规则。

进程上下文与原子上下文
   进程上下文在条件允许时可以调度和睡眠；中断、持有 spinlock 等原子路径必须保持不可睡眠。

``__user`` 标记与用户访问
   ``__user`` 说明指针来源；``copy_*_user()`` 等 helper 才真正执行受控访问。

``__iomem`` 与普通内存
   ``__iomem`` 表示设备映射，访问可能具有宽度、顺序和副作用；普通 RAM 可以按常规内存语义访问。

物理地址与虚拟指针
   物理地址标识硬件地址空间中的位置；虚拟指针才是 CPU 当前地址空间中可解引用的地址。

本章结论
--------

阅读内核 C 时，必须先判断代码运行在什么上下文、操作哪类地址、允许哪些阻塞和访问行为，再解释普通 C 控制流。
