第008章：怎样阅读 Linux 内核数据结构
===================================

核心知识点
----------

结构体是内核对象模型
   内核使用 C 结构体表达运行对象。阅读结构体时应先确定它代表什么，再识别身份、状态、对象关系、集合位置、操作和生命周期。

字段类型提供阅读线索
   指针通常表示对象关系，整数和枚举通常表示状态，集合节点表示对象属于某个容器，函数指针表示可执行操作，锁与引用计数表示并发和生命周期约束。

结构体嵌入建立对象组合
   内核把 ``list_head``、``rb_node``、``rcu_head``、``work_struct`` 等通用成员嵌入业务对象，使同一对象能够直接接入链表、树、RCU 或异步执行框架。

``container_of`` 恢复宿主对象
   ``container_of(ptr, type, member)`` 根据成员地址和固定偏移反推出宿主对象。``list_entry()``、``hlist_entry()`` 和 ``rb_entry()`` 都使用同类思想。

侵入式集合只管理节点关系
   链表、哈希链表和红黑树通常不额外包装业务对象，而是操作嵌入对象中的节点。一个对象可以通过不同成员同时加入多个集合。

不同容器解决不同索引问题
   ``list_head`` 适合顺序遍历，``hlist`` 常用于哈希桶，红黑树按可排序键组织对象，XArray 使用整数索引映射对象。容器选择反映查找和更新方式。

操作表表达运行时多态
   ``file_operations``、``net_device_ops`` 和 ``address_space_operations`` 让通用代码面对统一对象，并由具体子系统填入回调实现。

生命周期决定指针是否有效
   内存布局和容器关系只能说明怎样找到对象，不能证明对象仍然存活。对象有效性必须由引用计数、锁、RCU 或明确所有权保证。

关键路径
--------

阅读一个内核结构体：

::

   确定结构体代表的运行对象
   → 分类身份、状态和关系字段
   → 找到嵌入的集合节点
   → 确认对象加入哪些容器
   → 找到锁、引用计数与释放方式
   → 找到操作表或函数指针
   → 沿对象关系和回调进入下一层机制

文件读取中的对象链：

::

   current task_struct
   → files_struct 与 fd table
   → struct file
   → struct inode 与 address_space
   → file_operations
   → read_iter 回调
   → 页缓存、文件系统或设备实现

侵入式容器的通用关系：

::

   宿主对象嵌入容器节点
   → 容器代码操作节点
   → entry/container_of 恢复宿主对象
   → 锁、引用或 RCU 保证对象有效
   → 子系统继续处理宿主状态

概念辨析
--------

结构体定义与运行对象
   结构体定义只描述内存布局；对象经过分配、初始化、注册并进入生命周期后才成为运行实体。

成员地址与有效对象
   ``container_of`` 可以计算宿主地址；引用、锁或 RCU 才能证明该对象当前可以访问。

从集合删除与释放对象
   删除节点只改变集合成员关系；对象是否释放由所有权和引用规则决定。

操作表字段与具体回调
   字段只是统一的回调槽位；具体函数由操作表实例的初始化和对象绑定决定。

本章结论
--------

内核结构体应被读成对象模型：嵌入和容器说明对象怎样组织，操作表说明对象怎样行动，生命周期规则说明对象何时仍然有效。
