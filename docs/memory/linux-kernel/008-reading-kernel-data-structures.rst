第008章：怎样阅读 Linux 内核数据结构
===================================

本章必须记住
------------

#. Linux 内核使用 C 结构体表达运行对象；阅读结构体的目标是还原对象身份、状态、关系、集合位置、操作和生命周期。
#. ``task_struct`` 表示一个调度实体及其进程或线程状态，``struct file`` 表示一次打开产生的文件对象，``struct inode`` 表示文件系统对象身份，``sk_buff`` 表示网络包缓冲对象。
#. 指针字段通常表示对象关系，整数和枚举字段通常表示状态，集合节点表示对象属于某个集合，函数指针表示可执行操作。
#. 锁、引用计数、RCU 成员和释放回调表示对象的并发与生命周期约束。
#. 结构体嵌入把通用成员直接放进宿主对象内部，使成员拥有固定偏移。
#. ``container_of(ptr, type, member)`` 根据成员地址、宿主类型和成员名反推出宿主对象地址。
#. ``list_entry()``、``hlist_entry()`` 和 ``rb_entry()`` 等宏都建立在“从集合节点返回宿主对象”的思想上。
#. ``container_of`` 只能证明内存布局关系，不能证明宿主对象仍然存活；对象有效性还需要引用、锁或 RCU 等保护。
#. Linux 的链表、哈希链表和红黑树通常是侵入式集合：节点嵌入宿主对象，集合基础设施不单独保存业务对象。
#. 一个对象可以通过不同节点成员同时加入多个集合，因此看到节点时必须确认使用的是哪个成员。
#. ``list_head`` 适合通用双向链表，``hlist`` 常用于哈希桶，红黑树适合按可排序键组织对象。
#. XArray 用整数索引映射对象，内核常用它管理页缓存、ID 空间或其它按索引访问的数据。
#. 集合操作只说明节点被插入、查找或删除，不自动说明宿主对象已创建或释放。
#. 操作表是内核用 C 表达多态的主要方式；通用代码持有统一对象，具体子系统把函数地址填入操作表。
#. ``file_operations``、``net_device_ops`` 和 ``address_space_operations`` 分别把通用文件、网络设备和地址空间操作连接到具体实现。
#. 阅读操作表时必须找到操作表实例、赋值位置、对象如何取得该操作表以及回调运行时所需状态。

必背路径
--------

阅读一个结构体时采用以下顺序：

::

   确定结构体代表什么运行对象
   → 分类身份字段、状态字段和关系指针
   → 找到嵌入的集合节点
   → 确定对象加入哪些链表、树、哈希表或 XArray
   → 找到锁、引用计数和释放方式
   → 找到操作表或函数指针
   → 沿对象关系和回调进入下一子系统

以文件读取对象关系为例：

::

   current task_struct
   → files_struct 与文件描述符表
   → struct file
   → struct inode 与 address_space
   → file_operations
   → read 或 read_iter 回调
   → 页缓存、文件系统或设备实现

侵入式集合的通用读法：

::

   宿主对象中嵌入集合节点
   → 集合代码只操作节点
   → entry/container_of 宏恢复宿主对象
   → 子系统继续读取宿主状态
   → 引用、锁或 RCU 保证对象仍然有效

必须区分
--------

* 结构体定义与运行对象：结构体定义描述内存布局；分配、初始化、注册和生命周期规则使实例成为运行对象。
* 成员地址与宿主对象有效性：``container_of`` 能计算宿主地址；它不能保证该地址对应的对象仍然存活。
* 从集合删除与释放对象：删除节点只改变集合关系；对象是否释放由所有权和引用规则决定。
* 操作表字段与具体函数：字段只是回调槽位；具体目标由某个操作表实例中的赋值决定。

一句话结论
----------

内核结构体不是字段清单，而是对象模型；嵌入、集合、操作表和生命周期规则共同决定对象怎样被找到、调用和释放。
