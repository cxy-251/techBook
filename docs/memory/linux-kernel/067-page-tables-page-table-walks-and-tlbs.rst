第067章：页表、页表遍历与 TLB
=============================

核心知识点
----------

页表同时表达翻译与权限
   页表把虚拟页连接到物理页框，并编码 present、用户访问、读写和执行权限。内核关于隔离、共享和保护的决定，最终必须转换成 MMU 能执行的页表项。

Linux 使用统一的多级页表模型
   通用代码以 PGD、P4D、PUD、PMD、PTE 描述层级。具体架构可以折叠部分层级，也可以在 PUD 或 PMD 等中间层建立大页叶子映射，因此软件五级名称不等于固定五次硬件访存。

虚拟地址由索引和页内偏移组成
   地址高位用于逐级选择页表项，低位页内偏移在翻译前后保持不变。叶子表项中的 PFN 与页内偏移共同形成最终物理地址。

硬件与软件都会遍历页表
   TLB miss 后，MMU 从当前页表根执行硬件 walk；缺页、权限修改、回收、迁移和调试路径则由内核执行软件 walk。两者都必须正确解释普通页、大页和特殊表项。

Not-present 不等于非法地址
   页表项缺失可能代表尚未分配的匿名页、未装入的文件页、swap 条目或已撤销映射。CPU 产生 page fault 后，内核还要结合 VMA 判断该访问能否被合法修复。

TLB 是页表翻译结果的 CPU 缓存
   TLB 命中时，CPU 不必重新遍历页表。它同时缓存地址翻译和权限，因此提高访问速度，也使页表更新必须同步处理旧缓存项。

页表修改只有在 TLB 失效后才完成
   清除或降低页表权限后，旧 TLB 项仍可能允许访问。修改协议必须选择单页、范围、整个 mm 或更广的失效粒度，并在必要时等待其它 CPU 完成 shootdown。

页表更新遵循先建立、后发布与先撤销、后释放
   建立映射时先准备页面和下级页表，再发布叶子项；撤销映射时先清除表项并失效 TLB，确认旧翻译不可再用后，才能释放页面和页表页。

关键路径
--------

硬件地址翻译：

::

   CPU 产生虚拟地址
   → 查询 TLB
   → 命中时取得 PFN 与权限
   → 未命中时从当前页表根开始 walk
   → PGD → P4D → PUD → PMD → PTE
   → 识别普通页、大页或无效表项
   → 检查访问权限
   → 组合 PFN 与页内偏移
   → 把结果缓存到 TLB

缺页处理：

::

   页表 walk 无法完成访问
   → CPU 产生 page fault
   → 内核取得故障地址和访问类型
   → 查找覆盖地址的 VMA
   → 验证范围与权限
   → 分配匿名页、装入文件页、执行 COW 或换入 swap
   → 建立新页表项
   → 完成必要 TLB 处理
   → 返回并重试原指令

撤销映射：

::

   在地址空间与页表同步下定位表项
   → 清除或替换叶子映射
   → 记录需要失效的地址范围
   → 执行本地 TLB invalidation
   → 向正在使用该 mm 的远端 CPU 发起 shootdown
   → 等待旧翻译失效
   → 归还页面和页表页引用

批量解除映射：

::

   收集待删除的页表范围
   → 使用 mmu_gather 等机制延迟资源回收
   → 批量清除页表项
   → 合并 TLB flush 范围
   → 完成失效
   → 批量释放旧页面与页表页

概念辨析
--------

VMA 权限与页表权限
   VMA 是范围级策略；页表项是当前每页由硬件执行的实际权限。

软件页表层级与硬件页表层级
   Linux 提供统一五级接口；架构可以折叠层级或使用中间层大页映射。

页表与 TLB
   页表是内存中的权威映射结构；TLB 是 CPU 对翻译和权限的缓存。

清除表项与撤销访问
   软件表项改变不代表硬件立即停止使用旧翻译，只有相关 TLB 失效完成后访问才真正撤销。

地址空间标签与 TLB 失效
   ASID、PCID 可以区分不同 mm 的缓存项并减少切换开销，但不能取消同一 mm 修改后的失效要求。

Page fault 与程序错误
   Fault 可能是正常的延迟分配、文件装入或 COW；VMA 缺失或权限不允许时才构成非法访问。

本章结论
--------

页表把虚拟内存策略转换成硬件可执行的翻译和权限，TLB 则缓存这一结果。任何页表更新都必须把软件结构、远端 CPU 的缓存翻译和页面生命周期作为同一协议处理。
