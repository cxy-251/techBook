第041章：task_struct 是 Linux 内核的任务对象
============================================

核心知识点
----------

task 是内核的基本执行实体
   ``struct task_struct`` 表示一个能够被调度、阻塞、唤醒和退出的执行实体。调度器直接处理 task，而不是用户所说的“应用程序”。

进程通常由线程组表示
   用户态的一个进程通常对应一个线程组。线程组中的每个线程都有独立的 ``task_struct``，但共享一部分进程级资源。

PID 与 TGID 表达两种身份
   ``pid`` 对应具体 task 的线程 ID，``tgid`` 对应线程组的进程级 ID。单线程进程中二者通常相同，多线程进程中各线程 PID 不同而 TGID 相同。

PID 身份受 namespace 影响
   同一个 task 可以在不同 PID namespace 中拥有不同编号。用户态看到的 PID 必须结合观察者所在 namespace 才有完整意义。

task_struct 是资源关系中心
   ``task_struct`` 通过 ``mm``、``files``、``fs``、``signal``、``sighand``、``cred`` 和 ``nsproxy`` 等字段连接地址空间、文件表、路径上下文、信号、权限与 namespace。字段指向同一对象表示共享，指向不同对象表示资源边界已经分离。

current 表示当前执行的 task
   ``current`` 指向当前 CPU 正在执行的 task。它可能是用户线程、内核线程或 kworker，不能仅凭 ``current`` 存在就假定当前路径具有普通用户进程语义。

task 与资源对象具有独立生命周期
   task 退出时会归还它持有的资源引用，但共享的 ``mm_struct``、``files_struct`` 或其它对象可能继续被其它 task 使用。task 的结束不等于所有关联资源同时销毁。

退出分为停止执行与最终回收
   task 完成退出后可能进入 zombie 状态，保留退出码和统计信息供父进程读取。父进程执行 ``wait*()`` 后，task 才进入最终回收阶段。

关键路径
--------

从用户态 PID 还原内核对象关系：

::

   确认观察者所在 PID namespace
   → 区分 PID、TGID 与线程组
   → 定位具体 task_struct
   → 判断问题属于单个 task 还是线程组
   → 沿 mm、files、signal、cred 或 nsproxy 继续追踪
   → 检查这些对象是共享还是独立

读取一个 task：

::

   先看调度状态
   → 再看 pid、tgid、group_leader 和父子关系
   → 再看 mm、files、fs、signal、cred 与 namespace
   → 判断资源共享边界
   → 最后确认创建、运行、退出或回收阶段

任务生命周期：

::

   创建 task_struct
   → 建立身份与资源引用
   → 加入调度和任务关系
   → 独立运行、睡眠和唤醒
   → 进入退出路径
   → 归还运行资源引用
   → 保存退出信息成为 zombie
   → 父进程回收
   → 最终释放 task 对象

概念辨析
--------

进程与 task
   进程通常是线程组及其共享资源的用户态概念；task 是内核可独立调度的执行对象。

PID 与 TGID
   PID 标识具体 task；TGID 标识线程组的进程级身份。

task 对象与资源对象
   ``task_struct`` 组织关系；地址空间、文件表、信号与凭证由各自对象管理生命周期。

共享与复制
   多个 task 指向同一资源对象表示共享；指向不同对象但初始内容相同表示复制。

current 与用户进程语义
   ``current`` 始终存在；只有当前路径代表用户任务时，用户地址空间和调用者身份才具有相应意义。

退出与释放
   task 停止执行后仍可能以 zombie 或被引用对象存在，最终释放发生在回收和引用归零之后。

本章结论
--------

``task_struct`` 是 Linux 执行身份与资源关系的中心对象；理解进程问题时，应从具体 task 出发，再判断它与线程组、地址空间、文件表和其它资源的共享关系。
