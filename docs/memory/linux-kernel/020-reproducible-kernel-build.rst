第020章：建立可复现的 Linux 内核构建
=====================================

核心知识点
----------

可复现构建要求输入可追溯
   同样的源码、补丁、配置、工具链和环境输入，应能再次产生可比较并可解释的输出。位级一致是最严格目标；无法位级一致时，也必须能说明差异来源。

源码身份必须精确固定
   可复现记录应包含 commit 或 tag、额外补丁、工作区是否 dirty，以及 ``CONFIG_LOCALVERSION`` 或 ``LOCALVERSION``。仅记录“Linux 6.x”或源码目录名不能形成源码指纹。

最终 ``.config`` 是实际配置输入
   defconfig、旧配置和人工操作只是生成过程；Kconfig 求值后的最终 ``.config`` 才决定本次构建内容。记录配置时还应保存它的生成步骤。

工具链是完整工具集合
   构建输入不仅包括编译器，还包括链接器、汇编器、``objcopy``、``strip``、``pahole``、Make、脚本语言、压缩工具和证书工具。LLVM、目标架构和交叉编译参数必须贯穿所有构建阶段保持一致。

隐式环境会改变输出
   时间戳、构建用户、主机名、绝对路径、Git dirty 状态、随机种子、签名材料和 initramfs 内容都可能进入产物。``KBUILD_BUILD_TIMESTAMP``、``KBUILD_BUILD_USER`` 和 ``KBUILD_BUILD_HOST`` 可以固定部分元数据。

out-of-tree 构建隔离源码与产物
   ``O=<dir>`` 或 ``KBUILD_OUTPUT=<dir>`` 把中间文件放入独立输出目录。配置、编译、模块和安装阶段必须始终使用同一输出目录，才能避免两套构建状态混用。

调试构建与生产构建应分离
   调试构建可能启用符号、lockdep、KASAN、KCSAN、UBSAN、ftrace 等能力，会改变代码布局、时序、内存和性能。生产构建强调部署约束；两者应使用独立配置、输出目录和构建标识。

构建产物必须作为集合管理
   内核镜像、模块目录、initramfs、固件、``vmlinux``、``System.map``、最终配置和调试符号属于同一个构建身份。只保存一个 ``vmlinuz`` 无法支持可靠复盘和调试。

manifest 把构建转换成可审计记录
   构建清单应保存源码指纹、补丁、工具版本、配置、环境变量、目标架构、kernel release、输入文件和产物哈希，以及打包与安装步骤。

可复现性必须通过独立重建验证
   构建脚本相同不等于结果可复现。至少应在两个全新输出目录中使用相同显式输入重建，并比较哈希、ELF 段、符号、模块元数据和归档内容。

关键路径
--------

固定构建输入：

::

   固定源码 commit 与补丁
   → 固定工作区状态和 local version
   → 固定架构与完整工具链
   → 固定配置生成流程和最终 .config
   → 固定时间、路径、证书、随机数和 initramfs 输入
   → 写入构建 manifest

一次可审计构建：

::

   创建全新 O=<build-dir>
   → 生成最终配置
   → 构建内核与模块
   → 安装到 staging 目录
   → 收集镜像、模块、vmlinux、System.map 和配置
   → 生成匹配 initramfs
   → 记录工具版本、哈希与文件清单

验证可复现性：

::

   在独立目录完成第一次构建
   → 使用相同显式输入完成第二次构建
   → 比较文件哈希
   → 比较 ELF、符号、模块和归档内容
   → 定位时间、路径、随机数或工具差异
   → 固定隐式输入后重新验证

完整交付：

::

   安装架构启动镜像
   → 安装匹配 release 的模块目录
   → 生成匹配 initramfs
   → 保存 vmlinux、System.map、.config 和调试符号
   → 更新 bootloader 条目
   → 启动后核对构建身份

概念辨析
--------

源码目录名与源码指纹
   目录名只是标签；commit、补丁集合和工作区状态才构成可验证的源码身份。

配置来源与最终配置
   defconfig 或旧配置是生成起点；最终 ``.config`` 才是实际构建输入。

out-of-tree 构建与干净构建
   ``O=`` 只隔离输出位置；真正干净还要求全新输出目录、可审计源码和固定隐式输入。

调试构建与生产构建
   调试构建增加可观测性和检查，生产构建强调部署约束；两者的布局、时序和性能不能相互替代。

构建完成与交付完成
   构建完成表示产物生成；交付完成还要求匹配模块、initramfs、符号、配置、清单和实际启动入口。

版本字符串相同与构建相同
   相同 ``uname -r`` 不保证二进制、配置、补丁和工具链一致；还需要 manifest、哈希和匹配符号确认。

本章结论
--------

可复现内核构建的核心，是把源码、配置、工具链和环境从隐式条件变成显式输入，并用独立重建证明完整产物集合能够被稳定还原。
