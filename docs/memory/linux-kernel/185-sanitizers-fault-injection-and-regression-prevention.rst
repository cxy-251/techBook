第185章：Sanitizer、Fault Injection 与回归防止
=============================================

核心知识点
----------

检测器把运行时违规转成证据
   KASAN、UBSAN、KCSAN、KFENCE、Lockdep、Refcount 和 RCU 检查器分别暴露内存、并发、锁与生命周期问题，并提供调用栈和对象信息。

不同检测器覆盖不同错误类
   KASAN 关注越界和释放后访问，UBSAN 关注未定义行为，KCSAN 关注数据竞争，KFENCE 以较低开销采样堆错误。单一检测器不能证明其它错误不存在。

首个违规点通常最接近根因
   后续 Panic 往往是对象已经损坏后的二次结果。分析应从最早的非法访问、锁依赖、竞争或引用告警开始。

动态检测具有覆盖边界
   路径未执行、时序未命中、对象未被采样或配置不足都会漏检。没有报告只表示本次运行未观察到违规。

Fault Injection 让错误路径稳定可达
   分配失败、I/O 错误、Probe 失败、函数返回和 Timeout 可以被主动制造，用于验证清理、重试与恢复逻辑。

注入点必须符合真实失败合同
   有效注入应位于调用者本来就能处理失败的位置。任意强制返回错误可能制造生产环境中不可能出现的状态。

回归测试必须固定原缺陷
   合格测试应在旧实现上失败或触发旧报告，在修复后稳定通过，并继续检查相关 Sanitizer、Lockdep 和邻接路径。

关键路径
--------

检测与修复：

::

   检测器报告
   → 找首个违规点
   → 重建对象、锁与引用关系
   → 稳定复现
   → 修复生命周期或同步合同
   → 增加回归测试

故障注入：

::

   选择真实可失败点
   → 限定作用范围
   → 触发失败
   → 验证返回与回滚
   → 收束异步活动
   → 清除注入状态

概念辨析
--------

* **KASAN 与 KCSAN**：KASAN 检测内存越界和释放后访问；KCSAN 检测缺少同步的数据竞争。
* **KASAN 与 KFENCE**：KASAN 覆盖更高但开销较大；KFENCE 通过采样降低长期运行成本。
* **Lockdep 告警与真实死锁**：Lockdep 证明锁依赖图可能形成环；真实死锁还要求任务实际进入互相等待。
* **Refcount 与资源在线**：引用计数保护软件对象存储，不保证设备、Firmware 或业务状态仍可用。
* **RCU Grace Period 与异步取消**：Grace Period 只等待旧 RCU Reader，不能替代 Work、IRQ、Timer 和 DMA 的独立同步。
* **报告消失与根因修复**：改变配置或时序也能让报告消失；恢复对象与同步不变量才算修复。

本章结论
--------

Sanitizer 负责发现违规，Fault Injection 负责稳定进入错误路径，Regression Test 负责把修复后的对象、同步与恢复合同永久固定下来。
