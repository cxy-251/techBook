第185章：Sanitizer、Fault Injection 与回归防止
=============================================

核心知识点
----------

检测器把违规转成证据
   KASAN、UBSAN、KCSAN、KFENCE、Lockdep、Refcount 和 RCU 检查器把内存、并发、锁和生命周期违规转换成带调用栈和对象信息的运行时报告。

不同检测器覆盖不同错误类
   KASAN 关注越界和释放后访问；UBSAN 关注未定义行为；KCSAN 关注数据竞争；KFENCE 以低开销采样捕获部分堆错误。单一检测器不能证明其它错误类不存在。

报告要从首个违规点读取
   后续 Panic 常是对象已损坏后的二次结果。分析应从最早的非法访问、竞争、锁依赖或引用告警开始，再追踪分配、发布、访问和释放关系。

动态检测具有覆盖边界
   路径未执行、对象未被采样、时序未命中或配置能力不足都会造成漏检。没有报告只说明本次运行未观察到违规。

Lockdep 验证锁依赖图
   它记录锁类、获取顺序和 IRQ 上下文，能在真实死锁发生前发现潜在依赖环。修复必须建立一致锁层级，而不是只调整一个 Reproducer 的顺序。

Refcount 只保护软件对象存储
   ``refcount_t`` 与 ``kref`` 描述持有关系，不能证明硬件、Firmware 或业务状态仍在线。引用生命周期和底层资源生命周期必须分别管理。

RCU 只解决特定读侧并发
   Grace Period 等待旧读者离开，不会自动取消 Work、Timer、IRQ、DMA 或普通引用。删除对象时仍需逐类收束异步活动。

Fault Injection 让低概率错误稳定可达
   分配失败、块 I/O 错误、函数返回、Probe 失败和 Timeout 可被主动制造，使清理、重试和恢复路径能够重复测试。

注入点必须对应真实可失败语义
   在已经产生不可逆副作用后强制返回错误，可能构造生产中不可能出现的状态。有效注入必须位于调用者本来就有合同处理的失败边界。

错误路径要逐资源点验证
   初始化链每取得一个资源后都应有对应失败场景，并检查返回值、对象可见性、引用、异步活动、重复调用和后续恢复。

回归测试必须证明覆盖旧 Bug
   合格测试应在修复前稳定失败或触发旧报告，在修复后稳定通过，并且不产生新的 Sanitizer、Lockdep 或性能回归。

缺陷处理需要闭环
   首个报告、错误分类、稳定触发、对象协议修复、最小回归和相关配置矩阵共同构成完成条件；仅让当前报告消失不算结束。

关键路径
--------

检测与修复：

::

   Sanitizer / Lockdep / Refcount / RCU 报告
   → 找首个违规访问或依赖
   → 识别对象、锁、引用和 Context
   → 用 Reproducer 或 Fault Injection 稳定触发
   → 修复生命周期、同步或输入合同
   → 增加最接近根因的回归测试
   → 在相关检测配置持续运行

故障注入：

::

   选择真实可失败点
   → 限制 Task / Callsite / Device / 时间窗口
   → 保存原始配置
   → 强制一次或概率失败
   → 验证返回、回滚和异步收束
   → 清除注入状态
   → 检查日志、资源和重复恢复

回归固定：

::

   提取最小触发条件
   → 在旧代码上确认失败
   → 在修复代码上确认通过
   → 运行邻接子系统测试
   → 运行相关 Sanitizer / Lockdep 配置
   → 保存环境和预期结果
   → 纳入持续集成

概念辨析
--------

* **KASAN 与 KCSAN**：KASAN 检测内存越界和释放后访问；KCSAN 检测缺少同步的数据竞争。
* **KASAN 与 KFENCE**：KASAN 提供高覆盖但开销较大；KFENCE 通过采样降低长期运行成本，但检测概率更低。
* **Lockdep 告警与真实死锁**：Lockdep 证明依赖图可能形成环；真实死锁还要求任务实际进入互相等待。
* **Refcount 与硬件在线**：引用计数保护软件对象存储，不保证设备和底层资源仍可用。
* **RCU Grace Period 与异步取消**：Grace Period 只等待 RCU Reader，不能替代 Work、IRQ、Timer 和 DMA 的独立同步。
* **真实失败点与不可能状态**：有效注入模拟生产合同允许的失败；任意强制错误会得到无意义甚至误导的结论。
* **报告消失与根因修复**：屏蔽告警、改变时序或路径也能让报告消失；恢复对象和同步不变量才是修复。
* **修复后通过与覆盖旧 Bug**：测试必须在旧实现上失败，才能证明它真正固定了原缺陷条件。

本章结论
--------

Sanitizer 和检查器负责揭示违规，Fault Injection 负责稳定进入低概率错误路径，Regression Test 则把修复后的所有权、同步和恢复合同永久固定下来。
