第077章：kmalloc、kfree 与分配标志
==================================

核心知识点
----------

``kmalloc`` 是通用小对象接口
   调用者提交字节数和 ``gfp_t``，分配器通常把请求映射到合适的通用 SLUB 大小等级，并返回可由内核直接解引用的连续虚拟地址。

请求大小定义合法边界
   实际 cache 槽位可能大于请求值，但额外 bucket 空间不属于调用者对象。越界检查、类型语义和初始化范围仍以请求大小为准。

默认内容未初始化
   ``kmalloc()`` 返回区域可能保留旧对象字节。``kzalloc()`` 和 ``kcalloc()`` 可以清零请求区域，但锁、链表、引用计数等对象仍需专用初始化。

数组分配必须防止乘法溢出
   ``kcalloc()``、``kmalloc_array()``、``struct_size()`` 等 helper 把规模计算与溢出检查结合，避免小分配后发生大范围越界访问。

``krealloc`` 具有双重结果语义
   失败时通常返回 ``NULL`` 且旧对象仍有效；成功时地址可能改变，旧指针及所有依赖旧地址的关系都必须停止使用。

零大小结果不可解引用
   零大小申请可能返回特殊非 ``NULL`` 指针。该值可交给匹配释放接口，但不能当作真实对象访问。

``kfree`` 必须接收兼容来源的基址
   它不能释放栈、静态存储、用户地址、``vmalloc`` 区域、专用 cache 对象或对象内部偏移指针。

释放后地址立即失去对象身份
   槽位可以很快被重新分配。即使地址数值未改变，旧引用仍是 use-after-free，不能通过地址相同推断对象仍存在。

GFP 决定分配器能力边界
   ``GFP_KERNEL`` 允许睡眠和普通回收；``GFP_NOWAIT`` 避免阻塞回收；``GFP_ATOMIC`` 可尝试紧急储备；``GFP_NOIO`` 与 ``GFP_NOFS`` 限制回收递归层次。

GFP 必须从当前上下文推导
   是否处于 hardirq、softirq、spinlock 临界区、I/O 栈或文件系统事务，决定允许使用的标志。不能从“希望更容易成功”反推更激进的 GFP。

所有分配都必须允许失败
   ``GFP_ATOMIC``、``__GFP_RETRY_MAYFAIL`` 甚至大多数普通分配都没有绝对成功保证。调用者必须检查返回值并保持错误回滚完整。

对象必须初始化后再发布
   锁、引用、链表和业务状态应在进入全局表、RCU 结构、队列或异步回调之前建立完成。

大块 ``kmalloc`` 可能依赖高阶页
   请求增大后，物理连续性会提高碎片敏感度。只要求虚拟连续时可评估 ``kvmalloc()`` 或 ``vmalloc()``。

``kvmalloc`` 结果按物理分散设计
   它可以先尝试 ``kmalloc``，再退到 ``vmalloc``。调用者不得依赖物理连续性，并应使用 ``kvfree()`` 统一释放。

敏感数据需要显式清除
   普通 ``kfree()`` 不保证擦除旧内容；密钥等数据应使用适合的敏感释放接口或明确清零协议。

关键路径
--------

普通对象分配与发布：

::

   根据上下文选择 GFP
   → kmalloc / kzalloc(sizeof(*obj), gfp)
   → 检查 NULL
   → 初始化锁、引用、链表和业务字段
   → 建立所有权
   → 发布到查找结构或异步路径
   → 停止新引用并等待旧使用者
   → kfree

选择 GFP：

::

   判断当前路径能否睡眠
   → 判断能否直接回收
   → 判断回收能否进入 I/O
   → 判断回收能否进入文件系统
   → 判断失败后是否可立即降级
   → 选择 KERNEL、NOWAIT、ATOMIC、NOIO 或 NOFS
   → 无论何种标志都处理失败

安全重分配：

::

   保留原指针 old
   → new = krealloc(old, new_size, gfp)
   → new 为 NULL 时继续保留 old
   → 成功时停止使用 old
   → 更新所有保存对象地址的关系
   → 最终释放 new

数组与可变长度对象：

::

   验证元素数量和业务上限
   → 使用 kcalloc / kmalloc_array / struct_size
   → 由 helper 检查大小溢出
   → 检查分配结果
   → 只在计算后的合法边界内访问
   → 使用匹配接口释放

错误回滚：

::

   某一步申请失败
   → 不发布当前对象
   → 从最后成功资源开始逆序撤销
   → 归还嵌套对象和引用
   → kfree 可安全接收 NULL
   → 保留最初错误码并返回

概念辨析
--------

请求大小与 bucket 大小
   请求大小定义对象合法边界；bucket 是分配器内部复用、对齐和元数据单位。

``kmalloc`` 与 ``kzalloc``
   前者内容未初始化；后者清零字节区域，但不代替对象专用初始化。

``GFP_NOWAIT`` 与 ``GFP_ATOMIC``
   二者都避免普通睡眠回收；后者可尝试部分紧急储备，仍不保证成功。

``GFP_NOIO`` 与 ``GFP_NOFS``
   前者阻止回收进入块 I/O；后者限制回收递归进入文件系统路径。

``krealloc`` 失败与成功
   失败时旧对象仍有效；成功时返回地址可能改变，旧指针失效。

``kfree`` 与生命周期结束
   ``kfree`` 只归还存储；对象必须先从所有查找、引用和异步路径中退出。

本章结论
--------

``kmalloc`` family 的契约包括准确大小、合法 GFP、完整初始化、显式失败处理和匹配释放。任何一步缺失都会把分配问题转化为越界、死锁或生命周期错误。
