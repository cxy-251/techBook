第005章：怎样学习 Linux 内核源码
===============================

本章必须记住
------------

#. 初学 Linux 内核时应先顺序建立基础坐标，再使用按主题查阅解决具体问题。
#. 顺序阅读用于掌握对象、上下文、配置、回调、生命周期和运行路径之间的共同规律。
#. 按主题查阅适合已经明确的函数、错误、配置、日志或运行现象；查阅时仍要补齐必要前提。
#. 学习一个内核机制，必须把概念落到入口、核心对象、状态变化、回调分派和具体实现上。
#. “VFS 负责文件抽象”只是概念；“``fd`` 怎样变成 ``struct file``，再通过 ``file_operations`` 进入具体实现”才是可追踪机制。
#. 阅读源码的固定顺序是：先找入口，再找对象，再找对象的字段或操作表，然后找具体回调和错误路径。
#. 全仓库搜索只能提供候选位置；没有对象类型、配置条件和调用上下文时，搜索结果不能直接代表真实运行路径。
#. 源码说明某种路径在给定版本和条件下能够怎样运行；运行时证据说明当前机器、当前对象和当前时间窗口实际出现了什么。
#. ``/proc`` 适合观察进程、文件描述符、内存和调度状态等运行对象信息。
#. ``sysfs`` 适合观察设备、总线、驱动、kobject 以及子系统导出的属性。
#. ``tracefs`` 和 ftrace 适合观察函数路径、tracepoint、调度事件和时间关系。
#. ``perf`` 适合统计事件、采样热点和分析性能代价；它不自动给出完整对象关系和因果路径。
#. 运行证据都有边界：``/proc`` 和 ``sysfs`` 多为快照，ftrace 受启用范围和配置影响，perf 受权限、事件和采样精度影响。
#. 故障分析应从现象还原为入口、对象、状态、等待条件、回调和证据，而不是只搜索错误文字。
#. 一个可靠结论必须说明：源码证明了什么、运行证据证明了什么、哪些条件尚未验证。
#. 学习成果应保存为可复用的路径记录，而不是只记住零散函数名。

必背路径
--------

学习任意内核机制时采用以下顺序：

::

   明确用户动作或运行现象
   → 确定进入内核的入口
   → 找到承载状态的核心对象
   → 找到对象字段、操作表或状态机
   → 追踪具体实现与错误路径
   → 选择 /proc、sysfs、ftrace 或 perf 等证据
   → 对照源码与运行结果
   → 写明已经证明的范围和仍然存在的边界

一条最小读取路径：

::

   用户调用 read(fd, buf, count)
   → 系统调用 C 层入口
   → fd 转换成 struct file
   → VFS 执行通用检查
   → file_operations 分派
   → 文件系统、管道、套接字、proc、sysfs 或设备实现

一条最小证明链：

::

   提出可检查主张
   → 用固定版本源码找到入口、对象和回调
   → 用运行接口确认当前对象与状态
   → 用 tracing 或采样确认当前时间窗口的路径
   → 只在证据覆盖范围内形成结论

必须区分
--------

顺序阅读与按主题查阅
   顺序阅读建立通用坐标；按主题查阅解决已经明确的具体问题。

概念与机制
   概念说明某类功能是什么；机制说明哪些对象按照什么顺序完成它。

源码可能路径与当前实际路径
   源码给出条件下可执行的路径；运行证据确认当前环境实际选择的路径。

对象证据与路径证据
   ``/proc``、``sysfs`` 常用于确认对象和状态；ftrace、tracepoint 和 perf 用于观察事件、函数或性能表现。

证据与推断
   证据直接支撑观察到的事实；超出证据时间、版本、配置和对象范围的说法属于推断。

一句话结论
----------

学习 Linux 内核要把概念变成对象和路径，再用运行证据验证；没有入口、对象、回调和证据的知识不能形成可靠判断。
