第040章：失败、errno 与边界诊断
===============================

核心知识点
----------

错误在边界两侧有不同表示
   内核内部通常返回负错误码，例如 ``-EBADF``、``-EFAULT`` 和 ``-EINVAL``；libc 常把它转换为函数返回 ``-1``，并把正值错误号写入用户态 ``errno``。

``errno`` 只在失败后有意义
   应用必须先根据接口返回值确认失败，再读取 ``errno``。成功调用后遗留的旧 ``errno`` 不能用于判断本次操作。

返回值必须先按三类解释
   正值通常表示已经完成的数量，零表示成功无结果、EOF 或对象特定结束状态，负值或 ``-1`` 才表示失败。解释 ``errno`` 前必须先确认接口返回契约。

短操作属于成功进展
   ``read`` 或 ``write`` 返回小于请求长度的正数，表示已经完成一部分。调用者必须先消费或提交这部分进展，再根据对象协议决定是否继续。

零返回值依赖对象语义
   普通文件 ``read`` 返回零通常表示 EOF；pipe 或 socket 可能表示对端关闭。相同数值必须放回对象类型和接口合同解释。

错误码是失败分类，不是完整根因
   ``EBADF`` 常指 fd 无效，``EFAULT`` 指用户访问失败，``EINVAL`` 指参数或状态不合约，``EAGAIN`` 表示当前不能立即完成，``EIO`` 只是较宽泛的 I/O 失败分类。

信号可能改变系统调用结果
   阻塞调用被信号打断时，内核可能使用 ``-ERESTART*`` 内部状态，由退出路径决定自动重启或向用户态返回 ``EINTR``。这些重启码不是稳定用户 ABI。

失败后应立即保存边界事实
   返回值、``errno``、完整参数、fd 来源、flag、信号和时间应在其它库调用前记录，因为后续函数可能覆盖 ``errno`` 或改变现场。

``strace`` 观察系统调用边界
   ``strace`` 可以看到调用名、参数、fd、返回值、errno、信号和总耗时，适合确认应用到底向内核提交了什么以及边界最终返回了什么。

系统调用耗时不等于 CPU 执行时间
   一次 syscall 的墙钟耗时可能包含睡眠、I/O、锁等待、调度和信号处理。要区分运行与等待，需要结合 sched 事件、子系统 tracepoint 或 perf。

观察工具可能改变时序
   ``strace``、ftrace、动态日志和 perf 都会增加开销。竞态和低延迟问题应缩小进程、系统调用、事件与持续时间范围，并记录观测配置。

不同证据需要统一时间基准
   应用日志、strace、tracefs 和 dmesg 可能使用墙钟时间、单调时钟或启动后时间。建立时间线前必须记录基准并完成对应关系。

最后 errno 不一定是最早故障
   errno 只说明系统调用边界最终选择的结果。真正原因可能来自更早的设备错误、对象状态变化、权限检查或并发路径。

关键路径
--------

从应用失败固定边界事实：

::

   检查函数返回值
   → 区分正进展、零结果和失败
   → 失败时立即保存 errno
   → 记录完整参数、fd、flags 和信号
   → 判断非阻塞、权限和对象类型
   → 再决定是否进入内核追踪

``read`` 返回值分类：

::

   返回值 > 0
   → 已读取部分或全部数据
   → 消费已返回字节
   → 按协议决定是否继续

   返回值 = 0
   → EOF 或对象特定结束语义
   → 按对象类型结束或转换状态

   返回值 < 0 或 libc 返回 -1
   → 读取 errno
   → 按错误类别处理

跨边界诊断：

::

   应用日志固定返回值和 errno
   → strace 固定 syscall 参数与信号
   → procfs 和 sysfs 固定对象状态
   → dmesg 固定设备与子系统错误
   → tracefs 固定实际内核路径
   → perf 区分 CPU 热点和等待
   → 回到源码寻找最早失败点

分析耗时系统调用：

::

   strace 确认调用和总耗时
   → 判断阻塞、短操作或信号重启
   → sched trace 区分运行和睡眠
   → 子系统事件确认等待对象
   → function tracing 缩小代码路径
   → 日志补充设备或文件系统错误

概念辨析
--------

内核负错误码与用户态 ``errno``
   内核返回负值；常见 libc 包装返回 ``-1`` 并设置正 ``errno``。

失败与部分成功
   正字节数表示已有进展；只有接口明确报告失败后才读取 ``errno``。

短读与 EOF
   短读返回正数；EOF 或对象结束通常返回零。

``EINTR`` 与对象故障
   ``EINTR`` 表示信号影响了边界返回；对象损坏需要其它错误、日志或 trace 证明。

``-ERESTART*`` 与用户 ABI
   ``-ERESTART*`` 是内核退出路径的内部控制状态；应用通常只看到重启结果或 ``EINTR``。

系统调用耗时与 CPU 时间
   墙钟耗时包含运行、睡眠、I/O 和调度等待；CPU 时间只统计实际执行。

最终 errno 与根因
   errno 是接口最终分类；根因可能发生在更早的对象、设备、权限或并发路径。

本章结论
--------

边界诊断必须先正确解释返回值，再固定 ``errno``、参数、信号和耗时；errno 给出最终分类，真正根因要由对象状态、日志和运行路径共同证明。
