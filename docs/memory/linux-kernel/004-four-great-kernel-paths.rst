第004章：Linux 内核的四条核心路径
================================

核心知识点
----------

路径思维是内核阅读的基本方法
   大多数用户请求可以从执行、内存、I/O 和网络四条主路径理解。路径描述对象怎样被转换、排队、等待和交接，比单独记忆函数更稳定。

执行路径管理 task 与 CPU
   ``task_struct`` 是核心执行对象，``current`` 表示当前 task。task 可以运行、可运行或睡眠；可运行只表示具备调度资格，不表示正在占用 CPU。

内存路径管理地址到页面的映射
   ``mm_struct`` 表示进程地址空间，VMA 描述一段虚拟地址区域的属性，页表把虚拟页映射到物理页或其它后端。映射不存在或权限不满足时可能进入缺页处理。

I/O 路径连接句柄、缓存和设备
   文件描述符先转换成 ``struct file``，再经过 VFS 和对象操作表。普通文件可能在页缓存完成访问，也可能继续进入文件系统、块层和设备驱动。

网络路径连接 socket、协议和设备
   ``struct socket`` 表示文件接口侧对象，``struct sock`` 保存协议状态，``sk_buff`` 携带包数据和元数据。发送与接收还会经过协议处理、队列和网络设备。

四条路径会相互交叉
   I/O 等待会改变 task 状态，缺页可能触发文件 I/O，网络收包会经过中断和调度，设备 DMA 又依赖内存管理。定位问题时应先找主路径，再补充交叉路径。

关键路径
--------

执行路径：

::

   task 运行
   → 等待条件不满足
   → 进入等待队列并睡眠
   → 事件到来并唤醒
   → 重新进入可运行集合
   → 调度器选择后继续执行

内存路径：

::

   虚拟地址
   → mm_struct
   → VMA 与访问权限
   → 页表
   → 必要时缺页处理
   → 物理页或文件页

文件 I/O 路径：

::

   fd
   → struct file
   → VFS / file_operations
   → 页缓存或文件系统
   → 块层
   → 设备驱动

网络路径：

::

   socket fd
   → struct socket / struct sock
   → 协议栈
   → sk_buff 与队列
   → 网络设备

概念辨析
--------

正在运行与可运行
   正在运行表示 task 当前占用 CPU；可运行表示 task 正在等待调度器选择。

虚拟地址与物理页
   虚拟地址属于进程地址空间；物理页是内核管理的实际内存资源，两者通过页表和映射关系连接。

文件描述符与 I/O 实现
   文件描述符只是进程局部入口；``struct file``、操作表和缓存状态决定实际 I/O 路径。

本机接受发送数据与远端应用收到数据
   ``send()`` 成功通常只说明数据进入本机发送路径，不证明远端已经接收或处理。

本章结论
--------

执行路径决定谁获得 CPU，内存路径决定地址映射到哪里，I/O 路径决定文件数据如何流动，网络路径决定数据如何形成并传递网络包。
