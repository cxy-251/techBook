第004章：Linux 内核的四条核心路径
================================

本章必须记住
------------

#. 阅读 Linux 内核时，可以把大多数用户请求拆成四条核心路径：执行路径、内存路径、I/O 路径和网络路径。
#. 四条路径不是互相隔离的模块；同一个系统调用可以同时牵动其中多条路径。
#. 执行路径研究 task 如何进入内核、获得 CPU、进入睡眠、被唤醒并重新运行。
#. Linux 中被调度的核心执行对象是 ``task_struct``；``current`` 表示当前正在执行的 task。
#. task 处于可运行状态，只表示它有资格被调度，不表示它此刻正在占用 CPU。
#. task 等待 I/O、锁、内存或网络数据时，可以进入睡眠状态并让出 CPU；等待条件满足后，唤醒路径把它重新放入可运行集合。
#. 内存路径研究虚拟地址怎样经过地址空间、VMA、页表和缺页处理获得实际物理后端。
#. ``mm_struct`` 表示进程地址空间，VMA 表示一段具有共同属性的虚拟地址区域，页表负责把虚拟页映射到物理页或其它后端。
#. 用户指针属于当前进程的虚拟地址空间；相同数值的指针在另一个进程中通常没有相同含义。
#. 用户缓冲区尚未建立有效页映射时，访问可能触发缺页处理；缺页处理根据 VMA 属性决定页面来源和权限。
#. I/O 路径研究文件描述符怎样转换成 ``struct file``，再经过 VFS、页缓存、文件系统、块层和设备驱动取得数据。
#. 普通文件读取可能在页缓存命中时直接使用内存中的文件页；缓存未命中时才需要继续提交底层 I/O。
#. 网络路径研究 socket 数据怎样经过 ``struct socket``、``struct sock``、协议栈、``sk_buff``、队列和网络设备。
#. ``struct socket`` 表示面向文件接口的 socket 对象，``struct sock`` 保存协议运行状态，``sk_buff`` 携带网络包数据及其元数据。
#. ``send()`` 返回正数通常表示内核接受了相应数量的数据进入本机发送路径，不表示远端应用已经读取这些数据。
#. 网络接收时，驱动和协议栈把数据放入 socket 接收队列，再唤醒等待数据的 task。
#. 排查问题时，应先判断当前错误、阻塞或状态变化主要属于哪条路径，再进入对应子系统。

必背路径
--------

执行路径：

::

   用户线程进入内核
   → 当前 task 继续执行
   → 条件不满足时进入等待队列并睡眠
   → 事件到来触发唤醒
   → task 重新进入可运行集合
   → 调度器选择后继续执行

内存路径：

::

   用户虚拟地址
   → 当前进程的 mm_struct
   → 对应 VMA 与访问权限
   → 页表查找
   → 必要时处理缺页
   → 获得物理页或文件页后完成访问

普通文件 I/O 路径：

::

   fd
   → 当前进程文件描述符表
   → struct file
   → VFS 与 file_operations
   → 页缓存或具体文件系统
   → 块层与设备驱动

网络发送路径：

::

   socket fd
   → struct file
   → struct socket / struct sock
   → 协议处理与发送缓冲区
   → sk_buff
   → 排队与网络设备
   → 网卡或虚拟设备

必须区分
--------

正在运行与可运行
   正在运行表示 task 当前占用 CPU；可运行表示 task 正在等待调度器选择。

虚拟地址与物理页
   虚拟地址属于进程地址空间；物理页是内核管理的实际内存资源。

文件描述符与 I/O 实现
   文件描述符只是入口索引；对象类型、操作表和缓存状态决定具体 I/O 路径。

socket 接受数据与远端收到数据
   本机 ``send()`` 成功只证明数据进入本机协议处理边界，不证明远端应用已经处理。

一句话结论
----------

执行路径决定谁在运行，内存路径决定地址落到哪里，I/O 路径决定文件数据从哪里来，网络路径决定数据怎样成为并传递网络包。
