第042章：fork、clone 与 exec 的进程创建语义
==========================================

核心知识点
----------

Linux 通过创建 task 建立新的执行实体
   ``fork``、``clone`` 和 ``clone3`` 最终都围绕新建 ``task_struct`` 展开。区别不在于是否创建 task，而在于新 task 与调用者之间如何划分资源。

copy_process 是创建路径的装配中心
   ``copy_process()`` 负责建立新的 task、内核栈、调度状态、PID、父子关系以及各类资源引用。每类资源都要明确选择复制、共享、清空或重新初始化。

fork 是受控复制而不是完整复制
   ``fork`` 后父子拥有不同 task 和 PID。地址空间、文件表、信号与其它资源按照各自规则复制或共享，不能把 fork 理解成对整个进程内存的逐字节复制。

地址空间使用写时复制
   父子进程先共享物理页，并通过页表限制写入。某一方写入时发生写缺页，内核才复制对应页面。COW 延迟了物理页复制，但 VMA 和页表结构仍需要建立。

文件表与打开对象是两个层次
   fork 后父子通常拥有独立的 fd 表，但表项继续引用同一批 ``struct file``。因此 fd 表修改彼此独立，而文件偏移等打开对象状态仍可能共享。

clone flags 定义资源共享边界
   ``CLONE_VM``、``CLONE_FILES``、``CLONE_FS``、``CLONE_SIGHAND`` 和 ``CLONE_THREAD`` 等标志决定新 task 与调用者共享哪些对象。线程就是采用线程式共享组合创建的 task。

exec 替换映像而不创建 task
   ``execve`` 在当前 task 中加载新程序，通常保留 PID 和 task 身份，同时替换地址空间、代码、数据、用户栈和入口寄存器。

exec 具有提交边界
   提交新映像之前失败，旧程序应继续可用；完成关键提交后，旧映像已不能恢复。``FD_CLOEXEC`` 文件描述符、信号状态和多线程关系也在 exec 过程中按 ABI 规则重新整理。

关键路径
--------

fork 创建：

::

   用户态 fork
   → kernel_clone
   → copy_process
   → 复制 task 外壳与内核栈
   → 复制或共享 mm、files、signal、cred 与 namespace
   → 分配 PID 并建立父子关系
   → wake_up_new_task
   → 父子从不同返回值继续执行

COW 写入：

::

   fork 后页表共享物理页
   → 页表禁止直接写入
   → 一方发生写缺页
   → 分配新物理页
   → 复制原页内容
   → 更新写入方页表
   → 父子开始使用不同页面

创建线程：

::

   线程库准备用户栈与 TLS
   → clone 或 clone3 提交共享 flags
   → 创建新 task
   → 共享 mm、files、sighand 与线程组状态
   → 设置独立 TID、寄存器、栈和调度实体
   → 新线程进入调度器

exec 替换程序映像：

::

   当前 task 调用 execve
   → 复制并验证路径、argv 与 envp
   → 打开可执行文件并选择格式处理器
   → 建立新地址空间
   → 加载程序段与解释器
   → 构造用户栈和入口现场
   → 处理 close-on-exec、信号与线程组状态
   → 提交新映像
   → 从新程序入口返回用户态

概念辨析
--------

fork 与完整内存复制
   fork 复制地址空间结构并采用 COW；物理页通常在后续写入时才真正复制。

fork 与 clone
   fork 使用传统进程式资源策略；clone 通过 flags 明确描述资源共享关系。

创建 task 与执行新程序
   fork 和 clone 创建新 task；exec 在当前 task 中替换用户态程序映像。

独立 fd 表与共享 struct file
   fd 表决定整数槽位是否共同变化；``struct file`` 决定文件偏移与打开对象状态是否共享。

共享地址空间与独立线程栈
   线程共享同一个 ``mm_struct``，但各自在该地址空间中使用独立栈区域。

exec 身份与 exec 映像
   exec 通常保留 task、PID 和部分资源关系，原代码、数据、栈和地址空间则被替换。

本章结论
--------

Linux 用同一套 task 创建机制生成执行实体，再以资源共享规则区分进程与线程；``exec`` 不创建新 task，而是在原 task 中提交一个新的用户程序映像。
