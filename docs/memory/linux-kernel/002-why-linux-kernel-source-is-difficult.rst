第002章：为什么 Linux 内核源码难读
=================================

核心知识点
----------

内核没有唯一入口
   系统调用、中断、异常、定时器、工作队列、设备事件和模块初始化都可以启动执行路径。阅读前必须先确认当前入口类型。

入口层、通用层和实现层彼此分离
   系统调用入口负责接收参数，通用层负责公共检查和对象转换，最终实现由文件系统、协议或驱动完成。找到入口函数不等于找到完整机制。

宏会隐藏真实函数形态
   ``SYSCALL_DEFINE`` 等宏同时承担声明、包装和元数据生成。阅读时应先找到宏最终把参数交给哪个普通 C 函数，再继续追踪。

回调使调用链由对象决定
   ``object->ops->callback`` 的下一跳不直接写在调用位置。必须先确定对象类型、操作表从何处赋值以及回调实际指向哪个实现。

一次操作常跨越多个子系统
   ``read`` 会经过文件描述符表和 VFS，``send`` 会进入 socket 层和协议栈，``fork`` 会连接任务、内存、文件表和调度器。对象交接点决定后续源码范围。

运行上下文限制合法操作
   进程上下文通常允许阻塞；硬中断和软中断上下文不能睡眠。即使处于进程上下文，持有自旋锁、关闭中断或处于原子区时也不能执行可睡眠操作。

实际路径受状态和环境影响
   配置、硬件能力、对象状态、锁状态和并发时序都可能改变分支。源码只能说明路径可能存在，日志、调用栈和追踪才能证明当前运行实际经过哪条路径。

关键路径
--------

阅读一个内核入口：

::

   确认入口类型
   → 判断运行上下文
   → 找到核心对象
   → 追踪对象状态和所有权
   → 找到操作表或回调
   → 进入具体实现
   → 用运行证据确认实际路径

三类典型对象交接：

::

   read  → fd → struct file → VFS → 文件系统或设备
   send  → fd → struct socket / struct sock → 协议栈 → 网络设备
   fork  → current task_struct → copy_process → 资源复制或共享 → 调度器

概念辨析
--------

入口函数与最终实现
   入口函数接收请求并建立通用语义；最终实现由运行时对象、回调和状态决定。

直接调用与回调分派
   直接调用的目标写在源码中；回调目标存放在对象的函数指针或操作表中。

进程上下文与中断上下文
   进程上下文可能允许睡眠和用户内存访问；中断上下文不能阻塞，也没有普通系统调用的用户执行语义。

源码路径与实际路径
   源码证明某条路径在条件满足时可以执行；运行证据证明当前对象在当前时间窗口实际选择了该路径。

本章结论
--------

读内核源码时，应先确定路径、对象和上下文，再定位文件；函数名只能提供入口线索，不能独立说明完整机制。
