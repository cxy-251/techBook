第007章：怎样在巨大源码库中找到入口
===================================

核心知识点
----------

先给线索分类
   内核入口定位从线索类型开始。系统调用名、设备绑定、内核日志和 tracepoint 分别对应不同的入口模型，不能使用同一种搜索方式处理。

系统调用入口具有层次
   系统调用通常经过架构 ABI 与系统调用表、``SYSCALL_DEFINE*`` C 入口、通用子系统函数和对象回调。入口函数负责接收请求，最终实现常由运行时对象决定。

入口查找最终要落到对象
   当路径出现 ``file->f_op->read_iter``、``sock->ops->sendmsg`` 等间接调用时，下一步不是继续搜索字段名，而是确认当前对象从哪里获得操作表。

``probe`` 建立设备运行环境
   驱动 ``probe`` 在设备与驱动匹配后执行，负责申请资源、创建私有状态并注册操作接口。后续读写、中断或队列回调依赖它建立的状态。

生命周期钩子与运行期钩子不同
   ``.probe``、``.remove`` 等钩子管理设备绑定与拆除；``file_operations``、``net_device_ops``、``blk_mq_ops`` 等操作表处理用户请求或硬件事件。

日志提供已执行位置
   Oops、WARN 和 panic 中的符号、偏移、模块名和调用栈可以反查故障附近的源码，但必须与同一内核版本、配置和构建产物匹配。

运行跟踪提供实际事件
   tracepoint 与 ftrace 可以显示目标时间窗口实际经过的事件或函数。源码中存在事件定义只说明它可以被记录，不说明它已经发生。

关键路径
--------

从系统调用名寻找入口：

::

   用户态接口名称
   → 目标架构的系统调用号与表项
   → SYSCALL_DEFINE* C 入口
   → 通用子系统函数
   → 核心对象
   → 操作表或回调
   → 具体实现

从驱动绑定寻找运行期入口：

::

   设备被发现
   → 总线匹配设备与驱动
   → driver core 调用 probe
   → 驱动建立私有对象和资源
   → 注册子系统接口或操作表
   → 用户请求或硬件事件进入运行期回调

从故障证据反查入口：

::

   日志、调用栈或 trace 事件
   → 确认目标内核与模块版本
   → 解析符号和触发位置
   → 找到当前位置使用的对象
   → 向前追对象来源
   → 向后追状态变化、返回值和回滚

概念辨析
--------

系统调用入口与最终实现
   系统调用入口接收用户请求并完成通用处理；最终实现通常由对象类型和操作表决定。

``probe`` 与运行期操作
   ``probe`` 建立设备状态和接口；运行期回调使用这些状态处理后续请求或事件。

日志位置与根本原因
   日志指出症状被发现的位置；根本原因可能发生在更早的对象初始化、生命周期或并发路径中。

tracepoint 定义与实际事件
   定义表示事件具备观测能力；跟踪输出才证明事件在目标时间窗口发生。

本章结论
--------

入口定位的目标是找到第一条可信、可继续追踪的对象线索；先按证据类型选择入口模型，后续调用链才有稳定方向。
