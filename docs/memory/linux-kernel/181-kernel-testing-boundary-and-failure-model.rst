第181章：内核测试边界与失败模型
================================

核心知识点
----------

内核测试验证系统不变量
   内核代码共享地址空间、调度器、设备和全局对象。测试重点不仅是返回值，还包括对象是否可解释、资源是否释放、异步活动是否停止，以及系统能否继续运行。

执行上下文属于输入条件
   进程、IRQ、Softirq、NMI、RCU 读侧和持锁区具有不同的睡眠、分配与同步约束。同一接口在不同上下文中的合法行为可能不同。

并发测试要覆盖生命周期交叉
   Work、Timer、IRQ、RCU、DMA 和设备完成可能与取消、卸载和释放同时发生。测试必须验证正式同步边界能够阻止释放后访问。

错误路径必须逐点验证
   初始化链每取得一个资源，就应测试下一步失败时是否按逆序撤销，且半初始化对象未发布、引用未泄漏、重复初始化仍可成功。

测试层级由对象边界决定
   KUnit 验证局部逻辑和状态机；kselftest 验证用户态接口；集成与系统测试验证多对象协作、真实设备和完整运行环境。

环境与运行时告警共同决定结果
   Kernel Commit、Config、Architecture、Compiler 和硬件条件必须随结果记录。即使测试项显示通过，只要出现 KASAN、Lockdep、WARN、Oops 等报告，整次运行仍应失败。

关键路径
--------

失败安全验证：

::

   取得资源
   → 注入中途失败
   → 关闭外部入口
   → 收束异步活动
   → 逆序释放资源
   → 验证可重复初始化

测试层级选择：

::

   局部逻辑
   → KUnit
   → 用户态合同
   → kselftest
   → 多对象与真实硬件
   → 集成 / 系统测试

概念辨析
--------

* **错误码正确与失败安全**：错误码描述单次调用；失败安全要求对象、资源和异步状态恢复可信。
* **Coverage 与正确性**：Coverage 证明路径被执行；断言和运行时检查证明不变量成立。
* **``SKIP`` 与 ``PASS``**：``SKIP`` 表示前提不足、目标行为未验证；``PASS`` 表示目标路径已经执行并满足断言。
* **Mock 与真实硬件**：Mock 适合验证软件状态机；DMA、IRQ、Firmware 和物理时序仍需真实环境。
* **未复现与缺陷不存在**：未触发只说明本次输入和时序不足，不能证明竞态或硬件依赖问题不存在。

本章结论
--------

内核测试的核心，是验证错误、并发和异常上下文下的对象生命周期与系统不变量，而不是只检查函数是否返回预期值。
