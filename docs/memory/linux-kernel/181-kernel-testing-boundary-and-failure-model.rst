第181章：内核测试边界与失败模型
================================

核心知识点
----------

内核失败缺少进程级隔离
   内核代码共享地址空间、调度器、设备状态和全局对象。局部错误可能扩散为内存破坏、死锁、静默数据损坏或系统级崩溃，因此测试目标必须超过“函数返回了预期错误码”。

失败后的可信状态才是主要断言
   安全失败要求半初始化对象未发布、外部入口已关闭、异步活动已收束、资源按逆序释放，并且下一次初始化或请求可以从干净状态重新开始。

执行上下文属于测试输入
   进程、Hardirq、Softirq、NMI、内核线程、RCU 读侧和持锁区具有不同的睡眠、分配和同步约束。同一函数在不同上下文中可能具有不同合法性。

并发测试必须覆盖状态交叉
   Work、Timer、IRQ、RCU、DMA 和设备完成可能处于未排队、已排队、正在执行、正在取消或刚完成状态。测试应验证同步原语真正封闭了生命周期窗口。

测试层级由对象边界决定
   KUnit 适合纯逻辑和小状态机；集成测试验证多个内核对象协作；kselftest 和 LTP 验证用户态契约；系统测试覆盖启动、真实设备、电源管理和完整环境。

错误路径是一等行为
   初始化链 ``A → B → C`` 不只需要成功测试，还要逐点制造 A、B、C 失败，并验证已完成步骤按相反顺序撤销，没有残留注册、引用和异步回调。

覆盖率不等于正确性
   Coverage 只能证明代码执行过。返回值、对象状态、所有权、引用、队列、可见性和清理结果必须由明确断言验证。

可测试性来自显式设计
   纯逻辑与硬件操作分离、依赖显式注入、状态机集中、错误回滚统一和对象所有权清晰，会同时降低测试成本和生产缺陷概率。

测试环境是结论的一部分
   Kernel Commit、Config、Architecture、Compiler、CPU 数、内存模型、Boot 参数、虚拟化和硬件能力都会改变可达路径。测试报告必须绑定这些条件。

Flaky 失败是证据而非噪声
   偶发失败通常指向真实竞态、错误时序假设、共享状态污染或环境不稳定。重跑可以估计概率，不能把第一次失败改写成通过。

运行时告警覆盖功能断言
   Case 返回成功但触发 KASAN、KCSAN、Lockdep、RCU、Refcount、WARN 或 Oops，整次测试仍应判定失败，因为系统不变量已经被破坏。

回归测试要固定根因条件
   修复后应把最小触发条件放入最接近根因的测试层，并验证旧代码稳定失败、新代码稳定通过、邻接路径没有产生新的告警。

关键路径
--------

失败后恢复可信状态：

::

   操作开始
   → 逐步取得资源并记录所有权
   → 某一步失败
   → 阻止新的外部入口
   → 收束 IRQ / Timer / Work / DMA / RCU
   → 从发布集合撤销对象
   → 按逆序释放资源
   → 验证可重复初始化

测试层级选择：

::

   纯函数与局部状态机
   → KUnit
   → 多对象协作
   → Integration Test
   → 用户态稳定契约
   → kselftest / LTP
   → 真实设备与完整系统
   → System Test

并发生命周期验证：

::

   构造对象与异步工作
   → 在不同执行阶段触发 Remove / Cancel
   → 等待正式同步边界
   → 验证回调不再访问对象
   → 验证引用与队列归零
   → 重新创建对象并再次运行

概念辨析
--------

* **错误码正确与失败安全**：错误码只描述当前调用结果；失败安全还要求对象、资源和异步活动恢复可信状态。
* **Coverage 与断言**：Coverage 证明路径被执行；断言证明执行后的状态满足合同。
* **``SKIP`` 与 ``PASS``**：``SKIP`` 表示前提不足、目标行为未验证；``PASS`` 表示目标路径已经执行并满足断言。
* **Mock 与真实硬件**：Mock 验证软件边界和状态机；真实硬件还包含 DMA、IRQ、Firmware、缓存和物理时序。
* **同步调用与活动收束**：调用取消接口只是动作；只有等待所有访问者离开后，生命周期才真正闭合。
* **未复现与缺陷不存在**：当前环境未触发只说明本次输入和时序不足，不能证明竞态或硬件依赖缺陷不存在。

本章结论
--------

内核测试的中心问题不是某个函数是否返回预期值，而是在错误、并发和异常上下文中，系统对象是否仍保持可解释、可释放、可重试的可信状态。
