第111章：从块层到设备的存储栈
===============================

核心知识点
----------

存储栈是分层翻译链
   上层表达文件范围或块范围，下层逐步把它转换成 ``bio``、``request``、协议命令和设备操作。每层只理解自己的对象与合同。

必须先建立真实设备拓扑
   文件系统可能位于分区、Device Mapper、RAID、虚拟磁盘、远端块设备或物理盘之上。只看最上层 ``/dev`` 名称无法定位真实执行路径。

``bio`` 与 ``request`` 分属不同层次
   ``bio`` 描述目标块设备、sector、操作和内存片段；``request`` 是 request queue、blk-mq、tag 和驱动处理的执行单位。

虚拟块设备会改写请求
   Device Mapper、MD RAID、loop、NBD 和 zram 可以重映射 sector、克隆或拆分请求，并把一个上层完成关联到多个下层工作。

队列能力由整条路径共同决定
   最大请求、segment、对齐、discard、flush、FUA 和 zoned 等能力必须穿过所有中间层。上层能力通常受最严格下层约束。

缓存必须按层命名
   Page Cache、dm-cache、RAID 控制器缓存、设备 write cache 和远端服务缓存具有不同位置、失效方式与持久化语义。

完成只对当前层有效
   Page Cache 接收、块请求完成、协议命令完成和稳定介质持久化是不同事件。任何完成结论都必须指出由哪一层作出。

错误恢复会扩大影响范围
   Timeout 可能触发 abort、重试、路径切换或 controller reset。Reset 往往冻结多个队列并影响大量在途请求，而不是局限于单个慢请求。

完成路径仍包含 CPU 调度
   设备完成后，驱动定位 command/tag，块层结束 request 和 bio，再由上层回调、唤醒和调度把结果送回任务。块层完成不等于业务线程已经运行。

可靠性依赖承诺逐层传递
   地址映射、错误状态、flush/FUA、顺序和完成语义只有被每个虚拟层正确传播，文件系统与应用的恢复协议才成立。

关键路径
--------

分层块写入：

::

   文件系统 / Direct I/O
   → 构造上层 bio
   → 虚拟块设备 map / clone / split
   → 下层 request_queue
   → blk-mq request 与 tag
   → 协议驱动
   → 控制器和介质
   → completion 逐层返回

建立设备图：

::

   文件路径
   → mount 与文件系统
   → 上层块设备 major:minor
   → holders / slaves 与映射表
   → RAID、LVM、dm、虚拟化层
   → 最终 NVMe、SCSI、网络或文件后端

Timeout 恢复：

::

   request 超时
   → 检查命令与 controller 状态
   → abort 或重试
   → 必要时停止队列
   → reset 或 path failover
   → 重建队列
   → requeue 或失败旧请求
   → 验证新 I/O 与错误趋势

持久化承诺：

::

   应用 fsync / 事务提交
   → 文件系统形成数据与元数据顺序
   → 块层附加 flush / FUA
   → dm、RAID、cache 层传播或模拟
   → 驱动转换为协议命令
   → 最终设备确认稳定状态
   → 完成返回应用

概念辨析
--------

物理块设备与虚拟块设备
   物理设备由控制器和介质执行请求；虚拟设备把请求映射、转换或转发到其它对象。

Page Cache 与设备写缓存
   Page Cache 位于主机文件路径；设备写缓存位于控制器、设备或后端。二者的可见性和掉电风险不同。

Timeout 与永久故障
   Timeout 只说明未按期限完成，原因可能是拥塞、传输、固件、恢复或介质损坏。

Retry 与新请求
   Retry 延续原请求的完成责任；新请求拥有新的身份、顺序与生命周期。

块层完成与应用完成
   ``block_rq_complete`` 表示块层收到完成，后续仍可能等待 bio 回调、任务唤醒和业务处理。

上层统计与下层统计
   分层设备会在多个层次记录同一逻辑 I/O，不能把所有设备统计直接相加成业务字节。

本章结论
--------

Linux 存储栈是一条分层块翻译与承诺链。定位性能、错误和持久化问题时，必须同时还原设备图、请求变换、队列阶段与逐层完成语义。
