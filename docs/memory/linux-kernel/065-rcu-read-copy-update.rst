第065章：RCU Read-Copy-Update 同步模型
=====================================

核心知识点
----------

RCU 把可见性与回收分开
   更新者先让新读者看不到旧对象，再等待删除前已经进入的读者退出，最后回收旧对象。删除入口与释放内存因此是两个不同时间点。

RCU 适合读多写少场景
   读侧要求低开销，写侧可以承担复制、写侧锁和延迟回收成本。RCU 不是通用锁替代品，而是一种偏向高频读取的生命周期协议。

读侧临界区保护短期访问
   普通读侧使用 ``rcu_read_lock()`` 与 ``rcu_read_unlock()``，并通过 ``rcu_dereference()`` 或 ``*_rcu`` 遍历接口取得对象。对象至少在本次读侧临界区结束前不能被 RCU 回收。

RCU 读者不保证看到最新版本
   并发读者可以看到完整旧版本或完整新版本，协议保证对象可安全读取，不保证所有 CPU 同时切换到最新状态。

写者仍需要序列化
   RCU 处理读者与回收者的关系，不会自动保护多个写者同时修改链表或复合结构。更新者通常仍需 mutex、spinlock 或其它写侧锁。

发布必须使用 RCU 指针 API
   新对象应先完整初始化，再通过 ``rcu_assign_pointer()`` 或对应 ``*_rcu`` 插入接口公开。读者使用匹配的解引用接口，才能获得正确的编译器和内存顺序保证。

摘除对象不会立即终止旧读者
   ``list_del_rcu()``、``hlist_del_rcu()`` 或指针替换只关闭新发现路径。删除前已经取得指针的读者仍可在临界区内继续访问旧对象。

Grace period 只等待对应 RCU 读者
   ``synchronize_rcu()`` 同步等待，``call_rcu()`` 异步安排回调，``kfree_rcu()`` 封装延迟释放。它们不自动等待普通引用、timer、work、IRQ、DMA 或其它异步执行者。

长期使用必须提升为普通引用
   指针要离开 RCU 读侧范围继续保存或异步使用，通常应在临界区内安全增加引用。RCU 保护短访问，引用计数保护长期所有权。

Copy-update 避免暴露中间状态
   更新者复制旧对象、修改新副本、原子发布新版本，再延迟回收旧版本。并发读者因此看到稳定旧状态或稳定新状态，而不是原地修改的一半结果。

RCU 风味必须成套使用
   普通 RCU、SRCU、Tasks RCU 等具有不同读侧和 grace period 定义。需要睡眠的读侧应使用明确支持该语义的协议，不能混用不同风味的 API。

关键路径
--------

RCU 读取：

::

   rcu_read_lock
   → rcu_dereference 或 *_rcu 遍历
   → 在临界区内读取对象
   → 需要带出指针时安全取得普通引用
   → rcu_read_unlock
   → 只使用已复制结果或引用保护的对象

发布新对象：

::

   分配新对象
   → 初始化所有读者可见字段
   → 获取写侧锁
   → rcu_assign_pointer 或 *_rcu 插入
   → 释放写侧锁
   → 新读者可以观察新对象

删除旧对象：

::

   获取写侧锁并定位对象
   → 使用 *_del_rcu 或替换指针摘除
   → 新读者不再获得旧对象
   → 释放写侧锁
   → synchronize_rcu、call_rcu 或 kfree_rcu
   → 等待删除前旧读者退出
   → 等待长期引用和异步使用者
   → 最终释放对象

复制并替换：

::

   读取旧对象稳定状态
   → 构造并修改新副本
   → 在写侧锁下发布新版本
   → 旧读者继续读取旧版本
   → 新读者读取新版本
   → Grace period 后回收旧版本

检查 RCU 协议：

::

   找到受保护指针或链表
   → 找到全部读侧临界区
   → 找到 rcu_dereference 与 *_rcu 遍历
   → 找到写侧锁和发布点
   → 找到摘除或替换点
   → 找到 grace period 与最终释放
   → 确认普通引用和异步路径也已结束

概念辨析
--------

可见性删除与内存释放
   摘除指针只阻止新读者；旧对象必须在 grace period 和其它持有者结束后才能释放。

RCU 与写侧锁
   RCU 保护读者和延迟回收；写侧锁序列化多个更新者与复合结构修改。

RCU 与引用计数
   RCU 保证临界区内短期访问；引用计数保证对象跨越临界区长期存活。

Grace period 与所有使用者结束
   Grace period 只等待对应 RCU 读者，不等待 timer、work、IRQ、DMA 和普通引用。

可抢占 RCU 与可睡眠读侧
   读者可以被调度抢占，不表示可以任意阻塞；需要睡眠应选择明确支持的 RCU 风味。

本章结论
--------

RCU 通过“先摘除、再等待旧读者、最后回收”把读取成本转移到更新与释放路径；完整设计仍需写侧锁、长期引用和异步 teardown 共同闭合。
