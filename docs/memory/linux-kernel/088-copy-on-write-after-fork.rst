第088章：fork 之后的写时复制
============================

核心知识点
----------

``fork`` 复制地址空间语义
   父子进程拥有独立的 ``task_struct``、``mm_struct``、VMA 集合和页表页。COW 只让部分叶子页表项暂时指向相同物理页，不表示整个地址空间对象被共享。

COW 把复制成本推迟到写入
   Fork 阶段复制 VMA 和页表关系，并为私有可写映射布置写保护；只有父子任一方首次写入共享页时，才决定是否复制真实数据。

VMA 可写而 PTE 暂时只读
   VMA 保留用户态可写语义，PTE 清除写权限以捕获第一次分歧。只看 PTE 不可写，不能判断该地址永久只读。

父子双方都必须写保护
   Fork 后父进程和子进程都可能首先写入。若只保护子进程 PTE，父进程直接写旧页会破坏地址空间隔离。

写 Fault 是真实复制时刻
   写保护异常进入 COW 路径。页面仍被共享时，内核分配新匿名页、复制旧内容，并只更新写入方 PTE；另一方继续引用旧页。

独占页可以原地升级
   若内核证明旧页已由当前映射独占，并且页类型、引用、mapcount、pin、KSM 和 swap 状态都允许，可以直接把当前 PTE 改为可写而不复制。

Fork 成本与 COW 成本不同
   Fork 的主要成本是创建进程对象、复制 VMA、复制已有页表、调整引用和执行写保护；后续 COW 成本由实际写入范围决定。

未触碰范围不会复制数据页
   只有 VMA 而没有叶子 PTE 的地址范围，在 fork 时无需复制物理内容。大地址空间不等于全部驻留页都已存在。

COW 通常是 Minor fault
   原内容已经在内存中，因此通常无需后端读入，但页分配、复制、页表更新、rmap 维护和 TLB shootdown 仍可能形成明显延迟。

大页会放大分歧成本
   THP 写入可能复制整张大页、先拆分再复制基础页，或走版本相关优化。页面越大，清零、复制、拆分和内存带宽成本越集中。

Private 与 Shared 语义不同
   ``MAP_PRIVATE`` 匿名页和私有文件映射通过 COW 保持隔离；``MAP_SHARED`` 和共享匿名映射本来就要求修改可见，不使用普通 fork COW 隔离写入。

Pin 与设备访问改变 COW 边界
   长期 GUP pin、DMA pin 和可写 pin 会影响页面复制、迁移和回收。驱动不能缓存用户页物理地址并假设 fork 后映射永远不变。

Fork 成功不保证未来 COW 成功
   后续写入仍需分配页面，可能受到 memcg、NUMA、回收、THP 和系统容量限制。Overcommit 和 fork 返回成功都不构成物理内存承诺。

``fork`` 后立即 ``exec`` 可避免大部分复制
   子进程若只做最小准备后执行 ``exec``，旧 COW 地址空间很快被替换，大量父进程数据页不会发生真实复制。

关键路径
--------

Fork 布置 COW：

::

   父进程调用 fork
   → 创建子 task_struct 与 mm_struct
   → 复制 VMA 范围和后端语义
   → 遍历父进程已有页表
   → 私有可写页在父子 PTE 中写保护
   → 两边 PTE 暂时指向同一物理页
   → 更新引用和反向映射

首次写入共享页：

::

   父进程或子进程执行写操作
   → 只读 PTE 触发 write fault
   → VMA 证明 private write 合法
   → 检查页面能否独占复用
   → 不能复用时分配并复制新匿名页
   → 写入方 PTE 指向新页并设为可写
   → 维护 rmap、RSS、memcg 和 TLB

Fork 后内存增长诊断：

::

   记录 fork 与 worker 启动时间
   → 采样 minor fault 增量
   → 比较 PSS、Private_Dirty 和 Anonymous
   → 检查 AnonHugePages 与 THP split/copy
   → 对齐父子写入范围
   → 判断 COW 私有化、页表增长或其它匿名分配

概念辨析
--------

* 地址空间独立与物理页共享：父子拥有独立 mm/VMA/页表，只有部分叶子映射暂时共享物理页。
* VMA 可写与 PTE 可写：VMA 表达最终语义；PTE 写保护是捕获 COW 的临时机制。
* Fork 成本与 COW 成本：Fork 复制结构和映射关系；真实页面复制发生在后续写 fault。
* ``MAP_PRIVATE`` 与 ``MAP_SHARED``：Private 通过 COW 隔离；Shared 按共享后端传播修改。
* RSS 与独占物理内存：RSS 会重复统计共享页；PSS 和 Private_Dirty 更适合衡量私有化程度。
* Minor fault 与低成本：COW 通常计为 minor，但复制大页、触发回收或大量页表更新仍可能昂贵。

本章结论
--------

Fork 的低成本来自父子页表暂时共享物理页，并用写保护捕获首次分歧。真正的内存与延迟成本在后续写 fault 中按实际修改范围逐步支付。
