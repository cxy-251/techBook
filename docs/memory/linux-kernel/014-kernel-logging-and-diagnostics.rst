第014章：Linux 内核日志与诊断语法
===============================

本章必须记住
------------

#. 内核日志是运行时证据，用于记录对象、动作、结果、错误码、调用点和故障严重程度。
#. ``printk()`` 和 ``pr_*()`` 系列宏把消息写入内核日志缓冲区；消息是否实时出现在控制台由控制台日志级别决定。
#. 日志进入 ring buffer 与日志显示在 console 是两件事；``dmesg`` 主要读取日志缓冲区中的记录。
#. ``pr_emerg()``、``pr_alert()``、``pr_crit()``、``pr_err()``、``pr_warn()``、``pr_notice()``、``pr_info()`` 和 ``pr_debug()`` 表达不同严重程度。
#. 日志级别数值越小，通常表示事件越紧急。
#. 设备驱动常使用 ``dev_err()``、``dev_warn()`` 和 ``dev_info()``，让日志自动携带设备实例信息。
#. 一条高质量日志应尽量包含对象、动作、结果和错误码，不能只写没有上下文的 ``failed``。
#. 日志只能证明报告点执行过，不能单独证明根因、完整状态变化或并发顺序。
#. ``pr_debug()`` 调用点存在，不表示运行时一定输出；它可能受编译配置和 dynamic debug 控制。
#. Dynamic debug 可以按模块、文件、函数、行号或格式字符串打开和关闭调试调用点。
#. ``_ratelimited`` 日志宏限制高频事件的输出速率，防止日志淹没缓冲区和改变系统时序。
#. ``_once`` 日志宏通常只报告第一次命中；日志只出现一次不表示条件只发生过一次。
#. ``WARN`` 类宏表示违反了内核预期条件，通常记录调用点和调用栈，但系统或当前路径可能继续运行。
#. ``WARN_ON(condition)`` 的重点不是宏本身，而是 condition 表达的状态不变量和后续恢复路径。
#. ``BUG`` 或 ``BUG_ON()`` 表示作者认为当前上下文已经失去安全继续执行的前提，严重程度高于 ``WARN``。
#. ``panic()`` 表示故障已经升级到系统级终止或重启策略；实际行为还受启动参数、kdump 和 watchdog 等配置影响。
#. 调用栈提供故障发生时的动态函数路径，最靠近顶部的相关函数通常是第一处源码入口。
#. ``function+offset/size [module]`` 表示故障点位于该函数内部的偏移位置，并指出符号是否来自模块。
#. 精确偏移解析必须使用与运行内核匹配的 ``vmlinux``、模块和调试信息；版本不匹配会产生错误定位。
#. 阅读 warning、oops 或 panic 时，应先看故障类别，再看最近调用点，再读上层调用栈，最后结合前后普通日志建立时间线。

必背路径
--------

读取一段内核故障日志时采用以下顺序：

::

   按设备、模块和时间筛选相关记录
   → 判断日志级别和故障类别
   → 提取设备、进程、CPU、模块和错误码
   → 找最近的 function+offset/size 调用点
   → 向上读取一到三层调用栈
   → 回到对应源码检查状态条件和返回路径
   → 检查 dynamic debug、限速和 once 规则是否影响证据完整性
   → 使用 tracing 或其它证据验证时序

日志可见路径：

::

   源码执行 printk / pr_* / dev_*
   → 消息进入内核 ring buffer
   → 日志级别与 console_loglevel 决定是否实时显示
   → 用户态通过 dmesg 或 /dev/kmsg 读取

故障严重程度：

::

   普通状态信息
   → pr_warn / pr_err 报告异常或失败
   → WARN 记录不变量违反和调用栈
   → BUG / oops 表示当前上下文严重失效
   → panic 表示系统级终止策略

必须区分
--------

* ring buffer 与控制台：ring buffer 保存日志记录；控制台只实时显示满足当前级别策略的部分记录。
* 日志级别与根因：日志级别表示报告者判断的严重程度；根因仍需结合对象状态、错误路径和运行时证据确定。
* 调试调用点与实际输出：源码存在 ``pr_debug()`` 只说明观察点存在；是否输出取决于配置、动态开关和路径是否执行。
* ``WARN`` 与 ``panic``：``WARN`` 记录异常并可能继续执行；``panic`` 进入系统级停机或重启处理。
* 函数符号与精确源码行：函数名提供稳定入口；精确行号依赖完全匹配的构建产物和符号信息。

一句话结论
----------

内核日志负责给出对象、严重程度和第一处运行路径线索；日志给入口，源码给机制，跟踪工具给时序。
