第038章：跨越用户态与内核态边界复制数据
========================================

本章必须记住
------------

#. 系统调用进入内核后，参数数值已经进入内核，但用户指针指向的数据仍位于用户地址空间。
#. 用户指针由用户控制，地址、内容和修改时机都不可信，不能当作普通内核指针直接解引用。
#. 内核源码使用 ``__user`` 标注用户地址空间指针，帮助阅读者和 Sparse 静态检查区分用户指针与内核指针。
#. ``__user`` 是类型与静态分析标注，不会自动完成运行时地址验证、复制或生命周期保护。
#. ``copy_from_user(dst, src, n)`` 的方向是用户态到内核态，目标必须是内核缓冲区。
#. ``copy_to_user(dst, src, n)`` 的方向是内核态到用户态，目标必须是用户缓冲区。
#. 块复制接口的返回值通常是未成功复制的字节数；返回零才表示全部复制完成。
#. ``copy_from_user`` 或 ``copy_to_user`` 返回非零时，调用者通常要按当前接口语义转换成 ``-EFAULT``、短操作或其它结果。
#. 块复制接口的返回值不是普通的负 errno，不能写成 ``ret < 0`` 来判断失败。
#. ``get_user()`` 和 ``put_user()`` 适合复制简单标量，通常返回零或 ``-EFAULT``，与块复制接口语义不同。
#. ``access_ok()`` 只检查地址范围是否可以尝试作为用户地址访问，不保证页面已映射、数据稳定或后续复制一定成功。
#. 用户页访问可能触发缺页异常，普通 uaccess 操作因此可能睡眠。
#. 可能睡眠的 uaccess 不能随意放在硬中断、原子上下文或禁止睡眠的持锁区间中。
#. 架构 uaccess 实现通过受控访问序列和异常修复，把部分非法用户访问转换成可返回的错误，而不是让内核直接崩溃。
#. ``copy_from_user`` 成功只证明字节进入内核缓冲区，不证明长度、flag、索引、权限和业务语义有效。
#. 输入数据复制完成后，还必须验证范围、未知 flags、结构体版本、对象权限和状态机条件。
#. ``copy_to_user`` 前必须完整初始化输出对象，避免把内核栈残留、padding 或未赋值字段泄漏给用户态。
#. 安全的输入路径应尽早把用户数据复制成内核本地快照，后续业务逻辑只使用这个快照。
#. 对同一用户字段先检查、后再次从用户地址读取，会产生 TOCTOU 风险，因为用户线程可能在两次访问之间修改数据。
#. 收敛 TOCTOU 的基本方法是一次复制到内核对象，然后对这份稳定快照完成验证与使用。
#. 指向可变长度数据的用户结构体通常要先复制固定头部，验证长度上限和溢出，再分配并复制后续数据。
#. 长度计算必须检查整数溢出、乘法溢出、结构体大小上限和用户提供的偏移边界。
#. 用户结构体中的用户指针仍是用户指针；复制结构体只复制了地址数值，不能把嵌套指针直接解引用。
#. compat ABI 下，用户结构体的指针宽度、``long``、时间类型和对齐可能不同，必须先经过兼容转换。
#. nofault 类接口用于特定探测和诊断场景，使访问失败快速返回；它们不是普通 syscall 参数复制的默认替代品。
#. pin user pages、长期 DMA 和零拷贝路径不是普通 ``copy_*_user``，它们需要额外管理页面固定、写入方向和释放生命周期。
#. 从用户态复制字符串时，应使用限制长度的用户字符串 helper，不能对不可信地址直接调用普通 ``strlen``。
#. 边界复制失败路径必须释放已经分配的内核缓冲区，并保持输出长度、对象状态和返回值一致。
#. 用户地址可访问不等于用户有权操作目标内核对象；地址检查、权限检查和对象检查是不同层次。

必背路径
--------

复制一个固定用户结构体：

::

   系统调用或 ioctl 收到 __user 指针
   → 准备内核本地结构体
   → copy_from_user 复制固定大小
   → 返回非零则转换为边界错误
   → 验证 size、len、flags 和保留字段
   → 检查权限与目标对象状态
   → 后续逻辑只使用内核快照

复制可变长度输入：

::

   复制固定头部
   → 验证版本和头部大小
   → 验证元素数量与单项大小
   → 检查加法、乘法和偏移溢出
   → 限制总长度
   → 分配内核缓冲区
   → 复制剩余用户数据
   → 再次按内核快照处理
   → 失败时逆序释放

向用户态返回结构体：

::

   创建并清零内核输出对象
   → 填写公开字段
   → 将保留字段和 padding 保持确定值
   → copy_to_user 写回
   → 检查未复制字节数
   → 按接口约定返回成功、短操作或 -EFAULT

避免 TOCTOU：

::

   不直接反复读取用户字段
   → 一次复制到内核本地对象
   → 在快照上完成所有验证
   → 获取目标对象引用或锁
   → 使用同一份已验证数据执行操作
   → 结果写回前重新检查输出边界

必须区分
--------

用户指针与内核指针
   用户指针属于用户地址空间并由用户控制；内核指针指向由内核生命周期规则保护的对象。

``__user`` 标注与运行时保护
   标注帮助静态检查；真正访问仍必须通过 uaccess helper。

``access_ok`` 与复制成功
   ``access_ok`` 只说明地址范围可尝试；复制仍可能 fault 或部分完成。

块复制与标量复制返回值
   ``copy_*_user`` 返回未复制字节数；``get_user``、``put_user`` 通常返回零或负错误码。

字节复制成功与业务输入有效
   复制只解决数据移动；范围、权限、版本和状态仍需单独验证。

复制结构体与复制嵌套数据
   结构体中的用户指针只是地址数值，指向的数据要再次受控复制。

地址有效与权限允许
   用户缓冲区可访问不代表调用者可以操作指定设备、文件或内核对象。

一句话结论
----------

用户指针是不可信的边界输入；内核必须通过 uaccess 把数据复制成经过验证的内核快照，并正确处理 fault、部分复制、上下文限制和 TOCTOU。
