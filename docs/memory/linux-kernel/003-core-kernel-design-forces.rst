第003章：Linux 内核的核心设计取舍
=================================

核心知识点
----------

内核设计是多目标权衡
   Linux 内核同时承受性能、安全、通用性、硬件差异、延迟、吞吐、兼容性和维护成本等压力。多数机制都不是单一指标下的绝对最优解。

性能不能越过安全边界
   热路径需要减少复制、分支和锁竞争，但用户指针、长度、权限和对象状态仍必须校验。``__user``、``access_ok()``、``copy_to_user()`` 和 ``copy_from_user()`` 标记了用户态与内核态的数据边界。

通用抽象承载公共规则
   VFS、socket 层和设备模型使用统一对象与接口表达公共语义。硬件、文件系统和协议差异由操作表、具体实现和驱动承担。

抽象不会消除底层差异
   通用接口只统一入口和公共约束，不保证不同对象具有相同状态机、性能特征或错误语义。

延迟与吞吐需要不同策略
   延迟关注单个请求完成时间；吞吐关注单位时间完成量。立即处理、短队列通常有利于延迟，批量、预读、合并和并行队列通常有利于吞吐。

用户态 ABI 稳定，内部实现可演进
   系统调用语义、返回值、错误码和用户态 ABI 需要长期兼容；内部结构体、锁、辅助函数和驱动接口可以随版本重构。

设计判断必须回到压力来源
   看到检查、缓存、队列、批处理或抽象层时，应先判断它解决了哪种工程压力，以及它引入了什么成本。

关键路径
--------

分析一个内核机制：

::

   确认输入和信任边界
   → 找到权限、地址、长度和状态检查
   → 确定通用对象与公共规则
   → 找到回调或硬件相关实现
   → 识别缓存、排队、批量和同步策略
   → 判断它优先优化的指标
   → 区分稳定 ABI 与可演进实现

概念辨析
--------

性能与安全
   性能减少正常路径成本；安全确保不可信输入和非法状态不能破坏系统。优化不能绕过安全边界。

通用接口与统一实现
   通用接口让不同对象共享入口；具体实现仍可具有完全不同的数据来源和状态机。

延迟与吞吐
   延迟衡量单个工作完成时间；吞吐衡量一段时间内完成的总工作量。提高其中一个可能损害另一个。

用户态 ABI 与内核内部接口
   用户态 ABI 承担长期兼容责任；内核内部接口随源码版本、配置和维护需要变化。

本章结论
--------

Linux 内核的代码形态来自多种工程压力的平衡：边界必须安全，入口尽量通用，热路径控制成本，内部实现保持可演进。
