第032章：sysfs 是设备与对象模型接口
===================================

核心知识点
----------

sysfs 是内核对象模型的用户态投影
   ``sysfs`` 通常挂载在 ``/sys``，把 ``kobject``、device、driver、bus、class 和 module 等对象的层级与属性暴露给用户空间。

``kobject`` 提供名称、层级和生命周期基础
   一个已注册的 ``kobject`` 通常对应 sysfs 中的目录。它常嵌入更具体的内核对象中，父子关系决定目录层级，引用与释放规则保证目录对应的宿主对象仍然存在。

不同顶层目录表达不同对象关系
   ``/sys/devices`` 是设备对象主树；``/sys/bus`` 按总线组织设备与驱动；``/sys/class`` 按功能类别提供视图；``/sys/module`` 展示内建组件或模块的参数和状态。

符号链接表示同一对象的另一种视图
   ``/sys/class`` 和 ``/sys/bus`` 中的条目常链接到 ``/sys/devices``。链接说明对象关系或分类入口，不表示内核复制了新的设备对象。

属性文件把对象字段变成接口
   sysfs 属性通常通过 ``show()`` 读取、通过可选的 ``store()`` 写入，并倾向于遵守“一文件一属性”的文本接口。属性背后仍是宿主对象、锁和状态机。

可写属性是运行时控制入口
   写入 ``bind``、``unbind``、``remove``、``rescan`` 或电源管理属性，可能触发驱动绑定、设备移除、重新探测或电源状态变化。文件可写不代表当前操作一定安全。

目录存在只证明对象已发布
   sysfs 路径出现说明对象进入了该用户态视图。设备是否完成 probe、是否绑定驱动、硬件是否正常工作，还需结合 ``driver`` 链接、状态属性、日志和实际 I/O 判断。

sysfs 接口具有生命周期和兼容责任
   属性回调执行期间宿主对象必须存活；注销需要先关闭新访问，再等待旧回调退出。已经形成用户态 ABI 的属性不能随意改变名称、格式和语义。

关键路径
--------

从 sysfs 路径还原设备对象：

::

   判断路径属于 devices、bus、class 或 module
   → 判断条目是目录、链接还是属性
   → 链接时回到 /sys/devices 主对象
   → 确认父子关系、总线、class 和 driver
   → 读取属性确认当前状态
   → 回到 struct device、kobject 和属性回调

读取属性：

::

   用户 read 属性文件
   → sysfs 与 kernfs 定位 attribute
   → 调用对象类型的 show 回调
   → 读取宿主对象字段
   → 格式化为文本
   → 返回用户空间

写入控制属性：

::

   保存修改前状态
   → 确认输入格式与恢复方式
   → 用户 write
   → store 回调解析和验证
   → 在锁与状态机约束下修改对象
   → 检查属性、日志与实际行为

概念辨析
--------

``/sys/devices`` 与 ``/sys/class``
   ``devices`` 表达设备主层级；``class`` 按功能聚合设备，通常通过链接指向同一主对象。

设备对象与 sysfs 目录
   设备对象是内核中的运行时结构；目录只是它在用户空间的表示。

目录存在与功能正常
   目录存在证明对象已注册；功能正常还要求驱动绑定、probe 成功和实际操作通过。

文件可写与操作安全
   权限只决定谁能发起写入；``store()``、对象状态、锁和硬件条件决定写入是否有效和安全。

删除属性与释放对象
   删除属性只关闭用户入口；对象释放还需停止异步执行、回调和其它持有者。

sysfs 与 debugfs
   sysfs 表达对象模型和较稳定属性；debugfs 面向开发调试，接口通常没有稳定 ABI 承诺。

本章结论
--------

``sysfs`` 用目录表示对象、用链接表示关系、用属性表示状态和控制；阅读它时必须把路径重新映射到真实设备对象、驱动绑定和生命周期。
