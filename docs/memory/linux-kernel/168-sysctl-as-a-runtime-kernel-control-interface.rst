第168章：sysctl 作为运行时内核控制接口
======================================

核心知识点
----------

sysctl 是运行中的策略注入接口
   ``/proc/sys`` 把文本读写连接到内核子系统变量与处理函数，使系统无需重启即可调整部分 VM、FS、Network、Kernel 和安全策略。

``ctl_table`` 定义控制项
   表项通常包含名称、权限、数据位置、长度、处理函数和可选范围。文件路径只是入口，``proc_handler`` 与数据对象才决定真实语义。

读取与写入经过虚拟文件系统
   ``sysctl -w net.ipv4.ip_forward=1`` 与写 ``/proc/sys/net/ipv4/ip_forward`` 最终进入 procfs/sysctl 查表、权限检查、文本解析和状态更新路径。

作用域必须逐项确认
   许多 ``net.*`` 参数按 Network Namespace 分片；``kernel.*``、``vm.*`` 和 ``fs.*`` 中大量项目接近整机作用域。目录名不能替代注册位置与数据对象分析。

新值的生效时机并不统一
   有些值在每次热路径中读取，有些在新连接、新接口或新 Namespace 创建时复制，有些只在周期任务或下一次回收中体现。

参数族只提供定位线索
   ``kernel`` 常控制通用内核与安全策略，``vm`` 控制内存与写回，``fs`` 控制 VFS 资源和规则，``net`` 控制协议栈与接口策略；每个具体项仍需独立文档。

写入成功不等于目标完成
   Handler 接受文本后，子系统可能稍后才读取新值，或只影响未来对象。必须观察真实队列、连接、回收、转发、错误和延迟状态。

权限是多层组合
   文件 Mode 之外，Mount 只读、Credential、User Namespace、Capability、LSM 和 Lockdown 都可限制写入。容器内 Root 通常不能修改宿主全局 VM/Kernel 策略。

持久化不由内核负责
   运行时值通常在重启后丢失。``sysctl.conf``、``sysctl.d``、systemd-sysctl、网络管理器或 Runtime 决定何时重新应用，并可能互相覆盖。

当前值与配置来源是两件事
   配置文件存在不证明已经应用，当前值正确也不证明重启后保持。可靠管理需要同时记录目标值、实际值、加载顺序和写入主体。

参数之间存在联动
   Dirty 阈值、Writeback、内存限制、块队列和设备速度会共同决定延迟；网络 Backlog、Socket Buffer、NAPI 和应用消费也不能靠单一参数解释。

动态表项具有生命周期
   模块、设备或 Namespace 可注册和注销 sysctl 表。撤销文件入口后，表内存、已进入 Handler 的调用和对象引用仍需按框架协议同步释放。

关键路径
--------

sysctl 写入：

::

   用户写入 key=value
   → 映射到 /proc/sys 路径
   → procfs 查找 ctl_table
   → 检查 Mode、Credential、Namespace 与 LSM
   → 调用 proc_handler
   → 解析、范围校验并更新数据或执行副作用
   → 子系统后续路径读取新策略

作用域确认：

::

   定位 sysctl 名称
   → 找到 ctl_table 注册点
   → 记录 Data 指针与 Handler
   → 确认全局 / Netns / 对象作用域
   → 搜索运行路径读取位置
   → 判断新值影响现有对象还是未来对象

持久化闭环：

::

   临时写入并回读当前值
   → 验证业务与子系统效果
   → 写入正式 sysctl.d 配置
   → 记录加载顺序和配置 Owner
   → 重启或重载
   → 再次回读并检查覆盖者

概念辨析
--------

* ``/proc/sys`` 与普通 procfs 文件：前者由 sysctl 表和 Handler 驱动；其它 procfs 节点可使用完全不同的 ``proc_ops``。
* 当前值与持久配置：当前值属于本次运行状态；配置文件只是用户态下一次应用该值的来源。
* ``all``、``default`` 与具体接口：网络 sysctl 的组合规则逐项不同，不能统一理解为覆盖关系。
* 写入成功与策略生效：成功只证明 Handler 接受输入，最终对象和数据路径仍需独立验证。
* 参数回滚与状态回滚：写回旧值可能只恢复未来策略，已有连接、队列或缓存可能需要重建。

本章结论
--------

sysctl 将文本策略注入正在运行的内核子系统。参数只有与作用域、读取时机、处理函数、配置来源和运行证据连接起来，才具有可验证的工程意义。
