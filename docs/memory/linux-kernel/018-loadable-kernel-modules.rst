第018章：Linux 可加载内核模块
=============================

核心知识点
----------

模块是运行时接入的内核代码
   可加载模块通常以 ``.ko`` 文件交付，并在系统运行期间装入内核。模块进入内核地址空间后拥有内核级权限，不具备进程或容器隔离。

加载过程建立可执行状态
   内核加载模块时要完成格式与架构检查、内存分配、符号解析、重定位、参数解析、签名或策略检查，并调用初始化入口。任一步失败都必须撤销已经完成的状态变化。

``module_init()`` 定义初始化入口
   初始化函数负责申请资源、建立私有对象并向其它子系统注册接口。只有初始化返回 ``0``，模块才进入可用状态；返回负错误码表示加载失败。

``module_exit()`` 定义卸载入口
   可卸载模块必须在退出路径中注销所有外部入口、停止异步活动并释放资源。相同代码以内建方式构建时，退出入口通常没有运行期卸载意义。

发布与撤销必须遵守生命周期顺序
   初始化时应先构造完整对象，再把接口发布给外部调用者；卸载时应先阻止新的调用，再同步现有 IRQ、timer、workqueue、回调和打开对象，最后释放代码与数据。

模块引用阻止过早卸载
   模块仍被对象、文件或其它模块引用时，正常卸载应被拒绝。强制卸载会绕过生命周期保证，可能留下悬空函数指针和 use-after-free。

用户态工具承担不同职责
   ``insmod`` 按文件路径直接提交模块，通常不解析完整依赖；``modprobe`` 根据模块名、别名、配置和依赖数据库组织加载；``depmod`` 生成依赖与别名索引；``lsmod`` 只显示当前已加载状态。

模块参数是加载期或运行期控制面
   ``module_param()`` 定义有类型参数，通常在初始化前解析。可写参数会出现在 sysfs 中，但修改安全性仍取决于值校验、锁、硬件状态和失败回滚。

模块接口与目标内核紧密绑定
   模块只能使用明确导出的符号。Linux 不保证稳定的内核内部模块 ABI，``vermagic``、符号版本、架构、配置和签名策略不匹配都可能导致加载失败。

内建与模块化是部署选择
   内建代码适合启动早期和根文件系统依赖；模块适合按需加载与独立交付，但增加模块文件、依赖、签名和卸载生命周期管理。

关键路径
--------

模块加载：

::

   用户态选择 .ko
   → 内核检查格式、架构、版本和策略
   → 分配模块内存并解析符号
   → 完成重定位和参数解析
   → 调用 module_init
   → 初始化成功后发布外部接口
   → 模块进入 LIVE 状态

模块卸载：

::

   收到卸载请求
   → 检查是否仍被引用
   → 阻止新的调用进入
   → 注销设备、文件和回调入口
   → 取消并同步异步活动
   → 调用 module_exit 完成剩余清理
   → 释放模块资源与内存

``modprobe`` 加载：

::

   模块名或设备别名
   → 查询配置与 modules.alias
   → 查询依赖数据库
   → 先加载依赖模块
   → 加载目标模块并传递参数

概念辨析
--------

内建代码与可加载模块
   内建代码随内核镜像存在并参与启动；模块以独立文件交付，并具有加载、引用和卸载生命周期。

``insmod`` 与 ``modprobe``
   ``insmod`` 面向具体模块文件；``modprobe`` 面向模块名、别名、配置和依赖关系。

模块文件存在与模块已加载
   ``.ko`` 存在只说明文件可供加载；``lsmod`` 或 ``/proc/modules`` 才说明模块已进入运行内核。

加载成功与功能正确
   加载成功只说明初始化入口返回成功；设备绑定、I/O、并发和错误恢复仍需独立成立。

参数可写与运行时安全
   sysfs 允许写入只表示接口开放；参数更新仍必须维护对象、并发和硬件状态一致性。

本章结论
--------

可加载模块是具有完整内核权限的运行时代码：加载时必须建立完整状态，卸载时必须先撤销所有入口并等待所有使用者离开。
