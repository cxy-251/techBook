第043章：线程、线程组与共享资源
===============================

核心知识点
----------

线程是独立调度的 task
   Linux 中每个用户线程都有自己的 ``task_struct``，可以独立运行、睡眠、唤醒和迁移 CPU。多线程进程不是一个 task 内部保存多个线程，而是多个 task 组成线程组。

线程组提供进程级身份
   线程组中的 task 共享 TGID，每个 task 拥有独立 TID。``group_leader`` 指向线程组 leader，用户态 ``getpid()`` 通常返回 TGID，``gettid()`` 返回当前 TID。

线程通过共享资源形成进程
   普通线程通常共享 ``mm_struct``、``files_struct``、``fs_struct``、``sighand_struct`` 和线程组级 ``signal_struct``。这些共享对象构成用户态所感知的进程资源。

共享地址空间不等于共享栈
   线程共享堆、全局变量、mmap 和共享库映射，但每个线程在同一地址空间中使用独立用户栈和 TLS。栈仍属于共享地址空间，错误指针仍可能影响其它线程。

共享文件表意味着 fd 修改全局可见
   线程共享 ``files_struct`` 时，一个线程执行 open、close、dup 或替换 fd，会直接改变其它线程看到的 fd 表。fd 数值可能在关闭后被快速复用。

调度状态按线程独立
   每个线程拥有独立寄存器、内核栈、调度实体、优先级、CPU 亲和性和阻塞状态。一个线程睡眠不表示整个线程组停止运行。

信号同时具有线程组与线程语义
   信号处理动作通常在线程组内共享，每个线程仍有独立阻塞掩码和线程级 pending 状态。进程定向信号由内核选择可接收线程，线程定向信号明确指定 TID。

资源共享不提供并发安全
   多个线程可以访问同一对象，只说明对象可见性共享。访问顺序和一致性仍需锁、原子操作、内存顺序或其它同步协议保证。

线程组具有特殊的 fork、exec 与退出边界
   多线程进程 fork 时，子进程最初只包含调用线程；一个线程成功 exec 后，其它线程被清理；单个线程退出只归还自己的引用，共享资源通常在最后一个使用者离开后释放。

关键路径
--------

创建普通用户线程：

::

   线程库分配用户栈与 TLS
   → 准备 CLONE_VM、CLONE_FILES、CLONE_SIGHAND、CLONE_THREAD 等 flags
   → clone 或 clone3 创建新 task
   → 新 task 加入线程组
   → 共享 mm、files、signal 与 sighand
   → 设置独立 TID、寄存器、栈和调度状态
   → 进入调度器独立运行

定位异常线程：

::

   确认进程 TGID
   → 枚举线程组中的各个 TID
   → 查看每个线程的状态与等待位置
   → 判断问题属于共享对象还是单线程状态
   → 将锁、fd、futex、I/O 或信号落实到具体 TID
   → 再分析线程之间的资源依赖

共享 fd 表的竞态：

::

   线程 A 保存 fd 数值
   → 线程 B 关闭或替换共享表项
   → 原 fd 槽位失效
   → 槽位可能被新对象复用
   → 线程 A 再使用旧整数
   → 得到 EBADF 或错误操作新对象

线程退出：

::

   线程函数返回或调用退出接口
   → 清理线程私有状态与 TLS
   → 通知 join 等待者
   → 归还共享资源引用
   → task 进入回收路径
   → 最后一个使用者负责释放共享对象

概念辨析
--------

线程与 task
   线程是用户态共享资源语义；task 是内核独立调度的执行对象。

TGID 与 TID
   TGID 标识线程组，TID 标识具体线程对应的 task。

共享地址空间与共享栈
   线程共享 ``mm_struct``，但通常拥有独立栈区域和 TLS。

共享 fd 表与共享打开对象
   ``files_struct`` 决定 fd 表项是否共同变化；``struct file`` 决定打开对象状态是否共享。

进程定向信号与线程定向信号
   前者进入线程组语境并选择接收线程；后者直接投递给指定 task。

线程睡眠与进程停滞
   单个线程睡眠不影响其它线程调度；只有共享锁、关键线程或共享资源被阻塞时，进程整体功能才可能停滞。

共享与同步
   共享只建立共同可见性，不建立访问顺序和数据一致性。

本章结论
--------

Linux 线程是共享进程级资源的独立 task：地址空间、文件表和信号关系可以共享，栈、TLS、TID 与调度状态则按线程独立管理。
