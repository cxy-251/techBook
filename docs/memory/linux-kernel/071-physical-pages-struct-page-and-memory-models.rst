第071章：物理页、struct page 与内存模型
========================================

核心知识点
----------

物理页是页分配器的基本单位
   Linux 通常按 ``PAGE_SIZE`` 把可管理物理内存划分为 page frame。页大小由架构和配置决定，不能固定假设为 4 KiB。

PFN 是物理页框编号
   PFN 以页粒度标识物理位置。物理地址右移 ``PAGE_SHIFT`` 得到 PFN；PFN 左移后得到页框起始物理地址。

``struct page`` 是页框元数据
   真实数据位于物理页中，``struct page`` 保存状态、引用、映射、LRU、buddy、复合页和上层归属等管理信息。

页面状态决定字段含义
   ``struct page`` 大量复用联合字段。匿名页、文件页、空闲页、slab 页、设备页和复合页对同一字段位置可能有完全不同的解释。

引用与映射是两套关系
   页面引用保证物理页仍被内核持有；mapcount 描述用户页表映射。页面可以没有用户映射，仍被页缓存、I/O 或内核对象引用。

复合页由头页统一管理
   高阶页和大页通常由一个 head page 与若干 tail page 组成。主要状态和生命周期由头页承载，操作前常需转换到 compound head 或 folio。

Folio 是上层内存对象视角
   Folio 把一组连续、对齐且共同管理的页面视为一个对象，减少逐页处理开销；底层页框仍由 ``struct page`` 描述。

地址转换接口有适用范围
   ``pfn_to_page()``、``page_to_pfn()`` 连接 PFN 与页描述符。``virt_to_page()`` 通常只适用于普通 RAM 的内核直接映射，不能用于用户地址、``vmalloc`` 或 ``ioremap`` 地址。

内存模型组织页描述符
   FLATMEM 适合较连续的物理地址空间；SPARSEMEM 按 section 管理存在的物理范围，适合大内存、稀疏地址和热插拔。模型差异由统一转换接口屏蔽。

设备内存不等于普通 RAM
   某些设备内存也有 ``struct page``，但其访问、迁移、引用和释放规则由设备内存协议决定，不能套用普通系统内存规则。

关键路径
--------

从物理地址定位页对象：

::

   物理地址
   → 按 PAGE_SHIFT 得到 PFN
   → 确认 PFN 属于有效且在线的受管范围
   → pfn_to_page 定位 struct page
   → 判断 node、zone 与页面类型
   → 判断 head / tail 关系
   → 再解释 flags、引用和 mapping

从用户地址定位物理页：

::

   用户虚拟地址
   → 找到 task 与 mm_struct
   → 查找 VMA 并验证权限
   → 遍历页表取得 PFN
   → 判断 PFN 是否对应普通受管内存
   → 关联 struct page
   → 分析页面状态和上层归属

页面生命周期：

::

   buddy 中的空闲页
   → 分配器摘除页块
   → 建立引用和用途
   → 成为匿名页、文件页、slab 或其它对象
   → 解除映射和上层持有
   → 引用归零并清理状态
   → 返回 PCP 或 buddy

页元数据建立：

::

   固件报告物理内存范围
   → 内核建立可管理 PFN 区间
   → FLATMEM 或 SPARSEMEM 组织 struct page
   → node 与 zone 接管页框
   → 页分配器开始管理空闲状态

概念辨析
--------

物理页与 ``struct page``
   物理页保存数据；``struct page`` 保存管理该页所需的元数据。

PFN 与物理地址
   PFN 是页粒度编号；物理地址是字节粒度位置。

页面引用与页表映射
   引用保证页面存活；映射计数描述页表关系，二者不能互相替代。

普通页与复合页
   普通页独立管理；复合页由头页统一承载主要状态，tail page 不能脱离头页解释。

直接映射与 ``vmalloc``
   直接映射按普通 RAM 关系建立；``vmalloc`` 只保证虚拟连续，必须使用匹配的地址和页面接口。

FLATMEM 与 SPARSEMEM
   二者决定页描述符如何组织，不改变 PFN 表示物理页框这一基本语义。

本章结论
--------

Linux 先用 PFN 标识物理页框，再用 ``struct page`` 把页框纳入状态、引用、归属和生命周期管理；理解任何页面字段前，必须先确定页面当前属于哪种状态。
