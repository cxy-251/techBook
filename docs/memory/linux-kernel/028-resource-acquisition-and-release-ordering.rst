第028章：资源申请与释放顺序
===========================

核心知识点
----------

资源之间存在依赖关系
   内核对象常同时持有内存、寄存器映射、IRQ、DMA、工作队列、定时器和上层注册入口。申请顺序建立依赖，释放顺序拆除依赖。

构造应从基础资源走向外部入口
   私有对象、锁、映射和缓冲区应先准备，再启动硬件、IRQ 和异步执行，最后注册设备文件、网络接口、sysfs 等外部入口。越晚的步骤通常越容易引入并发访问。

发布和异步启动是生命周期边界
   注册上层对象、启用中断、启动 DMA、排队工作或启动定时器后，其它执行路径可能立即访问私有状态。进入这些阶段前，相关对象必须已经完整可用。

半初始化状态必须可清理
   初始化可能在任意一步失败。每个失败点只能清理此前已经成功取得的资源，既不能遗漏，也不能释放尚未建立的资源。

释放按依赖逆序进行
   安全拆除通常先关闭外部入口和新事件来源，再同步等待已经进入的执行路径，最后释放底层映射、缓冲区和对象内存。依赖逆序比机械源码倒序更重要。

停止与同步先于释放
   work、timer、IRQ、DMA 和异步 I/O 可能仍在使用对象。``cancel_work_sync()``、``free_irq()`` 等接口常同时承担停止、等待和释放语义，必须在底层数据消失前执行。

错误标签表达构造阶段
   ``goto err_*`` 的目标应对应“已经完成哪些资源阶段”。标签向下贯穿可以集中表达反向回滚，并让不同失败点跳到匹配的清理边界。

``devm_*`` 只托管已登记资源
   devres 可以把部分释放动作绑定到 ``struct device`` 生命周期，减少重复清理代码，但不会自动注销所有全局入口、停止异步任务或修复错误的依赖顺序。

正常 remove 与失败回滚使用同一依赖模型
   probe 失败只拆除已经完成的阶段，正常 remove 拆除完整对象。两者都应先关闭新入口、停止活动，再释放基础资源。

关键路径
--------

典型对象构造：

::

   分配私有对象
   → 初始化锁、状态和回调
   → 映射寄存器并申请缓冲区
   → 配置硬件到安全状态
   → 申请 IRQ 和异步执行资源
   → 注册上层接口
   → 对象进入 active 状态

典型对象拆除：

::

   标记停止服务
   → 注销上层入口
   → 停止硬件产生新事件
   → 取消并同步 work、timer 和 I/O
   → 释放 IRQ 并确认 DMA 停止
   → 释放缓冲区和映射
   → 释放私有对象

失败点回滚：

::

   找到失败调用
   → 列出此前成功建立的状态
   → 关闭已经发布的入口
   → 等待已经进入的执行者退出
   → 按依赖逆序释放资源
   → 返回原始错误码

概念辨析
--------

申请顺序与释放顺序
   申请从基础资源走向可见入口；释放从可见入口退回基础资源。

源码倒序与依赖逆序
   源码行顺序只是线索；真正决定清理顺序的是资源之间的使用关系。

关闭入口与释放对象
   关闭入口阻止新使用者；释放对象还要等待旧调用链和异步路径退出。

初始化失败与正常 remove
   初始化失败只清理已完成阶段；正常 remove 拆除完整运行状态。

``devm_*`` 与自动正确
   devres 自动执行登记的释放动作；发布、停机、同步和非托管状态仍需显式设计。

本章结论
--------

安全的资源管理必须先建立清楚的依赖图：构造时由内向外发布，退出时先封闭入口和活动，再由外向内拆除。
