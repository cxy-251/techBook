第028章：资源申请与释放顺序
===========================

本章必须记住
------------

#. 内核对象通常同时持有内存、寄存器映射、IRQ、DMA、工作队列、定时器、设备节点、sysfs 属性和上层注册关系。
#. 资源申请顺序表达依赖建立过程，释放顺序表达依赖拆除过程。
#. 判断资源顺序时，应问资源被谁使用、依赖哪个对象仍然有效，以及申请成功后是否打开新的并发入口。
#. 私有对象通常先于访问它的 IRQ、workqueue、timer 和上层回调创建。
#. 寄存器映射和 DMA buffer 必须在可能访问它们的中断、工作和硬件活动开始前准备好。
#. 注册设备、文件、sysfs、网络接口或其它上层入口会让外部路径开始发现对象，通常应放在构造后段。
#. 任何能打开新回调、异步执行或用户访问入口的资源，都是生命周期边界。
#. 初始化函数可能在任意资源申请点失败，因此对象必须能够安全处理半初始化状态。
#. 每个失败点都应列出此前已经成功取得的资源，不能按成功路径末尾的完整对象假设清理。
#. 少释放一个已取得资源会造成泄漏；释放一个尚未取得的资源会破坏状态；顺序错误会造成 use-after-free。
#. 释放通常按依赖关系逆序进行，而不是机械按源码行号倒序。
#. 外层可见入口应先关闭，随后停止异步执行，最后释放底层内存、映射和对象本体。
#. 注销上层对象后，还要等待已经进入的旧调用链离开，不能只阻止新调用。
#. 工作队列应使用 ``cancel_work_sync()``、``flush_workqueue()`` 或对应同步机制收束后再释放其访问对象。
#. 定时器、tasklet、IRQ 和异步 I/O 都必须先停止并同步，再释放回调会访问的数据。
#. 设备仍可能进行 DMA 时不能释放 DMA buffer；应先停止硬件并确认 DMA 已结束。
#. ``free_irq()``、同步取消 work 等接口不仅释放资源，还承担等待正在运行回调结束的同步语义。
#. ``goto err_*`` 标签应代表明确的构造阶段，例如已经申请 IRQ、已经创建工作队列或已经发布上层入口。
#. 标签向下贯穿可以集中表达反向释放顺序，并避免多条错误路径复制清理代码。
#. 成功的 ``probe`` 和正常 ``remove`` 应使用同一套资源依赖模型；remove 是完整对象的逆向拆除。
#. ``devm_*`` 把部分资源释放动作绑定到 ``struct device`` 生命周期，减少手写回滚代码。
#. ``devm_*`` 只管理通过 devres 登记的资源，不会自动注销全局入口、停止所有异步任务或修复错误的释放顺序。
#. 设备托管资源的释放顺序仍受登记顺序和资源依赖影响，不能因为使用 ``devm_*`` 就忽略生命周期设计。
#. 外部对象比设备活得更久时，不能把其资源无条件托管给较短的设备生命周期。
#. 资源清理顺序不是附属代码，而是对象架构和故障恢复设计的一部分。

必背路径
--------

典型驱动构造：

::

   分配私有对象
   → 初始化锁、状态和回调对象
   → 映射寄存器或申请 DMA 资源
   → 配置并停止在安全初始状态的硬件
   → 申请 IRQ
   → 创建 workqueue、timer 或线程
   → 注册字符设备、netdev、sysfs 或上层接口
   → 对象进入正常运行状态

典型驱动拆除：

::

   标记对象停止服务
   → 注销上层入口并阻止新请求
   → 停止硬件产生新事件
   → 取消并同步 work、timer 和异步 I/O
   → 释放 IRQ
   → 停止并确认 DMA 完成
   → 释放 DMA buffer 和寄存器映射
   → 释放私有对象

失败点回滚：

::

   找到失败调用
   → 列出此前成功取得的资源
   → 标记哪些资源已打开并发或外部入口
   → 先关闭最外层入口
   → 等待已进入的执行路径结束
   → 按依赖逆序释放其余资源
   → 保留原始错误码返回

``goto`` 标签模型：

::

   err_unregister_upper
   → err_destroy_workqueue
   → err_free_irq
   → err_unmap_regs
   → err_free_private
   → return error

必须区分
--------

* 申请顺序与释放顺序：申请从基础资源走向外部可见入口；释放从外部入口走回基础资源。
* 源码倒序与依赖逆序：资源通常按依赖逆序释放；存在独立资源时，不必机械复制源码的严格倒序。
* 初始化失败与正常 remove：初始化失败只清理已完成阶段；正常 remove 拆除已经完整运行的对象。
* 关闭入口与释放对象：关闭入口阻止新使用者；释放对象还要等待旧调用链和异步路径退出。
* ``devm_*`` 与自动正确：devres 自动执行已登记的释放动作；它不能自动设计正确的发布、停机和并发同步顺序。
* 释放函数与普通 free：某些释放函数同时执行同步、注销或等待；阅读时必须确认它关闭了什么入口、等待了谁。

一句话结论
----------

资源申请建立依赖，资源释放拆除依赖；安全退出必须先关闭外部和异步入口，再按依赖逆序释放底层对象。
