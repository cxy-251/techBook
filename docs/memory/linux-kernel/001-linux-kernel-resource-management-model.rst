第001章：Linux 内核资源管理模型
===============================

核心知识点
----------

内核是资源管理者
   Linux 内核统一管理 CPU 时间、内存、文件与块设备 I/O、硬件设备、网络和权限边界。用户程序提出资源请求，内核负责分配、隔离、同步和回收。

用户态通过受控入口请求资源
   用户程序不能直接操作内核对象和硬件，而是通过系统调用、异常或设备接口进入内核。入口参数来自用户态，进入内核后必须被校验并转换成内核对象。

句柄不是对象
   文件描述符 ``fd`` 只是当前进程文件描述符表中的整数索引。内核根据 ``fd`` 找到 ``struct file``，后者才表示一次打开产生的运行时文件对象。

对象保存状态
   ``struct file`` 保存访问模式、当前位置、关联对象和操作表等状态。多个 ``fd`` 可以引用同一个 ``struct file``，因此可能共享文件位置和打开状态。

操作表决定具体行为
   ``file_operations`` 把统一文件接口分派到具体实现。同一个 ``read()`` 可以进入普通文件、管道、套接字、伪文件系统或设备驱动，因为它们提供不同回调。

子系统通过对象协作
   调度、内存、VFS、网络、块层和驱动分别管理不同资源。一次请求常跨越多个子系统，真正连接路径的是对象关系、状态变化和回调，而不是源码目录顺序。

宏内核与模块扩展
   Linux 核心子系统共享内核地址空间。模块可以在运行时注册对象和回调，但装入后仍以内核权限执行，并不具备用户态插件的进程隔离。

关键路径
--------

``read(fd, buf, count)`` 的最小对象链：

::

   用户调用 read
   → 系统调用入口
   → current->files
   → 文件描述符表中的 fd
   → struct file
   → file_operations
   → 文件系统、管道、套接字或设备实现
   → 数据返回用户缓冲区

概念辨析
--------

``fd`` 与 ``struct file``
   ``fd`` 是进程局部的索引；``struct file`` 是内核中的打开文件对象。

``struct file`` 与 ``inode``
   ``struct file`` 表示一次打开的运行时状态；``inode`` 表示文件系统对象的身份和元数据。

统一接口与统一实现
   系统调用和 VFS 提供统一入口；具体对象仍通过自己的操作表执行不同实现。

内核模块与用户态插件
   内核模块进入内核地址空间并共享内核故障域；用户态插件通常受进程地址空间隔离。

本章结论
--------

阅读内核时，应把用户态句柄还原为内核对象，再沿对象状态和操作表追踪资源如何被具体子系统处理。
