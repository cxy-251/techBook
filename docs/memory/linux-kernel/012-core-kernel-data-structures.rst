第012章：Linux 内核核心数据结构
===============================

核心知识点
----------

通用数据结构表达对象关系
   内核中的链表、树、索引、引用计数和等待机制，不只是容器工具。它们分别说明对象如何被组织、查找、共享、等待和释放，是各子系统共同使用的对象语言。

侵入式集合把节点嵌入对象
   ``list_head``、``hlist_node`` 和 ``rb_node`` 通常作为成员嵌入宿主对象。集合代码只操作节点，再通过 ``container_of()`` 或对应 entry 宏恢复完整对象。

不同集合对应不同查找模型
   双向链表适合顺序组织；``hlist`` 常用于哈希桶；红黑树按可比较 key 维护有序索引；XArray 用整数索引保存条目。选择哪种结构取决于查找输入和更新方式。

IDR 与 IDA 管理小整数 ID
   IDR 建立 ID 到对象指针的映射；IDA 只分配和回收 ID，不保存对象指针。新代码中许多索引需求可由 XArray 承担，但旧代码仍广泛使用 IDR/IDA 接口。

集合关系不等于对象生命周期
   节点被插入或删除，只表示对象进入或离开某个索引。对象是否仍然可用，取决于引用计数、锁、RCU 和所有权规则。

引用计数保护对象存活
   ``kref`` 和 ``refcount_t`` 表达当前仍有多少持有者。对象通常先初始化引用，再对外发布；删除路径先阻止新引用，最后一个引用释放时才进入 release 回调。

引用计数不负责字段同步
   引用计数只能防止对象过早释放，不能保证多个 CPU 同时读写字段时的一致性。字段和集合更新仍需锁、RCU、原子操作或其它同步机制。

等待队列表达条件等待
   等待队列保存等待者，真正的事件由共享 condition 表达。``wake_up()`` 只让等待者重新获得运行机会，等待者醒来后仍必须再次检查条件。

Completion 表达完成事件
   ``struct completion`` 适合一次初始化完成、异步操作结束或线程退出等明确事件。等待期间，承载 completion 的对象必须保持存活。

关键路径
--------

阅读一个通用数据结构字段：

::

   识别字段类型
   → 找集合头、树根或索引容器
   → 找 key、index 或 condition
   → 找插入、查找、删除和遍历路径
   → 找锁或 RCU 保护
   → 找引用获取与释放
   → 找最终 release 或唤醒路径

共享对象的生命周期：

::

   创建对象并初始化引用
   → 加入可查找集合
   → 查找者取得引用
   → 删除路径撤销查找入口
   → 现有持有者依次释放引用
   → 引用归零
   → release 回调释放对象

条件等待：

::

   等待者检查 condition
   → 条件不成立时进入 waitqueue 并睡眠
   → 生产者修改共享状态
   → 生产者调用 wake_up()
   → 等待者重新运行
   → 再次检查 condition

概念辨析
--------

链表删除与对象释放
   删除节点只解除集合关系；对象释放还要满足引用、RCU 和所有权条件。

``hlist`` 与红黑树
   ``hlist`` 先用哈希选择 bucket，再比较完整 key；红黑树按比较规则维持有序查找。

XArray、IDR 与 IDA
   XArray 按整数索引保存条目；IDR 管理 ID 到指针的映射；IDA 只管理 ID 占用。

引用计数与并发同步
   引用计数保证对象仍然存在；锁和 RCU 保证字段或集合关系在并发访问下保持一致。

等待队列与 completion
   等待队列适合反复检查任意条件；completion 适合表达一个明确完成事件。

唤醒与条件成立
   唤醒只是调度动作；共享状态变化才表示等待条件真正成立。

本章结论
--------

内核通用数据结构共同回答三个问题：对象怎样被找到、怎样保持存活，以及状态变化怎样在不同执行路径之间交接。
