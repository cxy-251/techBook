第012章：Linux 内核核心数据结构
===============================

本章必须记住
------------

#. 内核数据结构不仅保存字段，也表达对象怎样被组织、查找、共享、等待和释放。
#. 内核常把通用节点嵌入业务对象内部，因此字段类型会直接暴露对象关系。
#. ``struct list_head`` 表示对象进入双向链表；链表管理节点关系，不自动管理宿主对象生命周期。
#. ``list_add*()`` 表示节点加入集合，``list_del*()`` 表示节点离开集合；节点删除不等于对象内存已经释放。
#. ``list_for_each_entry()`` 等宏通过嵌入成员和 ``container_of()`` 从链表节点返回宿主对象。
#. ``hlist`` 常用于哈希桶；哈希只缩小候选范围，真正匹配仍要比较原始 key。
#. 阅读 ``hlist`` 时必须找哈希函数、bucket、冲突比较、锁和删除路径。
#. 红黑树通过 ``struct rb_node`` 把对象按可比较 key 组织成有序索引；比较规则由使用该树的子系统代码定义。
#. 阅读红黑树时必须找树根、比较字段、插入路径、查找路径和相等 key 的处理方式。
#. XArray 用 ``unsigned long`` 索引映射条目，常用于页缓存、对象表和其它整数索引集合。
#. 阅读 XArray 时必须确认 index 的业务含义、条目所有权、锁或 RCU 规则以及擦除路径。
#. IDR 把小整数 ID 映射到指针；IDA 只管理 ID 是否被占用，不保存对象指针。
#. ``kref`` 和 ``refcount_t`` 表达对象被多少持有者共享；引用归零才允许进入最后释放路径。
#. 引用计数保证对象是否仍然存在，不自动保证对象字段并发读写安全；字段一致性仍需锁、RCU 或其它同步机制。
#. 对象对外可见前通常先初始化引用计数；查找者取得对象后应增加引用，离开时减少引用。
#. 删除对象时应先阻止新的查找或取得引用，再等待现有持有者释放，最后执行 release 回调。
#. 等待队列保存等待者集合，condition 表达真正的事件状态，``wake_up()`` 只是让等待者重新检查条件。
#. completion 表达明确的完成事件，常用于初始化完成、异步操作结束和线程退出等同步点。
#. 等待者睡眠期间，承载等待队列或 completion 的对象必须保持存活。

必背路径
--------

阅读结构体字段时采用以下顺序：

::

   识别字段类型
   → 找集合头、树根或索引容器的拥有者
   → 找 key、index 或 condition 的来源
   → 找插入、查找、删除和遍历路径
   → 找锁、RCU 或其它并发保护
   → 找引用获取、引用释放和最终 release
   → 找等待方、状态修改方和唤醒方

引用计数生命周期：

::

   创建对象并初始化引用计数
   → 把对象加入可查找集合
   → 查找者取得对象并增加引用
   → 删除路径先撤销新的查找入口
   → 各持有者依次减少引用
   → 引用归零
   → release 回调释放剩余资源和对象内存

等待队列协作：

::

   等待方检查 condition
   → 条件不成立时加入 waitqueue 并睡眠
   → 生产者修改共享状态
   → 生产者调用 wake_up()
   → 等待者重新获得运行机会
   → 再次检查 condition

必须区分
--------

集合删除与对象释放
   从链表、树或哈希表删除节点只解除索引关系；对象释放还取决于引用、RCU 和所有权规则。

哈希桶与最终匹配
   哈希值用于选择 bucket；桶中的候选对象仍需比较完整 key。

XArray、IDR 与 IDA
   XArray按整数索引保存条目；IDR管理 ID 到指针的映射；IDA只管理 ID 占用状态。

引用计数与字段同步
   引用计数保证对象不会过早释放；锁和 RCU 保证并发访问字段或集合关系时的一致性。

等待队列与完成量
   等待队列适合任意条件反复检查；completion 适合明确的完成事件或完成状态。

唤醒与条件成立
   唤醒只让等待者重新运行并检查条件；真正的事件由共享状态变化表达。

一句话结论
----------

内核通用数据结构是对象关系语言：集合字段说明怎样找到对象，引用字段说明对象何时存活，等待字段说明状态怎样在不同执行路径之间交接。
