第045章：进程、中断与内核线程执行上下文
=======================================

核心知识点
----------

执行上下文决定 API 能力
   一段内核代码能否睡眠、访问用户地址、使用 mutex 或采用 ``GFP_KERNEL``，首先取决于它运行在进程、硬中断、softirq、workqueue 还是内核线程上下文中。

进程上下文代表某个可调度 task
   系统调用、缺页处理、普通文件回调、线程型 workqueue 和内核线程通常运行在进程上下文。进程上下文通常允许睡眠，但持有 spinlock、关闭中断或处于其它原子区时仍不能阻塞。

进程上下文不等于用户进程语义
   kworker 和内核线程也有 ``current``，但通常不代表某个用户请求，也没有普通用户地址空间。访问用户指针必须发生在代表对应用户 task 的受控路径中。

硬中断必须快速且不可睡眠
   硬中断直接响应设备事件，应完成确认硬件、保存最小状态、更新计数或安排延迟处理。它不能调用阻塞 API、普通用户访问或可能睡眠的内存分配。

softirq 是延后的原子上下文
   softirq 承担网络、定时器、RCU 等高频延迟工作，仍然不能睡眠。即使它由 ``ksoftirqd`` 线程承载执行，回调本身仍遵守 softirq 语义。

workqueue 把工作迁移到线程上下文
   线程型 workqueue 的回调由 kworker task 执行，通常可以睡眠。IRQ 中执行 ``queue_work()`` 只表示排队发生在中断上下文，work function 的真实执行上下文已经改变。

用户数据不能直接跨异步边界
   用户指针只在原用户 task 的地址空间和生命周期中有效。异步处理前应先复制、验证并建立内核对象，再把该对象和必要引用交给 workqueue 或内核线程。

内核线程是独立调度的内核 task
   内核线程通常没有自己的用户 ``mm_struct``，可以睡眠并使用阻塞锁，但仍要遵守停止协议、对象生命周期和当前持锁状态。

上下文迁移必须同时迁移所有权
   从 IRQ 转到 softirq 或 workqueue 时，不仅要传递数据，还要明确同步方式、对象引用、分配策略、取消流程和拆除顺序。

关键路径
--------

设备事件的上下文迁移：

::

   硬件产生 IRQ
   → 硬中断确认设备并保存最小状态
   → 使用原子操作或 spinlock 发布事件
   → 安排 softirq、NAPI 或 workqueue
   → 硬中断快速返回
   → softirq 处理低延迟批量工作
   或 kworker 处理可睡眠复杂工作
   → 更新对象状态并唤醒等待 task

用户请求转为异步工作：

::

   用户 task 进入系统调用
   → 在用户进程上下文复制用户数据
   → 验证并建立内核请求对象
   → 取得目标对象和请求引用
   → queue_work
   → kworker 使用内核对象执行
   → 完成后记录结果或唤醒等待者
   → 归还引用并释放请求对象

判断能否睡眠：

::

   确认注册入口与当前调用链
   → 判断进程、hardirq 或 softirq 上下文
   → 检查是否持有 spinlock 或关闭 IRQ/BH
   → 检查目标 API 是否可能 fault、回收或阻塞
   → 全部条件允许时才能睡眠
   → 否则使用非阻塞操作或迁移到线程上下文

停止内核线程：

::

   阻止新任务进入
   → 设置 stopping 状态
   → 请求线程停止
   → 唤醒可能正在睡眠的线程
   → 线程检测停止条件并退出循环
   → 等待线程函数返回
   → 最后释放共享对象

概念辨析
--------

进程上下文与用户进程上下文
   二者都由 task 承载；只有后者代表相应用户请求并具有用户地址空间语义。

硬中断与 softirq
   两者都不能睡眠；硬中断直接响应硬件，softirq 承担延后的原子工作。

softirq 与 ksoftirqd
   ``ksoftirqd`` 是内核线程，但它执行 softirq 回调时仍不能使用睡眠 API。

workqueue 与 softirq
   线程型 workqueue 通常可以睡眠；softirq 必须保持原子执行语义。

current 与用户指针
   每种上下文都有 ``current``；只有代表对应用户 task 的路径才能受控访问其用户内存。

mm 与 active_mm
   ``mm`` 表示 task 拥有的用户地址空间；内核线程的 ``active_mm`` 只是 CPU 运行所借用的地址空间，不赋予用户指针语义。

排队上下文与执行上下文
   工作在哪里被提交，不等于回调在哪里执行，必须以回调注册机制和实际调用链为准。

本章结论
--------

内核代码是否合法首先取决于执行上下文：硬中断与 softirq 必须非阻塞，线程型 workqueue 和内核线程通常可睡眠，而跨上下文传递数据时必须同步转移对象引用与生命周期责任。
