第063章：原子操作与内存顺序
===========================

核心知识点
----------

原子性与顺序性是两个问题
   原子性保证一个共享内存位置的操作不可分割；内存顺序约束其它 CPU 观察多个内存访问的先后关系。一个操作是 atomic，不代表相邻普通字段已经可靠发布。

Atomic 类型表达并发整数或状态
   ``atomic_t``、``atomic64_t`` 和 ``atomic_long_t`` 适合计数、状态和读改写操作。普通 ``counter++`` 可能在多 CPU 下丢失更新，atomic RMW 可以避免这一竞争。

引用计数应使用专用类型
   ``refcount_t`` 把 0 作为生命周期边界，并提供针对溢出、重复递减和错误复活的保护。它比普通 ``atomic_t`` 更准确地表达对象所有权。

引用只保证对象仍然存在
   成功取得引用后，对象内存不能被最终释放；对象是否仍处于 active 状态、字段访问是否互斥、timer 和 work 是否已停止，仍由状态机和其它同步协议决定。

RMW 只保护目标变量
   ``atomic_inc()``、``atomic_fetch_add()`` 和 ``atomic_cmpxchg()`` 把读、修改和写回组合成单个不可分割操作。多个字段组成的复合不变量仍需要锁、seqcount、RCU 或完整状态协议。

Compare-exchange 适合条件状态转换
   ``cmpxchg`` 只有在当前值等于期望值时才提交新值。失败表示状态已被其它执行者改变，调用者必须读取最新值并重新判断重试、退出或走慢路径。

原子 API 的顺序由后缀决定
   ``_relaxed`` 只保证原子性；``_acquire`` 约束后续访问不能越过获取点；``_release`` 约束此前访问必须在发布动作之前完成。默认形式的具体保证应按当前内核 API 契约解释。

Release/acquire 建立数据发布关系
   生产者先写 payload，再对同步变量执行 release；消费者通过 acquire 观察到该发布值后，才可读取 payload。两侧必须围绕同一同步变量或明确的 reads-from 关系配对。

``READ_ONCE`` 和 ``WRITE_ONCE`` 不是完整同步
   它们约束编译器对单次访问的合并、缓存或拆分，但不自动建立跨 CPU 的发布和获取顺序。需要同步时仍要使用 acquire/release、锁、RCU 或屏障。

无锁状态机还要处理回收和 ABA
   数值从 A 变成 B 再回到 A 时，cmpxchg 可能看不出对象版本已经变化。无锁指针更新通常还需要版本号、引用计数、RCU 或其它回收协议。

关键路径
--------

发布数据给另一个 CPU：

::

   生产者初始化 payload
   → 完成全部普通字段写入
   → 对 ready 执行 release store
   → 消费者对 ready 执行 acquire load
   → 确认观察到已发布状态
   → 读取 payload
   → 生命周期协议保证 payload 仍然存在

安全取得对象引用：

::

   在锁或 RCU 保护下找到对象
   → refcount_inc_not_zero 尝试取得引用
   → 成功后离开查找保护区
   → 检查对象状态并使用
   → 执行 put
   → 最后一次 put 进入 release 路径

Compare-exchange 状态机：

::

   读取当前状态
   → 判断是否允许转换
   → 计算新状态
   → cmpxchg 比较并提交
   → 成功时完成状态迁移
   → 失败时取得最新值
   → 重新判断重试或走慢路径
   → 单独处理生命周期和 ABA

分析一个 atomic API：

::

   确认变量表达计数、状态还是引用
   → 判断操作是读写还是 RMW
   → 检查 relaxed、acquire、release 或默认顺序
   → 找到发布侧和观察侧
   → 检查普通字段的可见关系
   → 检查失败重试与对象回收

概念辨析
--------

原子性与顺序性
   原子性防止单个位置的更新被拆分；顺序性规定多个访问被其它 CPU 观察的先后。

``atomic_t`` 与 ``refcount_t``
   前者表达普通并发整数；后者表达对象引用和 0 值生命周期边界。

Atomic 变量与复合不变量
   Atomic API 只保护目标位置；多个字段必须由更完整的同步协议共同保护。

Relaxed 与 acquire/release
   Relaxed 只有原子性；acquire/release 还承担单向获取和发布顺序。

对象存活与字段一致性
   引用防止对象被释放；字段并发读写仍需要锁、RCU、原子状态或其它协议。

本章结论
--------

原子操作首先解决单个变量不丢更新；只有配合正确的 acquire/release 关系、复合状态协议和对象生命周期，它才能成为完整的跨 CPU 同步机制。
