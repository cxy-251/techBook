第079章：vmalloc 与非连续内核虚拟内存
=====================================

本章必须记住
------------

#. ``vmalloc()`` 返回一段连续的内核虚拟地址，背后的物理页可以彼此不连续。
#. 虚拟连续保证 CPU 可以用普通指针线性访问；它不保证物理连续、DMA 连续或设备可寻址。
#. ``vmalloc`` 适合大块、主要由 CPU 访问、只要求虚拟连续的缓冲区和表结构。
#. ``kmalloc`` 与 ``vmalloc`` 都返回连续内核虚拟地址，主要差异在背后物理页布局与分配成本。
#. ``kmalloc`` 大块分配可能依赖高阶连续页，容易受物理碎片影响；``vmalloc`` 可以用多个 order-0 页拼接区域。
#. ``vmalloc`` 提高大块申请在碎片化系统中的成功机会，但仍可能因总内存、memcg、虚拟区域或页表资源不足而失败。
#. ``vmalloc`` 的机制包括保留虚拟区间、分配页、建立内核页表映射和返回区域起始地址。
#. 每个虚拟页都要映射到对应物理页，映射建立和拆除会产生页表与 TLB 管理成本。
#. ``vmalloc`` 区域的访问通常比直接映射内存承受更多 TLB 压力，尤其是大范围随机访问。
#. 背后物理页分散还可能降低 NUMA 与缓存局部性，具体位置由分配策略和运行状态决定。
#. 普通 ``vmalloc`` 分配路径可能睡眠，不能在硬中断、softirq、持 spinlock 或其它原子上下文中调用。
#. 普通 ``vfree()`` 也应按可能涉及映射拆除和延迟处理的释放路径理解；原子上下文需要使用明确支持的接口或延后到工作线程。
#. ``vzalloc()`` 分配虚拟连续区域并将请求内容清零，仍需进行对象专用初始化。
#. ``vcalloc()``、``vmalloc_array()`` 等数组接口用于避免元素数量与大小乘法溢出，具体可用接口以目标内核为准。
#. ``vfree()`` 释放 ``vmalloc``/``vzalloc`` 区域；不能用 ``kfree()`` 释放普通 vmalloc 地址。
#. ``kvfree()`` 可以释放由 ``kvmalloc`` family 返回、来源可能是 kmalloc 或 vmalloc 的区域。
#. ``kvmalloc()`` 通常先尝试 kmalloc，再在允许时退到 vmalloc；调用者必须始终按“物理页可能分散”设计。
#. ``kvmalloc`` 的 fallback 需要可睡眠上下文，不能把它当作 ``GFP_ATOMIC`` 的大块分配方案。
#. ``vmap()`` 把调用者已经持有的一组页映射成连续内核虚拟地址；``vmalloc()`` 则同时负责取得页和建立映射。
#. ``vunmap()`` 解除 ``vmap`` 建立的映射，但背后页面的所有权和释放责任仍由调用者协议决定。
#. ``vm_map_ram()`` 适合特定短期、小规模页数组映射，和长期 ``vmap`` 混用可能导致虚拟地址空间碎片，必须按 API 文档选择。
#. ``virt_to_phys()``、``virt_to_page()`` 一般不能用于 vmalloc 地址，因为该区域不属于普通线性直接映射。
#. 要从 vmalloc 地址定位 backing page，应按页使用 ``vmalloc_to_page()`` 或目标接口提供的转换 helper。
#. 相邻 vmalloc 虚拟页对应的 PFN 可以完全不相邻，不能通过起始 PFN 加偏移推导整个区域。
#. ``is_vmalloc_addr()`` 可帮助判断地址是否位于 vmalloc 区域，但不能替代对象来源和生命周期记录。
#. ``remap_vmalloc_range()`` 等接口可以在受控条件下把 vmalloc 页映射给用户空间，必须验证 VMA、长度、权限和对象生命周期。
#. 用户映射仍存在时不能提前 ``vfree`` backing 区域；必须先撤销用户可见性并等待所有引用结束。
#. ``vmalloc`` 内存不能直接交给设备做 DMA；设备访问必须使用 DMA API、scatter-gather 或设备专用分配机制。
#. CPU 能解引用某个 vmalloc 指针，不代表设备能理解该虚拟地址或对应分散物理页。
#. 设备 DMA 需要总线地址、DMA mask、IOMMU 和缓存一致性语义，这些都不由 ``vmalloc`` 自动提供。
#. 模块、BPF、内核文本补丁等可执行内存使用专门的 vmalloc-like 和权限转换接口，不能把普通 ``vmalloc`` 区域直接当可执行内存。
#. W^X 要求内存不能同时可写和可执行，权限建立与切换必须使用架构和内核提供的专用路径。
#. Vmalloc 区域自身是有限的虚拟地址资源，区域碎片或地址空间耗尽可以在物理内存尚有余量时导致失败。
#. ``/proc/vmallocinfo`` 可观察当前 vmalloc 区域、大小和部分调用来源，是诊断虚拟区域占用的主要入口。
#. Vmallocinfo 是瞬时视图，映射会并发创建和释放；复杂泄漏需要结合时间线和调用栈。
#. Vmalloc 释放需要结束调用者对指针的使用、拆除页表、处理 TLB 旧翻译并归还 backing pages。
#. 内核可能批量或延迟部分 vmap/vmalloc TLB flush；实现优化不延长调用者使用已释放指针的权利。
#. ``vm_unmap_aliases()`` 一类接口处理延迟别名清理，不能作为普通对象释放协议的替代品。
#. 大块区域若需要频繁分配和释放，应评估预分配、复用池、分段对象或页面数组，避免反复建立页表映射。
#. 大块区域若只需要分散页集合而不需要线性 CPU 指针，可以直接保留 page array，避免无意义的 vmap 成本。
#. 选择 ``vmalloc`` 前必须确认所有访问者都接受物理分散，并确认分配和释放发生在允许睡眠的上下文。
#. 调试 vmalloc 故障时，应区分物理页分配失败、vmalloc 虚拟区域不足、页表建立失败、非法地址转换和 UAF。
#. 报告必须记录区域起始地址、大小、分配接口、调用栈、访问者、用户映射、DMA 使用和释放时间。

必背路径
--------

``vmalloc`` 分配：

::

   调用者提出大块虚拟连续需求
   → 确认只由 CPU 访问且允许物理分散
   → 确认当前上下文可以睡眠
   → 保留 vmalloc 虚拟地址区间
   → 分配多个 backing pages
   → 建立内核页表映射
   → 返回连续虚拟地址
   → 处理 NULL 失败

``vmalloc`` 释放：

::

   停止新访问和新用户映射
   → 等待普通引用、work、timer 和异步路径
   → vfree 解除虚拟映射
   → 使旧 TLB 翻译失效
   → 归还 backing pages 与区域元数据
   → 原指针彻底失效

分析 vmalloc 地址：

::

   取得内核虚拟地址
   → 确认位于有效 vmalloc 区域
   → 找到区域起点和长度
   → 对每个虚拟页使用 vmalloc_to_page
   → 分别取得 backing page / PFN
   → 不假设相邻 PFN
   → 检查区域生命周期与访问权限

选择 ``kmalloc``、``kvmalloc`` 或 ``vmalloc``：

::

   小对象或需要物理连续特征
   → 优先 kmalloc
   → 大块且只需虚拟连续
   → 可直接 vmalloc
   → 希望小块优先走 kmalloc、大块允许退化
   → kvmalloc
   → 所有可能退化路径按物理分散设计
   → kvmalloc 结果统一 kvfree

设备访问检查：

::

   识别访问者是 CPU 还是设备
   → 设备不能使用普通 vmalloc 虚拟地址
   → 读取设备 DMA mask 和一致性要求
   → 使用 dma_alloc_* / dma_map_* / scatterlist
   → 建立总线可见映射
   → 完成同步与 unmap
   → 最后释放原内存

必须区分
--------

* 虚拟连续与物理连续：Vmalloc 保证前者；背后页可以分散，不能直接满足连续物理需求。
* ``vmalloc`` 与 ``vmap``：``vmalloc`` 取得页并映射；``vmap`` 映射调用者已经拥有的页集合。
* ``vfree`` 与 ``kvfree``：``vfree`` 面向明确的 vmalloc 来源；``kvfree`` 适合来源可能是 kmalloc 或 vmalloc 的 kvmalloc 结果。
* CPU 地址与 DMA 地址：CPU 通过页表解释 vmalloc 指针；设备需要 DMA API 建立总线可见地址。
* 物理内存不足与 vmalloc 区不足：前者缺少 backing pages；后者缺少可用连续内核虚拟区间或页表资源。
* 映射仍存在与调用者仍可访问：实现可能延迟部分底层回收，但调用者在释放后立即失去访问权。

一句话结论
----------

``vmalloc`` 用页表把分散物理页拼成连续内核虚拟地址，适合可睡眠的 CPU 大块访问路径，但不能提供 DMA 或物理连续保证。
