第007章：上下文管理语义
======================

核心知识点
----------

context manager 把资源生命周期绑定到作用域
   ``with`` 和 ``async with`` 用对象协议统一表达资源进入、body 使用、退出清理和异常策略，使文件、锁、事务、连接和临时资源不依赖垃圾回收时机释放。

manager 与 ``as`` 绑定值可能不同
   manager expression 产生实现协议的对象；``as target`` 接收 ``__enter__`` 或 ``__aenter__`` 的返回值。manager 负责生命周期，body 使用的 handle 可以是 manager 自身、底层资源或代理对象。

同步协议由 ``__enter__`` 与 ``__exit__`` 构成
   ``__enter__`` 把资源带入可用状态并返回绑定值；``__exit__(exc_type, exc, tb)`` 接收退出原因、执行清理，并在异常退出时用返回值决定异常是否继续传播。

``with`` 的执行顺序固定
   解释器先求值 manager，取得退出能力，再调用 ``__enter__``，绑定 ``as`` target，执行 body，最后调用 ``__exit__``。只要 ``__enter__`` 成功，body 的正常结束、``return``、循环跳转和异常都会触发退出逻辑。

多个 context manager 按栈顺序退出
   ``with A() as a, B() as b`` 等价于嵌套 ``with``：A 先进入，B 后进入；退出时 B 先清理，A 后清理。内层退出动作改变异常状态后，外层看到的是更新后的状态。

异常抑制是显式错误策略
   异常退出时，``__exit__`` 返回真值表示异常已被处理，控制流从 ``with`` 之后继续；返回假值表示异常继续传播。普通完成或非异常跳转时，退出参数为三个 ``None``，返回值不改变原控制目标。

``__enter__`` 失败有独立边界
   当前 manager 的 ``__enter__`` 尚未成功时，其 ``__exit__`` 不会自动运行。部分资源已经获取的实现必须在进入方法内部清理，或使用 ``ExitStack`` 逐步注册成功取得的资源。

异步协议允许清理过程挂起
   ``async with`` 使用 ``await __aenter__()`` 与 ``await __aexit__()``，适合连接池、异步锁和 session 等需要等待 I/O 的进入与退出过程。取消同样会沿异常退出路径进入 ``__aexit__``。

退出栈管理动态资源组
   ``ExitStack`` 与 ``AsyncExitStack`` 在运行时注册 context manager 或清理回调，并按后进先出顺序收束。后续资源获取失败时，先前已经成功注册的资源仍能可靠退出。

关键路径
--------

同步 ``with`` 路径：

::

   求值 manager expression
   → 取得 enter 与 exit 协议能力
   → 调用 __enter__
   → 把返回对象绑定到 as target
   → 执行 body
   → 普通退出时调用 __exit__(None, None, None)
   → 异常退出时调用 __exit__(type, value, traceback)
   → 根据返回值抑制或继续传播异常

动态资源栈：

::

   创建 ExitStack 或 AsyncExitStack
   → 每取得一个资源就立即注册退出动作
   → 后续继续动态取得资源
   → body 正常结束、获取失败或抛出异常
   → 按注册顺序的反方向执行退出动作
   → 更新异常状态并完成整体收束

概念辨析
--------

* **manager object 与 ``as`` target**：前者实现生命周期协议；后者是进入方法返回给 body 使用的对象，二者不必相同。
* **清理与异常抑制**：清理应覆盖所有退出路径；异常抑制只应针对明确可处理的异常类型和稳定后续状态。
* **``__exit__`` 与 ``finally``**：二者都参与确定性收束；``__exit__`` 额外接收异常三元组，并可通过返回值抑制异常。
* **同步与异步 context manager**：同步退出必须立即完成；异步退出允许 ``await``，可把 I/O 清理纳入事件循环。
* **嵌套 ``with`` 与 ``ExitStack``**：嵌套 ``with`` 适合资源数量静态已知；退出栈适合数量或组合在运行时才能确定的资源。
* **对象回收与确定性释放**：垃圾回收管理 Python 对象可达性；context manager 用明确控制流边界管理外部资源状态。

本章结论
--------

评审资源代码时，应明确资源获取点、所有权、``as`` 绑定值、退出顺序和异常策略，再确认部分进入失败、嵌套资源、异步取消及动态资源数量是否都能沿同一退出协议收束；可靠的 context manager 让资源生命周期直接由作用域和控制流证明，而不是依赖析构时机或分散的关闭语句。
