第008章：万物皆对象
==================

核心知识点
----------

Python 运行时统一处理对象引用
   整数、函数、类、实例和容器元素的能力各不相同，但名字、参数、返回值和容器槽位保存的都是对象引用。赋值与传参通常改变引用关系，不会复制对象本体。

对象同时具有身份、类型和值
   identity 用于区分对象，type 决定对象支持的协议和分发入口，value 是类型专属状态。``is`` 比较身份；``id()`` 只在对象存活期间稳定，对象销毁后底层地址或编号可能被复用。

``PyObject`` 提供最小公共头部
   CPython 中对象通常可先按 ``PyObject *`` 观察。公共头部包含引用计数状态 ``ob_refcnt`` 与类型指针 ``ob_type``；类型指针连接到 ``PyTypeObject``，后续操作再由类型对象决定。

对象载荷由具体类型解释
   公共头部之后是类型专属数据。整数保存数值表示，列表保存元素引用数组与容量，函数保存 code object、globals、defaults 和 closure，实例保存或关联自身属性状态。

可变长对象扩展为 ``PyVarObject``
   ``PyVarObject`` 在公共头部之外增加 ``ob_size``，用于表达内部可变长布局。``ob_size`` 是实现字段，``len(obj)`` 是公开协议调用，二者不能直接等同。

引用计数负责大多数即时回收
   新的强引用通常增加引用计数，释放强引用通常减少引用计数。普通对象计数归零后进入类型定义的释放路径；循环引用无法仅靠计数发现，需要循环垃圾回收器参与。

对象存在多种分配与存活形态
   heap object 由运行时分配并按引用图回收；static object 随解释器或静态结构长期存在；immortal object 是 CPython 的内部优化形态，常规引用计数变化不会把它推进到销毁路径。

类型对象同时决定构造与销毁
   常规实例创建由类型调用开始，经过 ``tp_new``、``tp_alloc``、对象头初始化和 ``tp_init``；普通对象失去最后引用后，可能经过 finalizer、``tp_dealloc`` 和 ``tp_free`` 收束。

对象生命周期取决于完整引用图
   删除一个名字只释放一条引用关系。容器、闭包、frame、模块、缓存或其它对象仍然持有引用时，对象继续存活。判断回收时必须追踪所有权和可达性，而不是只看某个变量是否被删除。

关键路径
--------

对象识别与操作分发：

::

   namespace 中的名字
   → 对象引用
   → PyObject 公共头部
   → ob_type 指向 PyTypeObject
   → 类型 slot 或协议实现
   → 返回新对象或设置异常状态

普通对象创建与销毁：

::

   调用类型对象
   → tp_new
   → tp_alloc
   → 初始化对象头与类型专属状态
   → tp_init
   → 对象进入可达引用图
   → 强引用逐步释放或循环 GC 判定不可达
   → finalizer 与内部引用清理
   → tp_dealloc
   → tp_free

概念辨析
--------

* **名字与对象**：名字是 namespace 中的绑定；对象是独立运行时实体，多个名字可以指向同一个对象。
* **身份与相等**：身份回答是否为同一对象；相等由类型协议判断值是否等价。
* **引用计数与引用图**：引用计数记录强引用状态；引用图还包含环和可达性，循环回收需要额外 GC 算法。
* **对象头部与对象载荷**：头部提供统一识别、存活与类型入口；载荷表达具体类型的数据。
* **``PyObject`` 与 Python 层对象**：``PyObject`` 是 CPython 的通用 C 视角；其它 Python 实现可以用不同内部布局维持同一语言语义。
* **heap、static 与 immortal object**：三者都能作为 Python 对象使用，差异主要落在内存来源、引用计数行为和销毁时机。
* **删除名字与销毁对象**：删除绑定只减少一条持有关系；只有对象不再被需要并满足回收条件时才会销毁。

本章结论
--------

分析任何 Python 运行时现象时，应先把名字、对象引用、对象头部、类型对象和类型专属载荷分层，再沿创建、持有和释放路径检查生命周期；“万物皆对象”不是一句语法口号，而是所有值先通过统一对象模型进入类型分发、内存管理和协议执行的基础。
