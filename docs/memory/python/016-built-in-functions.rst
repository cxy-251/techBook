第016章：内置函数
=================

核心知识点
----------

内置函数是运行时协议入口
   ``len``、``iter``、``getattr``、``repr``、``open``、``compile`` 等名字虽然表现为普通函数，实际负责把调用转发到对象类型、属性系统、表示协议、I/O 层或编译执行管线。理解内置函数时，应先确认它要求对象提供什么能力。

长度与迭代由类型协议决定
   ``len(obj)`` 请求非负整数长度；``iter(obj)`` 请求 iterator；``next(it)`` 调用 ``__next__`` 并以 ``StopIteration`` 表示正常耗尽。缺少 ``__iter__`` 时，运行时还可能使用从索引 0 开始的 ``__getitem__`` 兼容路径。

``iter(callable, sentinel)`` 组合调用与迭代
   该形式反复执行零参数 callable，返回值等于 sentinel 时结束，常用于固定大小块读取。callable 负责产生数据，iterator 只负责推进和终止判断。

类型查询与能力查询不是同一件事
   ``type`` 返回直接类型；``isinstance`` 与 ``issubclass`` 判断继承或虚拟子类关系；``id`` 表示对象生命周期内稳定身份。类型关系只能说明对象处在哪个类型层级，不能替代对具体协议能力的判断。

属性类内置函数进入完整属性查找链
   ``getattr``、``setattr``、``hasattr`` 会触发 ``__getattribute__``、descriptor、实例字典、类字典、MRO、``__getattr__`` 或 ``__setattr__``。``hasattr`` 本质上把属性读取产生的 ``AttributeError`` 转成 ``False``，复杂属性计算不宜只依赖它诊断错误。

``callable`` 只检查调用入口
   函数、类、方法和类型定义了 ``__call__`` 的实例都可被调用。``callable(obj)`` 为真不保证参数绑定、对象状态和函数体执行一定成功；它只说明运行时会尝试进入调用协议。

对象文本表示分为不同用途
   ``repr`` 面向调试和状态复盘，要求返回字符串；``str`` 面向用户展示，缺少 ``__str__`` 时通常回退到 ``__repr__``；``format`` 与格式化字符串进入 ``__format__``。三者应共享对象事实，但服务不同展示语境。

``open`` 建立资源和编码边界
   文件模式决定文本或二进制语义；文本模式还涉及 encoding、errors 和 newline。文件对象应通过 ``with`` 管理关闭时机，不能把对象回收当作可靠的资源释放协议。

动态执行包含编译与命名空间控制
   ``compile`` 把源码转换为 code object；``eval`` 求值表达式并返回结果；``exec`` 执行语句块。globals 与 locals 决定名字解析和写入位置，限制 builtins 只能缩小可见表面，不能把不可信源码变成安全输入。

关键路径
--------

典型协议型内置函数路径：

::

   当前 frame 查找内置函数名字
   → 内置函数检查参数形状
   → 取得对象的实际类型
   → 进入对应 special method 或类型 slot
   → 校验返回值是否满足协议
   → 返回结果、执行 fallback 或抛出异常

动态执行路径：

::

   准备源码字符串或 AST
   → compile 生成 code object
   → 准备 globals、locals 与 builtins
   → eval 或 exec 创建执行环境
   → 执行名字解析、调用和副作用
   → 返回表达式结果或更新命名空间

概念辨析
--------

* **``type(obj) is T`` 与 ``isinstance(obj, T)``**：前者检查直接类型，后者接受子类和部分虚拟子类关系。
* **类型关系与 duck typing**：继承关系描述对象身份；协议调用关心对象类型是否提供所需行为。
* **``getattr`` 与直接点号访问**：二者进入相同属性系统，``getattr`` 允许属性名作为运行时字符串传入。
* **``hasattr`` 与安全探测**：它只根据 ``AttributeError`` 给出布尔结果，property 或 descriptor 内部的该异常也可能被视为属性不存在。
* **``repr``、``str`` 与 ``format``**：分别服务调试表示、用户文本和格式规范，不能混成一个没有边界的输出函数。
* **``next(it, default)`` 与异常吞没**：default 只处理正常耗尽，不应掩盖 iterator 内部产生的其它异常。
* **``eval`` 与 ``exec``**：前者处理表达式并返回值，后者处理语句块并主要通过命名空间产生效果。
* **隐藏 builtins 与安全沙箱**：删除部分内置名字不构成可靠隔离；不可信代码需要进程、权限和资源层面的真实边界。

本章结论
--------

分析内置函数时，不应停在函数名称上，而应定位它连接的对象协议、命名空间或资源层：先确认输入对象和调用形式，再沿类型级入口检查返回值、fallback、异常与副作用。可靠代码会把动态属性、I/O 模式、格式化契约和动态执行范围显式收束，使每个内置函数都只承担清晰、可验证的一段运行时职责。
