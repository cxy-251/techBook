第020章：数值、比较与哈希协议
==============================

核心知识点
----------

运算符通过类型级 slot 分发
   ``x + y``、``x * y``、``x += y`` 等表达式不会先查实例字典，而是根据两个对象的实际类型进入 ``__add__``、``__mul__``、``__iadd__`` 等 special method 及对应数值 slot。运算能力属于类型契约。

二元运算允许双方协商
   左操作数先尝试正向方法；无法处理时应返回 ``NotImplemented``，解释器再考虑右操作数的反向方法。右侧类型是左侧类型的更具体子类时，运行时还会给更具体实现适当优先级。

``NotImplemented`` 不是失败结果
   它表示当前实现放弃处理这组操作数，让分发继续。直接返回 ``False``、``None`` 或抛出过早的 ``TypeError`` 会阻断另一侧类型参与；只有所有候选路径都失败后，解释器才产生最终 ``TypeError``。

原地运算仍会重新绑定左侧目标
   ``x += y`` 优先调用 ``__iadd__``；缺少或返回 ``NotImplemented`` 时回退到普通加法。``__iadd__`` 可以原地修改并返回 ``self``，也可以返回新对象，最终返回值都会重新绑定给 ``x``。

值对象通常应保持不可变
   数值类和可哈希值对象的运算方法宜返回新对象，避免改变参与 equality 和 hash 的字段。可变容器可以提供原地语义，但必须让别名、返回对象和状态变化保持清晰。

rich comparison 包含六个独立入口
   ``<``、``<=``、``==``、``!=``、``>``、``>=`` 分别对应六个比较方法。定义一种关系不会自动推导其它关系；``functools.total_ordering`` 只能基于开发者提供的一致基础关系补齐方法。

相等与排序是不同承诺
   一个类型可能有自然的值相等语义，却没有唯一自然排序。此时只实现 ``__eq__``，把业务排序交给 ``sorted(..., key=...)``，比随意定义全序更稳定。

比较陌生类型时应返回 ``NotImplemented``
   同类比较可以依据值字段返回布尔结果；面对不理解的类型，返回 ``NotImplemented`` 允许对方类型或运行时 fallback 参与。排序双方都无法处理时产生 ``TypeError``，相等比较还可能退回身份语义。

哈希容器同时依赖 hash 与 equality
   ``dict`` 和 ``set`` 先通过 hash 定位候选位置，再通过 equality 确认对象是否代表同一个 key。相等对象必须拥有相同 hash；相同 hash 的对象仍可以不相等。

``__eq__`` 与 ``__hash__`` 必须使用同一组值字段
   若相等性依据 ``(x, y)``，hash 也应依据 ``(x, y)``。参与 hash 的字段在对象进入容器后不得变化，否则对象会留在旧桶位置，后续按新 hash 查询时可能无法找到。

重写相等性会影响默认可哈希性
   用户类定义 ``__eq__`` 而未定义 ``__hash__`` 时，Python 通常把 ``__hash__`` 设为 ``None``，使实例显式退出 hashable 协议。可变值对象应保持这种状态；不可变值对象可以实现与 equality 一致的 hash。

数字转换协议有不同语义层级
   ``__int__`` 表示向整数值转换，``__index__`` 表示对象可作为精确整数索引、切片或位级参数，``__float__`` 表示浮点转换。实现 ``__index__`` 是更强承诺，不能仅因对象“能近似转成整数”就提供。

关键路径
--------

普通二元运算路径：

::

   求值左、右操作数
   → 检查实际类型和子类优先关系
   → 尝试左类型的正向方法
   → 有结果则返回
   → 返回 NotImplemented 时尝试右类型的反向方法
   → 双方均放弃时抛出 TypeError

哈希容器查询路径：

::

   计算查询 key 的 hash
   → 定位候选桶或探测序列
   → 比较候选 key 的 identity 或 equality
   → 相等则命中同一条目
   → 不相等则继续探测
   → 找不到时返回缺失结果或插入新条目

概念辨析
--------

* **``NotImplemented`` 与 ``NotImplementedError``**：前者是二元协议的协商返回值，后者是普通异常，通常用于尚未实现的方法体。
* **正向方法与反向方法**：前者由左操作数类型实现，后者让右操作数在左侧无法处理时接管。
* **``+`` 与 ``+=``**：普通加法只产生结果；增强赋值优先请求原地协议，并把返回值重新绑定到左侧目标。
* **相等性与身份**：``==`` 请求值比较协议，``is`` 只比较对象身份，不能被类型重载。
* **相等与排序**：定义值相等不代表对象之间存在自然、完整且稳定的顺序。
* **hash 相同与对象相等**：相等必然要求 hash 相同；hash 相同只是碰撞候选，不证明相等。
* **可变对象与不可哈希对象**：可变性本身不是语法禁止，风险在于参与 equality/hash 的状态变化会破坏容器定位。
* **``__int__`` 与 ``__index__``**：前者允许数值转换，后者声明对象可无损充当整数索引。
* **数据类自动方法与协议设计**：``dataclass`` 可生成 equality、ordering、hash，但字段选择、冻结策略和跨类型语义仍由开发者负责。

本章结论
--------

实现数值和值对象时，应把运算、比较和哈希视为同一套类型语义，而不是彼此独立的方法集合。先定义对象的值由哪些字段决定，再决定哪些运算有意义、陌生类型如何协商、是否存在自然排序，以及对象能否保持 hash 稳定；只有这些承诺一致，类型才能安全参与表达式、排序、字典和集合。
