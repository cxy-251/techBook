第061章：Foreground, Background, Suspended, Cached, Killed
==========================================================

核心知识点
----------

* 进程状态是移动 OS 的资源管理标签，用来表达当前进程对用户体验和系统任务的重要程度。
* Foreground 表示用户正在直接依赖该进程完成交互，通常获得最高的调度和内存保护。
* Background 表示界面已离开前台，但仍可能存在系统认可的后台任务；普通线程和定时器不具备长期完成保证。
* Suspended 表示地址空间仍保留，但普通代码执行停止；它主要用于快速恢复，不用于继续推进业务工作。
* Cached 表示系统把进程当作可丢弃的恢复缓存；进程可能保留对象和页面状态，但资源压力下可被直接回收。
* Killed 表示进程执行容器已经消失；下次进入 App 时必须重新创建进程并从已保存状态恢复。
* 状态变化会影响 CPU 时间、内存保留、网络、定位、传感器和后台任务窗口，不能只看“进程是否还存在”。
* Android 与 Apple 状态名称不同，但共同目标都是优先保护用户可见任务，并把后台执行和内存占用纳入系统治理。

关键路径
--------

App 前台交互
→ Foreground：输入、绘制和用户可感知任务获得高优先级
→ 用户离开界面
→ Background：仅系统认可的后台工作继续获得执行窗口
→ 后台窗口结束
→ Suspended / Cached：保留内存以便快速恢复，普通执行停止或大幅收缩
→ 内存或系统资源压力上升
→ Killed：系统终止低重要性进程并释放地址空间
→ 用户重新进入 App
→ 系统重新创建进程
→ App 从 saved state 与持久化数据恢复用户任务。

概念辨析
--------

``Background`` 与 ``Suspended``：Background 仍可能有合法执行窗口；Suspended 的核心语义是保留内存但停止普通执行。

``Cached`` 与 ``Running``：cached process 可能仍存在于进程表和内存中，但它只是恢复缓存，不应依赖其继续完成业务工作。

``Killed`` 与 ``App closed``：Killed 只表示执行容器被回收；用户任务、最近任务记录和持久化数据仍可能存在。

``Foreground UI`` 与 ``User-visible task``：界面不可见时，音频、导航、通话等任务仍可能具有用户可感知语义，并通过专用系统入口获得较高保护。

本章结论
--------

移动 OS 用进程状态把用户价值转换成资源优先级。可靠架构必须假设后台进程会被挂起、缓存或回收，并把长期工作交给系统认可的后台入口，把关键用户状态保存到进程之外。
