第002章：SIMD 与 SIMT 并行架构
===============================

核心知识点
----------

SIMD 描述硬件执行形态
   SIMD 表示一条指令同时驱动多个 ``lane`` 处理不同数据。判断对象是当前发射的指令、参与执行的 ``lane`` 以及被 mask 关闭的 ``lane``。

SIMT 描述 shader 编程模型
   SIMT 允许程序员把每个 ``invocation`` 写成独立的标量线程，硬件再把多个线程映射到 SIMD-like 执行槽。shader 源码中的独立控制流不会让同一执行组内的线程变成完全独立的处理器。

执行组是调度与控制流单位
   ``warp``、``wavefront``、``subgroup`` 或 ``simdgroup`` 都表示一批共享指令推进位置和调度状态的线程。具体宽度属于平台属性，不应在跨平台算法中依赖未经查询的固定值。

GPU 通过执行组切换隐藏延迟
   一个执行组在纹理采样、缓冲区读取或特殊函数上等待时，调度器选择另一个就绪执行组。寄存器和共享存储占用决定同一计算单元能驻留多少执行组，从而决定等待能否被其它工作覆盖。

分支发散通过 active mask 执行
   同一执行组内不同 ``lane`` 对条件得到不同结果时，硬件分别执行各条路径，并在每条路径上关闭不参与的 ``lane``，最后在可汇合位置恢复统一推进。成本来自路径次数增加、有效 ``lane`` 比例下降以及寄存器和采样生命周期延长。

条件的空间分布决定发散概率
   来自 uniform、材质开关或 draw 级参数的条件通常组内一致；大块连续遮罩只在边界附近产生混杂；噪声、棋盘格、细碎透明边缘和随机粒子属性更容易让同组 ``lane`` 走不同路径。

分支优化是资源取舍
   短小纯 ALU 分支可用 ``mix``、``select``、``step`` 等转成数据流；包含多次纹理采样、循环、atomic、discard 或副作用的昂贵路径通常应保留可跳过性。优化目标不是删除 ``if``，而是减少无效执行且不把成本转移到更昂贵的资源路径。

关键路径
--------

执行组调度路径：

::

   多个 shader invocation 被组成执行组
   → 读取共同的下一条指令
   → active lane 读取寄存器或资源操作数
   → 指令发射到 ALU、纹理或内存单元
   → 数据未就绪时执行组进入等待
   → 调度器切换到其它 ready 执行组
   → 数据返回后继续执行并写回结果

发散分支路径：

::

   执行组计算同一分支条件
   → 不同 lane 得到不同结果
   → 生成路径 A 的 active mask
   → 关闭其它 lane 并执行路径 A
   → 切换到路径 B 的 active mask
   → 执行路径 B
   → 在汇合点恢复统一 mask

分支优化判断路径：

::

   确认条件来自 uniform、属性、纹理还是计算结果
   → 检查条件在执行组覆盖范围内是否连续
   → 估算各分支的 ALU、采样、寄存器和写回成本
   → 选择保留分支、数据分桶、shader variant 或 branchless
   → 用同一 pass 的 lane、branch、bandwidth 与时间证据复查

概念辨析
--------

* **SIMD 与 SIMT**：SIMD 是一条指令驱动多个硬件数据槽；SIMT 是多个逻辑线程映射到这种批量硬件执行上的编程抽象。
* **``invocation`` 与执行组**：``invocation`` 拥有自己的输入、局部变量和逻辑结果；执行组决定这些工作项如何共享取指、发射、mask 与等待状态。
* **分支与分支发散**：存在 ``if`` 不等于发生发散；只有同一执行组内的条件结果不一致，才需要按 mask 分路径推进。
* **uniform 分支与像素分支**：uniform 分支在同一批工作中通常结果一致；纹理、坐标或随机数据驱动的像素分支更可能产生组内混杂。
* **branchless 与低成本**：branchless 能稳定控制流，但会让所有 ``lane`` 执行相同计算；当被跳过路径包含昂贵采样时，它可能显著增加带宽和纹理单元压力。
* **early-out 与整体跳过**：少数 ``lane`` 提前退出只会关闭对应 mask；整个执行组都满足退出条件时，后续工作才可能整体省去。涉及 barrier 时还必须先保证控制流合法。
* **occupancy 与有效利用率**：occupancy 表示可驻留并发工作能力；有效利用率表示当前指令有多少 ``lane`` 在做有用工作。高 occupancy 不能抵消严重的分支发散。

本章结论
--------

SIMD/SIMT 的核心是把标量 shader 放回执行组、``lane``、active mask、寄存器和调度器中理解。排查 shader 性能时，应先判断执行组为何等待、条件是否组内一致、分支两侧消耗什么资源，再决定使用统一变体、数据重排、early-out 或 branchless；语法变化只有在同一帧的分支效率、带宽和 pass 时间得到改善时才成立。
