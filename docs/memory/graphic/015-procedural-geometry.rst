第015章：程序化几何
===================

核心知识点
----------

程序生成是一条从描述到运行时资源的生产路径
   输入可以是参数、控制点、规则、随机种子和约束，输出必须落到 mesh、instance、material、bounds、LOD、collision 和导航数据。数据由程序产生不会自动降低渲染成本，最终仍受普通图形管线的 buffer、draw 和 shader 约束。

确定性是缓存、复现和同步的基础
   相同参数、seed、生成器版本和依赖资源应得到相同结果。随机流应按道路、地块、建筑、立面等层级独立派生，避免修改局部模块时连带改变整个世界；缓存 key 必须覆盖所有影响输出的输入和版本。

中间表示比直接生成顶点更可维护
   Road graph、lot polygon、building volume、facade cell 等结构说明生成器认为场景是什么，mesh 只是它们的可见表达。错误优先在结构层定位，才能区分规则失败、约束失败、几何构建失败和渲染绑定失败。

规则与约束承担不同职责
   规则描述对象如何展开和组合，约束规定结果必须满足的边界。Grammar 可生成道路层级、楼层和立面模块；门朝道路、地块不越界、模块尺寸对齐等条件不能交给随机选择覆盖。局部合法不等于全局可解，生成后必须验证。

噪声提供连续变化而非结构正确性
   Perlin 和 Simplex 适合平滑随机场，Worley 适合细胞和距离结构，FBM 用多 octave 组合大轮廓与高频细节。噪声应明确采样空间、范围和用途，适合控制高度、密度、外观和细节，不应破坏道路连通、碰撞边界等硬约束。

Chunk 连接生成、streaming 与缓存
   大场景按空间 chunk 组织请求、任务、资源和生命周期。相邻 chunk 必须使用世界坐标和稳定 seed 派生，确保道路、地形和密度连续；每个 chunk 应记录状态、bounds、生成版本、资源句柄、LOD 和诊断统计。

低频结构与高频变化应分离
   道路、建筑主体和碰撞代理适合生成后长期缓存；颜色、灯光、风摆和局部装饰适合放入 instance data 或材质参数。把高频变化做成 mesh 重建会增加 CPU 任务、主线程提交和 GPU 上传成本。

实例化是重复模块的主要运行时表达
   窗户、阳台、路灯、树木等模块共享少量 mesh，通过 instance transform、module id 和材质变体表达差异。建筑主体和特殊转角可合并为静态 mesh；远景 LOD 可把重复实例烘焙为低频面片或 impostor。

关键路径
--------

程序生成模块进入引擎：

::

   可序列化参数、seed、profile 与生成版本
   → 规则和约束生成中间表示
   → 验证边界、连通性、尺寸和无解状态
   → 从中间表示生成 mesh、instance 与 material data
   → 同源生成 bounds、LOD、collision、navigation 与 occluder
   → 上传或缓存引擎资源
   → renderer、physics、navigation 消费
   → debug overlay 与统计验证结果

噪声进入几何：

::

   确定 object、world、UV 或 chunk 采样空间
   → 用稳定 seed 计算 coherent noise
   → 多 octave 组合并归一化
   → remap 到高度、密度或材质范围
   → 应用结构约束与 clamp
   → 生成中间参数或几何
   → 分别可视化原始噪声、映射值和最终边界

城市 chunk 生成：

::

   道路中心线与 chunk 边界
   → 生成 road graph 和道路 polygon
   → 分割 lot polygon
   → setback 得到 building footprint
   → 按规则与噪声生成 building volume
   → 展开 facade floor 和 module cell
   → 合并主体 mesh 并生成模块 instance
   → 生成 LOD、碰撞、导航和缓存资源
   → 记录 draw、instance、vertex、upload 与生成耗时

概念辨析
--------

* **随机性与确定性**：随机性提供变化；确定性保证同一输入可复现。确定性程序仍可生成看似随机的结果。
* **参数与 seed**：参数定义允许范围和设计意图；seed 决定候选中的具体选择，不能代替结构约束。
* **噪声与 Grammar**：噪声擅长连续数值变化；Grammar 擅长层级、重复和结构展开。城市道路和建筑通常需要两者组合。
* **规则与约束**：规则产生候选结构；约束过滤、修正或拒绝不合法结果。生成成功不代表约束已经满足。
* **中间表示与 mesh**：中间表示保存道路、地块和建筑语义；mesh 保存可渲染顶点和索引。直接从 mesh 反推结构通常成本更高。
* **生成与烘焙**：运行时生成保留变化能力并消耗任务和上传预算；烘焙把结果冻结为普通资产，加载更稳定但失去部分动态性。
* **Mesh 合并与实例化**：合并适合唯一连续结构并减少 draw；实例化适合大量重复模块并减少几何存储。二者可在同一 chunk 中同时使用。
* **Render mesh 与 collision data**：两者可来自同一结构来源，但精度和生命周期不同，不能用可见 LOD 直接替代稳定碰撞表示。

本章结论
--------

程序化几何的质量由可控输入、可解释中间表示、完整资源输出和可预算运行时路径共同决定。应先保证 seed、版本与约束可复现，再用噪声和 Grammar 构造结构，通过 chunk、缓存和实例化接入引擎，最后同时验证生成耗时、资源上传、draw 组织、LOD 与碰撞；程序生成的价值来自规模化生产，而不是绕开普通渲染工程规则。
