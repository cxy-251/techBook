第001章：GPU 硬件基础
======================

核心知识点
----------

GPU 是吞吐型处理器
   GPU 通过大量并行 ``invocation`` 处理相似数据，目标是在单位时间内完成更多顶点、像素、采样或计算任务。它依靠批量执行和大量在途工作隐藏单次操作延迟，不能用 CPU 的单任务低延迟模型评价。

计算单元由多类资源协作
   执行 ``lane`` 完成算术与逻辑指令，寄存器保存线程临时状态，调度器选择可运行的执行组，本地共享存储支持组内复用，纹理、深度、混合、光追和矩阵单元处理专门路径。ALU 空闲不代表 GPU 空闲，瓶颈可能位于纹理、混合或内存系统。

延迟隐藏依赖可驻留工作量
   当一个 ``warp``、``wavefront`` 或 ``simdgroup`` 等待纹理或缓冲区数据时，调度器切换到另一个就绪执行组。寄存器占用、共享存储占用和线程组织共同限制可驻留执行组数量；可切换工作不足时，内存延迟会直接暴露为执行停顿。

硬件能力必须按共同维度比较
   NVIDIA、AMD 与 Apple 的术语和实现不同，比较时应统一观察执行组宽度、计算单元、内存形态、专用单元、功耗边界、工具证据和 API 暴露能力。厂商名称、核心数量或显存容量都不能单独预测某个 ``pass`` 的表现。

独立显存与统一内存都受资源路径约束
   独立显存平台通常需要明确上传、拷贝和设备本地资源路径；统一内存平台减少部分显式拷贝，但 CPU 与 GPU 仍共享带宽，并受缓存可见性、同步、资源状态和功耗限制。统一内存不等于零成本访问。

性能症状要映射到硬件资源
   工作量随顶点或实例数量增长，优先检查顶点处理、实例数据和缓冲区读取；随屏幕覆盖面积增长，优先检查片元、透明混合和渲染目标带宽；随采样数量增长，优先检查纹理单元、缓存和内存带宽；随绘制数量增长，优先检查 CPU 提交与状态切换。

设备能力决定渲染路径
   引擎应把 ``adapter``、``device``、feature bits、limits、format support 和 fallback path 收敛为稳定的能力描述。能力查询不仅决定某项功能能否开启，还决定资源格式、批量规模、管线变体和低能力设备上的正确替代方案。

关键路径
--------

一次绘制进入 GPU：

::

   CPU 构建 draw 或 dispatch
   → 命令进入队列
   → GPU 前端分发顶点、片元或计算工作
   → 执行组占用计算单元并读取 buffer、texture
   → 专用单元完成采样、深度、混合或其它固定功能
   → 结果写入 render target 或 storage buffer
   → 完成信号与呈现结果返回

设备能力选择渲染路径：

::

   枚举 adapter
   → 创建逻辑 device
   → 查询 features、limits 与 format support
   → 生成统一的 GPU capability profile
   → 选择资源格式、pipeline 变体和质量等级
   → 能力不足时进入保持正确性的 fallback path

概念辨析
--------

* **吞吐量与单任务延迟**：吞吐量关注一段时间内完成多少并行工作；单任务延迟关注一个任务多久返回。GPU 通常通过大量在途线程覆盖等待，而不是让每个线程都立即完成。
* **``lane``、``invocation`` 与执行组**：``lane`` 是硬件执行槽；``invocation`` 是 shader 中的逻辑工作项；执行组把多个工作项绑定到同一指令流和调度状态上。
* **寄存器与共享存储**：寄存器保存单个线程的临时值；shared、LDS 或 threadgroup memory 服务同一工作组内的数据交换与复用。两者占用过高都会降低可并行驻留工作量。
* **统一内存与免费共享**：统一内存表示 CPU 与 GPU 共享物理内存池；数据仍要经过各自缓存、同步和带宽路径，读写方频繁切换仍可能产生等待。
* **硬件支持与 API 可用**：底层 GPU 具备某项能力，不代表当前驱动、操作系统、浏览器或图形 API 一定暴露；引擎只能依赖实际查询到的 feature 与 limit。
* **GPU busy 与计算受限**：GPU busy 只说明 GPU 在处理或等待工作；只有结合 ALU、纹理、带宽、混合、同步等证据，才能判断真正受限资源。

本章结论
--------

GPU 硬件应被理解为执行组、计算单元、寄存器、本地存储、缓存、外部内存和专用管线组成的可观察系统。阅读渲染代码或排查性能时，先把 ``pass`` 的工作量映射到具体硬件资源，再检查可驻留工作、数据路径和设备能力；任何优化都应由同一场景下的阶段耗时与资源证据验证。
