学习内容架构
============

``techBook`` 将技术学习拆成路径、单元、证据、评估和状态五类内容。它们都服务于直接阅读，不依赖构建系统。

学习路径
--------

track 定义目标读者、入口能力、最终能力、阶段顺序和范围。路径不会在开始时预先冻结全部章节。

学习单元
--------

unit 负责一次明确的能力变化。读者需要经历预测、观察、逐步推理、条件变化、误解修正和迁移任务。

证据
----

证据直接写在当前 RST 中，可以是：

* 示例代码；
* 命令与真实输出；
* 编译错误；
* 请求、日志或进程状态；
* 固定版本源码片段；
* 图示、界面现象或 trace。

证据形式由主题与学习阶段决定。源码级内容需要在当前文件中标明仓库、release、commit、平台和工具链。

评估
----

评估不只检查术语记忆。问题必须来自 unit 中的现象，答案必须给出推理和错误模型分析，最终任务检查
读者能否把理解迁移到变化场景。

状态
----

少量 TOML 记录学习路径和 unit 的当前状态。状态文件负责跨对话接续，不替代 RST 内容，也不能把
“文件已经写完”直接等同于“读者已经学会”。

直接阅读
--------

面向读者的内容位于 ``docs/tracks/``。文件使用普通 RST 相对链接互相连接，不使用 Sphinx、toctree、
自动检查、HTML 构建或发布系统。
