学习系统架构
============

``techBook`` 将技术学习拆成路径、单元、证据、评估和发布五类资产。

学习路径
--------

track 定义目标读者、入口能力、最终能力、阶段顺序和范围。路径不会在开始时预先冻结全部章节。

学习单元
--------

unit 负责一次明确的能力变化。读者需要经历预测、观察、逐步推理、条件变化、误解修正和迁移任务。

证据
----

证据位于 ``labs/`` 或来源记录中。它可以是运行结果、错误信息、网络请求、日志、编译产物、
固定源码或 trace。证据形式由主题与学习阶段决定。

评估
----

评估不只检查术语记忆。问题必须来自 unit 中的现象，答案必须给出推理和错误模型分析，最终任务
检查读者能否把理解迁移到一个变化场景。

RST 内容
--------

面向读者的路径位于 ``docs/tracks/``。需要复用的代码通过 ``literalinclude`` 引用实际 lab 文件。

验证
----

GitHub Actions 与本地命令检查 learning model、RST、Python 工具、已有 lab 测试和 Sphinx 构建。
自动验证不能替代实际阅读检查。

发布
----

私有仓库不发布 Pages。稳定 track 和 unit 由 ``tools/export_release.py`` 按白名单生成公共快照。
