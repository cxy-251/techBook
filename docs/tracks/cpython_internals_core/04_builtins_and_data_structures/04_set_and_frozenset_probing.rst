=============================================================================

.. note:: 前置背景与上下文承接

   在 Python 的内建容器家族中，**集合（``set`` 与 ``frozenset``）** 是唯一专为极速成员判定（Membership Testing）、元素去重与集合代数运算（交、并、差、对称差）而设计的无序容器。与字典不同，集合仅需存储键（Key）而无关联值（Value）。本章作为**模块四【核心内建数据结构实现】的收官之作**，将深入 CPython 核心源码文件 ``Objects/setobject.c``、``Include/cpython/setobject.h`` 以及 ``Include/internal/pycore_setobject.h``，自底向上深度剖析集合的单层开放寻址哈希表、内联小表（Small Table）零堆分配优化、基于双重伪随机递推的扰动探查（Perturbation Probing）数学模型、墓碑清理（Tombstone Purging）与自适应扩缩容机制，以及不可变 ``frozenset`` 的无序对称哈希算法与 Free-Threading 并发安全体系。

-----------------------------------------------------------------------------
1. PySetObject 物理内存拓扑与内联小表优化
-----------------------------------------------------------------------------

setentry 紧凑条目与 PySetObject 结构
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

在 ``Include/cpython/setobject.h`` 与 ``Objects/setobject.c`` 中，集合的基础槽位定义为 16 字节的紧凑单元：

.. code-block:: c

   typedef struct {
       PyObject *key;                   /* 存储元素的强引用指针 (NULL 或 dummy) */
       Py_hash_t hash;                  /* 缓存的 64 位元素哈希值 (避免重复计算) */
   } setentry;

   #define PySet_MINSIZE 8

   typedef struct {
       PyObject_HEAD
       Py_ssize_t fill;                 /* 活跃元素数 (used) + 伪删除墓碑数 (dummy) */
       Py_ssize_t used;                 /* 实际有效活跃元素个数 len(set) */
       Py_ssize_t mask;                 /* 当前哈希表掩码: table_size - 1 (必为 2^k - 1) */
       setentry *table;                 /* 指向当前活跃哈希表 (指向 smalltable 或堆内存) */
       Py_hash_t hash;                  /* 仅 frozenset 使用: 缓存的集合全局哈希值 */
       Py_ssize_t finger;               /* 供 pop() 快速定位下一个非空槽位的游标 */
       setentry smalltable[PySet_MINSIZE]; /* 内联小表: 预分配 8 个槽位 (128 字节) */
       PyObject *weakreflist;           /* 弱引用链表头 */
   } PySetObject;

.. code-block:: text

   +-------------------------------------------------------------------------+
   |                     PySetObject 物理结构与内联小表布局                  |
   +=========================================================================+
   | PyObject_HEAD (16 字节)                                                 |
   | ├── fill (8 字节): Active + Dummy 槽位总数                              |
   | ├── used (8 字节): 有效元素个数 len(set)                                |
   | ├── mask (8 字节): 槽位数 - 1 (如 7, 15, 31...)                         |
   | ├── table (8 字节指针) ───┐                                             |
   | ├── hash (8 字节): frozenset 哈希缓存                                   |
   | └── finger (8 字节): pop 游标                                           |
   +───────────────────────────┼─────────────────────────────────────────────+
                               │ (初始状态: 直接指向内嵌数组)
                               ▼
   +-------------------------------------------------------------------------+
   | smalltable[8] (内联连续 128 字节, 0 额外堆分配!)                        |
   | ├── [0]: { key=PyObject*, hash=0x1a2b... }                              |
   | ├── [1]: { key=NULL,      hash=0 } (Unused 空槽)                        |
   | ├── [2]: { key=dummy,     hash=0 } (Dummy 墓碑)                         |
   | └── ...                                                                 |
   | └── [7]: { key=NULL,      hash=0 }                                      |
   +-------------------------------------------------------------------------+

Small Table（内联小表）零堆分配优化
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

- **空间极致压缩**：对于绝大多数包含 $\le 5$ 个元素的小集合，创建集合时直接将 ``table`` 指针指向结构体内部的 ``smalltable``。
- **性能红利**：在创建小集合时，解释器仅需向内存分配器申请单块 ``sizeof(PySetObject)`` 内存，**完全不需要额外的二级堆内存分配**，使小集合的构造与析构开销降至极限。

2. 开放寻址三态状态机与扰动探查数学模型
-----------------------------------------------------------------------------

与字典采用稀疏索引表（``dk_indices``）加密集数据表（``dk_entries``）的双层架构不同，集合仅存储 Key。由于单条目仅 16 字节，采用单一扁平连续数组的**开放寻址法（Open Addressing）**能够提供最高的 CPU 缓存命中率。

槽位三态转换状态机
~~~~~~~~~~~~~~~~~~

每个 ``setentry`` 槽位在运行时处于以下三种严格状态之一：

.. code-block:: text

   +-------------------------------------------------------------------------+
   |                      集合槽位生命周期三态状态机                         |
   +=========================================================================+
   | 1. Unused (空闲未用态: entry->key == NULL)                              |
   | └─ 该槽位从未存放过数据。探查链在此合法截断, 判定元素不存在。             |
   +-------------------------------------------------------------------------+
                                     │ (插入新元素 key)
                                     ▼
   +-------------------------------------------------------------------------+
   | 2. Active (活跃占用态: entry->key != NULL && entry->key != dummy)       |
   | └─ 存储有效对象强引用指针与哈希值。                                     |
   +-------------------------------------------------------------------------+
                                     │ (删除元素: discard / remove)
                                     ▼
   +-------------------------------------------------------------------------+
   | 3. Dummy (伪删除墓碑态: entry->key == _PySet_Dummy)                     |
   | └─ 占位标记。探查链遇到 Dummy 不可中断, 必须继续向下探测后续冲突链!      |
   +-------------------------------------------------------------------------+

双重扰动探查递推公式（Perturbation Probing）
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

当发生哈希冲突时，CPython 在 ``Objects/setobject.c`` 的 ``set_lookkey()`` 中采用了非线性双重扰动递推算法：

$$i_0 = 	ext{hash} \ \& \ 	ext{mask}$$

$$i_{k+1} = \left( 5 	imes i_k + 1 + 	ext{perturb}_k \right) \ \& \ 	ext{mask}$$

$$	ext{perturb}_{k+1} = 	ext{perturb}_k \gg 5$$

.. code-block:: text

   +-------------------------------------------------------------------------+
   |                    扰动探查算法的数学与硬件级保证                       |
   +=========================================================================+
   | 1. 满周期遍历定理: 模乘同余递推 (5*i + 1) mod 2^k 保证在 2^k 步内能够   |
   |    精确遍历 [0, 2^k - 1] 空间中的每一个整数, 绝无死循环或漏槽风险;       |
   +-------------------------------------------------------------------------+
   | 2. 高位哈希熵注入: 每次迭代将 64 位哈希的高位熵右移 5 位注入低位, 迅速   |
   |    打散具有相同低位哈希的连续整数键, 消除初级集群（Primary Clustering）;|
   +-------------------------------------------------------------------------+
   | 3. 墓碑复用优化: 在探查过程中若遇到首个 Dummy 槽位, 记录 freeslot 指针;  |
   |    若最终确认 Key 不存在, 直接将新数据覆写在 freeslot 上, 抑制空洞扩散。|
   +-------------------------------------------------------------------------+

3. 集合扩容、缩容与墓碑清理机制（Set Resizing）
-----------------------------------------------------------------------------

$60\%$ 装载因子上限与扩容时机
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

为了维持 $O(1)$ 的常数级查找性能，集合将表装载因子的安全阈值严格限制在 **$3/5$（$60\%$）**：

$$	ext{当 } 	ext{fill} \ge \frac{3}{5} 	imes (	ext{mask} + 1) \quad (	ext{即 } 	ext{fill} 	imes 5 \ge 	ext{mask} 	imes 3) 	ext{ 时，强制触发扩容}$$

分段阶梯增长策略
~~~~~~~~~~~~~~~~

在 ``set_table_resize()`` 中，目标容量根据当前实际有效元素数（``used``）动态计算：

$$	ext{newsize} = \begin{cases} 	ext{used} 	imes 4 & (	ext{used} \le 50,000) \ 	ext{used} 	imes 2 & (	ext{used} > 50,000) \end{cases}$$

- **小中型集合（$\le 5$ 万元素）**：采用 $4	imes$ 激进增长，大幅减少内存重新分配次数；
- **大型集合（$> 5$ 万元素）**：平滑退化为 $2	imes$ 增长，严格遏制大内存分配时的物理碎片与浪费；
- 容量随后向上圆整为最接近的 $2^k$ 幂次。

墓碑清理（Tombstone Purging）与自适应缩容
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

当集合频繁执行删除操作时，哈希表中会充斥着大量的 ``Dummy`` 墓碑（``fill`` 极大而 ``used`` 很小），导致查找链变长。

每次触发 ``set_table_resize()`` 时：
1. 分配一个全新的目标容量哈希表；
2. 遍历旧表，**彻底忽略所有 ``Dummy`` 槽位**，仅将真正有效的 ``Active`` 元素按新表尺寸重新计算哈希索引并插入；
3. 如果有效元素数大幅缩水，新表的容量甚至会**缩小至小于旧表（缩容）**，若缩容后尺寸 $\le 8$，则重新将数据回填至 ``smalltable`` 并释放堆内存，实现完美的内存弹性自愈。

4. frozenset 不可变集合与对称无序哈希算法
-----------------------------------------------------------------------------

``frozenset`` 是 Python 提供的不可变集合对象。由于其不可变性，它可以作为字典的键或嵌套在其他集合中。

对称无序哈希算法物理模型
~~~~~~~~~~~~~~~~~~~~~~~~

因为集合元素是无序的（``{1, 2, 3} == {3, 2, 1}``），计算集合全局哈希值时，必须确保**运算结果与遍历顺序完全无关（Symmetric & Order-Independent）**。

CPython 在 ``Objects/setobject.c`` 的 ``frozenset_hash()`` 中实现了精妙的非线性置换对称哈希：

.. code-block:: c

   static Py_hash_t
   frozenset_hash(PyObject *self)
   {
       PySetObject *so = (PySetObject *)self;
       if (so->hash != -1)
           return so->hash; /* 直接读取缓存 */

       Py_uhash_t h, hash = 1927868237UL;
       setentry *entry = so->table;
       Py_ssize_t mask = so->mask;

       for (Py_ssize_t i = 0; i <= mask; i++) {
           PyObject *key = entry[i].key;
           if (key != NULL && key != _PySet_Dummy) {
               Py_hash_t value_hash = entry[i].hash;
               /* 非线性单向置换混淆函数 */
               h = (Py_uhash_t)value_hash;
               h = ((h ^ 89869747UL) ^ (h << 16)) * 3644798167UL;
               hash ^= h; /* 对称异或累加: 满足交换律与结合律 */
           }
       }

       /* 结合元素个数打散与最终雪崩处理 */
       hash ^= ((Py_uhash_t)so->used + 1) * 69069U;
       hash = hash * 69069U + 907133923UL;
       if (hash == -1) hash = 590923713UL; /* 避免保留值 -1 */

       so->hash = hash; /* 缓存计算结果 */
       return hash;
   }

- **对称异或累加（``hash ^= h``）**：利用异或的数学交换律与结合律，保证不同顺序遍历同一集合必产生绝对一致的中间态；
- **非线性混淆打散**：防止形如 ``hash({a, b})`` 容易被构造出异或抵消（Cancellation）的哈希碰撞攻击。

5. Python 3.13+ Free-Threading 并发安全与集合代数加速
-----------------------------------------------------------------------------

临界区互斥（Critical Sections）
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

在 PEP 703 Free-Threading 环境下，集合所有修改操作（``add``, ``discard``, ``pop``, ``update``）均被包裹在 ``Py_BEGIN_CRITICAL_SECTION(so)`` 临界区锁中，保证在无 GIL 状态下多线程并发扩容与写入的数据一致性。

集合代数运算（Set Algebra）的 C 级位运算优化
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

对于 ``set.intersection``（交集）、``set.union``（并集）与 ``set.difference``（差集）：
1. **尺寸自适应反转（Size-Adaptive Inversion）**：计算交集时，始终优先遍历较小的集合，并在较大集合中执行哈希查找（时间复杂度严格限制在 $O(\min(|A|, |B|))$）；
2. **同类快速路径（Fast Path for Exact Sets）**：当操作数均为原生集合时，绕过通用 Python 迭代协议，直接在 C 语言层解引用底层 ``setentry`` 数组进行指针级批量复制与哈希探测，计算吞吐提升数十倍。
