=============================================================================
偏向引用计数 Biased Reference Counting、线程私有 vs 共享计数器
=============================================================================

.. note:: 前置背景与上下文承接
   在前一章中，我们全景解构了 CPython 3.13+ PEP 703 Free-Threading 的四大架构支柱（BRC、Mimalloc、Critical Section 与 QSBR）。其中，解决多核并发下引用计数原子争用（Atomic Contention）与缓存行颠簸（Cache-Line Bouncing）的最核心发明，正是**偏向引用计数（Biased Reference Counting, BRC）**。
   
   在传统的非自由线程构建中，所有对象的引用计数（``ob_refcnt``）都是单一标量，且由全局 GIL 保护；若简单将单线程下的自增/自减改为硬件原子指令（``LOCK XADD``），单线程执行性能将直接暴跌 30% 以上。本章将深入 CPython 核心源码文件 ``Include/internal/pycore_object.h``、``Include/internal/pycore_brc.h`` 以及 ``Python/brc.c``，深度剖析 BRC 的微观对象头拓扑、线程私有本地计数（``ob_ref_local``）与原子共享计数（``ob_ref_shared``）的位域编码、拥有者线程零原子指令极速路径、异构线程无锁入队与双向合并状态机，以及针对全局高频共享对象的延迟引用计数（Deferred Reference Counting）机制。

-----------------------------------------------------------------------------
1. BRC 核心设计动机与硬件缓存拓扑挑战
-----------------------------------------------------------------------------

为什么全局原子引用计数不可行？
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

在现代多核 CPU（如 x86-64 或 ARM64）架构中，每个 CPU 核心拥有独立的 L1/L2 缓存，并通过 **MESI / MOESI 缓存一致性协议（Cache Coherence Protocol）** 保持物理内存视图一致：
1. **缓存行失效风暴（Cache-Line Invalidation Storm）**：
   当两个核心并发对同一个 64 字节缓存行内的变量执行原子写操作（如 ``Atomic Incref``）时，总线仲裁将强制将其他核心对应的 L1/L2 缓存行置为 Invalid（失效态），引发昂贵的跨核心总线嗅探与内存回写；
2. **局部变量的私有性**：
   在真实的 Python 应用程序中，**超过 85%~90% 的对象生命周期局限在创建它的单个线程内部**（如函数内部临时变量、循环迭代器、字符串拼接中间态）。如果为这些完全不发生跨线程共享的私有对象支付原子指令开销，是对 CPU 算力的巨大浪费。

BRC 的核心哲学：谁创建，偏向谁
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

偏向引用计数（Biased Reference Counting）的核心思想在于：
- 每个对象在分配时默认**偏向（Biased）**创建它的线程（拥有者线程，Owner Thread）；
- 拥有者线程在修改自身偏向的对象时，享有**零原子指令、零内存屏障的普通寄存器操作极速路径**；
- 只有当对象逃逸至其他线程（Foreign/Shared Thread）时，才切换为原子累加或跨线程消息队列延迟合并。

2. BRC 对象头微观物理拓扑与位域编码
-----------------------------------------------------------------------------

在 ``Include/internal/pycore_object.h`` 中，自由线程模式（``Py_GIL_DISABLED``）下的 ``PyObject`` 物理布局如下：

.. code-block:: c

   struct _object {
       union {
           uintptr_t ob_tid;            /* 拥有者线程 ID (Thread ID, 指向 _PyThreadState) */
           uintptr_t ob_flags;          /* 静态分配 / 不朽对象特殊标记 */
       };
       uint32_t ob_ref_local;           /* 拥有者私有的 32 位本地引用计数 (无锁) */
       uint32_t ob_gc_bits;             /* GC 追踪与延迟释放标志位 */
       PyMutex ob_mutex;                /* 1 字节对象级轻量级互斥锁 */
       Py_ssize_t ob_ref_shared;        /* 64 位跨线程共享引用计数与状态掩码 */
       PyTypeObject *ob_type;           /* 类型对象指针 */
   };

.. code-block:: text

   +-------------------------------------------------------------------------+
   |                     PyObject (Free-Threading) 32B 内存拓扑              |
   +=========================================================================+
   | [00-07] ob_tid: 拥有者线程 ID (_Py_ThreadId())                          |
   | [08-11] ob_ref_local: 本地引用计数 (普通汇编加减, 0 原子开销)           |
   | [12-12] ob_gc_bits: GC 分代状态位                                       |
   | [13-13] ob_mutex: 1 字节 Parking-Lot 互斥锁                             |
   | [14-15] 内存对齐填充 (2 字节)                                           |
   | [16-23] ob_ref_shared: 共享引用计数 (高 62 位: 计数, 低 2 位: 状态标志)  |
   | [24-31] ob_type: 类型元指针                                             |
   +-------------------------------------------------------------------------+

`ob_ref_shared` 低 2 位状态状态机
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

在 64 位系统上，``ob_ref_shared`` 将数值左移 2 位（``_Py_REF_SHARED_SHIFT = 2``），将最低 2 位用作并发控制标志位（``_Py_REF_SHARED_FLAG_MASK = 0x3``）：

.. code-block:: text

   +-------------------------------------------------------------------------+
   |                    ob_ref_shared 最低 2 位标志位定义                    |
   +====================+=======+============================================+
   | 状态常量           | 二进制| 语义说明                                   |
   +--------------------+-------+--------------------------------------------+
   | _Py_REF_NORMAL     | 00    | 普通共享态: 存在跨线程引用, 处于常规生命周期|
   +--------------------+-------+--------------------------------------------+
   | _Py_REF_QUEUED     | 01    | 排队态: 已推入拥有者线程的 BRC 延迟回收队列|
   +--------------------+-------+--------------------------------------------+
   | _Py_REF_MERGED     | 10    | 已合并态: 本地与共享计数已统一, 处于合并视界|
   +--------------------+-------+--------------------------------------------+
   | _Py_REF_MAYBE_WEAK | 11    | 弱引用保护态: 乐观标记可能存在弱引用关联   |
   +--------------------+-------+--------------------------------------------+

3. 本地拥有者极速路径（Local Fast-Path）
-----------------------------------------------------------------------------

本地快速自增（`_Py_TryIncrefFast`）
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

当拥有者线程执行 ``Py_INCREF(op)`` 时：

.. code-block:: c

   static inline int
   _Py_TryIncrefFast(PyObject *op)
   {
       uint32_t local = _Py_atomic_load_uint32_relaxed(&op->ob_ref_local);
       local += 1;
       if (local == 0) {
           /* 溢出回绕为 0 表示不朽对象 (Immortal) */
           return 1;
       }
       if (_Py_IsOwnedByCurrentThread(op)) {
           /* 拥有者线程判定命中: 纯单周期单目指令直接写入! */
           _Py_atomic_store_uint32_relaxed(&op->ob_ref_local, local);
           return 1;
       }
       return 0;
   }

- **编译后底层汇编**（x86-64）：

.. code-block:: nasm

   mov    eax, DWORD PTR [rdi+8]    ; 加载 ob_ref_local
   inc    eax                       ; 本地寄存器递增
   mov    DWORD PTR [rdi+8], eax    ; 单周期写回 (无 LOCK 前缀!)

完全不需要触发昂贵的多核缓存行锁定，实现了与单线程 CPython 完全相同的机器级执行效率！

本地快速自减与析构判定
~~~~~~~~~~~~~~~~~~~~~~

当拥有者线程执行 ``Py_DECREF(op)`` 时：
1. 本地计数递减：``op->ob_ref_local--``；
2. **若 ``ob_ref_local > 0``**：操作瞬间完成，立即返回；
3. **若 ``ob_ref_local == 0``**：
   - 检查 ``ob_ref_shared`` 是否为 0；
   - **若 ``ob_ref_shared == 0``**：说明既无本地引用也无任何跨线程引用，直接调用 ``_Py_Dealloc(op)`` 瞬时就地析构并回收内存；
   - **若 ``ob_ref_shared != 0``**：说明对象虽在本地解引用完毕，但在其他线程中仍存活，进入慢速合并流。

4. 跨线程共享引用与 BRC 消息队列（Shared Slow-Path）
-----------------------------------------------------------------------------

跨线程自增（`_Py_TryIncRefShared`）
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

当非拥有者线程获得对象指针并尝试自增引用时：
- 该线程严禁直接修改 ``ob_ref_local``（避免写数据竞争）；
- 通过原子 CAS 循环递增 ``ob_ref_shared`` 的高 62 位：

.. code-block:: c

   static inline int
   _Py_TryIncRefShared(PyObject *op)
   {
       Py_ssize_t shared = _Py_atomic_load_ssize_relaxed(&op->ob_ref_shared);
       for (;;) {
           if (shared == 0 || shared == _Py_REF_MERGED) {
               return 0; /* 对象已处于析构边缘, 放弃自增 */
           }
           if (_Py_atomic_compare_exchange_ssize(
                   &op->ob_ref_shared,
                   &shared,
                   shared + (1 << _Py_REF_SHARED_SHIFT))) {
               return 1;
           }
       }
   }

跨线程自减与 BRC 队列延迟投递
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

当非拥有者线程释放其持有的共享引用时：
1. 异构线程执行原子自减 ``op->ob_ref_shared -= (1 << 2)``；
2. 如果减完后发现该共享引用已归零，且需要确认拥有者线程是否已经释放了本地引用：
   - 异构线程**绝对不能直接调用 ``_Py_Dealloc(op)``**（因为对象的释放必须在其所属的 Mimalloc Thread-Local Heap 所在线程中执行，否则会破坏内存池局部性）；
   - 异构线程将该对象推入拥有者线程的 **BRC 延迟回收消息队列（BRC Queue）**，并将对象标志位原子置为 ``_Py_REF_QUEUED``。

.. code-block:: text

   +-------------------------------------------------------------------------+
   |                     跨线程 BRC 队列异步投递拓扑                         |
   +=========================================================================+
   | 【异构线程 Foreign Thread】                                             |
   | ├── 释放跨线程引用: atomic_sub(&op->ob_ref_shared, 4)                   |
   | └── 发现引用归零 ──► 推入拥有者线程的 Lock-Free BRC Queue                |
   +───────────────────────────────────┬─────────────────────────────────────+
                                       │ (无锁单向链表投递)
                                       ▼
   +-------------------------------------------------------------------------+
   | 【拥有者线程 Owner Thread】                                             |
   | ├── 解释器主循环在循环回边检测到 _PY_EVAL_EXPLICIT_MERGE_BIT            |
   | ├── 调用 _Py_brc_merge_refcounts() 批量排空 BRC Queue                    |
   | ├── 合并 ob_ref_local 与 ob_ref_shared 真实总和                          |
   | └── 若总计数为 0 ──► 在拥有者本地堆安全调用 _Py_Dealloc(op)!             |
   +-------------------------------------------------------------------------+

-----------------------------------------------------------------------------
5. 延迟引用计数（Deferred Reference Counting）
-----------------------------------------------------------------------------

对于极其高频被全量线程并发读取的不可变顶级结构（例如函数字节码对象 ``PyCodeObject``、全局内置类型 ``PyTypeObject`` 以及全局常量）：
- 如果每次函数调用或类型检查都执行一次 BRC 原子增减，即使有 BRC，依然会在高并发多核下产生巨大的 CPU 缓存行争用；
- CPython 引入了**延迟引用计数（Deferred Reference Counting）**：
  - 在对象初始化时，向 ``ob_ref_shared`` 预注入超大偏移量 ``_Py_REF_DEFERRED = PY_SSIZE_T_MAX / 8``；
  - 虚拟机的执行栈帧与调用链直接**借用（Borrow）**该引用而完全不再调用 Incref / Decref；
  - 这类对象的生命周期彻底脱离常规引用计数，全权交由全局 Stop-the-World 分代垃圾回收器（STW GC）统一安全回收。
