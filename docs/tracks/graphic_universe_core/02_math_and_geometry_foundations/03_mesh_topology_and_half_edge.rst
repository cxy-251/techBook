========================================================================
Chapter 8: 多边形网格拓扑数据结构：半边结构与 GPU 缓冲布局
========================================================================

.. note:: 前置背景与认知承接
   前两章系统推导了顶点的全局仿射/射影空间变换与局部表面的微积分微分几何。然而，离散三维模型并非孤立的点集，而是由大量多边形面片构成的复杂几何网格。网格的拓扑表达直接决定了几何编辑、曲面细分、网格简化（LOD）的算法复杂度，以及 GPU 图元装配与光栅化的内存访问吞吐。本章将解构 2-流形网格的拓扑学定义、半边数据结构（Half-Edge Mesh）的指针拓扑与常数级邻域循环遍历，并深入面向 GPU 硬件吞吐的顶点缓冲区布局（交错缓冲 vs 分流缓冲）优化模型。

------------------------------------------------------------------------
8.1 几何网格与拓扑流形：2-流形 (2-Manifold) 判定法则
------------------------------------------------------------------------

在多边形网格处理中，必须严格区分**几何属性（Geometry）**与**拓扑关系（Topology）**：

- **几何属性**：顶点的物理空间坐标 $[x, y, z]^T$、法线向量、切线向量与纹理坐标等度量信息；
- **拓扑关系**：顶点、边、多边形面之间的连通性、邻接性与包含关系，与具体的空间度量坐标完全无关。

2-流形 (2-Manifold) 的数学定义与物理意义
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

在拓扑学中，一个二维曲面被称为 **2-流形（2-Manifold）**，当且仅当曲面上任意一点的充分小局部邻域，在拓扑上同胚（Homeomorphic）于欧几里得平面上的一个开圆盘（Open Disk）；若允许存在边界，则边界点的局部邻域同胚于一个半圆盘（Half-Disk）。

在离散多边形三角网格中，满足 2-流形必须严格符合以下两项充要条件：

1. **边的流形约束**：网格中的任意一条物理边，**最多只能被两个多边形面片所共享**（处于内部时被恰好 2 个面共享，处于开边界时被恰好 1 个面共享）。
2. **顶点的流形约束**：围绕任意顶点的所有相邻三角形面，能够展开形成一个单一、连续闭合的扇形（Fan）或带状环（Ring）。

.. code-block:: text

   +-------------------------------------------------------------------------+
   |                       流形网格 vs 典型非流形奇异几何                    |
   +-------------------------------------------------------------------------+

   [ 正常流形网格 ]             [ 奇异 1: 非流形边 (Non-manifold Edge) ]
      /\    /\                     / \    / \
     /  \  /  \                   /   \  /   \
    /____\/____\                 /_____\/_____\   <-- 单条边被 3 个面共享 (T-Junction)
    \    /\    /                       / \
     \  /  \  /                       /   \
      \/____\/                       /_____\

   [ 奇异 2: 非流形顶点 (Hourglass) ]     [ 奇异 3: 面法线朝向不一致 ]
          /\                                 /\ (法线向外)      /\ (法线向内!)
         /  \                               /  \              /  \
        /____\                             /____\            /____\
        \    /   <-- 两个锥体仅共用
         \  /        单个中心顶点
          \/

非流形网格会导致绝大部分高级几何算法（如 Catmull-Clark 曲面细分、QEM 边折叠简化、布尔求交与阴影体积生成）在遍历拓扑时陷入死循环或内存越界，因此工业级几何处理管线必须在预处理阶段强制修复或剔除非流形几何。

8.2 经典网格表示法对比：Face-Vertex vs 翼边 vs 半边结构
------------------------------------------------------------------------

为了在内存中表达网格拓扑，图形学演进出了三种核心数据结构：

.. list-table:: 经典多边形网格拓扑数据结构特征对比
   :widths: 18 20 32 30
   :header-rows: 1
   :class: tight-table

   * - 拓扑数据结构
     - 内存开销
     - 邻域查询算法复杂度
     - 典型应用场景与局限
   * - 面-顶点列表 (Face-Vertex List)
     - 极低 (仅顶点数组与索引数组)
     - 极差 (查询顶点的相邻面需 $O(F)$ 全网格遍历)
     - **GPU 渲染提交标准格式**；不支持高效拓扑动态编辑
   * - 翼边结构 (Winged-Edge)
     - 中等 (以无向物理边为核心实体)
     - 良好 (邻域查询需多次条件分支判断方向)
     - 早期 CAD 实体建模；边的无向性导致遍历逻辑复杂
   * - **半边数据结构 (Half-Edge Mesh)**
     - 适中 (每条物理边拆为两条有向半边)
     - **极佳 (所有一阶局部邻域查询均为 $O(1)$ 常数级)**
     - **几何算法事实标准** (细分、简化、参数化)

半边数据结构 (Half-Edge / DCEL) 的核心指针模型
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

半边数据结构将每条无向物理边解构为两条方向相反、互相绑定的**有向半边（Directed Half-Edges）**。整个网格由 4 个互指的结构体紧密协作：

.. code-block:: text

   +-------------------------------------------------------------------------+
   |                       半边数据结构互指指针拓扑图                        |
   +-------------------------------------------------------------------------+

              Vertex: v_target
                     ^
                     |
            +--------+--------+
            |                 |
     he_next|                 | he_twin (对偶半边, 属于相邻面)
            |                 v
       +----+-----------------+----+
       |          Face: f          |
       |                           |
       +---------------------------+
                     ^
                     | he_prev
                     |
              Vertex: v_origin

1. **`HalfEdge` 结构体**（拓扑中枢）：
   - `target`: 指向该半边所指向的终点顶点 `Vertex*`；
   - `face`: 指向该半边左侧所属的多边形面片 `Face*`；
   - `next`: 指向同属于当前面片的下一条顺时针/逆时针半边 `HalfEdge*`；
   - `prev`: 指向同属于当前面片的上一条半边 `HalfEdge*`；
   - `twin`: 指向同一物理边上、方向相反且属于相邻面片的对偶半边 `HalfEdge*`。
2. **`Vertex` 结构体**：包含坐标 `position`，以及指向以该顶点为起点的任意一条出射半边 `halfedge`。
3. **`Face` 结构体**：包含面法线等属性，以及指向包围该面片的任意一条边界半边 `halfedge`。

8.3 半边数据结构的高效邻域遍历算法实现
------------------------------------------------------------------------

得益于 `twin` 与 `next` 指针的定向循环，所有复杂的拓扑查询均收敛为优雅的常数级循环链：

1. 绕顶点的 1-环邻域遍历 (1-Ring Vertex Traversal)
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

查询顶点 $V$ 的所有相邻顶点（用于拉普拉斯平滑或计算顶点平均法线）：

.. code-block:: cpp

   // 绕顶点 V 逆时针循环遍历所有相邻顶点与相邻面
   void Traverse1RingVertices(Vertex* v) {
       HalfEdge* startEdge = v->halfedge;
       HalfEdge* currEdge = startEdge;
       do {
           Vertex* neighbor = currEdge->target;
           ProcessNeighborVertex(neighbor);
           
           Face* adjacentFace = currEdge->face;
           ProcessAdjacentFace(adjacentFace);

           // 核心循环推进操作: 经对偶半边转入下一相邻面，再取下一条出射半边
           currEdge = currEdge->twin->next;
       } while (currEdge != startEdge);
   }

- **复杂度**：严格为 $O(k)$，其中 $k$ 为顶点的度数（Valence，在三角网格中平均仅为 6），在算力层面达到常数级 $O(1)$！

2. 绕面边界的遍历 (Face-Edge Traversal)
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

.. code-block:: cpp

   // 遍历面 F 的所有包围边与顶点
   void TraverseFaceEdges(Face* f) {
       HalfEdge* startEdge = f->halfedge;
       HalfEdge* currEdge = startEdge;
       do {
           ProcessEdge(currEdge);
           currEdge = currEdge->next;
       } while (currEdge != startEdge);
   }

8.4 面向 GPU 硬件吞吐的顶点缓冲布局架构
------------------------------------------------------------------------

半边结构专为 CPU 端的拓扑分析与编辑设计，但 GPU 顶点着色器需要高速、连续的线性内存缓冲。在将几何数据导出至 GPU 显存时，存在两种截然不同的物理布局模式：

.. list-table:: GPU 顶点缓冲布局模式优劣对比
   :widths: 20 40 40
   :header-rows: 1
   :class: tight-table

   * - 布局模式
     - 内存组织形式
     - 硬件访问特性与适用场景
   * - **交错缓冲 (Interleaved / AoS)**
     - 所有属性打包在单一连续结构体中：
`[Pos0, Normal0, UV0], [Pos1, Normal1, UV1]...`
     - **常规渲染标准**：单次 Draw Call 仅绑定 1 个 Vertex Buffer，具有极佳的缓存行局部性，完全规避多次总线寻址。
   * - **分流缓冲 (Separate Streams / SoA)**
     - 不同属性分散在独立连续数组中：
`Stream 0: [Pos0, Pos1...]; Stream 1: [UV0, UV1...]`
     - **Pass 级带宽优化核心**：在仅需要位置信息的通道（如 Depth Pre-Pass、Shadow Map Pass、视锥剔除）中，仅绑定 Stream 0，显存总线带宽节约 60%~75%！

.. code-block:: text

   +-------------------------------------------------------------------------+
   |              深度通道下交错缓冲 vs 分流缓冲显存带宽浪费对比             |
   +-------------------------------------------------------------------------+

   [ 交错缓冲 (AoS): 仅需 Position (12B)，但被迫读入完整顶点 (36B) ]
   Cache Line: [ Pos0 (12B) | Normal0 (12B) | UV0 (8B) | Pos1 (12B) ... ]
   有效载荷:   [ 有效数据   | === 冗余浪费 ===| 冗余浪费 | 有效数据   ... ] (利用率 33%)

   [ 分流缓冲 (SoA): 仅读取 Position Stream ]
   Cache Line: [ Pos0 (12B) | Pos1 (12B) | Pos2 (12B) | Pos3 (12B) ... ]
   有效载荷:   [ 100% 全为 Depth Pass 所需的有效坐标数据！               ] (利用率 100%)

8.5 顶点缓存优化与索引拓扑排序 (Vertex Cache Optimization)
------------------------------------------------------------------------

GPU 硬件在顶点着色器（VS）与图元装配器之间配备了一个硬件级的**变换后顶点缓存（Post-Transform Vertex Cache - FIFO/LRU 队列）**，通常可容纳 16 ~ 64 个顶点的计算结果。

当三角形图元装配器拉取一个索引 `Index` 时：
- 若命中 Post-Transform Cache，直接复用已变换坐标，**跳过该顶点的顶点着色器执行**；
- 若未命中（Cache Miss），则必须调度执行一次完整的顶点着色器。

Forsyth / Tipsify 索引重排优化算法
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

对于未经优化的原始多边形网格，其平均每顶点缓存未命中率（ACMR - Average Cache Miss Ratio）通常在 $2.0 \sim 3.0$（即每个顶点被重复计算 2~3 次）。

通过应用 **Forsyth 或 Tipsify 拓扑排序算法**，按照时间局部性重排索引缓冲区（Index Buffer），使共享相同顶点的三角形紧密相邻绘制：

.. math::

   	ext{ACMR} = \frac{	ext{Total Vertex Shader Invocations}}{	ext{Total Triangle Count}}

- 经过优化后，ACMR 可从 $2.5$ 骤降至接近理论极限 **$0.5 \sim 0.7$**，使得顶点着色器的整体执行负载降低 **60% 以上**！
