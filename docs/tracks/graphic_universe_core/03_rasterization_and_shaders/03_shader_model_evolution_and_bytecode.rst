========================================================================
Chapter 13: 着色器模型演进与字节码：从固定管线到统一着色器、DXIL 与 SPIR-V
========================================================================

.. note:: 前置背景与认知承接
   前一章解构了 2D 边缘方程（Juan Pineda 算法）、Top-Left 像素填充规则与多重采样抗锯齿（MSAA）的覆盖率掩码计算。当光栅化硬件完成离散片段的生成后，流水线必须依托着色器程序（Shader Programs）对每个顶点、图元或片段执行光照着色与数学计算。早期的固定功能管线（Fixed-Function Pipeline）已被彻底颠覆，现代 GPU 全面走向统一着色器架构（Unified Shader Architecture）与多级中间表示（IR）编译器体系。本章将系统剖析 Shader Model 从 1.0 到 6.x 的演进脉络、统一着色器硬件微架构、DirectX 字节码体系（从 DXBC 到基于 LLVM 的 DXIL）、Khronos SPIR-V 二进制中间表示结构，以及 GPU 驱动 JIT/AOT 编译生成硬件原生 ISA（SASS / RDNA ISA）的全生命周期。

13.1 着色器架构演进史：从固定功能流水线到统一着色器架构
------------------------------------------------------------------------

图形硬件计算单元的演进历程，本质上是一部从“专用硬连线 ASIC”向“高吞吐通用向量并行处理器”蜕变的计算架构史：

.. code-block:: text

   +-------------------------------------------------------------------------+
   |                  图形处理器计算架构三大历史演进阶段                     |
   +-------------------------------------------------------------------------+

   [ 阶段 1: 固定功能管线 (Fixed-Function - 1990s ~ DirectX 7) ]
   +-------------------------------------------------------------------------+
   | 硬件 T&L 矩阵乘法电路 -> 视口裁剪 -> 固定纹理级联融合器 (Texture Cascade) |
   +-------------------------------------------------------------------------+
   * 物理特征: 纯专用硬件电路，零可编程性；光照仅支持固化的 Gouraud / Phong 模型

   [ 阶段 2: 物理分离可编程架构 (DirectX 8 ~ 9 / SM 1.0 ~ 3.0) ]
   +------------------------------------+    +-------------------------------+
   | 专用顶点着色引擎 (Vertex Units)     | -> | 专用像素着色引擎 (Pixel Units)|
   | (例如 GeForce 6800: 6 个 VS 核心)  |    | (例如 GeForce 6800: 16 个 PS) |
   +------------------------------------+    +-------------------------------+
   * 物理缺陷: 算力严重失衡！几何复杂场景 VS 满载而 PS 闲置；重光照场景 PS 饥饿！

   [ 阶段 3: 统一着色器架构 (Unified Shader Architecture - DirectX 10 / SM 4.0 至今) ]
   +-------------------------------------------------------------------------+
   | 通用流式多处理器阵列 (Streaming Multiprocessors / Compute Units)        |
   |                                                                         |
   | [SIMD Core 0] [SIMD Core 1] ... [SIMD Core N] (全同通用可编程 ALU)      |
   |                                                                         |
   | 硬件线程束调度器 (Warp Scheduler): 动态将线程分配给 VS/PS/GS/CS 执行!   |
   +-------------------------------------------------------------------------+
   * 物理收益: 彻底消除物理核心闲置，硬件算力利用率逼近 100% 极限！

13.2 现代着色器编译全链路：从高级着色语言到硬件 ISA
------------------------------------------------------------------------

现代图形应用中，着色器程序从开发者编写的高级源码到最终在硅片晶体管上执行，经历了**三层解耦的编译流水线**：

.. code-block:: text

   +-------------------------------------------------------------------------+
   |                   现代着色器全链路三层编译与分发架构                    |
   +-------------------------------------------------------------------------+

   [ 离线开发构建期 (Offline Build Time) ]
   HLSL 源码 (.hlsl) / GLSL 源码 (.glsl) / WGSL 源码 (.wgsl)
        |
        v [ 前端离线编译器 (DXC / glslang / Tint) ]
   平台无关标准化二进制中间表示 (Intermediate Representation - IR):
        * DirectX 生态: DXBC (传统) / DXIL (基于 LLVM Bitcode)
        * Khronos / Web 跨平台生态: SPIR-V (基于 32-bit Words 强类型字节码)
        |
   +----+--------------------------------------------------------------------+
        |
        v [ 运行时应用分发 (Runtime Distribution) ]
   打包进游戏资源包 / 驱动管线状态对象 (PSO) 描述符
        |
        v [ 驱动预热 / JIT 编译期 (Driver JIT Compilation) ]
   GPU 硬件厂商专有驱动编译器 (NVIDIA Driver / AMD Adrenalin / Mesa RADV)
        |  * 寄存器分配与压力优化 (Register Allocation & Spilling)
        |  * 指令调度 (Instruction Scheduling) 与双发射优化
        v
   GPU 物理芯片原生机器指令集 (Native Hardware ISA):
        * NVIDIA: SASS (Streaming Assembler, 如 SM_80 / SM_90 原生机器码)
        * AMD: RDNA 3 / GCN 原生微码 (VOP3P / SALU / VALU 指令)
        * Apple: AGX 专用机器码

13.3 DirectX 字节码体系：从 DXBC 到基于 LLVM 的 DXIL
------------------------------------------------------------------------

传统 DXBC (DirectX Bytecode) 的架构局限
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

在 DirectX 11 及更早版本中，微软采用名为 DXBC 的自定义二进制字节码。DXBC 基于纯专有的 32 位 Token 序列编码。随着 GPU 通用计算能力的爆发，DXBC 封闭的寄存器语义使得其难以接入现代工业级通用编译器的优化成果，且无法表达复杂的复杂控制流与高级指针算术。

现代 DXIL (DirectX Intermediate Language) 架构
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

DirectX 12 引入了全新设计的 **DXIL（DirectX Intermediate Language）**，其本质是 **LLVM 3.7+ 的标准位码（Bitcode）子集**，并结合微软定制的 DirectX 扩展内建函数库（HLSL Intrinsics）：

1. **静态单赋值 (SSA - Static Single Assignment)**：DXIL 完全基于 SSA 形式，每一个变量仅被赋值一次，使得死代码消除（DCE）、全局值编号（GVN）与循环展开（Loop Unrolling）等高级优化达到极致。
2. **强类型系统与元数据绑定**：将着色器的资源绑定槽位（CBV、SRV、UAV、Sampler）编码为标准的 LLVM Metadata，供硬件驱动快速提取反射信息。
3. **Wave Intrinsics 硬件原语直接映射**：
   DXIL 原生表达线程束内部无锁通信操作，直接映射为底层 SIMD 跨通道指令：

   .. code-block:: hlsl

      // 在单个 Warp 内部瞬间完成 32 个线程的局部加和，完全无需显存/共享内存交换！
      float laneSum = WaveActiveSum(myVal);
      uint activeCount = WaveActiveCountBits(bCondition);

13.4 Khronos SPIR-V 二进制中间表示微架构
------------------------------------------------------------------------

**SPIR-V（Standard Portable Intermediate Representation - V）** 是 Vulkan、OpenCL 以及 WebGPU 底层标准的统一多语言中间表示，其设计哲学是彻底解耦高级着色语言与底层 API 执行环境。

SPIR-V 二进制文件头与指令拓扑
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

SPIR-V 文件是由一系列 **32 位无符号整数（32-bit Words）** 构成的紧凑二进制流。每个 SPIR-V 模块必须以标准的 5 个 Word 文件头起始：

.. code-block:: text

   +-------------------------------------------------------------------------+
   |                       SPIR-V 二进制文件头标准结构                       |
   +-------------------------------------------------------------------------+

   Word 0: 魔数 (Magic Number) -> 0x07230203 (用于快速校验大小端字节序)
   Word 1: 版本号 (Version)     -> 如 0x00010600 (SPIR-V 1.6)
   Word 2: 生成器标识 (Generator) -> 标识编译器厂商与版本 (如 0x00080001 = glslang)
   Word 3: Bound               -> 当前模块中所有 SSA ID 的最大上限值 (所有 ID < Bound)
   Word 4: Schema 保留字        -> 预留字段，当前标准固定为 0
   Word 5 ~ N: 连续指令流 (Instruction Stream)

标准指令格式与操作码 (Opcode) 编码
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

在 SPIR-V 中，每一条指令都具有高度统一的物理结构：

.. math::

   	ext{Instruction Word 0} = \big( 	ext{WordCount} \ll 16 \big) \;|\; 	ext{Opcode}

- **高 16 位 (WordCount)**：当前指令所占用的 32-bit Word 总长度（包含 Word 0 本身）；
- **低 16 位 (Opcode)**：指定操作指令枚举（如 `OpFMul = 133`, `OpTypeFloat = 22`）；
- **后续 Words**：依次携带可选的 `<Result-Type-ID>`、`<Result-ID>` 以及操作数（Operands）。

.. code-block:: text

   // 典型 SPIR-V 核心计算指令物理编码示例:
   OpTypeFloat %float 32                     ; 定义 32 位单精度浮点类型
   OpTypeVector %v4float %float 4           ; 定义 4 维浮点向量类型
   %res = OpFMul %v4float %vecA %vecB       ; 向量点乘/乘法运算

13.5 GPU 驱动 JIT 编译与管线状态对象 (PSO) 缓存
------------------------------------------------------------------------

着色器编译卡顿 (Shader Stuttering) 的物理成因
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

在传统的 OpenGL 与 DirectX 11 时代，图形驱动在运行时执行着色器编译面临灾难性的痛点：
驱动无法预知当前的顶点着色器（VS）究竟会与哪一个像素着色器（PS）搭配，更无法预知输出目标的分辨率与混合状态。驱动被迫在玩家触发 `DrawCall` 的**关键帧渲染主线程**中，紧急执行耗时数毫秒至数百毫秒的 JIT（即时编译），导致游戏帧率剧烈掉帧骤降（Stutter）。

现代显式管线状态对象 (Pipeline State Object - PSO)
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

现代图形 API（DirectX 12 / Vulkan / Metal）从物理架构层面彻底消除了这一缺陷：

.. code-block:: text

   +-------------------------------------------------------------------------+
   |                       不可变管线状态对象 (PSO) 编译模型                 |
   +-------------------------------------------------------------------------+

   [ 离线预编译 DXIL / SPIR-V 字节码 ]
        +
   [ 顶点输入布局描述符 (Input Layout) ]
        +
   [ 根签名 / 描述符集布局 (Root Signature / Pipeline Layout) ]
        +
   [ 渲染目标格式与混合模式 (RTV Format, BlendState, DepthStencilState) ]
        |
        v (在游戏加载期 / 离线预热期调用 CreateGraphicsPipelineState)
   [ 驱动后端编译器 JIT/AOT 极速优化 ] -> 生成硬件原生不可变机器码 (Native PSO)
        |
        v (持久化存储至磁盘)
   [ 驱动管线缓存 (Pipeline Cache / Steam Shader Pre-caching) ]

- **运行时零开销**：在真正的每帧渲染循环中，CPU 仅需向 GPU 发送一个极其微小的指针切换指令（`SetPipelineState`），开销仅为数纳秒，彻底实现 60fps/120fps 的绝对平滑帧时！

小结与下章导读
------------------------------------------------------------------------

本章系统解构了着色器从固定功能管线向现代统一着色器架构的演进必然性、三层解耦的着色器编译链路、DirectX DXIL 基于 LLVM 的优化机制、Khronos SPIR-V 强类型二进制指令结构，以及基于不可变管线状态对象（PSO）消除编译卡顿的底层原理。

在理解了通用着色器的执行模型后，流水线将进一步拓展至更高级的可编程拓扑阶段——**进阶可编程阶段剖析：几何着色器、硬件曲面细分 (Hull/Domain) 与网格着色器 (Mesh Shader)**，深入探讨现代几何处理从早期固定细分阶段向完全基于计算拓扑的网格着色器（Mesh Shading Pipeline）的划时代变革。
