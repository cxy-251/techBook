========================================================================
Chapter 14: 进阶可编程阶段：几何着色器、硬件曲面细分与网格着色器
========================================================================

.. note:: 前置背景与认知承接
   前一章解构了着色器从固定功能管线向统一着色器架构（Unified Shader Architecture）的演进、DXIL/SPIR-V 字节码微架构与 PSO 状态机缓存。传统的顶点着色器（VS）受制于严格的“单顶点进、单顶点出”一对一映射模型，无法在 GPU 流水线内部动态增删图元或自适应调整网格拓扑密度。为了突破几何生成的固定拓扑限制，GPU 架构经历了从几何着色器（GS）、硬件曲面细分（Tessellation），到全新革命性网格着色管线（Mesh Shading Pipeline）的三代演进。本章将系统剖析几何着色器的动态图元放大与内部缓冲瓶颈、硬件曲面细分三阶段（Hull/Tessellator/Domain）协同微架构、以 Meshlet 为核心的网格着色器拓扑重构，以及基于放大着色器（Amplification/Task Shader）的 GPU-Driven 视锥剔除与 LOD 调度。

------------------------------------------------------------------------
14.1 几何着色器 (Geometry Shader) 微架构与带宽瓶颈
------------------------------------------------------------------------

在 DirectX 10（Shader Model 4.0）中，微软首次引入了**几何着色器（Geometry Shader - GS）**。GS 位于顶点着色器与光栅化器之间，其革命性在于首次赋予了 GPU 在渲染管线中**动态增删图元（Primitive Amplification / Deamplification）**的能力。

几何着色器的执行模型与拓扑能力
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

- **全图元接入**：GS 不再以孤立顶点为单位执行，而是以完整的图元为输入（点 `Point`、线段 `Line`、三角形 `Triangle` 及其带相邻顶点的拓扑 `TriangleAdj`）。
- **动态图元流发射**：着色器内部通过 `inout TriangleStream<OutputVertex> stream` 输出流，能够将一个输入点扩增为一个四边形公告板（Billboard）、从单个三角形挤出体积阴影多边形（Shadow Volume Extrusion），或者通过不调用 `stream.Append()` 直接将图元剔除。

.. code-block:: hlsl

   // 典型几何着色器图元放大示例: 点扩增为四边形广告牌 (Billboard)
   [maxvertexcount(4)]
   void GS_Billboard(point VS_OUTPUT input[1], inout TriangleStream<GS_OUTPUT> outStream)
   {
       float3 pos = input[0].Pos;
       float halfSize = input[0].Size * 0.5f;

       GS_OUTPUT v0, v1, v2, v3;
       v0.Pos = mul(float4(pos + float3(-halfSize, -halfSize, 0), 1), ViewProj);
       v1.Pos = mul(float4(pos + float3( halfSize, -halfSize, 0), 1), ViewProj);
       v2.Pos = mul(float4(pos + float3(-halfSize,  halfSize, 0), 1), ViewProj);
       v3.Pos = mul(float4(pos + float3( halfSize,  halfSize, 0), 1), ViewProj);

       outStream.Append(v0); outStream.Append(v1);
       outStream.Append(v2); outStream.Append(v3);
       outStream.RestartStrip();
   }

物理微架构缺陷与性能崩溃成因
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

尽管功能强大，但几何着色器在现代高品质 3D 渲染引擎中已被全面边缘化甚至废弃，其根本原因在于其与 SIMT 硬件微架构之间无法调和的物理冲突：

.. list-table:: 几何着色器 (GS) 物理性能瓶颈分析
   :widths: 25 35 40
   :header-rows: 1
   :class: tight-table

   * - 物理瓶颈维度
     - 硬件底层机理
     - 性能与资源代价
   * - **可变输出与寄存器压力**
     - GPU SIMT 架构必须为每个线程预先分配由 `[maxvertexcount(N)]` 决定的最大可能显存/寄存器空间
     - 严重降低流式多处理器（SM）的**占用率（Occupancy）**，线程并发度断崖式下跌
   * - **片上缓冲区溢出 (Spilling)**
     - 当多个线程并发放大图元时，片上内部输出缓冲区（GS Output Buffer）迅速饱和耗尽
     - 硬件被迫将中间几何数据溢出（Spill）写回**外部高延迟 DRAM 显存**，带宽开销失控
   * - **拓扑装配流水线气泡**
     - GS 发射的 `TriangleStream` 必须重新进入硬件图元装配器以连接为条带
     - 破坏了统一光栅化的平滑流水线节拍，引入严重的管线停顿（Pipeline Stalls）

14.2 硬件曲面细分流水线 (Tessellation Pipeline)
------------------------------------------------------------------------

为了克服几何着色器在大规模几何细分上的带宽灾难，DirectX 11（Shader Model 5.0）引入了**三阶段解耦的硬件曲面细分流水线（Tessellation Pipeline）**：

.. code-block:: text

   +-------------------------------------------------------------------------+
   |                  DirectX 11 / Vulkan 硬件曲面细分流水线                 |
   +-------------------------------------------------------------------------+

   [ 顶点着色器 (VS) ]: 变换控制点网格 (Control Points)
        |
        v
   [ 1. 外壳着色器 (Hull Shader / TCS) - 可编程 ]
        |  * 输出细分控制点属性 (Per-Patch Control Points)
        |  * 计算并输出细分因子 (Tessellation Factors: Edge Levels & Inner Levels)
        v
   +----+--------------------------------------------------------------------+
        |
        v
   [ 2. 固定功能曲面细分器 (Tessellator Engine / TPG) - 硬件 ASIC 电路 ]
        |  * 纯硬件数学插值电路，无着色器代码！
        |  * 依据细分因子在单位参数空间 (u, v) 内等分并生成密集的标准三角形点阵拓扑
        v
   +----+--------------------------------------------------------------------+
        |
        v
   [ 3. 域着色器 (Domain Shader / TES) - 可编程 ]
        |  * 接收细分生成的参数空间坐标 (u, v) 与 Hull 输出的控制点
        |  * 执行多项式基函数求值，采样置换贴图 (Displacement Map)，输出最终三维顶点
        v
   [ 几何着色器 / 光栅化器 (Rasterizer) ]

曲面细分因子的硬件等分模式
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

外壳着色器输出的 `SV_TessFactor` 控制硬件细分器的剖分策略：

1. **整数等分 (Integer Partitioning)**：细分因子直接四舍五入为整数，但在动态 LOD 距离变化时会导致几何顶点出现剧烈的突变跳跃（Popping 伪影）；
2. **分数等分 (Fractional-Even / Fractional-Odd)**：
   细分因子在浮点区间 $[n, n+2]$ 内连续过渡，随着观察距离逼近，新的三角形在边缘处平滑“淡入”展开，实现肉眼完全无感的连续几何 LOD 过渡。

14.3 几何管线的大一统革命：网格着色器 (Mesh Shader)
------------------------------------------------------------------------

传统几何流水线（IA $	o$ VS $	o$ HS $	o$ DS $	o$ GS）自 1990 年代建立以来，始终背负着两大不可逾越的物理包袱：

1. **固定输入装配器 (IA) 的带宽与格式瓶颈**：IA 硬件只能按固定步长读取顶点缓冲，不支持灵活的数据解压与图元流合并；
2. **单顶点编程模型的线程隔离**：顶点着色器完全无法感知相邻三角形的存在，无法在几何前端内部执行局部图元索引重用或簇级视锥剔除。

网格着色管线 (Mesh Shading Pipeline) 的范式重构
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

DirectX 12 Ultimate（Shader Model 6.5+）与 Vulkan（`VK_EXT_mesh_shader`）彻底废黜了传统几何前端，将其重塑为**基于线程组的通用计算化几何管线**：

.. code-block:: text

   +-------------------------------------------------------------------------+
   |          传统图形管线 vs 现代网格着色管线 (Mesh Shading) 对比           |
   +-------------------------------------------------------------------------+

   [ 传统几何管线 (固定前端 + 串行链条) ]
   [ Input Assembler ] -> [ Vertex Shader ] -> [ Hull/DS/GS ] -> [ Rasterizer ]
   * 缺陷: 链条冗长，中间数据多次经由显存缓冲中转，无法高效剔除！

   [ 现代网格着色管线 (双阶段计算式几何网格分发) ]
   [ 绘制命令: DispatchMesh(X, Y, Z) ]
        |
        v
   [ 放大着色器 (Task / Amplification Shader) - 类似 Compute Shader 线程组 ]
        |  * 簇级 (Meshlet) 粗粒度视锥体剔除、遮挡查询与自适应 LOD 计算
        |  * 动态调用 DispatchMesh() 下发存活的 Meshlet
        v
   [ 网格着色器 (Mesh Shader) - 以 Meshlet 为单位并行执行 ]
        |  * 线程组协作：并行解算局部顶点空间变换并重构局部图元拓扑
        |  * 直接向片上光栅化器发射几何多边形
        v
   [ 光栅化器 (Rasterizer) ] -> [ 像素着色器 (Pixel Shader) ]

14.4 Meshlet 簇数据结构与片上局部拓扑重构
------------------------------------------------------------------------

网格着色器的物理核心是 **Meshlet（微几何簇）**。一个复杂的 3D 模型在离线构建期被预划分为成百上千个连续的 Meshlet：

.. code-block:: text

   +-------------------------------------------------------------------------+
   |                        Meshlet 微几何簇物理数据布局                     |
   +-------------------------------------------------------------------------+

   一个标准 Meshlet 约束上限: [ 最多 64 个唯一顶点, 最多 126 个局部三角形 ]

   Meshlet 内部存储结构:
   +-------------------------------------------------------------------------+
   | 1. 包围盒与法线锥 (Bounding Cone): 用于 Task Shader 单指令执行锥体背面剔除 |
   | 2. 顶点引用数组 (Unique Vertex Indices): 64 个全局顶点 ID (指向 VBO)    |
   | 3. 局部三角形微索引 (Micro-Primitive Indices):                          |
   |    每个三角形由 3 个 8-bit (uint8) 局部索引构成: (v0, v1, v2) \in [0, 63]|
   +-------------------------------------------------------------------------+

8 位局部微索引的显存压缩革命
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

- 传统几何索引缓冲（Index Buffer）必须使用 32 位全局整数（`uint32`，每三角形占 $3 	imes 4 = 12	ext{ 字节}$）；
- 在 Meshlet 内部，三角形仅需索引本簇内部的 64 个顶点，因此每个索引仅需 8 位（`uint8`，每三角形占 $3 	imes 1 = 3	ext{ 字节}$），**几何索引数据体积瞬间压缩 75%**！

单个线程组处理单个 Meshlet 的协同模式
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

在 Mesh Shader 内部，启动一个大小为 32 或 64 的线程组（Threadgroup）：

.. code-block:: hlsl

   [outputtopology("triangle")]
   [numthreads(64, 1, 1)]
   void MS_Main(
       uint gtid : SV_GroupThreadID,
       uint gid  : SV_GroupID,
       in payload TaskPayload payload,
       out vertices VertexOutput verts[64],
       out indices uint3 triangles[126])
   {
       uint meshletIndex = payload.MeshletIndices[gid];
       SetMeshOutputCounts(64, 126);

       // 64 个线程并行计算 64 个顶点的 MVP 空间变换与属性
       if (gtid < 64) {
           verts[gtid] = TransformVertex(meshletIndex, gtid);
       }

       // 线程并发加载 126 个三角形的局部 8-bit 拓扑索引
       if (gtid < 126) {
           triangles[gtid] = LoadLocalIndices(meshletIndex, gtid);
       }
   }

14.5 放大着色器 (Task/Amplification Shader) 与 GPU-Driven 几何分发
------------------------------------------------------------------------

两级网格着色管线的真正威力，在于将原本由 CPU 主线程处理的几何剔除与 DrawCall 分发，完全移交给 GPU 硬件并发执行（**100% GPU-Driven Pipeline**）。

.. list-table:: 几何处理阶段架构跨代演进矩阵
   :widths: 20 25 25 30
   :header-rows: 1
   :class: tight-table

   * - 几何架构代际
     - 图元数据输入形态
     - 剔除与 LOD 决策位置
     - 几何分发吞吐与物理瓶颈
   * - **传统流水线 (VS/GS)**
     - 顶点流 + 全局索引缓冲
     - CPU 逐 Object 粗筛 + VS 逐顶点变换
     - 受限于 CPU DrawCall 提交开销，复杂场景瓶颈严重
   * - **曲面细分 (HS/DS)**
     - 控制点 Patch 拓扑
     - 依据距离因子在 HS 动态设置
     - 细分器（TPG）为固定硬件，扩展性差，易产生极小三角形浪费
   * - **网格着色管线 (Task/Mesh)**
     - **Meshlet 紧凑簇 + 局部微索引**
     - **Task Shader 在 GPU 片上以 Meshlet 粒度毫秒级剔除**
     - **千万级多边形单指令调度**，完全消除 CPU 提交气泡与中间显存带宽消耗

Task Shader 的视锥与法线锥剔除算法
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

在 Task Shader 中，每个线程并发评估一个 Meshlet：
1. **视锥体相交测试 (Frustum Culling)**：测试 Meshlet 的局部包围球是否落在 6 个裁剪平面外部；
2. **法线锥背面剔除 (Normal Cone Culling)**：若 Meshlet 上所有三角形法线均背向相机视线向量，整簇直接丢弃；
3. **存活分发 (Compact & Dispatch)**：利用 Wave Intrinsics 原语在 Warp 内部进行存活 Meshlet 索引压缩，最后仅调用一次 `DispatchMesh(activeCount)` 启动 Mesh Shader。
