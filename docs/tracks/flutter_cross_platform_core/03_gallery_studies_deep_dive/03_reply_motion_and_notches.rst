第一幕：流体容器变换（`OpenContainer`）的图层形变与空间连续性
--------------------------------------------------------------

在传统的页面导航模型（如 ``Navigator.push``）中，新页面通常以整个屏幕从右向左滑入（Slide Transition）或淡入淡出（Fade Transition）的形式呈现。这种粗暴的转场模型会导致用户的视觉焦点在切换瞬间发生断裂：用户无法在空间感知上建立“我刚刚点击的这封邮件卡片”与“当前展开的全屏详情页面”之间的物理因果关联。

Reply 实现了 Material 3 体系中最核心的**流体容器变换（Container Transform / OpenContainer）**：

.. code-block:: text

   ┌──────────────────────────────────────────────────────────────────────────┐
   │ OpenContainer 物理图层连续形变流水线                                      │
   ├──────────────────────────────────────────────────────────────────────────┤
   │ 1. 闭合态 (Closed Builder - 列表项卡片):                                  │
   │    • 具有外层圆角 (Radius = 16.0px) 与卡片物理高程 (Elevation = 0 / 2)    │
   │    • 渲染: 发件人头像、主题摘要、时间戳与标签芯片 (MailPreviewCard)       │
   │                                                                          │
   │ 2. 变换过渡态 (Transitioning - 400ms 动力学插值):                        │
   │    • 几何包围盒插值: 从卡片屏幕绝对坐标 Rect_start 膨胀至全屏 Rect_end   │
   │    • 物理圆角退化: 顶角与底角从 16px 平滑衰减至 0px (直角)               │
   │    • 双向交叉淡化 (Fade Through): 列表摘要淡出 (0~35%)，邮件正文淡入 (35~100%)│
   │    • 阴影投射提升: 高程随展开面积从 2 级抬升至 8 级，形成浮空张力          │
   │                                                                          │
   │ 3. 展开态 (Open Builder - 全屏邮件详情页):                               │
   │    • 填满整个物理视口 (MailViewPage)，承载富文本内容、附件预览与回复栏   │
   └──────────────────────────────────────────────────────────────────────────┘

1. 空间包围盒（Bounding Box）全局坐标捕获
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
在用户点击卡片瞬间，``OpenContainer`` 通过其底层的 ``RenderBox.localToGlobal(Offset.zero)`` 提取卡片在当前屏幕绝对像素坐标系中的矩形位置：
$$	ext{Rect}_{	ext{closed}} = 	ext{Rect.fromLTWH}(X_{	ext{card}}, Y_{	ext{card}}, W_{	ext{card}}, H_{	ext{card}})$$
全屏目标矩形为当前窗口的完整尺寸：
$$	ext{Rect}_{	ext{open}} = 	ext{Rect.fromLTWH}(0, 0, W_{	ext{screen}}, H_{	ext{screen}})$$

2. 多物理维度的非线性协同插值方程
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
设转场动画参数为 $t \in [0, 1]$，采用 Material 强调减速曲线 $	ext{easeOut}(t)$：
* **几何位置插值**：
  $$	ext{Rect}(t) = 	ext{Rect.lerp}(	ext{Rect}_{	ext{closed}}, 	ext{Rect}_{	ext{open}}, 	ext{easeOut}(t))$$
* **外层物理圆角形变**：
  $$	ext{BorderRadius}(t) = 16.0 	imes (1.0 - 	ext{easeOut}(t))$$
* **两阶段交叉透明度（Fade Through）**：
  $$\alpha_{	ext{closed}}(t) = \operatorname{clamp}\left(1.0 - \frac{t}{0.35}, 0.0, 1.0\right)$$
  $$\alpha_{	ext{open}}(t) = \operatorname{clamp}\left(\frac{t - 0.35}{0.65}, 0.0, 1.0\right)$$
列表卡片与全屏详情页在同一个动画图层内无缝完成外壳放大、圆角拉平与内容交叉溶解，整个过程没有出现任何空白闪烁或跳跃，创造出极致自然的流体视觉体验。

第二幕：底部瀑布缺口（`WaterfallNotchedRectangle`）的切线几何数学推导
---------------------------------------------------------------------

在 Material 底部应用栏（BottomAppBar）设计中，悬浮操作按钮（FAB，Floating Action Button）通常以圆形形态嵌在导航底板的顶部边缘。若直接在矩形上挖一个半圆死坑，边缘会产生生硬的直角转折。

在 ``lib/studies/reply/waterfall_notched_rectangle.dart`` 中，通过继承 ``NotchedShape`` 实现了让底板平滑凹陷包络圆环的高阶几何算法：

.. code-block:: text

   Host Top Edge (底板顶边) ────────────────────────────────────────────────────
        │                                                                ▲
        │ 段 A: 二次贝塞尔切入                                            │ 段 C: 镜像贝塞尔切出
        ▼                                                                │
     (p0 ──► p1 ──► p2 切点)                                          (p3 ──► p4 ──► p5)
                       \                                              /
                        \            段 B: 连续圆弧避让               /
                         ▼ ───────────────────────────────────────── ▼
                           Guest Circle (悬浮圆形按钮 FAB, 半径 r)

1. 圆与相交直线的切线判别式推导
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
设悬浮按钮（Guest）为一个半径为 $r$ 的圆形，圆心位于 $(X_{	ext{guest}}, Y_{	ext{guest}})$；底板（Host）的顶边垂直位置为 $Y_{	ext{host}}$。

以悬浮按钮圆心作为相对坐标系原点 $(0, 0)$：
* 垂直相对高度差：$b = Y_{	ext{host}} - Y_{	ext{guest}}$；
* 贝塞尔控制点横向参数：$s_1 = 21.0$（平滑过渡延展区），$s_2 = 6.0$（控制点偏移距离）；
* 设定切入基准横坐标：$a = -r - s_2$；
* **联立圆方程与直线切线方程求解判别式**：
  $$n_2 = \sqrt{b^2 r^2 (a^2 + b^2 - r^2)}$$
* **左侧贝塞尔切入点坐标精确解**：
  $$p_{2xA} = \frac{a \cdot r^2 - n_2}{a^2 + b^2}, \quad p_{2yA} = \sqrt{r^2 - p_{2xA}^2}$$
  $$p_{2xB} = \frac{a \cdot r^2 + n_2}{a^2 + b^2}, \quad p_{2yB} = \sqrt{r^2 - p_{2xB}^2}$$
根据 $b$ 的正负符号（按钮上浮或下沉）选取最优实数解作为左侧接触切点 $p_2(p_{2x}, p_{2y})$。

2. 三段式连续光滑路径构建 (`Path`)
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
算法构建 6 个控制点数组 $p[0 \dots 5]$，并将其坐标平移回全局物理坐标系（$+ 	ext{guest.center}$）：

* **段 A（左平滑切入段）**：
  * 起点为底板左顶角 $(X_{	ext{left}}, Y_{	ext{host}})$，画直线至控制点 $p_0(a - s_1, b)$；
  * 调用 ``path.quadraticBezierTo(p1.dx, p1.dy, p2.dx, p2.dy)``，由控制点 $p_1(a, b)$ 驱动二次贝塞尔曲线平滑切入圆形边缘切点 $p_2$；
* **段 B（圆弧避让段）**：
  * 调用 ``path.arcToPoint(p3, radius: Radius.circular(r), clockwise: false)``，以半径 $r$ 沿逆时钟方向顺着圆形按钮底部绘制光滑凹弧；
* **段 C（右平滑切出段）**：
  * 将段 A 的控制点关于 Y 轴完全镜像对称（$p_3 = (-p_{2x}, p_{2y}), p_4 = (-p_{1x}, p_{1y}), p_5 = (-p_{0x}, p_{0y})$）；
  * 调用 ``path.quadraticBezierTo(p4.dx, p4.dy, p5.dx, p5.dy)``，二次贝塞尔平滑切出回到底部栏右顶边，并闭合底板四边。

第三幕：响应式侧边栏与底部抽屉形态演化 (`mailbox_body.dart`)
------------------------------------------------------------

在 ``lib/studies/reply/mailbox_body.dart`` 中，导航系统根据屏幕物理尺寸在三大形态间自适应演化：

1. **大屏桌面端（Desktop / Wide Screen）**：
   * 采用固定的 **导航导轨（NavigationRail）**，左侧常驻图标与标签，右侧展开邮件多列列表；
2. **中屏平板端（Tablet）**：
   * 导航导轨收缩为纯紧凑图标栏，释放宝贵的横向阅读空间；
3. **移动端（Mobile）**：
   * 导航导轨自动隐退，重构为底部标准悬浮栏配合 ``BottomDrawer``，通过底部手势向上拉起完整的分组邮箱树（收件箱、已发邮件、垃圾箱、自定义标签）。
