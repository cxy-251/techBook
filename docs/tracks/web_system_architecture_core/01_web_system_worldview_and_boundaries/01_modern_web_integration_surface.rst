========================================================================
Chapter 1: 现代 Web 集成表面：浏览器、网络协议、多执行区运行时与服务端边界系统全景
========================================================================

.. note:: 前置背景与认知锚点
   本章作为全书开篇，确立现代 Web 系统架构的全局世界观。现代 Web 绝非传统意义上的简单网页展示或前后端接口交互，而是一个横跨浏览器多进程内核、传输层协议族、Edge 边缘计算、服务端托管运行时（Node.js / Bun / Serverless）以及持久化数据库边界的复杂分布式系统。本章将建立统一的“路径、边界、状态与故障恢复”心智模型，解构现代全栈 Web 的核心集成表面。

------------------------------------------------------------------------
1.1 Web 作为跨执行区协同系统的宏观图谱
------------------------------------------------------------------------

在现代全栈工程实践中，一段看似简单的业务代码（如用户点击提交订单按钮）并非在单一机器上顺序执行，而是跨越了物理空间与安全信任完全隔离的多个异构执行区（Execution Zones）：

.. list-table:: 现代 Web 架构六大核心执行区拓扑与物理特性
   :widths: 16 18 20 22 24
   :header-rows: 1
   :class: tight-table

   * - 执行区名称
     - 典型宿主技术
     - 物理延迟与位置
     - 信任等级与安全边界
     - 核心系统职责
   * - 浏览器客户端 (Browser Client)
     - Blink / WebKit / V8 / SpiderMonkey
     - 0 ms (用户本地终端)
     - 完全不可信环境 (Zero Trust)
     - 用户输入捕获、DOM 渲染、局部状态响应、GPU 硬件加速合成
   * - CDN 缓存与传输层 (CDN / Anycast)
     - Cloudflare / Fastly / Akamai PoP 节点
     - 5 ~ 20 ms (地理邻近边缘)
     - 只读缓存契约 (Edge Cache)
     - 静态资产分发、TLS 快速终止、HTTP 强弱缓存命中、DDoS 流量清洗
   * - 边缘计算运行时 (Edge Runtime)
     - V8 Isolates (Workers / Deno Deploy)
     - 10 ~ 30 ms (全球边缘节点)
     - 受限受信任环境 (无本地磁盘)
     - A/B 动态路由、低延迟重定向、轻量鉴权校验、地理位置 Header 改写
   * - 源服务器 / Serverless (Server)
     - Node.js / Bun / Go / Rust / Linux 容器
     - 50 ~ 200 ms (区域数据中心)
     - 高度受信任区 (持有 Secret/Env)
     - 业务规则解算、服务端渲染 (SSR)、数据库事务编排、跨服务 RPC
   * - 持久化数据边界 (Database / Cache)
     - PostgreSQL / MySQL / Redis / S3
     - 数据中心内网 (< 2 ms)
     - 核心数据信任根 (ACID / CAP)
     - 数据强一致性持久化、行级锁/表级锁并发控制、多版本并发控制 (MVCC)
   * - 构建时静态合成 (Build-Time Static)
     - Vite / Turbopack / esbuild / Rollup
     - 离线阶段 (CI/CD 编译机)
     - 确定性编译输出
     - 模块图分析 (Module Graph)、静态预渲染 (SSG)、Tree-Shaking、代码分割

现代 Web 架构师的核心思考起点，在于精确判断每一行代码究竟运行在哪个执行区，以及当数据跨越不同执行区时所产生的网络时延、序列化成本、安全策略断层与并发一致性风险。

1.2 浏览器客户端运行环境的本质：操作系统级沙箱与流水线
------------------------------------------------------------------------

浏览器并非普通的桌面应用程序，其内部设计高度同构于一个现代多任务操作系统。以主流的 Blink 内核与 Chromium 架构为例，浏览器通过严格的多进程模型构筑安全沙箱与资源调度管线：

.. code-block:: text

   +-------------------------------------------------------------------------+
   |                       现代浏览器多进程架构与流水线拓扑                  |
   +-------------------------------------------------------------------------+

   [ 浏览器主进程 (Browser Process) ]
        |  * 管理窗口、Tab 标签生命周期、地址栏导航与全局权限弹窗
        |  * 调度跨进程 IPC 通信通道
        |
        +---> [ 网络进程 (Network Process) ]
        |        * 维持 HTTP 连接池、DNS 缓存、Cookie 状态机与 TLS 握手
        |
        +---> [ GPU 进程 (GPU Process) ]
        |        * 承接全页面图层光栅化与 Direct3D / Metal / Vulkan 硬件绘制
        |
        +---> [ 渲染进程 (Renderer Process - 独立沙箱隔离) ]
                 |
                 +--> 主线程 (Main Thread):
                 |       HTML Tokenizer -> DOM 构建 -> CSSOM 解析
                 |       -> 样式计算 (Style Recalculation) -> 几何排版 (Layout)
                 |       -> 绘制指令录制 (Paint) -> V8 JavaScript 执行
                 |
                 +--> 合成器线程 (Compositor Thread):
                 |       图层分块 (Tiling) -> GPU 指令生成 -> 滚动/变换解耦
                 |
                 +--> 光栅化工作线程 (Raster Threads):
                         Skia / GPU 纹理生成

当 V8 引擎执行 JavaScript 代码并操作 DOM（如 `element.style.transform = ...`）时，系统跨越了 C++ 原生对象与 JS 运行时的 DOM Bindings 桥接边界。若频繁进行同步测量与写操作（如交替读取 `offsetWidth` 并修改样式），将强行中断流水线并引发高开销的**强制同步重排（Layout Thrashing）**，直接导致 60fps/120fps 渲染掉帧。

1.3 网络协议与传输层语义边界 (Network as Semantic Boundary)
------------------------------------------------------------------------

网络在 Web 体系中并非透明的“数据导管”，而是具备严格语义规则的系统控制平面：

URL 统一资源标识与同源判定
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

URL 是整个 Web 体系最基础的寻址与安全基石。浏览器依据 URL 的三元组：

.. math::

   	ext{Origin} = \langle 	ext{Scheme}, 	ext{Host}, 	ext{Port} \rangle

确立同源策略（Same-Origin Policy - SOP）边界。任何跨源请求必须经过 CORS 协议（跨源资源共享）的显式预检（Preflight OPTIONS 请求）与凭据（Credentials）验证。

HTTP 协议族的微架构演进
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

.. list-table:: HTTP 协议族演进与传输层微架构对比
   :widths: 20 25 25 30
   :header-rows: 1
   :class: tight-table

   * - 协议版本
     - 底层传输协议
     - 连接复用机制
     - 核心瓶颈与解决痛点
   * - HTTP/1.1
     - TCP (单连接单请求)
     - Keep-Alive 串行管道化
     - 应用层队头阻塞 (Head-of-Line Blocking)、重复 Header 冗余
   * - HTTP/2
     - TCP (单连接多路复用)
     - 二进制分帧 (Binary Framing) 与流 (Stream ID)
     - 消除应用层队头阻塞；但 TCP 层丢包会导致全局连接停顿
   * - HTTP/3
     - UDP + QUIC (原生多路流)
     - 基于 QUIC Packet 的独立流
     - 彻底消除传输层队头阻塞、支持 0-RTT 连接快速迁移与原生加密

Header 控制平面与流式背压 (Streaming & Backpressure)
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

HTTP 响应头（如 `Cache-Control: max-age=31536000, immutable`、`Content-Security-Policy`、`Set-Cookie: HttpOnly; SameSite=Strict`）直接指示浏览器、CDN 及中间代理如何配置沙箱权限、维护 Session 状态机并建立资源缓存模型。

结合现代 Fetch Streams API，数据以分块形式（`Transfer-Encoding: chunked`）从服务端流式抵达浏览器，允许页面在首屏数据尚未全量就绪前，边传输边解析渲染骨架屏（Shell），实现首字节时间（TTFB）与最大内容绘制（LCP）的大幅优化。

1.4 现代全栈架构跨运行时协同与框架封装代价
------------------------------------------------------------------------

现代全栈 Web 框架（如 Next.js App Router、Remix/React Router、Astro、SvelteKit）的核心使命，是将分散在浏览器、Node.js 服务端与 Edge 运行时的多层边界，封装为声明式的组件化开发模型。

跨边界水合与渲染模式演进
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

.. code-block:: text

   +-------------------------------------------------------------------------+
   |                     全栈服务端渲染 (SSR) 与客户端水合路径               |
   +-------------------------------------------------------------------------+

   [ 服务端 Node.js / Edge 执行区 ]
   1. 异步获取数据库数据 (Server Component / Loader)
   2. 执行 Virtual DOM 树求值并序列化为 HTML 文本流
   3. 注入数据序列化快照: <script id="__DATA__">window.__INITIAL_STATE__=...</script>
        |
        | HTTP 分块传输 (Chunked HTML Stream)
        v
   [ 浏览器客户端执行区 ]
   4. 增量解析 HTML 快速呈现静态 UI 骨架 (First Contentful Paint)
   5. 下载并执行大型客户端 JavaScript Bundle
   6. 客户端水合 (Hydration): 重新在内存构建 VDOM，比对 DOM 节点并重新绑定事件监听器

框架抽象背后的系统性工程代价
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

1. **水合不匹配 (Hydration Mismatch)**：若服务端渲染时读取的时间戳、随机数或用户环境与客户端首次执行时存在微小差异，将导致整个 DOM 树校验失败，触发不可预测的重新挂载闪烁与性能损耗。
2. **Bundle 体积膨胀与主线程长任务 (Long Tasks)**：为了支持客户端交互，大量仅在服务端使用的校验逻辑与组件代码被过度打包进 Client Bundle，导致页面初始加载时主线程被长时间占用，劣化交互到下一次绘制指标（INP）。
3. **分布式缓存失效雪崩**：全栈数据突变（Server Actions / Form Mutations）后，若未能精准计算 CDN、Edge 及客户端本地 Query Cache 的局部失效依赖，容易导致脏数据回显（Stale Data）或全局过度重刷。

1.5 全书统一分析范式：路径、边界、状态与故障恢复 (Path, Boundary, State, Failure)
------------------------------------------------------------------------

为了穿透千变万化的前端框架语法糖，全书确立了一套通用的系统级架构分析框架：

.. list-table:: 现代 Web 架构“路径-边界-状态-故障”统一分析模型
   :widths: 20 40 40
   :header-rows: 1
   :class: tight-table

   * - 分析维度
     - 核心关注对象
     - 架构设计考量
   * - **路径 (Path)**
     - 请求与交互的端到端调用时序流
     - 追踪从用户点击、DOM 事件、Fetch 请求、CDN 穿透、Node.js 路由到 SQL 执行的每一段耗时
   * - **边界 (Boundary)**
     - 物理环境隔离与安全信任分界点
     - 判定数据是在受信任的服务端持有，还是暴露在不可信的客户端；明确 CORS、CSP 与沙箱限制
   * - **状态 (State)**
     - 运行时分布式数据存储位置与拓扑
     - 区分 URL Query 共享状态、DOM 内部状态、IndexedDB 本地缓存、Cookie 凭证与 DB 唯一事实源
   * - **故障 (Failure)**
     - 异常退化、降级策略与自愈重入机制
     - 规划离线断网、JS 加载失败、Hydration 崩溃、5xx 服务端错误与网络竞态下的优雅降级闭环
