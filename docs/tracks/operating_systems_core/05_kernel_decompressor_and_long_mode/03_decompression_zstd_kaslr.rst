第一幕：自解压总控中枢——``extract_kernel()`` 运行全景
------------------------------------------------------

当 CPU 在 64 位长模式下完成初始寄存器清理与临时栈搭建后，汇编代码立即调用 C 语言解压总控入口 **``extract_kernel()``**：

::

   +-----------------------------------------------------------------------------------+
   |                           extract_kernel() 执行流水线                             |
   |                                                                                   |
   |  [入参: rmode (R15 传递的 boot_params 零页指针), output (解压目标物理基地址)]      |
   |            │                                                                      |
   |            ▼ 1. 引导参数清理与机密计算环境嗅探                                    |
   |  - sanitize_boot_params(): 清洗零页潜在脏数据                                     |
   |  - early_tdx_detect() / early_sev_detect(): 探测 Intel TDX 与 AMD SEV-ES 机密计算 |
   |            │                                                                      |
   |            ▼ 2. 早期输出终端与 ACPI 根指针锚定                                     |
   |  - console_init(): 绑定 VGA 显存 (0xB8000) 与串口 (COM1 0x3F8), 开启 debug_putstr |
   |  - boot_params_ptr->acpi_rsdp_addr = get_rsdp_addr(): 提前锚定 ACPI 表            |
   |            │                                                                      |
   |            ▼ 3. KASLR 随机物理与虚拟基地址抉择                                     |
   |  - choose_random_location(): 硬件多源熵收集 + E820 避障 -> 选定 output 与 virt_addr|
   |            │                                                                      |
   |            ▼ 4. 执行核心解压缩 (decompress_kernel)                                |
   |  - __decompress() [Zstandard 算法]: 从 input_data 流式解压至 output 物理缓冲区   |
   |            │                                                                      |
   |            ▼ 5. ELF64 容器解析与动态重定位修复                                    |
   |  - parse_elf(): 解析 PT_LOAD 程序段并按对齐对位                                   |
   |  - handle_relocations(): 修复编译符号对 KASLR 偏移量 Delta 的指针引用             |
   |            │                                                                      |
   |            ▼ 6. 返回真正内核物理入口                                               |
   |  - 返回 output + entry_offset (指向解压后内核的 startup_64 汇编入口!)             |
   +-----------------------------------------------------------------------------------+

第二幕：KASLR 物理与虚拟地址随机化算法数学模型
----------------------------------------------

为了防范返回导向编程（ROP）攻击与内核物理内存布局推测漏洞，现代 Linux 7.2 默认强力开启 **KASLR (Kernel Address Space Layout Randomization)**。

2.1 多源硬件真随机熵收集引擎（``kaslr.c``）
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
在没有操作系统熵池支持的极早期引导阶段，Linux 内核通过物理硬件底层直接采集高熵随机种子：

::

   +-----------------------------------------------------------------------------------+
   |                           KASLR 多源硬件熵收集拓扑                                |
   |                                                                                   |
   |  [熵源 1: RDRAND 硬件指令] ──► 从片上热噪声发生器提取 64 位真随机数 (最高置信度)   |
   |  [熵源 2: RDTSC 时钟周期计数器] ──► 提取纳秒级 CPU 周期计数低 32 位 (高频抖动)   |
   |  [熵源 3: I8254 PIT 定时器] ──► 读回 PIT 计数器 0 的当前锁存计数值                 |
   |  [熵源 4: 启动参数与时间戳] ──► 混合 boot_params 中的固件启动时间与命令行特征      |
   |            │                                                                      |
   |            ▼                                                                      |
   |  [rotate_xor 循环移位异或] ──► [SHA-256 压缩单向散列] ──► 生成 64 位最终真随机种子 |
   +-----------------------------------------------------------------------------------+

2.2 ``mem_avoid`` 物理避障算法与安全槽位划分
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
选定随机物理地址并非盲目生成，内核必须在物理内存中避开所有正在使用的关键数据区：

.. table:: KASLR mem_avoid 绝对避障内存清单
   :widths: 20 30 50

   +-------------------------+------------------------------------+------------------------------------------------+
   | 避障物理区域名称        | 典型物理内存区间                   | 避障原因与保护机制                             |
   +=========================+====================================+================================================+
   | **``boot_params``**     | ``0x00090000 ~ 0x00090FFF`` (4KB)  | 存放整机硬件拓扑与引导参数，被覆盖将导致内核失联 |
   +-------------------------+------------------------------------+------------------------------------------------+
   | **``cmdline``**         | ``0x00091000 ~ 0x00091FFF`` (4KB)  | 存放内核命令行启动参数                         |
   +-------------------------+------------------------------------+------------------------------------------------+
   | **``initramfs``**       | ``0x07000000 ~ 0x08FFFFFF`` (~32MB)| 初始内存盘，解包前绝不可被解压内核覆写         |
   +-------------------------+------------------------------------+------------------------------------------------+
   | **``Decompressor Code``**| ``[startup_32 .. _end]`` (~20MB)  | 自解压器自身正在执行的代码、GDT、页表与栈空间  |
   +-------------------------+------------------------------------+------------------------------------------------+
   | **``E820 Reserved``**   | EBDA、ACPI 表、PCI ECAM 保留区     | 硬件保留空间，绝对禁止映射为可用 RAM           |
   +-------------------------+------------------------------------+------------------------------------------------+

* **安全槽位（Slots）划分**：内核遍历 E820 可用 ``E820_RAM`` 内存块，扣除上述避障区间后，将剩余可用内存按 **2MB 物理边界（``CONFIG_PHYSICAL_ALIGN``）** 切分成 $N$ 个可用槽位；
* **物理基地址计算**：
  $$	ext{Selected\_Slot} = 	ext{Random\_Seed} \pmod{N}$$
  $$	ext{output} = 	ext{Slot\_Base}[	ext{Selected\_Slot}]$$

第三幕：Zstandard (Zstd) 极限压缩算法与内存解压时序
---------------------------------------------------

在 Linux 7.2 中，**Zstandard (Zstd)** 已全面取代老旧的 Gzip 与 XZ 成为默认的内核压缩算法。

3.1 Zstandard 算法的物理微架构优势
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
* **有限状态熵编码（Finite State Entropy, FSE）**：相比传统 Huffman 编码，FSE 能够在单时钟周期内完成多符号的概率状态机转移，大幅提升流水线吞吐；
* **极速解压吞吐**：在现代 x86_64 处理器上，Zstd 解压吞吐可达 **1.2 GB/s ~ 1.5 GB/s**，解压一个 80MB 的内核本体仅需约 **50 毫秒**。

3.2 ``__decompress()`` 流式解压双指针状态机（``lib/decompress_unzstd.c``）
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
在 ``decompress_kernel()`` 中，解压引擎建立起严密的双指针流式读取模型：

::

   +-----------------------------------------------------------------------------------+
   |                          Zstandard 流式解压缩内存推进模型                         |
   |                                                                                   |
   |  [压缩数据输入区 (Input Buffer, 位于内存末端)]                                     |
   |  input_data ┌────────────────────────────────────────────────────────┐            |
   |             │ Zstd Frame Header (魔数 0xFD2FB528)                    │            |
   |  in_ptr ──► ├────────────────────────────────────────────────────────┤            |
   |             │ 压缩数据块 (Block N, FSE + LZ77 匹配序列)              │            |
   |             └────────────────────────────────────────────────────────┘            |
   |                                                                                   |
   |  [解压数据输出区 (Output Buffer, 位于 KASLR 随机物理基地址 output)]                |
   |  output     ┌────────────────────────────────────────────────────────┐            |
   |  out_ptr──► │ 已解压的 ELF64 未压缩内核数据流 (vmlinux 裸二进制)      │            |
   |             │ (以 128KB 块大小向高地址持续填充...)                   │            |
   |             └────────────────────────────────────────────────────────┘            |
   +-----------------------------------------------------------------------------------+

解压引擎通过校验每一帧末尾的 32 位 CRC 校验和，确保解压后的内核二进制数据 100% 完整无误。

第四幕：ELF64 头部解析与内核符号动态重定位（``handle_relocations``）
--------------------------------------------------------------------

解压完成后，输出缓冲区中的数据是一个完整的未压缩 **ELF64 格式映像**。

4.1 ELF64 程序头（Program Header）重组（``parse_elf()``）
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
``misc.c:parse_elf()`` 遍历 ELF 头部的所有程序头表项（``Elf64_Phdr``）：
1. 校验 ELF 头部魔数：``e_ident[0..3] == { 0x7F, 'E', 'L', 'F' }``；
2. 过滤类型为 ``PT_LOAD`` 的加载段（如 ``.text``, ``.rodata``, ``.data``, ``.bss``）；
3. 检查段物理对齐要求（在 x86_64 下必须为 **2MB（``0x200000``）整数倍**）；
4. 调用 ``memmove()`` 将各段根据其物理偏移行精确对位放置在内存目标地址。

4.2 符号动态重定位修复流水线（``handle_relocations()``）
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
由于内核被 KASLR 放置在一个随机的物理基地址，且虚拟地址空间基准发生了偏移 $\Delta$，编译期生成的所有绝对函数指针与全局变量引用必须被即时修正：

::

   +-----------------------------------------------------------------------------------+
   |                           handle_relocations() 修复算法                           |
   |                                                                                   |
   |  /* 1. 计算 KASLR 虚拟地址偏移差值 Delta */                                       |
   |  delta = virt_addr - LOAD_PHYSICAL_ADDR;                                          |
   |                                                                                   |
   |  /* 2. 从解压内核的最末端读取编译期嵌入的重定位表项 (Relocation Table) */         |
   |  /* 表项格式: WORK BACKWARDS (逆向遍历 32 位与 64 位重定位指针) */                |
   |  for (reloc = output + output_len - sizeof(*reloc); *reloc; reloc--) {            |
   |      long extended = *reloc;                                                      |
   |      extended += map;            /* 调整为自解压工作映射地址 */                   |
   |      ptr = (unsigned long)extended;                                               |
   |                                                                                   |
   |      /* 3. 指针修正: 为指针加上 KASLR 偏移量 Delta ! */                           |
   |      *(uint64_t *)ptr += delta;                                                   |
   |  }                                                                                |
   +-----------------------------------------------------------------------------------+

通过这趟完整的重定位扫描，未压缩内核内部成千上万个绝对函数跳转与数据访问地址被全部修复为当前运行时的真实绝对地址！

第五幕：解压完毕与向解压后内核入口的跃迁准备
--------------------------------------------

在 ``extract_kernel()`` 的最后：
1. **获取内核物理入口偏移**：
   $$	ext{entry\_offset} = 	ext{ehdr.e\_entry} - 	ext{LOAD\_PHYSICAL\_ADDR}$$
2. **清理自解压临时中断向量**：调用 ``cleanup_exception_handling()`` 卸载解压阶段的临时 IDT；
3. **输出经典启动成功日志**：
   在串口与 VGA 控制台打印终极字符串：
   ::

      Decompressing Linux... done.
      Booting the kernel.

4. **返回绝对入口指针**：
   函数执行 ``return output + entry_offset;``。

返回值被放置在 ``RAX`` 寄存器中，自解压汇编跳板执行：
::

   movq    %r15, %rsi             /* 恢复 RSI 指向 boot_params 零页 */
   jmp     *%rax                  /* 最终长跳转：进入真正的 Linux 7.2 内核入口! */
