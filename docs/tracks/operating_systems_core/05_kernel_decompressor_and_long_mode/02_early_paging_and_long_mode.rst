第一幕：从 32 位到 64 位的物理鸿沟——长模式 (IA-32e) 激活铁律
-------------------------------------------------------------

在 x86_64 微架构中，CPU 无法从 16 位实模式或普通保护模式直接突变进入 64 位模式。Intel 与 AMD 架构手册规定了极其严苛的 **长模式（IA-32e Mode）六步激活状态机**：

::

   +-----------------------------------------------------------------------------------+
   |                             长模式 (IA-32e) 激活六步状态机                        |
   |                                                                                   |
   |  [前提状态: 32 位保护模式, CR0.PE = 1, CR0.PG = 0]                                |
   |            │                                                                      |
   |            ▼ 步骤 1: 启用物理地址扩展                                             |
   |  [置位 CR4.PAE = 1] ──► 硬件将页表项宽度从 32 位扩展至 64 位                      |
   |            │                                                                      |
   |            ▼ 步骤 2: 构建并加载 4 级页表                                          |
   |  [内存写入 PML4 顶级页表] ──► [将 PML4 物理基地址载入 CR3 寄存器]                 |
   |            │                                                                      |
   |            ▼ 步骤 3: 使能长模式扩展特性                                           |
   |  [写 MSR_EFER (0xC0000080)] ──► 置位 Bit 8 (LME = 1, Long Mode Enable)            |
   |            │                                                                      |
   |            ▼ 步骤 4: 开启分页机制 (触发硬件模式跃迁!)                             |
   |  [置位 CR0.PG = 1] ──► CPU 硬件自动将 EFER.LMA (Long Mode Active) 置 1!           |
   |                        (此时 CPU 处于 IA-32e 兼容子模式: CS.L=0, CS.D=1)          |
   |            │                                                                      |
   |            ▼ 步骤 5: 远跳转/远返回加载 64 位代码段                               |
   |  [执行 lret / ljmp] ──► 载入 CS.L = 1 的描述符 (__KERNEL_CS)                      |
   |                         (CPU 硬件译码器正式进入 64 位原生长模式!)                 |
   |            │                                                                      |
   |            ▼ 步骤 6: 命中 64 位入口                                               |
   |  [RIP 命中 startup_64 (偏移 0x200)] ──► 开启 64 位原生汇编与 C 语言世界           |
   +-----------------------------------------------------------------------------------+

第二幕：4 级分页体系与 2MB 大页表项位域微观切片
-----------------------------------------------

为了让 CPU 在开启分页后依然能够无障碍访问所有物理内存，解压器必须在内存中手动组装 **4 级分页（4-Level Paging）** 结构。

2.1 48 位虚拟地址分解与 2MB 大页寻址
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
在 64 位架构中，48 位线性虚拟地址通过 4 级页表转换为物理地址。但在早期引导阶段，如果为每个 4KB 页面都建立第 4 级页表（PT），将消耗庞大的内存与初始化时间。因此，Linux 早期页表在 **第二级（Page Directory, PD）** 直接使用 **2MB 大页（Huge Page）** 映射：

::

   63        48 47     39 38     30 29     21 20                            0
   +-----------+---------+---------+---------+-------------------------------+
   | 符号扩展位| PML4 索引| PDPT 索引| PD 索引 | 2MB 物理页内偏移 (Offset)     |
   | (16 位)   | (9 位)   | (9 位)   | (9 位)  | (21 位, 范围 0 ~ 2MB-1)       |
   +-----------+---------+---------+---------+-------------------------------+
                     │         │         │
                     ▼         ▼         ▼
                 Level 4   Level 3   Level 2 (PS=1, 直接输出 2MB 物理页基地址!)

2.2 64 位页表项（PTE / PDE）位域微观解构
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
每个页表项占用 8 个字节（64 位）：

::

   63  62                                   52 51                   12 11   9 8 7 6 5 4 3 2 1 0
   +---+--------------------------------------+-----------------------+------+-----+-+-+-+-+-+-+
   |NX | 保留 (Reserved for OS)               | 物理基地址 [51:12]    | Ign  |G|P|D|A|P|P|U|R|P|
   |   |                                      | (4KB / 2MB 对齐)      |      | |S| | |C|W|/|/| |
   |   |                                      |                       |      | | | | |D|T|S|W| |
   +---+--------------------------------------+-----------------------+------+-----+-+-+-+-+-+-+

.. table:: 早期页表项核心控制位物理语义
   :widths: 15 20 65

   +----------------+------------------------+--------------------------------------------------------------------------------+
   | 字段名称       | 位域位置               | 硬件物理语义与参数设定                                                         |
   +================+========================+================================================================================+
   | **``P``**      | Bit 0 (Present)        | **存在标志**：1=该页在物理内存中真实存在，0=触发 #PF 缺页异常                  |
   +----------------+------------------------+--------------------------------------------------------------------------------+
   | **``R/W``**    | Bit 1 (Read/Write)     | **读写权限**：1=可读可写，0=只读                                               |
   +----------------+------------------------+--------------------------------------------------------------------------------+
   | **``U/S``**    | Bit 2 (User/Supervisor)| **特权级**：0=Ring 0/1/2 内核级访问，1=Ring 3 用户态可访问                     |
   +----------------+------------------------+--------------------------------------------------------------------------------+
   | **``PWT/PCD``**| Bits 3..4 (Cache)      | **缓存属性**：00b=标准 Write-Back (WB) 高速缓存模式                            |
   +----------------+------------------------+--------------------------------------------------------------------------------+
   | **``A / D``**  | Bits 5..6 (Access/Dirty| **访问与脏标志**：由 CPU 硬件在发生读写时自动置 1                              |
   +----------------+------------------------+--------------------------------------------------------------------------------+
   | **``PS``**     | Bit 7 (Page Size)      | **大页标志**：在 PD 层设为 1 表示当前项为 **2MB 大页**（跳过 PT 级）           |
   +----------------+------------------------+--------------------------------------------------------------------------------+
   | **``G``**      | Bit 8 (Global)         | **全局页标志**：1=TLB 刷新时不清除该项映射                                     |
   +----------------+------------------------+--------------------------------------------------------------------------------+
   | **``NX``**     | Bit 63 (No-Execute)    | **禁止执行标志**：0=允许执行机器指令                                           |
   +----------------+------------------------+--------------------------------------------------------------------------------+

.. important::
   **0x00000183 掩码的数学合成**：
   在 Level 2 (PD) 表项中，Linux 写入的控制掩码为：

   .. math::

      	ext{Flags} = 	ext{P}(0	ext{x01}) \ | \ 	ext{RW}(0	ext{x02}) \ | \ 	ext{PS}(0	ext{x80}) \ | \ 	ext{G}(0	ext{x100}) = \mathbf{0	ext{x00000183}}

   这代表一个具备 **可读写、2MB 大页、全局缓存、内核特权** 的标准物理页映射。

第三幕：2048 个 2MB 大页构建 0~4GB 恒等映射（head_64.S 逐行推导）
-----------------------------------------------------------------

在 ``arch/x86/boot/compressed/head_64.S`` 中，CPU 处于 32 位模式，利用汇编循环在 ``.pgtable`` 段中动态绘制 4 级页表。

3.1 为什么必须建立“恒等映射”（Identity Mapping）？
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
当 CPU 执行 ``movl %eax, %cr0``（开启分页）的瞬间：
* CPU 内部的指令计数器（EIP）依然存储着当前的物理基地址（如 ``0x00100080``）；
* CPU 硬件在抓取下一条指令时，会立即将 EIP 作为 **虚拟线性地址** 送入 MMU 进行页表翻译；
* **物理必然性**：如果页表中没有建立 $	ext{Virtual Address} \equiv 	ext{Physical Address}$ 的恒等映射，MMU 将无法翻译当前 PC 指针处的内存，瞬间引发三级重置（Triple Fault）导致机器闪退重启！

3.2 汇编逐级装配流水线
~~~~~~~~~~~~~~~~~~~~~~

::

   +-----------------------------------------------------------------------------------+
   |                           4 级早期页表汇编构建流水线                              |
   |                                                                                   |
   |  /* 1. 内存清零：将整个页表缓冲区 (BOOT_INIT_PGT_SIZE) 全量清零 */                 |
   |  leal    rva(pgtable)(%ebx), %edi                                                 |
   |  xorl    %eax, %eax                                                               |
   |  movl    $(BOOT_INIT_PGT_SIZE/4), %ecx                                            |
   |  rep     stosl                                                                    |
   |                                                                                   |
   |  /* 2. 构建 Level 4 (PML4): 第 0 项指向 Level 3 (PDPT) */                         |
   |  leal    rva(pgtable + 0)(%ebx), %edi                                             |
   |  leal    0x1007(%edi), %eax          /* EAX = (pgtable + 0x1000) | 0x07 (P|RW|US) */|
   |  movl    %eax, 0(%edi)               /* 写入 PML4[0] 低 32 位 */                  |
   |  addl    %edx, 4(%edi)               /* 写入高 32 位 (含 AMD SEV 加密掩码) */     |
   |                                                                                   |
   |  /* 3. 构建 Level 3 (PDPT): 4 个表项分别指向 4 个 PD 表，每项管辖 1GB */          |
   |  leal    rva(pgtable + 0x1000)(%ebx), %edi                                        |
   |  leal    0x1007(%edi), %eax          /* EAX = (pgtable + 0x2000) | 0x07 */        |
   |  movl    $4, %ecx                    /* 循环 4 次覆盖 4GB 空间 */                 |
   |  1:                                                                               |
   |  movl    %eax, 0x00(%edi)                                                         |
   |  addl    %edx, 0x04(%edi)                                                         |
   |  addl    $0x00001000, %eax           /* 下一个 PD 表偏移增加 4KB */               |
   |  addl    $8, %edi                    /* 下一个 PDPT 表项偏移增加 8 字节 */        |
   |  decl    %ecx                                                                     |
   |  jnz     1b                                                                       |
   |                                                                                   |
   |  /* 4. 构建 Level 2 (PD): 循环填充 2048 个 2MB 大页表项 (0x183 属性) */           |
   |  leal    rva(pgtable + 0x2000)(%ebx), %edi                                        |
   |  movl    $0x00000183, %eax           /* EAX = 物理基地址 0 | 0x183 (2MB 大页属性) */|
   |  movl    $2048, %ecx                 /* 2048 * 2MB = 4096MB = 4GB 覆盖! */        |
   |  1:                                                                               |
   |  movl    %eax, 0(%edi)               /* 写入当前 2MB 物理页基地址 + 属性 */       |
   |  addl    %edx, 4(%edi)                                                            |
   |  addl    $0x00200000, %eax           /* 物理基地址步进 2MB (0x200000) */          |
   |  addl    $8, %edi                    /* 页表项步进 8 字节 */                      |
   |  decl    %ecx                                                                     |
   |  jnz     1b                                                                       |
   +-----------------------------------------------------------------------------------+

通过这仅仅 20 余行汇编指令，Linux 内核在物理内存中以极其精巧的拓扑结构，瞬间构建完成了对低端 4GB 物理空间的完整线性映射！

第四幕：长模式硬件翻转与 64 位跳板（startup_64）
-------------------------------------------------

页表就绪后，``head_64.S`` 执行向 64 位长模式的最后冲刺：

4.1 寄存器连续配置流水线
~~~~~~~~~~~~~~~~~~~~~~~~
1. **加载 CR3**：``movl %eax, %cr3``（将 PML4 物理基地址写入 CPU 内存管理单元）；
2. **激活 MSR_EFER.LME**：

::

   movl    $MSR_EFER, %ecx        /* ECX = 0xC0000080 (Extended Feature Enable Register) */
   rdmsr                          /* 读出 64 位 MSR 内容至 EDX:EAX */
   btsl    $_EFER_LME, %eax       /* 将 Bit 8 (Long Mode Enable) 置 1 */
   wrmsr                          /* 回写 MSR */

3. **构建远返回跳转栈帧**：

::

   leal    rva(startup_64)(%ebp), %eax /* 计算 64 位入口 startup_64 真实物理地址 */
   pushl   $__KERNEL_CS                /* 压入 64 位代码段选择子 (0x18, L=1, D=0) */
   pushl   %eax                        /* 压入目标物理 EIP */

4. **开启分页与硬件模式突变**：

::

   movl    $CR0_STATE, %eax            /* CR0_STATE 包含 CR0.PG (Bit 31) 与 CR0.PE (Bit 0) */
   movl    %eax, %cr0                  /* 写入 CR0: 瞬间激活 MMU 分页与 IA-32e 长模式! */

   lret                                /* 32 位远返回: 弹出 0x18 与 startup_64 物理地址! */

.. danger::
   **从 32 位兼容模式向 64 位原生模式的微观跃迁**：
   * 在 ``movl %eax, %cr0`` 执行完毕后，CPU 虽已激活长模式（``EFER.LMA=1``），但由于此时 ``CS`` 寄存器中仍残留着 32 位描述符（``L=0, D=1``），CPU 实际运行在 **32 位兼容子模式（32-bit Compatibility Mode）**；
   * 紧随其后的 ``lret`` 指令从栈中弹出 ``__KERNEL_CS (0x18)``，CPU 检测到新段描述符中 ``L=1``，硬件译码逻辑瞬间切换为 **64 位长模式**，操作数与寄存器位宽全面扩展为 64 位！

第五幕：64 位原生世界的第一步——``startup_64`` 汇编初始化
--------------------------------------------------------

CPU 执行 ``lret`` 后，指令流无缝降落在 ``head_64.S`` 的 64 位代码段标号 **``startup_64 (偏移 0x200)``**：

::

   .code64
   .org 0x200
   SYM_CODE_START(startup_64)
       cld
       cli

       /* 1. 清空全部 64 位数据段选择子 (64 位模式下段基址强制为 0, 段寄存器已失效) */
       xorl    %eax, %eax
       movl    %eax, %ds; movl %eax, %es; movl %eax, %ss; movl %eax, %fs; movl %eax, %gs;

       /* 2. 将 boot_params 零页指针保存在 64 位被调用者保存寄存器 R15 中 */
       movq    %rsi, %r15

       /* 3. 设置 64 位专用解压缩栈指针 */
       leaq    rva(boot_stack_end)(%rbx), %rsp

       /* 4. 加载 64 位临时中断描述符表 (IDT) */
       call    load_stage1_idt

此时，CPU 已经全面驻留在拥有 16 个 64 位通用寄存器（RAX~R15）、48 位线性虚拟地址空间与平坦页表映射的现代 64 位计算环境中，为调用 C 语言解压函数 ``extract_kernel()`` 扫清了所有底层障碍。
