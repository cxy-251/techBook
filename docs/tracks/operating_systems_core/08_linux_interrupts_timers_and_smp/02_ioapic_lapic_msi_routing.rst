第一幕：多核中断路由中枢——Local APIC 片上中断控制器
---------------------------------------------------

在现代 x86_64 多核处理器中，每一个物理/逻辑 CPU 核心内部均集成了一个 **Local APIC（局部高级可编程中断控制器）**。

1.1 Local APIC 物理寻址演进：xAPIC (MMIO) vs x2APIC (MSR)
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

::

   +-----------------------------------------------------------------------------------+
   |                           Local APIC 寻址模式物理演进                             |
   |                                                                                   |
   |  [传统 xAPIC 模式: 4KB 物理内存映射 (MMIO)]                                       |
   |  - 基地址由 MSR_IA32_APICBASE (0x1B) 决定, 默认物理地址: 0xFEE00000               |
   |  - 访问方式: 通过内核直接映射区虚拟指针执行 readl() / writel() 内存读写            |
   |  - 硬件缺陷: APIC ID 仅为 8 位 (最多支持 255 个核心), MMIO 触发总线序列化开销大   |
   |                                                                                   |
   |  [现代 x2APIC 模式: MSR 寄存器直连 (MSR Direct Access)]                          |
   |  - 废弃 MMIO 映射, 映射至 MSR 空间 0x800 ~ 0x8FF                                 |
   |  - 访问方式: 直接通过 rdmsr / wrmsr 机器指令单时钟周期直达片上寄存器              |
   |  - 架构优势: APIC ID 扩展为 32 位 (支持上亿核心!), 读写延迟降低 60% 以上!          |
   +-----------------------------------------------------------------------------------+

1.2 Local APIC 核心控制寄存器矩阵（``arch/x86/include/asm/apicdef.h``）
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
每个 Local APIC 维护着一组至关重要的状态寄存器：

.. table:: Local APIC 核心控制寄存器位域与物理功能
   :widths: 20 25 55

   +-------------------+------------------------+------------------------------------------------------------------------------+
   | 寄存器名称        | MMIO 偏移 / MSR 编号   | 硬件物理语义与内核控制功能                                                   |
   +===================+========================+==============================================================================+
   | **``APIC_ID``**   | ``0x020`` / ``0x802``  | **Local APIC 唯一硬件 ID**：标识当前 CPU 核心在全系统中的物理拓扑编号        |
   +-------------------+------------------------+------------------------------------------------------------------------------+
   | **``APIC_TPR``**  | ``0x080`` / ``0x808``  | **任务优先级寄存器 (Task Priority)**：屏蔽所有优先级低于 TPR 的外部可屏蔽中断|
   +-------------------+------------------------+------------------------------------------------------------------------------+
   | **``APIC_EOI``**  | ``0x0B0`` / ``0x80B``  | **中断结束寄存器 (End of Interrupt)**：写入 0 触发硬件弹出当前正在服务的 ISR |
   +-------------------+------------------------+------------------------------------------------------------------------------+
   | **``APIC_SPIV``** | ``0x0F0`` / ``0x80F``  | **伪中断与使能控制**：Bit 8 置 1 开启 APIC 软件使能；Bits [7:0] 为伪中断向量 |
   +-------------------+------------------------+------------------------------------------------------------------------------+
   | **``APIC_ISR``**  | ``0x100..0x170`` (8项) | **正在服务寄存器 (In-Service)**：256 位位图，标识哪些中断已被 CPU 接收处理   |
   +-------------------+------------------------+------------------------------------------------------------------------------+
   | **``APIC_IRR``**  | ``0x200..0x270`` (8项) | **中断请求寄存器 (Request)**：256 位位图，标识哪些中断已到达但尚未被 CPU 响应|
   +-------------------+------------------------+------------------------------------------------------------------------------+
   | **``APIC_TMR``**  | ``0x180..0x1F0`` (8项) | **触发模式寄存器 (Trigger Mode)**：256 位位图，0=边沿触发，1=电平触发        |
   +-------------------+------------------------+------------------------------------------------------------------------------+
   | **``APIC_ICR``**  | ``0x300..0x310``       | **中断命令寄存器 (Interrupt Command)**：发送 IPI 核间中断、INIT-SIPI 多核唤醒|
   +-------------------+------------------------+------------------------------------------------------------------------------+

第二幕：板载南桥芯片扩展——I/O APIC 硬件架构与重定向表 (RTE)
-----------------------------------------------------------

在多核架构中，外部物理外设（如键盘、硬盘、网卡引脚）并不直接连在 CPU 上，而是接入主板南桥芯片组中的 **I/O APIC（输入输出高级可编程中断控制器）**。

2.1 I/O APIC 间接访问窗口机制（``io_apic.c``）
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
I/O APIC 芯片通常位于物理地址 ``0xFEC00000``，其硬件仅引出两个 32 位寄存器作为访问窗口：
* **``IOREGSEL (偏移 0x00)``**：索引寄存器，用于指定要操作的内部寄存器编号；
* **``IOWIN (偏移 0x10)``**：数据窗口寄存器，用于读写当前索引选中的内部寄存器值。

::

   static void io_apic_write(unsigned int apic, unsigned int reg, unsigned int value) {
       struct io_apic __iomem *io_apic = io_apic_base(apic);
       writel(reg, &io_apic->index);     /* 1. 向索引窗口写入寄存器偏移 */
       writel(value, &io_apic->data);    /* 2. 向数据窗口写入 32 位值 */
   }

2.2 64 位重定向表项（RTE 0..23）微观位域解构
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
标准 I/O APIC 包含 24 个引脚（Pin 0 ~ 23），每个引脚对应一个 64 位的 **重定向表项（Redirection Table Entry, RTE）**：

::

   63                                                            56 55                                32
   +---------------------------------------------------------------+-----------------------------------+
   | 目标 Local APIC ID (Destination ID, [63:56])                  | 保留 (Reserved)                   |
   +---------------------------------------------------------------+-----------------------------------+
   31                                17 16 15 14 13 12 11 10     8 7                                 0
   +-----------------------------------+-+--+--+--+--+--+--------+-----------------------------------+
   | 保留                              |M|T |R |P |D |D |Delivery| 分发目标中断向量号 Vector (0..255)|
   |                                   | |M |I |O |S |M |Mode(3位|                                   |
   +-----------------------------------+-+--+--+--+--+--+--------+-----------------------------------+

.. table:: I/O APIC 64 位 RTE 重定向表项关键位定义
   :widths: 15 20 65

   +----------------+------------------------+--------------------------------------------------------------------------------+
   | 字段名称       | 位域位置               | 硬件物理语义与控制功能                                                         |
   +================+========================+================================================================================+
   | **``Vector``** | Bits [7:0] (8 位)      | **目标中断向量**：该引脚触发中断时，递送给 CPU 的 IDT 向量号（``0x20 ~ 0xFE``） |
   +----------------+------------------------+--------------------------------------------------------------------------------+
   | **``DelivMode``| Bits [10:8] (3 位)     | **递送模式**：``000b``=Fixed (固定发往目标 CPU)；``001b``=Lowest Priority (最低负载)|
   +----------------+------------------------+--------------------------------------------------------------------------------+
   | **``DestMode``**| Bit 11 (1 位)         | **目标模式**：0=物理目标模式（Physical）；1=逻辑组目标模式（Logical）          |
   +----------------+------------------------+--------------------------------------------------------------------------------+
   | **``DelivStat``| Bit 12 (1 位)          | **递送状态**：0=空闲 (Idle)；1=总线发送中 (Send Pending)                       |
   +----------------+------------------------+--------------------------------------------------------------------------------+
   | **``Polarity``**| Bit 13 (1 位)         | **引脚极性**：0=高电平有效 (Active High)；1=低电平有效 (Active Low)            |
   +----------------+------------------------+--------------------------------------------------------------------------------+
   | **``RemoteIRR``| Bit 14 (1 位)          | **远程请求状态 (电平专用)**：1=已发送至 Local APIC 但尚未收到 EOI 响应         |
   +----------------+------------------------+--------------------------------------------------------------------------------+
   | **``TrigMode``**| Bit 15 (1 位)         | **触发模式**：0=边沿触发 (Edge-Triggered)；1=电平触发 (Level-Triggered)        |
   +----------------+------------------------+--------------------------------------------------------------------------------+
   | **``Mask``**   | Bit 16 (1 位)          | **屏蔽位**：1=屏蔽该引脚中断；0=使能该引脚中断                                 |
   +----------------+------------------------+--------------------------------------------------------------------------------+
   | **``DestID``** | Bits [63:56] (8 位)    | **目标 APIC ID**：接收该中断的目标 CPU 核心 Local APIC 硬件编号                |
   +----------------+------------------------+--------------------------------------------------------------------------------+

第三幕：硬件时钟时序——电平触发 vs 边沿触发与 EOI 硬件握手
---------------------------------------------------------

不同类型的外设硬件遵循截然不同的物理触发与确认协议：

::

   +-----------------------------------------------------------------------------------+
   |                       电平触发 vs 边沿触发硬件握手时序对比                        |
   |                                                                                   |
   |  [边沿触发 (Edge-Triggered) / 即发即弃模式]                                       |
   |  1. 外设引脚电平发生 0 -> 1 跳变;                                                 |
   |  2. IO-APIC 检测到上升沿，向 APIC 总线发送中断消息包;                             |
   |  3. Local APIC 将对应 Vector 的 IRR 位置 1，随后送 CPU 处理;                       |
   |  4. CPU 执行完毕后向 APIC_EOI 写 0 ──► 仅清除本核 ISR，无需与 IO-APIC 握手!       |
   |                                                                                   |
   |  [电平触发 (Level-Triggered) / 双向闭环确认模式]                                  |
   |  1. 外设持续将引脚拉低 (Active Low);                                              |
   |  2. IO-APIC 检测到低电平，置位 Remote IRR = 1，向 Local APIC 发送中断;            |
   |  3. Local APIC 记录 TMR[Vector] = 1 (标记为电平中断);                             |
   |  4. CPU 执行中断服务函数，处理外设寄存器并清除外设电平;                           |
   |  5. CPU 执行 apic_eoi() 向 APIC_EOI 写 0;                                         |
   |  6. Local APIC 检测到 TMR=1 ──► 自动向总线广播 EOI 消息!                          |
   |  7. IO-APIC 收到 EOI 广播 ──► 清除 Remote IRR = 0，允许下一次中断触发!            |
   +-----------------------------------------------------------------------------------+

3.1 Remote IRR 锁死与手动脉冲模拟容错（``ioapic_ack_level()``）
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
在某些老旧主板芯片组中，若由于硬件缺陷丢失了 EOI 广播，IO-APIC 的 ``Remote IRR`` 将永远卡在 1，导致该引脚永久静默挂死。
* **Linux 7.2 容错算法**：``ioapic_ack_level()`` 若检测到状态异常，通过软件将 RTE 触发模式强制切为边沿触发再瞬间切回电平触发（``mask+edge -> unmask+level``），在引脚上人为模拟一次假跳变，强制复位硬件 ``Remote IRR``！

第四幕：PCIe 架构的革命——MSI 与 MSI-X 消息信号中断
---------------------------------------------------

随着高速 PCIe 设备的普及，传统物理引脚（INTA#~INTD#）共享风暴成为了严重瓶颈。PCIe 规范彻底抛弃了物理引脚，引入了 **MSI / MSI-X（Message Signaled Interrupts）**。

4.1 MSI 物理工作原理：以 DMA 内存写入替代中断引脚
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
MSI 的本质是：**外设不需要任何专用中断线，而是直接向 Host 物理内存地址发起一次 32 位 DMA 写入事务！**

::

   +-----------------------------------------------------------------------------------+
   |                          PCIe MSI 消息中断物理流转模型                            |
   |                                                                                   |
   |  [PCIe 设备 (如 NVMe 控制器 / 万兆网卡)]                                          |
   |            │                                                                      |
   |            ▼ 触发中断: 向 PCIe 总线发送一次标准 Memory Write 事务                 |
   |  - 目标物理地址 (MSI Address): 0xFEE00000 | (Target_APIC_ID << 12)                |
   |  - 写入数据载荷 (MSI Data):    Vector | (Delivery_Mode << 8)                      |
   |            │                                                                      |
   |            ▼                                                                      |
   |  [PCIe 根复合物 (Root Complex / Host Bridge)]                                     |
   |  - 根复合物解码地址 0xFEE00000 ──► 识别为发往 APIC 总线的中断消息包!              |
   |            │                                                                      |
   |            ▼                                                                      |
   |  [目标 CPU 核心 Local APIC] ──► 收到数据包，直接在片上触发对应 Vector 中断!       |
   +-----------------------------------------------------------------------------------+

4.2 MSI-X 的多队列扩展与硬件绑核
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
* **MSI 限制**：每个设备最多支持 32 个连续向量，且所有向量必须使用相同的基地址；
* **MSI-X 突破**：
  * 支持高达 **2048 个独立中断向量**；
  * 每个向量在 PCIe BAR 空间的 ``MSI-X Table`` 中拥有专属的 16 字节描述符（含独立的目标地址、独立数据载荷与独立 Mask 掩码位）；
  * **网卡多队列直通（RSS / Multi-Queue）**：Linux 7.2 可将网卡的 64 个收发队列（RX/TX Queue）分别分配 64 个独立的 MSI-X 向量，每个向量精准绑定到不同的 CPU 核心上，实现真正的零锁并发中断处理！

第五幕：Linux 7.2 中断控制器驱动架构与硬件初始化全流程
------------------------------------------------------

在 ``init_IRQ() -> native_init_IRQ() -> x86_init.irqs.intr_init()`` 中，内核完成了中断控制器的拓扑建制：

::

   +-----------------------------------------------------------------------------------+
   |                           setup_IO_APIC() 硬件初始化时序                          |
   |                                                                                   |
   |  [步骤 1: 解析 ACPI MADT / MP Table]                                              |

--------------

本节深入剖析了 Local APIC 片上寄存器矩阵（xAPIC vs x2APIC）、I/O APIC 24 组 64 位 RTE 重定向表项位域、电平与边沿触发的 EOI 硬件握手时序、PCIe MSI/MSI-X 消息中断的 DMA 写入机制，以及中断控制器驱动的初始化全流程。
