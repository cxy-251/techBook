第一幕：从 CFS 到 EEVDF——调度器进化史与物理哲学
----------------------------------------------

在 Linux 内核调度器的演进长河中，通用公平调度体系经历了数次重大范式革命：
* **O(1) 调度器（Linux 2.6.0 ~ 2.6.22）**：依赖 140 个优先级队列和复杂的手工交互式启发式奖励（Interactivity Heuristics），极易被恶意构造的代码欺骗；
* **CFS 调度器（Completely Fair Scheduler, Linux 2.6.23 ~ 6.5）**：Ingo Molnar 引入了基于虚拟运行时间（``vruntime``）的红黑树调度，将 CPU 算力视为一条持续流动的流水线。

1.1 CFS 的历史局限性（公平性与延迟的不可兼得）
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
CFS 调度器的核心逻辑是：**每次挑选红黑树最左侧（``vruntime`` 最小）的任务运行**。
然而，CFS 存在一项先天的物理缺陷——**它将“公平性”（Fairness）与“响应延迟”（Latency）高度耦合在了一起**：
* 无论是吞吐密集型的批处理编译任务，还是突发高响应的 UI 渲染/音频处理线程，在 CFS 眼中都仅仅是一串单调递增的 ``vruntime``；
* 为了提升交互任务的响应速度，内核不得不引入大量的启发式微调参数（如 ``sched_min_granularity_ns``, ``sched_wakeup_granularity_ns``, ``sched_latency``）；
* 这些参数在复杂的桌面、服务器和移动端负载下相互掣肘，容易引发调度抖动（Scheduling Jitter）与音频爆音。

1.2 EEVDF 的物理哲学解耦
~~~~~~~~~~~~~~~~~~~~~~~~
Linux 7.2 全面普及的 **EEVDF（最早合格虚拟截止时间优先）** 算法，基于 Peter Hoon 1995 年的经典学术论文，在工业级内核中完成了彻底的数学重构：

::

   +-----------------------------------------------------------------------------------+
   |                           EEVDF 双维度正交控制模型                                |
   |                                                                                   |
   |  [维度一: 权重 Weight (Nice 值)] ────────► 决定长期 CPU 时间配额的【吞吐比例】     |
   |                                            (决定虚拟时钟推进的斜率 1/Weight)      |
   |                                                                                   |
   |  [维度二: 时间切片 Slice (Latency 期望)] ─► 决定单次调度的【最大响应延迟上限】     |
   |                                            (决定虚拟截止时间 Deadline 的跨度)     |
   +-----------------------------------------------------------------------------------+

通过将“吞吐分配”（Weight）与“响应延迟”（Slice）彻底解耦，EEVDF 能够原生保证低延迟任务在极短时间内得到调度，而无需依赖任何破坏公平性的外置启发式补丁！

第二幕：数学模型与积分守恒——$V$、$	ext{vruntime}$ 与 $	ext{Lag}$
-----------------------------------------------------------------

2.1 虚拟时间基准 $V$ 的数学定义
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
在一个理想的多任务流体模型（Fluid-flow Model）中，系统虚拟时间 $V$ 定义为当前所有处于运行队列中任务的加权平均虚拟运行时间：

$$V = \frac{\sum_{i=1}^N w_i \cdot v_i}{\sum_{i=1}^N w_i} = \frac{\sum_{i=1}^N w_i \cdot v_i}{W}$$

其中 $w_i$ 为任务 $i$ 的调度权重（由 Nice 值决定），$v_i$ 为该任务已消耗的虚拟运行时间（``se->vruntime``），$W$ 为当前队列总权重。

.. important::
   **Linux 7.2 防溢出相对加权基准实现（``kernel/sched/fair.c:avg_vruntime()``）**：
   由于 64 位无符号数直接累乘相加极其容易溢出，内核采用相对于锚点 $v_0$（``cfs_rq->zero_vruntime``）的差量积分公式：

   $$\mathbf{V = v_0 + \frac{\sum_{i=1}^N (v_i - v_0) \cdot w_i}{W}}$$

   内核仅维护 $	ext{sum\_w\_vruntime} = \sum (v_i - v_0) \cdot w_i$ 与 $	ext{sum\_weight} = W$，使得运算全程保持在安全数值区间内。

2.2 虚拟服务差额 $	ext{Lag}$ 积分方程与守恒定律
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
任务 $i$ 在当前时刻获得的实际服务与理想公平服务之间的差额，称为 **$	ext{Lag}$**：

$$	ext{Lag}_i = S_{	ext{ideal}} - S_{	ext{actual}} = w_i \cdot (V - v_i)$$

为了简化计算，内核在代码中直接追踪 **虚拟滞后量（Virtual Lag / ``vlag``）**：

$$\mathbf{vlag}_i = V - v_i = \mathbf{avg\_vruntime} - v_i$$

::

   +-----------------------------------------------------------------------------------+
   |                           Lag 数值物理状态机全景                                  |
   |                                                                                   |
   |  Lag_i > 0 (v_i < V)  ──► 系统【欠】该任务 CPU 时间 (落后于平均线，具备运行资格)   |
   |  Lag_i = 0 (v_i = V)  ──► 绝对公平点 (Perfect Parity)                             |
   |  Lag_i < 0 (v_i > V)  ──► 该任务【透支】了 CPU 时间 (超前于平均线，丧失运行资格)   |
   +-----------------------------------------------------------------------------------+

根据数学推导，整个系统的 Lag 具备神圣的 **零和守恒定律**：

$$\sum_{i=1}^N 	ext{Lag}_i = \sum_{i=1}^N w_i \cdot (V - v_i) = V \cdot W - \sum_{i=1}^N w_i \cdot v_i \equiv 0$$

2.3 资格判定准则（Eligibility Rule / ``entity_eligible``）
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
在 EEVDF 的宪章中，一个进程要想被 CPU 调度执行，**必须首先通过资格判定**：
* 只有当系统欠该进程时间（即 $	ext{Lag}_i \ge 0 \iff v_i \le V$）时，该进程才被判定为 **合格（Eligible）**；
* 如果一个进程在上一轮运行中过度透支了时间片导致 $v_i > V$（$	ext{Lag}_i < 0$），在系统平均虚拟时钟 $V$ 追赶上来之前，该进程**绝对禁止参与调度竞争**！

第三幕：虚拟截止时间（Virtual Deadline）与抢占时机
---------------------------------------------------

3.1 虚拟截止时间计算公式
~~~~~~~~~~~~~~~~~~~~~~~~
当一个任务申请了长度为 $q_i$ 的物理时间片（Slice，默认 ``sysctl_sched_base_slice = 0.70ms``）时，其对应的虚拟时间跨度为：

$$	ext{vslice}_i = \frac{q_i}{w_i} = \mathbf{calc\_delta\_fair}(q_i, w_i)$$

该任务本次调度的 **虚拟截止时间（Virtual Deadline / $d_i$）** 即为：

$$\mathbf{d_i = v_i + 	ext{vslice}_i = v_i + \frac{q_i}{w_i}}$$

::

   +-----------------------------------------------------------------------------------+
   |                       虚拟截止时间 d_i 的几何与物理意义                           |
   |                                                                                   |
   |  [任务 A (交互式/低延迟)]: 申请极短切片 q_A = 0.1ms ──► d_A = v_A + 0.1/w_A (极早)|
   |  [任务 B (批处理/高吞吐)]: 申请标准切片 q_B = 10ms  ──► d_B = v_B + 10/w_B  (较晚)|
   |                                                                                   |
   |  在同等资格 (v_A ≈ v_B ≤ V) 下:                                                   |
   |  ► EEVDF 优先挑出截止时间最早的【任务 A】执行，达成微秒级极致响应!                |
   +-----------------------------------------------------------------------------------+

3.2 运行消耗与截止时间更新（``update_deadline()``）
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
当当前运行任务在 CPU 上消耗物理时间 $\Delta t$ 时：
1. ``update_curr()`` 将其虚拟时间推进：$v_i \leftarrow v_i + \frac{\Delta t}{w_i}$；
2. 当 $v_i \ge d_i$ 时，表明该任务已经完整消耗了本轮申请的切片配额；
3. ``update_deadline()`` 立即为该任务计算下一周期的截止时间：$d_i \leftarrow v_i + 	ext{vslice}_i$，并触发 ``resched_curr_lazy()`` 请求重新调度。

第四幕：增强型红黑树（Augmented RB-Tree）与 $O(\log N)$ 极速决策
----------------------------------------------------------------

如果要在成百上千个就绪进程中找到“**所有 Eligible 任务中 Deadline 最小的那一个**”，最朴素的做法是遍历所有进程，时间复杂度高达 $O(N)$，这对于每秒发生上万次调度的操作系统是不可接受的。

4.1 双重特性的增强型红黑树（Augmented RB-Tree）
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
Linux 7.2 将红黑树（RB-Tree）与小顶堆（Heap）特性融为一体：
1. **红黑树主键（Primary Key）**：严格按照 **虚拟截止时间 $d_i$** 升序排列（最左侧节点 ``rb_leftmost`` 拥有全局最小的 Deadline）；
2. **增强型堆属性（Augmented Subtree Minimum）**：每个节点额外维护一个字段 **``min_vruntime``**，记录以该节点为根的整棵子树中所有节点的**最小虚拟运行时间**：

$$\mathbf{node->min\_vruntime = \min(se->vruntime,\ left->min\_vruntime,\ right->min\_vruntime)}$$

4.2 ``pick_eevdf()`` 剪枝决策状态机（``mm/sched/fair.c``）
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

::

   +-----------------------------------------------------------------------------------+
   |                     pick_eevdf() O(log N) 剪枝搜索微观流水线                      |
   |                                                                                   |
   |  struct sched_entity *se = __pick_first_entity(cfs_rq); /* 最左侧节点 */         |
   |                                                                                   |
   |  /* 1. 极速快径: 如果全局 Deadline 最早的节点刚好 Eligible (v_se <= V) */          |
   |  if (se && entity_eligible(cfs_rq, se))                                           |
   |      return se; /* 100% 最优解，常数级 O(1) 直接返回! */                          |
   |                                                                                   |
   |  /* 2. 树搜索慢径: 从根节点开始利用 min_vruntime 执行分治剪枝 */                  |
   |  while (node) {                                                                   |
   |      struct rb_node *left = node->rb_left;                                        |
   |                                                                                   |
   |      /* 判据 A: 左子树中是否存在具备资格 (Eligible) 的节点? */                    |
   |      if (left && vruntime_eligible(cfs_rq, __node_2_se(left)->min_vruntime)) {     |
   |          node = left; /* 左子树的 Deadline 必定比当前节点和右子树更早，向左深入! */|
   |          continue;                                                                |
   |      }                                                                            |
   |                                                                                   |
   |      se = __node_2_se(node);                                                      |
   |      /* 判据 B: 左子树完全无合格者，检查当前节点本身是否 Eligible */              |
   |      if (entity_eligible(cfs_rq, se)) {                                           |
   |          best = se; /* 当前节点就是全树中合格且 Deadline 最早的节点! */           |
   |          break;                                                                   |
   |      }                                                                            |
   |                                                                                   |
   |      /* 判据 C: 当前节点亦不合格，只能向右子树探索 */                             |
   |      node = node->rb_right;                                                       |
   |  }                                                                                |
   +-----------------------------------------------------------------------------------+

通过 ``min_vruntime`` 剪枝，调度器可以在 $O(\log N)$（通常仅需 3~5 次指针寻址）时间内精准定位到最优进程！

第五幕：延时出队（DELAY_DEQUEUE）与防作弊机制
----------------------------------------------

5.1 经典的“负 Lag 睡眠作弊漏洞”
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
在旧版调度机制中，存在一个著名的公平性漏洞：
1. 进程 $P$ 疯狂占用 CPU 运行了 10ms，导致其虚拟时间大幅超前，$v_P \gg V$（$	ext{Lag}_P \ll 0$ 严重负债）；
2. 进程 $P$ 随后调用 ``nanosleep(1us)`` 主动让出 CPU 进入休眠；
3. 如果出队时直接将 $P$ 移出调度器，当它在 1 微秒后苏醒时，调度器会将其重新对齐到当前基准线 $V$；
4. **作弊达成**：进程 $P$ 透支的巨额负 Lag 被彻底“洗白”，从而反复恶意霸占 CPU！

5.2 ``DELAY_DEQUEUE`` 延时出队硬核防御机制
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
Linux 7.2 引入了 **``DELAY_DEQUEUE`` 状态机**（由 ``sched_feat(DELAY_DEQUEUE)`` 控制）：

::

   +-----------------------------------------------------------------------------------+
   |                       DELAY_DEQUEUE 防作弊状态机时序                              |
   |                                                                                   |
   |  [负 Lag 任务进入睡眠 (dequeue_entity)]                                           |
   |  1. 检查条件: 若任务处于负债状态 (!entity_eligible 即 Lag < 0):                    |
   |     ► 拒绝将其真正从红黑树物理摘除!                                               |
   |     ► 标记 se->sched_delayed = 1 (进入延时出队虚影状态);                          |
   |     ► 该任务不再被调度执行，但其权重依然留在 cfs_rq 中参与平均虚拟时间 V 的演进;  |
   |            │                                                                      |
   |            ▼                                                                      |
   |  [随时间推移，其他就绪任务运行，系统虚拟时钟 V 持续推进]                          |
   |  2. 直到系统时钟 V 追赶上该任务的 v_i (Lag 负债自然清零，恢复 Eligible):          |
   |     ► 调度器在 pick 或 tick 时顺手将其物理摘除 (真正出队);                        |
   |     ► 彻底粉碎高频短睡眠偷窃 CPU 时间的投机漏洞!                                 |
   +-----------------------------------------------------------------------------------+

小结与下章导读
--------------

本节深入剖析了 Linux 7.2 EEVDF 调度器的数学与算法全景：从 CFS 到 EEVDF 的物理哲学解耦、加权平均虚拟时钟 $V$ 与相对差量积分、$	ext{Lag}$ 零和守恒定律与 Eligible 资格判定准则、虚拟截止时间 $d_i$ 与时间片调节、增强型红黑树（Augmented RB-Tree）结合 ``min_vruntime`` 的 $O(\log N)$ 剪枝搜索，以及 ``DELAY_DEQUEUE`` 延时出队防作弊机制。

EEVDF 完美统治了通用普通进程（``SCHED_NORMAL`` / ``SCHED_BATCH``）的公平世界。但在操作系统中，还存在着对执行时间有严苛硬性约束的实时进程与内核抢占体系。

在 **第 6 节：实时调度策略 (FIFO/RR)、SCHED_DEADLINE 与 Linux 内核抢占机制 (PREEMPT_DYNAMIC)** 中，我们将深入剖析实时优先级队列（``rt_rq``）、基于最早截止时间优先的硬实时算法（``SCHED_DEADLINE``）、动态内核抢占（``PREEMPT_NONE``, ``PREEMPT_VOLUNTARY``, ``PREEMPT_FULL``）的运行时切换，以及抢占计数器 ``preempt_count`` 的底层硬件时序。
