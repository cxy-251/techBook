第一幕：Linux x86 引导协议演进与 32 位保护模式交接基准
-------------------------------------------------------

为了让不同的引导加载器（GRUB2、Syslinux、QEMU Direct Kernel Boot）能够统一加载任何版本的 Linux 内核，Linux 社区制定了严格的 **x86 引导协议标准（Documentation/arch/x86/boot.rst）**。

1.1 引导协议版本的物理演进
~~~~~~~~~~~~~~~~~~~~~~~~~~
* **Protocol 1.0 (zImage 时代)**：内核被硬性限制在 512KB 以内，必须从实模式 ``0x1000:0000`` 载入，无法支持现代大内核；
* **Protocol 2.02 ~ 2.07 (bzImage 与 32 位平坦引导)**：引入 ``LOADED_HIGH`` 标志，允许内核映像直接放置在 1MB（``0x100000``）以上物理内存，突破低端内存限制；
* **Protocol 2.10 ~ 2.15+ (现代 64 位与 KASLR 时代)**：引入 ``XLF_KERNEL_64``、``XLF_CAN_BE_LOADED_ABOVE_4G`` 与重定位元数据，支持 64 位直接交接与内核地址空间布局随机化。

1.2 32 位保护模式引导交接基准（32-bit Boot Protocol Standard）
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
当 GRUB2 完成参数装配并准备交接给内核解压器时，必须满足以下不可违背的物理硬件约束：

::

   +-----------------------------------------------------------------------------------+
   |                       32 位保护模式 Linux Boot Protocol 寄存器铁律                |
   |                                                                                   |
   |  - CR0 控制寄存器:   CR0.PE = 1 (开启保护模式), CR0.PG = 0 (分页必须关闭!)         |
   |  - A20 地址总线:     物理引脚必须强制导通 (内存访问不得发生 1MB 回绕)             |
   |  - GDT 段选择子:     CS 为平坦 4GB 代码段 (Base=0, Limit=4GB, DPL=0, Type=0x9A)   |
   |                      DS = ES = FS = GS = SS 为平坦 4GB 数据段 (Type=0x92)         |
   |  - RFLAGS 寄存器:    RFLAGS.IF = 0 (全局关闭外部硬件中断)                         |
   |  - ESI 寄存器:       严格指向物理内存中填充就绪的 struct boot_params 结构体基地址 |
   |  - EAX, EBX, ECX, EDX, EBP: 必须严格清零 (0x00000000)                             |
   |  - EIP 跳转目标:     内核解压缩入口地址 (默认为 0x00100000, 即 1MB 物理地址)       |
   +-----------------------------------------------------------------------------------+

第二幕：512 字节 ``struct setup_header`` 核心字段微观切片
---------------------------------------------------------

在 ``linux-7.2-rc1/arch/x86/include/uapi/asm/bootparam.h`` 中，内核头部的 512 字节区域定义了引导加载器与内核握手的核心契约：

::

   +-----------------------------------------------------------------------------------+
   |                     struct setup_header 内存布局与偏移切片                        |
   |                                                                                   |
   |  偏移地址    字段类型    字段名称              硬件物理语义与协议定义             |
   +===================================================================================+
   |  0x01FE      __u16       boot_flag             引导扇区魔数 (固定为 0xAA55)       |
   |  0x0200      __u16       jump                  2 字节短跳转指令 (0xEB, 0x??)      |
   |  0x0202      __u32       header                协议魔法签名: 0x53726448 ("HdrS")  |
   |  0x0206      __u16       version               引导协议版本号 (如 0x020F = v2.15) |
   |  0x0210      __u8        type_of_loader        加载器标识 (0x72 = GRUB2)          |
   |  0x0211      __u8        loadflags             加载控制标志 (Bit 0: LOADED_HIGH)  |
   |  0x0214      __u32       code32_start          32 位内核入口地址 (默认 0x100000)  |
   |  0x0218      __u32       ramdisk_image         initrd 内存盘 32 位物理起始基地址  |
   |  0x021C      __u32       ramdisk_size          initrd 内存盘字节大小              |
   |  0x0228      __u32       cmd_line_ptr          内核命令行字符串的 32 位物理指针   |
   |  0x022C      __u32       initrd_addr_max       initrd 允许放置的最高物理地址上限  |
   |  0x0230      __u32       kernel_alignment      内核重定位对齐粒度 (通常 2MB)      |
   |  0x0234      __u8        relocatable_kernel    1=内核支持 KASLR 物理重定位        |
   |  0x0236      __u16       xloadflags            扩展标志 (XLF_KERNEL_64, XLF_5LEVEL|
   |  0x0238      __u32       cmdline_size          命令行字符串最大支持长度 (如 2048) |
   |  0x0244      __u64       pref_address          内核推荐首选装载物理基地址 (16MB)  |
   |  0x024C      __u32       init_size             内核解压运行时所需连续内存总大小   |
   |  0x0250      __u32       handover_offset       EFI Handover 引导协议入口偏移      |
   +-----------------------------------------------------------------------------------+

.. important::
   **"HdrS" 签名校验律**：
   GRUB2 在读取内核文件时，首先检查偏移 ``0x202`` 处的 4 字节整数是否严格等于 ``0x53726448``（ASCII ``"HdrS"``）。若不匹配，表明该文件不是合法的 x86 Linux 内核镜像，加载器立即中断并报错 ``"invalid magic number"``。

第三幕：4096 字节 ``struct boot_params``（零页 Zero Page）全景内存拓扑
-----------------------------------------------------------------------

在引导过程中，引导加载器必须在内存中分配一个 4096 字节（1 个标准页）的物理缓冲区，将整机的硬件拓扑、固件参数与启动配置全量打包。这个结构体被称为 **``struct boot_params``（业界俗称“零页 Zero Page”）**。

3.1 零页的核心物理子系统分布
~~~~~~~~~~~~~~~~~~~~~~~~~~~~

::

   物理内存 4096 字节 (0x000 ~ 0xFFF)
   0x000 ┌────────────────────────────────────────────────────────┐
         │ struct screen_info (64 字节): 文本光标 / 显存基址 / 分辨率 |
   0x040 ├────────────────────────────────────────────────────────┤
         │ struct apm_bios_info (20 字节): APM 电源管理参数       │
   0x070 ├────────────────────────────────────────────────────────┤
         │ acpi_rsdp_addr (8 字节): 64 位 ACPI RSDP 物理基地址    │
   0x140 ├────────────────────────────────────────────────────────┤
         │ struct edid_info (128 字节): 监视器 EDID 物理分辨率参数 │
   0x1C0 ├────────────────────────────────────────────────────────┤
         │ struct efi_info (32 字节): UEFI 系统表与内存映射指针   │
   0x1E8 ├────────────────────────────────────────────────────────┤
         │ e820_entries (1 字节): E820 内存拓扑条目总数           │
   0x1EF ├────────────────────────────────────────────────────────┤
         │ sentinel (1 字节): 哨兵魔数 (0xFF, 用于防越界校验)     │
   0x1F1 ├────────────────────────────────────────────────────────┤
         │ struct setup_header hdr (包含上一幕解构的 512 字节头部)│
   0x2D0 ├────────────────────────────────────────────────────────┤
         │                                                        │
         │ struct boot_e820_entry e820_table[128] (2560 字节)     │
         │ (全机物理内存拓扑切片，记录所有可用 RAM 与保留区)      │
         │                                                        │
   0xCD0 ├────────────────────────────────────────────────────────┤
         │ 保留扩展区与 EDD 磁盘签名缓冲区                        │
   0x1000└────────────────────────────────────────────────────────┘

第四幕：命令行（Cmdline）与 E820 内存图注入微观流水线
-----------------------------------------------------

在 ``grub-core/loader/i386/linux.c`` 中，GRUB2 执行精密的内存装配逻辑。

4.1 命令行字符串的物理注入
~~~~~~~~~~~~~~~~~~~~~~~~~~
1. GRUB2 解析 ``grub.cfg`` 中传递给内核的完整参数（如 ``"root=UUID=... ro quiet splash console=tty0"``）；
2. 调用 ``grub_malloc()`` 分配连续物理内存页（如物理地址 ``0x00091000``）；
3. 将字符串以 ``\0`` 结尾拷贝至该内存区域；
4. 将该物理基地址写入零页：
   $$	ext{boot\_params.hdr.cmd\_line\_ptr} \leftarrow 	ext{0x00091000}$$
   $$	ext{boot\_params.ext\_cmd\_line\_ptr} \leftarrow (	ext{0x00091000} \gg 32)$$

4.2 E820 物理内存图向内核的注入
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
内核必须知道物理内存中哪些区域已被占用，以防在解压自身或初始化伙伴系统时覆盖掉自身或 initramfs：
1. GRUB2 读取此前从 BIOS ``INT 15h, AX=E820h`` 获取的物理内存清单；
2. 过滤并按地址升序排列，逐项填充进零页的 ``boot_params.e820_table[]`` 数组；
3. 将有效条目总数写入 ``boot_params.e820_entries``（最大支持 128 项）。

第五幕：向 Linux 内核交付控制权的最终时序——从 GRUB2 到 startup_32
------------------------------------------------------------------

在所有物理数据结构装配就绪后，内存拓扑呈现如下最终就绪状态：

::

   +-----------------------------------------------------------------------------------+
   |                           交接前物理内存全局镜像布局                              |
   |                                                                                   |
   |  物理地址范围                数据结构名称与物理承载内容                           |
   +===================================================================================+
   |  0x00000000 ~ 0x000003FF     保留实模式 IVT (1KB)                                |
   |  0x00000400 ~ 0x000004FF     保留实模式 BDA (256B)                               |
   |  0x00090000 ~ 0x00090FFF     struct boot_params (零页 Zero Page, 4KB)             |
   |  0x00091000 ~ 0x00091FFF     Kernel Command Line (命令行字符串)                   |
   |  0x00100000 ~ 0x01FFFFFF     vmlinuz 压缩内核映像主体 (1MB 以上, 起始为 startup_32)|
   |  0x07000000 ~ 0x08FFFFFF     initramfs (初始内存盘 CPIO 压缩归档, ~32MB)          |
   +-----------------------------------------------------------------------------------+

5.1 最终汇编跃迁指令序列（``grub_linux_boot``）
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
GRUB2 执行不可逆的长跳转汇编指令：

::

   /* 32 位保护模式汇编 */
   movl    $0x00090000, %esi      /* ESI 指向 struct boot_params 物理基地址 */
   xorl    %eax, %eax             /* 遵循协议：清空全部通用寄存器 */
   xorl    %ebx, %ebx
   xorl    %ecx, %ecx
   xorl    %edx, %edx
   xorl    %ebp, %ebp

   /* 物理长跳转：直接冲入 1MB 处的内核解压器入口! */
   movl    $0x00100000, %edi
   jmpl    *%edi

当 ``jmpl *%edi`` 指令执行的瞬间，CPU 硬件正式跨越了引导加载程序与操作系统内核之间的楚河汉界：
* **GRUB2 的历史使命彻底终结**；
* **Linux 7.2 内核正式登场，开启汇编级解压缩与长模式穿越！**

小结与下章导读
--------------

本节深入剖析了 Linux x86 Boot Protocol 引导契约、512 字节 ``setup_header`` 字段语义、4096 字节 ``boot_params`` 零页拓扑，以及命令行和 E820 内存图注入内核的微观时序。

在控制权交由 ``0x100000`` 处的内核代码之前，引导加载器还需要将庞大的内核容器 ``vmlinuz`` 与内存盘 ``initramfs`` 完整装载进物理内存。

在 **第 6 节：``vmlinuz`` 容器结构解构、``vmlinux.bin`` 与 initramfs/initrd 物理内存装载** 中，我们将深入剖析 ``vmlinuz`` 的文件容器格式（包含 setup.bin 与 vmlinux.bin）、PE/COFF 头部嵌入机制，以及 initramfs 在高端物理内存中的连续对齐装载时序，为模块 04 画上圆满句号。
