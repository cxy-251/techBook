========================================================================================
第 1 节：MBR Stage 1 (boot.S) 446 字节机器码极限空间与跳转 diskboot.S
========================================================================================

.. note::
   **前置背景与上下文承接**
   * **体系结构基准**：承接模块 03 第 7 节中关于 SeaBIOS 固件完成全部加电自检（POST）与硬件建制后，通过 ``INT 19h`` 将磁盘 0 扇区装载至物理内存 ``0x00007C00`` 并以 16 位实模式跳转执行的物理状态。
   * **核心使命**：解构计算机从固件向全功能操作系统引导器（GRUB2）跨越的第一道极窄隘口；剖析 MBR（Master Boot Record）512 字节中 446 字节机器码区、64 字节 DPT 分区表与 2 字节 ``0x55AA`` 签名的严苛物理布局；深入 GRUB2 源码 ``grub-core/boot/i386/pc/boot.S`` 与 ``diskboot.S``，逐行解构寄存器初始化、LBA 扩展支持嗅探（``INT 13h, AH=41h``）、DAP 磁盘地址包动态装配、CHS 几何回退计算，以及如何将第 1 扇区起的 ``diskboot.S``（Stage 1.5）载入物理内存 ``0x8000`` 并交接控制权的微观时序。

----------------------------------------------------------------------------------------

第一幕：512 字节物理牢笼——MBR 扇区空间分配的微观切片
---------------------------------------------------

当 BIOS 将控制权交由磁盘第 0 扇区时，CPU 面临的是计算机工业史上最严苛的空间约束——**主引导记录 (Master Boot Record, MBR)**。

1.1 MBR 512 字节绝对物理结构
~~~~~~~~~~~~~~~~~~~~~~~~~~~~
MBR 的 512 字节空间在物理上被严格切割为三个功能区域：

::

   物理内存 0x00007C00
   0x0000 ┌────────────────────────────────────────────────────────┐
          │                                                        │
          │ GRUB2 Stage 1 引导机器码 (boot.S 编译产物)             │
          │ 大小: 446 字节 (0x000 ~ 0x1BD)                         │
          │                                                        │
   0x01BE ├────────────────────────────────────────────────────────┤
          │ 分区表项 1 (16 字节): 引导标志 / 起止 CHS / 起始 LBA / 扇区数 |
   0x01CE ├────────────────────────────────────────────────────────┤
          │ 分区表项 2 (16 字节)                                   │
   0x01DE ├────────────────────────────────────────────────────────┤
          │ 分区表项 3 (16 字节)                                   │
   0x01EE ├────────────────────────────────────────────────────────┤
          │ 分区表项 4 (16 字节)                                   │
   0x01FE ├────────────────────────────────────────────────────────┤
          │ 引导有效性魔法签名: 0x55, 0xAA (2 字节, 0x1FE ~ 0x1FF)  │
   0x0200 └────────────────────────────────────────────────────────┘

1.2 446 字节的极限工程挑战
~~~~~~~~~~~~~~~~~~~~~~~~~~
在仅仅 446 字节的机器指令限制内，GRUB2 的 Stage 1 必须以 16 位实模式汇编完成以下一系列精密动作：
1. 清除方向标志，重置全部段寄存器为标准基址 0；
2. 建立临时调用栈；
3. 保存并校验 BIOS 通过 ``DL`` 寄存器传入的物理启动磁盘编号；
4. 探测主板 BIOS 是否支持扩展 LBA 寻址；
5. 若支持 LBA，动态在内存中构造 16 字节 DAP（磁盘地址包）并发起 ``INT 13h, AH=42h`` 读盘；
6. 若不支持 LBA，读取磁盘 CHS 几何参数，在 16 位模式下执行 32 位模除换算，发起 ``INT 13h, AH=02h`` 读盘；
7. 输出引导失败调试错误字符串；
8. 精准跳转至载入内存的第二阶段代码入口。

----------------------------------------------------------------------------------------

第二幕：GRUB2 Stage 1 (boot.S) 汇编入口与环境初始化
---------------------------------------------------

在 GRUB2 源码 ``grub-core/boot/i386/pc/boot.S`` 中，Stage 1 的执行从标号 ``_start`` 开始：

::

   +-----------------------------------------------------------------------------------+
   |                         boot.S 启动初期寄存器归一化时序                           |
   |                                                                                   |
   |  .code16                                                                          |
   |  .globl _start; _start:                                                           |
   |      cli                         /* 1. 关中断，防止初始化栈期间产生硬件中断 */    |
   |                                                                                   |
   |      /* 2. 防御性长跳转：规范化 CS 寄存器为 0x0000 */                            |
   |      ljmp $0, $real_start                                                         |
   |                                                                                   |
   |  real_start:                                                                      |
   |      xorw %ax, %ax                                                                |
   |      movw %ax, %ds               /* DS <= 0x0000 */                               |
   |      movw %ax, %ss               /* SS <= 0x0000 */                               |
   |      movw $GRUB_BOOT_MACHINE_STACK_SEG, %sp /* SP <= 0x2000 (安全低端栈) */       |
   |                                                                                   |
   |      sti                         /* 3. 栈与段就绪，重新开中断 */                  |
   |      cld                         /* 清除方向标志 (字符串操作递增) */              |
   |                                                                                   |
   |      /* 4. 保存 BIOS 传递的物理启动盘号 (DL 寄存器) */                            |
   |      movb %dl, boot_drive                                                         |
   +-----------------------------------------------------------------------------------+

2.1 软驱与硬盘驱动器号探测与修正
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
在标准 PC 体系中：
* ``DL = 0x00 ~ 0x7F`` 代表软盘驱动器（Floppy Drive）；
* ``DL = 0x80 ~ 0xFF`` 代表硬盘驱动器（Hard Disk Drive 0, 1, ...）。
如果某些老旧 BIOS 没有正确设置 ``DL``，``boot.S`` 会检查硬编码在镜像中的默认盘号，确保后续读盘时传递给 ``INT 13h`` 的目标驱动器号绝对可靠。

第三幕：LBA 扩展探测与 DAP 磁盘地址包动态装配
---------------------------------------------

为了加载后续存放在磁盘上的 ``core.img`` 镜像，``boot.S`` 必须从磁盘读取下一个扇区（Sector 1，即 ``diskboot.S``）。

3.1 探测 BIOS 扩展中断支持（``check_lba``）
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
在 ``boot.S`` 中，GRUB 首先尝试嗅探 BIOS 是否支持扩展 INT 13h 接口：

::

   check_lba:
       movb $0x41, %ah             /* AH=0x41: 扩展安装检查 (Extensions Installation Check) */
       movw $0x55aa, %bx           /* BX=0x55AA (特定魔数) */
       movb boot_drive, %dl        /* DL=目标磁盘号 */
       int  $0x13                  /* 发起 BIOS 中断 */
       
       jc   chs_mode               /* 若 CF=1 (不支持扩展)，跳转降级至 CHS 传统模式 */
       cmpw $0xaa55, %bx           /* 检查 BX 是否被 BIOS 覆写为 0xAA55 */
       jne  chs_mode
       testb $1, %cl               /* 检查 CL Bit 0 是否置 1 (固定磁盘包访问能力) */
       jz   chs_mode

3.2 动态构建 16 字节 DAP 数据包（``lba_mode``）
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
一旦确认支持 LBA，``boot.S`` 立即在内存中动态装配一个标准的 16 字节 **DAP (Disk Address Packet)**：

::

   +-----------------------------------------------------------------------------------+
   |                           DAP 磁盘地址包在内存中的装配                            |
   |                                                                                   |
   |  /* 在局部内存区写入 DAP 字段 */                                                  |
   |  movl $0x00010010, (%si)     /* 字节 0=0x10 (DAP大小), 字节 2..3=0x0001 (读1扇区) */|
   |  movw $GRUB_BOOT_MACHINE_BUFFER_SEG, 4(%si) /* 字节 4..5=0x8000 (目标偏移) */      |
   |  movw $0x0000, 6(%si)        /* 字节 6..7=0x0000 (目标段基址: 0x0000:0x8000) */   |
   |  movl kernel_sector, %eax    /* 读取 core.img 起始 LBA 扇区号低 32 位 (通常为 1) */ |
   |  movl %eax, 8(%si)           /* 字节 8..11 = LBA 低 32 位 */                       |
   |  movl kernel_sector_high, %eax                                                    |
   |  movl %eax, 12(%si)          /* 字节 12..15 = LBA 高 32 位 (64 位绝对寻址) */      |
   |                                                                                   |
   |  movb $0x42, %ah             /* AH=0x42 (Extended Read 扩展读扇区) */             |
   |  movb boot_drive, %dl                                                             |
   |  int  $0x13                  /* 发起扩展磁盘读取! */                               |
   +-----------------------------------------------------------------------------------+

通过扩展 INT 13h，磁盘第 1 扇区的 512 字节内容被硬件直接写入物理内存 **``0x00008000``** 处。

第四幕：传统 CHS 几何回退与 32 位模除时钟时序
---------------------------------------------

如果运行在不支持 LBA 的古老硬件上，``boot.S`` 将执行复杂的 CHS 几何换算分支（``chs_mode``）。

4.1 探测磁盘几何参数
~~~~~~~~~~~~~~~~~~~~
调用 ``INT 13h, AH=0x08`` 读取磁盘物理几何参数：
* ``DH``：最大磁头号（$	ext{Heads} = 	ext{DH} + 1$）；
* ``CL[5:0]``：每磁道最大扇区数（$	ext{SPT} = 	ext{CL} \ \& \ 0	ext{x3F}$）。

4.2 16 位实模式下的 32 位 LBA 转换算法
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
在 16 位实模式下，由于没有 64 位除法器，汇编代码必须通过两次连续的 ``DIV`` 指令分解 32 位 LBA 扇区号：

::

   /* 设待读取的 LBA 扇区号为 N (32 位) */
   1. 计算扇区号 (Sector) 与临时商 (Temp):
      Sector = (N % SPT) + 1
      Temp   = N / SPT

   2. 计算磁头号 (Head) 与柱面号 (Cylinder):
      Head     = Temp % Heads
      Cylinder = Temp / Heads

   3. 组装寄存器发起 INT 13h, AH=0x02 传统读盘:
      CL <= (Sector & 0x3F) | ((Cylinder >> 2) & 0xC0)
      CH <= (Cylinder & 0xFF)
      DH <= Head
      ES:BX <= 0x0000:0x8000

第五幕：跳转 Stage 1.5 (diskboot.S) 与 MBR Gap 空间
---------------------------------------------------

当第 1 扇区被成功载入物理内存 ``0x00008000`` 后，Stage 1 的使命行将结束。

5.1 物理跃迁至 ``0x0000:0x8000``
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
在 ``boot.S`` 的最末尾，代码执行间接跳转指令：

::

   /* kernel_address 在编译时被硬编码为 0x8000 */
   jmp *(kernel_address)

此时 CPU 硬件寄存器状态：
* ``CS:IP = 0x0000:0x8000``；
* ``DL = boot_drive``（启动磁盘号）；
* CPU 保持在 **16 位实模式**，正式进入 Stage 1.5 引导程序——**``diskboot.S``**！

5.2 ``diskboot.S`` 的物理使命与 MBR Gap（后 MBR 间隙）
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
为什么 GRUB2 不直接在 MBR 中加载整个操作系统内核，而要引入 ``diskboot.S`` 与 ``core.img``？

::

   +-----------------------------------------------------------------------------------+
   |                             磁盘物理扇区空间布局 (MBR Gap)                        |
   |                                                                                   |
   |  扇区 0 (LBA 0):  MBR 引导扇区 (512 字节, 包含 boot.S 与分区表)                  |
   |  ──────────────────────────────────────────────────────────────────────────────── |
   |  扇区 1 (LBA 1):  diskboot.S (512 字节, Stage 1.5 入口)                           |
   |  扇区 2 ~ 62:     core.img 剩余压缩数据 (LZMA 解压引擎 + 内核基础模块 + 文件系统驱动)|
   |                   (总容量约 30KB ~ 1MB, 驻留在 MBR 与第 1 分区之间的 MBR Gap 中)   |
   |  ──────────────────────────────────────────────────────────────────────────────── |
   |  扇区 2048 起:    第一个主分区 (Primary Partition 1, 如 Linux /boot 分区)         |
   +-----------------------------------------------------------------------------------+

* **MBR Gap（后 MBR 间隙）的物理本质**：
  * 在传统 MBR 分区方案中，为了满足 1MB（2048 扇区）柱面边界对齐，第一个主分区通常从 **LBA 2048** 开始；
  * 因此在 LBA 1 到 LBA 2047 之间存在约 **1MB 的物理未分配空闲空间**；
  * GRUB2 将体积庞大（约 30KB ~ 60KB）的 **核心镜像（``core.img``）** 嵌入（Embedding）到这片宝贵的 MBR Gap 空间中！

5.3 ``diskboot.S`` 的微观加载状态机
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
驻留在物理内存 ``0x8000`` 的 ``diskboot.S`` 包含一个精巧的 **块列表循环加载器（Blocklist Reader）**：
1. 解析嵌入在其末尾的 **块列表（Block List）**（记录了 ``core.img`` 剩余扇区的连续 LBA 起点与扇区数）；
2. 循环调用 ``INT 13h``，将剩余的数十个扇区连续读入物理内存 ``0x8200`` 及以上空间；
3. 当 ``core.img`` 全部扇区加载完毕后，``diskboot.S`` 跳转进入 ``core.img`` 的自解压头部，正式开启向 **32 位保护模式的第一次历史性跃迁**！

小结与下章导读
--------------

本节深入剖析了 MBR 512 字节物理结构、GRUB2 Stage 1（``boot.S``）在 446 字节极限空间内的汇编流水线、LBA 扩展探测与 DAP 动态装配、CHS 模除回退时序，以及向 MBR Gap 中 ``diskboot.S (0x8000)`` 的物理跃迁。

在 ``diskboot.S`` 将完整的 ``core.img`` 镜像读入内存后，计算机将告别简陋的单扇区汇编时代，迎来全功能引导加载器的现代软件架构。
