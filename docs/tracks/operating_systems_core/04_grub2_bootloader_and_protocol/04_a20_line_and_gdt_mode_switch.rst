第一幕：从 1MB 枷锁到 4GB 平坦世界——保护模式跃迁的物理必然性
-------------------------------------------------------------

在计算机引导链条中，实模式（Real Mode）是 1978 年 Intel 8086 处理器的历史遗存。当系统准备加载现代 Linux 7.2 内核时，实模式成为了必须彻底粉碎的物理桎梏：

::

   +-----------------------------------------------------------------------------------+
   |                             实模式 vs 保护模式物理能力对比                        |
   |                                                                                   |
   |  [16 位实模式 (Real Mode)]                       [32 位保护模式 (Protected Mode)] |
   |  - 地址总线有效位宽: 20 位                       - 地址总线有效位宽: 32 位        |
   |  - 物理内存寻址上限: 1MB (0x000000..0x0FFFFF)   - 物理内存寻址上限: 4GB (0x0..0xFFFFFFFF)
   |  - 指令操作数与寄存器位宽: 默认为 16 位          - 指令操作数与寄存器位宽: 默认为 32 位
   |  - 寻址机制: 段基址 * 16 + 偏移量 (固定 64KB 界限)- 寻址机制: GDT 描述符基址 + 线性偏移
   |  - 特权级支持: 无 (全部代码均具有最高硬件权限)   - 特权级支持: 硬件 Ring 0 ~ Ring 3 隔离
   +-----------------------------------------------------------------------------------+

1.1 现代 Linux 内核的物理内存装载诉求
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
现代 Linux 内核镜像（``vmlinuz``）即便经过 LZMA/Zstd 极限压缩，体积通常仍在 10MB ~ 25MB 之间，解压缩后的内核映像（``vmlinux``）更是高达 50MB ~ 80MB，加上数十兆字节的初始内存盘（``initramfs``），必须直接装载在物理内存 **``0x01000000 (16MB)``** 或更高的平坦高位物理地址空间。

因此，引导加载器（GRUB2）必须将 CPU 彻底推入 **32 位平坦保护模式（Flat Protected Mode）**，使数据段与代码段能够无障碍读写完整的 4GB 物理内存。

----------------------------------------------------------------------------------------

第二幕：全局描述符表 (GDT) 物理内存拓扑与描述符位域编码
-------------------------------------------------------

在保护模式下，段寄存器（CS, DS, ES, SS, FS, GS）中存放的不再是物理段基址，而是指向 **全局描述符表（Global Descriptor Table, GDT）** 的 16 位 **段选择子（Segment Selector）**。

2.1 8 字节标准段描述符（Segment Descriptor）位域微观解构
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
GDT 中的每个表项占用 8 个字节（64 位），其位域排布体现了 x86 体系结构为了向后兼容 80286 而设计的复杂交错结构：

::

   63      56 55 54 53 52 51    48 47 46 45 44 43    40 39        32
   +---------+--+--+--+--+--------+--+-----+--+--------+------------+
   | Base    |G |D |L |A | Limit  |P | DPL |S |  Type  | Base       |  高 32 位
   | 31..24  |  |/B|  |V | 19..16 |  |     |  |        | 23..16     |
   +---------+--+--+--+--+--------+--+-----+--+--------+------------+
   31                                     16 15                    0
   +----------------------------------------+-----------------------+
   |              Base 15..0                |      Limit 15..0      |  低 32 位
   +----------------------------------------+-----------------------+

.. table:: GDT 段描述符核心控制位物理语义
   :widths: 15 20 65

   +----------------+------------------------+--------------------------------------------------------------------------------+
   | 字段名称       | 位域位置               | 硬件物理语义与参数设定                                                         |
   +================+========================+================================================================================+
   | **``Base``**   | 32 位分散字段          | 段在线性地址空间中的起始物理基地址（在平坦模式下恒等于 ``0x00000000``）        |
   +----------------+------------------------+--------------------------------------------------------------------------------+
   | **``Limit``**  | 20 位分散字段          | 段寻址的最大偏移上限（在 4GB 平坦模式下设为 ``0xFFFFF``）                      |
   +----------------+------------------------+--------------------------------------------------------------------------------+
   | **``G``**      | Bit 55 (Granularity)   | **粒度标志**：0=段界限以 1 字节为单位（最大 1MB）；1=以 4KB 为单位（最大 4GB）|
   +----------------+------------------------+--------------------------------------------------------------------------------+
   | **``D/B``**    | Bit 54 (Default Size)  | **默认操作数大小**：1=32 位代码/数据段（默认 32 位操作数与 ESP）；0=16 位     |
   +----------------+------------------------+--------------------------------------------------------------------------------+
   | **``L``**      | Bit 53 (Long Mode)     | **64 位代码段标志**：0=32 位兼容/保护模式代码段；1=64 位长模式 (IA-32e) 代码段 |
   +----------------+------------------------+--------------------------------------------------------------------------------+
   | **``P``**      | Bit 47 (Present)       | **段存在标志**：1=该段在物理内存中真实存在，0=访问触发 #NP 段不存在异常        |
   +----------------+------------------------+--------------------------------------------------------------------------------+
   | **``DPL``**    | Bits 46..45            | **描述符特权级**：00b=Ring 0（最高内核特权），11b=Ring 3（用户特权）          |
   +----------------+------------------------+--------------------------------------------------------------------------------+
   | **``Type``**   | Bits 43..40            | **段属性类型**：``0x9A`` (代码段, 可执行/可读), ``0x92`` (数据段, 可读/可写)   |
   +----------------+------------------------+--------------------------------------------------------------------------------+

2.2 GRUB2 核心 GDT 拓扑表构建（``grub-core/kern/i386/realmode.S``）
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
在 ``realmode.S`` 中，GRUB2 静态构建了 5 个核心段描述符构成的 GDT 表：

::

   .p2align 5                      /* 强制 32 字节自然边界对齐 */
   gdt:
       /* 描述符 0 (选择子 0x00): 空描述符 (Null Descriptor, 硬件要求必须全 0) */
       .word 0, 0
       .byte 0, 0, 0, 0

       /* 描述符 1 (选择子 0x08: GRUB_MEMORY_MACHINE_PROT_MODE_CSEG): 32 位平坦代码段 */
       /* Base = 0x00000000, Limit = 0xFFFFF, G=1(4KB), D=1(32-bit), DPL=0, Type=0x9A */
       .word 0xFFFF, 0
       .byte 0, 0x9A, 0xCF, 0

       /* 描述符 2 (选择子 0x10: GRUB_MEMORY_MACHINE_PROT_MODE_DSEG): 32 位平坦数据段 */
       /* Base = 0x00000000, Limit = 0xFFFFF, G=1(4KB), B=1(32-bit), DPL=0, Type=0x92 */
       .word 0xFFFF, 0
       .byte 0, 0x92, 0xCF, 0

       /* 描述符 3 (选择子 0x18: GRUB_MEMORY_MACHINE_PSEUDO_REAL_CSEG): 16 位实模式代码段 */
       /* Base = 0x00000000, Limit = 0x0FFFF, G=0(1B), D=0(16-bit), DPL=0, Type=0x9E */
       .word 0xFFFF, 0
       .byte 0, 0x9E, 0, 0

       /* 描述符 4 (选择子 0x20: GRUB_MEMORY_MACHINE_PSEUDO_REAL_DSEG): 16 位实模式数据段 */
       /* Base = 0x00000000, Limit = 0x0FFFF, G=0(1B), B=0(16-bit), DPL=0, Type=0x92 */
       .word 0xFFFF, 0
       .byte 0, 0x92, 0, 0

   gdtdesc:
       .word 0x27                  /* GDT 界限 Limit = 5 * 8 - 1 = 39 字节 */
       .long gdt                   /* GDT 32 位物理线性基地址 */

第三幕：``real_to_prot`` 模式跃迁微观汇编时钟时序
-------------------------------------------------

当 GRUB2 需要从实模式跃迁进入保护模式时，调用汇编桩 ``real_to_prot``。该函数执行了不可中断的硬件状态机翻转。

3.1 模式切换四大原子时钟步骤
~~~~~~~~~~~~~~~~~~~~~~~~~~~~

::

   +-----------------------------------------------------------------------------------+
   |                           real_to_prot 模式跃迁流水线                             |
   |                                                                                   |
   |  .code16                                                                          |
   |  real_to_prot:                                                                    |
   |      /* 步骤 1：关全局硬件中断 */                                                 |
   |      cli                                                                          |
   |                                                                                   |
   |      /* 步骤 2：加载 GDTR 寄存器 */                                               |
   |      xorw    %ax, %ax                                                             |
   |      movw    %ax, %ds                                                             |
   |      lgdtl   gdtdesc             /* 将 48 位 GDT 指针载入 CPU 片内 GDTR 寄存器 */ |
   |                                                                                   |
   |      /* 步骤 3：置位控制寄存器 CR0.PE (开启保护模式) */                           |
   |      movl    %cr0, %eax                                                           |
   |      orl     $GRUB_MEMORY_CPU_CR0_PE_ON, %eax /* Bit 0 (PE) 置 1 */               |
   |      movl    %eax, %cr0          /* 硬件状态机瞬间翻转为保护模式! */              |
   |                                                                                   |
   |      /* 步骤 4：长跳转冲刷流水线 (Far Jump to 32-bit Code Segment) */              |
   |      ljmpl   $GRUB_MEMORY_MACHINE_PROT_MODE_CSEG, $protcseg                       |
   |                                                                                   |
   |  .code32                                                                          |
   |  protcseg:                                                                        |
   |      /* 步骤 5：加载 32 位平坦数据段选择子 (0x10) */                              |
   |      movw    $GRUB_MEMORY_MACHINE_PROT_MODE_DSEG, %ax                             |
   |      movw    %ax, %ds; movw %ax, %es; movw %ax, %fs; movw %ax, %gs; movw %ax, %ss; |
   |                                                                                   |
   |      /* 步骤 6：双栈切换模型 (实模式栈 -> 保护模式栈) */                          |
   |      movl    (%esp), %eax                                                         |
   |      movl    %eax, GRUB_MEMORY_MACHINE_REAL_STACK /* 备份实模式返回地址 */        |
   |      movl    protstack, %eax                                                      |
   |      movl    %eax, %esp; movl %eax, %ebp          /* 切换为 32 位专用大栈 */      |
   |      movl    GRUB_MEMORY_MACHINE_REAL_STACK, %eax                                 |
   |      movl    %eax, (%esp)                         /* 将返回地址推入新栈 */        |
   |                                                                                   |
   |      /* 步骤 7：屏蔽中断描述符表 (加载空 IDT) */                                  |
   |      sidt    LOCAL(realidt)      /* 备份实模式 IVT (Limit=0x400, Base=0) */       |
   |      lidt    protidt             /* 加载保护模式 IDT (Limit=0, 拦截意外中断) */   |
   |                                                                                   |
   |      xorl    %eax, %eax                                                           |
   |      ret                         /* 在 32 位保护模式栈上正常返回调用者! */        |
   +-----------------------------------------------------------------------------------+

.. danger::
   **流水线冲刷长跳转（``ljmpl $0x08, $protcseg``）的硬件物理意义**：
   * 在执行 ``movl %eax, %cr0`` 之后，CPU 内部的译码单元仍然填充着此前在 16 位实模式下预取的后续指令字节序列；
   * 如果此时直接顺序执行下一条指令，CPU 将错误地以 16 位语法解析 32 位机器码，引发不可逆崩溃；
   * **硬件清洗效应**：``ljmpl $0x08, $protcseg`` 指令强制清空 CPU 全部预取队列与指令流水线，重新从 ``CS.Base + protcseg`` 抓取指令，并将代码段寄存器的隐藏属性缓存（Descriptor Cache）完整刷新为 32 位可读可执行属性！

第四幕：``prot_to_real`` 逆向保护模式切回实模式
-----------------------------------------------

在引导过程中，GRUB2 并非一去不复返地留在保护模式。为了调用 BIOS 中断读取磁盘后续数据或响应键盘按键，GRUB2 频繁调用 ``prot_to_real`` 逆向穿透回实模式。

4.1 逆向穿透的微观时序
~~~~~~~~~~~~~~~~~~~~~~
在 ``src/kern/i386/realmode.S:prot_to_real`` 中：

1. **重置数据段界限为 64KB**：
   * 将数据段选择子加载为 16 位实模式描述符 ``GRUB_MEMORY_MACHINE_PSEUDO_REAL_DSEG (0x20)``（Limit = 64KB）；
   * 这一步是为了防止切回实模式后，段描述符缓存残留 4GB 界限引发不可控行为；
2. **恢复实模式中断向量表**：
   * 执行 ``lidt LOCAL(realidt)``，恢复基地址为 ``0x00000000``、界限为 ``0x03FF`` 的传统 IVT；
3. **切换回实模式调用栈**：
   * 保存当前保护模式栈指针至 ``protstack``，将 ``ESP`` 切换回 ``GRUB_MEMORY_MACHINE_REAL_STACK``；
4. **清除 ``CR0.PE`` 位**：
   * ``movl %cr0, %eax; andl $~1, %eax; movl %eax, %cr0;``；
5. **实模式流水线冲刷长跳转**：
   * 执行 ``ljmpl $0, $realcseg``；
   * 强制将 ``CS`` 选择子恢复为 ``0x0000``，段基址恢复为实模式的 $	ext{CS} 	imes 16$ 寻址逻辑；
6. **归零数据段寄存器并开中断**：
   * 将 ``DS, ES, FS, GS, SS`` 归零，执行 ``sti`` 重新允许外部硬件中断响应。

第五幕：向 Linux 内核交接前的最终硬件就绪状态
----------------------------------------------

通过上述机制，GRUB2 构建了一个在 16 位实模式（访问 BIOS）与 32 位保护模式（操作 4GB 内存与执行 C 语言引擎）之间随意穿梭的自由通道。

当用户在引导菜单中按下回车，GRUB2 从磁盘读取完 ``vmlinuz`` 与 ``initramfs`` 并完成协议装配后，将执行最后的 **不可逆模式跃迁（Final Irreversible Transition）**：

::

   +-----------------------------------------------------------------------------------+
   |                       向 Linux 7.2 内核交接前的绝对硬件物理状态                   |
   |                                                                                   |
   |  1. A20 地址线: 硬件引脚强制导通 (物理内存 1MB 以上完全线性平坦)                  |
   |  2. CPU 运行模式: 32 位平坦保护模式 (CR0.PE = 1, CR0.PG = 0 分页未开启)           |
   |  3. GDT 描述符: CS = 0x10 (4GB 可执行代码段), DS = SS = 0x18 (4GB 可读写数据段)   |
   |  4. 中断状态: 全局关中断 (RFLAGS.IF = 0, IDT 无效化)                              |
   |  5. 寄存器参数装配 (遵循 32 位 Linux Boot Protocol):                              |
   |     - ESI = 物理基地址 (指向内存中填充好的 struct boot_params 结构体, 如 0x90000) |
   |     - EIP = 0x00100000 (跳转至 1MB 处的内核解压缩入口 startup_32 / head_64.S)     |
   +-----------------------------------------------------------------------------------+
