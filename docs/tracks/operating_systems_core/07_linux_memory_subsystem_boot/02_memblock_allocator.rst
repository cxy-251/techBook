第一幕：早期内存分配的基石——``struct memblock`` 数据结构全景
--------------------------------------------------------------

在内核启动早期，伙伴系统尚未建立，内核无法使用 ``alloc_pages()`` 或 ``kmalloc()``。为了追踪哪些物理内存可以分配、哪些物理内存已被占用，Linux 内核设计了极简而高效的 **``memblock`` 早期物理内存分配器**。

1.1 ``struct memblock`` 双核心拓扑结构
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
``memblock`` 分配器的核心数据结构定义在 ``include/linux/memblock.h`` 中：

::

   +-----------------------------------------------------------------------------------+
   |                            struct memblock 全景数据拓扑                           |
   |                                                                                   |
   |  struct memblock {                                                                |
   |      bool bottom_up;                   /* 分配方向: false=自顶向下, true=自底向上 */  |
   |      phys_addr_t current_limit;        /* 当前分配可访问的最大物理地址上限 */      |
   |                                                                                   |
   |      struct memblock_type memory;      /* 记录全系统所有物理可用 RAM 内存块 */     |
   |      struct memblock_type reserved;    /* 记录所有已被内核或硬件占用的保留内存块 */|
   |  };                                                                               |
   |                                                                                   |
   |  struct memblock_type {                                                           |
   |      unsigned long cnt;                /* 当前已记录的区间数量 (Region Count) */   |
   |      unsigned long max;                /* 当前数组可容纳的最大区间数 (Capacity) */ |
   |      phys_addr_t total_size;           /* 当前类型所管辖的物理内存总字节数 */      |
   |      struct memblock_region *regions;  /* 指向物理区间描述符数组的指针 */          |
   |      char *name;                       /* 调试名称 ("memory" 或 "reserved") */     |
   |  };                                                                               |
   |                                                                                   |
   |  struct memblock_region {                                                         |
   |      phys_addr_t base;                 /* 该区间的物理起始基地址 */                |
   |      phys_addr_t size;                 /* 该区间的物理连续字节长度 */              |
   |      enum memblock_flags flags;        /* 属性标志 (HOTPLUG / NOMAP / MIRROR 等) */ |
   |      int nid;                          /* 所属 NUMA 节点编号 (Node ID) */          |
   |  };                                                                               |
   +-----------------------------------------------------------------------------------+

1.2 静态初始数组与自举生命线
~~~~~~~~~~~~~~~~~~~~~~~~~~~~
在编译期，内核为 ``memblock.memory`` 与 ``memblock.reserved`` 各静态分配了一个大小为 **``INIT_MEMBLOCK_REGIONS``（通常为 128 或 512 项）** 的全局数组：
* 这确保在没有物理内存管理器的上电第一毫秒内，``memblock`` 就能依靠静态 BSS 内存直接展开工作。

第二幕：区间插入、重叠相交与同类合并算法（``memblock_add_range``）
-------------------------------------------------------------------

当内核向 ``memblock`` 注册一段物理内存（通过 ``memblock_add()`` 或 ``memblock_reserve()``）时，调用底层核心函数 **``memblock_add_range()``**。

2.1 物理区间相交的几何关系与裁剪状态机
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
新插入的物理区间 $[B_{	ext{new}}, B_{	ext{new}} + S_{	ext{new}}]$ 与既有已按基地址升序排列的区间集合存在复杂的重叠可能：

::

   +-----------------------------------------------------------------------------------+
   |                        物理区间插入的 4 种几何相交情形                            |
   |                                                                                   |
   |  情形 1: 完全独立 (Disjoint)                                                      |
   |  既有区间: [  Region A  ]                                                         |
   |  新插区间:                   [  Region B  ] ──► 直接执行二分查找按地址升序插入    |
   |                                                                                   |
   |  情形 2: 端点重叠 (Partial Overlap)                                               |
   |  既有区间: [    Region A    ]                                                     |
   |  新插区间:           [    Region B    ]     ──► 扩展 Region A 尾部边界            |
   |                                                                                   |
   |  情形 3: 包含子集 (Subset)                                                        |
   |  既有区间: [       Region A       ]                                               |
   |  新插区间:     [  Region B  ]               ──► 吸收合并，无需新增条目            |
   |                                                                                   |
   |  情形 4: 跨越多个既有区间 (Multi-region Span)                                     |
   |  既有区间: [ Reg A ]   [ Reg B ]   [ Reg C ]                                      |
   |  新插区间:    [─────────────────────────]   ──► 吞并中间区间并扩展整体边界!       |
   +-----------------------------------------------------------------------------------+

2.2 ``memblock_merge_regions()`` 原子合并算法
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
完成插入与裁剪后，算法遍历整个数组：
* 若发现 $	ext{base}_i + 	ext{size}_i == 	ext{base}_{i+1}$ 且二者的 ``flags`` 与 ``nid`` 严格相同；
* 算法将两个区间合并为一个：$	ext{size}_i \leftarrow 	ext{size}_i + 	ext{size}_{i+1}$，并将后续元素前移覆盖；
* 这一过程保证了数组中**绝不存在相互接触且属性相同的冗余碎片**。

第三幕：物理内存分配核心算法——自顶向下 vs 自底向上
---------------------------------------------------

当内核子系统向 ``memblock`` 申请一块物理内存时（如 ``memblock_alloc(size, align)``），分配器必须在可用内存中找到未被保留的连续物理页。

3.1 为什么现代 Linux 默认优先使用“自顶向下”（Top-Down）分配？
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
* **低端内存的战略价值**：在 x86_64 体系下，低端内存具备极其特殊的硬件约束（如 16MB 以下为传统 ISA DMA 区域，4GB 以下为 32 位 PCI/PCIe 设备寻址空间，640KB 以下为 CPU 实模式跳板区）；
* **自顶向下保护策略**：``memblock`` 默认从物理内存的**最高可用地址向下搜索**（Top-Down），优先将高端内存（如 64GB 顶部）分配给内核常规数据结构，将宝贵的 4GB 以下低端物理空间完好保留给后续的设备驱动与 DMA 缓冲区。

3.2 ``for_each_free_mem_range`` 差集搜索状态机
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
``memblock`` 分配物理内存的数学本质是求解可用内存与保留内存的 **物理集合差**：

$$	ext{Allocatable\_Memory} = 	ext{memblock.memory} \setminus 	ext{memblock.reserved}$$

::

   +-----------------------------------------------------------------------------------+
   |                     memblock 物理差集双指针扫描状态机                             |
   |                                                                                   |
   |  [memblock.memory]   [───────────────────── Memory Chunk ─────────────────────]   |
   |                                                                                   |
   |  [memblock.reserved]        [── Resv 1 ──]                 [── Resv 2 ──]         |
   |                                                                                   |
   |  [计算所得空闲区间]  [ Free 1 ]          [───── Free 2 ─────]            [ Free 3 ]|
   |                                                                                   |
   |  - 自顶向下遍历: 优先检查 Free 3 是否满足 size 与 align 对齐要求;                 |
   |  - 若 Free 3 空间不足，则依次回退检查 Free 2、Free 1;                             |
   |  - 选定物理地址后，立即调用 memblock_reserve() 将该物理块划入 reserved 数组!      |
   +-----------------------------------------------------------------------------------+

第四幕：左脚踩右脚的自举奇迹——``memblock_double_array()`` 动态扩容
-------------------------------------------------------------------

在物理内存碎片极多的复杂机器上，静态预留的 128 或 512 个区间条目可能在早期耗尽。此时内核面临一个经典的自举悖论：**没有通用内存分配器，如何动态扩大 memblock 自身数组？**

4.1 动态自翻倍扩容算法微观全流程
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

::

   +-----------------------------------------------------------------------------------+
   |                       memblock_double_array() 自举扩容流水线                      |
   |                                                                                   |
   |  [检测条件: type->cnt >= type->max (当前数组容量耗尽)]                            |
   |            │                                                                      |
   |            ▼ 1. 内存自寻址                                                        |
   |  - 计算新数组所需字节大小: new_size = type->max * 2 * sizeof(struct memblock_region);|
   |  - 调用内部函数 memblock_find_in_range() 在当前空闲内存中寻找一块 new_size 物理内存;|
   |            │                                                                      |
   |            ▼ 2. 内存数据克隆                                                      |
   |  - 获取新物理内存的直接映射虚拟地址: new_array = __va(new_addr);                  |
   |  - 将旧数组内容完整 memcpy 拷贝至 new_array;                                      |
   |            │                                                                      |
   |            ▼ 3. 指针替换与自我锁定                                                |
   |  - type->regions = new_array;                                                     |
   |  - type->max = type->max * 2;                                                     |
   |  - 调用 memblock_reserve(new_addr, new_size) 将新数组自身所在的物理内存锁定!      |
   |            │                                                                      |
   |            ▼ 4. 释放旧数组 (若旧数组也是此前动态分配的)                           |
   |  - memblock_free(old_addr, old_size);                                             |
   +-----------------------------------------------------------------------------------+

通过这套巧妙的“用自身的空闲物理页扩充自身的元数据”机制，``memblock`` 彻底打破了早期内存管理的自举死锁，支持无限扩展物理内存拓扑条目！

第五幕：物理内存分配 API 与向后续子系统的供血
----------------------------------------------

``memblock`` 构建完成后，成为整个内核在 ``start_kernel()`` 阶段唯一的物理内存分配中枢。

5.1 核心对外分配 API 家族
~~~~~~~~~~~~~~~~~~~~~~~~~
* **``memblock_alloc(size, align)``**：
  在系统可用内存中分配指定大小并满足自然对齐的物理内存，内部自动将其锁定进 ``memblock.reserved``，并调用 ``memset(0)`` 清零后返回其虚拟地址（``__va(phys)``）；
* **``memblock_alloc_low(size, align)``**：
  强制在 **4GB 以下低端物理内存** 中分配，专供实模式跳板、SMP 启动栈与 ISA 设备使用；
* **``memblock_alloc_node(size, align, nid)``**：
  在指定的 NUMA 节点物理内存块中执行局部就近分配。

5.2 ``memblock`` 对后续内存子系统的核心供血清单
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
1. **直接映射页表供血**：为下一节 ``init_mem_mapping()`` 分配构建全物理内存直接映射（``PAGE_OFFSET``）所需的全部 4 级/5 级页表页（PGD/P4D/PUD/PMD/PTE）；
2. **``vmemmap`` 核心供血**：为描述全系统物理页的庞大 ``struct page`` 结构体数组（数十 GB 内存需消耗数百 MB 元数据）分配物理内存；
3. **多核 Per-CPU 供血**：为每个 CPU 核心分配独立的变量副本物理内存；
4. **伙伴系统交接**：在 ``start_kernel() -> mm_core_init()`` 阶段，``memblock`` 会将剩余所有未被保留的空闲物理页整页释放给伙伴系统的各个 Free List，随后功成身退！

小结与下章导读
--------------

本节深入剖析了 ``memblock`` 早期物理内存分配器的双数组管理拓扑（``memory`` vs ``reserved``）、物理区间相交裁剪与同类合并算法、自顶向下与自底向上的差集搜索状态机、动态自翻倍扩容算法（``memblock_double_array``），以及其对早期内核核心结构的供血机制。
