第一幕：全架构通用内核中枢——``start_kernel()`` 宏观启动时序全景
--------------------------------------------------------------

当 CPU 在 ``x86_64_start_kernel()`` 的引导下完成底层汇编与早期架构建制后，指令流正式迈入全架构通用的 C 语言总入口——**``init/main.c:start_kernel()``**：

::

   +-----------------------------------------------------------------------------------+
   |                           start_kernel() 全景时钟时序流水线                       |
   |                                                                                   |
   |  [阶段 1: 栈安全金丝雀与 CPU 基础环境锁定]                                        |
   |  - set_task_stack_end_magic(&init_task): 写入 0x57AC6E9D 栈溢出金丝雀魔数         |
   |  - smp_setup_processor_id() / boot_cpu_init(): 标记当前 CPU 0 为引导核 (BSP)      |
   |  - local_irq_disable(): 确保中断处于关闭状态                                      |
   |  - pr_notice("%s", linux_banner): 向控制台输出 Linux 7.2 官方启动标语             |
   |            │                                                                      |
   |            ▼ 阶段 2: 架构级专属硬件建制 (全系统最核心初始化)                      |
   |  - setup_arch(&command_line): E820 内存图解析、memblock 早期分配器、页表扩建      |
   |  - setup_boot_config() / setup_command_line(): 解析内核启动命令行参数             |
   |  - setup_per_cpu_areas(): 为每个 CPU 核心动态克隆独立的 Per-CPU 物理内存          |
   |  - smp_prepare_boot_cpu(): 准备多核 SMP 上电上下文                                |
   |            │                                                                      |
   |            ▼ 阶段 3: 中断体系与核心子系统建制                                     |
   |  - trap_init(): 初始化架构专属硬件陷阱门                                          |
   |  - mm_core_init(): 激活物理内存伙伴系统 (Buddy System) 与核心内存管理器           |
   |  - sched_init(): 初始化 EEVDF 调度器核心拓扑与 runqueues 运行队列                 |
   |  - rcu_init(): 启动 RCU (Read-Copy Update) 无锁同步中枢                           |
   |  - early_irq_init() / init_IRQ(): 挂载 IO-APIC / Local APIC 硬件中断控制器       |

   |            ▼ 阶段 4: 细粒度对象分配器与虚拟文件系统上线                           |

1.1 栈底金丝雀防护机制（``STACK_END_MAGIC``）
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
在进入复杂函数调用前，内核第一件事是调用 ``set_task_stack_end_magic(&init_task)``：
* **栈底魔数注入**：向 0 号进程 16KB 内核栈的最底端 8 字节写入魔数 **``0x57AC6E9D``**；
* **溢出熔断检测**：在每次发生任务切换、中断嵌套或栈展开（Stack Unwind）时，内核通过 ``try_get_task_stack()`` 校验栈底数值。一旦递归调用导致栈指针越界侵蚀栈底，魔数被破坏，系统立即触发 Kernel Panic，阻止内存被静默污染。

第三幕：E820 内存图清洗、对齐与去重算法（``e820__memory_setup``）
-----------------------------------------------------------------

虽然 BIOS 在 POST 阶段构建了 E820 内存图，但引导加载器传递的数据往往存在重叠（Overlap）、未对齐或超界隐患。

3.1 扫描线算法（Sweep-line Algorithm）内存清洗（``arch/x86/kernel/e820.c``）
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
在 ``sanitize_e820_map()`` 中，内核采用扫描线算法对所有区间端点进行排序与裁决：

::

   +-----------------------------------------------------------------------------------+
   |                           E820 区间冲突裁决优先级铁律                             |
   |                                                                                   |
   |  高优先级 ──► [E820_TYPE_RESERVED (2): 硬件/固件保留区]                           |
   |                 │ (高优先级完全覆盖低优先级)                                      |
   |                 ▼                                                                 |
   |               [E820_TYPE_NVS (4): ACPI 非易失存储区]                              |
   |                 │                                                                 |
   |                 ▼                                                                 |
   |               [E820_TYPE_ACPI (3): ACPI 可回收表区]                              |
   |                 │                                                                 |
   |  低优先级 ──►   ▼                                                                 |
   |               [E820_TYPE_RAM (1): 常规可用物理内存]                               |
   +-----------------------------------------------------------------------------------+

* **区间裁决与对齐**：当发现一段 ``E820_TYPE_RAM`` 与一段 ``E820_TYPE_RESERVED`` 发生物理相交时，算法自动将 RAM 区间截断拆分为不重叠的子段，确保保留区绝对不被标记为可用 RAM；
* **物理边界合并**：将清洗后相邻且类型完全相同的物理区间合并为一个单一的大区间。

第四幕：早期固定映射 (early_ioremap) 与 ACPI 早期扫描
-----------------------------------------------------

在完整的虚拟内存分配器（``ioremap()``）建立之前，内核需要读取物理内存中由 BIOS 留下的 ACPI 表格（如 MADT 获取多核 Local APIC ID 与 IO-APIC 基地址）。

4.1 ``early_ioremap`` 槽位轮转机制（``arch/x86/mm/ioremap.c``）
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
内核在虚拟地址空间的顶端预留了一组专用的 **Fixmap 固定映射槽位（``FIX_BTMAP_BASE``）**：
1. 当调用 ``early_memremap(phys_addr, size)`` 时，内核在 Fixmap 区域选取一个空闲的虚拟页槽位；
2. 将 ``phys_addr`` 填入该槽位对应的早期页表项（PTE），并刷新本地 TLB；
3. 内核即可通过该虚拟槽位地址直接读取物理内存中的 ACPI 表头；
4. 读取完毕后立即调用 ``early_memunmap()`` 解除映射，释放槽位供后续设备复用。

4.2 ``acpi_boot_table_init()`` 硬件中枢嗅探
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
借助 ``early_memremap``，内核读取 RSDP 根指针并展开全局 ACPI 表格树：
* **解析 MADT**：提取所有在线 CPU 核心的 APIC ID，确定多核 SMP 拓扑并分配逻辑 CPU 编号；
* **解析 FADT / DSDT**：获取电源管理端口（PM1a/PM1b）、ACPI 事件中断号（SCI）与主板硬件控制方法。

第五幕：物理内存生命线交接——``e820__memblock_setup()``
------------------------------------------------------

在 E820 内存图清洗完毕后，内核将其正式转交接给启动阶段的物理内存总管——**``memblock`` 早期物理内存分配器**。

5.1 ``memblock`` 的两大核心物理数组
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
在 ``arch/x86/kernel/e820.c:e820__memblock_setup()`` 中：

::

   /* 1. 注册全系统所有物理可用 RAM 内存块 */
   for (i = 0; i < e820_table->nr_entries; i++) {
       struct e820_entry *entry = &e820_table->entries[i];
       if (entry->type != E820_TYPE_RAM)
           continue;
       memblock_add(entry->addr, entry->size);
   }

   /* 2. 注册所有绝对不可分配的保留物理内存区 */
   for (i = 0; i < e820_table->nr_entries; i++) {
       struct e820_entry *entry = &e820_table->entries[i];
       if (entry->type == E820_TYPE_RAM)
           continue;
       memblock_reserve(entry->addr, entry->size);
   }

   /* 3. 锁定运行期内核关键资产区 */
   memblock_reserve(__pa_symbol(_text), _end - _text);        /* 内核自身镜像 */
   memblock_reserve(boot_params.hdr.ramdisk_image, boot_params.hdr.ramdisk_size); /* initramfs */
   memblock_reserve(__pa(boot_params_ptr), sizeof(boot_params)); /* 零页数据 */

通过这三组核心操作，全机物理内存被清晰划分出“可分配区”与“绝对保护区”，为随后的内核早期页表全面展开与伙伴系统诞生铸就了坚不可摧的物理基石。

小结与下章导读
--------------

本节深入剖析了全架构通用内核中枢 ``start_kernel()`` 的宏观启动时钟时序、``setup_arch()`` 架构级硬件建制、E820 内存图扫描线清洗去重算法、``early_ioremap`` 早期固定映射与 ACPI 扫描，以及向 ``memblock`` 分配器的历史交接。
