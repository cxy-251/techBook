第一幕：异步通知的基石哲学——传统信号 vs POSIX 实时信号
------------------------------------------------------

信号（Signal）是操作系统内核向应用程序传递异步事件的软件中断机制。在 Linux 7.2 内核中，信号体系严密划分为两大阵营：

1.1 传统标准信号（Standard Signals: 1 ~ 31）
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
* **设计起源**：源自早期 UNIX 系统（如 ``SIGHUP``, ``SIGINT``, ``SIGKILL``, ``SIGSEGV``）；
* **位掩码管理**：在内核中仅通过一个 64 位无符号整数（``sigset_t``）的特定 Bit 表示；
* **不可靠性（Unreliable / 信号合并）**：如果同一信号在处于未决（Pending）状态期间被多次发送给同一进程，内核只会将对应 Bit 置 1 一次，**后续重复信号被直接丢弃**；且标准信号无法附带任何额外数据载荷。

1.2 POSIX 实时信号（Real-Time Signals: 32 ~ 64）
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
* **设计起源**：由 POSIX.1b 实时扩展标准引入（``SIGRTMIN`` 到 ``SIGRTMAX``）；
* **双向链表排队**：每个信号以独立的 ``struct sigqueue`` 结构体挂载在未决链表上；
* **可靠性（Reliable / 保证排队）**：支持多次发送并严格按 FIFO 顺序排队，绝不丢失；同时支持通过 ``sigqueue()`` 携带 ``union sigval``（整型或指针）传递富元数据。

1.3 核心数据结构拓扑（``include/linux/signal_types.h``）
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

::

   +-----------------------------------------------------------------------------------+
   |                           进程与线程信号数据结构拓扑                              |
   |                                                                                   |
   |  [struct task_struct] (线程描述符)                                                |
   |  ├── thread_info.flags ────► 包含 _TIF_SIGPENDING 标志位 (提示有未决信号)          |
   |  ├── blocked (sigset_t) ───► 当前线程屏蔽的信号位图 (不响应这些信号)             |
   |  ├── pending ──────────────► [struct sigpending] (线程私有未决信号队列)           |
   |  │                           ├── signal (sigset_t 位图: 快速判断是否有信号)       |
   |  │                           └── list ──► [struct sigqueue 双向链表]              |
   |  ├── signal ───────────────► [struct signal_struct] (进程/线程组共享上下文)       |
   |  │                           └── shared_pending ──► [struct sigpending] (共享队列)|
   |  └── sighand ──────────────► [struct sighand_struct] (信号处理函数表)             |
   |                              ├── siglock (spinlock_t 保护信号操作的核心自旋锁)   |
   |                              └── action[64] ──► [struct k_sigaction]              |
   |                                  ├── sa_handler (SIG_DFL / SIG_IGN / 用户函数指针)|
   |                                  ├── sa_flags (SA_RESTART / SA_SIGINFO / SA_NODEFER)|
   |                                  └── sa_mask (执行该 Handler 时临时屏蔽的信号集) |
   +-----------------------------------------------------------------------------------+

第二幕：信号生成与标记——从硬件异常到 ``TIF_SIGPENDING`` 唤醒
-------------------------------------------------------------

2.1 信号产生的三大物理与软件源头
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
1. **硬件 Trap / Fault 异常**：CPU 触发异常中断（如除以零 ``#DE`` $\rightarrow$ ``SIGFPE``、未定义指令 ``#UD`` $\rightarrow$ ``SIGILL``、缺页/非法地址访问 ``#PF`` $\rightarrow$ ``SIGSEGV``），异常处理函数调用 ``force_sig_fault()`` 强制生成信号；
2. **系统调用主动发送**：进程调用 ``kill()``, ``tkill()``, ``tgkill()``, ``sigqueue()``；
3. **内核异步事件驱动**：高精度定时器到期（``SIGALRM``）、子进程状态变迁（``SIGCHLD``）、控制终端输入 Ctrl+C 触发 TTY 驱动发送 ``SIGINT``。

2.2 信号投递微观流水线（``kernel/signal.c:__send_signal()``）
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

::

   +-----------------------------------------------------------------------------------+
   |                        __send_signal() 信号投递微观流水线                         |
   |                                                                                   |
   |  1. 获取 sighand->siglock 自旋锁 (spin_lock_irqsave);                             |
   |  2. 检查信号是否被忽略 (SIG_IGN): 若忽略且非追踪调试，直接释放并返回;              |
   |  3. 判断信号类型与未决挂载:                                                       |
   |     ├── 若为实时信号 (sig >= 32):                                                 |
   |     │   - 从 sigqueue_cachep Slab 分配 struct sigqueue 节点;                      |
   |     │   - 填充 siginfo_t 数据，调用 list_add_tail 挂入 pending->list 链表;        |
   |     └── 若为传统标准信号 (1 <= sig <= 31):                                        |
   |         - 检查 sigismember(&pending->signal, sig): 若已在未决中，直接合并跳过!    |
   |         - 否则分配轻量 sigqueue 并挂载;                                           |
   |  4. 设置未决位图: sigaddset(&pending->signal, sig);                               |
   |  5. 核心唤醒判定 (complete_signal):                                               |
   |     ├── 检查信号是否未被目标线程屏蔽 (!sigismember(&p->blocked, sig)):            |
   |     │   - 若目标线程处于可中断休眠态 (TASK_INTERRUPTIBLE):                        |
   |     │   │ └──► 调用 signal_wake_up_state(p, state) 强制唤醒线程!                  |
   |     │   - 【关键一击】: set_tsk_thread_flag(p, TIF_SIGPENDING);                   |
   |     │   - 向目标 CPU 发送 IPI 处理器间中断 (若目标正在其他核运行)，迫使其退出用户态! |
   |  6. 释放 sighand->siglock 自旋锁。                                                |
   +-----------------------------------------------------------------------------------+

第三幕：内核态向用户态穿越前夕——``exit_to_user_mode_loop`` 信号扫描
--------------------------------------------------------------------

信号在生成时仅仅是在目标任务结构体中打上了标记（``TIF_SIGPENDING``）。**信号绝不会在内核态内部执行，也不会突兀地在用户指令中间随机插入！**

3.1 为什么信号必须在 Ring 0 $\rightarrow$ Ring 3 穿越临界点处理？
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
* **特权级安全铁律**：用户自定义的信号处理函数（Signal Handler）是运行在 Ring 3 特权级下的用户代码。如果内核在 Ring 0 特权级下直接调用用户函数指针，将彻底破坏内核安全屏障，引发特权级漏洞与内核崩溃；
* **天然拦截点**：每次系统调用返回（``sysretq`` / ``iretq``）或硬件中断返回用户空间前，CPU 必然经过 **``kernel/entry/common.c:exit_to_user_mode_loop()``** 检查点。

3.2 信号收割状态机（``get_signal()``）
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

::

   +-----------------------------------------------------------------------------------+
   |                       exit_to_user_mode_loop() 信号扫描流水线                     |
   |                                                                                   |
   |  [CPU 准备退出内核态返回用户空间]                                                 |
   |  - 读取 ti_work = read_thread_flags();                                            |
   |  - if (ti_work & _TIF_SIGPENDING) {                                               |
   |        arch_do_signal_or_restart(regs);                                           |
   |    }                                                                              |
   |            │                                                                      |
   |            ▼                                                                      |
   |  [进入 get_signal(struct ksignal *ksig)]                                          |
   |  1. 循环扫描 p->pending 与 shared_pending，寻找未被 p->blocked 屏蔽的最高优先级信号;|
   |  2. 将该信号从未决链表与位图中摘除;                                               |
   |  3. 获取该信号绑定的处理策略 (struct k_sigaction *ka):                           |
   |     ├── 分支 A (SIG_IGN): 直接丢弃，继续寻找下一个信号;                           |
   |     ├── 分支 B (SIG_DFL 默认处理):                                                |
   |     │   ├── Term / Kill: 调用 do_group_exit() 终结进程;                           |
   |     │   ├── Core: 调用 do_coredump() 抓取内存转储并退出;                          |
   |     │   └── Stop: 调用 do_signal_stop() 暂停进程 (进入 TASK_STOPPED);             |
   |     └── 分支 C (自定义用户 Handler):                                              |
   |         └──► 组装 ksig 结构体，返回 1 ──► 触发第四幕: 用户栈帧伪造与 RIP 劫持!    |
   +-----------------------------------------------------------------------------------+

第四幕：用户栈帧伪造与 RIP 劫持——``setup_rt_frame()`` 微观注入时序
------------------------------------------------------------------

当判定需要执行用户态 Handler 时，内核执行整个操作系统中最精妙的“欺骗术”——**在用户态栈上凭空伪造一套栈帧，并篡改保存在内核栈上的寄存器现场！**

4.1 栈空间计算与 Red Zone 避让（``arch/x86/kernel/signal.c``）
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
1. **备用信号栈检测**：若设置了 ``SA_ONSTACK`` 且当前线程注册了备用栈（``sigaltstack()``），栈顶指针切换至 ``sas_ss_sp + sas_ss_size``；
2. **x86_64 Red Zone 避让**：根据 System V AMD64 ABI 规范，函数栈顶下方 128 字节为叶子函数的保护区（Red Zone）。内核必须严格下移 128 字节：
   $$\mathbf{sp = regs->sp - 128}$$
3. **16 字节对齐**：按照 x86_64 调用约定，栈帧基地址必须严格进行 16 字节向下对齐：
   $$\mathbf{sp = (sp \ \& \ \sim 15UL) - 8}$$

4.2 构造 ``struct rt_sigframe`` 用户栈帧
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

::

   +-----------------------------------------------------------------------------------+
   |                        struct rt_sigframe 用户栈物理布局                          |
   |                                                                                   |
   |  [低地址 / 栈顶 SP]                                                               |
   |  ├── pretcode ──────────► 指向 vDSO 中的恢复蹦床代码 (__restore_rt)               |
   |  ├── uc (ucontext_t)                                                              |
   |  │   ├── uc_flags                                                                 |
   |  │   ├── uc_link                                                                  |
   |  │   ├── uc_stack (用户原始栈属性)                                               |
   |  │   ├── uc_mcontext (【核心硬件快照】: 保存被打断时的全套通用寄存器!)            |
   |  │   │   ├── r8..r15, rdi, rsi, rbp, rbx, rdx, rax, rcx                           |
   |  │   │   ├── rip (被打断前原本要执行的下一条用户指令地址!)                        |
   |  │   │   ├── rsp (被打断前的用户原始栈顶指针!)                                    |
   |  │   │   ├── eflags (被打断前的 CPU 状态标志寄存器!)                              |
   |  │   │   └── cs, ss                                                               |
   |  │   └── uc_sigmask (被打断前的原始信号屏蔽位图 blocked)                          |
   |  ├── info (siginfo_t) ──► 完整的 128 字节信号元数据 (发送者 PID/UID/伴随数据)     |
   |  └── fpstate ───────────► 扩展浮点寄存器状态 (XSAVE / AVX-512 / SSE 快照)         |
   |  [高地址]                                                                         |
   +-----------------------------------------------------------------------------------+

4.3 篡改内核栈上的 ``pt_regs``（完成 RIP 劫持）
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
内核将现场写入用户栈后，直接修改内核栈中的 ``struct pt_regs``：
* **``regs->ip = ksig->ka.sa.sa_handler``**：**【RIP 劫持】** 将返回地址强行改为用户 Signal Handler 的入口！
* **``regs->sp = (unsigned long)frame``**：将用户栈顶切换为刚刚伪造的 ``rt_sigframe`` 基地址！
* **函数参数装配（遵循 AMD64 ABI）**：
  * ``regs->di = ksig->sig;``（第 1 参数 RDI：信号编号）
  * ``regs->si = (unsigned long)&frame->info;``（第 2 参数 RSI：``siginfo_t *`` 指针）
  * ``regs->dx = (unsigned long)&frame->uc;``（第 3 参数 RDX：``ucontext_t *`` 指针）
* **信号屏蔽位图原子更新**：将 ``ka->sa.sa_mask`` 与当前信号合并加入 ``p->blocked``，防止 Handler 执行期间被同类信号递归重入。

第五幕：用户态处理与 ``sigreturn`` 现场完美复原
------------------------------------------------

当内核完成上述伪造后，执行标准的硬件返回指令（``SYSRETQ`` 或 ``IRETQ``）。

5.1 跃迁入用户态执行 Handler
~~~~~~~~~~~~~~~~~~~~~~~~~~~~
CPU 弹出被篡改的 ``pt_regs`` 寄存器，特权级降为 Ring 3。此时 CPU 误以为自己原本就是要调用 Signal Handler，立即开始执行用户的处理逻辑：

.. code-block:: c

   void my_signal_handler(int sig, siginfo_t *info, void *ucontext) {
       printf("Received signal %d from PID %d
", sig, info->si_pid);
       /* 执行自定义业务逻辑... */
       return; /* 触发函数返回! */
   }

5.2 vDSO 蹦床（Trampoline）与 ``sys_rt_sigreturn`` 触发
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
当 Handler 执行到 ``return`` 语句时，CPU 执行 ``RET`` 汇编指令。
* ``RET`` 指令自动从栈顶弹出返回地址；
* 而此时栈顶存放的正是内核在第一步预埋的 **``pretcode`` 指针**（指向 vDSO 只读映射区中的 ``__restore_rt`` 函数）；
* CPU 指令流无缝滑入 vDSO 蹦床代码：

::

   __restore_rt:
       movq $15, %rax      # 15 即为 x86_64 体系下的 __NR_rt_sigreturn 系统调用号!
       syscall             # 再次执行 syscall 指令，重新陷入内核态!

5.3 ``sys_rt_sigreturn()`` 终极复原闭环（``arch/x86/kernel/signal.c``）
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

::

   +-----------------------------------------------------------------------------------+
   |                        sys_rt_sigreturn() 现场复原微观流水线                      |
   |                                                                                   |
   |  [再次陷入内核态 Ring 0]                                                          |
   |  1. 根据当前 regs->sp - 8 准确定位用户栈上的 struct rt_sigframe;                  |
   |  2. 权限校验: access_ok(frame, sizeof(*frame));                                   |
   |  3. 还原信号屏蔽位图: set_current_blocked(&frame->uc.uc_sigmask);                  |
   |  4. 【通用寄存器全量倒灌】(restore_sigcontext):                                   |
   |     - 将 uc.uc_mcontext 中保存的 r8..r15, rdi, rsi, rbp, rbx, rdx, rax, rcx 全量  |
   |       覆盖回当前内核栈的 pt_regs 中!                                              |
   |     - regs->ip = frame->uc.uc_mcontext.rip; (恢复被打断前的原始下一条指令 PC!)    |
   |     - regs->sp = frame->uc.uc_mcontext.rsp; (恢复被打断前的原始用户栈顶 SP!)     |
   |     - regs->flags = frame->uc.uc_mcontext.eflags; (恢复 CPU 运算标志位!)         |
   |  5. 【FPU/AVX 状态恢复】: 调用 fpu__restore_sig(&frame->fpstate);                 |
   |  6. 正常系统调用返回 (SYSRETQ / IRETQ):                                           |
   |     └──► CPU 降至 Ring 3，精准降落在被打断前的原始指令上继续执行!                 |
   +-----------------------------------------------------------------------------------+

整个注入与复原过程天衣无缝，被中断的用户主线程在寄存器、内存栈与标志位完全未受污染的情况下继续运转，对刚才发生的信号捕获毫无感知！

第六幕：系统调用自动重启机制（``SA_RESTART`` 与 ``-ERESTARTSYS``）
------------------------------------------------------------------

在多任务操作系统中，如果一个线程阻塞在慢速系统调用中（如等待网络数据 ``read(socket)``、休眠 ``nanosleep()``、等待锁 ``futex()``），此时收到一个非致命信号，系统调用会被强行打断。

6.1 系统调用的打断与返回值
~~~~~~~~~~~~~~~~~~~~~~~~~~
当慢速系统调用被唤醒且检测到 ``TIF_SIGPENDING`` 时，内核无法继续阻塞，会将系统调用返回值设为内部错误码 **``-ERESTARTSYS``** 并退出到 ``exit_to_user_mode_loop()``。

6.2 ``SA_RESTART`` 指令回退黑科技
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
如果用户在注册信号时配置了 ``SA_RESTART`` 标志位，内核将启动 **指令指针自动回退机制**：

::

   +-----------------------------------------------------------------------------------+
   |                           SA_RESTART 自动重启时钟时序                             |
   |                                                                                   |
   |  1. 在 handle_signal() 注入栈帧前，内核检测到 regs->ax == -ERESTARTSYS:           |
   |  2. 将保存在 rt_sigframe 中的原始 rip 强行减去 2 字节:                            |
   |     └──► frame->uc.uc_mcontext.rip -= 2;                                          |
   |  3. 将原始系统调用号重新写回 RAX:                                                 |
   |     └──► frame->uc.uc_mcontext.rax = orig_ax;                                     |
   |  4. 执行用户 Signal Handler...                                                    |
   |  5. 执行 sys_rt_sigreturn 恢复上下文;                                             |
   |  6. 返回用户空间:                                                                 |
   |     - 此时 CPU 的 RIP 恰好回退到了 2 字节机器码 "0F 05" (即 syscall 指令本身)!     |
   |     - CPU 重新执行 syscall 指令，自动重新发起刚才被中断的系统调用!                |
   +-----------------------------------------------------------------------------------+

通过这套极致的汇编级指令回退设计，应用程序彻底免去了在应用层对每个系统调用显式编写 ``if (errno == EINTR) retry;`` 的繁琐逻辑。
