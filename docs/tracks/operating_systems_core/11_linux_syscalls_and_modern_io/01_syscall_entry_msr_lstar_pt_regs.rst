第一幕：从 ``INT 0x80`` 到 ``SYSCALL``——特权级穿越的硬件演进史
--------------------------------------------------------------

系统调用是操作系统内核为用户空间程序提供的唯一受控安全大门。

1.1 经典 ``INT 0x80`` 软件中断的性能枷锁
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
在 32 位 x86 时代，用户态程序通过执行软中断指令 ``int $0x80`` 陷入内核。这种方式在微架构层面上开销极其沉重：
1. **漫长的微码寻址**：CPU 必须停下指令流水线，去中断描述符表（IDT）中索引第 ``0x80`` 号门描述符；
2. **段级特权级检查**：硬件必须检查门描述符的 DPL（Descriptor Privilege Level）是否允许 Ring 3 调用，读取 TSS 任务状态段；
3. **沉重的自动压栈**：硬件强制在栈上压入 ``SS, ESP, EFLAGS, CS, EIP`` 5 个寄存器；
4. **开销**：单次 ``INT 0x80`` 消耗 **300 ~ 500 个 CPU 时钟周期**，成为高频 I/O 与数据库系统的致命瓶颈。

1.2 现代 ``SYSCALL / SYSRET`` 硬件极速通道
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
x86_64 架构彻底废弃了 64 位下的软中断系统调用，引入专用的硬件指令对 **``syscall``** 与 **``sysret``**：
* **硬编码寄存器映射**：彻底绕过 IDT 与 GDT 描述符表查询；
* **极速跳转**：硬件仅需 **15 ~ 20 个时钟周期**（速度提升 20 倍以上！），直接将 CPU 指令指针（RIP）与特权级硬件拉升至内核态。

第二幕：硬件 MSR 寄存器组与系统调用引导装配（``syscall_init()``）
------------------------------------------------------------------

为了使 CPU 在执行 ``syscall`` 指令时知道“跳向何方”、“使用何种代码段”以及“屏蔽哪些标志”，Linux 内核在每个 CPU 核心初始化时必须对特定的 **MSR（Model Specific Registers）** 寄存器进行硬件级编程。

2.1 核心系统调用 MSR 寄存器矩阵
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

.. table:: x86_64 系统调用专用 MSR 寄存器硬件定义
   :widths: 25 25 50

   +======================+======================+======================================================================+
   | MSR 寄存器名称       | MSR 地址编码         | 硬件功能与存储数据                                                   |
   +======================+======================+======================================================================+
   | **``MSR_LSTAR``**    | ``0xC0000082``       | **Long Mode Target Address**：存放 64 位内核汇编入口 ``entry_SYSCALL_64`` 的虚拟地址 |
   +----------------------+----------------------+----------------------------------------------------------------------+
   | **``MSR_STAR``**     | ``0xC0000081``       | **Segment Target Address**：高 32 位硬编码存储内核代码段 ``__KERNEL_CS`` 与用户代码段 ``__USER_CS`` 选择子 |
   +----------------------+----------------------+----------------------------------------------------------------------+
   | **``MSR_SYSCALL_MASK``** (FMASK) | ``0xC0000084`` | **Syscall Flag Mask**：定义在执行 ``syscall`` 时硬件自动强制清零的 RFLAGS 标志位掩码 |
   +----------------------+----------------------+----------------------------------------------------------------------+

2.2 静态配置装配时序（``arch/x86/kernel/cpu/common.c:syscall_init()``）
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
在多核引导过程中，每个 CPU 执行：

::

   void syscall_init(void) {
       /* 1. 设置段选择子: [47:32]=Kernel CS/SS, [63:48]=User CS/SS */
       wrmsrl(MSR_STAR, ((u64)__USER32_CS << 48) | ((u64)__KERNEL_CS << 32));

       /* 2. 将 64 位统一入口 entry_SYSCALL_64 写入 MSR_LSTAR */
       wrmsrl(MSR_LSTAR, (unsigned long)entry_SYSCALL_64);

       /* 3. 配置 RFLAGS 屏蔽掩码: 硬件自动关中断 (IF), 清方向标志 (DF), 清对齐检查 (AC), 清陷阱标志 (TF) */
       wrmsrl(MSR_SYSCALL_MASK,
              X86_EFLAGS_TF|X86_EFLAGS_DF|X86_EFLAGS_IF|
              X86_EFLAGS_IOPL|X86_EFLAGS_AC|X86_EFLAGS_NT);
   }

第三幕：``entry_SYSCALL_64`` 汇编入口微观时钟时序
-------------------------------------------------

当用户态代码执行 ``syscall`` 指令的瞬间，CPU 硬件在晶体管级别自动完成一系列原子操作。

3.1 硬件第一纳秒的自动变迁
~~~~~~~~~~~~~~~~~~~~~~~~~~
在执行 ``syscall`` 指令的那一个时钟周期内，硬件完成：
1. **保存用户断点**：``RCX <- RIP``（保存用户态下一条指令地址）；
2. **保存用户标志**：``R11 <- RFLAGS``（保存用户态条件标志）；
3. **屏蔽敏感标志**：``RFLAGS <- RFLAGS & ~MSR_SYSCALL_MASK``（**硬件自动关闭外部中断 IF=0**，防止在栈未就绪前被中断打断！）；
4. **提升特权级**：``CS <- MSR_STAR[47:32]`` (Ring 0 ``__KERNEL_CS``), ``SS <- MSR_STAR[47:32] + 8`` (Ring 0 ``__KERNEL_DS``)；
5. **硬件跳转**：``RIP <- MSR_LSTAR``（瞬间跳转至内核 ``entry_SYSCALL_64`` 入口）。

.. warning::
   **硬件留下的致命空缺**：
   x86_64 的 ``syscall`` 指令**完全没有修改栈指针寄存器（``RSP``）**！此时 CPU 虽已进入 Ring 0 特权级，但 ``%rsp`` 依然指向不受信的用户态栈。内核如果在此时压栈，将直接踩踏用户内存或遭受恶意溢出攻击。

3.2 ``entry_SYSCALL_64`` 汇编极速自救与栈切换
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
在 ``arch/x86/entry/entry_64.S`` 中，内核通过一段精密设计的汇编指令建立安全的内核环境：

::

   +-----------------------------------------------------------------------------------+
   |                     entry_SYSCALL_64 入口第一阶段核心汇编                         |
   |                                                                                   |
   |  SYM_CODE_START(entry_SYSCALL_64)                                                 |
   |      UNWIND_HINT_ENTRY                                                            |
   |      ENDBR                                                                        |
   |                                                                                   |
   |      /* 1. 交换 GS 段基址: 从用户态 GSBASE 瞬切到内核 Per-CPU 区域基址! */         |
   |      swapgs                                                                       |
   |                                                                                   |
   |      /* 2. 将不受信的用户栈指针 %rsp 暂存到当前 CPU TSS 结构体的 scratch 槽位 */  |
   |      movq    %rsp, PER_CPU_VAR(cpu_tss_rw + TSS_sp2)                              |
   |                                                                                   |
   |      /* 3. (若启用 KPTI) 从用户态隔离页表 CR3 切换至全映射内核态 CR3 页表! */      |
   |      SWITCH_TO_KERNEL_CR3 scratch_reg=%rsp                                        |
   |                                                                                   |
   |      /* 4. 从 Per-CPU 变量中加载当前任务专属的 16KB 内核栈顶地址! */              |
   |      movq    PER_CPU_VAR(cpu_current_top_of_stack), %rsp                          |
   +-----------------------------------------------------------------------------------+

经过上述 4 条关键指令，CPU 拥有了受信任的独立内核栈与正确的 Per-CPU 数据结构访问能力。

第四幕：构造 168 字节完整 ``struct pt_regs`` 与熔断侧信道防御
--------------------------------------------------------------

4.1 压栈构造硬件与通用寄存器栈帧
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
内核栈就绪后，汇编代码立即在栈上构建完整的现场快照：

::

   +-----------------------------------------------------------------------------------+
   |                       struct pt_regs 168 字节内存栈帧布局                         |
   |                                                                                   |
   |  [内核栈高地址 (Top of Stack)]                                                    |
   |  ├── pt_regs->ss       (0x18: pushq $__USER_DS)                                   |
   |  ├── pt_regs->sp       (用户态原始 RSP: 从 TSS_sp2 读出压栈)                      |
   |  ├── pt_regs->flags    (用户态原始 RFLAGS: pushq %r11)                            |
   |  ├── pt_regs->cs       (0x10: pushq $__USER_CS)                                   |
   |  ├── pt_regs->ip       (用户态返回地址: pushq %rcx)                               |
   |  ├── pt_regs->orig_ax  (系统调用号: pushq %rax)                                   |
   |  ├── pt_regs->rdi      (系统调用第 1 参数)                                        |
   |  ├── pt_regs->rsi      (系统调用第 2 参数)                                        |
   |  ├── pt_regs->rdx      (系统调用第 3 参数)                                        |
   |  ├── pt_regs->r10      (系统调用第 4 参数: 注意 C ABI 是 rcx, 但 rcx 被保存用作 rip)|
   |  ├── pt_regs->r8       (系统调用第 5 参数)                                        |
   |  ├── pt_regs->r9       (系统调用第 6 参数)                                        |
   |  ├── pt_regs->r11 / rbx / rbp / r12 / r13 / r14 / r15                             |
   |  └── [内核栈当前 RSP (底端)]                                                      |
   +-----------------------------------------------------------------------------------+

4.2 幽灵与分支注入硬件级防御（Speculation Barriers）
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
在压栈完成后，为了防止恶意用户进程通过训练 CPU 分支预测器（Branch Target Buffer / BHB）进行跨特权级推测执行侧信道攻击（如 Spectre v2 / BHI），内核在调用 C 函数前插入了硬件防御屏障：
* **``IBRS_ENTER``**：写入 ``MSR_IA32_SPEC_CTRL``，限制间接分支推测；
* **``CLEAR_BRANCH_HISTORY``**：执行专用短循环清空分支历史记录。

第五幕：C 语言系统调用分发与 ``SYSRETQ`` 闪电返回
-------------------------------------------------

现场保护与安全屏障建立完毕后，汇编代码将栈指针 ``%rsp``（即 ``struct pt_regs *`` 指针）作为第一参数（``%rdi``），调用 C 语言总控函数 **``do_syscall_64()``**。

5.1 ``do_syscall_64()`` 查表路由流水线（``arch/x86/entry/common.c``）
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

::

   +-----------------------------------------------------------------------------------+
   |                          do_syscall_64() 核心路由状态机                           |
   |                                                                                   |
   |  __visible noinstr void do_syscall_64(struct pt_regs *regs, int nr) {            |
   |      /* 1. 检查 ptrace / seccomp / audit 等系统调用追踪与过滤挂钩 */              |
   |      if (likely(syscall_enter_from_user_mode(regs, nr) == 0)) {                   |
   |          /* 2. 校验系统调用号范围 (nr < NR_syscalls) */                           |
   |          if (likely(nr < NR_syscalls)) {                                          |
   |              /* 3. 查表调用具体内核实现函数 (如 sys_read, sys_write, sys_clone) */ |
   |              regs->ax = sys_call_table[nr](                                       |
   |                  regs->di, regs->si, regs->dx, regs->r10, regs->r8, regs->r9);    |
   |          }                                                                        |
   |      }                                                                            |
   |      /* 4. 处理挂起的信号 (Signals)、RCU 事务与重新调度请求 (TIF_NEED_RESCHED) */ |
   |      syscall_exit_to_user_mode(regs);                                             |
   |  }                                                                                |
   +-----------------------------------------------------------------------------------+

5.2 极速返回 Ring 3 用户空间
~~~~~~~~~~~~~~~~~~~~~~~~~~~~
当系统调用执行完毕，返回值写入 ``regs->ax`` 后，CPU 执行返回路径：
1. **``SYSRETQ`` 快速路径**：若未发生单步调试或段寄存器篡改，汇编执行：
   ::

      POP_REGS                /* 恢复所有通用寄存器 */
      SWITCH_TO_USER_CR3      /* 切换回用户空间页表 */
      swapgs                  /* 恢复用户态 GSBASE */
      sysretq                 /* 硬件指令: RIP <- RCX, RFLAGS <- R11, 特权级降为 Ring 3! */

2. **``IRETQ`` 慢速保底路径**：若用户修改了栈寄存器或需要处理复杂异常，降级通过 ``iretq`` 指令完整弹出栈帧返回。

小结与下章导读
--------------

本节深入解构了 Linux 7.2 x86_64 架构下系统调用的微观全链路：从 ``MSR_LSTAR`` 与 ``MSR_STAR`` 的编译期装配，到 ``syscall`` 硬件自动关中断与特权级提升；从 ``entry_SYSCALL_64`` 的 ``swapgs`` 栈切换、168 字节 ``struct pt_regs`` 栈帧构造与 Spectre 侧信道防御，到 ``do_syscall_64`` 查表路由与 ``SYSRETQ`` 闪电返回。

系统调用虽然极其迅速，但无论多么优化，进入内核态依然存在几十纳秒的硬件切换开销。对于某些超高频调用的接口（例如获取时间戳 ``gettimeofday()``、读取 CPU 编号 ``getcpu()``），即便几十纳秒的系统调用依然过于昂贵。

在 **第 2 节：vDSO (Virtual Dynamic Shared Object) 与用户态无系统调用直读硬件计时器** 中，我们将深入解构 Linux 内核如何通过只读共享内存页与 TSC 时钟寄存器，彻底颠覆系统调用模型，在 **完全不陷入内核态** 的情况下达成亚纳秒级时间与 CPU 拓扑读取。
