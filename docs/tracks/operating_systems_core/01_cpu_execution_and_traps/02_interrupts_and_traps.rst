第一幕：异步突发事件与电路级中断触发原理
-----------------------------------------

在计算机运行过程中，CPU 主频（GHz 级别）与外设处理速度（毫秒/微秒级别）存在数个数量级的差距。如果 CPU 采用软件循环轮询（Polling）方式检测外设就绪状态，总线带宽与计算算力将被无效读操作彻底吞噬。

1.1 电路级触发机制：电平触发 (Level-Triggered) vs 边沿触发 (Edge-Triggered)
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
主板印制电路板（PCB）上的外设中断引脚通过电信号跳变通知中断控制器。硬件物理层存在两种基础触发模式：

1. **边沿触发（Edge-Triggered）**：
   * **物理电平跃迁**：检测信号线上电压的快速跳变（上升沿 $0	ext{V} \rightarrow 3.3	ext{V}$ 或下降沿 $3.3	ext{V} \rightarrow 0	ext{V}$）；
   * **电路特征**：由施密特触发器锁存突发脉冲。若外设保持高电平不变，中断控制器不会重复触发；但若总线存在毛刺电压，易造成误触发。常用于 ISA 传统总线与 PCI 边沿中断。
2. **电平触发（Level-Triggered）**：
   * **物理电平持续**：检测信号线是否被拉低至低电平（如 PCI 总线的有源低电平 `/INTA` 引脚）；
   * **电路特征**：外设在产生事件后将引脚拉低并保持，直到 CPU 执行中断服务程序（ISR）显式向该外设控制器写入寄存器应答后，外设才释放总线引脚恢复高电平。支持多设备通过集电极开路（Open-Collector）线与（Wired-AND）共享同一中断引脚。

1.2 CPU 核心的物理中断引脚：INTR vs NMI
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
在 x86_64 处理器芯片封装引脚上，存在两条直通 CPU 运算核心的专用物理中断输入针脚：

* **``INTR`` (Maskable Interrupt, 可屏蔽中断引脚)**：
  * 连接到本地中断控制器（Local APIC）或外部 8259A 中断控制器；
  * **受控于标志位**：当 ``RFLAGS.IF = 1`` 时，CPU 响应此引脚上的电平请求；当 ``RFLAGS.IF = 0``（执行了 ``CLI`` 指令）时，CPU 完全忽略该引脚上的电平跳变，硬件不予理睬。
* **``NMI`` (Non-Maskable Interrupt, 不可屏蔽中断引脚)**：
  * 专用于指示灾难性硬件故障（如物理内存 ECC 校验不可纠正错误、主板总线超时、硬件看门狗超时）；
  * **无视标志位**：不受 ``RFLAGS.IF`` 影响，即使 CPU 处于关中断状态，硬件仍然强制在一个指令周期结束后挂起当前任务并跳转至向量 2（Vector 2）处理。

第二幕：中断控制系统拓扑演进——从 8259A 到 APIC / MSI-X
-------------------------------------------------------

随着计算机从单核单总线向多核 SMP（Symmetric Multiprocessing）与高速 PCIe 拓扑演化，中断路由硬件经历了三代架构跃变。

2.1 传统 8259A PIC 级联拓扑与 ISA 局限
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
在早期 PC/AT 架构中，系统采用两片 Intel 8259A 可编程中断控制器（PIC）级联构成，共支持 15 个硬件中断（IRQ 0 ~ 15）：

::

   [外设 IRQ 0..7]  ──► [主片 8259A (Master, I/O 0x20/0x21)] ──► CPU INTR 引脚
                               ▲ (IRQ 2 级联)
                               │
   [外设 IRQ 8..15] ──► [从片 8259A (Slave, I/O 0xA0/0xA1)]

* **内部核心寄存器**：
  * **IRR (Interrupt Request Register)**：8 位寄存器，记录哪些 IRQ 引脚当前正处于电平申请状态；
  * **ISR (In-Service Register)**：8 位寄存器，记录当前 CPU 正在执行哪一级 IRQ 的中断处理；
  * **IMR (Interrupt Mask Register)**：8 位屏蔽寄存器，位为 1 屏蔽对应 IRQ。
* **物理缺陷**：8259A 只能将中断路由给单一 CPU 核心，无法在多核处理器间分发中断，且基于慢速 I/O 端口访问，延迟高达数百纳秒。

2.2 现代 APIC 架构：I/O APIC 与 Local APIC 系统拓扑
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
现代 x86_64 多核系统普遍采用高级可编程中断控制器（Advanced Programmable Interrupt Controller, APIC）体系：

::

   +-----------------------------------------------------------------------------------+
   |                                 多核处理器芯片                                    |
   |                                                                                   |
   |   +-----------------------+                    +-----------------------+          |
   |   |   CPU Core 0 核心     |                    |   CPU Core 1 核心     |          |
   |   |  +-----------------+  |                    |  +-----------------+  |          |
   |   |  | Local APIC (LAPIC|  |                    |  | Local APIC (LAPIC|  |          |
   |   |  +--------+--------+  |                    |  +--------+--------+  |          |
   |   +-----------│-----------+                    +-----------│-----------+          |
   |               │                                            │                      |
   |   ════════════╪════════════════════════════════════════════╪═════════ 系统总线   |
   |               │                                            │ (System Bus/QPI)     |
   +───────────────┼────────────────────────────────────────────┼──────────────────────+
                   ▲                                            ▲
                   └──────────────────┬─────────────────────────┘
                                      │ 中断消息数据包 (Interrupt Messages)
                        +-------------┴-------------+
                        |   I/O APIC (位于芯片组)   |
                        +-------------▲-------------+
                                      │ 物理引脚
                        [外部硬件外设：PCIe / 定时器 / 网卡]

* **Local APIC (LAPIC)**：
  * 每个 CPU 物理核心独立集成一个 LAPIC。
  * **内存映射（MMIO）**：物理基地址默认为 ``0xFEE00000``（4KB 页面），在 x2APIC 模式下通过 MSR（``0x800 ~ 0x8FF``）寄存器以 64 位直读直写；
  * **核心寄存器**：
    * ``ICR`` (Interrupt Command Register)：用于发送核间中断（IPI），控制多核引导与任务调度抢占；
    * ``LVT`` (Local Vector Table)：配置局部 APIC 定时器、温度传感器、性能计数器中断；
    * ``TPR / PPR`` (Task/Processor Priority Register)：硬件优先级仲裁，低于当前优先级的外部中断直接被硬件挂起。
* **I/O APIC**：
  * 位于主板芯片组（PCH/南桥），通常提供 24 个外部中断输入引脚（RTE 0 ~ 23）；
  * 每个重定向表项（Redirection Table Entry, RTE 64-bit）可独立配置：目标 CPU APIC ID、中断向量号、触发模式（边沿/电平）与投递模式（固定/最低优先级）。

2.3 MSI / MSI-X：基于 PCIe 内存写入事务的无引脚中断
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
现代高速外设（如 NVMe SSD、千兆/万兆网卡）彻底摒弃了主板专用物理中断铜线，采用 **消息信号中断（Message Signaled Interrupts, MSI / MSI-X）**：

1. **无引脚物理本质**：外设产生中断时，不拉低任何物理电平引脚，而是通过 PCIe 总线向主机内存控制器发起一次标准的 **PCIe 内存写事务（PCIe Memory Write TLP）**；
2. **写入目标地址**：写入物理地址固定落在 APIC 中断消息窗口（``0xFEE00000 ~ 0xFEEFFFFF``）；
3. **写入数据载荷**：32 位数据包直接包含目标中断向量号（Vector ID, 8 位）、触发边沿模式与投递目标核心 APIC ID；
4. **MSI-X 扩展优势**：支持每个外设独立分配多达 2048 个中断向量，使多队列网卡（RSS）与多队列 NVMe（blk-mq）能够将各个硬件队列的中断直接绑定投递至特定的 CPU 核心，实现硬件级零总线锁争用。

第三幕：中断分发微观时序与硬件原子执行时序
-------------------------------------------

当一个中断信号最终抵达 CPU 核心时，CPU 硬件在纳秒级时钟节拍内执行一连串不可中断的原子硬件状态机动作。

3.1 指令边界断点（Instruction Boundary）
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
CPU 不会在一条指令执行到一半时响应中断。
* **时钟时序规则**：CPU 运算流水线在每条指令执行阶段（Execute）结束、写回阶段（Writeback）完成的**时钟下降沿**，硬件中断仲裁逻辑检查 ``INTR`` 引脚电平与 ``RFLAGS.IF`` 标志；
* **断点确定**：若允许中断，CPU 暂停取指流水线，将下一条即将执行的指令地址锁定为**返回地址（Return RIP）**。

3.2 中断向量号与中断描述符表 (IDT) 硬件查找
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
x86_64 支持 256 个中断向量（Vector 0 ~ 255）：

* **0 ~ 31**：由 CPU 体系结构硬性保留用于处理器内部异常（如 0 为除以零 ``#DE``，14 为缺页异常 ``#PF``）；
* **32 ~ 255**：供外部硬件中断（IRQ）与软件中断（如 Linux 早期 ``INT 0x80``）自由分配。

CPU 通过片内 **IDTR (IDT Register)** 寄存器定位中断描述符表在物理内存中的基地址。IDTR 包含 16 位表界限（Limit）与 64 位基地址（Base Address）。

在 64 位长模式下，IDT 中的每个中断门描述符（Interrupt Gate Descriptor）占用 **16 字节（128 位）**：

::

   127                                                          96
   +-------------------------------------------------------------+
   |                        保留位 (Reserved = 0)                |
   +-------------------------------------------------------------+
   95                                                            64
   +-------------------------------------------------------------+
   |                   处理函数入口目标地址 (Offset 63..32)      |
   +-------------------------------------------------------------+
   63                             48 47  46 45 44 40 39 36 35 32 31                             16 15                           0
   +--------------------------------+---+----+-----+---+-----+--+--------------------------------+-------------------------------+
   | 处理函数入口目标地址 (31..16)  | P |DPL |01110| 0 | IST | 0|        目标代码段选择子        | 处理函数入口目标地址 (15..0)  |
   |                                |(1)|(00)|(Gate|   |(0-7)|  |       (Segment Selector)       |                               |
   +--------------------------------+---+----+-----+---+-----+--+--------------------------------+-------------------------------+

硬件检索地址计算公式：

.. math::

   	ext{Descriptor\_Addr} = 	ext{IDTR.Base} + (	ext{Vector} 	imes 16)

3.3 硬件原子切栈与现场压栈微观时序
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
当 CPU 从用户态（Ring 3）捕获到中断，硬件必须切换到高特权级的内核栈（Ring 0），防止恶意用户程序破坏调用栈。

硬件在微码级别自动执行如下原子步骤（耗时数个时钟周期）：

::

   [Ring 3 用户态运行中]  (当前 RSP 指向用户栈)
             │
             ▼ 中断信号命中 (Vector N)
   1. 硬件读取当前 CPU 的 TSS (Task State Segment) 结构体，提取内核栈顶指针 RSP0；
   2. 内部暂存用户态现场：Old_SS = SS, Old_RSP = RSP, Old_FLAGS = RFLAGS, Old_CS = CS, Old_RIP = RIP;
   3. 将 CPU 栈指针切换为内核栈：SS <= 0 (长模式 SS 固定为 NULL 选择子), RSP <= TSS.RSP0;
   4. 若描述符指定了 IST (Interrupt Stack Table 1..7)，则强制切换到 IST 指定的独立紧急栈顶；
   5. 在新内核栈上自高向低依次原子压入 5 个 64 位寄存器：
      
      内核栈顶 (低地址)
      ┌─────────────────────────┐ ◄── 当前硬件 RSP
      │  RIP (Old_RIP)          │ (8 字节)
      ├─────────────────────────┤
      │  CS  (Old_CS)           │ (8 字节)
      ├─────────────────────────┤
      │  RFLAGS (Old_FLAGS)     │ (8 字节)
      ├─────────────────────────┤
      │  RSP (Old_RSP)          │ (8 字节)
      ├─────────────────────────┤
      │  SS  (Old_SS)           │ (8 字节)
      └─────────────────────────┘
      内核栈底 (高地址)

   6. 若当前为特定异常（如缺页异常 #PF 或通用保护 #GP），硬件额外压入 8 字节的【硬件错误码 (Error Code)】；
   7. 硬件清除中断标志：若目标描述符为中断门（Interrupt Gate），硬件自动执行 RFLAGS.IF = 0 关全局中断；若为陷阱门（Trap Gate），保持 IF 不变；
   8. 将 IDT 描述符中拼接解析出的 64 位函数入口地址加载至 RIP，流水线跳转开始执行内核中断处理函数。

第四幕：处理器异常（Exceptions）分类与微观时序
-----------------------------------------------

与外部异步中断不同，**异常（Exception）** 是 CPU 在执行指令时由内部运算逻辑直接触发的同步事件。体系结构将其严格划分为三类：

.. table:: x86_64 异常分类与硬件返回时序特征
   :widths: 15 20 30 35

   +----------------+------------------------+------------------------------------+------------------------------------------------+
   | 异常类别       | 经典向量实例           | 硬件保存的返回 RIP 特征            | 典型处理策略与操作系统行为                     |
   +================+========================+====================================+================================================+
   | **故障**       | 向量 14: 缺页异常 #PF  | **指向触发异常的那条指令本身**     | 内核分配物理页/调页后，执行 ``IRETQ`` 返回时   |
   | (Fault)        | 向量 0: 除以零 #DE     | (RIP = Addr_Faulting_Instr)        | CPU 重新执行触发异常的原指令。                 |
   +----------------+------------------------+------------------------------------+------------------------------------------------+
   | **陷阱**       | 向量 1: 调试断点 #DB   | **指向触发指令的下一条指令**       | 用于调试器断点与系统调用跟踪。                 |
   | (Trap)         | 向量 3: 断点指令 #BP   | (RIP = Addr_Faulting_Instr + Len)  | 处理完成后无需重试当前指令，继续向下推进。     |
   +----------------+------------------------+------------------------------------+------------------------------------------------+
   | **中止**       | 向量 8: 双重错误 #DF   | **不保证 RIP 有效性**              | 致命硬件或内核逻辑崩溃，不可恢复。             |
   | (Abort)        | 向量 18: 机器检查 #MC  | (严重系统级故障)                   | 内核直接触发 Kernel Panic 或强制宕机重启。     |
   +----------------+------------------------+------------------------------------+------------------------------------------------+

第五幕：Linux 7.2 内核数据结构对齐——``struct pt_regs``
------------------------------------------------------

当 CPU 硬件完成上述原子压栈后，控制权交由 Linux 内核汇编桩（Assembly Stub）。内核的第一项使命就是将剩余的通用寄存器压栈，构造一个完整的 ``struct pt_regs`` 结构。

在 Linux 7.2 内核源码 ``arch/x86/include/asm/ptrace.h`` 中，``struct pt_regs`` 的字段布局与 CPU 硬件压栈顺序呈现绝对严格的倒序映射：

::

   内存低地址 (栈顶)
   +-------------------------------------------------------+
   | r15, r14, r13, r12, rbp, rbx, r11, r10, r9, r8        | ◄── 由内核汇编 PUSH 压入
   | rax, rcx, rdx, rsi, rdi                               |
   | orig_ax (系统调用号/中断向量号)                       |
   +=======================================================+
   | [error_code] (部分异常由硬件压栈，无则软件占位压0)    | ◄── 硬件/软件混合边界
   +=======================================================+
   | rip                                                   | ◄── 完全由 CPU 硬件自动压栈
   | cs                                                    |
   | flags (rflags)                                        |
   | sp (rsp)                                              |
   | ss                                                    |
   +-------------------------------------------------------+
   内存高地址 (栈底)

当中断处理完毕后，内核执行汇编弹出通用寄存器，最后执行 ``IRETQ`` 指令：
* CPU 硬件在一个时钟周期内原子弹出 ``RIP, CS, RFLAGS, RSP, SS``；
* 若检测到 ``CS`` 中的特权级由 Ring 0 变为 Ring 3，硬件自动切回用户态栈指针，恢复用户空间执行。
