第一幕：从两片式架构到现代 PCIe 拓扑——I440FX 与 Q35 演进
---------------------------------------------------------

在 PC 体系结构中，主板芯片组（Chipset）是连接 CPU、物理内存与全部外部 I/O 设备的交通枢纽。在 QEMU（``/Volumes/LinuxKernel/qemu``）中，模拟主板的核心演进体现在 I440FX 与 Q35 两种平台架构上：

::

   [传统架构：I440FX + PIIX4 (PCI 时代)]
   +-------------------+
   |   CPU 运算核心    |
   +---------┬---------+
             │ 宿主前端总线 (FSB, 64-bit 并行)
   +---------┴-----------------------------------------+
   | 北桥：I440FX (MCH / PCI Host Bridge)              |
   | - DRAM 物理内存控制器                             |
   | - PAM (Programmable Attribute Map) 寄存器         |
   | - 32-bit 并行 PCI 局部总线 (PCI Bus 0)            |
   +-----------------------┬---------------------------+
                           │ 32-bit / 33MHz 共享并行总线
   +-----------------------┴---------------------------+
   | 南桥：PIIX4 (PCI-to-ISA / IDE / USB Bridge)       |
   | - IDE 硬盘接口                                    |
   | - ISA 总线桥接器 (连接 8254 PIT, 8259A PIC, 串口) |
   +---------------------------------------------------+

   [现代架构：Intel Q35 + ICH9 (PCIe 时代)]
   +-------------------+
   |   CPU 运算核心    |
   +---------┬---------+
             │ 点对点点互连总线 (QPI / DMI)
   +---------┴-----------------------------------------+
   | 北桥：Q35 MCH (PCIe Root Complex)                 |
   | - 高速 DDR4/DDR5 内存控制器                       |
   | - PCIe Root Ports (点对点差分串行链路)             |
   | - 256MB ECAM / MMCONFIG 内存映射配置空间          |
   +-----------------------┬---------------------------+
                           │ DMI 高速串行点对点总线
   +-----------------------┴---------------------------+
   | 南桥：ICH9 LPC Controller                         |
   | - SATA AHCI 磁盘控制器                            |
   | - PCIe 扩展下游端口                               |
   | - HPET 高精度定时器                               |
   | - LPC (Low Pin Count) 总线 (挂载传统 ISA 遗留设备)|
   +---------------------------------------------------+

1.1 I440FX / PIIX4 的物理瓶颈
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
I440FX 诞生于 1996 年（Pentium Pro 时代），其最大局限在于：
* **总线共享争用**：所有 PCI 设备挂载在同一组 32 位并行数据线上，总带宽被硬性锁死在 $33	ext{ MHz} 	imes 32	ext{ bit} = 133	ext{ MB/s}$；
* **配置机制老旧**：仅支持 256 字节的传统 PCI 配置空间，通过两个 32 位 I/O 端口（``0xCF8 / 0xCFC``）进行间接索引。

1.2 Q35 / ICH9 芯片组的现代特性
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
Q35（2007 年引入）代表了现代 PC 的标准拓扑：
* **点对点串行差分链路（PCIe）**：彻底淘汰共享并行总线，每个设备独享双向差分通道（Lane），PCIe 4.0/5.0 单通道带宽达数 GB/s；
* **PCIe 根复合体（Root Complex）**：集成内存控制器并引出独立的 PCIe Root Ports；
* **ECAM 机制**：将 PCI 配置空间扩展至 4096 字节，并将其直接映射为一段 256MB 的连续物理内存空间（MMCONFIG），消除了慢速 I/O 端口访问。

第二幕：QEMU 对象模型 (QOM) 与主板设备树装配
---------------------------------------------

在 QEMU 纯 C 语言体系中，主板上的物理芯片、总线与设备并非松散的数据结构，而是基于 **QOM (QEMU Object Model)** 构建的严格面向对象设备树。

2.1 QOM 类型系统核心抽象
~~~~~~~~~~~~~~~~~~~~~~~~
在 ``include/qom/object.h`` 与 ``include/hw/qdev-core.h`` 中，QOM 建立了四层继承矩阵：

::

   Object (根基类：提供类型注册、引用计数与属性访问)
     │
     └── DeviceState (设备抽象：提供 reset 回调、realize 实例化生命周期与中断引脚)
           │
           ├── SysBusDevice (系统总线设备：如 Host Bridge，直接挂载 MMIO/PIO)
           │
           └── PCIDevice (PCI 终端设备：包含 256/4096 字节配置空间与 BAR 映射)

* **总线与设备二叉绑定法则**：
  1. 每一个设备（``DeviceState``）必须且只能挂载在一条父总线（``BusState``）上；
  2. 每一条总线（``BusState``）必须且只能由一个宿主桥接设备拥有；
  3. 通过这一法则，QEMU 在内存中构建出一棵从根总线（``main-system-bus``）逐级发散至所有终端外设的严格物理设备拓扑树。

2.2 Q35 主板在 QEMU 中的微观装配时序
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
在 QEMU 源码 ``hw/i386/pc_q35.c:pc_q35_init()`` 中，主板装配严格遵循物理主板硬件上电逻辑：

::

   pc_q35_init()
     │
     ├─► 1. 创建 Q35 Host Bridge 对象: qdev_new(TYPE_Q35_HOST_DEVICE);
     │      - 分配 256MB ECAM 内存映射区域 (pcie_host_mmcfg_init);
     │      - 注册 I/O 端口 0xCF8 / 0xCFC 的读写拦截回调;
     │
     ├─► 2. 生成 PCIe 根总线: PCIBus *host_bus = pci_root_bus_new(...);
     │      - 该总线在拓扑中命名为 "pcie.0" (PCI Domain 0, Bus 0);
     │
     ├─► 3. 在 Bus 0 上实例化北桥芯片: pci_create_simple_multifunction(host_bus, 0, TYPE_MCH_PCI_DEVICE);
     │      - 设备编号固定为: Bus 0, Device 0, Function 0 (00:00.0);
     │      - 初始化 PAM (Programmable Attribute Map) 寄存器与 SMRAM 访问控制;
     │
     ├─► 4. 在 Bus 0 上实例化南桥芯片: pci_create_simple_multifunction(host_bus, PCI_DEVFN(31, 0), TYPE_ICH9_LPC_DEVICE);
     │      - 设备编号固定为: Bus 0, Device 31, Function 0 (00:1f.0);
     │
     └─► 5. 由 ICH9 LPC 南桥引出 ISA 总线: ISABus *isa_bus = ...;
            - 在 ISA 总线上挂载传统 8254 PIT、8259A PIC、RTC 与串口 UART 16550A。

第三幕：PCI 配置空间访问机制的硬件模拟实现
-------------------------------------------

每个 PCI/PCIe 设备都拥有一段用于由 BIOS/OS 探测设备类型、分配物理地址（BAR）与配置中断的专属寄存器矩阵。QEMU 必须在软件中精确拦截并模拟两种访问机制。

3.1 经典 I/O 端口机制（0xCF8 / 0xCFC）的微观分发
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
在传统 PCI 规范中，CPU 通过向主板两个特定 I/O 端口执行 ``OUT/IN`` 指令完成寻址与读写：

1. **``0xCF8 (CONFIG_ADDRESS)`` 寄存器位域**：

::

   31      30          24 23          16 15       11 10      8 7         2 1   0
   +------+--------------+--------------+-----------+---------+-----------+-----+
   | Enable|  保留位 (0)  |  Bus 号 (8位)| Dev 号(5位)| Func(3位)| Register  | 0 0 |
   | (1位) |              |  (0..255)    | (0..31)   | (0..7)  | 偏移(6位) |     |
   +------+--------------+--------------+-----------+---------+-----------+-----+

2. **QEMU 内部拦截与分发逻辑**（``hw/pci/pci_host.c``）：
   * 当客户机写入 ``0xCF8`` 时，QEMU 记录下目标三元组 $	ext{BDF} = (	ext{Bus}, 	ext{Device}, 	ext{Function})$ 与寄存器偏移量；
   * 当客户机读写 ``0xCFC (CONFIG_DATA)`` 时，QEMU 的 ``pci_host_data_write()`` 函数触发：
     1. 根据 Bus 号在总线树中查找到对应的 ``PCIBus``；
     2. 根据 Dev/Func 号在 ``bus->devices[]`` 数组中提取目标 ``PCIDevice`` 指针；
     3. 直接对目标设备内存中的 ``pci_dev->config[256]`` 数组进行读写操作。

3.2 现代 PCIe ECAM (MMCONFIG) 内存映射机制
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
在 Q35 架构中，ECAM 彻底取代了繁琐的端口索引，将整个 PCI 拓扑直接映射为一段 256MB 的平坦物理内存：

.. math::

   	ext{GPA} = 	ext{ECAM\_Base} + (	ext{Bus} \ll 20) + (	ext{Dev} \ll 15) + (	ext{Func} \ll 12) + 	ext{Register}

* **QEMU 内部实现（``hw/pci/pcie_host.c``）**：
  * QEMU 创建一个大小为 256MB 的 ``MemoryRegion``，并将其物理地址（GPA）注册在 ``0xB0000000``；
  * 当客户机 CPU 访问该内存范围时，触发 KVM 的 EPT Violation / MMIO 退出；
  * QEMU 的 ``pcie_mmcfg_data_write()`` 接收到物理地址偏移量，通过位移直接反解出 BDF 与 4096 字节配置空间内的偏移，单次内存写入即可完成配置。

第四幕：PCIe Root Complex 拓扑与 BAR 空间虚拟化
------------------------------------------------

PCI 设备的一大革命性设计在于 **完全消除跳线开关，实现物理地址动态分配（Plug and Play）**。该机制的核心载体就是 **基地址寄存器（Base Address Register, BAR）**。

4.1 256 字节标准 PCI 配置空间头部结构
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
每个 PCI 设备的前 64 字节（Header Type 0）具备全球统一的标准格式：

::

   31                              16 15                               0
   +--------------------------------+----------------------------------+
   |        Device ID (设备号)      |        Vendor ID (厂商号)        | 0x00
   +--------------------------------+----------------------------------+
   |          Status (状态)         |         Command (命令控制)       | 0x04
   +--------------------------------+----------------------------------+
   |       Class Code (类别代码)    |        Revision ID (版本号)      | 0x08
   +--------------------------------+----------------------------------+
   | BIST | Header Type | Latency   | Cache Line Size (缓存行大小)     | 0x0C
   +--------------------------------+----------------------------------+
   |                     Base Address Register 0 (BAR0)                | 0x10
   +-------------------------------------------------------------------+
   |                     Base Address Register 1 (BAR1)                | 0x14
   +-------------------------------------------------------------------+
   |                     Base Address Register 2 (BAR2)                | 0x18
   +-------------------------------------------------------------------+
   |                     Base Address Register 3 (BAR3)                | 0x1C
   +-------------------------------------------------------------------+
   |                     Base Address Register 4 (BAR4)                | 0x20
   +-------------------------------------------------------------------+
   |                     Base Address Register 5 (BAR5)                | 0x24
   +-------------------------------------------------------------------+
   |                     CardBus CIS Pointer                           | 0x28
   +--------------------------------+----------------------------------+
   |      Subsystem ID              |      Subsystem Vendor ID         | 0x2C
   +--------------------------------+----------------------------------+
   |                     Expansion ROM Base Address                    | 0x30
   +--------------------------------+----------------------------------+
   |            Reserved            | Capabilities Pointer (特性链表)  | 0x34
   +--------------------------------+----------------------------------+
   |            Reserved                                               | 0x38
   +--------------------------------+----------------------------------+
   | Max_Lat | Min_Gnt | Interrupt PIN | Interrupt LINE                | 0x3C
   +--------------------------------+----------------------------------+

4.2 BAR 物理地址探测与动态重映射全流程
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
BIOS 或操作系统内核在启动扫描时，必须为每个设备的 BAR 分配非冲突的系统物理地址（GPA）。

QEMU 内部完整模拟了 PCI 规范定义的 **全 1 写入探测协议（Size Probing Protocol）**：

::

   [BIOS / OS 探测阶段]
          │
          ├─► 1. 软件向目标设备的 BAR 寄存器 (如 0x10) 写入全 1: 0xFFFFFFFF;
          │
          ├─► 2. QEMU 硬件逻辑拦截此写入:
          │      - 设备内部固化的只读位保持为 0 (例如设备需要 64KB MMIO 空间，则低 16 位固定为 0);
          │      - QEMU 计算并保留硬件掩码: BAR = 0xFFFF0000;
          │
          ├─► 3. 软件读回该 BAR 寄存器:
          │      - 读出数值: 0xFFFF0000;
          │      - 软件计算空间大小: Size = ~(0xFFFF0000 & ~0xF) + 1 = 0x10000 (64 KB);
          │
   [BIOS / OS 物理分配阶段]
          │
          ├─► 4. 软件在系统物理内存图中寻找一段空闲物理区间 (如 0xFE000000);
          │
          ├─► 5. 软件将基地址 0xFE000000 写入该 BAR 寄存器;
          │
          └─► 6. QEMU 触发 pci_update_mappings() 回调函数:
                 - 将该设备内部的 MemoryRegion 挂载至系统全局内存地址树的 0xFE000000 处;
                 - 此后客户机访问 0xFE000000..0xFE00FFFF 即精准路由至该虚拟设备。

第五幕：南桥 LPC 总线与 ISA 遗留硬件互联
-----------------------------------------

尽管现代计算机已全面转向 PCIe，但 IBM PC 兼容体系依然需要向后兼容数十年前的标准外设（如键盘、串口、PIT、RTC）。Q35 芯片组通过 **LPC (Low Pin Count) 总线** 维系这一兼容性。

5.1 LPC 总线的物理本质
~~~~~~~~~~~~~~~~~~~~~~
* **硬件压缩**：将传统 98 根信号线的庞大并行 ISA 插槽，压缩为仅有 **7 根物理引脚** 的高频串行总线（4 根数据/地址复用线、1 根 33MHz 时钟线、1 根帧同步线 LFRAME# 与 1 根复位线）；
* **功能不变**：在逻辑与软件编程视角下，LPC 设备对 CPU 而言完全等同于传统的 ISA 端口设备。

5.2 QEMU ICH9 LPC 芯片内部的中断线路由矩阵
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
在 ``hw/isa/lpc_ich9.c`` 中，ICH9 LPC 控制器不仅负责挂载 ISA 设备，还承担着关键的 **PCI 中断引脚重定向（Interrupt Routing）** 职责：

::

   PCIe 设备的 4 条中断引脚 (INTA#, INTB#, INTC#, INTD#)
              │
              ▼ 通过芯片组内部可编程中断路由寄存器 (PIRQA..PIRQH)
   +-------------------------------------------------------------+
   |          ICH9 LPC 中断路由器 (Interrupt Router)             |
   +------------------------------┬------------------------------+
                                  │
                                  ▼ GSI (Global System Interrupts 0..23)
                    +-------------┴-------------+
                    |    I/O APIC (中断控制器)  |
                    +---------------------------+

通过这一硬件模拟拓扑，Q35 主板实现了对现代 PCIe MSI-X 中断与传统 ISA/PCI 共享引脚中断的统一硬件路由。
