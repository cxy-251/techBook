第一幕：虚拟物理内存的拓扑困境——树状重叠与动态性
-------------------------------------------------

在真实的 x86 物理主板上，CPU 发出的物理地址（GPA, Guest Physical Address）并非简单地直接连向内存条，而是被复杂的系统总线仲裁器切片分发至不同的物理芯片：

::

   0x00000000 ────────────────────────────────────────────────────────► 0xFFFFFFFF
   [ 低端 640KB RAM ] [ VGA 显存 ] [ Option ROM / BIOS ] [ 主 DRAM ] [ PCI MMIO 窗口 ] [ APIC/BIOS ]
   (0x00000..0x9FFFF) (0xA0000..)  (0xC0000..0xFFFFF)   (1MB..3.5GB)(0xE0000000..)  (0xFEE00000..)

1.1 物理内存的动态异构性
~~~~~~~~~~~~~~~~~~~~~~~~
* **异构物理属性**：一段连续的 4GB 物理地址空间内，混杂着标准 DRAM 物理内存（可读写）、Shadow ROM 固件（只读/只写受控）、外设 MMIO 寄存器（读写触发硬件副作用）、以及 PCIe ECAM 配置空间；
* **运行时动态重叠与遮蔽**：
  * 当显卡启动时，VGA 显存（``0xA0000 ~ 0xBFFFF``）会直接覆盖在系统主内存之上；
  * 当主板 PAM 寄存器切换时，``0xF0000 ~ 0xFFFFF`` 区域在只读（读取 BIOS ROM）与可写（写入 Shadow RAM）之间动态切换；
  * PCI 设备通过 BAR 寄存器动态申请或释放 MMIO 空间。

1.2 QEMU 的四层内存抽象模型
~~~~~~~~~~~~~~~~~~~~~~~~~~~
为了既能以优雅的树状结构模拟复杂的硬件设备连接，又能在纳秒级时间尺度内响应 CPU 访存，QEMU 在 ``include/exec/memory.h`` 与 ``system/memory.c`` 中设计了四层递进的拓扑抽象：

::

   +-----------------------------------------------------------------------------------+
   |                                 QEMU 四层内存拓扑架构                             |
   |                                                                                   |
   |  [第 1 层：AddressSpace (地址空间根)]                                              |
   |  address_space_memory (物理内存总线) / address_space_io (I/O 端口总线)            |
   |            │                                                                      |
   |            ▼ 根节点指针 (as->root)                                                |
   |  [第 2 层：MemoryRegion 树状拓扑 (设备开发者视角)]                                |
   |  system_memory (Root Container)                                                   |
   |    ├── ram-below-4g (RAM 类型, 优先级 0)                                          |
   |    ├── vga-vram (MMIO/RAM 类型, 优先级 1, 覆盖 0xA0000)                           |
   |    ├── pci-hole (Container, 优先级 0, 映射 0xE0000000..0xFFFFFFFF)                |
   |    │     └── e1000-mmio (BAR 0 映射, 优先级 1)                                   |
   |    └── smram / pam-rom (Alias 类型, 动态切换投影)                                 |
   |            │                                                                      |
   |            ▼ generate_memory_topology() 展平算法 + RCU 原子替换                   |
   |  [第 3 层：FlatView 线性区间数组 (VCPU 快速寻址与 KVM 同步视角)]                   |
   |  FlatRange 数组 (严格单调递增、互不重叠):                                         |
   |  - [0x00000000..0x0009FFFF] -> 映射至 RAMBlock A 偏移 0                           |
   |  - [0x000A0000..0x000BFFFF] -> 映射至 VGA MemoryRegionOps                         |
   |  - [0x000C0000..0x000FFFFF] -> 映射至 BIOS ROM                                    |
   |  - [0x00100000..0xDFFFFFFF] -> 映射至 RAMBlock A 偏移 1MB                         |
   |            │                                                                      |
   |            ▼ qemu_get_ram_ptr()                                                   |
   |  [第 4 层：RAMBlock & RAMList (宿主机物理堆内存分配)]                              |
   |  RAMBlock "pc.ram": host = mmap(NULL, 4GB, PROT_READ|WRITE, MAP_ANON, -1, 0)     |
   +-----------------------------------------------------------------------------------+

第二幕：MemoryRegion 树状层次模型微观解构
-----------------------------------------

``MemoryRegion`` 是 QEMU 描述一切内存与外设地址映射的基石数据结构。

2.1 五大核心 MemoryRegion 衍生类型
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
在 ``include/exec/memory.h`` 中，``struct MemoryRegion`` 通过内部标志位区分五种物理行为：

.. table:: QEMU 五大 MemoryRegion 类型与物理行为特征
   :widths: 15 20 30 35

   +----------------+------------------------+------------------------------------+------------------------------------------------+
   | 类型           | 典型硬件实例           | 宿主内存后备 (Backend)             | 物理读写行为                                   |
   +================+========================+====================================+================================================+
   | **RAM**        | 虚拟机主内存 (DRAM)    | 绑定 ``RAMBlock`` (宿主堆内存指针) | CPU 直读直写，KVM 下注册 EPT 硬件加速          |
   +----------------+------------------------+------------------------------------+------------------------------------------------+
   | **ROM**        | SeaBIOS 固件、OptionROM| 绑定 ``RAMBlock`` (只读标记)       | CPU 允许直接读取，写入操作被硬件忽略或触发异常 |
   +----------------+------------------------+------------------------------------+------------------------------------------------+
   | **MMIO**       | 串口、APIC、网卡寄存器 | 无 RAMBlock，绑定 ``Ops`` 回调函数 | 读写操作触发 VM-Exit，调用 C 语言函数读写外设  |
   +----------------+------------------------+------------------------------------+------------------------------------------------+
   | **Container**  | 系统物理地址总线、PCI  | 无实体内存，纯粹作为子节点容器     | 仅用于在逻辑上聚合与组织多个子 Region          |
   +----------------+------------------------+------------------------------------+------------------------------------------------+
   | **Alias**      | PAM 阴影内存、SMRAM    | 指向另一个目标 MemoryRegion 的切片 | 将目标 Region 的局部区间投影到当前地址空间     |
   +----------------+------------------------+------------------------------------+------------------------------------------------+

2.2 优先级（Priority）与重叠遮蔽仲裁
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
当多个 ``MemoryRegion`` 挂载到同一个父 Container 且地址范围发生重叠时：
* 每一个 ``MemoryRegion`` 包含一个 ``int32_t priority`` 字段（默认为 0）；
* **仲裁法则**：当地址 $A$ 同时落在 $MR_1$ 与 $MR_2$ 范围内时，若 $	ext{Priority}(MR_1) > 	ext{Priority}(MR_2)$，则 $MR_1$ 完全覆盖并遮蔽 $MR_2$。$MR_2$ 中未被重叠的部分依然保持可见。

第三幕：FlatView 展平算法微观时钟与 RCU 并发同步
-------------------------------------------------

树状结构虽然极易被驱动开发者挂载与解挂，但 CPU 寻址不能容忍每次访存都从根节点进行多叉树遍历。QEMU 必须将其**展平（Flatten）** 为一维无重叠数组。

3.1 树状拓扑向线性区间数组的转换算法
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
在 ``system/memory.c:render_memory_region()`` 中，展平引擎采用分治递归算法：

1. **绝对坐标换算**：深度优先遍历 ``MemoryRegion`` 树，将每一级的相对偏移（``addr``）沿路径累加，换算为绝对物理地址 $	ext{Base}_{	ext{abs}}$；
2. **可视区域裁剪（Clipping）**：计算当前 Region 与父容器可见窗口的交集；
3. **优先级区间切片与重叠消除**：
   * 收集所有子 Region 的起始与终止断点，将整个连续空间划分为若干细分微区间 $[x_i, x_{i+1}]$；
   * 在每一个微区间内，筛选出 ``priority`` 最高的非 Container 有效叶子节点；
4. **同质相邻区间合并（Coalescing）**：遍历生成的初始区间序列，若相邻两个区间的属性完全相同（目标设备相同、权限相同且在物理/宿主内存上连续），则原子合并为一个更大的 ``FlatRange``。

::

   [输入：MemoryRegion 树]
   system_memory (0x00000000 ~ 0xFFFFFFFF)
     ├── DRAM (0x00000000 ~ 0x40000000, 1GB, Priority = 0)
     └── VGA_VRAM (0x000A0000 ~ 0x000BFFFF, 128KB, Priority = 1)
          │
          ▼ render_memory_region() 递归切片与合并
   [输出：FlatView 的 FlatRange 数组]
   FlatRange 0: [0x00000000..0x0009FFFF] -> DRAM (偏移 0)
   FlatRange 1: [0x000A0000..0x000BFFFF] -> VGA_VRAM (覆盖 DRAM，优先级高)
   FlatRange 2: [0x000C0000..0x40000000] -> DRAM (偏移 0x000C0000)

3.2 RCU (Read-Copy-Update) 无锁并发切换
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
在多核虚拟机中，存在极高频的读写冲突：
* **读端**：数十个 VCPU 线程每秒发起数亿次内存访问与 TLB 查表（读 ``FlatView``）；
* **写端**：主板设备线程在运行中动态修改 PCI BAR、热插拔内存或切换 PAM 寄存器（写 ``MemoryRegion`` 树）。

QEMU 采用 Linux 内核经典的 **RCU (Read-Copy-Update) 机制** 彻底消除全局大锁：

::

   [主板配置线程 (写端)]                          [VCPU 线程 0..N (读端)]
             │                                              │
   1. 修改 MemoryRegion 树属性 (如 BAR 重定位);             │
   2. 在内存堆中完整分配并构建全新的 FlatView_New;          │ rcu_read_lock();
   3. memory_region_transaction_commit():                   │ 提取当前 FlatView_Old 进行访存;
      原子指针替换: as->current_map = FlatView_New; ───────►│ rcu_read_unlock();
   4. 调用 call_rcu(FlatView_Old, flatview_destroy):        │
      - 等待所有旧读临界区完全退出 (Grace Period);          │
      - 安全释放 FlatView_Old 内存。                        ▼

第四幕：从 GPA 到 HVA 与 HPA——三级地址翻译与 KVM EPT 同步
---------------------------------------------------------

理解虚拟化物理内存的核心，在于厘清三类地址空间及其映射驱动链路。

4.1 内存三级跳与物理指针换算
~~~~~~~~~~~~~~~~~~~~~~~~~~~~

.. table:: 现代硬件虚拟化三级物理地址转换矩阵
   :widths: 20 25 25 30

   +--------------------------+-----------------------+--------------------------+------------------------------------------------+
   | 地址层级                 | 符号定义              | 内存空间所属域           | 硬件/软件转换管理者                            |
   +==========================+=======================+==========================+================================================+
   | **客户机虚拟地址** (GVA) | Guest Virtual Addr    | 客户机进程用户空间       | 客户机 OS 内核页表 (CR3 指向)                  |
   +--------------------------+-----------------------+--------------------------+------------------------------------------------+
   | **客户机物理地址** (GPA) | Guest Physical Addr   | 客户机主板物理内存总线   | QEMU ``FlatView`` / Intel EPT 扩展页表         |
   +--------------------------+-----------------------+--------------------------+------------------------------------------------+
   | **宿主机虚拟地址** (HVA) | Host Virtual Addr     | QEMU 进程在宿主机的堆内存 | Linux 宿主内核页表 (通过 ``mmap`` 产生)         |
   +--------------------------+-----------------------+--------------------------+------------------------------------------------+
   | **宿主机物理地址** (HPA) | Host Physical Addr    | 物理机插槽中的真实 DRAM  | 物理 CPU MMU 硬件电路                          |
   +--------------------------+-----------------------+--------------------------+------------------------------------------------+

换算公式：

.. math::

   	ext{HVA} = 	ext{RAMBlock.host\_ptr} + (	ext{GPA} - 	ext{FlatRange.addr.start}) + 	ext{MemoryRegion.offset\_in\_ramblock}

4.2 MemoryListener 驱动 KVM EPT 内存槽注册
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
当 ``FlatView`` 生成后，QEMU 通过注册的 **``MemoryListener`` 监听器接口**，将变化增量同步给硬件加速内核模块（KVM）。

在 ``accel/kvm/kvm-all.c`` 中：

::

   FlatView 提交变更 ──► 触发 kvm_region_add() 回调
                             │
                             ▼ 构造 struct kvm_userspace_memory_region
   struct kvm_userspace_memory_region mem = {
       .slot = slot_id,                    /* KVM 内存槽序号 (0..511) */
       .flags = 0,                         /* 读写权限 / KVM_MEM_LOG_DIRTY_PAGES */
       .guest_phys_addr = range->start,    /* 客户机物理基地址 (GPA) */
       .memory_size = range->size,         /* 内存区间大小 (字节数) */
       .userspace_addr = (uintptr_t)hva,   /* 对应的宿主机虚拟内存指针 (HVA) */
   };
                             │
                             ▼ 发起内核系统调用
   ioctl(kvm_state->vmfd, KVM_SET_USER_MEMORY_REGION, &mem);

KVM 内核模块接收到该映射关系后，在宿主内核中构建 **EPT (Extended Page Tables) 多级硬件扩展页表**。此后客户机 CPU 发出的所有 GPA 访问直接由物理 CPU 硬件 MMU 自动翻译为 HPA，实现硬件级零软件干预访存。

第五幕：RAMBlock 物理分配与 Dirty Memory 脏页追踪
-------------------------------------------------

客户机数十 GB 的主内存，在宿主机底层究竟是如何真实分配的？

5.1 ``RAMBlock`` 物理内存分配机制
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
在 ``system/physmem.c:qemu_ram_alloc_internal()`` 中，每一个 RAM 类型的 ``MemoryRegion`` 都会在宿主机上分配一个 ``RAMBlock``：

::

   block->host = mmap(NULL, size, PROT_READ | PROT_WRITE,
                      MAP_PRIVATE | MAP_ANONYMOUS, -1, 0);

* **内存超分与按需调页（Demand Paging）**：虽然 QEMU 执行了 4GB 的 ``mmap``，但宿主机操作系统并不会立即分配 4GB 的真实物理内存。只有当虚拟机内部真正向某一页写入数据触发缺页中断时，宿主 Linux 内核才实时分配 4KB 物理页框；
* **HugePages 大页支持**：通过传递 ``-mem-path /dev/hugepages``，QEMU 可使用 2MB 或 1GB 的巨型页（HugePages），显著减少物理 CPU TLB 未命中次数。

5.2 脏页追踪（Dirty Memory Tracking）
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
为了实现**虚拟机热迁移（Live Migration）** 与 **显卡显存脏矩形局部刷新**，QEMU 必须精准获知哪些内存页在运行中被客户机写入修改过：

* **KVM 硬件写保护辅助**：QEMU 向 KVM 启用 ``KVM_MEM_LOG_DIRTY_PAGES``，KVM 硬件将 EPT 页表项置为只读。当客户机发生写操作时触发 EPT 退出，KVM 记录物理位图（Dirty Bitmap）后恢复写权限；
* **高效位图获取**：在热迁移迭代过程中，QEMU 定期调用 ``ioctl(KVM_GET_DIRTY_LOG)`` 原子提取脏页位图，仅将产生变动的内存页通过网络增量发送至目标主机。

小结与下章导读
--------------

本节深入剖析了 QEMU 内存虚拟化的三层拓扑与底层映射机制——从设备开发者维度的 ``MemoryRegion`` 树，到并发快速寻址的 ``FlatView`` RCU 展平数组，再到宿主机真实后备内存 ``RAMBlock`` 与 KVM EPT 内存槽同步。
