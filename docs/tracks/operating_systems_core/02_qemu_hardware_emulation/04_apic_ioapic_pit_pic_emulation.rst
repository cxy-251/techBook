第一幕：模拟时钟源物理节拍——8254 PIT 与 QEMU 虚拟定时器
-------------------------------------------------------

在任何操作系统的多任务调度体系中，时钟中断（Timer Tick）是驱动时间片流逝与任务抢占的心跳。在 IBM PC 架构中，最经典的时钟源是 **Intel 8254 PIT (Programmable Interval Timer)**。

1.1 8254 PIT 的微观电路构成
~~~~~~~~~~~~~~~~~~~~~~~~~~~
8254 芯片内部集成了 3 个独立的 16 位减法计数器（Channel 0 ~ 2），其硬件基准时钟源自物理主板晶振（14.31818 MHz）经过 12 分频后得到的固定频率：

.. math::

   f_{	ext{osc}} = \frac{14.31818 	ext{ MHz}}{12} = 1.193182 	ext{ MHz} \quad (T_{	ext{period}} \approx 838.095 	ext{ ns})

* **Channel 0 (系统时钟)**：输出引脚直连 8259A PIC 的 IRQ 0，用于产生周期性调度时钟中断；
* **Channel 1 (DRAM 刷新)**：历史上用于定时触发 DRAM 内存电容刷新控制器（现代主板由内存控制器自行处理）；
* **Channel 2 (PC 喇叭)**：输出直连机箱蜂鸣器，用于控制扬声器发声频率与脉冲宽度。

1.2 QEMU 8254 虚拟定时器实现机制
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
在纯软件模拟中，QEMU 不可能真的每隔 838 纳秒执行一次 CPU 减法循环（这会彻底耗尽宿主 CPU 算力）。在 ``hw/timer/i8254.c`` 中，QEMU 采用了 **事件驱动的时间差投影算法（Time-Projection Algorithm）**：

::

   +-----------------------------------------------------------------------------------+
   |                                 QEMU 8254 PIT 模拟逻辑                            |
   |                                                                                   |
   |  [客户机写入 Reload 计数初始值 N] (如 11932, 对应 100Hz 时钟)                      |
   |  1. 记录初始写入时刻的宿主虚拟纳秒时间戳: pit->count_load_time = qemu_clock_get_ns(); |
   |  2. 计算下一次中断到期纳秒时间:                                                   |
   |     expire_time = count_load_time + (N * 1000000000ULL / 1193182ULL);             |
   |  3. 向 QEMU 全局事件循环注册定时器: timer_mod(pit->timer, expire_time);          |
   |                                                                                   |
   |  [客户机实时读取当前 Counter 计数值]                                               |
   |  - 并不随时间递减，而是在读取瞬间动态反算:                                         |
   |    current_ns = qemu_clock_get_ns();                                              |
   |    elapsed_ticks = (current_ns - pit->count_load_time) * 1193182ULL / 1000000000ULL; |
   |    return (pit->latched_count - (elapsed_ticks % N));                             |
   +-----------------------------------------------------------------------------------+

当定时器到期时，QEMU 触发回调函数，调用 ``qemu_set_irq(s->irq, 1)`` 将输出电平拉高，驱动中断控制器。

第二幕：传统 8259A PIC 双片级联模拟与状态机
--------------------------------------------

8259A 是单核 PC 时代的唯一中断枢纽。QEMU 在 ``hw/intc/i8259.c`` 中用 C 语言结构体 ``PicState`` 完整复刻了其内部三组 8 位硬件寄存器状态机：

::

   [外设引脚输入 IRQ 0..7]
             │
             ▼
   +-----------------------------------------------------------------------------------+
   |  8259A 内部寄存器阵列 (PicState)                                                  |
   |                                                                                   |
   |  1. IRR (Interrupt Request Register, 8-bit):                                      |
   |     - 记录当前哪些外设引脚正处于拉高申请状态 (1=有中断请求, 0=空闲);              |
   |                                                                                   |
   |  2. IMR (Interrupt Mask Register, 8-bit, 通过端口 0x21/0xA1 读写):                |
   |     - 屏蔽掩码位 (1=屏蔽该 IRQ, 0=允许放行);                                     |
   |                                                                                   |
   |  3. ISR (In-Service Register, 8-bit):                                             |
   |     - 记录当前 CPU 正在执行哪一级中断服务 (防止低优先级中断打断高优先级中断);     |
   |                                                                                   |
   |  4. 优先级仲裁逻辑 (pic_update_irq):                                              |
   |     - 待处理有效中断: pending = irr & ~imr;                                       |
   |     - 在 pending 中找出优先级最高的引脚 (默认 IRQ0 最高, IRQ7 最低);              |
   |     - 若该优先级严格高于当前 ISR 中的最高优先级, 则拉高 output 引脚通知 CPU!      |
   +-----------------------------------------------------------------------------------+

2.1 中断应答与 EOI (End of Interrupt) 状态机
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
当 CPU 响应中断后，必须显式向 8259A 发送 **EOI 命令（向 I/O 端口 0x20/0xA0 写入 0x20）**：
* QEMU 拦截到写端口操作后，清除 ``s->isr`` 中对应的最高优先级位；
* 此时被阻塞的次优先级中断才能再次通过 ``pic_update_irq()`` 产生中断请求。

第三幕：Local APIC 与 I/O APIC 的 MMIO 模拟实现
------------------------------------------------

在多核 SMP 系统中，8259A 被边缘化，系统的核心中断路由全面转移至 **APIC (Advanced Programmable Interrupt Controller) 架构**。

::

   +-----------------------------------------------------------------------------------+
   |                                 QEMU APIC 拓扑架构                                |
   |                                                                                   |
   |   [VCPU 0 核心]                                [VCPU 1 核心]                      |
   |   +---------------------------------------+    +-------------------------------+  |
   |   | Local APIC (APICCommonState)          |    | Local APIC                    |  |
   |   | - 4KB MMIO 映射于 GPA 0xFEE00000      |    | - 4KB MMIO 映射于 GPA 0xFEE00000|
   |   | - TPR (0x080) / EOI (0x0B0) / ICR ... |    |                               |  |
   |   +-------------------▲-------------------+    +---------------▲---------------+  |
   |                       │                                        │                  |
   |   ════════════════════╪════════════════════════════════════════╪════ 系统总线   |
   |                       │ APIC Bus 中断数据包 (APIC ID + Vector) │                  |
   |                       └───────────────────┬────────────────────┘                  |
   |                                           │                                       |
   |                       +-------------------┴-------------------+                   |
   |                       | I/O APIC (IOAPICCommonState)          |                   |
   |                       | - 4KB MMIO 映射于 GPA 0xFEC00000      |                   |
   |                       | - 24 个 64 位重定向表项 (RTE 0..23)   |                   |
   |                       +-------------------▲-------------------+                   |
   |                                           │ GSI (0..23)                           |
   |                       [主板外设：PCIe / 串口 / HPET 定时器]                       |
   +-----------------------------------------------------------------------------------+

3.1 Local APIC 的 MMIO 读写模拟（``hw/intc/apic.c``）
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
QEMU 为每个虚拟 CPU 分配一个 ``APICCommonState``，并在物理地址 ``0xFEE00000`` 注册一个大小为 4KB 的 ``MemoryRegion``，绑定专属的 ``MemoryRegionOps`` 回调函数：

* **``0x080 (TPR, Task Priority Register)`` 写入拦截**：
  * 当操作系统内核修改任务优先级时，QEMU 更新 ``s->tpr``，并立即重新评估当前挂起中断（Pending IRQ）是否可以穿透送达；
* **``0x0B0 (EOI, End of Interrupt)`` 写入拦截**：
  * 内核写入 EOI 时，QEMU 在单循环内扫描 ``s->isr`` 位图，将当前最高位清零，并检查是否需要发送下一个挂起中断；
* **``0x300 / 0x310 (ICR, Interrupt Command Register)`` 核间中断分发**：
  * 当 CPU 0 写入 ICR 向 CPU 1 发送核间中断（IPI）时，QEMU 提取目标 APIC ID，在全局 CPU 列表中定位目标 VCPU 实例，直接调用 ``apic_deliver_irq(target_vcpu, vector, delivery_mode)``。

3.2 I/O APIC 间接寻址与重定向表项（RTE）模拟
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
在 ``hw/intc/ioapic.c`` 中，I/O APIC 映射在 ``0xFEC00000``，采用两个 32 位间接访问寄存器：

* **``0xFEC00000 (IOREGSEL)``**：写入要访问的内部寄存器编号（Index 0x00 ~ 0x3F）；
* **``0xFEC00010 (IOWIN)``**：读写对应寄存器的 32 位数据窗口。

当外设触发中断引脚（如串口触发 GSI 4）时：
1. I/O APIC 提取 ``i82093->ioredtbl[4]``（64 位重定向表项）；
2. 解析目标投递模式（Fixed 固定投递 / Lowest Priority 最低优先级）、中断向量号（Vector）与目标 APIC ID；
3. 构建 APIC 消息包，路由投递至目标 Local APIC 的待决中断寄存器（IRR 位图）。

第四幕：KVM 内核中断控制器（In-Kernel irqchip）与硬件注入
----------------------------------------------------------

在初期纯用户态模拟方案中，每次外部中断产生都必须经历极其沉重的性能惩罚：

::

   [纯用户态模拟方案的性能灾难]
   外设产生中断 ──► 触发 VM-Exit 退出到宿主机 ──► 陷入宿主内核 KVM ──► 返回用户态 QEMU 进程
   ──► QEMU 计算 APIC 状态机 ──► 调用 ioctl(KVM_INTERRUPT) ──► 重新进入 KVM ──► VM-Entry 注入中断
   (一次时钟中断产生 2 次高开销的上下文切换，每秒上千次中断将彻底打垮系统性能!)

4.1 KVM In-Kernel irqchip 下沉架构
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
为了实现生产级虚拟化性能，QEMU 在初始化时向 Linux KVM 发起 ``ioctl(vm_fd, KVM_CREATE_IRQCHIP)``：
* **状态机全面下沉**：8259A PIC、I/O APIC 与所有 VCPU 的 Local APIC 状态机代码被**100% 移入 Linux 内核模块（``arch/x86/kvm/lapic.c`` 与 ``arch/x86/kvm/ioapic.c``）**；
* **零退出闭环**：PIT 时钟到期后直接在内核态驱动 Local APIC 状态机，整个中断生成、仲裁与分发完全在内核态闭环，**产生的用户态 VM-Exit 次数暴跌为零**。

4.2 Intel VT-x VMCS 硬件中断注入时序
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
当内核态 KVM 的 Local APIC 判定需要向当前 VCPU 投递中断向量 $V$ 时，它并不需要修改任何客户机内存代码，而是利用了 Intel 物理 CPU 的硬件虚拟化中断注入特性：

::

   +-----------------------------------------------------------------------------------+
   |                  Intel VT-x VMCS 硬件中断注入 (VM-Entry Injection)                |
   |                                                                                   |
   |  1. KVM 内核准备恢复客户机执行 (调用 VMLAUNCH / VMRESUME 指令前):                  |
   |     - 写入 VMCS 寄存器:                                                           |
   |       vmcs_write32(VM_ENTRY_INTR_INFO_FIELD,                                      |
   |                    vector | INTR_TYPE_EXT_INTR | INTR_INFO_VALID_MASK);          |
   |                                                                                   |
   |  2. 物理 CPU 执行 VMRESUME 进入 VMX Non-Root 模式瞬间:                           |
   |     - 硬件电路自动检测到 VM_ENTRY_INTR_INFO_FIELD 有效标志;                        |
   |     - 物理 CPU 并不执行客户机原 RIP 处的指令，而是**直接在硬件层面触发中断异常流程**: |
   |       a. 自动读取客户机 IDTR 索引中断门描述符;                                    |
   |       b. 自动从 TSS 读取 RSP0 完成内核栈原子切换;                                 |
   |       c. 自动压入 SS/RSP/RFLAGS/CS/RIP;                                           |
   |       d. 硬件直接跳转至客户机中断处理函数入口!                                    |
   +-----------------------------------------------------------------------------------+

通过 VMCS 硬件注入，虚拟中断的投递过程完全等价于物理裸机上的硬中断响应，具备纳秒级的硬件响应速度。

第五幕：全模块架构总结（从硬件模拟迈向固件启动）
------------------------------------------------

至此，**模块 02：QEMU 硬件级虚拟化与平台芯片组模拟** 全部 4 节已全量落盘！

我们系统化构筑了虚拟化世界的完整硬件基座：
1. **计算引擎**：TCG 动态二进制翻译状态机与 Linux `/dev/kvm` 硬件加速 VCPU 线程；
2. **总线拓扑**：QOM 设备对象模型、Q35 PCIe 根复合体与 LPC 传统总线桥；
3. **物理内存**：MemoryRegion 树、FlatView RCU 并发展平算法与 KVM EPT 内存槽同步；
4. **中断时钟**：8254 PIT 虚拟脉冲、8259A PIC 级联仲裁与 KVM In-Kernel irqchip 硬件注入。
