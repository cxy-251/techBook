第一幕：PCI 树状总线拓扑的递归发现与编号算法
---------------------------------------------

在计算机系统中，PCI/PCIe 设备并非平铺在单一总线上，而是通过 **PCI-to-PCI 桥接器（P2P Bridge）** 与 PCIe 根端口构成分支繁复的树状网络：

::

   +-----------------------------------------------------------------------------------+
   |                                 PCI 树状总线拓扑模型                              |
   |                                                                                   |
   |  [Host Bridge 宿主桥]                                                             |
   |         │                                                                         |
   |         ▼ 根总线 (Bus 0, pcie.0)                                                  |
   |  ═══════╪════════════════════════════════════════════════════════════════════     |
   |         ├── Device 00:01.0 (VGA 显卡, 端点设备)                                   |
   |         ├── Device 00:02.0 (e1000 网卡, 端点设备)                                 |
   |         └── Device 00:03.0 (PCIe Root Port 桥接器)                                |
   |                   │                                                               |
   |                   ▼ 次级总线 (Secondary Bus 1)                                    |
   |            ═══════╪══════════════════════════════════════════════════             |
   |                   ├── Device 01:00.0 (NVMe 存储控制器)                            |
   |                   └── Device 01:01.0 (PCIe Switch 下游桥接器)                      |
   |                             │                                                     |
   |                             ▼ 附属总线 (Subordinate Bus 2)                        |
   |                      ═══════╪════════════════════════════                         |
   |                             └── Device 02:00.0 (USB 3.0 xHCI 控制器)              |
   +-----------------------------------------------------------------------------------+

1.1 桥接器的三组总线编号寄存器
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
每个 PCI-to-PCI 桥接器的配置空间内部包含 3 个 8 位关键寄存器，决定了总线事务向上和向下的物理路由边界：
* **``PRIMARY_BUS (偏移 0x18)``**：记录该桥上游直连的父总线编号；
* **``SECONDARY_BUS (偏移 0x19)``**：记录该桥引出的下游直连子总线编号；
* **``SUBORDINATE_BUS (偏移 0x1A)``**：记录该桥下游管辖的所有分支总线中的**最大总线编号**。

1.2 动态深度优先递归拓扑遍历算法
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
在 ``src/fw/pciinit.c:pci_bios_init_bus_rec()`` 中，SeaBIOS 执行了经典的自顶向下拓扑编号流水线：

::

   static void pci_bios_init_bus_rec(int bus, u8 *pci_bus) {
       // 阶段 1：防御性复位。将当前总线上所有桥的从属总线设为 0，防止地址重叠
       foreachbdf(bdf, bus) {
           if (pci_config_readw(bdf, PCI_CLASS_DEVICE) == PCI_CLASS_BRIDGE_PCI) {
               pci_config_writeb(bdf, PCI_SECONDARY_BUS, 255);
               pci_config_writeb(bdf, PCI_SUBORDINATE_BUS, 0);
           }
       }

       // 阶段 2：深度优先遍历与动态编号
       foreachbdf(bdf, bus) {
           if (pci_config_readw(bdf, PCI_CLASS_DEVICE) != PCI_CLASS_BRIDGE_PCI)
               continue;

           pci_config_writeb(bdf, PCI_PRIMARY_BUS, bus);     // 配置父总线号
           (*pci_bus)++;                                     // 全局总线计数器累加 1
           u8 secbus = *pci_bus;
           pci_config_writeb(bdf, PCI_SECONDARY_BUS, secbus);// 分配次级总线号

           // 临时将 subordinate 设为 255，允许配置空间事务穿透至下游
           pci_config_writeb(bdf, PCI_SUBORDINATE_BUS, 255);

           // 递归向下遍历子树
           pci_bios_init_bus_rec(secbus, pci_bus);

           // 回溯：将当前探测到的最大总线编号回填至 SUBORDINATE_BUS
           pci_config_writeb(bdf, PCI_SUBORDINATE_BUS, *pci_bus);
       }
   }

通过该算法，整个主板所有嵌套 PCI/PCIe 桥接器的拓扑层次与总线寻址范围被完全确定。

第二幕：BAR 空间资源测算与分配算法（两阶段裁决流水线）
-------------------------------------------------------

每个 PCI 设备通常需要若干段物理内存（MMIO）或 I/O 端口空间来映射其硬件控制寄存器与数据缓冲区。SeaBIOS 采用两阶段（Two-Pass）算法实现全局最优分配。

2.1 阶段一：大小探测与排序（Pass #1: ``pci_bios_check_devices()``）
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
在 ``src/fw/pciinit.c`` 中：

1. **探测 BAR 所需物理空间**（``pci_bios_get_bar()``）：
   * 向设备的 BAR 写入全 1（``0xFFFFFFFF``），读回掩码值；
   * 解析资源属性：I/O 空间（``PCI_REGION_TYPE_IO``）、32 位不可预取内存（``PCI_REGION_TYPE_MEM``）、64 位可预取内存（``PCI_REGION_TYPE_PREFMEM``）；
   * 计算对齐尺寸：$	ext{Size} = \sim(	ext{Val} \ \& \ 	ext{Mask}) + 1$；
2. **按对齐粒度降序贪心排序（Greedy Bin-Packing）**：
   * 在 ``pci_region_create_entry()`` 中，每个总线维护 3 个独立链表（IO, MEM, PREFMEM）；
   * **排序法则**：优先按 ``align`` 从大到小排序，若对齐相同则按 ``size`` 从大到小排序。

.. important::
   **为什么要按对齐粒度降序排序？**
   若先分配 4KB 空间，再分配 64MB 空间，为了满足 64MB 的自然边界对齐要求（基地址必须是 64MB 整数倍），将在中间产生高达近 64MB 的未利用物理内存空洞（Memory Fragmentation）。
   从大到小分配确保了每一个大块都能严丝合缝地对齐，完全消除了内部碎片。

2.2 阶段二：物理基地址分配与桥窗口映射（Pass #2: ``pci_bios_map_devices()``）
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
在排序完成后，SeaBIOS 从系统全局可用物理地址窗口中自顶向下切片分配实际基地址：

::

   +-----------------------------------------------------------------------------------+
   |                             系统物理地址空间分配规划                              |
   |                                                                                   |
   |  4GB 边界以上 (64-bit MMIO 窗口):                                                 |
   |  pcimem64_start ┌────────────────────────────────────────────────────────┐        |
   |                 │ 64-bit 可预取内存 (PREFMEM64): 映射大容量显存、NVMe 队列│        |
   |  pcimem64_end   └────────────────────────────────────────────────────────┘        |
   |                                                                                   |
   |  4GB 边界以下 (32-bit MMIO 窗口):                                                 |
   |  0xFEBFFFFF     ┌────────────────────────────────────────────────────────┐        |
   |  (从顶向下分配) │ 32-bit PREFMEM (不可扩展的 32 位显卡设备)               │        |
   |                 ├────────────────────────────────────────────────────────┤        |
   |                 │ 32-bit 非预取 MMIO (网卡寄存器、SATA 控制器)           │        |
   |  pcimem_start   └────────────────────────────────────────────────────────┘        |
   |  (紧随 DRAM 顶端, 如 0x80000000)                                                  |
   |                                                                                   |
   |  I/O 端口窗口:                                                                    |
   |  0xC000 ~ 0xFFFF (总容量 16KB): 顺序分配给所有 PCI 设备的 I/O BAR                |
   +-----------------------------------------------------------------------------------+

3. **回写设备与配置桥窗口**（``pci_region_map_one_entry()``）：
   * 对终端设备：调用 ``pci_set_io_region_addr()``，将计算出的 GPA 基地址写入其 BAR 寄存器；
   * 对桥接器：将下游子树所需的地址范围写入桥的 ``PCI_MEMORY_BASE / LIMIT`` 与 ``PCI_IO_BASE / LIMIT`` 寄存器，建立硬件层级的总线事务过滤窗口。

第三幕：设备最终使能与中断引脚路由
-----------------------------------

在 BAR 地址全部分配就绪后，SeaBIOS 执行 ``pci_bios_init_device()`` 激活硬件：

1. **中断引脚到中断线映射**：
   * 读取硬件配置空间 ``PCI_INTERRUPT_PIN``（值 1~4 对应 INTA# ~ INTD#）；
   * 调用主板中断路由函数 ``pci_slot_get_irq()``，通过南桥 LPC / PIIX4 的旋转路由算法计算出全局中断号（GSI，如 IRQ 10 或 11）；
   * 将分配的中断号写入 ``PCI_INTERRUPT_LINE (0x3C)``，供操作系统设备驱动后续读取。
2. **总线响应使能（Bus Mastering & Memory Enable）**：
   * 向配置空间 ``PCI_COMMAND (0x04)`` 寄存器写入控制掩码：
     $$	ext{PCI\_COMMAND} \leftarrow 	ext{PCI\_COMMAND\_IO} \ | \ 	ext{PCI\_COMMAND\_MEMORY} \ | \ 	ext{PCI\_COMMAND\_SERR}$$
   * **物理生效**：此后设备内部的地址解码器正式通电激活，开始响应来自 CPU 或其他总线主控发起的 MMIO 与 I/O 读写。

第四幕：Option ROM 扩展卡固件体系与安全调用机制
------------------------------------------------

许多 PCI 设备（如显卡、RAID 卡、PXE 网卡）随硬件集成了专用的只读固件——**Option ROM**，用于在操作系统加载前提供基本的输入输出能力（如在屏幕上打印开机画面或通过网络下载引导文件）。

4.1 标准 Option ROM 头部物理布局（``src/std/optionrom.h``）
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
所有合法的 Option ROM 必须放置在 UMA ``0xC0000 ~ 0xEA000`` 物理内存区间，并以 512 字节或 2KB 边界对齐。其前部具备严格的标准化头部结构：

::

   0x00               0x02 0x03               0x18         0x1A         0x1E
   +----------------------+--------------------+------------+------------+------+
   | 魔法签名 0x55AA      | 长度 (Size, 512B计)| 入口指令   | PCI头偏移  | PnP头偏移  |
   | (2 字节: 0x55, 0xAA) | (1 字节, 如 128)   | (jmp init) | (2 字节)   | (2 字节)   |
   +----------------------+--------------------+------------+------------+------+

.. important::
   **Option ROM 严格校验和定律**：
   SeaBIOS 在加载任何 ROM 前，必须对其全部字节进行累加校验（``is_valid_rom()``）：

   .. math::

      \sum_{i=0}^{	ext{Size} 	imes 512 - 1} 	ext{Byte}[i] \equiv 0 \pmod{256}

   若校验和不为 0，表明 ROM 镜像在传输过程中损坏，固件拒绝执行，防止 CPU 执行非法机器码崩溃。

4.2 显卡 VBIOS 加载与执行（``vgarom_setup()``）
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
在加电自检过程中，显示输出具有最高优先级。在 ``src/optionroms.c:vgarom_setup()`` 中：
1. 扫描 PCI 总线，寻找类别为 ``PCI_CLASS_DISPLAY_VGA (0x0300)`` 的主显卡；
2. 从显卡 Expansion ROM BAR（偏移 0x30）或 QEMU fw_cfg 虚拟通道读取 VBIOS 镜像；
3. 将镜像完整复制到固定物理地址 **``0x000C0000``**；
4. 调用 ``__callrom(0xC000, 0x0003, bdf)``：
   * 构建 ``struct bregs`` 寄存器帧，传递 ``AX = BDF``（显卡总线编号）；
   * 通过 ``farcall16big()`` 穿梭至实模式，执行 ``lcallw $0xC000, $0x0003``；
   * VBIOS 初始化显卡芯片，挂载 ``INT 10h`` 中断服务，将屏幕切换为标准 80x25 文本控制台。

4.3 引导扩展向量：BEV 与 BCV 注册
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
对于非显卡 Option ROM（如 SCSI/SATA RAID 卡或 PXE 网卡），PnP 规范禁止其直接抢占引导权，而是通过头部内的 PnP 结构体暴露入口：
* **BCV (Boot Connection Vector)**：存储设备挂载向量。SeaBIOS 依次调用各控制器的 BCV，使其将自身的磁盘驱动挂载到 ``INT 13h`` 链表；
* **BEV (Bootstrap Entry Vector)**：网络引导向量。网卡 PXE 固件提供此向量，供用户在启动菜单选择网络引导时直接跳转执行。

第五幕：防死锁与 Option ROM 恶意劫持防护
-----------------------------------------

在早期 PC 时代，部分老旧或恶意的 Option ROM 固件在执行初始化时，会强行覆写物理内存 ``0x00000064 (INT 19h)`` 处的向量指针，强行将机器劫持进入其自定义的引导流程。

SeaBIOS 在 ``src/optionroms.c:init_pcirom()`` 中设计了防御性闭环：

::

   static void init_pcirom(struct pci_device *pci, int isvga, u64 *sources) {
       // 1. 记录执行前 INT 19h 是否已被固件正确托管
       int irq_was_captured = boot_irq_captured();

       // 2. 调用第三方 Option ROM 初始化入口
       init_optionrom(rom, pci->bdf, isvga);

       // 3. 检查 INT 19h 是否遭到非法篡改
       if (boot_irq_captured() && !irq_was_captured && !file && !isvga) {
           dprintf(1, "PnP optionrom (bdf %pP) captured int19, restoring
", pci);
           // 4. 强制复原 INT 19h 指向 SeaBIOS 官方 entry_19_official 处理函数!
           boot_irq_restore();
       }
   }

通过这一机制，主板固件确保了自身对后续多盘引导与启动菜单排序（Boot Menu）的绝对控制权。
