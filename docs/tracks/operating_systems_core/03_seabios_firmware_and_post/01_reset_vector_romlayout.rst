第一幕：硬件通电复位（Power-On Reset）瞬间与 CPU 初始状态机
-----------------------------------------------------------

当计算机电源开启时，主板电源供应单元（PSU）并不立即让 CPU 运转，而是经历严格的半导体电气稳定时序。

1.1 Power Good 信号与 RESET# 引脚时序
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
1. **电压稳定延迟（100ms ~ 500ms）**：电源内部的 PWM 控制芯片在输出的 $+12	ext{V}, +5	ext{V}, +3.3	ext{V}$ 直流电压达到额定阈值且纹波稳定后，将主板上的 **``PWRGD (Power Good)``** 引脚拉高至 $5	ext{V}$；
2. **时钟振荡器就绪**：主板时钟发生器开始向 CPU 发送稳定的差分时钟信号（CLK/CLK#）；
3. **RESET# 信号释放**：主板芯片组在收到 PWRGD 信号后，维持 CPU 的 ``RESET#`` 引脚处于低电平数毫秒（触发 CPU 内部全部触发器强制清零），随后将其拉高释放。在 RESET# 变高的第一个时钟上升沿，CPU 内部硬件状态机正式启动！

1.2 x86_64 处理器复位瞬间的寄存器绝对初始物理状态
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
在物理硬件层面，刚通电的 x86_64 CPU 并非运行在 64 位长模式下，也不是教科书简单概括的“16 位实模式”，而是一种具备 **32 位隐藏段基址的特殊伪实模式（Real Address Mode with Hidden Base）**：

.. table:: x86_64 处理器通电复位（Reset）瞬间核心寄存器物理状态
   :widths: 20 25 25 30

   +--------------------------+-----------------------+--------------------------+------------------------------------------------+
   | 寄存器                   | 初始物理电平数值      | 对应硬件位域解释         | 体系结构物理含义                               |
   +==========================+=======================+==========================+================================================+
   | **``RIP / EIP``**        | ``0x0000FFF0``        | 偏移地址 64KB - 16 字节  | 指向当前代码段末尾 16 字节处                   |
   +--------------------------+-----------------------+--------------------------+------------------------------------------------+
   | **``CS (可见选择子)``**  | ``0xF000``            | 传统 16 位段基址 0xF0000 | 维持向后兼容性显示的伪段基址                   |
   +--------------------------+-----------------------+--------------------------+------------------------------------------------+
   | **``CS.Base (隐藏基址)``**| **``0xFFFF0000``**   | **4GB 顶端高位物理基地址**| **硬件芯片内部不可见的 32 位段描述符缓存**     |
   +--------------------------+-----------------------+--------------------------+------------------------------------------------+
   | **``CS.Limit (隐藏界限)``**| ``0x0000FFFF`` (64KB)| 64KB 寻址界限            | 允许从基地址向上偏移 64KB                      |
   +--------------------------+-----------------------+--------------------------+------------------------------------------------+
   | **``CR0``**              | ``0x60000010``        | CD=1, NW=1, ET=1, PE=0   | 保护模式关闭(PE=0)，CPU 内部 Cache 禁用(CD/NW) |
   +--------------------------+-----------------------+--------------------------+------------------------------------------------+
   | **``RFLAGS``**           | ``0x00000002``        | Bit 1 恒等于 1, IF=0     | 外部硬件中断被完全禁止(关中断状态)             |
   +--------------------------+-----------------------+--------------------------+------------------------------------------------+
   | **``EDX``**              | ``0x000206A0`` (示例) | CPUID 家族/型号/步进     | 芯片自检内置的处理器硬件型号指纹               |
   +--------------------------+-----------------------+--------------------------+------------------------------------------------+

.. important::
   **复位向量（Reset Vector）物理取指地址推导**：
   在实模式下，软件通常认为物理地址计算公式为 $	ext{CS} 	imes 16 + 	ext{IP}$。
   但通电第一瞬间，CPU 硬件实际直接使用隐藏的描述符缓存基地址（``CS.Base``）进行物理寻址：

   .. math::

      	ext{Physical\_Fetch\_Address} = 	ext{CS.Base} + 	ext{EIP} = 0	ext{xFFFF0000} + 0	ext{x0000FFF0} = \mathbf{0	ext{xFFFFFFF0}}

   这个物理地址 ``0xFFFFFFF0`` 正是全球所有 x86/x86_64 处理器硬件硬编码的 **第一条指令物理入口（Reset Vector）**，其物理位置距离 4GB 地址空间顶端（``0xFFFFFFFF``）恰好只有 **16 个字节**。

第二幕：主板芯片组 Shadow ROM 与物理内存解码拓扑
-------------------------------------------------

为什么 CPU 从 4GB 顶端（``0xFFFFFFF0``）取指，却能读取到主板 SPI Flash 芯片中的 SeaBIOS 固件？

::

   +-----------------------------------------------------------------------------------+
   |                             系统物理内存地址空间映射                              |
   |                                                                                   |
   |  4GB 空间顶端                                                                     |
   |  0xFFFFFFFF ┌──────────────────────────────────────────────┐                       |
   |  0xFFFFFFF0 │ 复位向量 (Reset Vector): ljmpw $SEG_BIOS, ...│ ◄── CPU 通电第一条指令 |
   |             ├──────────────────────────────────────────────┤                       |
   |  0xFFFE0000 │ SeaBIOS 128KB 固件完整镜像 (只读 ROM 映射)   │                       |
   |             └──────────────────────────────────────────────┘                       |
   |                                                                                   |
   |                            ... (DRAM 主内存与 PCI MMIO 窗口) ...                  |
   |                                                                                   |
   |  1MB 空间顶端                                                                     |
   |  0x00100000 ┌──────────────────────────────────────────────┐                       |
   |  0x000F0000 │ 传统 BIOS 兼容窗口 (Shadow ROM 64KB, F-Segment)│                       |
   |  0x000E0000 │ 扩展 BIOS 兼容窗口 (Shadow ROM 64KB, E-Segment)│                       |
   |             └──────────────────────────────────────────────┘                       |
   |  0x00000000 ┌──────────────────────────────────────────────┐                       |
   |             │ 传统实模式 640KB 低端物理内存 (DRAM)          │                       |
   |             └──────────────────────────────────────────────┘                       |
   +-----------------------------------------------------------------------------------+

2.1 芯片组的 ROM 双重地址窗口解码
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
主板北桥芯片（Q35 / I440FX）在硬件总线层面，将同一块只读 BIOS Flash 芯片的硬件内容，通过地址译码逻辑**同时投影至物理地址空间的两个不同位置**：
1. **高端 4GB 启动窗口（``0xFFFE0000 ~ 0xFFFFFFFF``，128KB）**：用于现代 32/64 位 CPU 上电时在 4GB 空间直接取指；
2. **低端 1MB 兼容窗口（``0x000E0000 ~ 0x000FFFFF``，128KB）**：用于传统 16 位 DOS/实模式软件与 BIOS 中断服务调用。

2.2 QEMU 中的固件加载与只读映射实现
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
在 QEMU 源码 ``hw/i386/pc_sysfw.c`` 中：
* QEMU 读取磁盘上的 ``bios.bin``（SeaBIOS 编译产物），创建一块名为 ``pc.bios`` 的 ``MemoryRegion``（RAMBlock 标记为 Read-Only）；
* 调用 ``memory_region_add_subregion()``，将其挂载到 ``system_memory`` 的 ``0xFFFE0000`` 处；
* 同时在 ``0xE0000 ~ 0xFFFFF`` 建立一个 Alias 别名区域，直接指向 ``pc.bios``。

第三幕：SeaBIOS ``romlayout.S`` 汇编入口微观解构
-----------------------------------------------

在开源主板固件 SeaBIOS（``/Volumes/LinuxKernel/seabios``）中，固件的全部物理入口、实模式/保护模式跳板与中断向量桩均定义在 ``src/romlayout.S``。

3.1 复位向量处的 16 字节极限代码
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
在 ``src/romlayout.S`` 的最末尾（第 354 行），SeaBIOS 使用 GNU 汇编器宏将复位入口强制对齐在固件镜像末尾 16 字节处（即偏移 ``0xFFF0``）：

::

        ORG 0xfff0 // Power-up Entry Point (物理地址 0xFFFFFFF0)
        .global reset_vector
reset_vector:
        ljmpw $SEG_BIOS, $entry_post

        // 0xfff5 - BiosDate in misc.c: 8 字节固件发布日期 (如 "06/23/99\0")
        // 0xfffe - BiosModelId in misc.c: 1 字节主板模型 ID (0xFC)
        // 0xffff - BiosChecksum in misc.c: 1 字节校验和补码

.. danger::
   **第一条长跳转指令（``ljmpw $SEG_BIOS, $entry_post``）的物理意义**：
   * 为什么通电第一条指令必须是段间长跳转（Far Jump）？
   * **物理原因**：虽然 CPU 当前在 ``0xFFFFFFF0`` 执行，但其 ``CS`` 寄存器的隐藏基址是特殊的 ``0xFFFF0000``。如果此时执行普通近跳转或直接顺序执行，一旦超出 64KB 界限将引发不可预测故障。
   * **硬件清洗效应**：执行 ``ljmpw $0xF000, $entry_post`` 时，CPU 硬件**强制将 ``CS.Base`` 重新从选择子计算为 $0	ext{xF000} 	imes 16 = 0	ext{x000F0000}$**，彻底清除了通电时的隐藏基址特权，将 CPU 平稳拉回标准的 1MB 传统实模式物理寻址空间！

3.2 POST 总入口：``entry_post``（位于 0xE05B）
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
在 ``src/romlayout.S`` 第 286 行，长跳转命中的目标地址为 ``entry_post``：

::

        ORG 0xe05b
entry_post:
        cmpl $0, %cs:HaveRunPost                // 检查是否为 S3 睡眠唤醒或软重启
        jnz entry_resume
        ENTRY_INTO32 _cfunc32flat_handle_post   // 正常冷启动入口：跃迁进入 32 位模式

第四幕：从 16 位实模式向 32 位扁平保护模式的早期跃迁
-----------------------------------------------------

虽然传统 BIOS 的对外接口是 16 位中断服务（如 INT 13h），但现代 SeaBIOS 内部的加电自检（POST）与设备探测逻辑 **99% 采用 C 语言编写**。为了运行 32 位 C 代码，CPU 必须以最快速度脱离 16 位实模式！

这一壮举在 ``src/romlayout.S`` 的核心函数 ``transition32`` 中完成：

::

   +-----------------------------------------------------------------------------------+
   |                         transition32 模式跃迁微观流水线                           |
   |                                                                                   |
   |  [1. 彻底关闭硬件中断与清除方向标志]                                              |
   |      cli                                                                          |
   |      cld                                                                          |
   |                                                                                   |
   |  [2. 物理屏蔽不可屏蔽中断 NMI]                                                    |
   |      movl $CMOS_RESET_CODE | NMI_DISABLE_BIT, %eax   /* 0x8F */                   |
   |      outb %al, $PORT_CMOS_INDEX                      /* 写入端口 0x70 */          |
   |      inb  $PORT_CMOS_DATA, %al                       /* 读端口 0x71 刷新总线 */   |
   |                                                                                   |
   |  [3. 开启快速 A20 地址线 (Fast A20 Gate)]                                         |
   |      inb  $PORT_A20, %al                             /* 读端口 0x92 */            |
   |      orb  $A20_ENABLE_BIT, %al                       /* 置位 Bit 1 */             |
   |      outb %al, $PORT_A20                             /* 写回端口 0x92 */          |
   |                                                                                   |
   |  [4. 加载早期 32 位 GDT 与 IDT]                                                   |
   |      lidtw %cs:pmode_IDT_info                                                     |
   |      lgdtw %cs:rombios32_gdt_48                      /* 基址指向 4GB 扁平段描述符*/|
   |                                                                                   |
   |  [5. 开启保护模式 (CR0.PE = 1)]                                                   |
   |      movl %cr0, %ecx                                                              |
   |      andl $~(CR0_PG | CR0_CD | CR0_NW), %ecx                                      |
   |      orl  $CR0_PE, %ecx                              /* 置位 Bit 0 */             |
   |      movl %ecx, %cr0                                                              |
   |                                                                                   |
   |  [6. 32 位长跳转刷新 CPU 指令预取流水线]                                         |
   |      ljmpl $SEG32_MODE32_CS, $(BUILD_BIOS_ADDR + 1f)                              |
   |                                                                                   |
   |  .code32                                                                          |
   |  1:  movl $SEG32_MODE32_DS, %ecx                     /* 重新加载所有数据段寄存器 */|
   |      movw %cx, %ds; movw %cx, %es; movw %cx, %ss; movw %cx, %fs; movw %cx, %gs;   |
   |      jmpl *%edx                                      /* 跳转进入 handle_post() */ |
   +-----------------------------------------------------------------------------------+

4.1 开启 A20 地址线的物理必然性
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
* **8086 地址回绕历史包袱**：8086 仅有 20 根地址线（$A_0 \sim A_{19}$），当寻址 ``0xFFFF:0x0010``（物理地址 ``0x100000`` = 1MB）时，最高位溢出丢失，地址自动回绕至物理地址 ``0x000000``；
* **A20 门控锁死**：为了兼容依赖这一特性的老旧软件，80286 之后的主板增加了 A20 逻辑门。若不主动将 A20 引脚拉高（通过端口 ``0x92`` 或键盘控制器端口 ``0x64``），CPU 在访问所有奇数兆内存（1MB, 3MB, 5MB...）时，第 20 位物理地址线恒定为 0，导致内存空间被物理切割破碎。

4.2 早期 GDT 段描述符构建
~~~~~~~~~~~~~~~~~~~~~~~~~
在切换进入 32 位模式前，SeaBIOS 在 ROM 中静态构建了 48 位的 GDT 指针 ``rombios32_gdt_48``：
* **代码段描述符（``SEG32_MODE32_CS = 0x08``）**：基地址 Base = 0，界限 Limit = 4GB（0xFFFFF 配合 4KB 粒度位 G=1），属性为 32 位可读可执行保护模式代码段；
* **数据段描述符（``SEG32_MODE32_DS = 0x10``）**：基地址 Base = 0，界限 Limit = 4GB，属性为 32 位可读可写数据段。

第五幕：SeaBIOS 内存链接脚本与 ``layoutrom.py`` 布局技术
--------------------------------------------------------

传统 GCC 编译器专为生成 32 位或 64 位 ELF 格式程序而设计，无法直接编译同时包含 16 位实模式汇编、32 位保护模式 C 语言并受限于 128KB ROM 物理空间的复杂固件。

SeaBIOS 在编译流程中设计了专门的 Python 布局重定位脚本 **``scripts/layoutrom.py``**：

::

   [GCC 编译生成的各个 32-bit ELF 目标文件]
                    │
                    ▼
   +-----------------------------------------------------------------------------------+
   |  scripts/layoutrom.py 符号与物理内存重排引擎                                      |
   |                                                                                   |
   |  1. 符号分类扫描：                                                                |
   |     - 16-bit 运行时段 (Fixed Runtime): 中断向量表处理函数、BDA、EBDA 接口         |
   |     - 32-bit 仅初始化段 (Init-only): post.c 中的硬件检测代码 (在引导后可被丢弃)    |
   |     - 32-bit 常驻段 (Runtime Flat): 运行时调用的 32 位 BIOS 服务 (如 SMM/APM)     |
   |                                                                                   |
   |  2. 物理地址空间精确排布 (128KB ROM: 0xE0000 ~ 0xFFFFF)：                         |
   |     - 0xE0000 .. 0xEF7FF: 存放 32 位初始化与扩展 Option ROM 代码                  |
   |     - 0xF0000 .. 0xFFEF: 存放标准 16 位 BIOS 中断服务入口与常驻数据结构          |
   |     - 0xFFFF0 .. 0xFFFFF: 严苛锁死 16 字节复位向量 reset_vector 与发布日期字符串 |
   +-----------------------------------------------------------------------------------+

通过 ``layoutrom.py``，SeaBIOS 最终输出一个恰好为 128KB 或 256KB 的纯二进制镜像 ``out/bios.bin``，为 CPU 通电执行提供了绝对精确的物理内存布局。
