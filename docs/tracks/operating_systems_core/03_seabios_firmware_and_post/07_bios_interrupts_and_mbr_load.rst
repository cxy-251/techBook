第一幕：BIOS 核心中断服务体系的物理结构与分发矩阵
-------------------------------------------------

在计算机操作系统内核接管硬件驱动之前，所有的底层 I/O 交互完全依赖 BIOS 驻留在物理内存 ``0xF0000 ~ 0xFFFFF``（Shadow RAM）中的 16 位实模式中断服务程序。

1.1 实模式中断的微观时序状态机
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
当引导程序（如 MBR 或早期 GRUB）执行一条软中断指令（如 ``int $0x13``）时，CPU 硬件在纳秒级时钟周期内自动执行：

::

   [实模式程序执行 int $0x13]
                 │
                 ▼
   1. 物理寻址：读取中断向量表 IVT[0x13] (位于物理内存 0x00000 + 0x13 * 4 = 0x0000004C);
   2. 提取 4 字节向量：Target_IP = [0x004C], Target_CS = [0x004E];
   3. 硬件原子压栈：
      - Push FLAGS (当前标志寄存器)
      - Push CS    (当前代码段选择子)
      - Push IP    (下一条指令偏移)
   4. 硬件清除中断使能标志 (IF=0) 与陷阱标志 (TF=0);
   5. 加载 CS:IP = Target_CS:Target_IP (跳转进入 SeaBIOS romlayout.S 的 entry_13 汇编桩);
                 │
                 ▼
   [SeaBIOS 中断服务处理] ──► 执行完毕后执行 IRETW ──► 弹出 IP, CS, FLAGS 恢复调用者

~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

   :widths: 15 20 30 35

   +----------------+------------------------+------------------------------------+------------------------------------------------+
   | 中断向量号     | 服务类别               | 核心功能调用 (AH 寄存器定义)       | 体系结构物理功能与调用参数                     |
   +================+========================+====================================+================================================+
   | **``INT 10h``**| **VGA 文本与图形显示** | ``AH=0x0E``: TTY 字符单字输出      | ``AL=字符ASCII``, ``BL=前景色``，向屏幕打印日志 |
   |                |                        | ``AH=0x00``: 设置显示模式          | ``AL=0x03`` (80x25 文本模式), ``AL=0x13``(VGA) |
   +----------------+------------------------+------------------------------------+------------------------------------------------+
   | **``INT 13h``**| **磁盘与块存储底层读写**| ``AH=0x02``: 传统 CHS 读扇区       | ``AL=扇区数``, ``CH/CL=柱面/扇区``, ``DH=磁头``|

   | **``INT 19h``**| **系统引导加载中断**   | (无子功能号，直接调用)             | **Bootstrap Loader**：重置引导序列并读取 MBR   |

第二幕：INT 13h 磁盘块存储驱动——CHS 几何与扩展 LBA 寻址
-------------------------------------------------------

磁盘读写是引导阶段最核心的生命线。SeaBIOS 在 ``src/block.c`` 中完整实现了从老旧机械硬盘到现代大容量存储的协议兼容。

2.1 传统 CHS (Cylinder-Head-Sector) 寻址与 8.4GB 物理天花板
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
在经典 ``INT 13h, AH=0x02`` 接口中，磁盘扇区寻址采用柱面（Cylinder）、磁头（Head）、扇区（Sector）三元组：

::

   寄存器编码：
   AH = 0x02 (读扇区命令)
   AL = 待读取的扇区数量 (1..128)
   CH = 柱面号低 8 位 (Cylinder 0..255)
   CL = 扇区号 (Bits 0..5, 取值 1..63) | 柱面号高 2 位 (Bits 6..7, 对应 Cylinder 256..1023)
   DH = 磁头号 (Head 0..255)
   DL = 驱动器编号 (0x00=软驱 A, 0x80=第 1 块硬盘, 0x81=第 2 块硬盘)
   ES:BX = 接收数据的物理内存缓冲区指针 (Segment:Offset)

.. danger::
   **8.4GB 物理容量锁死计算**：
   受限于寄存器位宽，传统 CHS 能够表示的最大物理扇区总数为：
   
   .. math::

      	ext{Max\_Sectors} = 1024 	ext{ 柱面} 	imes 256 	ext{ 磁头} 	imes 63 	ext{ 扇区} = 16,515,072 	ext{ 扇区}

   每个扇区固定 512 字节，导致寻址容量上限被硬性锁死在：

   .. math::

      	ext{Max\_Capacity} = 16,515,072 	imes 512 	ext{ B} = 8,455,716,864 	ext{ B} \approx \mathbf{8.456 	ext{ GB}}

   超过 8.4GB 的现代大硬盘无法通过传统 CHS 接口访问高位数据。

2.2 扩展 INT 13h (Extended INT 13h) 与 DAP (Disk Address Packet) 机制
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
为了彻底破除 8.4GB 瓶颈，行业引入了 **扩展 INT 13h 逻辑块寻址（LBA, Logical Block Addressing）**：

在 ``src/block.c:handle_1342()`` 中，CPU 调用 ``INT 13h, AH=0x42``，通过 ``DS:SI`` 寄存器在内存中传递一个 16 字节的 **DAP (Disk Address Packet)** 结构体：

::

   +-----------------------------------------------------------------------------------+
   |                 struct int13ext_s (16 字节磁盘地址包 DAP 内存布局)                |
   |                                                                                   |
   |  偏移地址    字段类型    字段名称        硬件物理语义与参数取值                   |
   +===================================================================================+
   |  0x00        u8          size            DAP 结构体自身大小 (固定为 0x10 = 16字节)|
   |  0x01        u8          reserved        保留字节 (恒为 0)                        |
   |  0x02        u16         count           待传输的扇区总数 (1..65535)              |
   |  0x04        u16         offset          接收缓冲区的 16 位段内偏移地址 (Offset)  |
   |  0x06        u16         segment         接收缓冲区的 16 位段基址 (Segment)       |
   |  0x08        u64         lba             64 位绝对逻辑块寻址扇区号 (LBA 0..2^64-1)|
   +-----------------------------------------------------------------------------------+

通过 64 位 LBA 寻址，扩展 INT 13h 能够直接以线性扇区号（$0, 1, 2, \dots$）访问容量达 $2^{64} 	imes 512	ext{ B} = 8	ext{ ZB}$ 的海量存储设备，彻底解放了现代操作系统引导器（如 GRUB2）的寻址空间。

第三幕：多设备启动优先级（BootOrder）与交互式引导菜单
------------------------------------------------------

在一台挂载了 NVMe 固态硬盘、SATA 硬盘、USB 启动盘与网卡 PXE 的计算机中，BIOS 如何决定先从哪个设备拉起引导？

3.1 ``BootList`` 链表与优先级排序
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
在 ``src/boot.c`` 中，SeaBIOS 维护了一个按优先级升序排列的全局链表 ``BootList``：

::

   struct bootentry_s {
       int type;               /* IPL 类型: FLOPPY(0x01), HARDDISK(0x02), CDROM(0x03), BEV(0x80)... */
       union {
           u32 data;
           struct segoff_s vector;
           struct drive_s *drive;
       };
       int priority;           /* 优先级数值 (数值越小优先级越高) */
       const char *description;/* 设备可读描述 (如 "DVD/CD [ata1-0: QEMU DVD-ROM]") */
       struct hlist_node node;
   };

* **优先级获取源**：SeaBIOS 首先通过 QEMU fw_cfg 读取用户配置的 ``bootorder`` 文件；若未配置，则按默认策略排序（软驱 101 $\rightarrow$ 光驱 102 $\rightarrow$ 硬盘 103 $\rightarrow$ 网卡 BEV 104）。

3.2 引导失败恢复循环：``INT 18h`` 机制
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
在 ``src/boot.c:do_boot()`` 中：
1. 提取当前最高优先级设备执行引导（如 ``boot_disk(0x80)``）；
2. 若该设备未插入介质、扇区损坏或未发现有效引导签名，引导函数直接返回失败；
3. 固件主动触发 **``INT 18h``（ROM BASIC / 引导失败恢复中断）**：
   * ``handle_18()`` 将全局变量 ``BootSequence`` 累加 1，自动轮转尝试 ``BootList`` 中的下一个候选设备；
   * 若所有设备均尝试完毕且全部失败，调用 ``boot_fail()`` 打印 ``"No bootable device."`` 并在等待超时后复位重启。

第四幕：MBR 引导扇区 (0x7C00) 加载与物理跃迁微观时序
-----------------------------------------------------

当确定从第一块硬盘（驱动器号 ``0x80``）引导时，SeaBIOS 进入整个固件生命周期的最核心函数——``src/boot.c:boot_disk()``。

4.1 为什么加载锚点是物理地址 ``0x0000:0x7C00``？
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
在 1981 年 IBM 5150 PC 设计之初：
* 早期计算机仅有 32KB 最低配置内存（``0x00000 ~ 0x07FFF``）；
* 设计团队希望将 512 字节的 MBR 扇区尽可能放置在 **32KB 内存的最高端**，为后续加载的操作系统（DOS）在低端留出最大连续空间：

.. math::

   32	ext{ KB (0x00008000)} - 512	ext{ 字节 (MBR 大小 0x200)} - 512	ext{ 字节 (栈与中断变量安全区)} = \mathbf{0	ext{x00007C00}}

这一设计从此被写进体系结构铁律，沿用至今 40 余年。

4.2 ``boot_disk()`` 源码级微观执行流水线
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
在 ``src/boot.c`` 中，引导扇区加载经历 4 个严密的物理时序步骤：

::

   +-----------------------------------------------------------------------------------+
   |                           boot_disk(bootdrv=0x80, checksig=1)                     |
   |                                                                                   |
   |  [步骤 1：调用 INT 13h 读扇区]                                                    |
   |  - 设置段基址 bootseg = 0x07C0;                                                   |
   |  - 构建寄存器: DL = 0x80, ES = 0x07C0, AH = 0x02, AL = 1, CL = 1;                 |
   |  - 发起 call16_int(0x13, &br) ──► 将磁盘 LBA 0 读入物理内存 0x07C0:0000;         |
   |                                                                                   |
   |  [步骤 2：校验 0xAA55 魔法引导签名]                                               |
   |  - 读取物理内存 0x07C0:01FE (即偏移 510 字节处) 的 16 位整数;                      |
   |  - 校验: if (GET_FARVAR(0x07C0, mbr->signature) != 0xAA55)                        |
   |           printf("Boot failed: not a bootable disk
"); return;                   |
   |                                                                                   |
   |  [步骤 3：段基址规范化 (Canonicalization)]                                         |
   |  - 历史上有部分 BIOS 使用 0x07C0:0000 跳转，部分使用 0x0000:0x7C00 跳转;           |
   |  - SeaBIOS 执行数学对齐换算:                                                      |
   |    u16 bootip = (bootseg & 0x0FFF) << 4;   /* (0x07C0 & 0x0FFF) << 4 = 0x7C00 */  |
   |    bootseg &= 0xF000;                      /* 0x07C0 & 0xF000 = 0x0000 */         |
   |    // 最终生成规范化的标准远指针: 0x0000:0x7C00 !                                 |
   |                                                                                   |
   |  [步骤 4：物理跃迁 call_boot_entry()]                                             |
   |  - br.dl = 0x80;        /* 向 MBR 传递启动磁盘驱动器号 */                         |
   |  - br.ax = 0xAA55;      /* 向 MBR 传递握手魔法数值 */                             |
   |  - br.code = 0x0000:0x7C00;                                                       |
   |  - farcall16(&br) ──► 执行 IRETW 机器指令!                                        |
   +-----------------------------------------------------------------------------------+

在 ``farcall16(&br)`` 执行的瞬间：
* CPU 硬件在一个时钟周期内弹出 ``CS = 0x0000, IP = 0x7C00``；
* CPU 以 **16 位纯实模式** 精准命中物理内存 ``0x00007C00``；
* **主板固件的历史使命至此圆满达成，控制权正式移交磁盘 MBR 引导代码！**

第五幕：全模块总结与从固件到 GRUB 引导器的历史交接
--------------------------------------------------

至此，**模块 03：SeaBIOS 固件启动、POST 自检与硬件建制** 全部 7 节已全量落盘！

我们完整遍历了计算机从通电第 1 纳秒到移交引导权的宏观与微观世界：
1. **上电复位**：复位向量 ``0xFFFFFFF0``、Shadow ROM 双重映射与 ``romlayout.S`` 入口；
2. **模式穿梭**：``__call32`` 栈线性化、大实模式 4GB 寻址与 6 指令协同多线程；
3. **内存解锁**：PAM0~PAM6 寄存器配置、Flash 镜像向 Shadow RAM 热搬迁与 ``wbinvd`` 缓存强刷；
4. **数据中枢**：POST 自检流水线、IVT 中断向量表、BDA 数据区与 EBDA 拓扑建立；
5. **设备使能**：PCI 总线深度优先递归遍历、BAR 空间贪心装箱对齐分配与 Option ROM 校验执行；
6. **高级描述**：ACPI RSDP 物理扫描、MADT 多核 APIC 拓扑、DSDT 字节码与 E820 内存图动态裁决；
7. **最终引导**：扩展 INT 13h LBA 寻址、``0xAA55`` 签名校验与向 ``0x0000:0x7C00`` 的物理跃迁。

现在，CPU 停留在 ``0x7C00`` 处，面对着磁盘 MBR 仅有的 446 字节代码空间。
