第一幕：从遗留硬件向现代高级配置的跃迁——ACPI 的拓扑架构
---------------------------------------------------------

在单核 PC 时代，操作系统通过直接读写固定的 I/O 端口或依靠 BIOS 中断（如 INT 10h/13h）与硬件交互。然而随着多核 SMP、NUMA 分布式内存架构、PCIe 热插拔以及高级电源管理（S3 睡眠、S5 关机）的引入，硬编码机制彻底失效。

**ACPI (高级配置与电源接口)** 提供了一套纯内存描述表体系，使操作系统内核（如 Linux 7.2）无需针对每块主板硬编码驱动，即可自适应解析整机的硬件拓扑：

::

   +-----------------------------------------------------------------------------------+
   |                                 ACPI 内存表格分层网络                             |
   |                                                                                   |
   |  [物理内存锚点：RSDP 根系统描述指针] (位于 EBDA 或 0xE0000~0xFFFFF)              |
   |  签名: "RSD PTR " ──► 包含 32 位 RSDT 物理地址 与 64 位 XSDT 物理地址             |
   |            │                                                                      |
   |            ├──► [RSDT / XSDT 根描述表] (系统核心表物理指针数组)                   |
   |            │          │                                                           |
   |            │          ├─► [FADT / FACP (固定 ACPI 描述表)]                        |
   |            │          │      ├── 指向 FACS (固件控制结构，记录 S3 唤醒向量)       |
   |            │          │      └── 指向 DSDT (区分系统描述表，包含 AML 设备字节码)  |
   |            │          │                                                           |
   |            │          ├─► [MADT / APIC (多 APIC 描述表)]                          |
   |            │          │      ├── 每个 CPU 核心的 Local APIC ID (SMP 核心数)       |
   |            │          │      ├── I/O APIC 物理基地址 (0xFEC00000) 与 GSI 起点     |
   |            │          │      └── 中断重定向覆盖 (如 IRQ 0 定时器重定向至 GSI 2)   |
   |            │          │                                                           |
   |            │          ├─► [MCFG (PCIe ECAM 配置表)] ──► 256MB 内存映射基地址      |
   |            │          │                                                           |
   |            │          ├─► [SRAT / SLIT (NUMA 拓扑表)] ──► CPU 与内存距离矩阵      |
   |            │          │                                                           |
   |            │          └─► [HPET (高精度定时器表)] ──► 内存基地址 (0xFED00000)     |
   +-----------------------------------------------------------------------------------+

第二幕：RSDP 根描述符在物理内存中的精准锚定与双重校验和
-------------------------------------------------------

当 64 位 Linux 7.2 内核启动（``arch/x86/kernel/acpi/boot.c:acpi_scan_rsdp()``）时，它在没有页表、没有设备树的情况下，必须通过物理内存扫描定位 ACPI 的根基——**RSDP (Root System Description Pointer)**。

2.1 Linux 内核的物理内存扫描窗口
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
内核依照 ACPI 规范，在两个物理内存区间内以 **16 字节对齐（0x10 步长）** 进行暴力特征码扫描：
1. **EBDA 区域**：读取 BDA ``0x40:0x0E`` 提取 EBDA 段基址，扫描 EBDA 前 1KB 内存（通常为 ``0x9FC00 ~ 0x9FFFF``）；
2. **系统 BIOS Shadow ROM 区域**：扫描物理内存 ``0x000E0000 ~ 0x000FFFFF``（128KB 范围）。

2.2 RSDP 数据结构与双重校验和算法
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
在 SeaBIOS ``src/std/acpi.h`` 中，``struct rsdp_descriptor`` 严格遵循 ACPI 2.0+ 工业标准：

::

   struct rsdp_descriptor {
       u64 signature;              /* 8 字节字符串: "RSD PTR " (0x2052545020445352) */
       u8  checksum;               /* ACPI 1.0 校验和: 前 20 字节累加和必须为 0 */
       u8  oem_id[6];              /* OEM 厂商标识 (如 "BOCHS ") */
       u8  revision;               /* 规范版本: 0=ACPI 1.0, 2=ACPI 2.0+ */
       u32 rsdt_physical_address;  /* 32 位 RSDT 物理基地址 (GPA) */
       u32 length;                 /* XSDT 结构体全长 (包括头部，通常为 36 字节) */
       u64 xsdt_physical_address;  /* 64 位 XSDT 物理基地址 (64 位内核首选此项) */
       u8  extended_checksum;      /* ACPI 2.0 全表 36 字节扩展校验和: 累加和必须为 0 */
       u8  reserved[3];            /* 保留对齐字节 */
   } PACKED;

.. important::
   **ACPI 物理校验和计算法则**：
   ACPI 规定所有表格（无论是 RSDP、RSDT 还是 MADT）必须满足 **单字节累加和取模 256 恒等于 0** 的物理约束：

   .. math::

      \sum_{i=0}^{	ext{Table.Length} - 1} 	ext{Byte}[i] \equiv 0 \pmod{256}

   固件在填充完所有字段后，计算校验和字段：$	ext{checksum} = (256 - (\sum 	ext{other\_bytes} \pmod{256})) \pmod{256}$。内核扫描到签名后第一件事就是验证校验和，若不为 0 则直接判定为内存噪音并继续向下扫描。

第三幕：MADT (APIC 表) 与多核/中断拓扑构建
-------------------------------------------

在操作系统启动阶段，**MADT (Multiple APIC Description Table, 签名 ``"APIC"``)** 具有无可替代的核心地位。Linux 内核正是通过解析 MADT 获知系统包含多少个物理/虚拟 CPU 核心，以及各设备的中断是如何路由的。

3.1 MADT 主表头与多子表拓扑
~~~~~~~~~~~~~~~~~~~~~~~~~~~
在 ``src/std/acpi.h`` 中，MADT 由一个标准 ACPI 表头、一个主控制结构以及紧随其后的若干变长子结构（Subtables）拼接而成：

::

   +-----------------------------------------------------------------------------------+
   |                               MADT (Multiple APIC Table)                          |
   |                                                                                   |
   |  [主表头部 (struct multiple_apic_table)]                                          |
   |  - signature: "APIC"                                                              |
   |  - local_apic_address: 0xFEE00000 (所有 CPU 默认的 Local APIC 物理基地址)         |
   |  - flags: 1 (PCAT_COMPAT = 1, 表示系统同时存在传统双片 8259A PIC)                 |
   +===================================================================================+
   |  [子表 1..N: Processor Local APIC (Type 0, 8 字节)]                               |
   |  - type = 0, length = 8                                                           |
   |  - acpi_processor_id = 0, local_apic_id = 0, flags = 1 (Enabled / 可调度在线)     |
   |  - (每一个 CPU 核心对应一条 Type 0 子表，Linux 由此确定 NR_CPUS 与 AP 唤醒清单)   |
   +-----------------------------------------------------------------------------------+
   |  [子表: I/O APIC (Type 1, 12 字节)]                                               |
   |  - type = 1, length = 12                                                          |
   |  - io_apic_id = 0, address = 0xFEC00000, interrupt_base = 0 (GSI 0 起点)          |
   +-----------------------------------------------------------------------------------+
   |  [子表: Interrupt Source Override (Type 2, 10 字节)]                              |
   |  - type = 2, length = 10                                                          |
   |  - bus = 0 (ISA 总线), source = 0 (IRQ 0 定时器), gsi = 2 (全局系统中断号 2)      |
   |  - flags = 0x0000 (遵循总线默认极性与边沿触发)                                    |
   |  - (物理意义: 告知 Linux 内核，8254 PIT 的时钟中断在 IOAPIC 上已被硬件重定向至引脚 2!)|
   +-----------------------------------------------------------------------------------+
   |  [子表: Local APIC NMI (Type 4, 6 字节)]                                          |
   |  - type = 4, length = 6                                                           |
   |  - acpi_processor_id = 0xFF (代表所有 CPU 核心), lint = 1 (连接至 LAPIC LINT1 引脚)|
   +-----------------------------------------------------------------------------------+

第四幕：DSDT 设备描述表与 SMBIOS 硬件资产结构体
-----------------------------------------------

4.1 DSDT (Differentiated System Description Table) 与 AML 字节码
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
与 MADT 等静态数据表不同，**DSDT (签名 ``"DSDT"``)** 包含的是主板硬件的 **AML (ACPI Machine Language)** 解释型字节码：
* **设备树定义**：使用 ASL（ACPI Source Language）定义系统总线（``_SB.PCI0``）、PCI 主机桥、LPC 总线下的键盘（``PS2K``）、RTC 时钟、电源按钮（``PWRB``）与电池状态；
* **控制方法（Control Methods）**：包含操作系统在运行中可调用的硬件控制函数（如 ``_PTS`` 准备睡眠、``_WAK`` 唤醒、``_Qxx`` GPE 事件响应函数）；
* **Linux 内核解析机制**：Linux 内核内置了庞大的 **ACPICA (ACPI Component Architecture)** 解释器引擎，在启动时动态加载 DSDT 字节码，在内存中构建完整的 ACPI 命名空间树（Namespace Tree）。

4.2 SMBIOS (System Management BIOS) 结构体树
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
为了向操作系统用户态（如 ``dmidecode``、监控系统）暴露主板制造信息，固件在内存中构建了一套标准 SMBIOS 结构体表：
* **定位入口**：在低端 1MB 内存中写入 16 字节特征结构（以 ``"_SM_"`` 或 64 位 ``"_SM3_"`` 开头）；
* **核心结构体类型**：
  * **Type 0 (BIOS Information)**：固件厂商（"SeaBIOS"）、发布版本、ROM 物理大小（128KB）；
  * **Type 1 (System Information)**：系统制造商（"QEMU"）、产品名称（"Standard PC (Q35 + ICH9, 2009)"）、UUID 唯一标识符；
  * **Type 4 (Processor Information)**：CPU 插槽、家族型号、最大主频与特性；
  * **Type 16/17 (Memory Array & Device)**：物理内存插槽、单条内存容量（DDR4/DDR5）与物理拓扑。

第五幕：E820 物理内存图动态构建算法——内核唯一的内存事实源
---------------------------------------------------------

在计算机通电后，操作系统内核（如 Linux 7.2）是如何确切知道物理内存中“哪里是可用 RAM、哪里是 ACPI 表、哪里是显卡 MMIO 洞”的？

内核不依赖 CMOS，也不依赖任何硬件猜测，而是**唯一信任 BIOS 通过 INT 15h 传递的 E820 物理内存图**。

5.1 E820 内存类型规范
~~~~~~~~~~~~~~~~~~~~~
每个 E820 表项由 20 字节（或 24 字节带扩展属性）构成：

::

   struct e820entry {
       u64 start;  /* 区间起始物理地址 (GPA) */
       u64 size;   /* 区间字节长度 */
       u32 type;   /* 内存类型 */
   } PACKED;

.. table:: E820 核心内存类型与操作系统使用规则
   :widths: 15 25 30 30

   +----------------+------------------------+------------------------------------+------------------------------------------------+
   | 类型枚举数值   | 宏定义名称             | 对应物理区域实例                   | 操作系统内核处理准则                           |
   +================+========================+====================================+================================================+
   | **``1``**      | **``E820_RAM``**       | 0x0..0x9FBFF, 1MB..3.5GB, 4GB+ DRAM| **完全可自由分配的物理内存**，交由伙伴系统接管  |
   +----------------+------------------------+------------------------------------+------------------------------------------------+
   | **``2``**      | **``E820_RESERVED``**  | EBDA, 0xA0000..0xFFFFF, PCI ECAM   | **绝对禁止操作系统触碰**，硬件/固件专用保留空间 |
   +----------------+------------------------+------------------------------------+------------------------------------------------+
   | **``3``**      | **``E820_ACPI``**      | RSDT, MADT, DSDT 等静态 ACPI 数据表 | **ACPI 可回收内存**：OS 解析完 ACPI 后可回收为RAM|
   +----------------+------------------------+------------------------------------+------------------------------------------------+
   | **``4``**      | **``E820_NVS``**       | 非易失性 ACPI 存储区 (S3 唤醒上下文)| **操作系统必须严格保留**，休眠与唤醒期间不可修改|
   +----------------+------------------------+------------------------------------+------------------------------------------------+
   | **``5``**      | **``E820_UNUSABLE``**  | ECC 校验损坏的物理内存页           | **致命坏页**，内存管理系统永久隔离禁止分配     |
   +----------------+------------------------+------------------------------------+------------------------------------------------+

5.2 动态区间分割、合并与排序算法（``src/e820map.c:e820_add()``）
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
在 POST 执行过程中，不同硬件子系统会随时调用 ``e820_add(start, size, type)`` 注册自己的内存需求。SeaBIOS 在内部维护了一个动态裁决状态机：

::

   +-----------------------------------------------------------------------------------+
   |                           e820_add() 动态区间裁决算法                             |
   |                                                                                   |
   |  [场景：原已有低优先级连续内存 A: 0x00000000 ~ 0x000A0000 (640KB RAM)]           |
   |            │                                                                      |
   |            ▼ 此时 bda_init() 注册高优先级 EBDA: 0x0009FC00 ~ 0x000A0000 (RESERVED) |
   |                                                                                   |
   |  1. 扫描重叠：发现新插入区间 [0x9FC00, 0xA0000] 落在已有区间 [0x0, 0xA0000] 尾部; |
   |  2. 类型比对：原区间为 RAM (1)，新区间为 RESERVED (2)，类型冲突!                  |
   |  3. 触发区间拆分 (Split):                                                         |
   |     - 将原区间收缩截断为: [0x00000000, 0x0009FC00] (639KB, RAM)                   |
   |  4. 插入新区间:                                                                   |
   |     - 紧随其后插入: [0x0009FC00, 0x000A0000] (1KB, RESERVED)                      |
   |  5. 保持严格单调递增排序与紧凑合并。                                              |
   +-----------------------------------------------------------------------------------+

5.3 一台典型 4GB 虚拟机的标准 E820 拓扑实录
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
在 SeaBIOS 准备引导（``e820_prepboot()``）时，输出的完整最终 E820 内存图如下：

::

   0: 0000000000000000 - 000000000009fbff = 1 RAM (639 KB 常规低端内存)
   1: 000000000009fc00 - 000000000009ffff = 2 RESERVED (1 KB EBDA 扩展数据区)
   2: 00000000000a0000 - 00000000000fffff = 2 RESERVED (384 KB UMA: VRAM/OptionROM/ShadowROM)
   3: 0000000000100000 - 000000007ffeffff = 1 RAM (~2047 MB 主系统可用 DRAM)
   4: 000000007fff0000 - 000000007fffffff = 3 ACPI (64 KB ACPI 描述表)
   5: 00000000b0000000 - 00000000bfffffff = 2 RESERVED (256 MB PCIe ECAM 空间)
   6: 00000000fed00000 - 00000000fed003ff = 2 RESERVED (1 KB HPET 定时器)
   7: 00000000fee00000 - 00000000fee00fff = 2 RESERVED (4 KB Local APIC 映射)
   8: 00000000fffc0000 - 00000000ffffffff = 2 RESERVED (256 KB 4GB 顶端 Flash ROM)
   9: 0000000100000000 - 000000017fffffff = 1 RAM (2048 MB 4GB 以上高端可用 DRAM)

这个精确的内存拓扑图，构成了 Linux 7.2 内核初始化伙伴系统（Buddy System）与直接映射区（``PAGE_OFFSET``）的唯一物理依据。
