   * **核心使命**：解构在没有操作系统内核支持的裸机环境中，主板固件如何实现 16 位传统实模式（Real Mode）与 32 位保护模式（Protected Mode / Flat Mode）之间的双向毫秒级安全穿梭；深入剖析 SeaBIOS 源码 ``src/stacks.c`` 与 ``src/romlayout.S``，逐行解构 ``__call32`` 向上跃迁、``call16`` 向下穿透、``Big Real Mode``（大实模式）段界限破解、``ExtraStack`` 独立调用栈防溢出保护，以及固件级微型协同多线程（Cooperative Threads）的上下文切换状态机。

第一幕：固件面临的模式困境——16 位兼容包袱 vs 32 位 C 开发效率
--------------------------------------------------------------

在主板 BIOS 的生命周期中，固件处于一个高度矛盾的体系结构夹缝之中：

::

   +-----------------------------------------------------------------------------------+
   |                             BIOS 固件的双重运行需求                               |
   |                                                                                   |
   |  [需求 A：传统 16 位实模式兼容性]               [需求 B：现代 32 位 C 语言高效性] |
   |  - 必须向 DOS / MBR / 引导器提供                - PCI/PCIe 设备枚举、BAR 地址计算 |
   |    标准的 16 位中断服务 (INT 10h/13h/15h)       - ACPI 复杂数据表 (MADT/DSDT) 生成|
   |  - 必须能调用第三方显卡 Option ROM (16-bit)      - USB / SATA AHCI 复杂驱动堆栈    |
   |  - 寻址空间受限于 1MB (段界限 64KB)             - 需要自由读写 4GB 扁平物理内存   |
   +-----------------------------------------------------------------------------------+

为了兼顾二者，SeaBIOS 并没有采用“全程 16 位汇编编写”的传统老路，而是设计了一套极其精巧的 **运行态双向模式跃迁（Mode Transition Engine）与跨模式调用跳板（Trampolines）**。

----------------------------------------------------------------------------------------

第二幕：向上穿透——从 16 位调用 32 位 C 函数（``__call32``）
------------------------------------------------------------

当系统处于 16 位实模式时（例如处理外部发起的 ``INT 13h`` 磁盘中断），SeaBIOS 需要调用内部用 32 位 C 语言编写的高级磁盘驱动函数。

2.1 状态暂存与准备：``call32_prep()``
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
在进入 32 位模式前，SeaBIOS 在低端常驻内存（``VARLOW`` 区域）中定义了一个全局结构体 ``Call16Data``，用于在内存堆中暂存当前的 16 位硬件环境：

在 ``src/stacks.c:call32_prep()`` 中：
1. **备份当前段与控制寄存器**：读取 ``CR0``（确认未处于异常保护态）、``FS``, ``GS`` 选择子；
2. **备份实模式 GDT**：调用 ``sgdt`` 保存当前描述符表指针；
3. **备份并开启 A20 地址线**：调用 ``set_a20(1)`` 确保第 20 位地址线处于导通状态；
4. **备份当前调用栈段**：记录 ``Call16Data.ss = SS``；
5. **屏蔽外部与非可屏蔽中断**：向 CMOS 端口 ``0x70`` 写入 ``0x8F``，防止在切换瞬间突发硬件中断导致 CPU 状态机混乱。

2.2 栈指针的线性化转换（Linearizing the Stack）
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
在 16 位实模式下，栈顶指针是由段基址与偏移组成的双元组 ``SS:SP``，其实际对应的物理地址为 $	ext{SS} 	imes 16 + 	ext{SP}$。
在切换至 32 位扁平模式（代码与数据段基址均为 0）后，如果直接使用原 ``ESP``，CPU 将访问错误的低位内存。

在 ``src/stacks.c:__call32()`` 中，内联汇编执行了著名的 **栈指针线性化算法**：

::

   // 内联汇编：在切换前将实模式 SS:ESP 转换为 32 位绝对线性物理地址
   movl %ss, %eax
   shll $4, %eax                /* EAX = SS * 16 (计算段基址) */
   addl %eax, %esp              /* ESP = (SS * 16) + ESP (转换为 32 位扁平物理栈指针!) */

通过这一转换，原本由实模式维护的调用栈空间，被 100% 无缝转换为 32 位 C 语言运行时可直接寻址的扁平连续栈。

2.3 跃迁执行与安全返回时序
~~~~~~~~~~~~~~~~~~~~~~~~~~
在完成栈线性化后，汇编指令直接跳转至 ``transition32_nmi_off``：
1. 硬件置位 ``CR0.PE = 1`` 开启保护模式；
2. 长跳转进入 32 位代码段，加载数据段选择子 ``SEG32_MODE32_DS``；
3. 执行目标 32 位 C 函数（``calll *%func``）；
4. C 函数执行完毕并返回后，调用 ``transition16big``，将 CPU 重新切回 16 位实模式；
5. 逆向恢复数据段寄存器、调用 ``call32_post()`` 恢复 A20 与 CMOS 状态，最终平稳返回 16 位调用者。

第三幕：向下穿透——从 32 位调用 16 位汇编服务与大实模式
-------------------------------------------------------

当 SeaBIOS 运行在 32 位 POST 初始化主逻辑中，需要调用传统的 16 位外部服务（如显卡 Option ROM 或 BIOS 内部的 16 位中断桩）时，则执行逆向穿透。

3.1 栈指针逆向拆解与 ``call16()``
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
在 ``src/stacks.c:call16()`` 中：
1. 获取此前保存的 ``stackseg = Call16Data.ss``；
2. 在调用跳板 ``transition16`` 切换回实模式后，立即执行逆向栈换算：

.. math::

   	ext{ESP}_{	ext{16}} = 	ext{ESP}_{	ext{32}} - (	ext{Call16Data.ss} \ll 4)

3. 重新将 ``SS`` 与 ``DS`` 设置为原始段选择子，调用 16 位目标函数。

3.2 大实模式（Big Real Mode / Unreal Mode）黑科技
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
在实模式（``CR0.PE = 0``）下，x86 处理器的标准段界限被锁死在 **64KB（0xFFFF）**。如果 16 位代码需要向 1MB 以上的高端物理内存读写数据（例如在实模式下拷贝内核镜像），必须借助 **大实模式（Big Real Mode）**：

::

   +-----------------------------------------------------------------------------------+
   |                            Big Real Mode (大实模式) 破解原理                      |
   |                                                                                   |
   |  [步骤 1：在 32 位保护模式下 (PE=1)]                                              |
   |  - GDT 中构造一个特殊段描述符 SEG32_MODE16BIG_DS:                                 |
   |    Base = 0x00000000, Limit = 0xFFFFFFFF (4GB!), 粒度位 G=1 (4KB)                 |
   |  - 将该选择子加载入数据段寄存器: movw $SEG32_MODE16BIG_DS, %ds                    |
   |  - CPU 内部的段描述符缓存 (Descriptor Cache) 此时记录: DS.Limit = 4GB!            |
   |                                                                                   |
   |  [步骤 2：关闭保护模式 (CR0.PE = 0) 切回实模式]                                   |
   |  - 清除 CR0.PE 位: movl %cr0, %eax; andl $~1, %eax; movl %eax, %cr0;              |
   |  - 执行长跳转 ljmpw $SEG_BIOS, $1f 刷新流水线;                                    |
   |                                                                                   |
   |  [物理结果：破除 64KB 枷锁]                                                       |
   |  - CPU 当前处于实模式 (PE=0)，支持全部 16 位中断与寻址指令;                       |
   |  - 但硬件未清空 DS 描述符缓存中的 4GB Limit!                                       |
   |  - 16 位代码现在可以使用 32 位地址前缀直接执行:                                  |
   |    addr32 movl %eax, (%ebx) /* 在实模式下直接向 2GB 处的物理地址写入数据! */     |
   +-----------------------------------------------------------------------------------+

3.3 外部 16 位寄存器现场封装：``struct bregs`` 与 ``_farcall16``
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
调用第三方未知的 16 位代码时，必须保证所有通用寄存器与标志位能够被 100% 精确传递与抓取。

SeaBIOS 在 ``src/bregs.h`` 中定义了完整的 16 位通用寄存器上下文结构体 ``struct bregs``：

::

   struct bregs {
       u16 ds, es, fs, gs;
       u32 edi, esi, ebp, esp;
       u32 ebx, edx, ecx, eax;
       struct segoff_s code;   /* 目标调用的 16 位入口 CS:IP */
       u16 flags;              /* 传递与返回的 FLAGS 状态标志 */
   };

在 ``src/romlayout.S:__farcall16`` 中，SeaBIOS 构造了一个精妙的 **``IRETW`` 伪造调用时序**：
1. 将目标函数返回地址（当前 CS 与返回标签 ``1f``）压入栈；
2. 将待调用的目标寄存器状态 ``bregs->flags`` 与 ``bregs->code (CS:IP)`` 压入栈；
3. 执行宏 ``RESTOREBREGS_DSEAX`` 恢复所有通用寄存器；
4. 执行指令 **``iretw``**：硬件自动将栈上的 ``CS:IP`` 与 ``FLAGS`` 弹出至 CPU 核心，无缝跳转执行第三方 16 位固件；
5. 第三方固件执行 ``RETF`` 或 ``IRET`` 返回时，精确落入返回标签 ``1f``；
6. 执行 ``SAVEBREGS_POP_DSEAX`` 将执行后的全部寄存器状态原样写回 ``struct bregs``，完成参数回传。

第四幕：栈安全防线——``ExtraStack`` 与栈跳跃（Stack Hop）
--------------------------------------------------------

4.1 栈溢出危机（Stack Overflow Hazard）
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
在 PC 引导早期，调用第三方 Option ROM（如老式 SCSI/网卡启动固件）时存在巨大的物理风险：
* 第三方 Option ROM 往往假设调用者提供了极浅的栈，其自身可能只分配了 64 字节的微型栈；
* 而 SeaBIOS 内部的 C 语言逻辑嵌套较深，若直接在第三方栈上执行 C 函数，极易踩踏低端内存数据导致死机。

4.2 ``ExtraStack`` 物理隔离与 ``__stack_hop()``
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
SeaBIOS 在低端保留物理内存（``VARLOW`` 区域）开辟了一块受保护的专用独立栈：

::

   u8 ExtraStack[BUILD_EXTRA_STACK_SIZE + 1] VARLOW __aligned(8); /* 通常 2KB ~ 4KB */
   u8 *StackPos VARLOW;

当外部 16 位中断命中 SeaBIOS 时，入口桩执行 **``__stack_hop()`` 栈跳跃**：

::

   [外部 Option ROM / DOS 栈环境 (不可信, 深度极浅)]
             │
             ▼ 触发 SeaBIOS 中断服务入口
   1. 汇编指令保存当前不可信的 SS:ESP 至局部变量;
   2. 将 CPU 栈段与栈指针强行覆写为安全独立栈:
      movw $SEG_LOW, %ss;
      movl StackPos, %esp;
   3. 将原不可信的 SS:ESP 压入 ExtraStack 栈底进行链表式保存;
             │
             ▼ 在安全的 ExtraStack 上执行 SeaBIOS 复杂的 C 语言逻辑
   4. 函数处理完毕即将返回时, 调用 __stack_hop_back();
   5. 从 ExtraStack 栈底弹出原 SS:ESP 并写回 CPU 寄存器;
             │
             ▼ 平稳返回外部 Option ROM 环境

第五幕：微型固件协同多线程（Cooperative Threads）实现
------------------------------------------------------

在传统观念中，多线程是操作系统的专属能力。但在现代服务器启动过程中，扫描数十个 PCIe 设备与 SATA/NVMe 磁盘需要耗费数秒等待硬件就绪（超时等待）。为了极致压缩开机耗时，SeaBIOS 在固件内部实现了一套微型 **协同多线程调度器（Cooperative Multithreading）**。

5.1 线程描述符与独立 4KB 线程栈
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
在 ``src/stacks.c`` 中，每个初始化线程都拥有一个独立的 4KB 物理堆栈：

::

   struct thread_info {
       void *stackpos;             /* 当前线程挂起时暂存的 ESP 栈指针 */
       struct hlist_node node;     /* 挂载在全局活动线程就绪双向链表上 */
   };
   #define THREADSTACKSIZE 4096

5.2 极速汇编级协作调度器：``switch_next()``
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
当一个硬件初始化线程需要等待设备响应（如等待硬盘磁头就绪）时，它显式调用 ``yield()``，触发纯汇编实现的上下文切换函数 ``switch_next()``：

::

   static void switch_next(struct thread_info *cur) {
       struct thread_info *next = container_of(cur->node.next, struct thread_info, node);
       if (cur == next) return;

       asm volatile(
           "  pushl $1f
"            /* 1. 将当前线程恢复执行的 PC 标签 (1f) 压入当前栈 */
           "  pushl %%ebp
"          /* 2. 备份当前线程的基础基址指针 EBP */
           "  movl %%esp, (%0)
"     /* 3. cur->stackpos = ESP (保存当前线程栈顶) */
           "  movl (%1), %%esp
"     /* 4. ESP = next->stackpos (原子切换为下一线程的栈顶!) */
           "  popl %%ebp
"           /* 5. 从下一线程栈中恢复其历史 EBP */
           "  retl
"                 /* 6. 从下一线程栈中弹出其历史 PC 并跳转恢复执行! */
           "1:
"                     /* ──► 当前线程未来被再次调度时的苏醒断点 */
           : : "r"(cur), "r"(next)
           : "ebx", "edx", "esi", "edi", "cc", "memory");
   }

整套线程切换仅消耗 **6 条汇编机器指令**（耗时小于 5 纳秒），无任何操作系统介入，实现了硬件探测的完全异步并发。

小结与下章导读
--------------

本节深入剖析了 SeaBIOS 在裸机环境下实现 16 位实模式与 32 位保护模式双向安全穿梭的微观机制，解构了栈线性化算法、大实模式 4GB 界限破解、``ExtraStack`` 栈隔离保护以及固件 6 指令协同多线程的精妙设计。

在固件能够自由执行 32 位 C 代码后，它面临的下一个物理挑战是：**BIOS 代码本身存放在只读的 ROM 中，无法直接在固件内存区域修改全局变量或构造动态数据结构**。

在 **第 3 节：PAM (Programmable Attribute Map) 寄存器与 ROM 区域可读写/只读硬件状态切换** 中，我们将深入剖析主板芯片组的 PAM 硬件寄存器，解构主板如何通过微观寄存器配置将只读 ROM 区域原子切换为可写的 Shadow RAM 内存。
