第一幕：物理现实——只读 ROM 带来的动态数据构造死结
-------------------------------------------------

当 CPU 通电启动并进入 SeaBIOS C 语言入口 ``handle_post()`` 时，遇到了一个根本性的物理矛盾：

::

   +-----------------------------------------------------------------------------------+
   |                             固件初期的物理“写死结”矛盾                            |
   |                                                                                   |
   |  [矛盾 1：物理介质的不可写性]                   [矛盾 2：初始化任务的高度动态性]  |
   |  - BIOS 代码当前直接从只读的 SPI Flash / ROM   - 需要统计系统内存并动态构建 E820 表 |
   |    芯片中执行 (物理引脚只读);                   - 需要探测 PCI 设备并生成 ACPI/MADT |
   |  - 任何写内存操作 (如修改全局变量 HaveRunPost)   - 需要动态初始化中断向量表与 BDA    |
   |    在总线上均被硬件丢弃，写入完全失效!          - 需要调用 malloc 在堆中分配数据结构|
   +-----------------------------------------------------------------------------------+

1.1 传统 PC 1MB 内存空洞（Upper Memory Area, UMA）
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
在 x86 体系结构的物理内存拓扑中，``640KB ~ 1MB (0xA0000 ~ 0xFFFFF)`` 被划分为专用的固件与设备映射区（UMA）：

::

   0x00000000 ┌────────────────────────────────────────────────────────┐
              │ 640KB 传统低端物理内存 (Base DRAM)                      │
   0x000A0000 ├────────────────────────────────────────────────────────┤
              │ 128KB VGA / 显卡显示内存 (VRAM, 0xA0000 ~ 0xBFFFF)     │
   0x000C0000 ├────────────────────────────────────────────────────────┤ ◄── PAM1..PAM6 管理区间
              │ 192KB 扩展卡 Option ROM 区域 (0xC0000 ~ 0xEFFFF)       │     (C-Segment, D-Segment, E-Segment)
   0x000F0000 ├────────────────────────────────────────────────────────┤ ◄── PAM0 管理区间
              │ 64KB 主系统 BIOS 固件与中断服务区域 (0xF0000 ~ 0xFFFFF) │     (F-Segment)
   0x00100000 └────────────────────────────────────────────────────────┘ (1MB 边界)

1.2 Shadow RAM（影子内存）的硬件解决方案
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
为了让固件既能享受 DRAM 纳秒级的读写速度，又能在初始化完成后防止代码被操作系统破坏，主板硬件设计了 **Shadow RAM（影子内存）**：
* 主板在 ``0xC0000 ~ 0xFFFFF``（384KB 区域）在物理上铺设了真实的 DRAM 内存颗粒；
* 通过主板北桥/MCH 芯片内部的一组专用硬件配置寄存器——**PAM 寄存器**，动态切换总线译码器将读写请求分发至“物理 ROM 芯片”还是“底层 DRAM 颗粒”。

第二幕：PAM 寄存器矩阵与 4 种硬件工作模式
-----------------------------------------

在 Intel I440FX 与 Q35 芯片组中，控制 Shadow RAM 物理路由的硬件单元被称为 **Programmable Attribute Map (PAM)**。

2.1 PAM 寄存器在 PCI 配置空间中的映射
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
PAM 寄存器组集成在主板北桥（Host Bridge，BDF ``00:00.0``）的 PCI 配置空间内：
* **I440FX (82441FX)**：位于 PCI 配置空间偏移 ``0x59 ~ 0x5F``（共 7 个 8 位寄存器 PAM0 ~ PAM6）；
* **Q35 (MCH)**：位于 PCI 配置空间偏移 ``0x90 ~ 0x96``（共 7 个 8 位寄存器 PAM0 ~ PAM6）。

2.2 2-bit 状态机编码与 4 种物理工作模式
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
每个 PAM 寄存器拆分为高 4 位（High Nibble）与低 4 位（Low Nibble），每 2 位（Bit Pair）严格控制一段 16KB 或 32KB/64KB 物理内存切片的总线路由：

.. table:: PAM 寄存器 2-bit 硬件编码状态机与总线路由
   :widths: 15 25 30 30

   +----------------+------------------------+------------------------------------+------------------------------------------------+
   | 2 位编码数值   | 硬件模式名称           | CPU 读取 (Read) 总线路由           | CPU 写入 (Write) 总线路由                      |
   +================+========================+====================================+================================================+
   | **``00b``**    | **只读 ROM 模式**      | 路由至外部 **Flash ROM 芯片**      | **写抑制 (Write Inhibit)**，硬件丢弃写入数据   |
   |                | (Disabled)             | (用于通电刚复位时的初始取指)       | (不影响任何 DRAM 内容)                         |
   +----------------+------------------------+------------------------------------+------------------------------------------------+
   | **``01b``**    | **只读 RAM 模式**      | 路由至底层 **DRAM 影子内存**       | **写抑制 (Write Inhibit)**，硬件丢弃写入数据   |
   |                | (Read-Only Shadow)     | (BIOS 引导就绪后的最终固化保护态)   | (防止 OS/恶意代码破坏 BIOS 中断服务)           |
   +----------------+------------------------+------------------------------------+------------------------------------------------+
   | **``10b``**    | **写 DRAM / 读 ROM**   | 路由至外部 **Flash ROM 芯片**      | 路由至底层 **DRAM 影子内存**                   |
   |                | (Write-Only Shadow)    | (从 ROM 读代码，同时可写 DRAM)     | (用于在执行 ROM 代码时向 DRAM 预写数据)        |
   +----------------+------------------------+------------------------------------+------------------------------------------------+
   | **``11b``**    | **全读写 RAM 模式**    | 路由至底层 **DRAM 影子内存**       | 路由至底层 **DRAM 影子内存**                   |
   |                | (Full Read/Write)      | (完全作为普通 RAM 使用，可自由修改)| (POST 自检、构建 ACPI/E820 表时的黄金模式)     |
   +----------------+------------------------+------------------------------------+------------------------------------------------+

第三幕：SeaBIOS ``make_bios_writable()`` 内存解锁与代码搬迁
----------------------------------------------------------

在 SeaBIOS 源码 ``src/fw/shadow.c`` 中，固件通过一段极度严苛的无内存变量 C 代码，完成了主板内存由“死”到“活”的关键蜕变。

3.1 零全局变量的硬件 BDF 嗅探
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
在调用 ``make_bios_writable()`` 时，由于内存尚不可写，代码中**绝对不能使用任何静态全局变量**（写入会静默丢失）。

SeaBIOS 采用直接读写 PCI I/O 端口（``0xCF8 / 0xCFC``）的方式，在局部栈变量中遍历 PCI 总线：

::

   void make_bios_writable(void) {
       int bdf;
       pci_ioconfig_foreachbdf(bdf, 0) {
           u32 vendev = pci_ioconfig_readl(bdf, PCI_VENDOR_ID);
           u16 vendor = vendev & 0xffff, device = vendev >> 16;
           // 匹配 Intel I440FX 北桥芯片
           if (vendor == PCI_VENDOR_ID_INTEL && device == PCI_DEVICE_ID_INTEL_82441) {
               make_bios_writable_intel(bdf, I440FX_PAM0);
               return;
           }
           // 匹配 Intel Q35 MCH 北桥芯片
           if (vendor == PCI_VENDOR_ID_INTEL && device == PCI_DEVICE_ID_INTEL_Q35_MCH) {
               make_bios_writable_intel(bdf, Q35_HOST_BRIDGE_PAM0);
               return;
           }
       }
   }

3.2 解锁 PAM 读写权限与热搬移微观时序
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
在 ``__make_bios_writable_intel()`` 中：

::

   static void __make_bios_writable_intel(u16 bdf, u32 pam0) {
       union pamdata_u pamdata;
       // 1. 从 PCI 配置空间读取 PAM0 ~ PAM6 当前 8 字节数值
       pamdata.data32[0] = pci_ioconfig_readl(bdf, pam0);
       pamdata.data32[1] = pci_ioconfig_readl(bdf, pam0 + 4);
       u8 *pam = &pamdata.data8[pam0 & 0x03];

       // 2. 将 0xC0000 ~ 0xEFFFF (PAM1..PAM6) 全部置为 0x33 (全读写 RAM 模式)
       for (int i = 0; i < 6; i++)
           pam[i + 1] = 0x33;

       // 3. 将 0xF0000 ~ 0xFFFFF (PAM0) 置为 0x30 (全读写 RAM 模式)
       int ram_present = pam[0] & 0x10;
       pam[0] = 0x30;

       // 4. 将配置写回北桥芯片 PCI 寄存器
       pci_ioconfig_writel(bdf, pam0, pamdata.data32[0]);
       pci_ioconfig_writel(bdf, pam0 + 4, pamdata.data32[1]);

       // 5. 若此前 Shadow RAM 中无有效代码，则从 4GB 高端 Flash 镜像完整克隆代码
       if (!ram_present) {
           memcpy(VSYMBOL(code32flat_start),
                  VSYMBOL(code32flat_start) + BIOS_SRC_OFFSET, /* 0xFFF00000 偏移 */
                  SYMBOL(code32flat_end) - SYMBOL(code32flat_start));
       }
   }

通过以上步骤，低端 ``0x000F0000 ~ 0x000FFFFF`` 的物理内存完全变成了可读可写的 DRAM。此后，SeaBIOS 即可正常执行 ``malloc``、向 BDA 写入设备参数、动态生成 ACPI 描述表。

第四幕：数据固化与写保护闭环——``make_bios_readonly()`` 与 ``wbinvd``
---------------------------------------------------------------------

在完成所有硬件设备探测、Option ROM 执行与引导扇区装配后，SeaBIOS 在将控制权交由 OS 引导器（如 GRUB / MBR）前，必须执行逆向的 **固化写保护闭环**。

4.1 缓存一致性与 ``wbinvd`` 指令的物理时钟时序
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
在修改主板 PAM 寄存器将 DRAM 切换为“只读”之前，必须解决一个致命的半导体缓存物理隐患：

.. danger::
   **CPU 脏缓存行丢失隐患（Cache Invalidation Hazard）**：
   在 POST 执行过程中，CPU 核心曾向 ``0xF0000`` 区域写入了大量的 ACPI 表与数据。这些修改可能仍然滞留在 CPU 片内 L1 / L2 / L3 缓存的高速 SRAM 单元中，标记为 Modified（脏）状态，尚未真正回写到主板外部的 DRAM 物理电容中！
   如果此时直接将主板 PAM 寄存器置为只读，后续一旦 CPU 发生缓存行置换触发写回，主板芯片组总线将**直接丢弃写入数据**，导致 DRAM 中的数据永远处于损坏的不完整状态！

为了消除此隐患，SeaBIOS 在 ``src/fw/shadow.c:make_bios_readonly_intel()`` 的第一行硬性执行特权指令 **``wbinvd``**：

::

   static void make_bios_readonly_intel(u16 bdf, u32 pam0) {
       // 必须首先执行 wbinvd 强制刷写全部片上缓存!
       wbinvd();

       // 读取当前 PAM 寄存器
       ...
       // 将 0xF0000 ~ 0xFFFFF (PAM0) 重新配置为 0x10 (只读 RAM 模式, 01b)
       pam[0] = 0x10;
       
       // 将 Option ROM 区域配置为只读
       for (int i = 0; i < 6; i++) {
           pam[i + 1] = 0x11; /* 01b (只读) */
       }

       // 写回 PCI 配置空间，永久锁定物理 Shadow RAM
       pci_config_writel(bdf, pam0, pamdata.data32[0]);
       pci_config_writel(bdf, pam0 + 4, pamdata.data32[1]);
   }

* **``wbinvd`` (Write-Back and Invalidate Cache) 的硬件微观动作**：
  1. 广播总线控制信号，强制要求当前核心及所有 CPU 核心的 L1/L2/L3 Cache 逐行检查脏标记（Dirty Bit）；
  2. 将全部脏 Cacheline 产生总线写事务完整刷回物理 DRAM 颗粒；
  3. 将片上所有 Cacheline 标记为无效（Invalid），强制后续所有内存读取必须从已固化的只读 DRAM 中重新获取。

第五幕：QEMU 源码对 PAM 与 Shadow RAM 的硬件级模拟
--------------------------------------------------

在 QEMU 源码库（``/Volumes/LinuxKernel/qemu``）中，主板北桥芯片是如何在软件中精确模拟 PAM 寄存器的四种状态的？

在 ``hw/pci-host/q35.c`` 与 ``hw/pci-host/i440fx.c`` 中：

::

   +-----------------------------------------------------------------------------------+
   |                             QEMU PAM 虚拟化状态机模型                             |
   |                                                                                   |
   |  [系统物理内存总线 system_memory]                                                 |
   |            │                                                                      |
   |            ├── pam-memory-region (PAM 容器)                                       |
   |            │     ├── alias-to-rom  (指向只读 pc.bios 镜像)                        |
   |            │     └── alias-to-ram  (指向可读写 pc.ram 堆内存)                     |
   |                                                                                   |
   |  [客户机写入 PAM 寄存器] ──► 触发 pam_update() 回调函数:                          |
   |  - 若配置为 00b (ROM):                                                            |
   |    memory_region_set_enabled(alias-to-rom, true);  // 启用只读 ROM Alias          |
   |    memory_region_set_enabled(alias-to-ram, false);                                |
   |  - 若配置为 11b (Full RAM):                                                       |
   |    memory_region_set_enabled(alias-to-rom, false);                                |
   |    memory_region_set_enabled(alias-to-ram, true);  // 启用可读写 RAM Alias        |
   |  - 若配置为 01b (Read-Only RAM):                                                  |
   |    memory_region_set_readonly(alias-to-ram, true); // 强制 RAM 区域为只读         |
   |  - 触发 FlatView 重新展平并在 KVM 中更新 EPT 页表读写权限标志位!                  |
   +-----------------------------------------------------------------------------------+

通过这套状态机，QEMU 在纯软件或 KVM 硬件加速下，100% 精确复刻了物理主板 PAM 寄存器的微观时钟与内存路由行为。

小结与下章导读
--------------

本节深入剖析了主板芯片组 PAM 寄存器的硬件结构、4 种总线读写状态机、SeaBIOS 在无变量环境下通过 PCI 端口解锁 Shadow RAM 的热搬移时序，以及 ``wbinvd`` 缓存强刷与只读固化闭环。

在 Shadow RAM 成功转变为可读写内存后，SeaBIOS 终于获得了在物理内存中建立数据结构的自由。它将在 ``0x00000400`` 处建立整个 PC 体系结构最重要的硬件信息中枢。

在 **第 4 节：POST (Power-On Self-Test) 加电自检时序、BDA (0x400) 与 EBDA 内存拓扑建立** 中，我们将深入剖析 SeaBIOS 的 POST 总体调度流水线，解构 BIOS 数据区（BDA）与扩展 BIOS 数据区（EBDA）的核心字段物理内存布局。
