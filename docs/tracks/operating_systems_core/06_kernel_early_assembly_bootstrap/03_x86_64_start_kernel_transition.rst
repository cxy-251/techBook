第一幕：C 语言世界的大门——``x86_64_start_kernel()`` 运行全景
--------------------------------------------------------------

当 CPU 在 ``arch/x86/kernel/head_64.S:common_startup_64`` 中完成 0 号进程（``init_task``）的 16KB 独立内核栈挂载、重置段寄存器并开启系统调用支持后，汇编代码执行 ``callq *initial_code(%rip)``，正式命中内核首个 C 语言入口函数 **``x86_64_start_kernel()``**：

::

   +-----------------------------------------------------------------------------------+
   |                        x86_64_start_kernel() 执行全景流水线                       |
   |                                                                                   |
   |  [入参: real_mode_data (由 RDI 传入的 struct boot_params 虚拟映射指针)]           |
   |            │                                                                      |
   |            ▼ 1. 编译期虚拟内存拓扑静态断言校验 (BUILD_BUG_ON)                     |
   |  - 验证 MODULES_VADDR, __START_KERNEL_map, Fixmap 之间无重叠越界                  |
   |            │                                                                      |
   |            ▼ 2. 彻底销毁早期低端恒等映射 (reset_early_page_tables)                |
   |  - early_top_pgt 清空 0~510 表项，仅保留高位内核映射，彻底消除空指针漏洞          |
   |            │                                                                      |
   |            ▼ 3. 内存清零与早期页表母表建立                                        |
   |  - clear_bss(): 清空 __bss_start ~ __bss_stop 与 __brk_base ~ __brk_limit          |
   |  - clear_page(init_top_pgt): 初始化正式母表并挂载 init_top_pgt[511]               |
   |            │                                                                      |
   |            ▼ 4. 硬件机密计算与内存调试安全底座                                    |
   |  - sme_early_init(): 激活 AMD 内存加密掩码注入页表                                |
   |  - kasan_early_init(): 映射 KASAN 早期单页影子内存                                |
   |  - tdx_early_init(): 绑定 Intel TDX 机密虚拟机半虚拟化 I/O 接口                   |
   |            │                                                                      |
   |            ▼ 5. 早期中断与引导数据深拷贝                                          |
   |  - idt_setup_early_handler(): 挂载 32 向量早期异常处理数组                        |
   |  - copy_bootdata(): 将 real_mode_data 深拷贝至静态 boot_params 并释放低端物理内存  |
   |  - load_ucode_bsp(): 在引导核上热加载早期 CPU 微码补丁                            |
   |            │                                                                      |
   |            ▼ 6. 平台特性修正与跨入通用内核大门                                    |
   |  - x86_64_start_reservations() ──► 终极调用体系无关通用入口 start_kernel() !       |
   +-----------------------------------------------------------------------------------+

第二幕：编译期静态边界断言（BUILD_BUG_ON）的数学契约
----------------------------------------------------

在 ``x86_64_start_kernel()`` 函数的最顶端，没有任何实际生成的机器指令，而是由一系列严密的 **编译期断言（``BUILD_BUG_ON``）** 构成的物理内存安全铁律：

::

   BUILD_BUG_ON(MODULES_VADDR < __START_KERNEL_map);
   BUILD_BUG_ON(MODULES_VADDR - __START_KERNEL_map < KERNEL_IMAGE_SIZE);
   BUILD_BUG_ON(MODULES_LEN + KERNEL_IMAGE_SIZE > 2 * PUD_SIZE);
   BUILD_BUG_ON((__START_KERNEL_map & ~PMD_MASK) != 0);
   BUILD_BUG_ON((MODULES_VADDR & ~PMD_MASK) != 0);
   BUILD_BUG_ON(__fix_to_virt(__end_of_fixed_addresses) <= MODULES_END);

.. table:: 内核虚拟内存边界数学断言深度剖析
   :widths: 35 30 35

   +---------------------------------------------+------------------------+------------------------------------------------+
   | 断言逻辑表达式                              | 涉及虚拟地址常量       | 架构级物理安全约束                             |
   +=============================================+========================+================================================+
   | **``MODULES_VADDR < __START_KERNEL_map``**  | ``MODULES_VADDR``      | 内核模块虚拟空间（通常为 ``0xFFFFFFFFC0000000``|
   |                                             | ``__START_KERNEL_map`` | 必须严格排布在内核静态映像基址之后             |
   +---------------------------------------------+------------------------+------------------------------------------------+
   | **``MODULES_LEN + KERNEL_IMAGE_SIZE > 2GB``**| ``KERNEL_IMAGE_SIZE``  | 内核镜像（最大 512MB/1GB）与模块空间（1GB）    |
   |                                             | ``PUD_SIZE (1GB)``     | 总和绝不可超越 2 个 PUD 目录项管辖的 2GB 范围  |
   +---------------------------------------------+------------------------+------------------------------------------------+
   | **``(__START_KERNEL_map & ~PMD_MASK) != 0``**| ``PMD_MASK (2MB 对齐)``| 内核基地址必须严格满足 2MB 大页自然边界对齐    |
   +---------------------------------------------+------------------------+------------------------------------------------+

这些断言在编译器前端进行静态求值，一旦内核配置或编译脚本引发任何虚拟地址冲突，编译将立即中断，杜绝了运行期内存覆盖风险。

第三幕：早期动态页表分配器与 #PF 即时自愈机制
----------------------------------------------

在进入 ``start_kernel()`` 之前，内核面临着一个经典的死锁困境：**物理内存管理器（memblock 与 Buddy System）尚未初始化，内核无法动态申请物理页作为页表；但早期代码在访问某些特殊区域时，又必须动态扩展页表映射。**

3.1 ``early_dynamic_pgts`` 静态预留页表池（``head64.c``）
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
为了打破僵局，Linux 内核在 ``.init.data`` 段中静态预留了一个固定容量的页表池：

::

   #define EARLY_DYNAMIC_PAGE_TABLES 64
   pmd_t early_dynamic_pgts[EARLY_DYNAMIC_PAGE_TABLES][PTRS_PER_PMD] __aligned(PAGE_SIZE);
   unsigned int next_early_pgt = 0;

当内核早期需要分配新的 P4D、PUD 或 PMD 表时，无需经过内存分配器，直接自增 ``next_early_pgt``，从静态预留池中切片分配一页（4KB）并清零使用。

3.2 ``do_early_exception()`` 早期缺页 (#PF) 即时自愈流水线
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
如果早期代码在访问内存时触发了硬件缺页异常（Page Fault, 中断向量 14）：

::

   +-----------------------------------------------------------------------------------+
   |                           早期缺页异常 (#PF) 动态自愈状态机                       |
   |                                                                                   |
   |  [CPU 触发 #PF (Vector 14)] ──► 硬件自动将故障线性地址存入 CR2 寄存器             |
   |            │                                                                      |
   |            ▼                                                                      |
   |  [do_early_exception(regs, trapnr)]                                               |
   |  - 判断: if (trapnr == X86_TRAP_PF && early_make_pgtable(native_read_cr2())) return;|
   |            │                                                                      |
   |            ▼                                                                      |
   |  [__early_make_pgtable(fault_address, pmd_flags)]                                 |
   |  1. 提取线性地址对应的 PGD / P4D / PUD / PMD 索引;                                |
   |  2. 逐级向下探测: 若某级页表指针为空 (NULL)，立即从 early_dynamic_pgts 申请新页表; |
   |  3. 填充 PMD 表项: 将物理地址与 early_pmd_flags (2MB 大页属性) 写入目标槽位;      |
   |  4. 刷新当前 CPU TLB;                                                             |
   |            │                                                                      |
   |            ▼                                                                      |
   |  [执行 iretq 恢复执行] ──► CPU 重新执行引发缺页的指令，硬件成功命中新页表无缝运行!   |
   +-----------------------------------------------------------------------------------+

第四幕：硬件机密计算与安全底座——SME / SEV 与 TDX 早期建制
---------------------------------------------------------

在云原生与多租户服务器环境中，硬件级机密计算已成为现代操作系统的标配。Linux 7.2 在进入 C 语言的第一时间建立起内存加密防护。

4.1 AMD SME / SEV 内存加密早期初始化（``sme_early_init()``）
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
* **物理加密原理**：AMD 处理器在内存控制器内部集成了 AES 硬件加密引擎。当页表项中的 **C-bit（Encryption Bit，通常为物理地址 Bit 47 或 Bit 51）** 置 1 时，写入 DRAM 的所有数据均被硬件自动透明加密；
* **掩码注入**：``sme_early_init()`` 探测硬件特性，将加密掩码 ``sme_me_mask`` 动态注入到全局变量 ``early_pmd_flags`` 中，确保后续动态分配的所有页表项自动带上硬件加密属性。

4.2 早期 KASAN (Kernel Address Sanitizer) 影子页表建立（``kasan_early_init()``）
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
* **影子内存拓扑**：KASAN 为内核中每 8 字节物理内存映射 1 字节影子内存（Shadow Memory），用于在硬件层面检测数组越界与 Use-After-Free 漏洞；
* **单页折叠映射（Zero-Cost Early Shadowing）**：在早期没有海量内存支持完整影子映射时，``kasan_early_init()`` 将整个高达数十 TB 的 KASAN 影子虚拟地址空间，全部递归映射到**单一物理页 ``kasan_early_shadow_page``** 上！这一设计使得内核在消耗仅仅 4KB 物理内存的前提下，在启动第一秒即获得了全量内存访问安全保护。

第五幕：向体系无关通用初始化总控 ``start_kernel()`` 的历史交接
--------------------------------------------------------------

在所有平台前置工作完备后，``head64.c`` 推动系统跨过最后一个体系结构屏障：

5.1 ``copy_bootdata()`` 引导参数深拷贝
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
1. 将引导加载器传递的 ``real_mode_data`` 完整深拷贝至静态全局变量 ``boot_params``：
   ::

      memcpy(&boot_params, real_mode_data, sizeof(boot_params));
      sanitize_boot_params(&boot_params);

2. 解析命令行物理指针 ``get_cmd_line_ptr()``，将参数字符串完整复制到 ``boot_command_line``；
3. 解除对原始实模式数据的引用，将其物理内存释放回系统。

5.2 引导核微码补丁热加载（``load_ucode_bsp()``）
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
调用 ``load_ucode_bsp()``，从 initramfs 头部扫描微码容器，通过向 MSR ``0x79`` 写入补丁物理地址，在引导核（BSP）上原子更新 CPU 内部微码，修复已知晶体管逻辑缺陷。

5.3 终极跨越：调用 ``start_kernel()``
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
在 ``x86_64_start_reservations()`` 的最末端，函数执行：

::

   void __init __noreturn x86_64_start_reservations(char *real_mode_data) {
       x86_early_init_platform_quirks();
       ...
       start_kernel(); /* 终极跨越：正式进入 Linux 通用内核启动总控! */
   }

.. important::
   **历史分水岭**：
   * 在 ``start_kernel()`` 被调用的瞬间，Linux 内核彻底结束了 x86_64 体系结构特定的汇编与机器初始化阶段；
   * 控制权正式交由全架构通用的 C 语言中枢（``init/main.c:start_kernel()``），开启内存伙伴系统、中断体系、EEVDF 调度器与 VFS 虚拟文件系统的全景初始化！
