================================================================================
编译器转换模型：源码文本、程序语义、阶段边界与语义保持契约
================================================================================

.. note:: 前置背景与上下文承接
   本章作为《现代编译器架构设计与程序转换优化全景深度剖析》全书的总览基石，确立贯穿整个编译器工程的核心心智模型：编译器不是黑盒文本翻译器，而是一套严格基于形式语义等价性、在不同抽象层级之间逐步施加机器物理约束的多阶段数据流转换系统。

编译器工程的核心任务是将人类可读的高级语言源码，逐步重写、降级（Lowering）并特化为目标硬件能够直接执行的机器指令或字节码序列。这一过程必须在绝对保持程序原始可观察语义（Observable Behavior）的前提下，实现时间与空间效率的最大化。

源码文本、程序语义与可执行行为
------------------------------

在编译器理论与工业实践中，一个计算机程序存在三个完全解耦但逐层投影的物理形态：

1. **源码文本 (Source Text)**：存放于存储介质上的 UTF-8 字符流。源码文本包含大量仅服务于人类程序员心智的表层信息，如缩进、空格、注释、变量命名与语法糖。源码文本本身不具备直接执行能力。
2. **程序语义 (Program Semantics)**：由语言标准（如 C++ ISO 标准、ECMAScript 规范）通过形式化规则定义的数学与状态机契约。语义明确定义了：给定输入流与初始内存状态，计算步骤如何改变变量环境、产生何种内存读写、引发哪些系统调用以及产生何种确定的外部副作用。
3. **可执行行为 (Executable Behavior)**：目标物理 CPU（或虚拟机解释器）执行机器指令时引发的真实微架构状态迁移：物理寄存器数值变迁、栈指针 ``RSP`` 移动、L1/L2 缓存行刷新、总线事务与操作系统内核陷入（Trap/Syscall）。

   :widths: 20 25 30 25
   :header-rows: 1
   :class: tight-table

   * - 程序形态
     - 物理承载实体
     - 包含的关键信息
     - 编译器阶段操作
   * - 源码文本 (Source)
     - 磁盘文件 / 字符流
     - 字符编码、排版格式、注释、语法糖
     - 词法扫描、字符剔除、Token 化
   * - 程序语义 (Semantics)
     - AST / 符号表 / SSA IR
     - 数据流依赖、控制流拓扑、类型契约、副作用集合
     - 语义推导、类型检查、规范化、死代码消除
   * - 执行行为 (Execution)
     - 物理寄存器 / 内存总线 / 指令流
     - 机器操作码、寻址模式、栈帧对齐、ABI 约定
     - 指令选择、寄存器分配、流水线调度、重定位

翻译与转换的本质区别
--------------------

初学者常将编译器视作“从语言 A 到语言 B 的翻译器（Translator）”。在工业级编译器工程中，编译器的本质是 **基于中间表示的多轮渐进式转换器（Iterative Transformer）**。

* **简单翻译（Translation）**：建立语法规则的机械映射，通常发生于同构抽象层级（如 Source-to-Source Transpiler）。翻译往往无法摆脱源语言的语法包袱，难以进行跨语句全局优化。
* **编译转换（Transformation & Lowering）**：编译器首先将源语法剥离，投射为正交、显式的中间图结构（如 Control Flow Graph 与 SSA Data-Flow Graph）。随后，编译器在此抽象结构上执行数十至数百轮自包含的“分析-重写”循环（Analysis-Transform Passes）。每一轮 Pass 仅解决一个具体工程目标（如常量传播、循环外提、向量化），逐步去除高层抽象，最终压实为贴合物理硬件特性的低级形态。

前端、中端、后端与运行时的职责边界
----------------------------------

现代工业级编译器（以 LLVM / GCC / Rustc 为代表）采用高度模块化的“三段式”或“四段式”解耦架构。这种架构确保了 $M$ 种源语言与 $N$ 种目标硬件架构的解耦组合复杂度为 $M + N$，而非 $M 	imes N$。

.. list-table:: 现代编译器四大核心子系统职责与数据契约
   :widths: 15 25 35 25
   :header-rows: 1
   :class: tight-table

   * - 架构子系统
     - 核心职责
     - 输入数据结构
     - 输出数据结构
   * - 编译器前端 (Frontend)
     - 词法分词、语法解析、作用域计算、类型检查与错误诊断
     - 源码字符流 (Source Characters)
     - 具象/抽象语法树 (AST) 与符号表 (Symbol Table)
   * - 编译器中端 (Middle-End / Optimizer)
     - 硬件无关的全局控制流与数据流分析、冗余消除、循环变换与函数内联
     - 线性/高层 IR (如 AST / High-Level Dialect)
     - 静态单赋值 (SSA) 形式规范化 IR (如 LLVM IR)
   * - 编译器后端 (Backend / CodeGen)
     - 指令选择 (ISel)、类型与操作合法化 (Legalization)、图着色寄存器分配、机器指令调度
     - 优化后的 SSA IR
     - 目标机器汇编文件 (``.s``) 或目标文件 (``.o``)
   * - 语言运行时 (Runtime System)
     - 动态内存分配堆管理、垃圾回收 (GC)、异常栈展开 (Stack Unwinding)、线程调度与 JIT 支持
     - 编译器注入的 Helper 符号引用与元数据表
     - 实际进程物理运行环境

正确性即语义保持契约
--------------------

编译器所有优化 Pass 必须遵守的最高铁律是 **语义保持（Semantic Preservation）**。

设源程序在形式语义模型下的输入输出及外部可观察行为为集合 $\mathcal{S}(P)$，经过编译器 Pass 转换后的程序为 $P'$，其行为集合为 $\mathcal{S}(P')$。

* **严格语义保持**：要求 $\mathcal{S}(P') = \mathcal{S}(P)$。
* **合法优化收敛**：在存在未定义行为（Undefined Behavior, UB）或实现定义行为（Implementation-Defined Behavior）的语言规范下，编译器被允许收窄行为分支：
  
  $$\mathcal{S}(P') \subseteq \mathcal{S}(P)$$

.. code-block:: cpp

   // 源码级输入：
   int compute(int x) {
       int a = 10;
       int b = 20;
       int c = a + b; // 常量表达式
       return x * c;
   }

中端优化管线在保证语义绝对守恒的前提下，执行如下重写推导：

1. **常量折叠 Pass**：分析证明 $a=10, b=20$，将 $c = a + b$ 判定为常量 30。
2. **死代码消除 Pass (DCE)**：证明临时变量 $a, b, c$ 在后续路径无直接使用且无内存写入副作用，物理擦除对应存储分配。
3. **强度折减与指令生成**：在 x86-64 后端，将 $x 	imes 30$ 改写为移位与加法组合（$(x \ll 5) - (x \ll 1)$）或直接生成 ``imul eax, edi, 30``。

输出的最终机器码在 CPU 寄存器层面的外部表现，与源码多行变量运算在数学上完全一致。

编译器将人类意图转化为机器物理约束
----------------------------------

高级语言为人类程序员提供了丰富的抽象概念：对象、闭包、继承、多态、异步协程、泛型与自动内存管理。然而物理 CPU 硅片仅仅理解：

* 寄存器堆的位宽限制（如 64-bit GPR, 512-bit ZMM）。
* 线性平坦的虚拟地址空间。
* 条件跳转指令与指令指针寄存器（``RIP / PC``）。
* 硬件中断与系统调用门。

编译器的工程使命，即是一座 **“抽象消除桥梁”**：它在编译期通过静态推导与证明，逐步将高级抽象剥离，并为目标机器填补所有必须的物理细节。

.. list-table:: 高层抽象向硬件物理约束的映射路径
   :widths: 25 35 40
   :header-rows: 1
   :class: tight-table

   * - 高级语言抽象
     - 编译器中间降级路径
     - 最终硬件物理约束
   * - 变量作用域与局部生命周期
     - 活跃变量分析 (Liveness) $\rightarrow$ 栈槽分配
     - 栈指针 ``RSP`` 偏移量或物理通用寄存器
   * - 虚函数多态调用
     - 类虚表偏移计算 $\rightarrow$ 间接函数指针加载
     - 内存二次寻址指令 ``call [rax + offset]``
   * - 递归与函数调用
     - 调用约定 (Calling Convention) 实参寄存器重排
     - ``RDI/RSI/RDX`` 传参 + ``call`` 压栈返回地址
   * - 泛型模板与参数化多态
     - 编译期单态化 (Monomorphization) 特化生成
     - 针对具体数据类型尺寸生成的专用机器码块
   * - 异常处理 (try-catch)
     - 静态 DWARF ``.eh_frame`` 表与 Landing Pad 插入
     - 零运行时开销，异常触发时由运行时库解析栈帧元数据
