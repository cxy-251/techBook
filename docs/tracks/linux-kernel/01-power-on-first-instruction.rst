按下电源键后，CPU 从哪里取得第一条指令？
========================================

这本书讲 Linux 内核。Linux 还没有出现之前，先要有一段代码把机器带到能够装入内核的位置。
故事从电源键被按下开始。

为了让后面的每一次跳转都能定位到源码，软件主线固定为：

::

   x86-64
   → QEMU q35
   → SeaBIOS
   → GRUB i386-pc
   → bzImage
   → Linux 6.12.95

真实主板上的电源控制器、供电芯片和时钟分布会因平台改变。QEMU 也不会模拟每一段模拟电路。
本章先讲物理机器必然经历的电源与复位关系，再从 x86 处理器被释放复位的位置进入可定位的软件流程。

电源键没有直接启动 CPU
----------------------

按下电源键时，CPU 还不能立即执行指令。主板首先需要建立一组稳定的工作条件。

电源管理逻辑接收到开机请求后，按照平台规定的顺序打开不同电压轨。芯片组、内存、处理器核心、
I/O 设备并不一定使用同一个电压，也不能保证在完全相同的时刻稳定。时钟源也要先开始振荡并锁定。
在这些条件尚未满足时，平台保持处理器的复位信号有效。

复位信号的作用不是“让 CPU 运行一段复位程序”，而是把处理器限制在架构规定的初始状态。
寄存器、控制位和内部执行状态被放到可预测的位置，处理器不会从任意内存地址继续执行上一次留下的代码。

当电源和时钟达到平台要求后，平台释放处理器复位。对软件来说，真正可以观察的启动故事从这里开始：
处理器现在必须决定第一条指令从哪里取。

x86 已经规定了复位后的取指位置
------------------------------

x86 处理器不会在复位后扫描磁盘，也不会自己寻找 Linux。处理器架构给出了一个固定的复位入口。
在现代 x86 处理器的传统启动路径中，第一条指令位于物理地址：

::

   0xfffffff0

它距离 4 GiB 地址空间的顶部只有 16 字节。

这个地址不能简单地只用 ``CS << 4 + IP`` 的普通实模式公式理解。复位时，``CS`` 可见的选择子值和
处理器内部保存的段基址并不完全等同于一次普通加载 ``CS`` 后的状态。处理器内部的代码段基址使
``CS:RIP`` 最终指向 ``0xfffffff0``。保护模式和分页此时都还没有成为正常的运行环境。

处理器只负责发出这个地址的取指请求。地址上究竟放着什么内容，由平台的地址映射决定。

为什么这个地址能读到固件
------------------------

系统内存 DRAM 此时通常还没有完成初始化，第一条指令不能依赖普通内存。主板会把非易失性固件存储
映射到处理器复位入口所在的高地址区域。真实机器上，这通常涉及 SPI flash、芯片组地址译码和固件
映射窗口；在 QEMU q35 中，同样的可见结果由虚拟芯片组和固件映像共同建立。

因此，CPU 对 ``0xfffffff0`` 的第一次取指最终落到固件映像，而不是磁盘、GRUB 或 Linux。

这里容易混淆两个动作：

* CPU 已经知道从哪个地址取第一条指令；
* 平台负责让这个地址返回固件中的字节。

前一个规则来自处理器架构，后一个映射来自主板或虚拟平台。缺少任何一项，启动都无法继续。

SeaBIOS 把复位入口放在 ROM 尾部
------------------------------

当前主线使用 SeaBIOS。它在 ``src/romlayout.S`` 中明确把复位入口放到 BIOS 段的 ``0xfff0`` 偏移：

.. code-block:: asm

           ORG 0xfff0 // Power-up Entry Point
           .global reset_vector
   reset_vector:
           ljmpw $SEG_BIOS, $entry_post

当这段 BIOS 映像映射到地址空间顶部时，``ORG 0xfff0`` 对应的字节正好出现在 CPU 的复位入口。
CPU 取到的第一条固件指令是一条远跳转：

::

   ljmpw $SEG_BIOS, $entry_post

复位入口只剩 16 字节空间，无法容纳完整的固件初始化过程。它的职责很小：立刻把 ``CS:IP`` 改到
SeaBIOS 真正的开机入口 ``entry_post``。

这里的远跳转还有一个重要效果。复位时 ``CS`` 的隐藏段基址处于特殊初始状态；远跳转重新装载代码段，
让后续代码进入 SeaBIOS 预期的 16 位 BIOS 地址布局。处理器从架构规定的复位状态，正式进入固件自己
组织的执行环境。

第一章结束时，谁拥有控制权
--------------------------

到这里，机器只完成了启动故事的第一个交接：

::

   电源管理逻辑
   → 释放 CPU 复位
   → CPU 从 0xfffffff0 取指
   → SeaBIOS reset_vector
   → entry_post

当前状态是：

* 当前执行者：SeaBIOS；
* CPU 环境：传统 x86 复位后的 16 位启动环境；
* 当前代码：固件 ROM；
* 普通 DRAM：还不能假设已经完成可用初始化；
* GRUB：尚未被寻找；
* Linux：尚未装入内存；
* 下一入口：SeaBIOS 的 ``entry_post``。

本章在这里换章。接下来的故事将从 ``entry_post`` 继续，追踪固件怎样建立栈、进入能够运行主要 C 代码
的环境，并开始初始化这台机器。
