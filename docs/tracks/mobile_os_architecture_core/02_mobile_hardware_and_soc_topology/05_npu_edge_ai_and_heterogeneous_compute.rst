11.1 移动 NPU 硬件架构与张量计算微拓扑
------------------------------------------------------------------------

深度神经网络推理的物理计算本质，是极高密度的矩阵乘加运算（General Matrix Multiply - GEMM）以及激活函数（ReLU/GELU）、层归一化（LayerNorm）与逐元素张量操作。

CPU、GPU 与 NPU 计算特征与能效对比
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

.. code-block:: text

   +-------------------------------------------------------------------------+
   |                     CPU vs GPU vs NPU 硬件微架构能效分水岭              |
   +-------------------------------------------------------------------------+

   [ 1. 通用 CPU (标量/短向量) ]
   +-------------------------------------------------------------------------+
   | 控制单元 (庞大预测器) | L1/L2/L3 巨大缓存 | 少量 128-bit NEON/SVE 向量单元 |
   +-------------------------------------------------------------------------+
   * 特征: 调度极其灵活，但绝大部分晶体管用于分支预测与指令重排，能效比仅约 0.1~0.5 TOPS/W。

   [ 2. 移动 GPU (SIMT 线程束阵列) ]
   +-------------------------------------------------------------------------+
   | 线程束调度器 (Warp Schedulers) | 大容量寄存器堆 | 数百个可编程 32-bit ALU |
   +-------------------------------------------------------------------------+
   * 特征: 高吞吐着色并发，兼顾通用渲染，能效比约 1~3 TOPS/W，但指令解码与控制开销依然存在。

   [ 3. 专用 NPU (硬化张量计算阵列) ]
   +-------------------------------------------------------------------------+
   | 静态流水编排 | 大容量片上 Scratchpad SRAM | 2D 脉动阵列 (Systolic Array MACs) |
   +-------------------------------------------------------------------------+
   * 特征: 彻底剔除动态指令译码与分支硬件，全数据流硬件直连，**能效比高达 15~45 TOPS/W！**

.. list-table:: 移动 SoC 三大异构计算引擎处理张量推理物理特性矩阵
   :widths: 18 24 28 30
   :header-rows: 1
   :class: tight-table

   * - 算力单元
     - 典型硬件拓扑
     - 优势与能效表现
     - 在移动 AI 系统中的架构分工
   * - **通用 CPU**
     - 8 核异构 (X4/A720/A520)
     - 极低调用延迟 ($<0.1	ext{ms}$)，能效低 ($0.2	ext{ TOPS/W}$)
     - 复杂动态控制流、树搜索、非标算子 Fallback
   * - **移动 GPU**
     - 8~16 Core TBDR 计算阵列
     - 高吞吐浮点 FP16/FP32，中等能效 ($2	ext{ TOPS/W}$)
     - 计算摄影后处理、通用图像滤波、无 NPU 时的通用加速
   * - **专用 NPU**
     - 2D 脉动阵列 + 向量后处理引擎
     - **极致定点整数吞吐，超高能效 ($30	ext{ TOPS/W}$)**
     - 实时视频超分、人像背景虚化、端侧 Transformer 推理

2D 脉动阵列 (Systolic Array) 与片上权重缓存 (Weight Buffer) 微架构
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

NPU 能效比实现数十倍跨越的核心在于**数据复用（Data Reuse）与内存访存最小化**：

.. code-block:: text

   +-------------------------------------------------------------------------+
   |                  NPU 2D 脉动乘加阵列 (Systolic Array) 数据流动拓扑      |
   +-------------------------------------------------------------------------+

              激活值输入流 X(0) -> [ PE 0,0 ] ===> [ PE 0,1 ] ===> [ PE 0,2 ]
                                      ||             ||             ||
              激活值输入流 X(1) -> [ PE 1,0 ] ===> [ PE 1,1 ] ===> [ PE 1,2 ]
                                      ||             ||             ||
              激活值输入流 X(2) -> [ PE 2,0 ] ===> [ PE 2,1 ] ===> [ PE 2,2 ]
                                      vv             vv             vv
                                 输出累加和 Y(0)  输出累加和 Y(1)  输出累加和 Y(2)

1. **权重固化（Weight Stationary）**：将卷积核或全连接层的权重矩阵预先加载至每个处理单元（Processing Element - PE）的本地内部寄存器中；
2. **激活值横向脉动传输**：输入的特征图激活值以行时钟对齐的方式自左向右横向穿过 PE 阵列；
3. **部分和纵向累加**：乘积累加结果（Partial Sums）沿着垂直方向逐级脉动向下累加，在最底部单个周期直接流出结果；
4. **访存削减**：整个 $N 	imes N$ 矩阵乘法过程中，权重与激活值在进入片上后仅从片外 LPDDR 读取 1 次，**消除了 95% 以上的高功耗总线往返数据搬运**。

11.2 模型定点量化 (Quantization) 数学模型与硬件执行
------------------------------------------------------------------------

标准深度学习模型训练阶段采用 IEEE 754 单精度浮点数（FP32 / 32 位）。若将一个 70 亿参数的端侧大模型直接以 FP32 部署，仅模型权重文件就需占用 $7 	imes 10^9 	imes 4\,	ext{Bytes} = 28\,	ext{GB}$ 显存，远超智能手机物理内存上限，且 FP32 浮点乘加单元面积与功耗巨大。

均匀非对称线性量化 (Uniform Asymmetric Quantization) 数学模型
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

现代端侧 AI 推理全面采用 **INT8 / INT4 低位宽定点量化**。其数学本质是将实数域连续浮点值 $r \in [r_{\min}, r_{\max}]$ 线性映射到有界整数域 $q \in [q_{\min}, q_{\max}]$（例如 INT8 对应 $[-128, 127]$）：

.. math::

   q = 	ext{clamp}\left( \left\lfloor \frac{r}{S} \right\rceil + Z, \, q_{\min}, \, q_{\max} \right)

其中：
- **缩放因子（Scale Factor - $S$）**：表征量化离散步长，为正实数：

  .. math::

     S = \frac{r_{\max} - r_{\min}}{q_{\max} - q_{\min}}

- **零点偏移量（Zero Point - $Z$）**：确保浮点数 $0.0$ 能够精确对齐为整数（避免 Padding 零值引入系统误差）：

  .. math::

     Z = 	ext{round}\left( \frac{-r_{\min}}{S} \right) + q_{\min}

量化定点矩阵乘法 (Quantized Matrix Multiplication) 硬件展开
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

对于两个实数矩阵相乘 $R_3 = R_1 	imes R_2$，代入反量化方程 $r \approx S(q - Z)$ 可推导出纯整数硬件计算流程：

.. math::

   q_3^{(i,k)} = \frac{S_1 S_2}{S_3} \sum_{j} \left( q_1^{(i,j)} - Z_1 \right) \left( q_2^{(j,k)} - Z_2 \right) + Z_3

在 NPU 微架构中：
1. 核心乘加项 $\sum q_1 q_2$ 运行在专用的 **8 位乘法累加器（MAC）** 上，累加结果暂存于 32 位整数寄存器（INT32 Accumulator），彻底消除浮点计算单元；
2. 标量缩放因子乘积 $\frac{S_1 S_2}{S_3}$ 被编译器重构为**定点定数乘法与右移位操作（Fixed-point Multiplier + Bit-Shift）**，在硬件上仅需单周期完成。

   :widths: 20 20 20 20 20
   :header-rows: 1
   :class: tight-table

   * - 数值格式
     - 位宽 (Bit Width)
     - 显存占用压缩比
     - 计算能耗 (pJ/Op)
     - 硬件乘法器面积
   * - **FP32 (单精度)**
     - 32-bit
     - 1.0x (基准 100%)
     - $\approx 4.0\,	ext{pJ}$
     - 1.0x (基准 100%)
   * - **FP16 (半精度)**
     - 16-bit
     - 2.0x (压缩 50%)
     - $\approx 1.1\,	ext{pJ}$
     - $\approx 0.25	ext{x}$
   * - **INT8 (8位定点)**
     - 8-bit
     - **4.0x (压缩 75%)**
     - **$\approx 0.2\,	ext{pJ}$ (节能 95%)**
     - **$\approx 0.05	ext{x}$ (节省 95%)**
   * - **INT4 (4位定点)**

11.3 移动端异构计算框架分层：Android NNAPI 与 Apple CoreML
------------------------------------------------------------------------

在操作系统层面，为了隔离底层千差万别的高通 Hexagon、联发科 APU、苹果 ANE 以及三星 NPU 专有微架构，移动 OS 确立了标准化的跨层硬件抽象栈。

Android NNAPI (Neural Networks API) 与 HAL 架构
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

.. code-block:: text

   +-------------------------------------------------------------------------+
   |                     Android 端侧 AI 全栈软件体系架构                    |
   +-------------------------------------------------------------------------+

   [ 顶层应用层 (Camera / System Apps / 3rd Party ML Apps) ]
        |
        v
   [ 机器学习运行时 (TFLite / ONNX Runtime / PyTorch Mobile) ]
        |  * 模型解析器 (FlatBuffers Parser)
        |  * 算子委托代理机制 (Delegate: GPU Delegate / NNAPI Delegate)
        v
   [ Android NNAPI 运行时库 (libneuralnetworks.so - 系统服务层) ]
        |  1. 模型图验证与拓扑分析 (Model Graph Validation)
        |  2. 子图分割引擎 (Subgraph Partitioning Engine):
        |     +-> 支持的卷积/Attention 子图 ---> 指派给 NPU 厂商驱动
        |     +-> 复杂的特殊激活算子 ---------> 指派给 GPU OpenCL/Vulkan 驱动
        |     +-> 不受支持的稀有自定义算子 ------> 回退至 CPU NEON/SVE 执行
        v
   [ NNAPI AIDL / HIDL 硬件抽象层 (android.hardware.neuralnetworks) ]
        |
        v
   [ 厂商 NPU 内核驱动与固件 (Qualcomm QNN / MediaTek NeuroPilot) ]
        |
        v
   [ 物理片上硬件 (SoC NPU Hardware Engine) ]

Apple CoreML 与 Apple Neural Engine (ANE) 软硬件协同
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

与 Android 的多厂商开放抽象不同，Apple 实施了从顶层框架到底层硬件的纵向垂直闭环：

.. list-table:: Android NNAPI 与 Apple CoreML 体系架构对比
   :widths: 20 40 40
   :header-rows: 1
   :class: tight-table

   * - **编译器后端**

   * - **算子调度策略**

     - 跨进程 Binder IPC 交互，开销约 $20\sim 80\,\mu	ext{s}$
     - **基于 Mach-O 内核直接调度，零用户态代理开销**

11.4 跨异构计算单元显存零拷贝流转闭环
------------------------------------------------------------------------

在实时计算摄影与端侧多模态视觉处理中，图像数据在相机 ISP、AI 神经网络处理器（NPU）以及图形渲染引擎（GPU）之间高频流转。若采用常规用户态内存复制，系统总线将被数据搬运彻底阻塞。

移动操作系统构建了基于 **硬件 DMA 连续物理内存共享（AHardwareBuffer / IOSurface）** 的端到端零拷贝闭环：

.. code-block:: text

   +-------------------------------------------------------------------------+
   |          ISP -> NPU -> GPU -> DPU 跨异构硬件全链路零拷贝流转闭环        |
   +-------------------------------------------------------------------------+

   [ 1. 显存分配中枢 (Gralloc / IOSurface) ]
        |  * 分配连续物理页框，导出标准文件描述符 dma_buf fd
        |  * 协商对齐格式: 硬件通用 NV12 / RGBA8888 格式
        v
   [ 2. 相机传感器采集与 ISP 硬件处理 ]
        |  * 硬件 ISP 完成 RAW 处理后，通过其专属 IOMMU 直接 DMA 将图像写入该物理内存！
        v
   [ 3. 触发系统 Hardware Sync Fence (acquire_fence 触发) ]
        |
        v
   [ 4. NPU 硬件推理引擎介入 ]
        |  * NPU 直接将同一块物理内存映射为输入张量特征图 (Tensor Input Feature Map)!
        |  * 无需格式重排，脉动阵列硬件直接执行卷积/特征提取;
        |  * NPU 将推理生成的【人像掩码张量 (Mask Tensor)】直接写入共享显存槽位 B;
        v
   [ 5. 触发下一个 Sync Fence ]
        |
        v
   [ 6. GPU 渲染管线 (RenderThread) ]
        |  * 像素着色器 (PS) 直接绑定显存槽位 A (原图) 与显存槽位 B (NPU 掩码);
        |  * 执行背景虚化与虚化边缘 Alpha 混合;
        v
   [ 7. 硬件合成器 (HWC) / DPU 扫描输出至 OLED 点阵刷新 ]
   ===========================================================================
   * 物理效益: 全程仅使用同一组显存页框，内存拷贝次数为严格的 0 次！

11.5 常驻低功耗 Sensor Hub 协处理器与微型机器学习 (TinyML)
------------------------------------------------------------------------

除了主 SoC 上的高性能 NPU 外，现代移动设备还面临一类严苛的**全天候常驻感知（Always-On Sensing）** 需求：
- 24 小时后台步态识别与跌倒检测；
- 息屏状态下唤醒词监听（如 "Hey Siri"、"OK Google"）；
- 抬腕亮屏与注视感知。

主 AP 休眠与独立低功耗 Sensor Hub 拓扑
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

如果让主 CPU 或主 NPU 保持常开运行这些感知模型，整机待机功耗将高达 $300\sim 800\,	ext{mW}$，手机电池在数小时内就会耗尽。移动系统设计了**基于独立微控制器（MCU）的低功耗 Sensor Hub 架构**：

.. code-block:: text

   +-------------------------------------------------------------------------+
   |                 主 AP 深度休眠态与 Sensor Hub 常驻感知时钟域            |
   +-------------------------------------------------------------------------+

   [ 状态 A: 主芯片处于深度睡眠 (AP Deep Sleep - 功耗 < 5mA) ]
   +-------------------------------------------------------------------------+
   | 主 CPU (时钟关闭) | 主 GPU/NPU (供电切断) | 主 LPDDR5X (自刷新状态)      |
   +-------------------------------------------------------------------------+
        ^
        | (保持休眠，不消耗主电量)
        |
   [ 状态 B: 独立 Sensor Hub 子系统 (常驻常开 - 功耗 < 200μA / 0.7mW) ]
   +-------------------------------------------------------------------------+
   | 低频 MCU (如 Cortex-M33 / RISC-V 32MHz)                                 |
   | 片上紧耦合 SRAM (512KB ~ 1MB)                                           |
   | 微型音频/加速度计硬件 FIFO 环形缓冲区                                   |
   | 微型深度学习推理引擎 (TinyML: 权重仅 50KB ~ 100KB INT8 模型)             |
   +-------------------------------------------------------------------------+
        |
        v (以 16kHz 采样音频并送入 TinyML 循环神经网络执行特征匹配)
   [ 命中唤醒词 (Confidence > 0.95) ]
        |
        v (拉高硬件专用唤醒引脚 Wakeup IRQ 产生物理电平翻转)
   [ PMIC 稳压器通电 -> 瞬间唤醒主 CPU 进入工作态！]
