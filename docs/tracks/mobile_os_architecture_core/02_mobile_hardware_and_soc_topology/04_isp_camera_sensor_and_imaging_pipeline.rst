10.1 CMOS 图像传感器 (CIS) 物理架构与色彩滤波阵列 (CFA)
------------------------------------------------------------------------

在移动摄影系统中，**CMOS 图像传感器（CMOS Image Sensor - CIS）** 是实现光电转换的物理核心。其微观结构由微透镜阵列（Microlens）、色彩滤波阵列（Color Filter Array - CFA）、光电二极管（Photodiode）矩阵以及列并行模数转换器（Column-Parallel ADC）构成。

.. code-block:: text

   +-------------------------------------------------------------------------+
   |                     CMOS 图像传感器 (CIS) 垂直物理截面与读出拓扑        |
   +-------------------------------------------------------------------------+

   [ 入射光子流 ]
        |
        v
   [ 顶层微透镜阵列 (Microlens Array) ] ---> 聚集光子，减少光子在边缘的散射损耗
        |
        v
   [ 色彩滤波阵列 (CFA - 如 Bayer RGGB) ] -> 仅允许特定波长 (红/绿/蓝) 的光波穿透
        |
        v
   [ 背照式感光区 (Back-Illuminated Photodiode - BSI) ]
        |  * 硅衬底光电效应: 光子能量激发电子-空穴对
        |  * 势阱 (Potential Well) 累积光生电荷 (电荷量 Q = 积分时间 * 光照强度)
        v
   [ 浮动扩散节点 (Floating Diffusion - FD) ] -> 电荷转换为微弱模拟电压信号 (V = Q/C)
        |
        v
   [ 列并行 10/12/14-bit 模数转换器 (Column-Parallel ADC) ]
        |
        v
   [ 原始数字图像数据流 (Digital RAW / RAW10 / RAW12) ]

色彩滤波阵列 (CFA) 拓扑演进与像素合并技术 (Pixel Binning)
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

自然界的光子本身不带有颜色信息，传感器依靠贴在光敏单元表面的色彩滤波膜识别颜色。为了在有限的手机模组体积内兼顾“高分辨率细节”与“暗光信噪比”，CFA 拓扑经历了三次重大架构演进：

.. list-table:: 现代移动 CMOS 传感器色彩滤波阵列 (CFA) 特性对比
   :widths: 18 22 28 32
   :header-rows: 1
   :class: tight-table

   * - CFA 拓扑架构
     - 像素排列矩阵
     - 核心物理优势
     - 计算与算法代价
   * - **传统 Bayer 阵列**
     - $2 	imes 2$ 单元：RGGB
     - 绿色占 50%，契合人眼视网膜绿光感度峰值
     - 物理进光面积受限，暗光噪点严重
   * - **Quad Bayer (四合一)**
     - $4 	imes 4$ 单元：$2 	imes 2$ 同色聚合
     - **暗光下 4 像素合并（Binning），信噪比提升 200%**
     - 强光下需硬件 ISP 执行 **Remosaic** 算法重排颜色
   * - **Nonacell (九合一)**
     - $6 	imes 6$ 单元：$3 	imes 3$ 同色聚合
     - **超大底（如 1/1.12 英寸）单像素等效达 2.4μm**
     - Remosaic 算法复杂度呈平方级激增，发热显著
   * - **RYYB 阵列**
     - $2 	imes 2$ 单元：RYYB（黄光替代绿光）
     - **进光量激增 40%（黄色通透红+绿双波段）**
     - 色彩校正矩阵（CCM）极复杂，易发生偏色失真

卷帘快门 (Rolling Shutter) 物理时序与果冻效应
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

由于移动传感器包含数千万像素，无法实现全局瞬时读取（Global Shutter），传感器采用**逐行曝光与逐行读出（Rolling Shutter）**。当拍摄高速运动物体或手机剧烈晃动时，顶部像素行与底部像素行存在数毫秒的读出时差（Line Readout Time），导致画面发生倾斜拉伸（果冻效应 - Jello Effect）。现代传感器通过引入 2-Hi 堆叠式架构（在感光层下方直接键合高速 DRAM 缓存），将全画幅读出时间压缩至 10ms 以内，大幅削弱了几何畸变。

10.2 MIPI CSI-2 高速差分传输协议与 D-PHY/C-PHY 物理层
------------------------------------------------------------------------

4K 60fps 10-bit RAW 视频流的数据吞吐量高达：

.. math::

   	ext{Bandwidth} = 3840 	imes 2160 	imes 10\,	ext{bit} 	imes 60\,	ext{fps} \approx 4.98\,	ext{Gbps}

传统 I2C/SPI 总线带宽（Mbps 级）无法承载如此海量的数据。移动产业确立了 **MIPI CSI-2（Camera Serial Interface 2）** 作为标准相机传输协议。

.. code-block:: text

   +-------------------------------------------------------------------------+
   |                     MIPI CSI-2 物理层与协议栈拓扑                       |
   +-------------------------------------------------------------------------+

   [ 传感器端 (Transmitter - TX) ]               [ 处理器 SoC 端 (Receiver - RX) ]
   +------------------------------+             +-------------------------------+
   | CCI 控制面 (I2C / I3C 双向)  |<===========>| CCI 控制器 (配置曝光/增益/马达) |
   |                              |             |                               |
   | CSI-2 数据面 (单向高速通道):  |             | CSI-2 接收控制器 (DMA Engine)  |
   |   - 时钟通道 (Clock Lane)    |------------>|   - 差分时钟恢复               |
   |   - 数据通道 0 (Data Lane 0) |============>|   - 解包器 (Packet De-packetizer)|
   |   - 数据通道 1 (Data Lane 1) |============>|   - 多通道虚拟路由 (VC Demux)  |
   |   - 数据通道 2 (Data Lane 2) |============>|                               |
   |   - 数据通道 3 (Data Lane 3) |============>|                               |
   +------------------------------+             +-------------------------------+
                                                        |
                                                        v
                                         [ 写入片上 ISP SRAM / 系统 LPDDR5X ]

D-PHY vs C-PHY 物理层微架构对比
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

.. list-table:: MIPI 物理层 D-PHY 与 C-PHY 核心规格对比
   :widths: 20 40 40
   :header-rows: 1
   :class: tight-table

   * - 规格维度
     - MIPI D-PHY (传统标准)
     - MIPI C-PHY (现代旗舰标准)
   * - **信号引脚拓扑**
     - 1 对差分时钟线 + 1~4 对差分数据线（共 10 根线）
     - **3 根线为一组（Trio），无需独立时钟线（共 9 根线）**
   * - **调制编码机制**
     - 不归零码（NRZ），每周期传输 1 bit/lane
     - **五电平三相符号调制，每符号传输 2.28 bits/trio**
   * - **单通道极限速率**
     - 最高 4.5 Gbps / Lane
     - **最高 6.0 Gsps / Trio（等效 13.68 Gbps / Trio）**
   * - **PCB 布线抗干扰**
     - 必须严格做等长走线匹配，高频易串扰
     - 自嵌入时钟，无时钟偏斜（Clock Skew），布线容忍度极高

- **虚拟通道（Virtual Channel - VC）多路复用**：单个物理 CSI-2 链路支持通过数据包头部的 2-bit VC 标识复用传输多路独立数据流（如同时传输可见光 RAW 图像、深度 ToF 数据以及嵌入式传感器元数据 Embedded Metadata）。

10.3 专用硬件 ISP 图像流水线多级微架构
------------------------------------------------------------------------

从 CMOS 输出的 RAW 数据是灰度且带有噪声的离散电荷计数，必须经过专用**硬件图像信号处理器（Image Signal Processor - ISP）**进行百级工序的高速像素重构。现代移动 ISP 通常划分为四大级联处理域：

.. code-block:: text

   +-------------------------------------------------------------------------+
   |                     专用硬件 ISP 核心处理阶段全景流水线                 |
   +-------------------------------------------------------------------------+

   [ 输入: MIPI 原始 RAW10/12 数据流 ]
        |
        v
   [ 阶段 1: RAW 域硬件预处理 (RAW Domain Processing) ]
        |  1. 黑电平校正 (BLC): 扣除热暗电流底噪基准
        |  2. 坏点校正 (DPC): 动态检测死像素，利用周围 8 邻域中值滤波替代
        |  3. 镜头阴影校正 (LSC): 乘法增益网格，消除边缘光学暗角与色彩偏移
        |  4. 多帧 HDR 硬件对齐与曝光融合 (HDR Merge: 长/中/短曝光对齐)
        v
   [ 阶段 2: 去马赛克插值 (Demosaicing / Debayer) ]
        |  * 边缘导向自适应插值 (Edge-Directed Interpolation)
        |  * 将单通道 Bayer 恢复为每个像素具备完整的 [R, G, B] 三原色
        v
   [ 阶段 3: RGB 域色彩与色调精修 (RGB Domain Processing) ]
        |  1. 色彩校正矩阵 (CCM): 3x3 矩阵转换，校正传感器光谱响应失真
        |  2. 3D-LUT 局部色调映射 (Local Tone Mapping - LTM)
        |  3. 伽马非线性校正 (Gamma Curve) 与对比度增强
        v
   [ 阶段 4: YUV 域降噪、缩放与格式输出 (YUV Domain Processing) ]
        |  1. 色彩空间转换 (RGB -> YUV420)
        |  2. 空域+时域多帧混合降噪 (2D/3D Noise Reduction - 3DNR)
        |  3. 边缘自适应锐化增强 (Edge Sharpening) 与紫边消除 (CAC)
        |  4. 多比例硬件标量缩放器 (Hardware Scaler)
        v
   [ 输出: 实时预览流 (YUV) / 录像编码流 (YUV) / 高清抓拍流 (RAW/JPEG) ]

10.4 3A (AE / AF / AWB) 统计引擎与闭环控制状态机
------------------------------------------------------------------------

ISP 流水线的高画质输出高度依赖于底层的 **3A（自动曝光 AE、自动对焦 AF、自动白平衡 AWB）** 算法闭环。3A 控制回路不是运行在通用 CPU 上的纯软件处理，而是由 **ISP 硬件统计引擎（Statistics Engine）** 与 **运行在 Sensor DSP/CPU 上的控制状态机** 实时交互实现的微秒级闭环。

.. code-block:: text

   +-------------------------------------------------------------------------+
   |                        3A 闭环控制系统时钟与数据流拓扑                  |
   +-------------------------------------------------------------------------+

   [ 逐帧图像数据流穿过 ISP ]
        |
        +---> [ 硬件统计引擎 (Hardware Stats Engine) ]
        |        |  * AE 统计: 划分 64x64 网格，统计各区域平均亮度直方图
        |        |  * AF 统计: 高通滤波算子卷积计算各网格高频边缘能量 (清晰度评价值)
        |        |  * AWB 统计: 提取白点色度坐标直方图 (Cb, Cr 投影)
        |        v (每帧结束生成统计元数据 Stats Buffer)
        |     [ 触发内核 VSYNC / SOF 中断 ]
        |        |
        v        v
   [ 3A 算法状态机 (运行于 ISP 协处理器 / DSP) ]
        |
        +---> 1. AE 算法: 调整下一帧的【积分时间 (Exposure Time)】与【模拟增益 (Analog Gain)】
        +---> 2. AF 算法: 驱动音圈马达 (Voice Coil Motor - VCM) 移动镜片位置
        +---> 3. AWB 算法: 动态下发新的 R/G/B 通道白平衡增益参数
        |
        v (通过 CCI / I2C 总线在下一个垂直消隐期 VBLANK 准时下发给传感器与马达)
   [ 传感器与马达完成物理参数更新 -> 采集下一帧画面 ]

相位对焦 (PDAF) vs 反差对焦 (Contrast AF)
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

- **反差对焦（Contrast AF）**：移动马达反复前后微调镜片，寻找高频边缘能量最大的峰值点。缺点：存在明显的“拉风箱”前后试探过程，耗时 300ms~500ms。
- **相位差对焦（PDAF - Phase Detection AF）**：在感光像素表面覆盖微型遮蔽层或采用双核全像素对焦（Dual Pixel），左侧光电管与右侧光电管采集具有物理视差（Parallax）的左右影像。算法直接对左右信号做互相关运算（Cross-Correlation），**单次计算直接得出离焦距离与方向**，马达 50ms 内一步合焦到位。

10.5 Android Camera HAL3 架构与多流请求管线 (Stream Pipeline)
------------------------------------------------------------------------

在移动操作系统软件栈中，相机驱动架构经历了从早期的同步阻塞单流模型（Camera HAL1）到现代完全异步解耦的 **Camera HAL3** 架构的演进。

Camera HAL3 核心概念：按帧请求模型 (Per-Frame Request Pipeline)
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Camera HAL3 抛弃了“打开预览”、“拍照”等高层粗粒度接口，将其抽象为高度原子化的**帧捕获请求（Capture Request）**流水线：

.. code-block:: text

   +-------------------------------------------------------------------------+
   |                   Android Camera HAL3 多流请求分发管线拓扑              |
   +-------------------------------------------------------------------------+

   [ 应用层 (Camera2 API) / 系统 CameraService ]
        |
        +--- 循环下发 CaptureRequest (附带独立的 AE/AF 参数、曝光补偿元数据)
        |
        v
   [ 厂商 Camera HAL3 驱动中枢 ]
        |
        +---> 调度硬件 ISP 流水线同时配置多个输出端口 (Streams):
                 |
                 +--> Stream 0 [ 预览流 (Preview) ]: 1080p YUV420 -> 送入 SurfaceFlinger 屏幕显示
                 +--> Stream 1 [ 录像流 (Video) ]: 4K NV12 -> 送入 MediaCodec 硬件 H.265 编码器
                 +--> Stream 2 [ 抓拍流 (Snapshot) ]: 50MP RAW/JPEG -> 送入拍照存储管道
                 +--> Stream 3 [ 视觉流 (Vision/AI) ]: 480p YUV -> 送入 NPU 执行人脸追踪/场景分类
                 |
        +<-------+ 各硬件模块并行处理完毕
        |
   [ 异步回调 CaptureResult (携带该帧实际曝光时间、陀螺仪位姿、直方图等完整元数据) ]

基于 DMA-BUF 的全链路跨硬件零拷贝直通
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

在 Camera HAL3 多流管道中，所有的 `camera3_stream_buffer_t` 输出缓冲区，均由 Gralloc 分配并封装为 Linux 内核 `dma_buf` 文件描述符。
- ISP 硬件通过其专用 IOMMU 将像素数据直接 DMA 写入物理内存；
- GPU 渲染管线、Display 硬件合成器（HWC）与视频硬件编码器（VPU）无需发生任何内存复制（`memcpy`），通过虚拟地址映射直接访问同一组物理显存页框，**支撑 4K 60fps HDR 录像全链路整机功耗控制在 2.5W 以内**。
