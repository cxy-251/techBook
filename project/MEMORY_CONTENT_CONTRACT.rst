必背课本内容合同
================

目的
----

``docs/memory/`` 保存与 AIBook 章节一一对应的教材式知识提炼。它不是完整教材的缩写，
也不是问答、练习、源码时间线或资料索引。每章应围绕一个中心主题，提炼出少量能够建立
概念模型、解释关键路径并支持工程判断的知识点。

适用范围
--------

本合同只约束 ``docs/memory/``。现有 ``docs/tracks/linux-kernel/``、审计记录、状态文件和
固定源码流程继续服从 ``project/LINUX_KERNEL_CONTRACT.rst``，两条内容线不得相互覆盖。

权威顺序
--------

发生冲突时依次服从：

#. 用户当前明确指令；
#. 根目录 ``AGENTS.md``；
#. 本合同；
#. AIBook 对应章节及其引用的一手资料；
#. 已有必背正文。

章节对应
--------

每篇正文必须与 AIBook 的 Part、章节号和主题一一对应。文件编号、标题、目录和 Git 历史
维护对应关系；正文不保留来源元数据或固定链接。不得合并无关章节，也不得把一章拆成
脱离原书的新知识体系。

教材式提炼原则
--------------

每章先确定一个中心模型，再选择支撑该模型的核心知识点。正文必须满足：

* 保留定义、对象关系、状态变化、执行顺序和判断边界；
* 删除铺垫、重复解释、长案例、扩展阅读、工具清单和过程性叙事；
* 同一事实只在最合适的位置表达一次，不在多个小节重复改写；
* 核心知识点使用“概念名称 + 准确定义或作用”的形式，不写成零散句子堆积；
* 默认每章提炼 4—8 个核心知识点；复杂章节可以增加，但必须按主题归并；
* 路径只保留决定对象转换和状态变化的主干节点，不展开旁支实现；
* 容易混淆的概念必须直接写出双方定义及关键差异，不能只并列名称；
* 函数名、类型名、字段名、宏、配置项和路径保留准确拼写；
* 版本相关、配置相关或实现相关内容必须明确边界，不能写成无条件事实；
* 不写问题、练习、互动提示，也不要求读者先完成推导才接受结论。

AIBook 决定章节范围，技术事实决定最终表述。正文应像教材中的知识提要：先建立概念，
再给出路径，最后澄清边界，而不是把原章节逐句压缩。

固定格式
--------

每章依次包含：

#. ``核心知识点``：用定义列表提炼本章的主要概念、对象和规则；
#. ``关键路径``：给出一至三条最能代表本章机制的对象或状态转换路径；
#. ``概念辨析``：直接说明容易混淆概念的定义与差异；
#. ``本章结论``：用一至两句话收束中心模型。

没有适用路径的章节可以省略 ``关键路径``，但不得保留空标题。正文应能在 5—15 分钟内完成
一次阅读；篇幅服从知识密度，不以固定字数机械截断。

修改边界
--------

制作必背内容时，不修改 AIBook 原文，不修改 ``docs/tracks/`` 旧正文，不推进 Linux Kernel
旧轨道的审计游标，也不更新 ``project/STATE.rst``。同一任务只改当前书籍的必背目录、必要
导航和本合同。
