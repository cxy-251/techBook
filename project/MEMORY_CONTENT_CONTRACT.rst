必背课本内容合同
================

目的
----

``docs/memory/`` 保存与 AIBook 章节一一对应的必背知识。它不是完整教材、章节摘要、
问答练习或源码时间线，而是面向直接记忆的课本正文。读者应能在较短时间内掌握一章中
稳定、确定、必须记住的结论。

适用范围
--------

本合同只约束 ``docs/memory/``。现有 ``docs/tracks/linux-kernel/``、审计记录、状态文件和
固定源码流程继续服从 ``project/LINUX_KERNEL_CONTRACT.rst``，两条内容线不得相互覆盖。

权威顺序
--------

发生冲突时依次服从：

#. 用户当前明确指令；
#. 根目录 ``AGENTS.md``；
#. 本合同；
#. AIBook 对应章节及其引用的一手资料；
#. 已有必背正文。

章节对应
--------

每篇必背正文必须与 AIBook 的 Part、章节号和主题一一对应。对应关系由文件编号、标题、目录
和 Git 历史维护；正文不保留来源元数据或固定链接。章节范围、顺序和主题由 AIBook 决定，
不允许为了凑结构合并无关章节，也不允许把一章拆成脱离原书的新知识体系。

内容标准
--------

每条正文必须满足：

* 只表达一个明确结论；
* 只保留稳定、必要、可以直接记忆的知识；
* 删除铺垫、重复叙事、长案例、过程性讨论和扩展阅读；
* 函数名、类型名、字段名、宏、配置项和路径保留准确拼写；
* 执行路径按真实顺序书写，不能用含糊箭头掩盖关键对象转换；
* 容易混淆的概念必须分别写出定义、适用范围或判断条件，不能只并列名称；
* 不写问题、练习、作业、互动提示或“请自行思考”；
* 不要求读者先完成推导才接受结论；
* 不把推断、版本相关实现或存在争议的说法写成无条件事实。

AIBook 决定章节范围，技术事实决定最终表述。AIBook 中涉及版本相关、实现相关或容易失真的
结论，在发布为“可直接背诵”内容前必须复核其引用的一手资料。无法确认的内容不写入正文。

固定格式
--------

每章依次包含：

#. ``本章必须记住``；
#. ``必背路径``；
#. ``必须区分``；
#. ``一句话结论``。

没有适用路径的章节可以省略 ``必背路径``，但不得用空标题占位。正文以 5—15 分钟可完成一次
阅读为目标；篇幅服从知识密度，不以固定字数机械截断。


修改边界
--------

制作必背内容时，不修改 AIBook 原文，不修改 ``docs/tracks/`` 旧正文，不推进 Linux Kernel 旧轨道的
审计游标，也不更新 ``project/STATE.rst``。同一任务只改当前书籍的必背目录、必要导航和本合同。
