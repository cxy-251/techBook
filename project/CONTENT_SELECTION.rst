内容计划规则
============

本文件规定一本技术书如何在开始写作前确定内容。选题只在书籍规划阶段执行一次；正式生产阶段不得每次重新选题。

两层模型
--------

书籍内容分成两个层次：

``fixed plan``
   在一本书开始前固定范围、Part、章节 ID、章节顺序、学习结果、前置依赖和证据类型。

``execution gate``
   每次运行只检查固定计划中的下一章是否具备 source、实验、输出和源码验证条件。

execution gate 只决定“现在能否执行”，不决定“下一章写什么”。

计划必须固定的内容
------------------

一本书进入正式生产前，必须在 ``manifests/books/<book>-plan.toml`` 中固定：

* 书名和卷名；
* 目标读者；
* 最终能力；
* 明确排除的内容；
* Part 顺序；
* 全部章节 ID；
* 全部章节问题；
* 章节顺序；
* 每章学习结果；
* 前置章节；
* 所需证据类型。

计划状态
--------

``proposed``
   目录仍在整体设计。不得创建正式章节。

``frozen``
   计划已经固定。Agent 必须按顺序执行，不得临时增删、重排或替换问题。

``superseded``
   旧计划已经被新版本替代，只保留历史依据。

一本书只有在计划为 ``frozen`` 时才能进入章节生产。

每次生成时的行为
----------------

Agent 每次工作必须：

#. 读取当前 frozen plan。
#. 找到顺序最靠前且状态未完成的章节。
#. 检查其前置章节是否完成。
#. 检查 source contract、lab、真实输出和源码符号条件。
#. 条件齐全时执行该章。
#. 条件不足时记录 blocker，停止正文生成。

Agent 不执行评分、随机选择、主题发散或从旧 Roadmap 中临时挑选章节。固定顺序中的章节被 blocked 时，默认不跳过；计划明确允许并行时才可以处理其他章节。

计划修订
--------

以下情况可以发起计划修订：

* 用户改变整本书的目标或范围；
* 固定源码版本证明某个章节问题不存在；
* 一个问题无法形成可重复实验；
* 两个章节在实际证据中属于同一条不可分割路径；
* 前置依赖顺序被源码和实验推翻。

修订必须：

#. 增加 ``plan_version``；
#. 记录修改原因和影响章节；
#. 更新 ``project/DECISIONS.rst``；
#. 重新检查全书依赖顺序；
#. 将旧版本标记为 superseded。

普通章节生产 Agent 没有自行修订计划的权限。

旧 aiBook 的作用
----------------

旧仓库只作为规划阶段的主题库存、资料索引和反面样本。旧 Roadmap 不直接成为新书目录，旧章节顺序也不控制新计划。

Linux 第一卷
------------

Linux Kernel 第一卷的固定计划位于 ``manifests/books/linux-kernel-plan.toml``。主线顺序为：

``ARM64 启动入口 → MMU 与虚拟地址切换 → start_kernel → initcall → 用户空间 init → read 系统调用 → VFS``。

因此第一章从 ARM64 内核镜像入口开始，``read()`` 与 VFS 位于后半卷，不再作为首章。
