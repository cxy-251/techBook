学习内容规划规则
================

适用边界
--------

本文件规定跨路径的一般内容选择。当前Linux Kernel已经进入从001开始的顺序回溯审查，
其批次、完成语义和后续生产条件由 ``LINUX_KERNEL_CONTRACT.rst`` 覆盖。回溯期间不重新
随机选unit，也不越过审查游标生产新章。

本文件规定新内容从哪里来，以及 Roadmap 如何转化为适合零基础读者的学习路径。

内容来源分工
------------

``aiBook`` 中三类资产承担不同职责。

Roadmap 与生成控制文件
   表达用户真正希望获得的知识范围、主题关系、深度要求和工程方向。它们是 ``techBook`` 的知识需求输入。

权威资料与真实现象
   提供技术事实。包括官方文档、标准、固定版本源码、真实代码行为、命令输出、日志、请求、trace 和可确认的系统现象。

旧 ``docs`` 正文
   用于分析旧生成结果为什么看不下去、为什么过度展开、为什么问题与答案脱节。它不是新正文的事实来源或文本底稿。

因此，新内容不是从旧文章改写而来，也不是由 Agent 仅凭主题名称自由发挥。

Roadmap 是知识清单，不是章节目录
------------------------------

Roadmap 中的条目代表用户希望覆盖的知识，不能直接解释为“一条生成一章”。

一个 Roadmap 条目可以：

* 与其他条目合并成一个连续学习单元；
* 因范围过大而拆成多个能力台阶；
* 因缺少前置能力而调整顺序；
* 在基础阶段只讲行为模型，在后续阶段再进入源码；
* 因与其他条目重复而合并覆盖；
* 因不属于当前路径目标而明确排除并记录原因。

不能因为旧生成控制文件要求章节完整，就把每个小标题扩充成定义、背景、分类、实现、边界、工程实践和总结。

知识库存
--------

每条学习路径开始设计前，先盘点其 Roadmap 和文章生成控制文件。盘点至少记录：

* 控制文件的仓库路径；
* 用户真正想获得的知识项；
* 条目之间的前置关系；
* 原生成结构中只服务于文章形式的要求；
* 旧正文中被明显过度扩充的部分；
* 每个知识项需要重新查证的一手来源类型。

知识项状态使用以下语义：

``pending``
   已从控制文件识别，尚未设计学习位置。

``planned``
   已进入某个阶段或学习单元的设计。

``merged``
   与其他知识项合并覆盖，必须记录目标学习单元。

``covered``
   已由完成的学习单元覆盖。

``deferred``
   当前阶段前置能力不足，延后处理。

``excluded``
   明确不属于当前路径范围，必须记录原因。

知识库存可以直接记录在路径入口 RST 或 track TOML 中，不需要新建程序或自动化系统。

三层规划
--------

``track contract``
   根据 Roadmap 知识库存固定目标读者、入口能力、最终能力、阶段顺序、覆盖范围和排除项。

``stage batch``
   从尚未覆盖的知识项中选择一个小批次，设计少量 unit、顺序、前置能力和完成标准。

``execution``
   每次只处理当前批次中顺序最靠前的未完成 unit，并检查前置能力、事实来源和内容证据。

整条路径不在开始时冻结全部章节。每次也不重新随机选题。

Unit 进入批次的条件
-------------------

一个知识项只有同时回答以下问题后，才能转化为 unit：

#. 它对应 Roadmap 中哪个知识需求？
#. 读者在什么真实场景中需要它？
#. 学习前容易形成什么错误判断？
#. 学习后能够独立做什么？
#. 能用什么最小代码、错误、输出或现象观察它？
#. 技术事实需要查阅哪些一手来源？
#. 需要哪些前置能力？
#. 如何改变一个条件检验理解边界？
#. 如何设计一个不能照抄原例子的迁移任务？

只因为 Roadmap 或旧目录中存在一个标题，不能直接生成文章。

每次工作时的行为
----------------

Agent 每次必须：

#. 读取当前路径的 Roadmap/控制文件库存；
#. 找到当前阶段中顺序最靠前且未完成的 unit；
#. 检查它覆盖的知识项、前置能力和一手来源；
#. 重新核实旧正文中的任何代码、链接、源码路径和结论；
#. 条件齐全时继续编写或修订 RST；
#. 条件不足时记录问题，不用流畅文字补齐事实缺口；
#. 批次完成后进行整体阅读检查，再设计下一批。

旧正文的使用限制
----------------

旧 ``aiBook/docs`` 允许用于：

* 定位某个知识项被扩充到什么程度；
* 发现读者缺少的前置台阶；
* 找出没有来源的问题和没有推理的答案；
* 对比新单元是否真正减少了无效篇幅。

旧正文中的文字、链接、代码、输出、源码路径和技术结论默认都不可信，必须重新确认后才能进入新 RST。

当前策略
--------

当前先完成控制文件盘点，而不是立即从旧 ``docs`` 挑文章改写。

盘点完成后，从知识库存中选择三个能够代表不同难度的黄金学习单元：语言基础、系统行为和源码阅读各一个。黄金单元经过实际阅读检查后，再设计各路径的第一批正式内容。
