学习内容规划规则
================

本文件回答两个问题：路径开始时固定什么，以及每次生成内容时是否重新选题。

结论
----

每次生成内容时不重新选题。Agent 只执行当前阶段已设计批次中的下一个 unit。

整条路径也不在开始时冻结所有章节。开始时固定的是目标、能力层级、阶段顺序和边界；具体 unit
按阶段分批设计，并根据真实学习反馈校准。

三层规划
--------

``track contract``
   路径开始时固定。包含目标读者、入口能力、最终能力、阶段顺序、范围和排除项。

``stage batch``
   一个阶段开始前固定。包含少量 unit、顺序、前置能力和完成标准。

``execution``
   每次运行只处理当前 batch 中顺序最靠前的未完成 unit，并检查证据与前置能力。

因此，规划既不是“每次临时发挥”，也不是“在没有学习反馈时提前冻结整本书”。

Track contract
--------------

每条学习路径必须在 ``manifests/tracks/<track>.toml`` 中明确：

* 零基础读者从什么能力进入；
* 最终达到哪个能力层级；
* 为什么需要这条路径；
* 固定的阶段顺序；
* 明确覆盖和排除的范围；
* 哪些主题需要源码级证据，哪些只需行为级证据。

这些内容改变时必须记录长期决策。

Stage batch
-----------

每个阶段只设计一个可验证的小批次。一个 batch 中的 unit 应当满足：

* 共同服务同一个阶段结果；
* 每个 unit 只产生一次能力变化；
* 前置能力顺序明确；
* 能在完成后进行实际阅读和任务检查；
* 数量足够形成连续学习，又小到能够整体校准。

默认先使用三到五个 unit。数量不是硬限制，设计者需要说明为什么这些 unit 构成一个完整批次。

Unit 进入批次的条件
-------------------

一个主题只有同时回答以下问题后才能成为 unit：

#. 读者在什么真实场景中会需要它？
#. 学习前容易形成什么错误判断？
#. 学习后能够独立做什么？
#. 能用什么最小现象、代码、错误或输出观察它？
#. 需要哪些前置能力？
#. 如何改变一个条件检验理解边界？
#. 如何设计一个不照抄示例的迁移任务？

只因为旧 Roadmap 中存在某个标题，不能成为 unit 的理由。

每次运行时的行为
----------------

Agent 每次工作必须：

#. 读取当前 track 和当前 stage batch；
#. 找到顺序最靠前且未完成的 unit；
#. 检查前置能力、学习设计和证据；
#. 条件齐全时继续实验、写作或评估；
#. 条件不足时记录 blocker，不临时选择无关主题；
#. batch 完成后进行整体学习检查，再设计下一批。

校准与修订
----------

以下情况允许修改尚未完成的 batch：

* 实际阅读表明前置能力缺失；
* 问题动机不成立，读者不知道为什么要学；
* 两个 unit 的能力变化无法区分；
* 一个 unit 同时引入过多新概念；
* 迁移任务无法独立完成；
* 真实证据推翻原来的解释或顺序。

修订必须记录原因和影响，不得为了让 Agent 更容易生成而扩展内容。

旧 aiBook 的作用
----------------

旧仓库用于建立主题库存和寻找典型失败样本。迁移时不继承旧章节的标题、篇幅和段落顺序。

处理顺序是：

``旧主题 → 真实困惑 → 能力变化 → 最小证据 → unit 设计 → 阅读验证``。
