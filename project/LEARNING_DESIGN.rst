学习设计
========

``techBook`` 的目标不是批量生产文章，而是把 ``aiBook/docs`` 中的技术方向重做为面向零基础程序员、
可以逐步获得真实能力的 RST 学习资料。

学习是否发生
------------

读者看懂一段文字不代表已经学会。一个学习单元结束后，读者至少应当能够：

#. 预测一个最小示例或具体系统现象；
#. 根据代码、对象、状态、输出或源码证据解释原因；
#. 改变一个条件并重新判断；
#. 识别一个常见错误理解；
#. 在不照抄原例子的情况下完成一个小型迁移任务。

缺少关键步骤时，内容只能算资料说明，不能标记为完成的学习单元。

零基础读者模型
--------------

* 不假设读者知道尚未在当前路径中建立的术语；
* 新术语第一次出现时必须绑定当前代码、对象、状态或现象；
* 需要前置能力时必须链接到已有 RST，不能只写“需要基础知识”；
* 源码阅读是较高阶段的学习工具，不是所有主题的开场方式；
* 一次只引入解决当前困惑所需的最少概念。

能力层级
--------

``L1 运行``
   能运行或观察最小例子，知道结果是什么。

``L2 解释``
   能指出关键对象、调用、状态变化和结果之间的关系。

``L3 修改``
   改变参数、数据或场景后仍能预测结果，并解释边界。

``L4 排错``
   面对错误输出，能够提出假设并设计验证步骤。

``L5 迁移``
   面对未见过的代码或系统，能够查资料、读源码、构造例子并形成判断。

每条学习路径必须明确从哪个层级开始，以及最终要求读者达到哪个层级。

学习单元主链
------------

一个 unit 只负责一次清晰的能力变化。内容通常需要形成下面这条主链：

#. ``为什么现在需要它``：给出真实场景或可观察困惑；
#. ``先预测``：在解释出现前让读者作出判断；
#. ``最小证据``：给出代码、命令、输出、错误、界面现象、日志或源码片段；
#. ``逐步推理``：把每个结论连接到具体输入、调用、对象、状态和结果；
#. ``改变一个条件``：建立边界，防止只记住一个答案；
#. ``常见误解``：指出错误模型与证据冲突的位置；
#. ``能力检查``：问题必须来自前面的预测和证据；
#. ``答案与推理``：说明答案来源，也说明常见错误答案为什么错；
#. ``独立任务``：要求读者完成一个小型迁移；
#. ``完成标准``：定义何时算学会，而不是何时算读完。

这些名称不是强制标题。内容可以按主题自然组织，但不能删除预测、证据、推理、变化和迁移组成的
学习过程。

RST 自包含原则
--------------

一个学习单元原则上使用一个 RST 文件完成：

* 示例代码使用 ``.. code-block::`` 直接写入；
* 命令和输出使用 ``.. code-block:: console`` 直接写入；
* 编译错误、日志和 trace 使用合适的代码块直接写入；
* 图示可以使用 RST 支持的简单图、Mermaid 文本或普通图片链接；
* 源码级内容在当前文件中记录仓库、release、commit、平台和工具链；
* 文件之间使用普通相对链接；
* 不依赖 ``literalinclude``、Sphinx 角色、toctree 或构建产物。

只有内容确实无法在 RST 中合理表达时，才讨论增加额外资产。不得提前建立 lab 或工具目录。

证据类型
--------

证据必须与学习阶段匹配：

* 语言基础可以使用运行结果、对象状态和官方语言文档；
* 编译与类型问题可以使用编译错误、警告、AST 或中间表示；
* Web 与系统内容可以使用请求、日志、网络面板和进程状态；
* 源码级内容需要固定实现、版本、commit、源码符号和可复现观察；
* 架构内容需要具体场景、边界、失败路径和可定位组件。

禁止为了显得“底层”而强行加入源码。需要源码证明时，也不能用抽象描述替代真实实现。

问题设计
--------

问题不是正文结束后的装饰。每个问题必须能够说明：

* 它来自哪个现象、代码行或输出；
* 正确答案需要经过哪些推理步骤；
* 哪项证据支持答案；
* 常见错误答案依赖什么错误模型；
* 答错后应该回到哪个步骤重新观察。

无法回答“为什么要问这个问题”的题目必须删除。

解释标准
--------

解释应当使用可追踪语言：

* 指明是哪一行代码、哪个对象、哪个函数或哪个状态；
* 说明输入发生了什么变化；
* 说明输出为什么随之变化；
* 区分事实、推断和约定；
* 每段只增加一个新判断。

避免使用“系统进行处理”“框架负责协调”“底层完成转换”等无法定位的句子。

学习路径与批次
--------------

路径开始时固定目标读者、入口能力、最终能力、阶段顺序、范围和明确排除项。完整章节数量不在开头
冻结。每个阶段开始前设计一个小批次 unit，并在实际阅读和能力检查后校准下一批。

黄金样例
--------

批量迁移 ``aiBook/docs`` 前，需要完成三类黄金学习单元：

* 一个语言基础单元；
* 一个系统行为单元；
* 一个源码阅读单元。

黄金单元必须由真实阅读反馈确认：读者知道为什么要学、答案从哪里来，并能完成变化与迁移任务。
