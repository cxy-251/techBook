第055章证据
-----------

``random_init_early()``
   混入编译期潜在熵、架构随机数据、UTS信息以及 ``setup_arch()`` 交回的架构命令行；
   ``bootconfig`` 后加文本不属于该参数。混入数据不自动等于随机数生成器已经就绪。

``setup_log_buf(0)``
   先公布正式每CPU数据。动态日志缓冲区已经存在时不重复分配；从静态缓冲区迁移的任一分配
   失败都会释放本次对象并继续使用静态缓冲区。

``vfs_caches_init_early()``
   固定初始化 ``in_lookup_hashtable``。 ``hashdist=false`` 时，
   ``dcache_init_early()`` 和 ``inode_init_early()`` 在此分配目录项与索引节点哈希表；
   ``hashdist=true`` 时，两者直接结束，把分配推迟到 ``vfs_caches_init()``。两条路径都不会
   在这里创建运行期目录项或索引节点对象缓存，也不会挂载文件系统。

``sort_main_extable()`` 与 ``trap_init()``
   主异常表仅在需要且非空时排序。x86陷阱路径完成CPU入口区域、TSS、IST以及FRED或IDT条件，
   不初始化设备IRQ，也不打开IF位。

``mm_core_init()``
   先完成IOMMU早期内存、零页PFN、内存区域回退表、页面分配器热插拔回调和可选调试设施；
   KHO仍在memblock有效时处理。 ``memblock_free_all()`` 只把
   ``memblock.memory - memblock.reserved`` 覆盖的页面交给伙伴系统，并据实际释放量更新
   ``totalram_pages``。随后，x86 ``mem_init()``、SLUB自举、页面扩展、调试缓存、
   ``vmalloc_init()``、 ``espfix``、PTI、KMSAN、MM缓存和 ``execmem_init()`` 依次完成。

第056章证据
-----------

``maple_tree_init()``
   用 ``SLAB_PANIC`` 创建 ``maple_node`` 缓存；不创建用户 ``mm_struct``、VMA或具体地址树。

``poking_init()``
   创建 ``text_poke_mm``，选择同一PMD内的连续双页地址并预建页表。当前PTE为空，内核正文页
   没有映入临时地址。真正修补时才建立短暂别名、写入并刷新TLB。

``ftrace_init()``
   动态函数追踪构建先处理 ``__start_mcount_loc`` 到 ``__stop_mcount_loc``。值为0或不属于内核
   正文段的位置被逐项跳过，不会因此禁用全部函数追踪；空表或记录页申请失败才进入禁用路径。
   记录建立后， ``ftrace_process_locs()`` 会在本章调用 ``ftrace_update_code()``，所以这里可能
   已经按架构约定改写内置函数追踪位置。

``early_trace_init()``
   ``tracepoint_printk`` 迭代器与普通日志缓冲区分离。 ``tracer_alloc_buffers()`` 失败会按阶段
   清理并保持追踪禁用，但其返回值不会阻止随后执行 ``init_events()``；不能把事件类型登记与
   全局追踪缓冲区可用合并为同一状态。

第057章证据
-----------

``sched_init()``
   检查调度类链接顺序，建立位等待表、 ``root_task_group`` 和
   ``def_root_domain``。 ``def_root_domain`` 先持有基础引用1；每个可能CPU的 ``rq`` 连接根域时
   再增加一份引用，并加入 ``span``。

逐CPU运行队列
   初始化循环先把每个 ``rq->online`` 置为0。 ``rq_attach_root()`` 随后检查
   ``cpu_active_mask``：CPU0已经活动，因此 ``set_rq_online(rq0)`` 把 ``rq0.online`` 置为1，
   并把CPU0加入 ``def_root_domain.online``；尚未活动的应用处理器仍保持0。循环最后申请
   ``scratch_mask``，栈外CPU掩码构建中的申请结果未被调用者检查。

``init_task`` 与 ``init_idle()``
   当前任务取得惰性TLB引用和内核线程元数据， ``__sched_fork(0, current)`` 只重置调度状态，
   不创建子任务。 ``init_idle(current, 0)`` 在 ``pi_lock`` 与运行队列锁保护下公布
   ``rq0.curr``、 ``rq0.idle``、 ``on_rq`` 和 ``on_cpu``，把任务改为CPU0的空闲调度类，但不
   进入空闲循环，也不调用 ``schedule()``。

调度器公布与出口
   完成调度类全局初始化、PSI、利用率钳制和条件抢占模式后，
   ``scheduler_running`` 置为1。紧随其后的 ``WARN(!irqs_disabled())`` 会在异常打开中断时重新
   执行 ``local_irq_disable()``，所以第058章入口处IF位确定为0。

复查发现并修正
--------------

#. 纠正第055章VFS结论： ``hashdist=true`` 会同时推迟目录项和索引节点哈希表分配，不再写成
   无条件早期分配。
#. 纠正第056章函数追踪失败语义：无效位置逐项跳过，不会使整体失败；同时补明
   ``ftrace_process_locs()`` 在本章实际进入 ``ftrace_update_code()``。
#. 补齐第057章CPU0出口状态： ``rq_attach_root()`` 因CPU0已经活动而执行
   ``set_rq_online()``，根域在线掩码包含CPU0，引用数包含基础引用和每个已连接运行队列的引用。
#. 六十章当前工作范围内，对第055—057章重新检查普通英文叙述、压缩短句和标题长度；源码标识
   保持英文，条件、状态、动作和因果关系改用完整中文。

失败与未发生
------------

* ``SLAB_PANIC``、文本修补 ``BUG_ON()`` 以及若干内存管理致命分配路径没有正常返回分支；
* 函数追踪、早期追踪、KMSAN、KFENCE、KHO和PTI等设施受构建与分配结果控制；
* 没有控制台驱动、根文件系统挂载、初始内存盘解包、PID 1或PID 2；
* 没有设备中断启用、调度器时钟滴答、任务切换、应用处理器启动或完整SMP调度域。
