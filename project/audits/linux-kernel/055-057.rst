early allocator与MM交接边界
---------------------------

* ``random_init_early`` 收到的是 ``setup_arch`` 返回的arch command line，不含后来bootconfig单独追加的
  extra init/kernel文本；mix也不自动证明CRNG ready；
* ``setup_log_buf(0)`` 先发布per-CPU readiness；dynamic buffer已存在则返回，迁移任一步失败则释放本次
  对象并保留static ring；
* ``vfs_caches_init_early`` 只建立lookup heads与dentry/inode hash backing，不创建later SLUB object
  caches、文件系统或mount；
* ``trap_init`` 完成x86 CPU entry/TSS/IST与FRED-or-IDT foundation，不等于 ``init_IRQ`` 或打开IF；
* zonelists、boot pagesets和page-allocator CPUHP callback存在时，普通free RAM仍未交给buddy；
* KHO处理必须在memblock active、紧邻handoff处完成，disabled build才是no-op；
* ``memblock_free_all`` 释放的是memblock ``memory - reserved``，而不是全部E820 RAM；
* x86 ``mem_init`` 的共享vmalloc page-table预分配与later ``vmalloc_init`` 的vmap-area allocator不同；
* ``kmem_cache_init`` 只完成SLUB bootstrap， ``kmem_cache_init_late`` 尚未执行；
* ``mm_core_init`` 不能在vmalloc后提前截断，真实尾部还包括espfix、PTI、KMSAN runtime、MM cache与
  execmem initialization。

Maple、text-poke与tracing边界
----------------------------

* Maple call只创建node cache，不创建user ``mm_struct``、VMA或实际Maple tree；
* text-poke专用mm预分配page tables，PTE尚未映入kernel text，也没有常驻RWX alias；
* later patcher的临时alias/patch/synchronization不能倒写为 ``poking_init`` 已经执行；
* ftrace location records、enabled infrastructure和actual trace recording是三种不同状态；
* empty/invalid locations或allocation failure会设置 ``ftrace_disabled``；build-disabled path可为stub；
* Maple node cache使用 ``SLAB_PANIC``，其failure语义与ftrace降级不同；
* ``tracer_alloc_buffers`` 的返回值在此call site未用于阻止 ``init_events``，失败状态不能写成必然
  建成完整global tracing；
* ordinary printk ring与 ``tracepoint_printk`` iterator/buffer不是同一对象；tracefs尚未mount。

scheduler与boot idle边界
-----------------------

* possible CPU的runqueue container存在不等于CPU online；初始化loop还将 ``rq->online`` 置0；
* root task group/default root domain不等于cgroupfs已挂载或SMP scheduling domains已建立；
* ``__sched_fork(0,current)`` 只重置scheduler state，不分配task/PID或创建child；
* ``init_task`` 是PID 0 ``swapper/0``，不是later PID 1 ``kernel_init``；
* ``init_idle`` 在task ``pi_lock`` 与rq lock下发布 ``rq->idle``、 ``rq->curr``、 ``on_rq`` 和
  ``on_cpu``，但不调用 ``schedule`` 或进入idle loop；
* ``scheduler_running=1`` 只表示scheduler core ready，不表示tick、full topology、AP或context switch
  已发生；
* return后的 ``WARN(!irqs_disabled())`` 与 ``local_irq_disable`` 属于本批出口，使第058章入口IF确定为0。

发现并修复
----------

#. 三章从历史6.12.95标签和百科式展开重写为fixed 7.2-rc1连续时间线，补齐统一章末四节。

#. 修正VFS early call：只建hash backing，不提前声称inode/dentry object caches已完成。
#. 补x86 trap的CPU entry、SEV-ES/FRED条件与不打开device IRQ边界。
#. 按7.2-rc1恢复 ``mm_core_init`` 的KHO、alloc-tag/page-ext/debug、完整handoff和tail顺序。
#. 将memblock ``memory - reserved``、buddy ownership、 ``totalram_pages`` 与保留metadata分开。
#. 将x86 vmalloc page-table preallocation、SLUB bootstrap和vmap-area publication分成三处边界。
#. 固定Maple cache的对象参数与 ``SLAB_PANIC`` failure，而不虚构user tree。
#. 固定text-poke专用mm、two-page address与PTE backing，不把机制准备写成已修改kernel text。
#. 恢复ftrace empty/failure disable、build stubs、early buffer failure与actual recording条件。
#. 按源码恢复scheduler class order、root objects、per-possible-CPU rq字段和scratch mask。
#. 固定 ``init_task`` lazy-TLB/kthread/idle publication的locks与字段，不把它写成PID 1或context switch。
#. 将 ``sched_init`` 后的IRQ sanity repair纳入057出口，保证058的IF继承值无歧义。
