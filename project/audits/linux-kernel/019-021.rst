  ``device_hardware_setup()`` 中；
* 固定默认machine USB关闭， ``usb_setup()`` 未建立USB worker或启动项；

* ``BootList`` 尚无固定AHCI硬盘项，BIOS drive map、MBR、GRUB与Linux均未进入。

整批控制流与交接
----------------

``第019章``
   ``block_setup → ahci_setup`` 探测固定SATA port 0并登记内建硬盘；随后完成
   ``device_hardware_setup`` 的相邻入口与第一次必要的 ``wait_threads``。出口应位于
   ``optionrom_setup()`` 前。

``第020章``
   ``optionrom_setup`` 部署、初始化并登记当前确实存在的普通ROM入口，同时必须把
   固定默认QEMU ROM集合与仅在显式附加设备时出现的条件ROM分开。出口应位于
   ``interactive_bootmenu()`` 前。

``第021章``
   ``interactive_bootmenu → wait_threads → prepareboot``；重点核验BCV执行、drive map、
   最终启动序列、内存收尾及checksum的真实先后。出口应位于
   ``make_bios_readonly()`` 前。

执行上下文与对象账本
--------------------

* 主控制流始终是BSP/MainThread；AHCI port和PS/2初始化可通过SeaBIOS协作线程在同一
  CPU上交错，并非并行vCPU执行；
* 本批分别追踪QEMU AHCI function/port/backend、SeaBIOS controller/port/``drive_s``、
  DMA结构、 ``BootList``、 ``IDMap``、BDA ``hdcount``、FDPT、最终 ``BEV[]`` 以及
  Option ROM低端驻留区；
* 已核定每份对象的分配zone、失败释放、持久化边界，以及 ``wait_threads`` 前后
  哪些结论才稳定；
* 已核定固定默认路径真实存在的ROM、bootorder优先级和启动菜单默认分支，避免把
  可配置分支写成固定事实。

已核定的整批成功路径
--------------------

``block_setup与AHCI``
   ``block_setup`` 的驱动入口顺序与原文一致，但“没有floppy/legacy ATA drive”不等于
   两个setup无状态变化： ``floppy_setup`` 仍发布INT 1Eh表并解除IRQ6屏蔽；
   ``ata_setup`` 的PCI class扫描不命中固定ICH9 AHCI，却仍写BDA disk-control byte并解除
   IRQ14屏蔽。QEMU q35默认 ``sata_enabled=true``，在00:1f.2创建 ``ich9-ahci``；实现固定
   ``ports=6``、 ``PI=0x3f``，用户固定硬盘由IDE index 0连接到AHCI port 0。

``AHCI线程与对象``
   SeaBIOS先建立共享low-memory bounce buffer，成功 ``pci_enable_membar(BAR5)`` 时就同步
   设置 ``pci->have_driver=1``，随后分配F-segment controller、置bus master、reset HBA并
   开启AE。PI六位使MainThread为六个port各分配temporary metadata/list/FIS/table并各建一
   个协作线程；port 0完成link、ready、IDENTIFY与条件SET FEATURES，ports 1—5在10 ms
   link deadline后释放temporary对象。固定驱动用轮询和 ``yield``，没有开启AHCI port IRQ。

``AHCI持久化与失败边界``
   成功port不是把temporary DMA内容原样搬走： ``ahci_port_realloc`` 先把metadata复制到
   F-segment，停engine并释放旧list/FIS/table，再从ZoneHigh重新分配三块buffer、重写
   CLB/FB并重启FRE/ST；任一persistent分配失败就释放新对象，不登记drive。只有realloc
   成功才 ``boot_add_hd``。失败port由 ``ahci_port_release`` 停engine并释放temporary对象。

``第一次wait_threads``
   ``block_setup`` 返回只代表扫描入口已发起；MainThread还执行 ``lpt_setup``、
   ``serial_setup``、 ``cbfs_payload_setup``。固定 ``threads_during_optionroms=false`` 路径在
   ``device_hardware_setup`` 返回后立即 ``wait_threads``，这个barrier才证明六个AHCI port
   worker与PS/2 worker全部退出、port 0 drive和BootList条目稳定。AHCI ``have_driver`` 则
   早在BAR5 helper成功时已经同步置位，不能把它误归因于barrier。

``BootList初始优先级``
   QEMU PC默认boot order为 ``cad``；CMOS使SeaBIOS ``DefaultHDPrio=101``、floppy=102、
   CD=103，未列出的BEV保持9999。没有per-device ``bootindex`` 时，port 0 ATA路径查找
   fw_cfg ``bootorder`` 返回-1， ``boot_add_hd`` 因而给固定硬盘priority 101。此时只登记
   ``drive_s`` 指针，尚未写 ``IDMap`` 或BDA ``hdcount``。

``普通Option ROM固定结果``
   沿用第017—018章的无设备override默认基线，QEMU q35还自动创建默认e1000e；其class
   指定 ``efi-e1000e.rom``。固定blob的git object是
   ``1f9e0e9dd8d4a0a2fdcfb74fcd8fe0c73d22018e``，SHA-256是
   ``102c20348be2d0ebe45a77b076b31848182c2f7b4364775b6bc2ece6e97b4024``；首幅image是
   vendor/device 8086:10d3、code type 0， ``$PnP`` header的BCV为0、BEV为0x0385，后接
   code type 3的EFI image。标准VGA按class跳过，ICH9 AHCI按 ``have_driver`` 跳过；e1000e
   没有SeaBIOS内建driver，故默认 ``RunPCIroms=2`` 路径映射其ROM BAR、选择x86 image、
   校验并复制、调用PnP init，第二遍登记priority 9999的iPXE BEV。固定无TPM使measurement
   helper无状态变化；没有显式standalone option ROM时 ``genroms/`` 为空。

``ROM边界``
   checksum始终计算；默认 ``EnforceChecksum=1`` 才使坏checksum成为拒绝条件。PnP ROM
   在部署时调用标准init vector；无PnP header的legacy ROM不在部署时调用，而在第二遍
   被登记为offset 3的BCV。 ``init_pcirom`` 只会为来自PCI ROM BAR的非VGA PnP ROM在
   “本次新捕获INT 19h”时恢复官方vector；不能概括成所有ROM都禁止修改INT 19h。

``菜单、第二次barrier与prepareboot``
   固定无输入主线显示默认ESC提示并在2500 ms后返回，不改变BootList。第一次barrier已使
   fixed ``have_threads=false``，所以菜单后的无条件 ``wait_threads`` 在当前路径不迭代；
   它仍覆盖 ``threads_during_optionroms=true`` 的配置分支。固定BootList随后按priority为
   AHCI HD(101)、e1000e BEV(9999)，没有BCV，因此 ``bcv_prepboot`` 当前不调用
   ``call_bcv``；BCV执行只属于附加legacy/storage ROM的条件路径。

``drive map与最终启动序列``
   ``bda_init`` 已把 ``hdcount`` 清零；固定只有一块硬盘， ``map_hd_drive`` 把port 0
   ``drive_s`` 写到 ``IDMap[EXTTYPE_HD][0]`` 并把 ``hdcount`` 增至1，再选择translation、
   写第一份EBDA FDPT及IVT 41h。 ``bcv_prepboot`` 不销毁或“转换”BootList，而是另行填充
   ``BEV[]``：当前依次为generic hard disk、iPXE BEV，最后再补一个没有drive map的generic
   floppy fallback；末尾补hard disk被 ``HaveHDBoot`` 去重。

``prepareboot收尾``
   固定无TPM时 ``tpm_prepboot`` 的命令、log与separator helper均无状态变化；无CD时
   ``cdrom_prepboot`` 因 ``CDCount=0`` 返回。 ``pmm_prepboot`` 清PMM signature/entry；
   ``malloc_prepboot`` 清未用ROM/F-segment区、保留低端区并归还未用ZoneHigh页；
   ``e820_prepboot`` 只 ``dump_map``，源码没有“冻结开关”。随后 ``HaveRunPost=2``，并从
   ``BiosChecksum`` 减去当前64 KiB BIOS segment checksum。出口严格停在
   ``make_bios_readonly()`` 调用前。

审查问题闭合
------------

* ``block_setup`` 的精确驱动扫描顺序、固定q35会命中的非AHCI入口及其否定依据；
* ICH9 AHCI ``PI``、port reset、IDENTIFY、DMA内存重分配和 ``boot_add_hd`` 的实际条件；
* ``have_driver`` 的设置时点与普通PCI ROM跳过条件；
* PnP/legacy ROM的部署、init、BCV/BEV登记和执行边界；
* ``interactive_bootmenu`` 默认无输入路径、第二次 ``wait_threads`` 的必要性；
* ``bcv_prepboot`` 对固定硬盘的映射顺序、 ``0x80`` 是否能在当前固定条件下唯一确定；
* ``prepareboot`` 后PMM、allocator、E820、 ``HaveRunPost`` 与BIOS checksum的精确状态。

上述问题均已由固定源码闭合，无剩余技术阻塞。

发现并修复
----------

第019章
   原文把“没有floppy/legacy ATA drive”写成对应setup近似空操作，漏掉IVT 1Eh、IRQ6、
   BDA disk-control byte和IRQ14变化；现已补齐。原文也只泛称implemented ports，本批由
   固定QEMU ``PI=0x3f`` 收紧为六个worker、port 0成功和ports 1—5 link-down。纠正
   ``have_driver`` 被 ``wait_threads`` 稳定的错误、AHCI使用中断的暗示、temporary DMA
   “搬到”persistent区的错误，以及SET FEATURES成功是登记前提的错误。章节出口现固定在
   第一次 ``wait_threads`` 返回后。

第020章
   原文把网络PXE全写成条件可能，遗漏无override q35默认e1000e。现从固定QEMU device
   class和ROM blob核定：首幅是8086:10d3 x86 image，PnP BCV=0、BEV=0x0385，后接EFI
   image；因此当前确定执行PnP init并登记priority 9999的iPXE BEV。纠正checksum只有
   enable时才检查、所有PnP ROM都统一恢复INT 19h、第一遍与第二遍职责混写等问题，并固定
   当前 ``genroms/`` 为空、BootList没有BCV。

第021章
   标题由“执行BCV”改为“处理BCV”，因为固定路径 ``call_bcv=0``。正文把无输入菜单与
   用户选择拆开，证明第二次 ``wait_threads`` 在当前配置不迭代。纠正BootList被转换/
   消耗、AHCI translation读取QEMU CMOS、E820由 ``e820_prepboot`` 冻结等错误；固定
   ``IDMap[HD][0]``、BDA ``hdcount=1``、IVT 41h，并精确列出最终
   ``BEV[0]=hard disk``、 ``BEV[1]=iPXE``、 ``BEV[2]=floppy fallback``。

三章
   原有“第十九/二十/二十一章结束时的机器状态”已统一改为合同要求的
   ``本章结束状态 → 关键边界 → 下一入口 → 资料``。资料从文件级泛链收紧到固定commit
   行锚；QEMU组合ROM本身保留固定blob链接。

连续性检查
----------

``018 → 019``
   第018章停在 ``ps2port_setup`` 返回、即将调用 ``block_setup``；第019章从同一语句
   进入，继承“PS/2 worker可能尚未完成”，并只在 ``device_hardware_setup`` 返回后的
   第一次 ``wait_threads`` 宣告worker全退出。

``019 → 020``
   第019章停在第一次barrier返回、下一条 ``optionrom_setup``；第020章从同一调用开始。
   AHCI ``have_driver=1``、固定hard-disk BootList项和 ``IDMap`` 仍空的三份状态无断裂。

``020 → 021``
   第020章停在 ``interactive_bootmenu`` 前，BootList精确为AHCI HD与iPXE BEV；
   第021章从菜单默认无输入分支开始，保持相同顺序后进入 ``prepareboot``。

``021 → 022``
   第021章停在 ``prepareboot`` 返回、 ``make_bios_readonly`` 尚未调用；第022章既有开头
   从相同三条调用继续。第022章把E820称为“frozen”的措辞尚未按合同审查，已登记给下一批
   修复；它不改变当前调用入口。
