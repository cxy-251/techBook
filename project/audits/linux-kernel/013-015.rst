批次开始状态
------------

当前执行者是BSP上的SeaBIOS ``MainThread``，CPU仍处于32位保护模式，分页关闭、
A20开启、IF=0，CMOS NMI保持屏蔽。PIC只放行master IRQ2与slave IRQ13。
``PCIDevices``、 ``MaxCountCPUs``、 ``FoundAPICIDs`` 和条件建立的MSR重放前缀已经
存在；固定条件未规定 ``-smp``，所以无override时只有BSP，显式多CPU时才有AP已经
执行 ``entry_smp`` 并停在IF=0的HLT循环。

证据账本
--------

PIR与MP总门
   ``qemu_platform_setup()`` 只在 ``MaxCountCPUs <= 255`` 时连续调用
   ``pirtable_setup()`` 与 ``mptable_setup()``。两个函数还分别受默认开启的
   ``CONFIG_PIRTABLE``、 ``CONFIG_MPTABLE`` 控制；内存分配、校验或600字节FSEG复制
   上限失败时，对应兼容表可以缺席，不能把调用扩大成必然安装成功。

PIR表语义
   SeaBIOS构造的是一份静态六slot、四link的PCI IRQ Routing Table：router
   devfn为 ``0x08``，compatible device为 ``8086:122e``，slot devfn覆盖
   1—6，link在 ``0x60``—``0x63`` 间轮转，IRQ bitmap为 ``0xdef8``。它是历史
   PCI BIOS兼容接口，不是当前q35 ICH9 LPC真实BDF、PIRQA—H寄存器或ACPI ``_PRT``
   的权威镜像。

MP CPU与中断项
   临时MP表从32 KiB ``ZoneTmp`` 构造，但 ``copy_mptable()`` 最多复制600字节到
   FSEG。CPU循环按CPUID推导的 ``pkgcpus`` 跨度遍历 ``0..MaxCountCPUs-1``，每个
   package只写首个logical ID； ``apic_id_is_present(i)`` 决定enabled位，ID 0另带
   BSP位。固定条件没有指定CPU模型或 ``-smp``，不能把AP存在、package跨度或表项数
   唯一化。

   MP表按当前 ``PCIDevices`` 为bus 0 PCI INTx创建去重项，并把先前已写入的
   ``PCI_INTERRUPT_LINE`` 用作destination input；ISA源跳过 ``BUILD_PCI_IRQS`` 的
   5、9、10、11，并按QEMU fw_cfg给出的IRQ0 override条件把timer改接IOAPIC input 2。
   最后还有BSP LINT0的ExtINT与所有APIC LINT1的NMI项。MP表只描述兼容发现数据，不
   重新配置已经建立的IOAPIC、PIC或LAPIC状态。

SMBIOS当前与回退路径
   固定QEMU最新q35默认 ``smbios_defaults=true``、入口类型 ``AUTO``。QEMU先尝试
   生成SMBIOS 2.x；只有表长、结构数等不能满足2.x约束时才改试3.x，然后把
   ``etc/smbios/smbios-tables`` 与 ``etc/smbios/smbios-anchor`` 发布给fw_cfg。
   SeaBIOS同时取得两文件且anchor签名/长度正确时，复制QEMU结构、仅在缺少Type 0时
   前置自己的Type 0，修补运行时表地址、长度与校验和并安装入口。

   若romfile输入缺失或无效， ``smbios_setup()`` 才进入SeaBIOS legacy构造器。该路径
   用 ``MaxCountCPUs`` 创建Type 4并按RAM布局创建Type 16/17/19/20等结构；它不能冒充
   固定QEMU正常fw_cfg路径的实际表内容。

table-loader错误模型
   ``romfile_loader_execute()`` 只把loader文件缺失、命令blob长度不是固定entry大小
   整数倍、或files数组分配失败作为函数级 ``-1``。逐项的ALLOCATE、ADD_POINTER、
   ADD_CHECKSUM和WRITE_POINTER失败只告警或跳过，循环仍继续，函数最终仍可能返回0；
   未知命令也被静默跳过。因此返回0只表示命令流被遍历，不是所有表都链接成功。

   ALLOCATE只接受HIGH/FSEG，非零alignment必须是2的幂；ADD_POINTER把源blob运行时
   基址加进目标字段；
   ADD_CHECKSUM从目标字节减去给定范围的8位和；WRITE_POINTER经fw_cfg DMA把已分配源
   地址回写宿主文件并登记resume重放项。已分配blob留在相应SeaBIOS zone，临时命令
   blob和files索引在函数返回前释放。

RSDP搜索与分支
   loader返回后SeaBIOS无条件扫描 ``ZoneFSeg``，从16字节对齐地址检查RSDP签名、
   20字节校验和；revision大于1时还按 ``length`` 检查扩展校验和。搜索成功与
   ``loader_err`` 并不等价：即使loader返回 ``-1``，只要FSEG里已有有效RSDP也会
   进入解析；反之loader返回0但找不到RSDP会告警。

ACPI表图与DSDT解析
   ``find_acpi_table()`` 优先遍历4 GiB以下的XSDT，再回退RSDT，只以root与目标表
   signature筛选，不在此重新验证root/目标校验和。 ``acpi_dsdt_parse()`` 只查FADT、
   读取其32位 ``dsdt`` 字段，再从offset ``0x24`` 开始解析受限AML子集；它不是完整
   AML解释器，也不是当前遍历MADT、MCFG等所有表的控制流。

   随后的 ``virtio_mmio_setup_acpi()`` 只消费解析缓存中HID ``LNRO0005`` 且同时有
   memory与IRQ resource的device；固定q35 PCI设备并不因此变成virtio-mmio设备。
   若未找到RSDP，当前SeaBIOS的 ``acpi_setup()`` 只报告QEMU 1.6及更旧ACPI表已不再
   支持，不再生成一套内建兼容表。

整批控制流与交接
----------------

``第013章``
   ``if (MaxCountCPUs <= 255) → pirtable_setup() → mptable_setup()``，随后无条件进入
   ``smbios_setup()``。PIR是静态legacy模板；MP表从 ``PCIDevices``、present APIC-ID
   与CPUID package跨度构造；SMBIOS先消费QEMU正常romfile输入，只有失败才进入SeaBIOS
   legacy构造器。章节停在ACPI loader调用之前。

``第014章``
   ``romfile_loader_execute("etc/table-loader")`` 按128字节entry分配HIGH/FSEG blob、
   重定位pointer、修checksum并条件回写fw_cfg。函数级返回不汇总逐命令失败。随后无条件
   ``RsdpAddr = find_acpi_rsdp()``，在FSEG按16字节搜索并校验RSDP；章节停在
   ``if (RsdpAddr)`` 前，保留found/not-found两个出口。

``第015章``
   found分支执行 ``acpi_dsdt_parse() → find_acpi_table(FACP)``，XSDT优先、RSDT回退，
   再从FADT 32位 ``dsdt`` 进入受限AML设备缓存，随后条件探测 ``LNRO0005``
   virtio-mmio并直接return。not-found分支只条件告警，再调用已经退化为提示的
   ``acpi_setup()``。两个出口都结束 ``qemu_platform_setup()``。

执行上下文与对象账本
--------------------

* BSP的 ``MainThread`` 是三章平台主控制流；CPU一直处于32位保护模式，分页关闭、
  A20开启、IF=0，CMOS NMI屏蔽。只有显式ACPI ``LNRO0005`` virtio-blk/scsi命中时，
  第015章的 ``run_thread()`` 才可能创建并切入初始化worker；固定AHCI磁盘不命中。
* 固定条件未规定 ``-smp``。缺省只有BSP；显式多CPU时在场AP从上一章起停在IF=0的
  HLT循环。本批没有唤醒或释放AP，也没有改写 ``MaxCountCPUs``。
* PIR与MP最终对象在FSEG；构造或复制失败时可以缺席。MP的32 KiB临时buffer在
  ``mptable_setup()`` 返回前释放。
* SMBIOS的QEMU输入buffer与SeaBIOS扫描buffer是临时对象；最终structure blob在FSEG或
  HIGH、入口在FSEG。legacy结构只存在于romfile失败分支。
* table-loader command blob与files索引在执行器返回前释放；成功ALLOCATE的ACPI blob
  留在HIGH/FSEG，WRITE_POINTER resume项条件保留在全局list。
* ``RsdpAddr`` 是FSEG入口的全局发现pointer； ``acpi_devices`` 保存指回DSDT blob的
  有限摘要。完整ACPI表图与SeaBIOS解析缓存是不同消费者、不同对象集合。
* PIC mask、local APIC/LINT状态、ICH9 IRQ路由、RAM布局与 ``PCIDevices`` 在本批保持。

发现并修复
----------

第013章
   原文把AP已经执行、重放MSR并停驻写成无条件事实，现已继承第012章的缺省单CPU与
   显式多CPU分支。PIR的静态 ``00:01.0``/四link模板已与q35 ICH9真实路由及ACPI
   ``_PRT`` 分层；MP的package跨度、present enabled位、bus 0去重、IRQ0 override与
   600字节复制上限均按固定源码重建。SMBIOS也从“混合QEMU与legacy内容”改为q35
   ``AUTO`` 先试2.x、失败试3.x，SeaBIOS romfile失败才进入legacy 2.4。

第014章
   原文近似把loader返回0写成所有command成功，现已证明只有文件缺失、blob长度错误
   与索引分配失败进入函数级 ``-1``；ALLOCATE、ADD_POINTER、ADD_CHECKSUM、
   WRITE_POINTER均可能软失败后继续，未知command也静默跳过。RSDP搜索改为与
   ``loader_err`` 正交，章节出口不再伪装成必然found。

第015章
   原文把MADT、MCFG、FADT、DSDT内容总览写成当前SeaBIOS遍历流程，现已收敛到真实的
   ``find_acpi_table(FACP)`` 与32位 ``dsdt`` 入口，并逐项列出当前函数没有执行的
   checksum/length验证。AML范围收紧到设备摘要与有限 ``_CRS``， ``_PRT`` 不再冒充
   已被解释。最重要的事实修复是：当前 ``acpi_setup()`` 不生成旧兼容表，只打印
   QEMU 1.6及更旧表不再支持。

三章
   原有“第十三/十四/十五章结束时的机器状态”与散落预告已统一成合同要求的
   ``本章结束状态 → 关键边界 → 下一入口 → 资料``，并给每章建立单一精确终点。

连续性检查

``012 → 013``

   ``if (MaxCountCPUs <= 255)`` 开始，并保留未固定 ``-smp`` 的状态分支。

   ``romfile_loader_execute("etc/table-loader")``；第014章从同一调用进入，不重复
   SMBIOS或提前搜索RSDP。

``014 → 015``
   第014章在 ``RsdpAddr = find_acpi_rsdp()`` 返回后结束；第015章从紧邻的
   ``if (RsdpAddr)`` 开始，同时闭合found与not-found，不用loader返回值替代搜索结果。

``015 → 016``
   第015章的found显式return与not-found ``acpi_setup()`` 返回都结束
   ``qemu_platform_setup()``。第016章既有开头正确回到 ``platform_hardware_setup()``，
   依次列出 ``coreboot_platform_setup()``、 ``timer_setup()``、 ``clock_setup()`` 与
   ``tpm_setup()``；相邻边界无需改正文。
