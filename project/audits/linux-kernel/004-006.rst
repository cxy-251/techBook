批次开始状态
------------

控制权刚由 ``reloc_preinit()`` 交给搬迁后的 ``maininit()``。当前执行者是BSP上的
SeaBIOS 32位平坦C代码；保护模式已开启，分页关闭，可屏蔽中断关闭。早期栈顶最初
设为 ``0x7000``，经过第003章的C调用后当前 ``ESP`` 在其下方，不能固定成
``0x7000``。低地址BIOS shadow可写， ``HaveRunPost=1``，初始E820、malloc临时区和
E820保留的 ``ZoneHigh`` 已存在；GRUB与Linux尚未装入。

整批控制流与交接
----------------

``第004章``
   ``maininit() → interface_init() → malloc_init() → qemu_cfg_init() →
   coreboot_cbfs_init() → multiboot_init() → ivt_init() → bda_init()``。
   默认QEMU构建中后两个文件来源初始化分别因 ``CONFIG_COREBOOT_FLASH=n`` 与
   ``CONFIG_MULTIBOOT=n`` 返回。结束点在 ``boot_init()`` 之前。

``第005章``
   ``boot_init() → bios32_init() → pmm_init() → pnp_init() → kbd_init() →
   mouse_init() → interface_init() return``。结束点回到 ``maininit()``，
   ``platform_hardware_setup()`` 尚未执行。

``第006章``
   ``platform_hardware_setup() → dma_setup() → pic_setup() → thread_setup() →
   mathcp_setup()``。结束点在 ``qemu_platform_setup()`` 之前，与第007章入口一致。

执行上下文与对象账本
--------------------

* 三章主控制流始终由BSP在32位保护模式、分页关闭的POST上下文执行；没有操作系统线程、
  内核锁或多CPU并发参与。
* 第004章建立最终VARLOW副本、 ``ZoneLow``、 ``ZoneFSeg``、romfile目录、IVT、BDA、
  初始EBDA和 ``ExtraStack/StackPos``。默认 ``CONFIG_MALLOC_UPPERMEMORY=y`` 时初始
  EBDA为 ``0x9fc00-0x9ffff``，BDA传统内存计数为639 KiB。
* 第005章建立排序策略和可扫描服务头；没有发现具体启动设备。BIOS32的 ``$PCI``
  入口存在，但 ``MaxPCIBus`` 与 ``PirAddr`` 要到后续PCI平台初始化才成为最终状态。
* 第006章重置传统DMA状态，设置8259A向量与掩码，读取线程策略并初始化16/32位
  转换状态，再解除IRQ13并把其IVT项改为 ``entry_75``；静态 ``MainThread`` 仍是
  链表中的唯一线程。
* ``thread_setup()`` 之后 ``check_irqs()`` 才允许在明确位置短暂执行
  ``sti … cli``；主控制流的IF不会因此长期保持为1。本章没有调用 ``run_thread()``，
  所以没有设备线程、线程栈或调度并发产生。

默认配置与成功路径
------------------

固定提交的默认QEMU配置使 ``RELOCATE_INIT``、 ``MALLOC_UPPERMEMORY``、
``ENTRY_EXTRASTACK``、 ``BOOT``、 ``BOOTORDER``、 ``PCIBIOS``、 ``OPTIONROMS``、
``PMM``、 ``PNPBIOS``、 ``KEYBOARD``、 ``MOUSE``、 ``HARDWARE_IRQ``、 ``RTC_TIMER``
和 ``THREADS`` 为 ``y``。正文只把这条默认成功路径写成当前事实；配置关闭时函数可能
返回，不能沿用对应结果。

``qemu_cfg_init()`` 为目录项分配 ``qemu_romfile_s``；单项分配失败时会警告并跳过该项，
不是回滚整个目录。 ``bootorder``、 ``bios-geometry`` 和多个 ``etc/*`` 文件可以不存在，
源码已有缺省或空列表路径。PMM分配失败返回0；本批只建立入口，没有实际PMM请求。

发现并修复
----------

第004章
   开头把初始栈顶写成当前栈位置；已改成当前 ``ESP`` 位于 ``0x7000`` 以下。原文还
   没有交代默认QEMU路径中 ``coreboot_cbfs_init()``、 ``multiboot_init()`` 的返回，
   并遗漏 ``ivt_init()`` 安装INT 02h/05h/40h以及把INT 60h—66h、79h明确清零的边界；
   均已补入正文和章末状态。

第005章
   原文列出静态初值101/102/103/104后笼统说QEMU CMOS“重写默认值”。当前QEMU分支
   实际先把四类都设为9999，再只读取三个nibble并分配101—103；未出现的类别保持
   9999，BEV不能在当前分支无条件保留104。已修正该状态，并明确BIOS32入口已发布
   不等于PCI设备、 ``MaxPCIBus`` 或PIR表已经准备好。

第006章
   原标题声称已经“启动内部线程”，但本章没有调用 ``run_thread()``；已改为“准备内部
   线程”。同时把DMA/PIC重写描述为SeaBIOS主动建立的已知状态，不把设计上的防残留
   理由冒充固定冷启动入口事实；把 ``call16_override(1)`` 精确为清零
   ``Call16Data`` 并为下一次16/32位转换设置 ``C16_BIG`` 与A20保持状态；明确
   ``ThreadControl=2`` 的RTC辅助执行尚未启动。

连续性检查
----------

``003 → 004``
   第003章停在重定位后的 ``maininit()``；第004章从其第一条调用
   ``interface_init()`` 开始。

``004 → 005``
   第004章停在 ``bda_init()`` 返回；第005章从 ``interface_init()`` 的下一条调用
   ``boot_init()`` 开始。

``005 → 006``
   第005章停在 ``interface_init()`` 返回后的 ``maininit()``；第006章从下一条
   ``platform_hardware_setup() → dma_setup()`` 开始。

``006 → 007``
   第006章停在 ``mathcp_setup()`` 返回；第007章从
   ``platform_hardware_setup()`` 的下一条调用 ``qemu_platform_setup()`` 开始，并先
   处理普通QEMU/Xen分支与条件性的 ``kvmclock_init()``。
