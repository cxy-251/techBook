CMA、crashkernel、xDBC与KASAN边界
--------------------------------

* ``max_pfn_mapped<<PAGE_SHIFT`` 是global CMA default limit，不覆盖explicit ``cma=`` limit或
  per-NUMA CMA声明；
* CMA call存在不等于area存在，size 0、已有default、declare failure与success须分开；
* crashkernel确实位于NUMA后以避开hotpluggable memory，但fixed GRUB原始line无option不排除未知
  builtin line；
* xDBC setup stub/未定位DbC返回error，只有hardware setup成功且没有existing early console才register；
* native x86-64 paging hook不重建direct map，只清default node-state bits；
* KASAN遍历 ``pfn_mapped[]``，其中含ISA compatibility mapping与memblock RAM，不能缩写为free RAM；
* KASAN施工root是刚从 ``init_top_pgt`` 复制的 ``early_top_pgt``，最终active CR3回到
  ``init_top_pgt``；
* x86-64 ``sync_initial_page_table`` 是inline no-op。

tboot、vsyscall、quirk与capacity边界
-----------------------------------

* fixed GRUB zeroed params没有tboot writer， ``tboot_addr=0`` guard确定返回；
* nonzero branch给 ``e820__mapped_any`` 传相同start/end，按overlap predicates只可能命中entry严格
  内部point，不验证整页、alignment或UUID；
* fixed build启用vsyscall emulation framework时default只能XONLY/NONE，EMULATE来自early option；
* EMULATE建立PTE与upper user bits，XONLY刻意无PTE、只保留execute gate，NONE无gate；
* x86-64的 ``x86_32_probe_apic`` 无工作，Local APIC fixmap不能记到047；
* ``early_quirks`` 只扫描fixed table的direct-PCI matches，不是完整PCI enumeration；
* q35 core IDs不自动命中实体机quirks，optional devices未固定；
* topology early limit在firmware enumeration前只收紧capacity；positive ``maxcpus=N`` 不在该函数中
  把possible capacity缩为N， ``maxcpus=0``/``nosmp`` 才强制1。

ACPI、APIC、topology与IOAPIC边界
-------------------------------

* 045只登记LAPIC physical address；048 full MADT才首次遍历Local APIC/x2APIC processor records；
* FADT x86 handler落实legacy/i8042/RTC/VGA/PM timer，SCI route在MADT IOAPIC pass使用canonical FADT；
* full MADT按processor/local NMI → IOAPIC → source override → SCI fallback → legacy identity → NMI
  source有序处理；
* ACPI enabled却无MADT会清先前MPS discovery，纯MPS takeover需要明确ACPI-disabled path；
* full MP parser在ACPI LAPIC+IOAPIC齐全时返回，ACPI LAPIC-only时不重复processor records；
* successful non-x2APIC LAPIC fixmap通常由045 ``register_lapic_address`` 建立，048只完成last check；
* ``topology_init_possible_cpus`` 才把firmware registry与capacity变成possible/present masks；online仍仅
  CPU0；
* SRAT affinity在045保存，048 logical IDs明确后才由 ``init_cpu_to_node`` 接回；
* ``io_apic_init_mappings`` 分配resource objects并映射fixmaps，不插入resource tree、不编程runtime
  vectors；IOAPIC resource insertion实际在later PCI survey的 ``ioapic_insert_resources``；
* QEMU accelerator未固定，guest late hook不能写死KVM或native no-op。

* 本批没有普通PCI enumeration/BAR assignment、final clocksource selection或ACPI namespace/AML；
