批次开始状态
------------

第066章结束时，CPU0上的 ``start_kernel()`` 仍由 ``init_task`` 执行，处于x86-64长模式、
CPL0，RFLAGS.IF为1。只有CPU0在线且活动，PID 1、PID 2、应用处理器和普通工作线程均尚未

第067章源码证据
---------------

CPU集合根对象
   ``cpuset_init()`` 只在 ``CONFIG_CPUSETS`` 启用时执行实质工作。它为顶层
   ``cpuset`` 分配允许、有效、独占、子分区和隔离CPU掩码，把顶层CPU与内存节点范围设为全集，
   再按启动期housekeeping配置计算隔离CPU。分配失败由 ``BUG_ON()`` 停止当前路径；调度域要等
   后续 ``cpuset_init_smp()`` 才建立。

内存控制组前置对象
   ``mem_cgroup_init()`` 只在 ``CONFIG_MEMCG`` 启用时建立CPU热插拔回调、 ``memcg`` 工作队列、
   每个可能CPU的库存排空工作项，以及 ``mem_cgroup`` 与逐节点缓存。工作队列分配失败只触发
   ``WARN_ON()``，两个对象缓存则带有 ``SLAB_PANIC``。根内存控制组不在这里建立，而由紧接着的
   ``cgroup_init()`` 初始化。

控制组核心
   ``cgroup_init()`` 只在 ``CONFIG_CGROUPS`` 启用时完成默认根、初始
   ``css_set``、各控制器状态与文件项的连接，然后创建 ``/sys/fs/cgroup`` 挂载点对象，登记
   cgroup v1、cgroup v2和可选cpuset文件系统，并按条件创建 ``/proc/cgroups``。此时只是登记
   文件系统和入口，没有挂载cgroupfs；控制组专用工作队列也要等后续初始化调用。

统计与延迟记账
   ``taskstats_init_early()`` 按 ``CONFIG_TASKSTATS`` 创建对象缓存并初始化每个可能CPU的监听
   列表与读写信号量；Generic Netlink族要等后续 ``taskstats_init()`` 才登记。
   ``delayacct_init()`` 按 ``CONFIG_TASK_DELAY_ACCT`` 创建延迟信息缓存、为 ``init_task``
   建立状态，并依据 ``delayacct_on`` 设置静态键；没有 ``delayacct`` 启动参数时不能把该入口
   写成必然启用采集。

ACPI、x86修正与KCSAN
   ``acpi_subsystem_init()`` 在ACPI可用时以 ``~ACPI_NO_ACPI_ENABLE`` 调用ACPICA。该位掩码
   只允许切换ACPI模式，跳过FACS、事件和SCI/全局锁处理器初始化；失败会记录错误并禁用ACPI，
   成功才通知regulator核心固件约束完整。x86的 ``arch_post_acpi_subsys_init()`` 只在启动CPU
   带有 ``X86_BUG_AMD_E400`` 且MSR确认C1E活动时设置修正，并按能力标记TSC不稳定或要求时钟
   广播。 ``kcsan_init()`` 按 ``CONFIG_KCSAN`` 为每个可能CPU播种随机状态，仅在
   ``kcsan_early_enable`` 为真时打开检测。

第068章源码证据
---------------

RCU阶段转换
   ``rcu_scheduler_starting()`` 要求当前仍只有一个在线CPU且尚未发生上下文切换，修正RCU树的
   宽限期序号并把 ``rcu_scheduler_active`` 设为 ``RCU_SCHEDULER_INIT``。此后同步宽限期原语
   采用由请求任务推动的加速路径；完整运行期RCU仍要等后续 ``rcu_set_runtime_mode()``。

PID 1与暂时亲和性
   ``user_mode_thread(kernel_init, NULL, CLONE_FS)`` 通过 ``kernel_clone()`` 与
   ``copy_process()`` 分配第一个动态PID，并在返回前唤醒新任务，因此持续启动路径得到PID 1。
   PID 0随后在RCU读侧区间找到该任务，设置 ``PF_NO_SETAFFINITY`` 并把允许CPU固定为当前CPU0，
   防止SMP调度域建立前迁移。源码没有检查创建函数的负返回值；继续执行依赖创建成功这一启动
   不变量，不能虚构恢复分支。

PID 2与完成量
   PID 0先用 ``numa_default_policy()`` 把自身的启动期交错内存策略恢复为
   ``MPOL_DEFAULT``，再以 ``CLONE_FS | CLONE_FILES`` 创建真正的内核线程
   ``kthreadd``。 ``kernel_thread()`` 还加入 ``CLONE_VM | CLONE_UNTRACED`` 并设置内核线程
   标志。持续路径得到PID 2，PID 0发布 ``kthreadd_task``，把 ``system_state`` 推进到
   ``SYSTEM_SCHEDULING``，再完成 ``kthreadd_done``。PID 1即使提前获得CPU，也会在
   ``kernel_init()`` 的该完成量上等待；PID 2何时首次运行则由调度决定。

PID 0退出启动主线
   ``schedule_preempt_disabled()`` 暂时允许抢占并执行第一次显式调度，返回时再次禁止抢占。
   源码没有规定PID 1和PID 2谁先运行。PID 0随后进入
   ``cpu_startup_entry(CPUHP_ONLINE)``，设置 ``PF_IDLE``、完成CPU热插拔空闲状态，并永久循环
   ``do_idle()``；需要重新调度时，空闲循环执行 ``schedule_idle()``。 ``rest_init()`` 不会
   返回 ``start_kernel()``。

第069章源码证据
---------------

PID 1开放后续初始化条件
   PID 1越过 ``kthreadd_done`` 后进入 ``kernel_init_freeable()``。它把
   ``gfp_allowed_mask`` 从启动期限制恢复为 ``__GFP_BITS_MASK``，使后续分配可以请求回收、
   I/O和文件系统路径；再把当前任务的 ``mems_allowed`` 设为所有有内存节点，并为
   ``cad_pid`` 取得PID 1的引用。这些操作不表示具体分配必然成功，也不表示磁盘根已经可用。

处理器准备与工作线程
   x86的 ``smp_prepare_cpus()`` 先为可能CPU建立拓扑掩码和CPU0兄弟关系，再按最终APIC中断模式
   决定禁用SMP或准备逐CPU时钟事件、启动延时和平台唤醒入口；它尚未发送应用处理器启动请求。
   ``workqueue_init()`` 随后创建释放工作队列对象所需的专用线程，为所有可能CPU建立底半部
   伪工作线程，为当时在线CPU和无绑定池建立首批真正工作线程，并把工作队列核心标为在线。
   早期救援线程创建失败只警告，关键工作线程创建失败则由 ``BUG_ON()`` 停止当前路径。

内存统计与早期初始化调用
   ``init_mm_internals()`` 建立逐CPU内存管理工作队列，按SMP配置登记VM统计热插拔状态、初始化
   节点状态并启动汇总定时器，按procfs配置创建内存统计入口与系统控制项；热插拔状态登记失败
   只记录错误，工作队列分配结果则没有在本函数内检查。 ``do_pre_smp_initcalls()`` 只执行链接区间
   ``__initcall_start`` 到 ``__initcall0_start`` 之前的 ``early_initcall()``；0级纯初始化
   调用从后一个边界才开始。锁死检测器再按配置和housekeeping计时器掩码探测并设置；探测失败
   可能保留稍后重试，而不是保证每个CPU已有看门狗线程。

应用处理器与SMP调度器
   启用 ``CONFIG_SMP`` 时， ``smp_init()`` 先建立空闲线程与CPU热插拔线程，再按
   ``setup_max_cpus`` 尝试并行或串行推进非启动CPU的热插拔状态。x86唤醒路径验证APIC ID、
   准备空闲任务与跳板，然后选择平台提供的64位、通用APIC或INIT启动方法。应用处理器进入
   ``start_secondary()`` 后加载微码、与控制CPU同步，初始化CPU、FPU、RCU、时钟和TSC，
   只有在向量空间受锁保护时才发布在线状态，最后打开本地中断并进入自己的空闲循环。配置、
   ``maxcpus``、中断模式或唤醒错误都可能使部分或全部应用处理器保持离线。

   ``sched_init_smp()`` 根据最终 ``cpu_active_mask`` 建立NUMA与调度域，把当前PID 1迁移许可
   扩大到非隔离housekeeping CPU，清除 ``PF_NO_SETAFFINITY``，再完成调度粒度、实时类、截止
   期限类及其服务器初始化，并发布 ``sched_smp_initialized``。它不会把PID 1固定迁移到某个
   指定CPU。

拓扑消费者与页分配收尾
   ``workqueue_init_topology()`` 依据CPU、SMT、缓存、缓存分片和NUMA关系建立无绑定工作队列
   分组，并为已有工作队列逐在线CPU更新池连接。 ``async_init()`` 创建具有更高最小活跃数的
   专用无绑定工作队列，失败由 ``BUG_ON()`` 停止当前路径。 ``padata_init()`` 登记CPU热插拔
   多实例状态并为每个可能CPU分配工作对象；失败会撤销已登记状态并打印警告。

   ``page_alloc_init_late()`` 在启用延后 ``struct page`` 初始化时为每个内存节点启动线程并
   等待全部完成，然后关闭按需初始化分支并重算文件数限制。各次 ``kthread_run()`` 的返回值
   没有被检查，继续路径依赖每个节点线程都能启动并完成。无论该配置是否启用，该入口都会稳定
   内存统计、初始化缓冲区、丢弃memblock私有元数据、随机化空闲内存、标记连续zone，并按条件
   建立页扩展，最后登记页分配系统控制项。

发现并修复
----------

#. 三章旧正文普遍使用普通英文叙述、中英混杂短句和沿前章继续压缩的表达，章末状态节也不符合
   当前合同；已按每章独立源码边界重写为完整中文叙事，并统一章末四节。
#. 第067章把 ``cpuset_init()``、 ``mem_cgroup_init()`` 与 ``cgroup_init()`` 压缩成
   无条件成功链，并提前写入调度域、根内存控制组和控制组工作队列；已按配置、失败行为和当前
   对象边界拆开。
#. 第067章把 ``taskstats_init_early()`` 写成统计接口已经对外可用，把
   ``delayacct_init()`` 写成必然启用记账；已分别推迟Generic Netlink登记，并保留启动参数对
   静态键的控制。
#. 第067章把 ``acpi_subsystem_init()`` 写成ACPI事件与SCI处理器已经建立；已改为本入口只尝试
   切换ACPI模式，并保留失败后禁用ACPI的分支。
#. 第067章夸大 ``kcsan_init()`` 的对象分配范围；已改为逐CPU随机状态与按启动选择启用检测。
#. 第068章把RCU写成已经进入完整运行期；已区分 ``RCU_SCHEDULER_INIT`` 与稍后的完整运行模式。
#. 第068章没有处理两个任务创建结果未检查这一关键启动不变量，也把第一次调度写成固定选择；
   已保留失败边界和PID 1、PID 2并发次序的不确定性。
#. 第068章把 ``rest_init()`` 写成PID 0完成后返回；已明确PID 0永久进入空闲循环，而PID 1在
   完成量屏障后接续初始化主线。
#. 第069章把 ``smp_prepare_cpus()`` 写成已经唤醒应用处理器，把
   ``workqueue_init()`` 写成新建所有池；已区分准备、既有池、首批工作线程与正式唤醒阶段。
#. 第069章把 ``smp_init()`` 写成所有应用处理器必然上线；已保留SMP配置、APIC模式、
   ``setup_max_cpus``、并行启动选择和逐CPU失败结果。
#. 第069章把 ``sched_init_smp()`` 写成PID 1必然迁移，并把
   ``page_alloc_init_late()`` 泛化成内存分配器完成；已改为亲和范围、调度域和实际页分配收尾
   操作，同时补入逐节点线程创建结果未检查的启动不变量。

连续性
------

第066章出口的下一条语句是 ``cpuset_init()``，与第067章入口一致。第067章完成控制组、
记账、ACPI模式和KCSAN条件入口后，出口正好停在 ``rest_init()``。第068章由PID 0创建并发布
PID 1与PID 2，随后PID 0进入永久空闲循环；初始化主线由越过 ``kthreadd_done`` 的PID 1接到
``kernel_init_freeable()``。第069章完成应用处理器、工作线程、SMP调度域和页分配晚期收尾，
其下一条语句是第070章开头的 ``do_basic_setup()``。
