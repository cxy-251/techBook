本批新增的磁盘内容约定
----------------------

固定源码和平台条件没有附带磁盘artifact，不能仅凭commit推导GRUB配置文件名以外的内容、
kernel artifact名称或initramfs名称。本批把唯一成功叙事补齐为显式镜像约定：

.. code-block:: cfg

   set timeout=0
   set default=0

   menuentry 'Linux 7.2-rc1' {
       linux /boot/bzImage root=/dev/sda1 ro console=ttyS0
       initrd /boot/initramfs.img
   }

``/boot/bzImage`` 固定为 Linux 7.2-rc1、commit
``7404ce51637231382873d0b55edabc2f3b841a9d`` 构建结果，initramfs与该场景匹配。
路径和配置内容是镜像约定，不冒充GRUB或Linux源码默认值；实际inode、extent和数据LBA仍不制造数值。

已核定的控制流
--------------

``第028章``
   ``grub_load_normal_mode → grub_dl_load(normal) miss → prefix/i386-pc/normal.mod →
   file/device/biosdisk → part_msdos → ext2 → 完整读取并关闭module file →
   ELF依赖/section/relocation/init → normal command → read_lists →
   read_config_file → menu容器 → grub.cfg raw file + bufio → 读入第一条可解析行``。

``第029章``
   ``grub_normal_parse_line → parse/execute/unref(set timeout) →
   parse/execute/unref(set default) → 多行menuentry parser callback →
   grub_cmd_menuentry → setparams prefix + block source复制 →
   grub_normal_add_menu_entry → EOF → 恢复config变量 → 关闭bufio/raw file →
   menu返回grub_normal_execute``。

``第030章``
   ``grub_show_menu → run_menu(default=0,timeout=0 fast path) →
   execute_with_fallback → restricted auth short-circuit → chosen发布/default暂时unset →
   execute_new_scope → setparams → linux dynamic placeholder →
   grub_dl_load(linux.mod) → 完整读取并关闭file → ELF依赖/重定位/init →
   注册真实linux/initrd → ref module → 注销placeholder → 重新查找真实linux``。

关键对象与生命期
----------------

* ``normal.mod`` 是第028章首次实际文件系统访问的目标；四份 ``*.lst`` 和 ``grub.cfg`` 都在
  normal装载/init之后，不能再把list文件称为GRUB第一次磁盘访问；
* ``grub_dl_load_file`` 为module file分配完整临时buffer，并在dependency processing前关闭
  file/device/disk对象；临时ELF镜像随后释放，重定位sections、 ``grub_dl`` 元数据和dependency
  refs才是长期对象；
* ``grub_fs_probe`` 通过 ``fs_dir("/")`` 使用一份临时ext2 mount data；
  ``grub_ext2_open`` 为目标file重新mount并由file持有另一份data，二者不同时遗留；
* MBR LBA 0给出partition start 2048；ext4 superblock相对partition offset 1024，在固定512-byte
  sector下可算为whole-disk LBA 2050。文件data LBA仍取决于实际inode/extent；
* list/module file各自关闭后disk cache可继续存活，cache命中不产生新INT 13h；因此正文只核定
  cache-miss的SeaBIOS/QEMU链，不编造每次open的BIOS/AHCI命令数；
* ``read_config_file`` 先发布empty menu，再打开grub.cfg并用bufio wrapper持有raw file；EOF时
  wrapper close递归关闭raw file并清wrapper device，避免double close；
* ``config_file`` 与 ``config_directory`` 只在配置读取期间设置/export；顶层原值不存在，EOF
  后恢复为unset；
* menuentry复制title/id/args/users/sourcecode后，当前parser临时script和block AST可释放；entry
  不依赖已释放对象；
* 默认既无 ``--users`` 又无 ``--unrestricted`` 时，users是分配的空字符串、restricted为1；
  仅因 ``superusers`` 未设置，执行时authentication才直接成功；
* timeout=0在menu viewer建立前返回index 0；fast path不立刻unset timeout。entry执行时chosen
  发布，default=0因无submenu后缀而暂时unset，旧值只在entry返回后恢复；
* ``command.lst`` 注册的是 ``BLOCKS|EXTCMD|DYNCMD`` placeholder。linux.mod init另行注册真实
  linux/initrd command；dispatcher注销placeholder并按名称重新查找，不在旧对象上原地改写func；
* linux.mod file在init前已经关闭；dispatcher对module增加ref后，真实 ``grub_cmd_linux`` 才准备
  接收 ``/boot/bzImage`` 与三项kernel command-line参数。

已核定的整批成功路径
--------------------

``第028章：动态normal与配置文件打开``
   ``grub_dl_get(normal)`` 在simple-install状态下miss，loader按prefix打开normal.mod。
   ``hd0`` 解析为BIOS drive 0x80， ``msdos1`` 解析为从LBA 2048开始的第一主分区；GRUB ext2
   driver在ext4中查找文件。normal ELF file完整读入并先关闭，再解析依赖、分配/重定位sections、
   加入module list和执行init；normal init保留自身并注册脚本/menu/normal命令。顶层normal随后
   读取四类index并安装prefix hook，建立空menu，打开grub.cfg与bufio，发布配置上下文变量，停在
   第一条parse call前。

``第029章：顺序解析与menu长期对象``
   两条set脚本单元各自立即执行并释放，environment得到timeout/default字符串。menuentry的左花括号
   让parser用同一bufio callback继续取行；handler不运行body，而是生成setparams prefix并复制block
   源码。长期entry取得title/id/argc/args/users/sourcecode所有权并令menu size变为1。EOF后配置
   context变量恢复为unset，bufio/raw/ext2/disk对象全部关闭，menu返回normal execute。

``第030章：自动选择与linux command替换``
   default字符串解析为0，timeout整数为0，run_menu在界面初始化前直接返回。restricted entry的
   auth检查因superusers不存在而成功；chosen导出，default暂时unset，sourcecode在新scope重解析。
   setparams完成后，linux placeholder用prefix打开linux.mod。module file完整读取并关闭，loader
   完成依赖、重定位与init，真实linux/initrd command注册；dispatcher建立module ref、注销旧
   placeholder并重新查找，停在调用真实 ``grub_cmd_linux`` 之前。

失败与未发生边界
----------------

* normal/module文件缺失、ELF校验失败、dependency失败或init失败会使normal命令不可用；固定成功
  镜像排除这些分支，但 ``grub_load_normal_mode`` 打印/清错后仍尝试执行normal的源码顺序保留；
* INT 13h extensions失败可使biosdisk使用CHS fallback；当前SeaBIOS支持EDD，成功路径使用LBA，
  但disk cache hit不会下钻任一BIOS读取；
* ``*.lst`` 缺失错误被读取函数清除，只有后续使用相关自动加载映射时才显现；当前成功镜像包含
  linux映射；
* config parse error由循环打印/清理，normal execute又清 ``grub_errno``；本批固定配置不触发错误，
  不能由“normal会继续”推导错误配置也建立同一menu；
* menuentry建立时不执行body，故第029章没有linux.mod、bzImage或initramfs I/O；
* timeout=0路径不画menu、不读键盘；不能描述为绘制完成后立即擦除；
* authentication确实被调用，不能写成entry unrestricted；当前只是没有superusers导致短路；
* linux.mod装载完不等于kernel已装载；本批终点前 ``grub_cmd_linux`` 尚未调用，loader hook也尚未设置；
* fixed commit不包含构建产物的物理布局，本批不固定module/config/kernel/initramfs inode、extent、
  文件大小、目标LBA或BIOS/AHCI请求次数。
