第001章
--------

核验入口与证据：

* QEMU ``x86_cpu_reset_hold()`` 固定CS隐藏基址、EIP、EFLAGS与A20状态；
* QEMU ``x86_bios_rom_init()`` 建立顶部完整映射， ``x86_isa_bios_init()`` 建立低端别名；
* SeaBIOS ``reset_vector`` 位于 ``ORG 0xfff0``，执行
  ``ljmpw $SEG_BIOS, $entry_post``；
* ``entry_post`` 位于固定偏移 ``0xe05b``。

发现并修复：

#. 主线列表仍写 ``Linux 6.12.95``，与固定Linux commit的 ``7.2-rc1`` 不一致；已修正
   并补齐全部固定commit。
#. 原文只用SeaBIOS解释复位入口，没有把QEMU CPU reset状态和固件高低地址映射接入证据链；
   已增加固定QEMU源码依据。
#. 原章末不是当前合同要求的四节结构；已补齐“本章结束状态—关键边界—下一入口—资料”。

结束边界：BSP执行远跳转后到达 ``f000:e05b`` 的SeaBIOS ``entry_post``，仍在16位
启动环境；尚未建立早期栈，也未进入POST C代码。

第002章
--------

核验入口与证据：

* ``entry_post`` 在冷启动的 ``HaveRunPost==0`` 路径展开 ``ENTRY_INTO32``；
* 宏把 ``SS`` 清零、栈顶设为 ``0x7000``、目标入口装入 ``EDX``，再跳
  ``transition32``；
* ``transition32`` 执行 ``cli``/``cld``、NMI屏蔽、端口0x92 A20写入、IDT/GDT装载、
  CR0修改、远跳转和数据段重载，最后 ``jmpl *%edx``；
* QEMU reset源码已证明本固定路径到达SeaBIOS时 ``IF=0``、 ``DF=0`` 且A20有效。

发现并修复：

#. 原文把SeaBIOS A20操作写成固定场景中的“打开”转换；实际上QEMU reset已经设置
   ``a20_mask=~0``。已改成SeaBIOS再次确认并保持A20开启。
#. 同样补充 ``cli``/``cld`` 在固定冷启动下是幂等操作，避免把防御性入口代码误写成
   必然的标志翻转。
#. 补齐固定QEMU build target、精确源码行锚和合同章末四节。

结束边界：BSP以32位保护模式进入 ``post.c:handle_post()``；分页关闭，早期栈顶为
``0x7000``，A20有效，可屏蔽中断关闭，NMI仍被当前CMOS index写入屏蔽。

第003章
--------

核验入口与证据：

* ``handle_post()`` 依次执行早期调试、Xen检查、 ``make_bios_writable()`` 和 ``dopost()``；
* q35路径通过PAM0让 ``0xc0000-0x100000`` shadow RAM可写，并在需要时从高地址固件
  副本执行复制辅助函数；
* 默认QEMU构建的 ``CONFIG_RELOCATE_INIT=y``；
* QEMU把含RAM与保留项的 ``etc/e820`` 放入fw_cfg，SeaBIOS ``qemu_early_e820()``
  在malloc建立前分块读取；
* ``malloc_preinit()`` 建立 ``ZoneTmpLow``、 ``ZoneTmpHigh`` 与被E820保留的 ``ZoneHigh``；
* ``reloc_preinit()`` 复制 ``code32init``、应用三类重定位并调用移动后的 ``maininit()``。

发现并修复：

#. 原文没有固定 ``CONFIG_RELOCATE_INIT=y``，却无条件叙述复制分支；已固定构建条件并
   说明关闭配置时控制流不同。
#. 原结束状态把当前栈写成仍在 ``0x7000``。该值是初始栈顶；经过多层C调用后当前
   ``ESP`` 已在其下方，不能固定为0x7000。已修正。
#. 增加QEMU生成 ``etc/e820`` 的固定源码证据和关键SeaBIOS行锚。
#. 补齐合同章末四节。

结束边界：控制权进入重定位后的 ``maininit()``；BSP仍是32位保护模式、分页关闭；
低地址BIOS shadow可写，初始E820与临时分配区已经建立，一次性初始化代码已搬迁。

连续性检查
----------

``001 → 002``
   第001章停在 ``entry_post``；第002章从同一地址和 ``HaveRunPost`` 比较开始。

``002 → 003``
   第002章停在 ``handle_post()`` 入口；第003章从该函数第一批调用开始。

``003 → 004``
   第003章停在重定位后的 ``maininit()``，下一入口为 ``interface_init()``；现有第004章
   也从 ``maininit()`` 和 ``interface_init()`` 开始。第004章尚未通过审查，其中关于
   当前栈“仍位于0x7000”的表述将在004—006批次核验，不能提前视为正确。
