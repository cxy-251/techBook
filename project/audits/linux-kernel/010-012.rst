批次开始状态
------------

当前执行者是BSP上的SeaBIOS POST主控制流，仍在32位保护模式，分页关闭、A20开启、
IF=0，NMI由CMOS index bit 7屏蔽。PIC只放行master IRQ2与slave IRQ13；静态
``MainThread`` 仍是唯一SeaBIOS线程。PCI枚举、资源映射和ICH9设备初始化已经结束，
``PCIDevices`` 仍可供后续查找；SMM、MTRR与SMP尚未由本段代码处理。

证据账本
--------

SMM能力与跳过分支
   SeaBIOS默认配置同时启用 ``CONFIG_USE_SMM`` 与 ``CONFIG_CALL32_SMM``，但固定条件
   没有限定QEMU加速器，也没有把 ``-machine smm=`` 固定为 ``on``。QEMU把该属性
   初始化为 ``auto``：TCG/qtest支持SMM；KVM只有 ``KVM_CAP_X86_SMM`` 可用时支持；
   其他不支持SMM的后端在 ``auto`` 下返回false。q35把结果同时交给MCH的
   ``smm-ranges`` 和ICH9 LPC的 ``smm-enabled``。

   ICH9复位在SMM不可用时预置 ``SMI_EN.APMC_EN``，注释明确说明这是“标记SMM已
   初始化，防止SMM运行”。SeaBIOS的q35路径一见 ``APMC_EN`` 已置位便直接返回；
   因而当前固定条件必须保留“成功安装”和“能力关闭后跳过”两个出口，不能把SMI、
   SMBASE迁移或 ``HaveSmmCall32=1`` 写成无条件事实。

SMM成功路径
   ``smm_device_setup()`` 从 ``PCIDevices`` 取得ICH9 LPC与Q35 MCH BDF。成功路径把
   MCH ``SMRAM`` 写为 ``0x4a`` 打开A0000—BFFFF窗口，保存默认SMBASE布局和
   ``0x38000`` 入口原字节，只安装最小SMI入口；随后置
   ``SMI_EN.APMC_EN|GBL_SMI_EN``，再置 ``GEN_PMCON_1.SMI_LOCK``，通过端口
   ``0xb2`` 写0触发当前CPU的SMI。

   第一次 ``handle_smi()`` 只接受保存状态revision ``0x00020000`` 或
   ``0x00020064``。它把新SMBASE ``0xa0000`` 写入默认保存状态，清零握手状态；
   默认 ``CALL32_SMM=y`` 时还复制两份保存状态并置 ``HaveSmmCall32=1``。
   ``RSM`` 返回后，BSP恢复默认区原内容，在 ``0xa8000`` 安装永久入口，执行
   ``wbinvd``，最后用 ``0x0a`` 关闭MCH SMRAM窗口。该值没有设置 ``D_LCK``，所以
   “当前关闭”不能扩大成“MCH窗口寄存器已经锁死”。

   不支持的保存状态revision会在SMI内告警并直接返回，握手状态不会清零，BSP随后
   永久忙等；此路径没有成功出口或事务回滚。若 ``APMC_EN`` 在进入前已置位，
   SeaBIOS无法只凭该位区分“QEMU关闭SMM”和“此前已经安装”。

SMM锁语义
   QEMU在MCH ``D_LCK`` 真正被设置时才会清掉 ``D_OPEN`` 并把SMRAM寄存器写掩码
   收紧到 ``D_CLS``；SeaBIOS本路径写入的 ``0x0a`` 并不包含 ``D_LCK``。
   ICH9 ``GEN_PMCON_1.SMI_LOCK`` 会锁住该锁位本身，并从
   ``SMI_EN`` 写掩码中清掉bit 0，也就是 ``GBL_SMI_EN``；它不会把
   ``APMC_EN`` 或整个 ``SMI_EN`` 一并变成只读。正文不得把两种锁合并成一个泛化的
   “SMM全部配置锁”。

   QEMU的APM command回调只检查 ``SMI_EN.APMC_EN``，没有再次以
   ``GBL_SMI_EN`` 为门。SeaBIOS确实同时设置两位，但正文不能用物理芯片的泛化模型
   反过来宣称固定QEMU中“缺少全局位便绝不触发”。

MTRR与MSR重放
   ``mtrr_setup()`` 先检查构建开关、CPUID ``MTRR``/``MSR`` 位以及
   ``MTRRcap`` 的variable-count与fixed-range能力，任一不满足便返回。成功路径依次
   关闭MTRR、按 ``RamSize`` 写11个fixed-range MSR、清零每个variable pair、
   用pair 0把 ``pcimem_start`` 到4 GiB标成UC，最后以WB默认类型重新启用fixed与
   variable MTRR。注释中的“3.5—4GB”不是固定数值边界；实际起点是前章算出的
   ``pcimem_start``。

   ``wrmsr_smp()`` 总是先对当前BSP执行 ``wrmsr``，随后才尝试写入32项静态重放表。
   MTRR成功路径需要 ``15 + 2 * vcnt`` 次调用；若QEMU还发布非零
   ``etc/msr_feature_control``，再增加一次。超过32项时 ``warn_noalloc()`` 后停止
   记录，但BSP写入仍已发生，之后AP只会重放表内前32项。固定CPU模型与
   ``MTRRcap.vcnt`` 未被当前合同唯一化，因此“表一定够用”和“BSP/AP必然完全一致”
   都不是可证明结论。

FEATURE_CONTROL
   QEMU只在CPU公布VMX、LMCE、SGX或SGX-LC中的至少一项时创建
   ``etc/msr_feature_control``，并在给出的功能位上加lock bit；文件不存在或值为0
   时SeaBIOS不写该MSR。该写入同样经过 ``wrmsr_smp()``，受32项重放上限约束。

CPU数量与AP启动
   QEMU通用machine class把 ``default_cpus`` 的缺省值定为1，并以它初始化
   ``smp.cpus`` 与 ``smp.max_cpus``。当前固定条件没有规定 ``-smp``，所以不能选择
   单CPU或显式多CPU为唯一事实；只能确认无override时QEMU缺省场景只有BSP。
   ``FW_CFG_NB_CPUS`` 是在场CPU数； ``FW_CFG_MAX_CPUS``/
   ``etc/max-cpus`` 在x86上实际是APIC-ID上界。SeaBIOS先读取二者并保证
   ``MaxCountCPUs >= present``，不能把两个概念混写。

   若CPUID没有local APIC， ``smp_scan()`` 直接令 ``CountCPUs=1`` 返回。否则它保存
   ``0x10000`` 的8字节，安装指向 ``entry_smp`` 的远跳转，开启BSP local APIC并配置
   LINT0/LINT1，初始化共享栈锁，然后广播INIT和一个vector 0x10的SIPI。只有在场AP
   才会执行入口；缺省单CPU路径没有AP接收者，BSP的 ``CountCPUs`` 从1开始并立即满足
   expected count，随后恢复 ``0x10000``。

   多CPU条件路径中，每个AP竞争同一个 ``SMPLock`` 和BSP发布的 ``SMPStack``，调用
   ``handle_smp()`` 登记APIC ID、重放已记录MSR并递增 ``CountCPUs``，再释放锁、在
   IF=0下永久 ``hlt`` 循环。BSP循环交还/重取共享栈，直到计数精确相等；无超时，
   缺AP或多计数都会永久等待。 ``yield()`` 发生在计数完成后，但当前没有其他
   SeaBIOS线程可切换。

整批控制流与交接
----------------

``第010章``
   ``smm_device_setup() → smm_setup() → ich9_lpc_apmc_smm_setup()``。先以
   ``SMI_EN.APMC_EN`` 分出QEMU SMM能力跳过路径；能力可用且save-state revision受支持
   时，BSP完成 ``0x30000 → 0xa0000`` SMBASE迁移。两个正常出口都回到
   ``qemu_platform_setup()`` 的 ``mtrr_setup()``。

``第011章``
   ``mtrr_setup() → msr_feature_control_setup()``。MTRR能力完整时BSP执行
   ``15 + 2 * vcnt`` 项写入；无能力时直接返回。FEATURE_CONTROL文件存在时追加一次
   写入。每次都先写BSP，再尝试写入32项AP重放表。章节停在 ``smp_setup()`` 前。

``第012章``
   ``smp_setup() → smp_scan()``。没有local APIC时只登记BSP；有APIC时安装0x10000
   跳板、配置BSP LINT并广播INIT/SIPI。未固定的 ``-smp`` 决定是否有AP执行入口；
   正常完成后恢复跳板，进入 ``MaxCountCPUs <= 255`` 的固件表分支判断。

执行上下文与对象账本
--------------------

* BSP的MainThread是三章共同的主控制流。成功SMM路径暂时切入同一BSP的SMM handler，
  ``RSM`` 后恢复原普通现场；没有创建线程或发生scheduler切换。
* ``PCIDevices`` 与Q35/ICH9 PCI配置从第009章继承并保持。第010章只缓存两个BDF；
  成功路径临时修改默认低端RAM和SMRAM窗口，正常退出时恢复默认RAM并关闭窗口。
* ``smp_msr[32]`` 与 ``smp_msr_count`` 是第011—012章的共享对象。BSP创建有上限的
  顺序日志；只有多CPU分支中的AP读取它，且所有AP通过 ``SMPLock`` 串行共享
  ``SMPStack``。
* ``CountCPUs`` 在APIC扫描路径从1开始， ``FoundAPICIDs`` 登记BSP和条件存在的AP；
  ``MaxCountCPUs`` 保存APIC-ID上界。0x10000跳板只在扫描期间存在。
* PIC mask、CMOS NMI mask、普通IF=0、分页关闭与A20开启在整批正常出口保持不变。

发现并修复
----------

第010章
   原文把SMM成功安装写成无条件路径，遗漏QEMU ``smm=auto`` 与ICH9在能力关闭时预置
   ``APMC_EN`` 的跳过协议，现已拆成两个正常出口。原文还把 ``SMI_LOCK`` 扩大为全部
   SMI enable锁，并把 ``0x0a`` 关闭窗口写成MCH ``D_LCK`` 锁定；固定QEMU实际只锁
   ``GLB_SMI_EN``，SeaBIOS也没有设置 ``D_LCK``。不支持save-state revision后的永久
   轮询也已补入。第009章末尾“CPU必然首次进入SMM”的相邻预告同步收紧。

第011章
   原文把重放表容量检查放在BSP写入之前，并断言固定配置必不超过32项；固定源码相反，
   ``wrmsr`` 先发生，超限只截断AP日志。现已给出 ``15 + 2 * vcnt`` 的精确计数及
   ``vcnt=9`` 的首个分歧例子。原文把历史注释“3.5—4GB”与固定q35的
   ``pcimem_start=0xc0000000`` 混写，也把条件FEATURE_CONTROL写成稳定结果，均已
   对齐固定SeaBIOS/QEMU表达式。

第012章
   原文把AP执行、MSR重放和HLT停驻写成必然事实，遗漏固定条件未规定 ``-smp``；现已
   并列QEMU缺省单CPU与显式多CPU出口，不替用户选择参数。 ``etc/max-cpus`` 已从普通
   “最大CPU数量”改为QEMU明确的APIC-ID上界，并补齐单CPU仍广播、共享栈竞争不保证AP
   先抢到、MSR日志截断继承、精确计数无timeout等边界。

连续性检查
----------

``009 → 010``
   第009章停在 ``pci_setup()`` 返回；第010章从下一条 ``smm_device_setup()`` 开始，
   沿用 ``PCIDevices``、BSP mode、PIC/NMI与MainThread状态。相邻预告已改为条件SMM。

``010 → 011``
   SMM成功与能力跳过两个正常出口都从 ``smm_setup()`` 返回；第011章从下一条
   ``mtrr_setup()`` 开始，不把SMM成功状态当成MTRR入口前提。

``011 → 012``
   第011章停在MSR日志建立后、AP尚未执行；第012章从 ``smp_setup()`` 读取CPU数量
   开始，并明确只重放日志中实际保留的前缀。

``012 → 013``
   第012章正常结束于0x10000恢复后，下一条真实入口是
   ``if (MaxCountCPUs <= 255)``。第013章既有开头仍把AP停驻写成无条件事实，已登记为
   下一批首项修复，不越过当前游标修改未审正文。
