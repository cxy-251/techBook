长期决策
========

本文件保存跨对话必须继续遵守的长期决定。新 Agent 不得仅凭聊天记忆推翻这些决定。

D-001：私有学习内容仓库
-----------------------

状态：accepted

``cxy-251/techBook`` 是私有学习内容仓库，用于把 ``aiBook`` 中真正想获得的技术知识重做为适合零基础程序员逐步掌握的 RST 学习资料。

D-002：只使用 main
------------------

状态：accepted

当前所有工作直接提交到 ``main``。不创建功能分支和 PR，除非用户明确改变规则。

D-003：RST 直接阅读
-----------------

状态：accepted

项目说明、教学规则、学习路径和正式内容使用 reStructuredText。RST 源文件就是最终阅读内容，不依赖 Sphinx、HTML 或其他构建产物。

D-004：不建立构建与自动化系统
-----------------------------

状态：accepted

仓库不保留 Python 校验脚本、``pyproject.toml``、Sphinx 配置、GitHub Actions、CI、构建任务、release 导出脚本或 Pages 发布配置。真实需要出现前不提前预留这些功能。

D-005：AGENTS 是接续入口
-----------------------

状态：accepted

任何新对话和新 Agent 都从根目录 ``AGENTS.md`` 恢复上下文。聊天记录不属于项目依赖。

D-006：不使用独立 Skill
----------------------

状态：accepted

仓库规则、内容设计和接续信息由 ``AGENTS.md``、``project/``、RST 与少量 TOML 状态文件共同提供。不维护与这些文件重复的 Skill。

D-007：内容与证据写在同一 RST
-----------------------------

状态：accepted

代码、命令、输出、错误信息、源码片段和推理直接写入对应学习单元。源码级内容在当前 RST 中记录 repository、release、commit、平台和工具链，不使用全局 source lock 或独立 lab 层。

D-008：当前不批量生成
--------------------

状态：accepted

黄金学习单元经过实际阅读校准前，不批量生产正式内容，也不自动连续生成。

D-009：学习发生优先于内容覆盖
-----------------------------

状态：accepted

一个学习单元必须让读者经历预测、证据、推理、条件变化、误解修正和迁移任务。读完页面或看懂句子不能单独视为学会。

D-010：按阶段小批次规划
----------------------

状态：accepted

路径开始时固定目标、能力层级、阶段与知识覆盖范围。每个阶段开始前设计一个有限批次，通常三到五个学习单元。批次完成后根据真实阅读反馈设计下一批，不在开头冻结整条路径的全部章节。

D-011：问题必须有来源
--------------------

状态：accepted

每道能力检查题必须能够说明为什么要问、答案来自哪段代码或哪项现象、推理经过哪些步骤，以及常见错误答案依赖了什么错误模型。

D-012：Narrative 不进入本仓库
-----------------------------

状态：accepted

文学、电影、电视剧和游戏编年史等 Narrative 内容继续留在旧仓库，不进入 ``techBook``。

D-013：Roadmap 和生成控制文件定义知识范围
-----------------------------------------

状态：accepted

``aiBook`` 的 Roadmap、Roadmap 配套规范和文章生成控制文件体现用户真正希望获得的知识。它们是 ``techBook`` 的知识范围输入。

这些文件只能回答“需要学什么”，不能证明技术结论正确。

D-014：Roadmap 条目不是章节
--------------------------

状态：accepted

Roadmap 条目属于覆盖要求，不采用“一项一章”。允许根据零基础学习依赖合并、拆分、重排、延后或明确排除，但必须保留覆盖记录和原因，不能静默丢弃用户真正想学的知识。

D-015：旧 docs 只作为失败样本
----------------------------

状态：accepted

旧 ``aiBook/docs`` 只用于分析过度扩充、前置缺失、问题脱节和解释失败。旧正文默认不复制、不缩写、不逐章改写。

旧正文中的链接、代码、输出、源码路径和技术结论都必须重新核实，不能作为事实来源。

D-016：技术事实重新建立
----------------------

状态：accepted

正式内容中的事实、代码行为、源码路径和工程判断必须重新来自官方文档、标准、固定版本源码或真实可确认的运行现象。Roadmap 负责知识意图，一手资料与真实证据负责事实。

D-017：输出必须标明真实性
------------------------

状态：accepted

RST 中的实际输出必须记录验证环境和验证日期。无法实际执行时必须标记为“预期结果，尚未实测”，不能把推测写成真实输出。

D-018：Linux Kernel采用专用稳定生产合同
--------------------------------------

状态：accepted

当前Linux Kernel路径统一遵守 ``project/LINUX_KERNEL_CONTRACT.rst``。通用的
``LEARNING_DESIGN.rst``、 ``CONTENT_SELECTION.rst`` 与D-008至D-011在不冲突时仍可提供
设计参考；涉及批次、章节格式、审查状态和完成语义时，由Linux Kernel专用合同覆盖。

D-019：从第001章顺序回溯审查
----------------------------

状态：accepted

第001—193章只表示历史正文存在，不再整体视为已验证。审查从001开始连续推进，每批通常
三章，发现问题就在当前批修复。第193章审查闭合前暂停UDP及之后的新章生产。

D-020：稳定规则与动态状态分离
----------------------------

状态：accepted

``AGENTS.md`` 和Linux Kernel合同保存稳定规则； ``project/STATE.rst`` 是唯一动态接续
状态；逐批证据保存在 ``project/audits/linux-kernel/``。README、章节index和历史前向
检查点不承担Agent接续，避免每批在多份文件复制完整调用链。

D-021：允许源码缓存和只读一致性检查器
------------------------------------

状态：accepted

作为D-004的窄例外，允许：

* 在被 ``.gitignore`` 排除的 ``.sources/`` 缓存固定提交的外部源码；
* 保留 ``tools/check-linux-kernel-track.sh`` 这个只读结构检查器。

仍不建立Sphinx、CI、GitHub Actions、批量正文生成器或自动技术事实判定系统。检查器只能
发现结构问题，不能代替固定源码审查。

D-022：Linux Kernel批次原子提交main
----------------------------------

状态：accepted

每批正文、审计报告、状态和必要manifest更新作为一个原子提交直接进入 ``main`` 并推送
``origin/main``。不再为三章和多份接续文件拆出一串中间不一致提交。

已废止决定
------------

以下旧设计已经废止，相关历史仍保存在 Git 中：

* 整本书开始前冻结全部章节；
* Linux Kernel 固定 17 章源码计划；
* source-first 章节生产 Skill；
* Python 内容审计与模型校验；
* Sphinx 和 GitHub Actions 构建；
* 私有仓库到公共仓库的自动 release 导出；
* 把旧 ``aiBook/docs`` 当作新内容资料库；
* 把 Roadmap 条目直接解释成章节目录。
