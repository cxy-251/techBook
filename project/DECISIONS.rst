长期决策
========

本文件保存跨对话必须继续遵守的长期决策。新 Agent 不得仅凭聊天记忆修改这些决策；修改时要记录新决策及原因。

D-001：私有开发仓库
-------------------

状态：accepted

``cxy-251/techBook`` 是私有开发仓库，保存学习路径、unit、实验、内部状态、审计工具和来源信息。

D-002：只使用 main
------------------

状态：accepted

当前所有工作直接提交到 ``main``。不创建功能分支和 PR，除非用户以后明确改变该规则。

D-003：RST 与 Sphinx
-------------------

状态：accepted

面向读者的稳定内容使用 reStructuredText。RST 源文件可以直接保存和阅读，不依赖构建才能存在。
Sphinx 只在需要 HTML 预览、交叉引用检查或正式发布前手动运行。

D-004：暂不发布 Pages
---------------------

状态：accepted

普通 GitHub 用户的私有仓库不作为 Pages 发布源。内容稳定后建立独立公共 release 仓库，由公共仓库发布 GitHub Pages。

D-005：私有仓库与公共仓库分离
--------------------------------

状态：accepted

私有仓库持续修改。公共仓库只接收通过验证的稳定快照。公共 release 由 ``release-manifest.toml`` 白名单控制。

D-006：AGENTS 是接续入口
-------------------------

状态：accepted

任何新对话和新 Agent 都从根目录 ``AGENTS.md`` 恢复上下文。聊天记录不属于项目依赖。

D-007：当前不依赖独立 Skill
----------------------------

状态：accepted

仓库接续和学习单元生产规则全部由 ``AGENTS.md``、``project/`` 和 manifests 提供。旧的源码文章 Skill 已从工作树删除。

D-008：当前不批量生成正式内容
-----------------------------

状态：accepted

基础目录存在不代表教学模型已经有效。黄金 unit 经过真实阅读校准前，不进行大规模迁移或自动连续生成。

D-009：学习发生优先于内容覆盖
-----------------------------

状态：accepted

一个 unit 必须让读者经历预测、证据、推理、条件变化、误解修正和迁移任务。看懂文字或读完页面不能单独视为学会。

D-010：整本书全部章节提前冻结
-------------------------------

状态：superseded

旧决定曾要求一本书开始前冻结全部章节。该做法会复制 ``aiBook`` 的目录填充问题，已经废止。

当前规则是：路径开始时固定目标与阶段；每个阶段开始前设计一个小批次 unit；批次完成后根据真实学习反馈校准下一批。

D-011：Narrative 不进入本仓库
------------------------------

状态：accepted

文学、电影、电视剧和游戏编年史等 Narrative 内容继续留在旧仓库，不进入 ``techBook`` 的技术学习流程。

D-012：Linux 原 17 章计划
------------------------

状态：superseded

原计划按 ARM64 启动、初始化和 VFS 冻结 17 章，过早采用源码目录视角。相关文件已从工作树删除，历史保留在 Git 中。

Linux 当前只固定四个能力阶段：基础认知、运行时观察、源码阅读、排错与迁移。

D-013：unit 批次执行
-------------------

状态：accepted

每个阶段开始前设计一个有限批次，通常三到五个 unit。每次 Agent 运行处理批次中顺序最靠前的未完成项，不临时发散主题。

D-014：证据与阶段匹配
---------------------

状态：accepted

语言基础可以使用运行输出和对象状态；编译内容可以使用错误、AST 或 IR；系统内容可以使用日志、请求和进程状态；只有源码级阶段才强制固定 commit 与源码符号。

D-015：问题必须有来源
---------------------

状态：accepted

每道能力检查题必须能说明为什么要问、答案来自哪项证据、推理经过哪些步骤、错误答案依赖了什么错误模型。

D-016：CI 只手动运行
--------------------

状态：accepted

仓库搭建和内容校准期间，GitHub Actions 只允许 ``workflow_dispatch`` 手动触发。普通 push 不运行 CI，避免每个小提交触发构建、失败邮件和无意义消耗。
