长期决策
========

本文件保存跨对话必须继续遵守的长期决策。新 Agent 不得仅凭聊天记忆修改这些决策。

D-001：私有开发仓库
-------------------

状态：accepted

``cxy-251/techBook`` 是私有学习内容开发仓库，保存 unit、实验、状态、审计工具和来源信息。

D-002：只使用 main
------------------

状态：accepted

当前所有工作直接提交到 ``main``。不创建功能分支和 PR，除非用户以后明确改变该规则。

D-003：RST 与 Sphinx
-------------------

状态：accepted

面向读者的学习内容使用 reStructuredText。Sphinx 负责构建、交叉引用、``literalinclude``、
doctest 和 warnings-as-errors 验证。

D-004：暂不发布 Pages
---------------------

状态：accepted

当前私有仓库不发布 Pages。稳定内容后续导出到独立公共仓库，由公共仓库发布 GitHub Pages。

D-005：私有开发与公共发布分离
----------------------------

状态：accepted

私有仓库持续修改。公共仓库只接收通过学习检查和自动验证的稳定快照。

D-006：AGENTS 是接续入口
-------------------------

状态：accepted

任何新对话和新 Agent 都从根目录 ``AGENTS.md`` 恢复上下文。聊天记录不属于项目依赖。

D-007：暂不维护独立 Skill
-------------------------

状态：accepted

当前仓库依靠 ``AGENTS.md``、``project/`` 和 manifests 继续工作。旧章节生成 Skill 与仓库规则
重复，并且建立在错误的“冻结目录后自动写书”模型上，因此退出活动使用。

只有黄金 unit 通过验证、重复流程稳定且需要跨仓库复用时，才重新创建 Skill。

D-008：当前不批量生成内容
-------------------------

状态：accepted

基础目录和自动构建不代表学习模型已经成立。三个黄金 unit 通过实际阅读检查前，不进行大规模迁移
或自动连续生成。

D-009：证据形式服务学习目标
---------------------------

状态：accepted

学习内容必须有可定位证据。证据可以是运行结果、错误信息、对象状态、官方文档、网络请求、日志、
编译产物、固定源码或 trace。并非所有 unit 都从源码开始。

D-010：整本书全部章节提前冻结
-----------------------------

状态：superseded

旧决定要求在开始时冻结全部 Part、章节和顺序。该方式重现了 ``aiBook`` 的目录填充问题，已经由
D-015 取代。

D-011：Narrative 不进入本仓库
------------------------------

状态：accepted

文学、电影、电视剧和游戏编年史等 Narrative 内容继续留在旧仓库，不进入技术学习路径。

D-012：Linux 第一卷固定 17 章
-----------------------------

状态：superseded

旧 17 章计划从 ARM64 启动函数和 VFS 路径出发，没有先为零基础读者建立行为模型与观测能力。
该计划不再控制生产，Git 历史保留其设计过程。

D-013：blocked 时严格停止整条书
------------------------------

状态：superseded

旧决定绑定 frozen plan。新模型按 stage batch 工作：当前 unit 缺少证据时停止该 unit；阶段设计者
可以补充前置 unit，但不能临时跳到无关主题。

D-014：仓库是可执行学习系统
-----------------------------

状态：accepted

``techBook`` 的核心产物是 learning track 和 unit。书、网站和课程是这些 unit 的发布形式，不是
仓库内部唯一模型。

D-015：路径固定，unit 分阶段设计
--------------------------------

状态：accepted

路径开始时固定目标读者、入口能力、最终能力、阶段顺序、范围和排除项。每个阶段开始前设计一个
小批次 unit。每次运行执行当前批次中的下一个 unit，不重新随机选题。

D-016：学习单元必须形成能力变化
--------------------------------

状态：accepted

unit 完成后，读者至少能够预测、解释、改变条件并完成一次迁移。只介绍术语或给出总结的内容不能
标记为 complete。

D-017：问题与答案必须可追溯
-----------------------------

状态：accepted

每个检查题必须来自前面的现象、代码或输出。答案必须给出推理步骤、证据位置和常见错误答案失败
的原因。无法说明“为什么问”的问题必须删除。

D-018：aiBook 是主题库存与反面样本
-----------------------------------

状态：accepted

``aiBook/docs`` 提供七条技术方向、候选资料和典型失败内容。旧文本不直接成为新 unit 的底稿；
迁移从真实困惑和能力目标重新设计。

D-019：从零基础到精通使用能力层级
----------------------------------

状态：accepted

学习路径使用 ``L1 运行 → L2 解释 → L3 修改 → L4 排错 → L5 迁移`` 描述进阶。每条路径必须
明确入口层级和目标层级，不能只用“入门”“高级”“精通”作为空泛标签。
